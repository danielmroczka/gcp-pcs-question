Question 60 / 361

A company is running their webshop on Google Kubernetes Engine and wants to analyze customer transactions in BigQuery. You need to ensure that no credit card numbers are stored in BigQuery. What should you do?

  • A. Create a BigQuery view with regular expressions matching credit card numbers to query and delete affected rows.
  • B. Use the Cloud Data Loss Prevention API to redact related infoTypes before data is ingested into BigQuery.
  • C. Leverage Security Command Center to scan for the assets of type Credit Card Number in BigQuery.
  • D. Enable Cloud Identity-Aware Proxy to filter out credit card numbers before storing the logs in BigQuery.
Show Suggested Answer Hide Answer
Suggested Answer: B

Wyjaśnienie

Potwierdzona odpowiedź: B (Use the Cloud Data Loss Prevention API to redact related infoTypes before data is ingested into BigQuery.)

Wyjaśnienie:
Cloud Data Loss Prevention (DLP) API to flagowa usługa Google Cloud do wykrywania i ochrony danych wrażliwych (PII, numery kart kredytowych, adresy itp.). Najlepszą praktyką bezpieczeństwa jest "oczyszczanie" danych (redakcja/anonimizacja) ZANIM trafią one do docelowego systemu analitycznego (BigQuery). Pozwala to zminimalizować ryzyko wycieku danych oraz zmniejsza zakres audytów (np. PCI DSS). Cloud DLP posiada wbudowane "infoTypes" dla kart kredytowych (`CREDIT_CARD_NUMBER`), co pozwala na ich automatyczną identyfikację i zastąpienie (redaction) np. znakami `X`.

Dlaczego pozostałe są błędne:
A. BigQuery view + Regex: Widoki służą do prezentacji danych, a nie do ich usuwania. Usuwanie wierszy po ich zapisaniu w BigQuery jest nieefektywne kosztowo i nie gwarantuje, że dane nie zostały już gdzieś zreplikowane lub zapisane w logach systemowych.
C. Security Command Center: SCC może raportować, że dane wrażliwe znajdują się w BigQuery (poprzez Sensitive Data Protection), ale samo w sobie nie służy do "w locie" filtrowania danych podczas ich przesyłania.
D. Identity-Aware Proxy: IAP służy do kontroli dostępu do aplikacji webowych (uwierzytelnianie/autoryzacja). Nie ma funkcjonalności głębokiej analizy i modyfikacji treści (payloadu) danych przesyłanych do BigQuery.

Tips & Tricks:
- "Sensitive data" / "Credit Card" + "Google Cloud" = DLP API.
- Zawsze wybieraj rozwiązanie, które blokuje/anonimizuje dane jak najbliżej źródła ("before ingestion").
- DLP API to jedyne narzędzie Google Cloud zaprojektowane specjalnie do manipulacji treścią danych wrażliwych.

Zagadnienia:
- Cloud Data Loss Prevention (DLP) infoTypes.
- De-identification techniques (Redaction, Masking, Tokenization).
- PCI DSS compliance in GCP.

Dokumentacja:
https://cloud.google.com/dlp/docs/redacting-sensitive-data
