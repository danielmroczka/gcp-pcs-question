Question 228 / 361

Your organization manages a mission-critical workload in a highly regulated industry. The workload uses Compute Engine VMs to analyze and process sensitive data after it is uploaded to Cloud Storage from endpoint computers. Your compliance team has detected that this workload does not meet data protection requirements. You need to meet these requirements:
- Manage the data encryption key (DEK) outside the Google Cloud boundary.
- Maintain full control of encryption keys through a third-party provider.
- Encrypt sensitive data before uploading to Cloud Storage.
- Decrypt sensitive data during processing in Compute Engine VMs.
- Encrypt sensitive data in memory while in use in Compute Engine VMs.
What should you do? (Choose two.)

  • A. Configure Customer Managed Encryption Keys (CMEK) to encrypt the sensitive data before it is uploaded to Cloud Storage, and decrypt the sensitive data after it is downloaded into your VMs.
  • B. Configure Cloud External Key Manager (EKM) to encrypt the sensitive data before it is uploaded to Cloud Storage, and decrypt the sensitive data after it is downloaded into your VMs.
  • C. Create Confidential VMs to access the sensitive data.
  • D. Migrate the Compute Engine VMs to Confidential VMs to access the sensitive data.
  • E. Create a VPC Service Controls service perimeter across your existing Compute Engine VMs and Cloud Storage buckets.
Show Suggested Answer Hide Answer
Suggested Answer: BC

Wyjaśnienie

Poprawna odpowiedź: BC (B: Configure Cloud External Key Manager, C: Create Confidential VMs)

Dlaczego te odpowiedzi są poprawne:
- Cloud External Key Manager (EKM) (B): Wymóg "Manage the data encryption key (DEK) outside the Google Cloud boundary" oraz "Maintain full control ... through a third-party provider" bezpośrednio wskazuje na usługę Cloud EKM, która integruje KMS z zewnętrznym HSM.
- Confidential VMs (C): Wymóg "Encrypt the sensitive data in memory while in use in the Compute Engine VMs" wskazuje na Confidential Computing (Confidential VMs), które używają szyfrowania RAM w trakcie przetwarzania danych.

Analiza niepoprawnych odpowiedzi:
- A. CMEK: CMEK (Customer Managed Encryption Keys) są zarządzane wewnątrz Cloud KMS (infrastruktura Google). Nie spełnia to wymogu przechowywania kluczy poza "Google Cloud boundary".
- D. Migrate to Confidential VMs: Tożsama z odpowiedzią C, ale opcja C jest bardziej zwięzła i poprawna w kontekście wyboru usług. (Uwaga: W pytaniu 228 opcje mogą się dublować, ważne jest wskazanie EKM i Confidential VM).
- E. VPC Service Controls: VPC Service Controls chroni przed eksfiltracją (wynoszeniem danych), ale nie jest technologią szyfrowania danych ("in memory" lub "at rest").

Wskazówki i triki (Tips & Tricks):
- "External key provider" = EKM.
- "Encrypt memory" / "Data in use" = Confidential VMs.
- "Regulatory compliance" = EKM + KAJ + Confidential Computing.

Praktyczne informacje na egzamin:
- Zapamiętaj: EKM to separacja kluczy od chmury, a Confidential Computing to separacja danych w RAM od hypervisora.
- Razem tworzą najwyższy możliwy poziom suwerenności danych w GCP.

Kluczowe zagadnienia

Sugerowana odpowiedź: BC

Analiza strategiczna: To pytanie testuje Twoją wiedzę o najbardziej zaawansowanych funkcjach bezpieczeństwa w GCP (Sovereign Cloud). Kluczowym wyzwaniem jest tu separacja kluczy od platformy (EKM) oraz szyfrowanie pamięci (Confidential VM). Jeśli widzisz wymagania o suwerenności i regulacjach, to zawsze EKM i Confidential Computing.
