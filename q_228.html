Question 228 / 361

You manage a mission-critical workload for your organization, which is in a highly regulated industry. The workload uses Compute Engine VMs to analyze and process the sensitive data after it is uploaded to Cloud Storage from the endpoint computers. Your compliance team has detected that this workload does not meet the data protection requirements for sensitive data. You need to meet these requirements: - Manage the data encryption key (DEK) outside the Google Cloud boundary. - Maintain full control of encryption keys through a third-party provider. - Encrypt the sensitive data before uploading it to Cloud Storage. - Decrypt the sensitive data during processing in the Compute Engine VMs. - Encrypt the sensitive data in memory while in use in the Compute Engine VMs. What should you do? (Choose two.)

  • A. Configure Customer Managed Encryption Keys to encrypt the sensitive data before it is uploaded to Cloud Storage, and decrypt the sensitive data after it is downloaded into your VMs.
  • B. Configure Cloud External Key Manager to encrypt the sensitive data before it is uploaded to Cloud Storage, and decrypt the sensitive data after it is downloaded into your VMs.
  • C. Create Confidential VMs to access the sensitive data.
  • D. Migrate the Compute Engine VMs to Confidential VMs to access the sensitive data.
  • E. Create a VPC Service Controls service perimeter across your existing Compute Engine VMs and Cloud Storage buckets.
Show Suggested Answer Hide Answer
Suggested Answer: BC

Wyjaśnienie

1. Prawidłowa odpowiedź lub odpowiedzi:
B. Configure Cloud External Key Manager to encrypt the sensitive data before it is uploaded to Cloud Storage, and decrypt the sensitive data after it is downloaded into your VMs.
C. Create Confidential VMs to access the sensitive data.

2. Kompleksowe wyjaśnienie dlaczego dana odpowiedź jest prawidłowa (Analiza):
Odpowiedzi B i C są prawidłowe, ponieważ łącznie spełniają skomplikowane wymagania regulacyjne dotyczące ochrony danych w spoczynku i w użyciu przy zachowaniu suwerenności kluczy szyfrujących poza chmurą Google.

Szczegóły rozwiązań:
a. **Szyfrowanie danych w spoczynku poza GCP (B):** Użycie Cloud External Key Manager (Cloud EKM) pozwala na to, aby klucz szyfrujący (KEK) fizycznie znajdował się u zewnętrznego dostawcy (on-premises HSM) poza jurysdykcją i infrastrukturą Google Cloud. Cloud EKM jest zintegrowany z Cloud Storage, co pozwala na automatyczne szyfrowanie danych podczas przesyłania ich do kubełka i ich odszyfrowywanie przy pobieraniu przez autoryzowane maszyny wirtualne.
b. **Szyfrowanie danych w użyciu (C):** Maszyny wirtualne przetwarzające te dane w pamięci RAM muszą być skonfigurowane jako **Confidential VMs** (Poufne Maszyny Wirtualne). Wykorzystują one sprzętowe szyfrowanie pamięci (RAM encryption), dzięki czemu dane w użyciu są chronione przed potencjalnym odczytem z poziomu systemu hosta fizycznego GCP.

3. Wyjaśnienie z osobna każdej niepoprawnej odpowiedzi:
A. Configure Customer Managed Encryption Keys...
   * Dlaczego nieprawidłowa: Standardowe klucze zarządzane przez klienta (CMEK) w Cloud KMS są przechowywane w infrastrukturze Google Cloud. Nie spełnia to krytycznego wymagania przechowywania i zarządzania kluczem szyfrującym (KEK/DEK) w 100% poza granicami Google (outside the Google Cloud boundary).
D. Migrate the Compute Engine VMs to Confidential VMs...
   * Dlaczego nieprawidłowa: Choć cel jest poprawny, to technicznie w GCP nie można po prostu "zmigrować" istniejącej standardowej maszyny wirtualnej bezpośrednio na typ Confidential VM bez zmiany typu maszyny w locie lub jej ponownego wdrożenia (wymagane jest utworzenie nowej instancji z włączoną opcją Confidential Computing - stąd opcja C "Create Confidential VMs" jest poprawnym sformułowaniem).
E. Create a VPC Service Controls service perimeter...
   * Dlaczego nieprawidłowa: VPC Service Controls zapobiega eksfiltracji danych z projektów, ale nie szyfruje danych w użyciu (w pamięci RAM) ani nie pozwala na zarządzanie kluczami u zewnętrznego dostawcy.

4. Wskazówki, hinty, tips and tricks:
* Przechowywanie kluczy poza chmurą (External control of keys) -> **Cloud EKM (External Key Manager)**.
* Ochrona danych w użyciu w procesorze/pamięci (encryption in-use) -> **Confidential VMs**.

5. Reguły wyboru odpowiedzi (Słowa kluczowe):
* Encryption key outside Google Cloud + encrypt data in memory -> Cloud EKM + Confidential VMs.

6. Dodatkowe źródła i dokumentacja:
Cloud External Key Manager (Cloud EKM)
Confidential Computing in GCP

Wskazówki egzaminacyjne (Tips & Tricks)

Reguła Egzaminacyjna (Exam Rule): 
Jeśli scenariusz dotyczy zabezpieczania zasobów chmurowych (GCP), zawsze wybieraj rozwiązanie typu Managed (SCC, Secret Manager, Cloud KMS), a unikaj rozwiązań self-managed, chyba że pytanie wyraźnie wymaga dostosowania niskopoziomowego.

Haczyki egzaminacyjne (Exam Traps):
- Pułapka IAM: Pytania o uprawnienia często sugerują 'Project Owner' – zawsze szukaj 'Least Privilege' (np. 'Role: Secret Manager Secret Accessor').
- Pułapka Sieciowa: Często mylone są VPC Peering (wydajność) oraz VPN (szyfrowanie/on-premise).

Głębokie wyjaśnienie techniczne:
Rozwiązanie bazuje na GCP Shared Responsibility Model. Google zarządza bezpieczeństwem infrastruktury (Physical, Network, Host), podczas gdy administrator zarządza tożsamością (IAM), danymi (Encryption, Cloud KMS) i regułami dostępu (VPC Firewall).

Analiza i Podsumowanie (AI)

Kluczowe zagadnienia

Sugerowana odpowiedź: BC

Analiza strategiczna: To pytanie testuje Twoją wiedzę o najbardziej zaawansowanych funkcjach bezpieczeństwa w GCP (Sovereign Cloud). Kluczowym wyzwaniem jest tu separacja kluczy od platformy (EKM) oraz szyfrowanie pamięci (Confidential VM). Jeśli widzisz wymagania o suwerenności i regulacjach, to zawsze EKM i Confidential Computing.
