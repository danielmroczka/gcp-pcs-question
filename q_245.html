Question 245 / 361

You have placed several Compute Engine instances in a private subnet. You want to allow these instances to access Google Cloud services, like Cloud Storage, without traversing the internet. What should you do?

  • A. Enable Private Google Access for the private subnet.
  • B. Configure Private Service Connect for the private subnet's Virtual Private Cloud (VPC) and allocate an IP range for the Compute Engine instances.
  • C. Reserve and assign static external IP addresses for the Compute Engine instances.
  • D. Create a Cloud NAT gateway for the region where the private subnet is configured.
Show Suggested Answer Hide Answer
Suggested Answer: A

Wyjaśnienie

1. Prawidłowa odpowiedź lub odpowiedzi:
A. Enable Private Google Access for the private subnet.

2. Kompleksowe wyjaśnienie dlaczego dana odpowiedź jest prawidłowa (Analiza):
Odpowiedź A jest prawidłowa, ponieważ Private Google Access (Prywatny dostęp do Google) to natywna funkcja sieciowa w GCP, która pozwala instancjom maszyn wirtualnych posiadającym wyłącznie prywatne adresy IP (brak publicznego IP) na łączenie się z publicznymi adresami IP usług i interfejsów API Google (np. Cloud Storage, BigQuery) bez przechodzenia przez internet.

Jak to działa:
a. Maszyny wirtualne w podsieci prywatnej wysyłają żądania do API Google (np. `storage.googleapis.com`).
b. Gdy Private Google Access jest włączone dla tej podsieci, ruch ten jest kierowany bezpośrednio przez sieć wewnętrzną Google do punktów końcowych API Google.
c. Pakiety nie są kierowane do bramy internetowej (Internet Gateway) i nie wymagają translacji NAT ani publicznych adresów IP na maszynach. Jest to rozwiązanie wysoce bezpieczne, wydajne i bezkosztowe.

3. Wyjaśnienie z osobna każdej niepoprawnej odpowiedzi:
B. Configure Private Service Connect... and allocate an IP range...
   * Dlaczego nieprawidłowa: Private Service Connect (PSC) służy do tworzenia prywatnych punktów końcowych (Internal IPs) w sieci VPC w celu uzyskania dostępu do usług własnych (innych firm) lub specyficznych interfejsów API Google. Chociaż PSC może realizować podobne cele, to standardowym, znacznie prostszym i domyślnym rozwiązaniem dla ogólnego dostępu do usług Google (jak GCS) z podsieci prywatnej jest włączenie Private Google Access.
C. Reserve and assign static external IP addresses for the Compute Engine instances.
   * Dlaczego nieprawidłowa: Przypisanie zewnętrznych (publicznych) adresów IP do maszyn wirtualnych sprawia, że przestają być one w podsieci prywatnej (są wystawione na internet). Ruch do usług Google przechodziłby wówczas przez internet, co narusza kluczowy warunek "without traversing the internet".
D. Create a Cloud Cloud NAT gateway for the region where the private subnet is configured.
   * Dlaczego nieprawidłowa: Cloud NAT pozwala maszynom prywatnym na dostęp do ogólnego internetu (np. w celu pobrania aktualizacji systemu). Choć ruch do API Google również mógłby przechodzić przez NAT, to Cloud NAT tłumaczy adresy na publiczne i kieruje ruch przez internetową bramę Google (traversing the internet), co jest mniej bezpieczne i generuje koszty transferu NAT w porównaniu do darmowego i wewnętrznego Private Google Access.

4. Wskazówki, hinty, tips and tricks:
* Dostęp z maszyn bez publicznego IP (private VMs) do usług Google (Cloud Storage, BigQuery itp.) bez internetu -> Zawsze **Private Google Access** (PGA).
* PGA jest konfigurowane jako prosta flaga (włącz/wyłącz) bezpośrednio na poziomie podsieci (subnet level).

5. Reguły wyboru odpowiedzi (Słowa kluczowe):
* Private subnet VMs + access Google services + without traversing the internet -> Private Google Access.
