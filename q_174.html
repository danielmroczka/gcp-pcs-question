Question 174 / 361

You manage your organization's Security Operations Center (SOC). You currently monitor and detect network traffic anomalies in your VPCs based on network logs. However, you want to explore your environment using network payloads and headers. Which Google Cloud product should you use?

  • A. Cloud IDS
  • B. VPC Service Controls logs
  • C. VPC Flow Logs
  • D. Google Cloud Armor
  • E. Packet Mirroring
Show Suggested Answer Hide Answer
Suggested Answer: A

Wyjaśnienie

Poprawna odpowiedź: A (Cloud IDS)

Dlaczego ta odpowiedź jest poprawna:
- Cloud IDS (Intrusion Detection System): Jest to w pełni zarządzana usługa bezpieczeństwa sieciowego w Google Cloud, która umożliwia wykrywanie zagrożeń, takich jak malware, spyware, command-and-control (C2) oraz ataki typu exploit.
- Analiza Payload i Headerów: W przeciwieństwie do logów przepływu (Flow Logs), Cloud IDS wykonuje głęboką inspekcję pakietów (Deep Packet Inspection), analizując nie tylko nagłówki, ale i samą zawartość (payload) ruchu sieciowego. Wykorzystuje do tego zaawansowane silniki analizy zagrożeń (partnerstwo z Palo Alto Networks).
- Scenariusz SOC: Dla Security Operations Center (SOC), Cloud IDS dostarcza wysokiej jakości alerty o konkretnych zagrożeniach, co pozwala na znacznie skuteczniejszą "eksplorację środowiska" pod kątem bezpieczeństwa niż analiza surowych metadanych.

Analiza niepoprawnych odpowiedzi:
- B. VPC Service Controls logs: Logi te informują jedynie o naruszeniach perymetru (kto próbował dostać się do API Google poza dozwoloną regułą). Nie zawierają one payloadu ruchu IP między maszynami wewnątrz VPC.
- C. VPC Flow Logs: Zawierają tylko metadane połączeń (IP, porty, protokół). Nie pozwalają na analizę zawartości pakietów (payload), o którą pyta scenariusz.
- D. Google Cloud Armor: Chroni głównie przed atakami na warstwę aplikacji (WAF/DDoS) dla ruchu HTTP/S przychodzącego przez Load Balancer. Nie służy do inspekcji ogólnego ruchu wewnątrz sieci VPC (ruch East-West).
- E. Packet Mirroring: Jest to technologia "podkładowa", która dostarcza ruch do systemu analizującego. Choć pozwala na dostęp do payloadu, samo w sobie nie jest "produktem do eksploracji" ani systemem detekcji – wymagałoby wdrożenia własnego oprogramowania (np. Zeek, Suricata). Cloud IDS (A) jest gotowym, zarządzanym rozwiązaniem spełniającym ten wymóg.

Wskazówki i triki (Tips & Tricks):
- "Explore environment using network payloads" + "Google Cloud product" = Cloud IDS.
- "Threat detection" + "Managed service" = Cloud IDS.

Praktyczne informacje na egzamin:
- Cloud IDS jest zintegrowany z konsolą Google Cloud i wysyła alerty bezpośrednio do Cloud Logging oraz Security Command Center.
- Pamiętaj: Cloud IDS to system DETEKCJI (IDS), a nie prewencji (IPS). Nie blokuje on automatycznie ruchu, a jedynie o nim informuje.

Analiza i Podsumowanie (AI)

Kluczowe zagadnienia

Sugerowana odpowiedź: A

Analiza strategiczna: To pytanie testuje Twoją znajomość narzędzi do "Network Security Monitoring" (NSM). W ekosystemie GCP Cloud IDS jest pozycjonowany jako rozwiązanie premium dla firm, które potrzebują profesjonalnej ochrony sieciowej bez konieczności zarządzania własną flotą maszyn inspekcyjnych. Kluczowe jest zrozumienie, że IDS "widzi" to, czego nie "widzą" standardowe logi.

Dodatkowe wskazówki

  • Cloud IDS tworzy tzw. "endpoint" w Twojej sieci VPC, do którego ruch jest przekierowywany za pomocą automatycznie konfigurowanych reguł Packet Mirroring.
  • Alerty z Cloud IDS zawierają szczegółowe informacje o zagrożeniu, w tym linki do baz wiedzy o malware (np. CVE, silnik Unit 42).
