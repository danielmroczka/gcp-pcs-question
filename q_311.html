Question 311 / 361

Your organization is worried about recent news headlines regarding application vulnerabilities in production applications that have led to security breaches. You want to automatically scan your deployment pipeline for vulnerabilities and ensure only scanned and verified containers can run in the environment. What should you do?

  • A. Use Kubernetes role-based access control (RBAC) as the source of truth for cluster access by granting "container.clusters.get" to limited users. Restrict deployment access by allowing these users to generate a kubeconfig file containing the configuration access to the GKE cluster.
  • B. Use gcloud artifacts docker images describe LOCATION-docker.pkg.dev/PROJECT_ID/REPOSITORY/IMAGE_ID@sha256:HASH --show-package-vulnerability in your CI/CD pipeline, and trigger a pipeline failure for critical vulnerabilities.
  • C. Enforce the use of Cloud Code for development so users receive real-time security feedback on vulnerable libraries and dependencies before they check in their code.
  • D. Enable Binary Authorization and create attestations of scans.
Show Suggested Answer Hide Answer
Suggested Answer: D

Wyjaśnienie

Poprawna odpowiedź: D (Enable Binary Authorization and create attestations of scans.)

Dlaczego ta odpowiedź jest poprawna:
- Binary Authorization: To kluczowa usługa w GCP służąca do zapewnienia integralności łańcucha dostaw oprogramowania (Supply Chain Security). Wymusza ona, aby każdy kontener przed uruchomieniem w GKE posiadał podpisane zaświadczenie (attestation) o tym, że został poprawnie przeskanowany pod kątem podatności.
- "Scanned and verified containers": To definicja działania Binary Authorization. Jeśli kontener nie ma poprawnej atestacji (np. skanowanie nie wyszło czysto lub nie przeszło procesu CI/CD), GKE po prostu go nie uruchomi.

Analiza niepoprawnych odpowiedzi:
- A. RBAC: Zarządza dostępem do klastra, ale nie sprawdza bezpieczeństwa samych obrazów kontenerów.
- B. Gcloud description: To tylko sprawdzenie podatności. Sama komenda nie 'zablokuje' uruchomienia kontenera w GKE.
- C. Cloud Code: Zapewnia feedback dla deweloperów (IDE), ale nie gwarantuje wdrożenia bezpiecznego obrazu do produkcji w sposób wymuszony.

Wskazówki i triki (Tips & Tricks):
- "Only scanned and verified containers" + "Pipeline enforcement" = Binary Authorization.
- Zapamiętaj: Binary Authorization to brama bezpieczeństwa dla GKE.

Praktyczne informacje na egzamin:
- Zapamiętaj: Binary Authorization sprawdza sygnatury (atestacje) w momencie próby wdrożenia poda do klastra.

Sugerowana odpowiedź: D

Analiza strategiczna: To pytanie testuje Twoją wiedzę o zabezpieczaniu łańcucha dostaw oprogramowania (Supply Chain Security). Binary Authorization to "najtwardsza" metoda wymuszania standardów – jeśli obraz nie przejdzie przez bezpieczny proces CI/CD i nie zostanie podpisany, nie ma prawa zaistnieć w Twoim klastrze produkcyjnym.
