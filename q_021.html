Question 21 / 361

In order to meet PCI DSS requirements, a customer wants to ensure that all outbound traffic is authorized. Which two cloud offerings meet this requirement without additional compensating controls? (Choose two.)

  • A. App Engine
  • B. Cloud Functions
  • C. Compute Engine
  • D. Google Kubernetes Engine
  • E. Cloud Storage
Show Suggested Answer Hide Answer
Suggested Answer: CD

Wyjaśnienie

Potwierdzona odpowiedź: CD (Compute Engine oraz Google Kubernetes Engine)

Wyjaśnienie: 
Wymóg PCI DSS 1.2.1 nakłada obowiązek ścisłej kontroli ruchu wychodzącego (egress). 
- Compute Engine (C) oraz Google Kubernetes Engine (D) są usługami typu IaaS/CaaS, które działają wewnątrz sieci VPC. Pozwala to na bezpośrednie stosowanie reguł "VPC Firewall Rules" (Egress Deny All z wyjątkami), co zapewnia pełną kontrolę nad wychodzącym ruchem bez potrzeby wdrażania dodatkowych komponentów.

Dlaczego pozostałe są błędne:
- A, B (App Engine, Cloud Functions): Są usługami PaaS (serverless). W standardowej konfiguracji nie oferują bezpośredniej kontroli nad warstwą sieciową VPC. Aby je połączyć z VPC, wymagany jest "Serverless VPC Access Connector", co stanowi dodatkowy komponent sieciowy, a więc "compensating control" (kontrolę kompensacyjną), której pytanie zakazuje.
- E (Cloud Storage): Jest usługą typu object storage, która sama w sobie nie inicjuje ruchu sieciowego w taki sposób, jak środowiska wykonawcze kodu (Compute).

Wskazówki egzaminacyjne (Tips & Tricks):
- Jeśli pytanie o PCI DSS wyklucza "compensating controls", zawsze wybieraj usługi, które natywnie wspierają VPC Firewall Rules (Compute Engine, GKE).

Kluczowe zagadnienia do powtórzenia:
- PCI DSS w chmurze (Cloud Shared Responsibility Model).
- VPC Egress Firewall Rules.
- Ograniczenia usług serverless w kontekście sieciowym.

Dokumentacja:
VPC Firewall Rules

**Reguła Egzaminacyjna (Exam Rule):**
Zawsze identyfikuj warstwę modelu OSI, na której operuje atak oraz rozwiązanie. DNSSEC działa na poziomie warstwy aplikacji dla DNS, zapobiegając zatruwaniu pamięci podręcznej (Cache Poisoning).

**Haczyki egzaminacyjne (Exam Traps):**
- Mylenie Cloud Armor (WAF - L7) z zabezpieczeniami DNS (DNSSEC - integralność danych DNS).
- Zakładanie, że TLS/SSL wystarczy do ochrony przed przekierowaniem całego ruchu DNS (DNSSEC zabezpiecza sam proces rezolucji, zanim nawiążesz bezpieczne połączenie TLS).

**Głębokie wyjaśnienie techniczne:**
DNSSEC wykorzystuje kryptografię klucza publicznego (RRSIG, DNSKEY, DS) do cyfrowego podpisywania rekordów DNS w strefach (Zone Signing). Dzięki temu resolver DNS może zweryfikować łańcuch zaufania aż do punktu głównego (root zone) bez konieczności polegania wyłącznie na adresie IP serwera autorytatywnego, co drastycznie ogranicza skuteczność ataków typu MITM i cache poisoning.

Analiza spornych kwestii (AI): Głównym punktem debaty jest to, co Google uznaje za "dodatkową kontrolę". W oficjalnych materiałach szkoleniowych GCP, VPC Access Connector jest traktowany jako dodatkowy element infrastruktury, który trzeba wdrożyć i nim zarządzać, stąd przewaga Compute Engine i GKE, które mają natywny dostęp do VPC.
