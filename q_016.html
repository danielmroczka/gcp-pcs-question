Question 16 / 361

An organization's typical network and security review consists of analyzing application transit routes, request handling, and firewall rules. They want to enable their developer teams to deploy new applications without the overhead of this full review. How should you advise this organization?

  • A. Use Forseti with Firewall filters to catch any unwanted configurations in production.
  • B. Mandate use of infrastructure as code and provide static analysis in the CI/CD pipelines to enforce policies.
  • C. Route all VPC traffic through customer-managed routers to detect malicious patterns in production.
  • D. All production applications will run on-premises. Allow developers free rein in GCP as their dev and QA platforms.
Show Suggested Answer Hide Answer
Suggested Answer: B

Wyjaśnienie

**Poprawna odpowiedź: B**

**1. Kompleksowe wyjaśnienie poprawnej odpowiedzi:**
Organizacja chce umożliwić deweloperom samodzielne wdrażanie aplikacji przy jednoczesnym automatycznym egzekwowaniu reguł bezpieczeństwa (sieć, zapory, trasy) bez narzutu czasochłonnych, ręcznych przeglądów bezpieczeństwa:
- **Wprowadzenie zasad Infrastructure as Code (IaC) oraz wdrożenie analizy statycznej w potokach CI/CD do egzekwowania polityk (B):** Użycie narzędzi takich jak Terraform (IaC) pozwala na deklaratywne definiowanie zasobów. Skanowanie kodu infrastruktury w potoku CI/CD (np. za pomocą narzędzi do analizy statycznej/polityk takich jak Terraform Validator, Checkov czy OPA) pozwala automatycznie zablokować wdrożenia naruszające reguły bezpieczeństwa zanim trafią one do chmury. Daje to deweloperom szybkość, a zespołowi bezpieczeństwa pełną kontrolę.

**2. Wyjaśnienie niepoprawnych odpowiedzi:**
- **A. Forseti w środowisku produkcyjnym:** Forseti to doskonałe narzędzie, ale działa reaktywnie (wykrywa błędy konfiguracji już po ich wdrożeniu na produkcji). Nie zapobiega to wdrożeniu błędnych konfiguracji, a jedynie o nich raportuje.
- **C. Kierowanie ruchu przez własne routery:** Wprowadza to ogromny narzut wydajnościowy, dodatkowe punkty awarii i nie rozwiązuje problemu wdrożeń niezgodnych z politykami.
- **D. Praca w chmurze tylko dla Dev/QA, a produkcja on-premises:** To podejście neguje korzyści z migracji do chmury i nie rozwiązuje problemu automatyzacji kontroli w środowiskach deweloperskich.

**3. Wskazówki i pułapki egzaminacyjne (Tips & Tricks):**
- Nowoczesne bezpieczeństwo w chmurze stawia na podejście **Shift-Left** – czyli wykrywanie błędów konfiguracji jak najwcześniej (w fazie kodu / CI/CD pipeline), a nie po wdrożeniu.
- Statyczna analiza kodu infrastruktury (IaC static analysis) w potokach CI/CD to złoty standard automatycznego egzekwowania polityk (Policy as Code).

**4. Reguły wyboru odpowiedzi:**
- Bezpieczne wdrożenia bez ręcznego przeglądu -> Automatyczne testy polityk w CI/CD + Infrastructure as Code.
