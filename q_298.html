Question 298 / 361

A security audit uncovered several inconsistencies in your project's Identity and Access Management (IAM) configuration. Some service accounts have overly permissive roles, and a few external collaborators have more access than necessary. You need to gain detailed visibility into changes to IAM policies, user activity, service account behavior, and access to sensitive projects. What should you do?

  • A. Configure Google Cloud Functions to be triggered by changes to IAM policies. Analyze changes by using the policy simulator, send alerts upon risky modifications, and store event details.
  • B. Enable the metrics explorer in Cloud Monitoring to follow the service account authentication events and build alerts linked on it.
  • C. Use Cloud Audit Logs. Create log export sinks to send these logs to a security information and event management (SIEM) solution for correlation with other event sources.
  • D. Deploy the OS Config Management agent to your VMs. Use OS Config Management to create patch management jobs and monitor system modifications.
Show Suggested Answer Hide Answer
Suggested Answer: C

Wyjaśnienie

1. Prawidłowa odpowiedź lub odpowiedzi:
C. Use Cloud Audit Logs. Create log export sinks to send these logs to a security information and event management (SIEM) solution for correlation with other event sources.

2. Kompleksowe wyjaśnienie dlaczego dana odpowiedź jest prawidłowa (Analiza):
Odpowiedź C jest prawidłowa, ponieważ Cloud Audit Logs rejestruje wszystkie istotne zdarzenia związane z modyfikacjami polityk IAM, działaniami użytkowników oraz zachowaniem kont serwisowych w Google Cloud.

Dlaczego to najlepsza metoda dochodzeniowa:
a. **Pełne pokrycie (Visibility):** Logi audytowe Admin Activity oraz Data Access rejestrują wywołania API (kto, co, kiedy, z jakiego IP). Każda zmiana uprawnień w IAM oraz każda próba dostępu do danych w projektach zostaje zapisana.
b. **Integracja z SIEM (Correlation):** Przesłanie tych logów za pomocą log sinks (odbiorników logów) do zewnętrznego systemu SIEM pozwala na korelację tych danych z logami z innych systemów firmy (np. logowania do VPN, lokalny Active Directory). Umożliwia to wykrycie zaawansowanych ataków (np. logowanie na konto serwisowe z IP z innego kraju zaraz po tym, jak inżynier zalogował się lokalnie).

3. Wyjaśnienie z osobna każdej niepoprawnej odpowiedzi:
A. Configure Google Cloud Functions to be triggered by changes to IAM policies. Analyze changes by using the policy simulator...
   * Dlaczego nieprawidłowa: Policy Simulator służy do testowania wpływu proponowanych zmian w IAM przed ich zastosowaniem (np. czy dodanie roli nie da komuś zbyt szerokiego dostępu). Nie służy do ciągłego monitorowania w czasie rzeczywistym i analizowania faktycznie zaistniałych zdarzeń na kontach serwisowych po ich wykonaniu.
B. Enable the metrics explorer in Cloud Monitoring to follow the service account authentication events...
   * Dlaczego nieprawidłowa: Cloud Monitoring zbiera metryki wydajnościowe (np. zużycie CPU, liczba zapytań na sekundę). Metryki te są agregowane i nie zawierają szczegółowych danych audytowych (kto dokładnie dokonał zmiany w IAM, jaki był adres IP, jaki był payload żądania), co uniemożliwia analizę śledczą incydentu.
D. Deploy the OS Config Management agent to your VMs. Use OS Config Management to create patch management jobs...
   * Dlaczego nieprawidłowa: OS Config Management (VM Manager) służy do zarządzania systemami operacyjnymi maszyn wirtualnych (np. instalowanie poprawek). Nie monitoruje zmian w politykach IAM na poziomie platformy Google Cloud ani nie analizuje dostępu do wrażliwych projektów.

4. Wskazówki, hinty, tips and tricks:
* Szczegółowa widoczność zmian IAM, operacji użytkowników i kont serwisowych (visibility into IAM changes and user activity) -> Zawsze używaj **Cloud Audit Logs**.
* Analiza bezpieczeństwa i korelacja zdarzeń w skali przedsiębiorstwa -> Eksport logów do **SIEM**.

5. Reguły wyboru odpowiedzi (Słowa kluczowe):
* Visibility into changes to IAM + user activity + service account behavior -> Cloud Audit Logs + export to SIEM.

Wskazówki egzaminacyjne (Tips & Tricks)

Reguła Egzaminacyjna (Exam Rule): 
W pytaniach typu 'Security in GCP', zawsze priorytetyzuj rozwiązania natywne (SCC, Cloud KMS, Secret Manager, VPC SC) nad rozwiązaniami typu 'third-party' lub 'self-managed', chyba że scenariusz wymaga specyficznej integracji hybrydowej.

Haczyki egzaminacyjne (Exam Traps):
- Pułapka 'Least Privilege': Egzamin często podpowiada role o szerokim zakresie (np. 'Editor' lub 'Owner') – zawsze odrzucaj je na rzecz ról predefiniowanych o najmniejszym zakresie uprawnień.
- Pułapka 'Logging vs Monitoring': Pamiętaj: Audit Logs służą do badania aktywności (Who/What/When), a Monitoring do zbierania metryk wydajnościowych.

Głębokie wyjaśnienie techniczne:
Każda architektura bezpieczeństwa w GCP powinna być projektowana w oparciu o 'Security by Default'. Oznacza to m.in. szyfrowanie w spoczynku (domyślne), tożsamość opartą na rolach (IAM) oraz pełną widoczność zapewnianą przez scentralizowane logowanie (Cloud Logging/SCC).

Analiza i Podsumowanie (AI)

Kluczowe zagadnienia

Sugerowana odpowiedź: C

Analiza strategiczna: Pytanie dotyczy podstaw monitoringu bezpieczeństwa (Monitoring & Logging). W środowiskach enterprise logi audytowe muszą być nie tylko zbierane, ale i eksportowane do centralnych systemów analitycznych (SIEM) w celu zapewnienia niezaprzeczalności i możliwości korelacji.
