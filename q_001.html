Question 1 / 361

Your team needs to make sure that a Compute Engine instance does not have access to the internet or to any Google APIs or services. Which two settings must remain disabled to meet these requirements? (Choose two.)

  • A. Public IP
  • B. IP Forwarding
  • C. Private Google Access
  • D. Static routes
Show Suggested Answer Hide Answer
Suggested Answer: AC

Wyjaśnienie

**Poprawna odpowiedź: AC**

**1. Kompleksowe wyjaśnienie poprawnej odpowiedzi:**
Aby całkowicie zablokować instancji Compute Engine (VM) dostęp do internetu oraz do jakichkolwiek usług lub API Google, konieczne jest wyłączenie dwóch kluczowych ustawień sieciowych:
- **Public IP (A):** Brak przypisanego publicznego adresu IP uniemożliwia bezpośrednie, dwukierunkowe przesyłanie pakietów między instancją a zewnętrznym internetem. Instancja bez publicznego IP nie może inicjować połączeń ze światem zewnętrznym, chyba że zastosowano bramę NAT lub proxy.
- **Private Google Access (C):** Jest to funkcja włączana na poziomie podsieci (subnet), która umożliwia instancjom posiadającym wyłącznie prywatne adresy IP komunikację z publicznymi adresami IP usług i interfejsów API Google (np. Cloud Storage, BigQuery, KMS). Wyłączenie tej opcji gwarantuje, że instancja nie będzie mogła połączyć się z usługami Google przez sieć prywatną.

**2. Wyjaśnienie niepoprawnych odpowiedzi:**
- **B. IP Forwarding (Przekazywanie IP):** Umożliwia instancji odbieranie i przekazywanie pakietów zaadresowanych do innych maszyn (wymagane np. przy budowie własnych routerów lub programowych bram NAT). Wyłączenie tego ustawienia nie ogranicza bezpośredniego dostępu samej instancji do internetu ani API Google.
- **D. Static routes (Trasy statyczne):** Służą do kierowania ruchu wewnątrz sieci VPC i poza nią (np. do sieci lokalnej przez VPN). Choć usunięcie tras mogłoby zakłócić routing, samo wyłączenie tras statycznych nie jest natywną metodą blokowania dostępu do internetu ani usług Google (który domyślnie jest obsługiwany przez trasę domyślną i Private Google Access).

**3. Wskazówki i pułapki egzaminacyjne (Tips & Tricks):**
- Jeśli na egzaminie pojawia się warunek braku dostępu do *Google Services / APIs* z instancji bez publicznego IP, kluczowym pojęciem zawsze jest **Private Google Access (PGA)**.
- Pamiętaj, że usługi Google (takie jak Cloud Storage czy BigQuery) posiadają publiczne adresy IP, a PGA to jedyny sposób, by maszyny z prywatnym IP mogły do nich dotrzeć bez bramy NAT.

**4. Reguły wyboru odpowiedzi:**
- Blokowanie internetu -> Wyłącz Public IP.
- Blokowanie usług Google (bez NAT) -> Wyłącz Private Google Access.

**5. Dodatkowe źródła:**
- Dokumentacja Google Cloud: https://cloud.google.com/vpc/docs/private-google-access

Analiza i Podsumowanie Dyskusji (AI)

Analiza i Wyjaśnienie

Sugerowana odpowiedź: AC

Analiza spornych kwestii (AI): Głównym punktem debaty w sieci jest to, czy wyłączenie PGA wystarczy. Eksperci zauważają, że w nowoczesnych sieciach GCP istnieje również Private Service Connect (PSC), który mógłby być trzecią drogą wyjścia, ale nie ma go w opcjach. Dlatego AC pozostaje jedyną poprawną odpowiedzią w ramach dostępnego zestawu. Pułapką jest tu opcja D – trasy statyczne są potrzebne do komunikacji wewnątrz VPC, ich wyłączenie to 'przysłowiowe spalenie mostu', a nie precyzyjna kontrola dostępu.
