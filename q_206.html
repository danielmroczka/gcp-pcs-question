Question 206 / 361

You manage a BigQuery analytical data warehouse in your organization. You want to keep data for all your customers in a common table while you also restrict query access based on rows and columns permissions. Non-query operations should not be supported.

  • A. Create row-level access policies to restrict the result data when you run queries with the filter expression set to TRUE.
  • B. Configure column-level encryption by using Authenticated Encryption with Associated Data (AEAD) functions with Cloud Key Management Service (KMS) to control access to columns at query runtime.
  • C. Create row-level access policies to restrict the result data when you run queries with the filter expression set to FALSE.
  • D. Configure dynamic data masking rules to control access to columns at query runtime.
  • E. Create column-level policy tags to control access to columns at query runtime.
Show Suggested Answer Hide Answer
Suggested Answer: CE

Wyjaśnienie

1. Prawidłowa odpowiedź lub odpowiedzi:
C. Create row-level access policies to restrict the result data when you run queries with the filter expression set to FALSE.
E. Create column-level policy tags to control access to columns at query runtime.

2. Kompleksowe wyjaśnienie dlaczego dana odpowiedź jest prawidłowa (Analiza):
Odpowiedzi C i E są prawidłowe, ponieważ stanowią natywne i zalecane mechanizmy Google Cloud do wdrażania zaawansowanej kontroli dostępu na poziomie wierszy i kolumn w BigQuery dla wspólnych tabel.

Szczegóły rozwiązań:
a. **Polityki dostępu na poziomie wiersza (Row-level access policies) (C):** Pozwalają na filtrowanie wierszy zwracanych użytkownikom na podstawie ich tożsamości. Przykładowo, filtr `country = 'PL'` sprawi, że użytkownik z Polski zobaczy tylko te wiersze. Zastosowanie filtru domyślnego dla nieautoryzowanych zapytań (lub jawne zdefiniowanie polityki z filtrem dającym wynik logiczny `FALSE` dla niepasujących warunków) gwarantuje, że nieuprawnieni użytkownicy nie zobaczą żadnych danych.
b. **Tagi polityki na poziomie kolumny (Column-level policy tags) (E):** Pozwalają na przypisywanie taksonomii bezpieczeństwa (Data Catalog) do poszczególnych kolumn w tabeli BigQuery. Użytkownik, który nie posiada roli `Fine-Grained Reader` dla danego tagu, otrzyma błąd przy próbie wykonania zapytania odwołującego się do tej kolumny. Chroni to dane wrażliwe (np. numery PESEL czy kart kredytowych) bez konieczności tworzenia oddzielnych tabel.

3. Wyjaśnienie z osobna każdej niepoprawnej odpowiedzi:
A. Create row-level access policies... filter expression set to TRUE.
   * Dlaczego nieprawidłowa: Ustawienie wyrażenia filtrującego na `TRUE` spowodowałoby, że polityka zezwalałaby wszystkim dopasowanym tożsamościom na zobaczenie wszystkich wierszy w tabeli, co całkowicie niweczy cel segmentacji danych klientów.
B. Configure column-level encryption by using AEAD functions with Cloud KMS...
   * Dlaczego nieprawidłowa: Szyfrowanie AEAD z KMS na poziomie zapytań wymaga skomplikowanego zarządzania kluczami w locie i modyfikacji kodu zapytań SQL przez użytkowników. Jest to znacznie trudniejsze w implementacji i zarządzaniu niż natywne Column-level policy tags.
D. Configure dynamic data masking rules to control access to columns at query runtime.
   * Dlaczego nieprawidłowa: Maskowanie danych (Data Masking) modyfikuje zwracane wartości (np. zastępuje cyfry znakami 'X'), ale nie blokuje całkowicie dostępu do kolumny w sposób tak restrykcyjny i oparty na taksonomii jak tagi polityk. Pytanie dotyczy restrykcji dostępu (query access restriction) w trybie bez wsparcia dla operacji modyfikacji danych.

4. Wskazówki, hinty, tips and tricks:
* Bezpieczeństwo w BigQuery:
  - Poziom wierszy -> **Row-level security / Row-level access policies**.
  - Poziom kolumn -> **Column-level security / Policy tags (Data Catalog)**.
* Kiedy stosujesz row-level security na tabeli, domyślny dostęp do wierszy dla wszystkich innych użytkowników (którzy nie są objęci żadną regułą) zostaje całkowicie zablokowany.

5. Reguły wyboru odpowiedzi (Słowa kluczowe):
* BigQuery segmentacja danych (wiersze i kolumny) -> Row-level access policies + Column-level policy tags.
