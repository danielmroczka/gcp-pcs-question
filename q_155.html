Question 155 / 361

You want to make sure that your organization's Cloud Storage buckets cannot have data publicly available to the internet. You want to enforce this across all Cloud Storage buckets. What should you do?

  • A. Remove Owner roles from end users, and configure Cloud Data Loss Prevention.
  • B. Remove Owner roles from end users, and enforce domain restricted sharing in an organization policy.
  • C. Configure uniform bucket-level access, and enforce domain restricted sharing in an organization policy.
  • D. Remove *.setIamPolicy permissions from all roles, and enforce domain restricted sharing in an organization policy.
Show Suggested Answer Hide Answer
Suggested Answer: C

Wyjaśnienie

1. Prawidłowa odpowiedź lub odpowiedzi:
C. Configure uniform bucket-level access, and enforce domain restricted sharing in an organization policy.

2. Kompleksowe wyjaśnienie dlaczego dana odpowiedź jest prawidłowa (Analiza):
Należy uniemożliwić użytkownikom udostępnianie jakichkolwiek danych z kubłów Cloud Storage publicznie do internetu w skali całej organizacji:
- Krok 1 (Uniform bucket-level access - UBLA): Włączenie UBLA wyłącza obsługę list kontroli dostępu (ACL) dla obiektów w kubełku. Sprawia to, że uprawnienia można nadawać wyłącznie na poziomie całego kubełka za pomocą polityk IAM, eliminując ryzyko, że użytkownik udostępni pojedynczy plik publicznie poprzez ACL.
- Krok 2 (Domain Restricted Sharing - DRS): Ta polityka organizacji (`constraints/iam.allowedPolicyMemberDomains`) blokuje możliwość przypisywania ról IAM dla tożsamości spoza dozwolonych domen (np. uniemożliwia dodanie do roli czytelnika tożsamości `allUsers` lub `allAuthenticatedUsers`, które reprezentują cały publiczny internet).
Połączenie UBLA i DRS całkowicie uniemożliwia publiczne udostępnienie kubełka lub jego zawartości.

3. Wyjaśnienie z osobna każdej niepoprawnej odpowiedzi:
- A. Usunięcie ról właściciela (Owner) i konfiguracja Cloud DLP: Usunięcie ról Owner jest dobrą praktyką, ale edytorzy (Editors) lub Storage Admini nadal mogliby omyłkowo zmienić politykę IAM na publiczną. Cloud DLP skanuje zawartość w celu wykrycia PII, ale nie blokuje technicznej możliwości upublicznienia plików.
- B. Brak UBLA: Bez wymuszenia jednolitego dostępu (UBLA), użytkownicy mogą nadal korzystać z drobnoziarnistych list ACL na poszczególnych plikach wewnątrz kubełka. Polityka Domain Restricted Sharing chroni tylko polityki IAM, więc użytkownik mógłby upublicznić plik bezpośrednio za pomocą ACL (np. public-read).
- D. Odebranie uprawnień `*.setIamPolicy`: Całkowicie uniemożliwiłoby to jakąkolwiek konfigurację uprawnień i zarządzanie dostępem do kubłów dla administratorów, paraliżując pracę firmy.

4. Wskazówki, hinty, tips and tricks:
- Aby skutecznie zablokować publiczny dostęp do Cloud Storage na poziomie organizacji, musisz zamknąć obie drogi udostępniania:
  1. Wyłącz ACL-e (włącz **Uniform bucket-level access**).
  2. Zablokuj publiczne tożsamości w IAM (włącz **Domain Restricted Sharing**).

5. Reguły wyboru odpowiedzi (Słowa kluczowe):
- Całkowita blokada publicznego dostępu do Cloud Storage -> Uniform bucket-level access + Domain Restricted Sharing.
