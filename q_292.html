Question 292 / 361

You are implementing a new web application on Google Cloud that will be accessed from your on-premises network. To provide protection from threats like malware, you must implement transport layer security (TLS) interception for incoming traffic to your application. What should you do?

  • A. Configure Secure Web Proxy. Offload the TLS traffic in the load balancer, inspect the traffic, and forward the traffic to the web application.
  • B. Configure an internal proxy load balancer. Offload the TLS traffic in the load balancer inspect, the traffic and forward the traffic to the web application.
  • C. Configure a hierarchical firewall policy. Enable TLS interception by using Cloud Next Generation Firewall (NGFW) Enterprise.
  • D. Configure a VPC firewall rule. Enable TLS interception by using Cloud Next Generation Firewall (NGFW) Enterprise.
Show Suggested Answer Hide Answer
Suggested Answer: C

Wyjaśnienie

1. Prawidłowa odpowiedź lub odpowiedzi:
C. Configure a hierarchical firewall policy. Enable TLS interception by using Cloud Next Generation Firewall (NGFW) Enterprise.

2. Kompleksowe wyjaśnienie dlaczego dana odpowiedź jest prawidłowa (Analiza):
Odpowiedź C jest prawidłowa, ponieważ Cloud Next Generation Firewall (NGFW) Enterprise jest jedynym natywnym rozwiązaniem sieciowym w GCP, które wspiera funkcję deszyfrowania i inspekcji ruchu TLS (TLS Interception / TLS Decryption).

Jak to działa:
a. **NGFW Enterprise:** Usługa ta działa na poziomie infrastruktury sieciowej GCP i pozwala na inspekcję ruchu przychodzącego (ingress) oraz wychodzącego (egress).
b. **TLS Interception:** Zapora sieciowa deszyfruje ruch TLS w locie przy użyciu zintegrowanego Certificate Managera, przeprowadza głęboką inspekcję pakietów (Deep Packet Inspection - DPI) w poszukiwaniu wirusów, malware i włamań, a następnie ponownie szyfruje ruch i przesyła go do aplikacji docelowej.
c. **Konfiguracja hierarchiczna:** Wdrożenie tej funkcji wymaga skonfigurowania polityki hierarchicznej zapory sieciowej (Hierarchical Firewall Policy) na poziomie folderu lub organizacji, co pozwala na centralne narzucenie inspekcji dla całego ruchu.

3. Wyjaśnienie z osobna każdej niepoprawnej odpowiedzi:
A. Configure Secure Web Proxy. Offload the TLS traffic...
   * Dlaczego nieprawidłowa: Secure Web Proxy (SWP) służy do filtrowania i zabezpieczania wychodzącego (egress) ruchu internetowego z maszyn w chmurze. Nie jest przeznaczony do przechwytywania i zabezpieczania ruchu przychodzącego (incoming traffic) od użytkowników zewnętrznych do aplikacji webowej.
B. Configure an internal proxy load balancer...
   * Dlaczego nieprawidłowa: Internal HTTPS Load Balancer terminuje połączenie TLS (TLS offloading), ale nie służy do głębokiej inspekcji pakietów (Deep Packet Inspection) pod kątem zagrożeń i malware w locie – po prostu przekazuje odszyfrowany ruch HTTP do backendu. Nie realizuje funkcji aktywnego TLS interception w celach bezpieczeństwa NGFW.
D. Configure a VPC firewall rule. Enable TLS interception...
   * Dlaczego nieprawidłowa: Klasyczne, standardowe reguły zapory sieciowej VPC (VPC Firewall Rules) działają na poziomie warstw L3/L4 i nie posiadają zaawansowanych funkcji warstwy L7, takich jak deszyfrowanie i inspekcja ruchu TLS (TLS Interception). Funkcja ta jest dostępna wyłącznie w Cloud NGFW Enterprise za pośrednictwem polityk hierarchicznych.

4. Wskazówki, hinty, tips and tricks:
* Intercepcja i deszyfrowanie ruchu TLS (TLS Interception / Decryption) w celu wykrywania malware w GCP -> Zawsze **Cloud Next Generation Firewall (NGFW) Enterprise**.
* Funkcja ta wymaga integracji z Certificate Managerem do generowania certyfikatów w locie.

5. Reguły wyboru odpowiedzi (Słowa kluczowe):
* Implement TLS interception for incoming traffic -> Hierarchical firewall policy + Cloud Next Generation Firewall (NGFW) Enterprise.
