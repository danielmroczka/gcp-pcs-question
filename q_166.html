Question 166 / 361

You have been tasked with inspecting IP packet data for invalid or malicious content. What should you do?

  • A. Use Packet Mirroring to mirror traffic to and from particular VM instances. Perform inspection using security software that analyzes the mirrored traffic.
  • B. Enable VPC Flow Logs for all subnets in the VPC. Perform inspection on the Flow Logs data using Cloud Logging.
  • C. Configure the Fluentd agent on each VM Instance within the VPC. Perform inspection on the log data using Cloud Logging.
  • D. Configure Google Cloud Armor access logs to perform inspection on the log data.
Show Suggested Answer Hide Answer
Suggested Answer: A

Wyjaśnienie

Poprawna odpowiedź: A (Use Packet Mirroring to mirror traffic to and from particular VM instances)

Dlaczego ta odpowiedź jest poprawna:
- Packet Mirroring: Jest to usługa Google Cloud, która klonuje ruch sieciowy (zarówno przychodzący, jak i wychodzący) z konkretnych instancji VM, podsieci lub tagów i przesyła go do wybranego celu (zazwyczaj Load Balancera przed grupą instancji inspekcyjnych).
- Deep Packet Inspection (DPI): Aby wykryć "złośliwą zawartość" (malicious content) wewnątrz pakietów IP, potrzebujesz dostępu do całej treści pakietu (payload), a nie tylko do nagłówków. Rozwiązania klasy IDS (Intrusion Detection System) lub IPS (Intrusion Prevention System) wymagają właśnie pełnych pakietów dostarczanych przez Packet Mirroring, aby móc przeanalizować je pod kątem sygnatur ataków lub anomalii.

Analiza niepoprawnych odpowiedzi:
- B. VPC Flow Logs: Logi przepływu zawierają metadane o połączeniach (IP źródłowe/docelowe, porty, protokół, liczba bajtów, czas), ale NIE zawierają samej treści pakietów. Nie pozwalają więc na inspekcję zawartości pod kątem malware czy exploitów.
- C. Fluentd agent: Jest to agent zbierający logi systemowe i aplikacyjne (pliki tekstowe). Nie służy on do przechwytywania i analizowania surowych pakietów sieciowych na poziomie warstwy IP.
- D. Cloud Armor access logs: Cloud Armor działa na poziomie warstwy 7 (HTTP/S) dla Load Balancera. Jego logi pokazują szczegóły żądań webowych, ale nie dają wglądu w surowe pakiety IP dla całego ruchu sieciowego wewnątrz VPC.

Wskazówki i triki (Tips & Tricks):
- "Inspect packet data" / "Malicious content" + "Network level" = Packet Mirroring.
- "Metadata" / "Connection info" = VPC Flow Logs.
- "L7 protection" / "WAF" = Cloud Armor.

Praktyczne informacje na egzamin:
- Packet Mirroring nie wpływa na wydajność mirrorowanych maszyn, ponieważ odbywa się na poziomie infrastruktury sieciowej Google (SDN).
- Pamiętaj, że ruch mirrorowany jest płatny (koszt za GB przetworzonych danych).
- Mirrorowanie odbywa się w obrębie tego samego VPC (lub przez VPC Peering).

Analiza i Podsumowanie (AI)

Kluczowe zagadnienia

Sugerowana odpowiedź: A

Analiza strategiczna: To pytanie sprawdza różnicę między monitorowaniem "gdzie idzie ruch" (Flow Logs) a analizowaniem "co jest w środku ruchu" (Packet Mirroring). W nowoczesnych architekturach bezpieczeństwa w GCP, Packet Mirroring jest kluczowym elementem integracji z zewnętrznymi systemami IDS/IPS (np. Palo Alto, Check Point, Suricata).

Dodatkowe wskazówki

  • Warto wiedzieć, że Cloud IDS to natywna usługa Google, która "pod spodem" wykorzystuje Packet Mirroring i silnik Palo Alto Networks do automatycznego wykrywania zagrożeń.
  • Packet Mirroring może mirrorować zarówno ruch wewnątrz VPC (East-West), jak i ruch wychodzący/przychodzący do internetu (North-South).
