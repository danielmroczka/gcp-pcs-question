Question 22 / 361

A website design company recently migrated all customer sites to App Engine. Some sites are still in progress and should only be visible to customers and company employees from any location. Which solution will restrict access to the in-progress sites?

  • A. Upload an .htaccess file to App Engine.
  • B. Create an App Engine firewall rule.
  • C. Enable Cloud Identity-Aware Proxy (IAP).
  • D. Use Cloud VPN.
Show Suggested Answer Hide Answer
Suggested Answer: C

Wyjaśnienie

**Poprawna odpowiedź: C**

**1. Kompleksowe wyjaśnienie poprawnej odpowiedzi:**
Wymagane jest ograniczenie dostępu do niedokończonych stron hostowanych w App Engine tylko dla klientów i pracowników z **dowolnej lokalizacji**:
- **Włączenie Cloud Identity-Aware Proxy (IAP) (C):** Jest to najlepsze i zgodne z zaleceniami chmurowymi rozwiązanie. IAP kontroluje dostęp do aplikacji na podstawie tożsamości użytkownika (konto Google/Workspace) oraz przypisanych ról IAM. Ponieważ autoryzacja odbywa się na poziomie tożsamości, użytkownicy mogą bezpiecznie logować się z dowolnego miejsca na świecie bez konieczności korzystania z sieci VPN czy posiadania statycznego IP.

**2. Wyjaśnienie niepoprawnych odpowiedzi:**
- **A. Upload pliku .htaccess:** Pliki `.htaccess` są specyficzne dla serwera Apache. App Engine nie korzysta z Apache i nie interpretuje plików `.htaccess`.
- **B. App Engine firewall rule:** Reguły zapory App Engine filtrują ruch wyłącznie po adresach IP. Ponieważ klienci i pracownicy mogą łączyć się z "dowolnej lokalizacji" (np. z domów, kawiarni z dynamicznymi IP), zarządzanie regułami firewall dla setek zmieniających się adresów IP jest niemożliwe i nieskuteczne.
- **D. Cloud VPN:** Wdrożenie VPN wymagałoby od każdego klienta zewnętrznego instalacji i konfiguracji oprogramowania VPN, co jest zbyt inwazyjne, trudne do wdrożenia u klientów i niepotrzebnie skomplikowane w porównaniu z IAP.

**3. Wskazówki i pułapki egzaminacyjne (Tips & Tricks):**
- Słowo-klucz: **from any location** (z dowolnej lokalizacji). Filtrowanie po IP (Firewall) odpada w scenariuszach pracy mobilnej/zdalnej.
- Cloud IAP realizuje model bezpieczeństwa **Zero Trust** (BeyondCorp) na poziomie warstwy aplikacyjnej.

**4. Reguły wyboru odpowiedzi:**
- Dostęp dla uprawnionych użytkowników z dowolnego IP -> Cloud IAP.

**5. Dodatkowe źródła:**
- Dokumentacja Cloud IAP dla App Engine: https://cloud.google.com/iap/docs/app-engine-quickstart

Analiza i Podsumowanie Dyskusji (AI)

Analiza i Wyjaśnienie

Sugerowana odpowiedź: C

Analiza spornych kwestii (AI): Kluczowym elementem pytania jest "any location". Każda próba filtrowania po IP (opcja B) zawiedzie w świecie pracy zdalnej. IAP przesuwa punkt kontroli z adresu sieciowego (IP) na tożsamość użytkownika (Konto Google), co jest fundamentem nowoczesnego bezpieczeństwa chmurowego.
