Question 284 / 361

You are responsible for a set of Cloud Functions running on your organization's Google Cloud environment. During the last annual security review, secrets were identified in environment variables of some of these Cloud Functions. You must ensure that secrets are identified in a timely manner. What should you do?

  • A. Implement regular peer reviews to assess the environment variables and identify secrets in your Cloud Functions. Raise a security incident if secrets are discovered.
  • B. Implement a Cloud Function that scans the environment variables multiple times a day, and creates a finding in Security Command Center if secrets are discovered.
  • C. Use Sensitive Data Protection to scan the environment variables multiple times per day, and create a finding in Security Command Center if secrets are discovered.
  • D. Integrate dynamic application security testing into the CI/CD pipeline that scans the application code for the Cloud Functions. Fail the build process if secrets are discovered.
Show Suggested Answer Hide Answer
Suggested Answer: C

Wyjaśnienie

1. Prawidłowa odpowiedź lub odpowiedzi:
C. Use Sensitive Data Protection to scan the environment variables multiple times per day, and create a finding in Security Command Center if secrets are discovered.

2. Kompleksowe wyjaśnienie dlaczego dana odpowiedź jest prawidłowa (Analiza):
Odpowiedź C jest prawidłowa, ponieważ Sensitive Data Protection (dawniej Cloud Data Loss Prevention - Cloud DLP) jest natywną usługą GCP stworzoną do automatycznego wykrywania danych wrażliwych (w tym kluczy API, haseł, sekretów i tokenów kryptograficznych) w nieustrukturyzowanych metadanych i plikach.

Dlaczego to najlepsza metoda:
a. **Inspekcja metadanych:** Skaner Sensitive Data Protection potrafi odczytywać konfigurację zasobów (w tym zmienne środowiskowe Cloud Functions) i analizować je pod kątem występowania wzorców sekretów (np. infoType `OAUTH_CLIENT_SECRET` lub wzorce kluczy prywatnych).
b. **Automatyzacja i powiadomienia:** Konfigurując regularne zadania skanowania i integrując je z Security Command Center (SCC), organizacja uzyskuje ciągły i zautomatyzowany monitoring (compliance control), który wykryje naruszenie zasad bezpieczeństwa bez udziału człowieka.

3. Wyjaśnienie z osobna każdej niepoprawnej odpowiedzi:
A. Implement regular peer reviews to assess the environment variables...
   * Dlaczego nieprawidłowa: Przeglądy kodu i konfiguracji przez inżynierów (peer reviews) są procesem czysto manualnym, wolnym i podatnym na błędy ludzkie. Nie spełnia to warunku wykrywania zagrożeń "w odpowiednim czasie" (in a timely manner) dla dynamicznie zmieniających się konfiguracji w chmurze.
B. Implement a Cloud Function that scans the environment variables...
   * Dlaczego nieprawidłowa: Budowanie własnej funkcji Cloud Function skanującej API w pętli wymaga napisania dedykowanego kodu, utrzymywania go, obsługi uprawnień i obsługi bibliotek detekcji sekretów. Jest to nieefektywne, ponieważ Google udostępnia już gotową i zoptymalizowaną usługę Sensitive Data Protection do tego celu.
D. Integrate dynamic application security testing into the CI/CD pipeline...
   * Dlaczego nieprawidłowa: Testy DAST (Dynamic Application Security Testing) analizują działającą aplikację z zewnątrz (np. symulując ataki HTTP). Nie mają one wglądu w wewnętrzne zmienne środowiskowe zdefiniowane w konfiguracji chmurowej Cloud Functions w konsoli GCP.

4. Wskazówki, hinty, tips and tricks:
* Wykrywanie kluczy, haseł i sekretów w plikach lub konfiguracjach zasobów (environment variables) w GCP -> Zawsze używaj **Sensitive Data Protection (Cloud DLP)**.
* Zintegrowanie skanowania DLP z SCC pozwala na centralną wizualizację alertów bezpieczeństwa.

5. Reguły wyboru odpowiedzi (Słowa kluczowe):
* Identify secrets in environment variables in a timely manner -> Sensitive Data Protection (DLP) + Security Command Center.

Wskazówki egzaminacyjne (Tips & Tricks)

Reguła Egzaminacyjna (Exam Rule): 
W pytaniach typu 'Security in GCP', zawsze priorytetyzuj rozwiązania natywne (SCC, Cloud KMS, Secret Manager, VPC SC) nad rozwiązaniami typu 'third-party' lub 'self-managed', chyba że scenariusz wymaga specyficznej integracji hybrydowej.

Haczyki egzaminacyjne (Exam Traps):
- Pułapka 'Least Privilege': Egzamin często podpowiada role o szerokim zakresie (np. 'Editor' lub 'Owner') – zawsze odrzucaj je na rzecz ról predefiniowanych o najmniejszym zakresie uprawnień.
- Pułapka 'Logging vs Monitoring': Pamiętaj: Audit Logs służą do badania aktywności (Who/What/When), a Monitoring do zbierania metryk wydajnościowych.

Głębokie wyjaśnienie techniczne:
Każda architektura bezpieczeństwa w GCP powinna być projektowana w oparciu o 'Security by Default'. Oznacza to m.in. szyfrowanie w spoczynku (domyślne), tożsamość opartą na rolach (IAM) oraz pełną widoczność zapewnianą przez scentralizowane logowanie (Cloud Logging/SCC).

Analiza i Podsumowanie (AI)

Kluczowe zagadnienia

Sugerowana odpowiedź: C

Analiza strategiczna: To pytanie testuje Twoją zdolność do projektowania systemów detekcji błędów. Użycie natywnych usług zarządzanych (DLP + SCC) jest zawsze preferowane względem własnych skryptów (Dług Techniczny), ponieważ zapewnia lepszą skalowalność, utrzymanie i integrację z ekosystemem bezpieczeństwa GCP.
