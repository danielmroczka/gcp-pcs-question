Question 269 / 361

Your organization is using Security Command Center Premium as a central tool to detect and alert on security threats. You also want to alert on suspicious outbound traffic that is targeting domains of known suspicious web services. What should you do?

  • A. Create a DNS Server Policy in Cloud DNS and turn on logs. Attach this policy to all Virtual Private Cloud networks with internet connectivity.
  • B. Forward all logs to Chronicle Security Information and Event Management. Create an alert for suspicious egress traffic to the internet.
  • C. Create a Cloud Intrusion Detection endpoint. Connect this endpoint to all Virtual Private Cloud networks with internet connectivity.
  • D. Create an egress firewall policy with Threat Intelligence as the destination. Attach this policy to all Virtual Private Cloud networks with internet connectivity.
Show Suggested Answer
Suggested Answer: D

Wyjaśnienie

1. Prawidłowa odpowiedź lub odpowiedzi:
D. Create an egress firewall policy with Threat Intelligence as the destination. Attach this policy to all Virtual Private Cloud networks with internet connectivity.

2. Kompleksowe wyjaśnienie dlaczego dana odpowiedź jest prawidłowa (Analiza):
Odpowiedź D jest prawidłowa, ponieważ usługa Cloud Firewall (w wersji Advanced/Plus) wspiera funkcję Threat Intelligence (Inteligentna analiza zagrożeń), która pozwala na automatyczne blokowanie lub logowanie ruchu do znanych, szkodliwych adresów IP i domen w internecie.

Jak to działa:
a. **Threat Intelligence w Firewallu:** Google stale aktualizuje listy reputacyjne zawierające adresy IP powiązane ze złośliwym oprogramowaniem, botnetami, serwerami Command & Control (C2) oraz witrynami phishingowymi.
b. **Polityka Egress:** Tworząc regułę zapory sieciowej dla ruchu wychodzącego (egress) z celem (destination) ustawionym na odpowiednią listę Threat Intelligence (np. "iplist-malicious-ips"), system automatycznie zablokuje lub wyśle alert w przypadku próby nawiązania połączenia przez dowolną maszynę w sieci VPC z tymi adresami. Jest to wysoce skuteczna obrona prewencyjna.

3. Wyjaśnienie z osobna każdej niepoprawnej odpowiedzi:
A. Create a DNS Server Policy in Cloud DNS and turn on logs...
   * Dlaczego nieprawidłowa: Włączenie logowania zapytań DNS pozwala na audyt (monitoring) i analizę po fakcie, ale samo w sobie nie blokuje złośliwego ruchu IP i nie generuje automatycznych alertów o zagrożeniach w czasie rzeczywistym w SCC w taki sposób jak zapora sieciowa.
B. Forward all logs to Chronicle Security Information and Event Management...
   * Dlaczego nieprawidłowa: Choć Chronicle SIEM doskonale nadaje się do korelacji logów w skali całej firmy, to wdrożenie i konfiguracja SIEM do detekcji ruchu wykracza poza prosty i natywny mechanizm bezpośredniego filtrowania na poziomie zapory chmurowej i generuje znaczne opóźnienia oraz koszty.
C. Create a Cloud Intrusion Detection endpoint. Connect this endpoint to all VPC...
   * Dlaczego nieprawidłowa: Cloud IDS (Intrusion Detection System) służy do pasywnego wykrywania zagrożeń (identyfikacji anomalii) i generuje alerty w SCC, ale nie filtruje i nie blokuje (inline mitigation) aktywnie ruchu sieciowego, co było celem wdrożenia prewencyjnego zabezpieczenia zapory.

4. Wskazówki, hinty, tips and tricks:
* Blokowanie/filtrowanie ruchu wychodzącego do znanych złośliwych domen/IP na poziomie sieci w GCP -> Używaj **Cloud Firewall** z włączoną funkcją **Threat Intelligence**.
* Listy Threat Intelligence są w pełni zarządzane i aktualizowane przez Google.

5. Reguły wyboru odpowiedzi (Słowa kluczowe):
* Alert/block egress traffic targeting known suspicious web services -> Egress firewall policy with Threat Intelligence.
