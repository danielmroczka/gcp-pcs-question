Question 168 / 361

Your security team wants to implement a defense-in-depth approach to protect sensitive data stored in a Cloud Storage bucket. Your team has the following requirements:
- The Cloud Storage bucket in Project A can only be readable from Project B.
- The Cloud Storage bucket in Project A cannot be accessed from outside the network.
- Data in the Cloud Storage bucket cannot be copied to an external Cloud Storage bucket.
What should the security team do?

  • A. Enable domain restricted sharing in an organization policy, and enable uniform bucket-level access on the Cloud Storage bucket.
  • B. Enable VPC Service Controls, create a perimeter around Projects A and B, and include the Cloud Storage API in the Service Perimeter configuration.
  • C. Enable Private Access in both Project A and B's networks with strict firewall rules that allow communication between the networks.
  • D. Enable VPC Peering between Project A and B's networks with strict firewall rules that allow communication between the networks.
Show Suggested Answer Hide Answer
Suggested Answer: B

Wyjaśnienie

Poprawna odpowiedź: B (Enable VPC Service Controls, create a perimeter around Projects A and B, and include the Cloud Storage API in the Service Perimeter configuration)

Dlaczego ta odpowiedź jest poprawna:
- VPC Service Controls (VPC SC): Jest to mechanizm bezpieczeństwa Google Cloud, który pozwala na stworzenie logicznego obwodu (perimetru) wokół zasobów w różnych projektach.
- Zapobieganie eksfiltracji danych (Data Exfiltration): VPC SC chroni przed kopiowaniem danych z chronionego zasobu (np. Bucket w Projekcie A) do niechronionego zasobu poza perymetrem (np. prywatny bucket pracownika), nawet jeśli użytkownik posiada odpowiednie role IAM w obu projektach.
- Spełnienie wymagań: 
  1. "Readable from Project B" - Projekty A i B są w tym samym perymetrze, więc mogą się swobodnie komunikować.
  2. "Cannot be accessed from outside the network" - VPC SC domyślnie blokuje dostęp do usług Google Cloud z internetu, chyba że skonfigurujesz poziomy dostępu (Access Levels).
  3. "Cannot be copied to external bucket" - To kluczowa funkcja perymetru VPC SC.

Analiza niepoprawnych odpowiedzi:
- A. Domain restricted sharing + UBLA: Te mechanizmy chronią przed przypadkowym udostępnieniem danych osobom postronnym (IAM). Nie zapobiegają jednak sytuacji, w której uprawniony użytkownik (mający dostęp do obu projektów) kopiuje dane z projektu firmowego do swojego prywatnego projektu.
- C. Private Access + Firewalls: Private Google Access pozwala maszynom bez publicznego IP łączyć się z API Google, a firewalle kontrolują ruch na poziomie IP między VM. Żadne z tych narzędzi nie kontroluje operacji na poziomie API (np. 'gsutil cp'), czyli nie widzi, dokąd dane są przesyłane wewnątrz usług Google.
- D. VPC Peering + Firewalls: Podobnie jak w punkcie C, peering dotyczy warstwy sieciowej (IP). Nie ma wpływu na bezpieczeństwo usług PaaS takich jak Cloud Storage na poziomie logicznym/API.

Wskazówki i triki (Tips & Tricks):
- Jeśli w pytaniu pojawia się "Prevent copy to external project/bucket" -> szukaj VPC Service Controls (Perymetr).
- IAM to "Kto ma dostęp?", VPC SC to "Skąd i dokąd dane mogą płynąć?".
- VPC SC działa na poziomie API (Warstwa 7), a nie na poziomie IP (Warstwa 3).

Praktyczne informacje na egzamin:
- Zapamiętaj termin "Data Exfiltration Protection". To główne zadanie VPC SC.
- Perymetr może obejmować wiele projektów z różnych organizacji (poprzez tzw. Bridge).
- Uważaj na "Dry-run mode" – to funkcja VPC SC pozwalająca testować restrykcje bez faktycznego blokowania ruchu (często pojawia się w pytaniach o wdrażanie).
