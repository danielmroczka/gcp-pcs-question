Question 171 / 361

You have created an OS image that is hardened per your organization's security standards and is being stored in a project managed by the security team. As a Google Cloud administrator, you need to make sure all VMs in your Google Cloud organization can only use that specific OS image while minimizing operational overhead. What should you do? (Choose two.)

  • A. Grant users the compute.imageUser role in their own projects.
  • B. Grant users the compute.imageUser role in the OS image project.
  • C. Store the image in every project that is spun up in your organization.
  • D. Set up an image access organization policy constraint, and list the security team managed project in the project's allow list.
  • E. Remove VM instance creation permission from users of the projects, and only allow you and your team to create VM instances.
Show Suggested Answer Hide Answer
Suggested Answer: BD

Wyjaśnienie

1. Prawidłowa odpowiedź lub odpowiedzi:
B. Grant users the compute.imageUser role in the OS image project.
D. Set up an image access organization policy constraint, and list the security team managed project in the project's allow list.

2. Kompleksowe wyjaśnienie dlaczego dana odpowiedź jest prawidłowa (Analiza):
Należy wymusić w całej organizacji używanie wyłącznie jednego, zatwierdzonego obrazu systemu operacyjnego (hardened OS image) przechowywanego w bezpiecznym projekcie zespołu bezpieczeństwa, minimalizując przy tym narzut operacyjny:
- D (Blokada użycia innych obrazów): Polityka organizacji z ograniczeniem `constraints/compute.trustedImageProjects` pozwala zdefiniować listę zaufanych projektów, z których użytkownicy w organizacji mogą pobierać obrazy do tworzenia maszyn VM. Dodając do tej listy wyłącznie projekt zespołu bezpieczeństwa, blokujemy możliwość korzystania z publicznych obrazów (np. Debian, Ubuntu) oraz obrazów z innych nieautoryzowanych projektów.
- B (Autoryzacja dostępu): Aby użytkownicy z projektów deweloperskich mogli fizycznie odczytać i uruchomić ten zatwierdzony obraz, muszą posiadać rolę `roles/compute.imageUser` (imageUser) nadaną na poziomie projektu zespołu bezpieczeństwa (właściciela obrazu).

3. Wyjaśnienie z osobna każdej niepoprawnej odpowiedzi:
- A. Nadanie roli `compute.imageUser` deweloperom w ich własnych projektach: Daje im to uprawnienie do używania obrazów w ich własnym projekcie, ale nie pozwala na dostęp do chronionego obrazu w zewnętrznym projekcie bezpieczeństwa.
- C. Kopiowanie obrazu do każdego nowego projektu: Generuje ogromny narzut operacyjny związany z kopiowaniem, aktualizowaniem obrazu w setkach projektów i marnowaniem miejsca, co stoi w sprzeczności z wymogiem minimalizacji overheadu.
- E. Odebranie uprawnień do tworzenia maszyn deweloperom: Całkowicie uniemożliwia samoobsługę (self-service) i paraliżuje proces wdrażania maszyn wirtualnych przez zespoły, zmuszając zespół bezpieczeństwa do ręcznego tworzenia każdej maszyny.

4. Wskazówki, hinty, tips and tricks:
- Wymuszenie użycia zatwierdzonych obrazów OS w GCP realizuje się za pomocą:
  1. Polityki organizacji **`compute.trustedImageProjects`** (określa skąd można brać obrazy).
  2. Roli IAM **`roles/compute.imageUser`** na projekcie źródłowym (daje prawo do odczytu obrazu).

5. Reguły wyboru odpowiedzi (Słowa kluczowe):
- Wymuszenie użycia obrazów z zaufanego projektu w organizacji -> compute.trustedImageProjects + roles/compute.imageUser na projekcie źródłowym.
