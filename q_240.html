Question 240 / 361

Your customer has an on-premises Public Key Infrastructure (PKI) with a certificate authority (CA). You need to issue certificates for many HTTP load balancer frontends. The on-premises PKI should be minimally affected due to many manual processes, and the solution needs to scale. What should you do?

  • A. Use Certificate Manager to issue Google managed public certificates and configure it at HTTP the load balancers in your infrastructure as code (IaC).
  • B. Use a subordinate CA in the Google Certificate Authority Service from the on-premises PKI system to issue certificates for the load balancers.
  • C. Use Certificate Manager to import certificates issued from on-premises PKI and for the frontends. Leverage the gcloud tool for importing.
  • D. Use the web applications with PKCS12 certificates issued from subordinate CA based on OpenSSL on-premises. Use the gcloud tool for importing. Use the External TCP/UDP Network load balancer instead of an external HTTP Load Balancer.
Show Suggested Answer Hide Answer
Suggested Answer: B

Wyjaśnienie

Potwierdzona odpowiedź: B (Use a subordinate CA in the Google Certificate Authority Service from the on-premises PKI system to issue certificates for the load balancers)

Wyjaśnienie:
- Certificate Authority Service (CAS): Jest to w pełni zarządzana usługa Google Cloud do tworzenia i zarządzania urzędami certyfikacji (CA).
- Subordinate CA (Podległy CA): Pozwala na stworzenie CA wewnątrz chmury, które jest technicznie "podległe" (zaufane przez) Twojemu głównemu urzędowi CA on-premises. Jest to najbardziej skalowalne i natywne rozwiązanie: certyfikaty wystawiane w chmurze są automatycznie zaufane w sieci firmowej, ponieważ główny klucz CA jest w on-premises.
- Integracja z Load Balancerem: Certyfikaty wystawione przez podległy CA w chmurze można bezpośrednio przypisać do Load Balancera HTTP/S, co rozwiązuje problem skali i automatyzacji.

Dlaczego pozostałe odpowiedzi są niepoprawne:
- A. Certificate Manager z Google managed public certificates: Te certyfikaty są wydawane przez publiczne CA Google. Nie będą zaufane przez Twoją wewnętrzną PKI, chyba że wgrasz certyfikat CA Google do każdego zaufanego systemu on-prem, co jest operacyjnie trudne.
- C. Import certificates: Ręczne importowanie certyfikatów wystawionych przez on-prem PKI jest procesem manualnym, który trudno skalować (wymaga częstego odświeżania, importowania do Certificate Manager, etc.). Nie rozwiązuje to problemu "manual processes".
- D. External TCP/UDP Network LB: Zmiana typu Load Balancera (z HTTP na TCP) jest nieuzasadniona i pozbawia Cię funkcji L7 (WAF, SSL termination), co jest niedopuszczalne dla aplikacji webowej.

Wskazówki i triki (Tips & Tricks):
- "On-premises PKI integration" + "Scale" + "HTTP Load Balancer" = Subordinate CA w Cloud CAS.
- Jeśli chcesz automatyzacji i skali wewnątrz chmury, używaj Google CAS.

Praktyczne informacje na egzamin:
- Zapamiętaj: Google CAS to usługa klasy Enterprise. Subordinate CA to idealny wzorzec dla architektury hybrydowej (zaufanie z on-prem -> wydawanie w chmurze).

Wskazówki egzaminacyjne (Tips & Tricks)

Reguła Egzaminacyjna (Exam Rule): 
Jeśli scenariusz dotyczy zabezpieczania zasobów chmurowych (GCP), zawsze wybieraj rozwiązanie typu Managed (SCC, Secret Manager, Cloud KMS), a unikaj rozwiązań self-managed, chyba że pytanie wyraźnie wymaga dostosowania niskopoziomowego.

Haczyki egzaminacyjne (Exam Traps):
- Pułapka IAM: Pytania o uprawnienia często sugerują 'Project Owner' – zawsze szukaj 'Least Privilege' (np. 'Role: Secret Manager Secret Accessor').
- Pułapka Sieciowa: Często mylone są VPC Peering (wydajność) oraz VPN (szyfrowanie/on-premise).

Głębokie wyjaśnienie techniczne:
Rozwiązanie bazuje na GCP Shared Responsibility Model. Google zarządza bezpieczeństwem infrastruktury (Physical, Network, Host), podczas gdy administrator zarządza tożsamością (IAM), danymi (Encryption, Cloud KMS) i regułami dostępu (VPC Firewall).

Analiza i Podsumowanie (AI)

Kluczowe zagadnienia

Sugerowana odpowiedź: B

Analiza strategiczna: To pytanie sprawdza umiejętność łączenia systemów on-premises z chmurą w sposób skalowalny. Ręczne operacje (importowanie certyfikatów) to "dług techniczny". Zbudowanie hierarchii CA (główny on-prem -> podległy w chmurze) to najlepsza praktyka inżynierska, która zapewnia pełną automatyzację i spójność zaufania.
