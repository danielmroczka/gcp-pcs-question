Question 48 / 361

Applications often require access to `secrets` - small pieces of sensitive data at build or run time. The administrator managing these secrets on GCP wants to keep a track of `who did what, where, and when?` within their GCP projects. Which two log streams would provide the information that the administrator is looking for? (Choose two.)

  • A. Admin Activity logs
  • B. System Event logs
  • C. Data Access logs
  • D. VPC Flow logs
  • E. Agent logs
Show Suggested Answer Hide Answer
Suggested Answer: AC

Wyjaśnienie

**Poprawna odpowiedź: AC**

**1. Kompleksowe wyjaśnienie poprawnej odpowiedzi:**
Administrator chce mieć pełny wgląd (ścieżkę audytową - audit trail) w to, "kto, co, gdzie i kiedy" robił w odniesieniu do sekretów w projektach GCP:
- **Admin Activity logs (A):** Rejestrują wszelkie operacje modyfikujące konfigurację lub metadane (zapisy, usunięcia, modyfikacje) zasobów i uprawnień IAM w projekcie. Są włączone domyślnie i bezpłatne.
- **Data Access logs (C):** Rejestrują operacje odczytu i zapisu samych danych (np. pobranie wartości sekretu przez aplikację, odczyt obiektu w GCS). Te logi pozwalają precyzyjnie stwierdzić, kto pobrał/odczytał sekret. Ze względu na dużą objętość są domyślnie wyłączone i należy je ręcznie aktywować w polityce IAM projektu.

**2. Wyjaśnienie niepoprawnych odpowiedzi:**
- **B. System Event logs:** Rejestrują operacje administracyjne wykonywane przez systemy Google Cloud (np. automatyczna migracja maszyny na inny host), nie rejestrują działań użytkowników i aplikacji na danych.
- **D. VPC Flow logs:** Rejestrują metadany o ruchu sieciowym (IP źródłowe/docelowe, porty, pakiety) w sieci VPC. Nie informują o tym, jakie konkretne zasoby aplikacyjne (np. sekrety) były odczytywane przez użytkowników.
- **E. Agent logs:** Logi pochodzące z agentów zainstalowanych na maszynach VM (np. logi aplikacji, logi systemowe Windows/Linux), nie rejestrują operacji na poziomie API Google Cloud.

**3. Wskazówki i pułapki egzaminacyjne (Tips & Tricks):**
- Ścieżka audytowa w GCP (GCP Audit Trail) składa się z trzech typów logów (Cloud Audit Logs):
  1. **Admin Activity** (Kto zmienił konfigurację/zasób? - Zawsze włączone).
  2. **Data Access** (Kto odczytał/zapisał dane? - Domyślnie wyłączone).
  3. **System Event** (Działania systemu Google).
- Słowo-klucz: **who did what, where, and when** w odniesieniu do danych/sekretów wymaga włączenia **Data Access logs**.

**4. Reguły wyboru odpowiedzi:**
- Pełny audyt administracyjny i dostępu do danych -> Admin Activity + Data Access logs.

**5. Dodatkowe źródła:**
- Cloud Audit Logs overview: https://cloud.google.com/logging/docs/audit

Wyjaśnienie Audytowe

Reguła Egzaminacyjna (Exam Rule):
Pamiętaj, że w egzaminie Professional Cloud Security Engineer kluczowe jest wybieranie rozwiązań najmniej uprzywilejowanych (Principle of Least Privilege), zoptymalizowanych kosztowo i spełniających wymogi compliancy (np. CMEK, Data Loss Prevention).

Haczyki egzaminacyjne (Exam Traps):
- Wybór rozwiązań, które wydają się wygodne, ale nie spełniają wymogów bezpieczeństwa (np. zbyt szerokie uprawnienia IAM).
- Mylenie usług: np. Cloud Armor (WAF) z Cloud IAP (Identity-Aware Proxy).

Głębokie wyjaśnienie techniczne (GCP Professional Cloud Security Engineer):
W każdym pytaniu analizuj warstwy: IAM (dostęp), Encryption (at rest/in transit), Logging/Monitoring (Audit Logs, Cloud Logging, Security Command Center) oraz Networking (VPC Service Controls, Firewall Rules). GCP kładzie duży nacisk na współdzieloną odpowiedzialność (Shared Responsibility Model) - klient odpowiada za konfigurację zabezpieczeń wewnątrz usług chmurowych.
