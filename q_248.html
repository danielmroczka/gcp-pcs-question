Question 248 / 361

During a routine security review, your team discovered a suspicious login attempt to impersonate a highly privileged but regularly used service account by an unknown IP address. You need to effectively investigate in order to respond to this potential security incident. What should you do?

  • A. Enable Cloud Audit Logs for the resources that the service account interacts with. Review the logs for further evidence of unauthorized activity.
  • B. Review Cloud Audit Logs for activity related to the service account. Focus on the time period of the suspicious login attempt.
  • C. Run a vulnerability scan to identify potentially exploitable weaknesses in systems that use the service account.
  • D. Check Event Threat Detection in Security Command Center for any related alerts. Cross-reference your findings with Cloud Audit Logs.
Show Suggested Answer Hide Answer
Suggested Answer: D

Wyjaśnienie

1. Prawidłowa odpowiedź lub odpowiedzi:
D. Check Event Threat Detection in Security Command Center for any related alerts. Cross-reference your findings with Cloud Audit Logs.

2. Kompleksowe wyjaśnienie dlaczego dana odpowiedź jest prawidłowa (Analiza):
Odpowiedź D jest prawidłowa, ponieważ łączy zautomatyzowane wykrywanie zagrożeń za pomocą silnika Event Threat Detection (ETD) z głęboką analizą śledczą (forensics) w logach audytowych (Cloud Audit Logs).

Dlaczego to najlepsze podejście śledcze:
a. **Event Threat Detection (ETD):** Jest to usługa Security Command Center Premium, która stale monitoruje strumień logów (w tym logi audytowe Cloud Audit Logs) w czasie rzeczywistym i stosuje zaawansowane algorytmy detekcji zagrożeń. Potrafi automatycznie wykryć anomalie takie jak "Service Account Leaked Credentials" lub podejrzane logowania z nietypowych IP na konta serwisowe i wygenerować precyzyjny alert.
b. **Cross-referencing z Cloud Audit Logs:** Znalezienie alertu w SCC daje punkt wyjścia (np. dokładny czas, ID konta serwisowego, IP napastnika). Następnie analityk bezpieczeństwa odpytuje Cloud Audit Logs (Admin Activity i Data Access), aby prześledzić wszystkie operacje wykonane przez to konto serwisowe (np. jakie zasoby zostały odczytane lub zmodyfikowane), co pozwala na pełną ocenę incydentu i skuteczną reakcję.

3. Wyjaśnienie z osobna każdej niepoprawnej odpowiedzi:
A. Enable Cloud Audit Logs for the resources... Review the logs for further...
   * Dlaczego nieprawidłowa: Włączenie logów *po* wykryciu incydentu nie pomoże w badaniu przeszłych zdarzeń – logi nie działają wstecz. Ponadto samo przeglądanie logów bez wsparcia zautomatyzowanego systemu wykrywania (jak ETD) utrudnia szybkie znalezienie korelacji zagrożeń.
B. Review Cloud Audit Logs for activity related to the service account...
   * Dlaczego nieprawidłowa: Choć jest to część poprawnego procesu, to samo przeglądanie surowych logów bez sprawdzenia alertów w SCC (Event Threat Detection) jest mniej efektywne. ETD dostarcza gotowe analizy i kontekst zagrożenia, który znacznie przyspiesza dochodzenie.
C. Run a vulnerability scan to identify potentially exploitable weaknesses...
   * Dlaczego nieprawidłowa: Skanowanie podatności (vulnerability scan) szuka dziur w oprogramowaniu i konfiguracji systemu. Nie pomaga w badaniu aktywnego incydentu polegającego na użyciu skradzionych poświadczeń (impersonation) konta serwisowego, które zostało już dokonane.

4. Wskazówki, hinty, tips and tricks:
* Wykrywanie i analiza anomalii w logach systemowych i logowaniach kont serwisowych w GCP -> **Event Threat Detection** w **Security Command Center**.
* Pamiętaj, że logi audytowe (Cloud Audit Logs) są podstawowym źródłem prawdy podczas badania incydentów (forensic investigation).

5. Reguły wyboru odpowiedzi (Słowa kluczowe):
* Investigate suspicious login / impersonation of service account -> Event Threat Detection + Cloud Audit Logs.
