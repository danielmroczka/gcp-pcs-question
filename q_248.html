Question 248 / 361

During a routine security review, your team discovered a suspicious login attempt to impersonate a highly privileged but regularly used service account by an unknown IP address. You need to effectively investigate in order to respond to this potential security incident. What should you do?

  • A. Enable Cloud Audit Logs for the resources that the service account interacts with. Review the logs for further evidence of unauthorized activity.
  • B. Review Cloud Audit Logs for activity related to the service account. Focus on the time period of the suspicious login attempt.
  • C. Run a vulnerability scan to identify potentially exploitable weaknesses in systems that use the service account.
  • D. Check Event Threat Detection in Security Command Center for any related alerts. Cross-reference your findings with Cloud Audit Logs.
Show Suggested Answer Hide Answer
Suggested Answer: D

Wyjaśnienie

Potwierdzona odpowiedź: D (Check Event Threat Detection in Security Command Center for any related alerts. Cross-reference your findings with Cloud Audit Logs.)

Wyjaśnienie:
- Event Threat Detection (ETD): Jest to zaawansowana usługa w ramach Security Command Center (SCC) Premium, która automatycznie monitoruje logi (głównie logi audytowe i logi przepływu VPC) w poszukiwaniu wzorców świadczących o zagrożeniach w czasie rzeczywistym. ETD specjalizuje się w wykrywaniu anomalii, takich jak podejrzane próby logowania (impersonacja), ataki typu brute-force czy komunikacja z złośliwymi adresami IP.
- Cloud Audit Logs: Są niezbędne do "dochodzenia" (forensics). Po otrzymaniu alertu z ETD, to właśnie w logach audytowych (Data Access / Admin Activity) znajdziesz szczegółowe dowody: kto, kiedy i przy użyciu jakich uprawnień próbował dokonać podejrzanej akcji.
- Synergia: SCC dostarcza "alert" (sygnał o problemie), a Cloud Audit Logs dostarczają "dowód" (szczegóły zdarzenia).

Dlaczego pozostałe odpowiedzi są niepoprawne:
- A. Cloud Audit Logs: Choć logi są ważne, przeglądanie ich bez alertu z systemu detekcji (jak ETD) jest nieefektywne ("szukanie igły w stogu siana").
- B. Security scan: Skaner podatności służy do wykrywania luk konfiguracyjnych lub nieaktualnego oprogramowania, a nie do analizy podejrzanych prób logowania w czasie rzeczywistym.
- C. Vulnerability scan: Podobnie jak B, skaner podatności nie wykrywa aktywnych prób włamania (impersonacji).

Wskazówki i triki (Tips & Tricks):
- "Suspicious login attempt" / "Impersonation" + "Threat Detection" = Event Threat Detection (ETD).
- "Investigate" / "Evidence" = Cloud Audit Logs.
- Pamiętaj: ETD wymaga włączonego SCC Premium i odpowiednich logów w logach audytowych.

Praktyczne informacje na egzamin:
- Zapamiętaj: ETD wykrywa zagrożenia na podstawie analizy logów, nie wymaga instalacji żadnych agentów.
- Kiedy widzisz "Suspicious pattern in logs", myśl o ETD.

Wskazówki egzaminacyjne (Tips & Tricks)

Reguła Egzaminacyjna (Exam Rule): 
Jeśli scenariusz dotyczy zabezpieczania zasobów chmurowych (GCP), zawsze wybieraj rozwiązanie typu Managed (SCC, Secret Manager, Cloud KMS), a unikaj rozwiązań self-managed, chyba że pytanie wyraźnie wymaga dostosowania niskopoziomowego.

Haczyki egzaminacyjne (Exam Traps):
- Pułapka IAM: Pytania o uprawnienia często sugerują 'Project Owner' – zawsze szukaj 'Least Privilege' (np. 'Role: Secret Manager Secret Accessor').
- Pułapka Sieciowa: Często mylone są VPC Peering (wydajność) oraz VPN (szyfrowanie/on-premise).

Głębokie wyjaśnienie techniczne:
Rozwiązanie bazuje na GCP Shared Responsibility Model. Google zarządza bezpieczeństwem infrastruktury (Physical, Network, Host), podczas gdy administrator zarządza tożsamością (IAM), danymi (Encryption, Cloud KMS) i regułami dostępu (VPC Firewall).

Analiza i Podsumowanie (AI)

Kluczowe zagadnienia

Sugerowana odpowiedź: D

Analiza strategiczna: To pytanie testuje Twoją reakcję na incydent bezpieczeństwa w środowisku chmurowym. W GCP SCC Premium jest "mózgiem" operacyjnym. Zrozumienie, że najpierw otrzymujesz sygnał (ETD), a następnie wykonujesz dochodzenie (Audit Logs), jest standardowym, najlepszym podejściem operacyjnym dla każdego inżyniera bezpieczeństwa.
