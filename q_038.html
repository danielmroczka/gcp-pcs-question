Question 38 / 361

A customer's internal security team must manage its own encryption keys for encrypting data on Cloud Storage and decides to use customer-supplied encryption keys (CSEK).
How should the team complete this task?

  • A. Upload the encryption key to a Cloud Storage bucket, and then upload the object to the same bucket.
  • B. Use the gsutil command line tool to upload the object to Cloud Storage, and specify the location of the encryption key.
  • C. Generate an encryption key in the Google Cloud Platform Console, and upload an object to Cloud Storage using the specified key.
  • D. Encrypt the object, then use the gsutil command line tool or the Google Cloud Platform Console to upload the object to Cloud Storage.
Show Suggested Answer Hide Answer
Suggested Answer: B

Wyjaśnienie

Potwierdzona odpowiedź: B (Use the gsutil command line tool to upload the object to Cloud Storage, and specify the location of the encryption key.)

Wyjaśnienie:
Customer-Supplied Encryption Keys (CSEK) to model szyfrowania, w którym to użytkownik całkowicie odpowiada za generowanie i przechowywanie kluczy szyfrujących poza infrastrukturą Google. Google używa klucza dostarczonego przez użytkownika tylko tymczasowo w pamięci RAM do zaszyfrowania danych podczas ich zapisu (lub odszyfrowania przy odczycie), a następnie natychmiast go usuwa. Aby przesłać obiekt zaszyfrowany kluczem CSEK, należy użyć narzędzia `gsutil` i wskazać lokalizację klucza (np. w pliku konfiguracyjnym `.boto` lub za pomocą flagi), ponieważ konsola GCP nie wspiera operacji z użyciem CSEK ze względu na fakt, że Google nie może mieć dostępu do tych kluczy.

Dlaczego pozostałe są błędne:
A. Upload the encryption key to a Cloud Storage bucket...: Przechowywanie klucza w tym samym miejscu co zaszyfrowane dane jest skrajnie niebezpieczne (to tak, jakby zostawić klucz w zamku do sejfu). Dodatkowo, mechanizm CSEK nie polega na pobieraniu klucza z innego bucketu przez Google.
C. Generate an encryption key in the Google Cloud Platform Console...: Konsola GCP nie pozwala na generowanie kluczy CSEK. Klucze CSEK z definicji powstają poza kontrolą Google. W Konsoli można zarządzać jedynie kluczami CMEK (Cloud KMS).
D. Encrypt the object, then use the gsutil...: To opisuje szyfrowanie po stronie klienta (Client-Side Encryption). W przypadku CSEK to Google wykonuje szyfrowanie po swojej stronie (Server-Side Encryption), ale używa do tego klucza dostarczonego przez klienta w locie.

Wskazówki egzaminacyjne (Tips & Tricks):
- CSEK = Klucz dostarczany w locie przez `gsutil` (plik `.boto`). Brak wsparcia w Konsoli GCP dla zapisu/odczytu takich obiektów.
- CMEK = Klucz zarządzany w Cloud KMS (Google go przechowuje, ale Ty nim zarządzasz).
- Jeśli zgubisz klucz CSEK, dane są bezpowrotnie stracone – Google nie ma ich kopii.

Kluczowe zagadnienia do powtórzenia:
- Różnice między GMEK, CMEK i CSEK
- Konfiguracja `gsutil` (sekcja `encryption_key` w `.boto`)
- Ograniczenia Konsoli GCP w kontekście CSEK

Dokumentacja:
https://cloud.google.com/storage/docs/encryption/customer-supplied-keys

Analiza i Podsumowanie Dyskusji (AI)

Analiza i Wyjaśnienie

Sugerowana odpowiedź: B

Analiza spornych kwestii (AI): Użytkownicy często mylą CSEK z szyfrowaniem po stronie klienta (client-side). Główna różnica polega na tym, że w CSEK Google "widzi" proces szyfrowania (dostaje klucz na chwilę), podczas gdy w szyfrowaniu po stronie klienta Google widzi tylko zaszyfrowany bełkot i nie ma żadnej możliwości odczytu danych.

Wyjaśnienie Audytowe

Reguła Egzaminacyjna (Exam Rule):
Pamiętaj, że w egzaminie Professional Cloud Security Engineer kluczowe jest wybieranie rozwiązań najmniej uprzywilejowanych (Principle of Least Privilege), zoptymalizowanych kosztowo i spełniających wymogi compliancy (np. CMEK, Data Loss Prevention).

Haczyki egzaminacyjne (Exam Traps):
- Wybór rozwiązań, które wydają się wygodne, ale nie spełniają wymogów bezpieczeństwa (np. zbyt szerokie uprawnienia IAM).
- Mylenie usług: np. Cloud Armor (WAF) z Cloud IAP (Identity-Aware Proxy).

Głębokie wyjaśnienie techniczne (GCP Professional Cloud Security Engineer):
W każdym pytaniu analizuj warstwy: IAM (dostęp), Encryption (at rest/in transit), Logging/Monitoring (Audit Logs, Cloud Logging, Security Command Center) oraz Networking (VPC Service Controls, Firewall Rules). GCP kładzie duży nacisk na współdzieloną odpowiedzialność (Shared Responsibility Model) - klient odpowiada za konfigurację zabezpieczeń wewnątrz usług chmurowych.
