Question 190 / 361

Your organization is using Active Directory and wants to configure Security Assertion Markup Language (SAML). You must set up and enforce single sign-on (SSO) for all users.
What should you do?

  • A. 1. Create a new SAML profile. 2. Populate the sign-in and sign-out page URLs. 3. Upload the X.509 certificate. 4. Configure Entity ID and ACS URL in your IdP.
  • B. 1. Configure prerequisites for OpenID Connect (OIDC) in your Active Directory (AD) tenant. 2. Verify the AD domain. 3. Decide which users should use SAML. 4. Assign the pre-configured profile to the select organizational units (OUs) and groups.
  • C. 1. Create a new SAML profile. 2. Upload the X.509 certificate. 3. Enable the change password URL. 4. Configure Entity ID and ACS URL in your IdP.
  • D. 1. Manage SAML profile assignments. 2. Enable OpenID Connect (OIDC) in your Active Directory (AD) tenant. 3. Verify the domain.
Show Suggested Answer Hide Answer
Suggested Answer: A

Wyjaśnienie

1. Prawidłowa odpowiedź lub odpowiedzi:
A. 1. Create a new SAML profile. 2. Populate the sign-in and sign-out page URLs. 3. Upload the X.509 certificate. 4. Configure Entity ID and ACS URL in your IdP.

2. Kompleksowe wyjaśnienie dlaczego dana odpowiedź jest prawidłowa (Analiza):
Integracja Google Cloud (Cloud Identity) z lokalnym Active Directory przy użyciu protokołu SAML 2.0 wymaga skonfigurowania relacji zaufania między dostawcą tożsamości (Identity Provider - IdP, czyli Active Directory/ADFS) a dostawcą usługi (Service Provider - SP, czyli Google).
Prawidłowa procedura konfiguracji Single Sign-On (SSO) po stronie Google (SP) wymaga:
1. Utworzenia nowego profilu SAML w konsoli Google Admin.
2. Wprowadzenia adresów URL stron logowania (sign-in) i wylogowania (sign-out) wskazujących na Twój IdP (aby Google wiedziało, dokąd przekierować użytkownika w celu uwierzytelnienia).
3. Przesłania certyfikatu X.509 (zawierającego klucz publiczny IdP), aby Google mogło kryptograficznie zweryfikować asercje SAML przesyłane z IdP.
Po stronie IdP (Active Directory / ADFS):
4. Konfiguracji Entity ID (identyfikatora Google) oraz ACS URL (Assertion Consumer Service URL – adresu, na który IdP ma wysyłać zaszyfrowane asercje SAML po udanym zalogowaniu użytkownika).

3. Wyjaśnienie z osobna każdej niepoprawnej odpowiedzi:
- B. Configure prerequisites for OpenID Connect (OIDC) in your Active Directory...: OIDC to nowoczesny protokół uwierzytelniania oparty na standardzie OAuth 2.0 i JSON Web Tokens (JWT). Pytanie wprost wymaga konfiguracji standardu SAML.
- C. Create a new SAML profile. Upload the X.509 certificate. Enable the change password URL...: Ta konfiguracja nie uwzględnia kluczowego kroku polegającego na podaniu adresów URL logowania i wylogowania (sign-in i sign-out page URLs). Bez tych adresów Google nie będzie w stanie przekierować przeglądarki użytkownika do formularza logowania w Active Directory. "Change password URL" jest opcjonalny.
- D. Manage SAML profile assignments. Enable OpenID Connect (OIDC)...: Podobnie jak w opcji B, ta opcja błędnie wprowadza protokół OIDC do zadania dotyczącego konfiguracji SAML.

4. Wskazówki, hinty, tips and tricks:
- W pytaniach o konfigurację SAM SSO z Active Directory w Google Cloud szukaj elementów składowych standardu SAML: **SAML profile, sign-in/sign-out URLs, X.509 certificate, Entity ID i ACS URL**.
- Pamiętaj, że federacja tożsamości przez SAML służy do uwierzytelniania (Authentication), natomiast do synchronizacji kont z Active Directory (cykl życia użytkowników) służy narzędzie GCDS (Google Cloud Directory Sync).

5. Reguły wyboru odpowiedzi (Słowa kluczowe):
- "Active Directory" + "configure SAML" + "enforce single sign-on (SSO)" -> SAML profile -> sign-in/sign-out URLs + X.509 certificate + Entity ID + ACS URL.
