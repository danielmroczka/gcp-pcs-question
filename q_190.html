Question 190 / 361

Your organization is using Active Directory and wants to configure Security Assertion Markup Language (SAML). You must set up and enforce single sign-on (SSO) for all users.
What should you do?

  • A. 1. Create a new SAML profile. 2. Populate the sign-in and sign-out page URLs. 3. Upload the X.509 certificate. 4. Configure Entity ID and ACS URL in your IdP.
  • B. 1. Configure prerequisites for OpenID Connect (OIDC) in your Active Directory (AD) tenant. 2. Verify the AD domain. 3. Decide which users should use SAML. 4. Assign the pre-configured profile to the select organizational units (OUs) and groups.
  • C. 1. Create a new SAML profile. 2. Upload the X.509 certificate. 3. Enable the change password URL. 4. Configure Entity ID and ACS URL in your IdP.
  • D. 1. Manage SAML profile assignments. 2. Enable OpenID Connect (OIDC) in your Active Directory (AD) tenant. 3. Verify the domain.

Suggested Answer: A

Wyjaśnienie

Poprawna odpowiedź: A (1. Create a new SAML profile. 2. Populate the sign-in and sign-out page URLs. 3. Upload the X.509 certificate. 4. Configure Entity ID and ACS URL in your IdP)

Dlaczego ta odpowiedź jest poprawna:
- SAML SSO (Single Sign-On): Jest to standard federacji tożsamości, w którym Google Cloud pełni rolę Service Provider (SP), a Twoja firma (np. Active Directory z ADFS) pełni rolę Identity Provider (IdP).
- Konfiguracja w Google (SP): Aby Google wiedziało, dokąd wysłać użytkownika w celu zalogowania, musisz stworzyć profil SAML i podać adresy URL strony logowania (Sign-in) i wylogowania (Sign-out) Twojego IdP.
- Certyfikat X.509: Jest kluczowy dla bezpieczeństwa. IdP podpisuje asercje SAML swoim kluczem prywatnym, a Google weryfikuje ten podpis za pomocą klucza publicznego zawartego w przesłanym certyfikacie X.509.
- Konfiguracja w IdP: Aby Twoje Active Directory wiedziało, że ma wysłać poświadczenia do Google, musisz w nim skonfigurować Entity ID (identyfikator Google jako SP) oraz ACS URL (Assertion Consumer Service URL – adres, pod który Google przyjmuje potwierdzenia zalogowania).

Analiza niepoprawnych odpowiedzi:
- B i D. OpenID Connect (OIDC): Choć OIDC jest nowocześniejszym protokołem (opartym na OAuth 2.0), pytanie wyraźnie prosi o konfigurację SAML. OIDC i SAML to dwa różne światy techniczne i nie konfiguruje się ich tymi samymi krokami.
- C. SAML profile without URLs: Opcja ta pomija kluczowy krok podania adresów URL (sign-in/sign-out), bez których użytkownik nie zostanie przekierowany do strony logowania firmy. "Change password URL" jest opcjonalny i nie jest fundamentem działania SSO.

Wskazówki i triki (Tips & Tricks):
- "SAML" + "AD" = SSO (Federacja).
- Zapamiętaj "Czwórkę SAML": Sign-in URL, X.509 Cert (w SP) + Entity ID, ACS URL (w IdP).
- Jeśli widzisz "Entity ID" i "ACS URL", niemal na pewno chodzi o konfigurację SAML.

Praktyczne informacje na egzamin:
- Zrozum kierunek zaufania: Google ufa Twojemu IdP, ponieważ posiada jego certyfikat publiczny.
- Pamiętaj, że SSO nie tworzy użytkowników w Google Cloud – do tego potrzebujesz GCDS (Google Cloud Directory Sync) lub Just-in-Time provisioning.

Analiza i Podsumowanie (AI)

Kluczowe zagadnienia

Sugerowana odpowiedź: A

Analiza strategiczna: To pytanie sprawdza fundamentalną wiedzę o tym, jak połączyć tożsamość korporacyjną z chmurą. SAML jest standardem "Enterprise", który pozwala na zachowanie jednego hasła (tego z AD) do wszystkich usług. Najważniejszym elementem dla inżyniera jest zrozumienie mechanizmu "handshake'u" – wymiany metadanych między dwiema stronami procesu.

Dodatkowe wskazówki

  • W Cloud Identity możesz przypisać różne profile SAML do różnych jednostek organizacyjnych (OU), co pozwala np. na użycie Okty dla deweloperów i AD dla reszty firmy.
  • Pamiętaj o ważności certyfikatu X.509 – jeśli wygaśnie, nikt nie będzie mógł się zalogować do Google Cloud.
