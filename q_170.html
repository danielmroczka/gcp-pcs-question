Question 170 / 361

You are onboarding new users into Cloud Identity and discover that some users have created consumer user accounts using the corporate domain name. How should you manage these consumer user accounts with Cloud Identity?

  • A. Use Google Cloud Directory Sync to convert the unmanaged user accounts.
  • B. Create a new managed user account for each consumer user account.
  • C. Use the transfer tool for unmanaged user accounts.
  • D. Configure single sign-on using a customer's third-party provider.
Show Suggested Answer Hide Answer
Suggested Answer: C

Wyjaśnienie

Poprawna odpowiedź: C (Use the transfer tool for unmanaged user accounts)

Dlaczego ta odpowiedź jest poprawna:
- Unmanaged User Accounts (Konta niezarządzane): To konta osobiste Google (np. Gmail), które użytkownicy stworzyli samodzielnie przy użyciu swojego służbowego adresu e-mail (np. jan@firma.pl), zanim firma wdrożyła Cloud Identity.
- Conflicting Accounts (Konta konfliktowe): Gdy firma zaczyna zarządzać domeną firma.pl w Cloud Identity, te osobiste konta stają się kontami "konfliktowymi". Firma nie ma nad nimi kontroli, dopóki nie zostaną one przeniesione (stransferowane) do domeny zarządzanej.
- Transfer Tool for Unmanaged Users (TTUU): Jest to narzędzie w konsoli administracyjnej Google, które pozwala na: 
  1. Zidentyfikowanie takich użytkowników w Twojej domenie.
  2. Wysłanie im prośby o przeniesienie ich konta (wraz z danymi, np. z Dysku Google) pod kontrolę organizacji.
  3. Monitorowanie statusu tych próśb.

Analiza niepoprawnych odpowiedzi:
- A. Google Cloud Directory Sync (GCDS): GCDS służy do synchronizowania użytkowników z lokalnego katalogu (np. AD) do Google Cloud. Nie służy do konwertowania istniejących już "osobistych" kont Google na konta zarządzane. Próba stworzenia takiego konta przez GCDS spowoduje błąd konfliktu.
- B. Create new managed accounts: Stworzenie nowego konta "obok" istniejącego konta osobistego o tym samym adresie e-mail spowoduje powstanie tzw. konta tymczasowego (gtempaccount.com) dla użytkownika i nie rozwiąże problemu rozproszonych danych oraz braku kontroli nad pierwotnym kontem.
- D. Configure SSO: SSO (Single Sign-On) służy do uwierzytelniania użytkowników, którzy JUŻ SĄ w systemie Cloud Identity. Nie pomaga w procesie odkrywania i migrowania niezarządzanych kont osobistych.

Wskazówki i triki (Tips & Tricks):
- "Consumer accounts with corporate domain" / "Unmanaged users" = Transfer Tool.
- Pamiętaj: Użytkownik musi wyrazić zgodę na transfer. Nie możesz go do tego zmusić technicznie jednym kliknięciem bez jego interakcji.

Praktyczne informacje na egzamin:
- Proces transferu jest kluczowy przy przejmowaniu istniejącego środowiska (Onboarding).
- Jeśli użytkownik odrzuci prośbę, możesz jedynie zablokować mu możliwość tworzenia nowych kont w Twojej domenie, ale stare konto pozostanie pod jego prywatną kontrolą (zmieniony zostanie tylko jego login na adres nie-firmowy).
