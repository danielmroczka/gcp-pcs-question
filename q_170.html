Question 170 / 361

You are onboarding new users into Cloud Identity and discover that some users have created consumer user accounts using the corporate domain name. How should you manage these consumer user accounts with Cloud Identity?

  • A. Use Google Cloud Directory Sync to convert the unmanaged user accounts.
  • B. Create a new managed user account for each consumer user account.
  • C. Use the transfer tool for unmanaged user accounts.
  • D. Configure single sign-on using a customer's third-party provider.
Show Suggested Answer Hide Answer
Suggested Answer: C

Wyjaśnienie

1. Prawidłowa odpowiedź lub odpowiedzi:
C. Use the transfer tool for unmanaged user accounts.

2. Kompleksowe wyjaśnienie dlaczego dana odpowiedź jest prawidłowa (Analiza):
Podczas wdrożenia Cloud Identity okazuje się, że niektórzy pracownicy wcześniej utworzyli osobiste (konsumenckie) konta Google przy użyciu firmowych adresów e-mail (np. `jan.kowalski@firma.com` jako konto do YouTube lub Dysku). Są to tzw. unmanaged accounts (konta niezarządzane). Należy przejąć nad nimi kontrolę w organizacji:
- Dedykowanym narzędziem do tego celu jest **narzędzie do przenoszenia kont niezarządzanych (transfer tool for unmanaged user accounts)** w konsoli administracyjnej Google Workspace / Cloud Identity.
- Narzędzie to skanuje domenę, wykrywa konta konsumenckie i umożliwia wysłanie do użytkowników zaproszenia do migracji konta pod kontrolę organizacji. Po zaakceptowaniu, konto staje się w pełni zarządzane przez firmowy IAM, a użytkownik zachowuje swoje dotychczasowe dane.

3. Wyjaśnienie z osobna każdej niepoprawnej odpowiedzi:
- A. Użycie Google Cloud Directory Sync (GCDS): GCDS służy do synchronizacji kont z lokalnego katalogu LDAP/AD do Cloud Identity, ale nie potrafi migrować ani konwertować istniejących, konfliktowych osobistych kont Google. Próba synchronizacji takiego konta stworzy tzw. konto konfliktowe.
- B. Ręczne utworzenie nowego konta zarządzanego: Spowoduje to konflikt nazw. Istniejące konto konsumenckie zostanie zmuszone do zmiany nazwy (np. na `jan.kowalski%firma.com@gtempaccount.com`), a użytkownik zostanie odcięty od swoich dotychczasowych danych chmurowych, co wywoła chaos operacyjny.
- D. Skonfigurowanie SSO: Logowanie jednokrotne (SSO) obsługuje proces uwierzytelniania, ale nie przenosi fizycznie struktury i własności istniejących unmanaged kont pod kontrolę administracyjną domeny.

4. Wskazówki, hinty, tips and tricks:
- Słowo-klucz w pytaniach GCP dotyczące przejmowania kontroli nad osobistymi kontami Google założonymi na firmowych adresach e-mail (conflict/unmanaged accounts) to **transfer tool for unmanaged user accounts**.

5. Reguły wyboru odpowiedzi (Słowa kluczowe):
- Konsumenckie konta w domenie firmowej -> transfer tool for unmanaged user accounts.

6. Dodatkowe źródła i dokumentacja:
