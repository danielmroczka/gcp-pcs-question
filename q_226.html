Question 226 / 361

Your organization wants to protect all workloads that run on Compute Engine VM to ensure that the instances weren't compromised by boot-level or kernel-level malware. Also, you need to ensure that data in use on the VM cannot be read by the underlying host system by using a hardware-based solution. What should you do?

  • A. 1. Use Google Shielded VM including secure boot, Virtual Trusted Platform Module (vTPM), and integrity monitoring. 2. Create a Cloud Run function to check for the VM settings, generate metrics, and run the function regularly.
  • B. 1. Activate Virtual Machine Threat Detection in Security Command Center (SCC) Premium. 2. Monitor the findings in SCC.
  • C. 1. Use Google Shielded VM including secure boot, Virtual Trusted Platform Module (vTPM), and integrity monitoring. 2. Activate Confidential Computing. 3. Enforce these actions by using organization policies.
  • D. 1. Use secure hardened images from the Google Cloud Marketplace. 2. When deploying the images, activate the Confidential Computing option. 3. Enforce the use of the correct images and Confidential Computing by using organization policies.
Show Suggested Answer Hide Answer
Suggested Answer: C

Wskazówki egzaminacyjne (Tips & Tricks)

Reguła Egzaminacyjna (Exam Rule): 
Jeśli scenariusz dotyczy zabezpieczania zasobów chmurowych (GCP), zawsze wybieraj rozwiązanie typu Managed (SCC, Secret Manager, Cloud KMS), a unikaj rozwiązań self-managed, chyba że pytanie wyraźnie wymaga dostosowania niskopoziomowego.

Haczyki egzaminacyjne (Exam Traps):
- Pułapka IAM: Pytania o uprawnienia często sugerują 'Project Owner' – zawsze szukaj 'Least Privilege' (np. 'Role: Secret Manager Secret Accessor').
- Pułapka Sieciowa: Często mylone są VPC Peering (wydajność) oraz VPN (szyfrowanie/on-premise).

Głębokie wyjaśnienie techniczne:
Rozwiązanie bazuje na GCP Shared Responsibility Model. Google zarządza bezpieczeństwem infrastruktury (Physical, Network, Host), podczas gdy administrator zarządza tożsamością (IAM), danymi (Encryption, Cloud KMS) i regułami dostępu (VPC Firewall).

Wyjaśnienie

Potwierdzona odpowiedź: C (1. Use Google Shielded VM including secure boot, Virtual Trusted Platform Module (vTPM), and integrity monitoring. 2. Activate Confidential Computing. 3. Enforce these actions by using organization policies)

Wyjaśnienie:
- Shielded VM: Zapewnia ochronę przed atakami na etapie uruchamiania systemu (boot-level) oraz wewnątrz jądra (kernel-level). Używa technologii takich jak Secure Boot (sprawdza podpisy cyfrowe bootloadera) oraz vTPM (bezpieczne przechowywanie kluczy/poświadczeń).
- Confidential Computing: Używa technologii sprzętowej (np. AMD SEV) do szyfrowania danych w pamięci RAM ("data in use"), co chroni przed odczytem pamięci przez hosta/hypervisor.
- Organizacja polityk (Enforcement): Wymuszenie tych ustawień przez politykę organizacji (np. `constraints/compute.requireConfidentialComputing`) gwarantuje, że każda nowa VM w firmie będzie miała te zabezpieczenia.

Dlaczego pozostałe odpowiedzi są niepoprawne:
- A. Cloud Run function: Cloud Run służy do obsługi żądań HTTP/zdarzeń, nie posiada żadnych uprawnień ani możliwości kontrolowania ustawień bezpieczeństwa VM. To błędna ścieżka.
- B. VM Threat Detection (SCC): VMTD wykrywa zagrożenia w pamięci RAM, ale NIE zapewnia sprzętowego szyfrowania pamięci ani ochrony procesu bootowania (to robią Shielded VM i Confidential Computing).
- D. Hardened images: Skanowanie obrazów jest dobrą praktyką (część procesu budowania), ale użycie "zwykłego" twardego obrazu (bez Shielded VM/Confidential Computing) nie daje ochrony sprzętowej na poziomie bootowania czy szyfrowania RAM-u.

Wskazówki i triki (Tips & Tricks):
- "Boot-level/kernel-level malware protection" = Shielded VM.
- "Data in use encryption" / "Hardware-based RAM encryption" = Confidential Computing.
- "Enforce across organization" = Organization Policy.

Praktyczne informacje na egzamin:
- Zapamiętaj: Shielded VM chroni integralność (Boot), a Confidential VM chroni poufność (RAM). Najwyższy poziom bezpieczeństwa to połączenie obu tych technologii.

Analiza i Podsumowanie (AI)

Kluczowe zagadnienia

Sugerowana odpowiedź: C

Analiza strategiczna: To pytanie testuje Twoją znajomość "poufności obliczeniowej" (Confidential Computing). Przez lata był to brakujący element w bezpieczeństwie chmurowym. Google jako lider w tej dziedzinie pozwala na całkowite odizolowanie danych klienta od infrastruktury dostawcy. Na egzaminie zawsze łącz "Data in use" z "Confidential VMs".

Dodatkowe wskazówki

  • Włączenie Confidential VMs wiąże się z niewielkim narzutem wydajnościowym (kilka procent), co wynika z procesu szyfrowania/deszyfrowania "w locie" przez procesor.
  • Pamiętaj, że do działania tej funkcji system operacyjny wewnątrz VM musi być nowoczesny i wspierać odpowiednie sterowniki (np. obrazy Shielded VM).
