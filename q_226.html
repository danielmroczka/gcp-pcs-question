Question 226 / 361

Your organization wants to protect all workloads that run on Compute Engine VM to ensure that the instances weren't compromised by boot-level or kernel-level malware. Also, you need to ensure that data in use on the VM cannot be read by the underlying host system by using a hardware-based solution. What should you do?

  • A. 1. Use Google Shielded VM including secure boot, Virtual Trusted Platform Module (vTPM), and integrity monitoring. 2. Create a Cloud Run function to check for the VM settings, generate metrics, and run the function regularly.
  • B. 1. Activate Virtual Machine Threat Detection in Security Command Center (SCC) Premium. 2. Monitor the findings in SCC.
  • C. 1. Use Google Shielded VM including secure boot, Virtual Trusted Platform Module (vTPM), and integrity monitoring. 2. Activate Confidential Computing. 3. Enforce these actions by using organization policies.
  • D. 1. Use secure hardened images from the Google Cloud Marketplace. 2. When deploying the images, activate the Confidential Computing option. 3. Enforce the use of the correct images and Confidential Computing by using organization policies.
Show Suggested Answer Hide Answer
Suggested Answer: C

Wyjaśnienie

1. Prawidłowa odpowiedź lub odpowiedzi:
C. 1. Use Google Shielded VM including secure boot, Virtual Trusted Platform Module (vTPM), and integrity monitoring. 2. Activate Confidential Computing. 3. Enforce these actions by using organization policies.

2. Kompleksowe wyjaśnienie dlaczego dana odpowiedź jest prawidłowa (Analiza):
Odpowiedź C jest prawidłowa, ponieważ łączy dwa zaawansowane mechanizmy bezpieczeństwa maszyn wirtualnych w GCP w celu ochrony przed zagrożeniami na różnych etapach cyklu życia danych:
1. **Zabezpieczenie przed malware podczas rozruchu (Shielded VMs):** Shielded VMs zapewniają ochronę przed rootkitami i bootkitami na poziomie jądra (kernel) i bootloadera za pomocą Secure Boot (podpisywanie cyfrowe komponentów startowych), vTPM (weryfikacja stanu maszyny) oraz Integrity Monitoring (raportowanie zmian w procesie bootowania).
2. **Szyfrowanie danych w użyciu (Confidential Computing):** Confidential VMs szyfrują dane w pamięci RAM za pomocą kluczy generowanych sprzętowo przez procesor (np. AMD SEV). Uniemożliwia to odczytanie danych w użyciu przez hypervisor Google Cloud, system operacyjny hosta oraz inne maszyny wirtualne współdzielące ten sam serwer fizyczny.
3. **Wymuszenie automatyczne:** Użycie polityk organizacji (np. `compute.requireConfidentialCompute` oraz `compute.requireShieldedVm`) gwarantuje, że żadna maszyna w organizacji nie zostanie uruchomiona bez tych zabezpieczeń, eliminując ryzyko błędów ludzkich.

3. Wyjaśnienie z osobna każdej niepoprawnej odpowiedzi:
A. ...Create a Cloud Run function to check for the VM settings...
   * Dlaczego nieprawidłowa: Monitorowanie za pomocą funkcji Cloud Run (reaktywne) pozwala jedynie na wykrycie maszyn niezgodnych z zasadami po ich utworzeniu. Nie zabezpiecza pamięci RAM (brak Confidential Computing) i nie zapobiega samemu wdrożeniu maszyn podatnych.
B. 1. Activate Virtual Machine Threat Detection in Security Command Center...
   * Dlaczego nieprawidłowa: VMTD to usługa detekcyjna (wykrywa malware w uruchomionej pamięci). Nie zapobiega infekcji na poziomie bootowania (brak Shielded VM) ani nie szyfruje pamięci w użyciu przed wglądem z poziomu hosta fizycznego.
D. 1. Use secure hardened images from the Google Cloud Marketplace...
   * Dlaczego nieprawidłowa: Choć utwardzone obrazy (hardened images) są dobrą praktyką, to same w sobie nie zapewniają sprzętowej ochrony procesu bootowania (Shielded VM) ani szyfrowania pamięci RAM (Confidential Computing) bez jawnej aktywacji tych funkcji na poziomie platformy Compute Engine.

4. Wskazówki, hinty, tips and tricks:
* Ochrona bootowania/jądra przed malware -> **Shielded VM** (Secure Boot, vTPM).
* Ochrona danych w użyciu (in-use data / RAM encryption) -> **Confidential Computing** (Confidential VMs).
* Zawsze wdrażaj te zabezpieczenia w sposób prewencyjny za pomocą polityk organizacji (Organization Policies).

5. Reguły wyboru odpowiedzi (Słowa kluczowe):
* Boot-level/kernel-level malware protection + data in use cannot be read by host -> Shielded VM + Confidential Computing.
