Question 20 / 361

How should a customer reliably deliver Stackdriver logs from GCP to their on-premises SIEM system?

  • A. Send all logs to the SIEM system via an existing protocol such as syslog.
  • B. Configure every project to export all their logs to a common BigQuery DataSet, which will be queried by the SIEM system.
  • D. Build a connector for the SIEM to query for all logs in real time from the GCP RESTful JSON APIs.
Show Suggested Answer Hide Answer
Suggested Answer: C

Wyjaśnienie

**Poprawna odpowiedź: C**

**1. Kompleksowe wyjaśnienie poprawnej odpowiedzi:**
Wymagane jest niezawodne (reliable) dostarczenie logów z GCP do lokalnego systemu SIEM w czasie rzeczywistym:
- **Skonfigurowanie sinków logów (Organizational Log Sinks) do eksportu logów do tematu Cloud Pub/Sub, a następnie przesłanie ich do SIEM za pomocą potoku Dataflow (C):** Pub/Sub działa jako bufor kolejki komunikatów, gwarantując dostarczenie wiadomości ("at-least-once delivery") i odporność na awarie sieci czy przeciążenia systemu SIEM. Cloud Dataflow automatycznie przetwarza i przekazuje strumień logów z Pub/Sub do lokalnego SIEM (np. Splunk) przy użyciu dedykowanych szablonów Google.

**2. Wyjaśnienie niepoprawnych odpowiedzi:**
- **A. Send logs via syslog:** Stackdriver (Cloud Logging) nie posiada wbudowanego mechanizmu bezpośredniego wysyłania logów protokołem syslog do zewnętrznych lokalizacji bez dodatkowych agentów i infrastruktury pośredniczącej.
- **B. Export logs to BigQuery:** BigQuery jest bazą danych przeznaczoną do analiz analitycznych (SQL). SIEM musiałby stale odpytywać bazę danych (polling), co jest nieefektywne, kosztowne i nie działa w czasie zbliżonym do rzeczywistego (real-time).
- **D. Query logs via RESTful JSON APIs:** Odpytywanie API Cloud Logging w czasie rzeczywistym dla dużych ilości logów doprowadzi do przekroczenia limitów API (rate limiting) i nie gwarantuje niezawodności w przypadku awarii sieci po stronie lokalnej.

**3. Wskazówki i pułapki egzaminacyjne (Tips & Tricks):**
- Standardowa, zalecana przez Google architektura eksportu logów do systemów trzecich (SIEM/Splunk/Elastic) to: **Cloud Logging Sink -> Cloud Pub/Sub -> Cloud Dataflow -> SIEM**.
- Słowo-klucz: **reliably** i **SIEM** w GCP zawsze oznacza użycie Cloud Pub/Sub jako bufora odpornego na skoki obciążenia.

**4. Reguły wyboru odpowiedzi:**
- Eksport logów do zewnętrznych systemów w czasie rzeczywistym -> Pub/Sub (+ ewentualnie Dataflow).
