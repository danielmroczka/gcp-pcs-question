Question 19 / 361

You need to follow Google-recommended practices to leverage envelope encryption and encrypt data at the application layer. What should you do?

  • A. Generate a data encryption key (DEK) locally to encrypt the data, and generate a new key encryption key (KEK) in Cloud KMS to encrypt the DEK. Store both the encrypted data and the encrypted DEK.
  • B. Generate a data encryption key (DEK) locally to encrypt the data, and generate a new key encryption key (KEK) in Cloud KMS to encrypt the DEK. Store both the encrypted data and the KEK.
  • C. Generate a new data encryption key (DEK) in Cloud KMS to encrypt the data, and generate a key encryption key (KEK) locally to encrypt the key. Store both the encrypted data and the encrypted DEK.
  • D. Generate a new data encryption key (DEK) in Cloud KMS to encrypt the data, and generate a key encryption key (KEK) locally to encrypt the key. Store both the encrypted data and the KEK.
Show Suggested Answer Hide Answer
Suggested Answer: A

Wyjaśnienie

**Poprawna odpowiedź: A**

**1. Kompleksowe wyjaśnienie poprawnej odpowiedzi:**
Envelope Encryption (Szyfrowanie kopertowe) polega na szyfrowaniu danych za pomocą lokalnego klucza (Data Encryption Key - DEK), a następnie zaszyfrowaniu tego klucza za pomocą klucza nadrzędnego (Key Encryption Key - KEK) zarządzanego w Cloud KMS:
- **Wygenerowanie DEK lokalnie, zaszyfrowanie danych kluczem DEK, wygenerowanie KEK w Cloud KMS w celu zaszyfrowania DEK, a następnie zapisanie zaszyfrowanych danych oraz zaszyfrowanego DEK (A):** Ta metoda minimalizuje opóźnienia sieciowe, ponieważ dane są szyfrowane na miejscu (lokalnie) szybkim algorytmem symetrycznym (np. AES-256), a do usługi KMS przesyłany jest tylko mały klucz DEK w celu zaszyfrowania (tzw. "opakowania"). Przechowujemy zaszyfrowany DEK obok danych – do odszyfrowania aplikacja wyśle zaszyfrowany DEK do KMS, otrzyma odszyfrowany DEK i nim odszyfruje dane.

**2. Wyjaśnienie niepoprawnych odpowiedzi:**
- **B. Store both the encrypted data and the KEK:** KEK to klucz główny (klucz-klucz), który nigdy nie opuszcza bezpiecznego modułu HSM w Cloud KMS. Zapisanie KEK lokalnie obok danych jest niemożliwe i zaprzecza idei bezpieczeństwa KMS.
- **C. Generate a new DEK in Cloud KMS, generate KEK locally:** DEK (klucz szyfrowania danych) jest generowany lokalnie przez aplikację do szyfrowania wolumenu danych, natomiast KEK (klucz szyfrowania klucza) jest generowany i przechowywany w chmurze (KMS), a nie lokalnie.
- **D. Generate DEK in KMS, generate KEK locally and store KEK:** Podobnie jak w C, odwraca to role i narusza zasady bezpieczeństwa szyfrowania kopertowego.

**3. Wskazówki i pułapki egzaminacyjne (Tips & Tricks):**
- Zapamiętaj prosty schemat szyfrowania kopertowego (Envelope Encryption):
  1. Wygeneruj **DEK** lokalnie.
  2. Szyfruj dane lokalnie za pomocą **DEK**.
  3. Wyślij **DEK** do Cloud KMS, aby zaszyfrować go kluczem **KEK**.
  4. Przechowuj **zaszyfrowane dane** + **zaszyfrowany DEK** (nigdy jawny DEK i nigdy KEK!).

**4. Reguły wyboru odpowiedzi:**
- Szyfrowanie kopertowe -> Szyfruj dane lokalnym DEK, szyfruj DEK za pomocą KEK w KMS, przechowuj zaszyfrowany DEK.
