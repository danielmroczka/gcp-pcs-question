Question 19 / 361

You need to follow Google-recommended practices to leverage envelope encryption and encrypt data at the application layer. What should you do?

  • A. Generate a data encryption key (DEK) locally to encrypt the data, and generate a new key encryption key (KEK) in Cloud KMS to encrypt the DEK. Store both the encrypted data and the encrypted DEK.
  • B. Generate a data encryption key (DEK) locally to encrypt the data, and generate a new key encryption key (KEK) in Cloud KMS to encrypt the DEK. Store both the encrypted data and the KEK.
  • C. Generate a new data encryption key (DEK) in Cloud KMS to encrypt the data, and generate a key encryption key (KEK) locally to encrypt the key. Store both the encrypted data and the encrypted DEK.
  • D. Generate a new data encryption key (DEK) in Cloud KMS to encrypt the data, and generate a key encryption key (KEK) locally to encrypt the key. Store both the encrypted data and the KEK.
Show Suggested Answer Hide Answer
Suggested Answer: A

Wyjaśnienie

Potwierdzona odpowiedź: A (Generate a data encryption key (DEK) locally to encrypt the data, and generate a new key encryption key (KEK) in Cloud KMS to encrypt the DEK. Store both the encrypted data and the encrypted DEK.)

Wyjaśnienie: 
Szyfrowanie kopertowe (Envelope Encryption) to proces szyfrowania danych przy użyciu klucza szyfrowania danych (DEK), a następnie zaszyfrowania samego klucza DEK przy użyciu klucza szyfrowania kluczy (KEK). 
- DEK: Generowany lokalnie w aplikacji, używany do szyfrowania dużych zbiorów danych (symetrycznie).
- KEK: Przechowywany bezpiecznie w Cloud KMS. Służy do zaszyfrowania ("owinięcia" - wrapping) klucza DEK.
- Przechowywanie: Aplikacja przechowuje zaszyfrowane dane oraz zaszyfrowany klucz DEK (niejawny). Aby odszyfrować dane, aplikacja musi poprosić KMS o odszyfrowanie DEK przy użyciu KEK, a następnie użyć odzyskanego DEK lokalnie. Jest to wydajne i bezpieczne rozwiązanie warstwy aplikacji.

Dlaczego pozostałe są błędne:
B. Przechowywanie KEK (klucza nadrzędnego) razem z danymi jest całkowicie błędne – KEK musi pozostać bezpiecznie w usłudze KMS.
C, D. Sugerują one generowanie DEK w chmurze i KEK lokalnie, co jest odwrotnością poprawnego modelu. Klucz główny (KEK) powinien być zarządzany przez zaufaną usługę (KMS), a klucze operacyjne (DEK) używane w aplikacji.

Wskazówki egzaminacyjne (Tips & Tricks):
- "Envelope encryption" = Encrypted Data + Encrypted DEK.
- Zapamiętaj: KEK (Key Encryption Key) nigdy nie opuszcza Cloud KMS w postaci jawnej.
- DEK (Data Encryption Key) jest używany do faktycznego szyfrowania danych (zazwyczaj AES-256).

Kluczowe zagadnienia do powtórzenia:
- Envelope Encryption (Szyfrowanie kopertowe)
- Cloud KMS (Key Management Service)
- DEK vs KEK

Dokumentacja:
https://cloud.google.com/kms/docs/envelope-encryption

**Reguła Egzaminacyjna (Exam Rule):**
Zawsze identyfikuj warstwę modelu OSI, na której operuje atak oraz rozwiązanie. DNSSEC działa na poziomie warstwy aplikacji dla DNS, zapobiegając zatruwaniu pamięci podręcznej (Cache Poisoning).

**Haczyki egzaminacyjne (Exam Traps):**
- Mylenie Cloud Armor (WAF - L7) z zabezpieczeniami DNS (DNSSEC - integralność danych DNS).
- Zakładanie, że TLS/SSL wystarczy do ochrony przed przekierowaniem całego ruchu DNS (DNSSEC zabezpiecza sam proces rezolucji, zanim nawiążesz bezpieczne połączenie TLS).

**Głębokie wyjaśnienie techniczne:**
DNSSEC wykorzystuje kryptografię klucza publicznego (RRSIG, DNSKEY, DS) do cyfrowego podpisywania rekordów DNS w strefach (Zone Signing). Dzięki temu resolver DNS może zweryfikować łańcuch zaufania aż do punktu głównego (root zone) bez konieczności polegania wyłącznie na adresie IP serwera autorytatywnego, co drastycznie ogranicza skuteczność ataków typu MITM i cache poisoning.

Analiza i Podsumowanie Dyskusji (AI)

Analiza i Wyjaśnienie

Sugerowana odpowiedź: A

Analiza spornych kwestii (AI): Wiele osób pyta, dlaczego nie generować DEK w KMS. Choć technicznie jest to możliwe, wzorzec 'envelope encryption' optymalizuje wydajność: aplikacja generuje DEK natychmiastowo, szyfruje dane, a KMS używa się tylko do 'zapakowania' tego klucza. To minimalizuje opóźnienia sieciowe przy szyfrowaniu dużych wolumenów danych.
