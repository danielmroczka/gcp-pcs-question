Question 19 / 361

You need to follow Google-recommended practices to leverage envelope encryption and encrypt data at the application layer. What should you do?

  • A. Generate a data encryption key (DEK) locally to encrypt the data, and generate a new key encryption key (KEK) in Cloud KMS to encrypt the DEK. Store both the encrypted data and the encrypted DEK.
  • B. Generate a data encryption key (DEK) locally to encrypt the data, and generate a new key encryption key (KEK) in Cloud KMS to encrypt the DEK. Store both the encrypted data and the KEK.
  • C. Generate a new data encryption key (DEK) in Cloud KMS to encrypt the data, and generate a key encryption key (KEK) locally to encrypt the key. Store both the encrypted data and the encrypted DEK.
  • D. Generate a new data encryption key (DEK) in Cloud KMS to encrypt the data, and generate a key encryption key (KEK) locally to encrypt the key. Store both the encrypted data and the KEK.
Show Suggested Answer Hide Answer
Suggested Answer: A

Wyjaśnienie

Poprawna odpowiedź: A (Generate a data encryption key (DEK) locally to encrypt the data, and generate a new key encryption key (KEK) in Cloud KMS to encrypt the DEK. Store both the encrypted data and the encrypted DEK.)

Analiza poprawności:
Szyfrowanie kopertowe (Envelope Encryption) to standardowa praktyka dla ochrony danych na poziomie aplikacji. Proces wygląda następująco:
1. Aplikacja generuje lokalnie unikalny "Klucz Danych" (DEK - Data Encryption Key).
2. Aplikacja używa DEK do zaszyfrowania danych (szyfrowanie symetryczne, bardzo szybkie).
3. Aplikacja wysyła DEK do Cloud KMS, aby został on zaszyfrowany (opakowany) za pomocą "Klucza Szyfrującego Klucz" (KEK - Key Encryption Key), który bezpiecznie spoczywa w KMS i nigdy nie opuszcza sprzętowego modułu bezpieczeństwa (HSM).
4. Przechowujesz zaszyfrowane dane oraz "zaszyfrowany DEK" razem (jako "kopertę"). Aby odszyfrować dane, aplikacja najpierw prosi KMS o odszyfrowanie DEK, a potem używa DEK do odczytu danych.

Dlaczego pozostałe są błędne:
B (Store KEK): Nigdy nie przechowujesz KEK obok danych. KEK musi być bezpieczny w KMS.
C, D: DEK generowany w KMS (do szyfrowania dużych zbiorów danych lokalnie) byłby nieefektywny (opóźnienia sieciowe) i niezgodny z zasadami szyfrowania kopertowego.

Wskazówki egzaminacyjne:
- "Envelope Encryption": Szukaj sekwencji: Generuj DEK lokalnie -> Szyfruj dane -> Szyfruj DEK w KMS (KEK).
- Wydajność: Zawsze wybieraj opcje, w których KMS służy do operacji na *kluczach* (mały rozmiar), a nie do szyfrowania dużych *danych* (duży rozmiar).
- Eliminacja: Jeśli odpowiedź mówi o przechowywaniu KEK poza KMS – to jest to błąd bezpieczeństwa.

Sugerowana odpowiedź: A

Analiza spornych kwestii (AI): Ta metoda łączy wydajność szyfrowania symetrycznego (lokalny DEK) z bezpieczeństwem centralnego zarządzania (KEK w KMS z pełnym audytem użycia). Jest to standard w usługach takich jak Cloud Storage (Customer-Managed Encryption Keys - CMEK).
