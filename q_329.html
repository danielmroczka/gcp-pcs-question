Question 329 / 361

Your organization is implementing a new Python application that will be deployed on Cloud Run. The application needs to connect to a MySQL database that runs on Cloud SQL in a different project in your Google Cloud organization. You must secure the connection from the application to the Cloud SQL instance while minimizing management overhead. What should you do?

  • A. Configure a Cloud VPN connection between the two VPCs and use the internal IP address of the Cloud SQL instance to connect.
  • B. Enable the Cloud SQL Auth Proxy on a sidecar container in Cloud Run and use the Unix socket to connect to the database.
  • C. Configure VPC peering between the two projects and use the internal IP address of the Cloud SQL instance.
  • D. Enable SSL/TLS for all connections and whitelist the Cloud Run service account in the Cloud SQL instance settings.
Show Suggested Answer Hide Answer
Suggested Answer: B

Wyjaśnienie

✅ PRAWIDŁOWA ODPOWIEDŹ: B

Prawidłowa odpowiedź: B – Enable the Cloud SQL Auth Proxy on a sidecar container in Cloud Run and use the Unix socket to connect to the Cloud SQL instance.

DLACZEGO B JEST PRAWIDŁOWE?
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
Cloud SQL Auth Proxy to Google-recommended sposób łączenia aplikacji z Cloud SQL:
- Szyfruje połączenia automatycznie (TLS).
- Autoryzacja przez IAM (service account) bez białej listy IP.
- Sidecar container w Cloud Run = bezpośrednie połączenie przez Unix socket (szybsze niż TCP).
- Cross-project: działa między różnymi projektami bez konieczności konfiguracji sieci.
- Brak zarządzania certyfikatami SSL.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
DLACZEGO INNE OPCJE SĄ BŁĘDNE?
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
A. ❌ Cloud VPN = nadmiarowe i drogie dla tego scenariusza. VPN jest dla on-premises, nie między GCP projektami.
C. ❌ VPC peering wymaga konfiguracji sieci i nadal potrzebuje autoryzacji. Bardziej skomplikowane niż Cloud SQL Auth Proxy.
D. ❌ SSL/TLS + whitelist IP = zarządzanie certyfikatami + statyczne IP (Cloud Run nie ma stałego IP). Nie skaluje się dobrze.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
WSKAZÓWKI EGZAMINACYJNE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
• Cloud Run/GKE → Cloud SQL = Cloud SQL Auth Proxy (zawsze Google recommended).
• Cloud SQL Auth Proxy = automatyczny TLS, IAM auth, bez konieczności zarządzania IP.
• Sidecar container w Cloud Run = serwis pomocniczy w tym samym pode.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
REGUŁY
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
• Aplikacja → Cloud SQL = Cloud SQL Auth Proxy (standard).
• Cross-project = Proxy działa natywnie bez dodatkowej konfiguracji sieci.
