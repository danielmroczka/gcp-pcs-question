Question 329 / 361

Your organization is implementing a new Python application that will be deployed on Cloud Run. The application needs to connect to a MySQL database that runs on Cloud SQL in a different project in your Google Cloud organization. You must secure the connection from the application to the Cloud SQL instance while minimizing management overhead. What should you do?

  • A. Configure a Cloud VPN connection between the two VPCs and use the internal IP address of the Cloud SQL instance to connect.
  • B. Enable the Cloud SQL Auth Proxy on a sidecar container in Cloud Run and use the Unix socket to connect to the database.
  • C. Configure VPC peering between the two projects and use the internal IP address of the Cloud SQL instance.
  • D. Enable SSL/TLS for all connections and whitelist the Cloud Run service account in the Cloud SQL instance settings.
Show Suggested Answer Hide Answer
Suggested Answer: B

Wskazówki egzaminacyjne (Tips & Tricks)

Reguła Egzaminacyjna (Exam Rule): 
W pytaniach typu 'Security in GCP', zawsze priorytetyzuj rozwiązania natywne (SCC, Cloud KMS, Secret Manager, VPC SC) nad rozwiązaniami typu 'third-party' lub 'self-managed', chyba że scenariusz wymaga specyficznej integracji hybrydowej.

Haczyki egzaminacyjne (Exam Traps):
- Pułapka 'Least Privilege': Egzamin często podpowiada role o szerokim zakresie (np. 'Editor' lub 'Owner') – zawsze odrzucaj je na rzecz ról predefiniowanych o najmniejszym zakresie uprawnień.
- Pułapka 'Logging vs Monitoring': Pamiętaj: Audit Logs służą do badania aktywności (Who/What/When), a Monitoring do zbierania metryk wydajnościowych.

Głębokie wyjaśnienie techniczne:
Każda architektura bezpieczeństwa w GCP powinna być projektowana w oparciu o 'Security by Default'. Oznacza to m.in. szyfrowanie w spoczynku (domyślne), tożsamość opartą na rolach (IAM) oraz pełną widoczność zapewnianą przez scentralizowane logowanie (Cloud Logging/SCC).

Wyjaśnienie

Poprawna odpowiedź: B (Enable the Cloud SQL Auth Proxy on a sidecar container in Cloud Run and use the Unix socket to connect to the database.)

Dlaczego ta odpowiedź jest poprawna:
- Cloud SQL Auth Proxy: To "bezpieczny i najmniej zarządzalny" (minimizing management overhead) sposób połączenia z Cloud SQL.
- Sidecar container: W Cloud Run, Cloud SQL Auth Proxy może działać jako sidecar, co bezpiecznie tuneluje połączenie (z automatycznym szyfrowaniem TLS i autoryzacją IAM) bez konieczności otwierania instancji bazy na świat lub konfigurowania skomplikowanych połączeń sieciowych (VPN/Peering).

Analiza niepoprawnych odpowiedzi:
- A, C: Konfiguracja VPN lub VPC peering w celu połączenia Cloud Run z Cloud SQL to "overkill" (niepotrzebny narzut administracyjny), gdy mamy dedykowane narzędzie w postaci Auth Proxy.
- D: Whitelisting IP to metoda mniej bezpieczna niż Auth Proxy, a SSL/TLS to tylko szyfrowanie transportu, nie załatwia kwestii autoryzacji IAM.

Wskazówki i triki (Tips & Tricks):
- "Cloud Run" + "Cloud SQL" + "Secure connection" + "Minimize management overhead" = Cloud SQL Auth Proxy (sidecar).
- Pamiętaj: Auth Proxy zarządza szyfrowaniem i autoryzacją IAM za Ciebie.

Praktyczne informacje na egzamin:
- Zapamiętaj: Cloud SQL Auth Proxy to "złoty standard" bezpiecznego łączenia aplikacji z bazami danych w GCP.
