Question 134 / 361

You need to set up a Cloud interconnect connection between your company's on-premises data center and VPC host network. You want to make sure that on-premises applications can only access Google APIs over the Cloud Interconnect and not through the public internet. You are required to only use APIs that are supported by VPC Service Controls to mitigate against exfiltration risk to non-supported APIs. How should you configure the network?

  • A. Enable Private Google Access on the regional subnets and global dynamic routing mode.
  • B. Set up a Private Service Connect endpoint IP address with the API bundle of "all-apis", which is advertised as a route over the Cloud interconnect connection.
  • C. Use private.googleapis.com to access Google APIs using a set of IP addresses only routable from within Google Cloud, which are advertised as routes over the connection.
  • D. Use restricted googleapis.com to access Google APIs using a set of IP addresses only routable from within Google Cloud, which are advertised as routes over the Cloud Interconnect connection.
Show Suggested Answer Hide Answer
Suggested Answer: D

Wyjaśnienie

Potwierdzona odpowiedź: D (Use restricted googleapis.com to access Google APIs using a set of IP addresses only routable from within Google Cloud, which are advertised as routes over the Cloud Interconnect connection).

Wyjaśnienie:
Aby umożliwić aplikacjom on-premises dostęp do usług Google Cloud przy jednoczesnym zachowaniu ochrony VPC Service Controls (VPC SC), należy skonfigurować dostęp przez domenę `restricted.googleapis.com`.
1. `restricted.googleapis.com` rozwiązuje się na zakres adresów IP `199.36.153.4/30`, który nie jest rutowalny w internecie.
2. Ten zakres musi być rozgłoszony do sieci on-premises przez Cloud Interconnect (BGP).
3. Kluczową cechą `restricted.googleapis.com` jest to, że obsługuje ona wyłącznie API wspierane przez VPC Service Controls. Jeśli aplikacja spróbuje połączyć się z usługą, która nie jest wspierana (i tym samym mogłaby służyć do exfiltracji danych), połączenie zostanie zablokowane. Jest to wymaganie bezpośrednio wymienione w zadaniu.

Dlaczego pozostałe są błędne:
- A. Enable Private Google Access on the regional subnets...: Private Google Access (PGA) dotyczy instancji wewnątrz VPC, a nie hostów on-premises. Ponadto samo PGA nie wymusza korzystania wyłącznie z API wspieranych przez VPC SC.
- B. Set up a Private Service Connect endpoint... bundle of "all-apis": Private Service Connect (PSC) to nowoczesna metoda, ale paczka "all-apis" zawiera wszystkie usługi Google, w tym te niewspierane przez VPC SC, co narusza wymóg minimalizacji ryzyka exfiltracji do nieobsługiwanych API.
- C. Use private.googleapis.com...: Domena `private.googleapis.com` (`199.36.153.8/30`) pozwala na dostęp do większości usług Google (w tym Map, YouTube itp.), które nie są wspierane przez VPC Service Controls. Nie zapewnia więc ochrony przed exfiltracją danych do usług spoza perymetru bezpieczeństwa.

Wskazówki egzaminacyjne (Tips & Tricks):
- Słowo klucz "VPC Service Controls" + "on-premises/Interconnect" = zawsze szukaj `restricted.googleapis.com`.
- `restricted.googleapis.com` = tylko usługi wspierane przez VPC SC.
- `private.googleapis.com` = prawie wszystkie usługi Google (szerszy zakres, mniejsze bezpieczeństwo).
- Pamiętaj o konfiguracji DNS w sieci on-premises, aby mapować żądania do API na te specjalne zakresy IP.

Kluczowe zagadnienia do powtórzenia:
- VPC Service Controls (VPC SC).
- Private Google Access for on-premises hosts.
- Różnice między `restricted.googleapis.com` a `private.googleapis.com`.
