Question 266 / 361

Your organization is migrating a complex application to Google Cloud. The application has multiple internal components that interact with each other across several Google Cloud projects. Security is a major concern, and you must design an authorization scheme for administrators that aligns with the principles of least privilege and separation of duties. What should you do?

  • A. Identify the users who will migrate the application, revoke the default user roles and assign the users with purposely created custom roles.
  • B. Use multiple external identity providers (IdP) configured to use different SAML profiles and federate the IdPs for each application component.
  • C. Configure multi-factor authentication (MFA) to enforce the use of physical tokens for all users who will migrate the application.
  • D. No action needed. When a Google Cloud organization is created, the appropriate permissions are automatically assigned to all users in the domain.
Show Suggested Answer
Suggested Answer: A

Wyjaśnienie

1. Prawidłowa odpowiedź lub odpowiedzi:
A. Identify the users who will migrate the application, revoke the default user roles and assign the users with purposely created custom roles.

2. Kompleksowe wyjaśnienie dlaczego dana odpowiedź jest prawidłowa (Analiza):
Odpowiedź A jest prawidłowa, ponieważ tworzenie i przypisywanie ról niestandardowych (Custom Roles) jest podstawowym i zalecanym mechanizmem w GCP do wdrażania zasad najmniejszych uprawnień (least privilege) oraz rozdziału obowiązków (separation of duties).

Dlaczego to podejście jest poprawne:
a. **Odrzucenie ról domyślnych:** Role predefiniowane o szerokim zakresie (takie jak Owner, Editor czy Viewer) dają zbyt duże uprawnienia (np. prawo do usuwania zasobów lub wglądu w dane poufne).
b. **Custom Roles (Role niestandardowe):** Pozwalają administratorowi na wybranie z dokładnością do pojedynczego uprawnienia API (np. `compute.instances.start` bez prawa do ich usuwania) zestawu akcji niezbędnych do wykonania migracji przez poszczególnych inżynierów. Dzięki temu każdy użytkownik ma dostęp wyłącznie do tych funkcji, które są mu niezbędne do pracy.

3. Wyjaśnienie z osobna każdej niepoprawnej odpowiedzi:
B. Use multiple external identity providers (IdP) configured to use different SAML profiles...
   * Dlaczego nieprawidłowa: Konfigurowanie wielu dostawców tożsamości i profili SAML dla poszczególnych komponentów aplikacji wprowadza olbrzymią złożoność architektoniczną i utrudnia zarządzanie tożsamościami. SSO/IdP odpowiada za uwierzytelnianie (kto się loguje), a nie za autoryzację granularną (co może robić) wewnątrz zasobów GCP, co kontroluje IAM.
C. Configure multi-factor authentication (MFA) to enforce the use of physical tokens...
   * Dlaczego nieprawidłowa: Wdrożenie MFA/2SV jest kluczową praktyką bezpieczeństwa (chroni przed kradzieżą poświadczeń), ale samo w sobie nie rozwiązuje problemu nadmiernych uprawnień. Nawet z fizycznym tokenem, użytkownik z rolą Owner nadal ma zbyt szerokie uprawnienia, co łamie zasadę least privilege.
D. No action needed. When a Google Cloud organization is created, the appropriate permissions...
   * Dlaczego nieprawidłowa: Jest to nieprawda. Po utworzeniu organizacji domyślni użytkownicy domeny nie otrzymują automatycznie precyzyjnych uprawnień administracyjnych dostosowanych do konkretnej migracji aplikacji. Brak jakichkolwiek działań doprowadzi do braku kontroli dostępu lub zablokowania prac.

4. Wskazówki, hinty, tips and tricks:
* Najmniejsze uprawnienia (Least Privilege) w IAM -> Unikaj ról podstawowych (primitive roles: Owner, Editor, Viewer). Twórz **Custom Roles** (role dedykowane) z minimalnym zakresem uprawnień API.
* Rozdział obowiązków (Separation of Duties) polega na rozdzieleniu ról tak, aby jedna osoba nie mogła kontrolować całego procesu (np. deweloper nie może być administratorem bezpieczeństwa).

5. Reguły wyboru odpowiedzi (Słowa kluczowe):
* Granular access control / least privilege / separation of duties -> Revoke default roles + create custom roles.
