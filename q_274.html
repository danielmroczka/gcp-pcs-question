Question 274 / 361

Your EU-based organization stores both Personally Identifiable Information (PII) and non-PII data in Cloud Storage buckets across multiple Google Cloud regions. EU data privacy laws require that the PII data must not be stored outside of the EU. To help meet this compliance requirement, you want to detect if Cloud Storage buckets outside of the EU contain healthcare data. What should you do?

  • A. Create a Sensitive Data Protection job. Specify the infoType of data to be detected and run the job across all Google Cloud Storage buckets.
  • B. Create a log sink with a filter on resourceLocation.currentLocations. Trigger an alert if a log message appears with a non-EU country.
  • C. Activate Security Command Center Premium. Use compliance monitoring to detect resources that do not follow the applicable healthcare regulation.
  • D. Enforce the gcp.resourceLocations organization policy and add "EU" in a custom rule that only applies on resources with the tag "healthcare".
Show Suggested Answer Hide Answer
Suggested Answer: A

Wyjaśnienie

Poprawna odpowiedź: A (Create a Sensitive Data Protection job. Specify the infoType of data to be detected and run the job across all Google Cloud Storage buckets.)

Dlaczego ta odpowiedź jest poprawna:
- Cloud DLP (Sensitive Data Protection): To jedyne narzędzie w GCP, które potrafi "czytać" treść plików wewnątrz bucketów i identyfikować konkretne typy danych (np. numery ubezpieczenia zdrowotnego). Pytanie dotyczy wykrycia danych wrażliwych (PII/healthcare) w konkretnej lokalizacji (spoza EU).

Analiza niepoprawnych odpowiedzi:
- B. Log sink: Logi pokazują dostęp do bucketa, ale nie powiedzą Ci, CO jest wewnątrz pliku (jaki typ danych).
- C. SCC Compliance: SCC monitoruje KONFIGURACJĘ (np. czy bucket jest publiczny), ale nie analizuje zawartości plików w poszukiwaniu PII.
- D. Org Policy: Org Policy zapobiega tworzeniu zasobów w złym regionie, ale nie skanuje istniejących danych w poszukiwaniu "healthcare data".

Wskazówki i triki (Tips & Tricks):
- "Detect PII/Sensitive data inside storage" = Sensitive Data Protection (DLP).

Praktyczne informacje na egzamin:
- Zapamiętaj: DLP to Twój detektor "treści", a Org Policy to Twój detektor "konfiguracji".
- Jeśli musisz znaleźć konkretny typ danych w pliku -> DLP.

Kluczowe zagadnienia

Sugerowana odpowiedź: A

Analiza strategiczna: To pytanie sprawdza umiejętność odróżnienia detekcji "konfiguracyjnej" (gdzie jest zasób?) od detekcji "treściowej" (co jest w zasobie?). Sensitive Data Protection (DLP) jest jedynym narzędziem, które głęboko skanuje pliki w poszukiwaniu wzorców danych.
