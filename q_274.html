Question 274 / 361

Your EU-based organization stores both Personally Identifiable Information (PII) and non-PII data in Cloud Storage buckets across multiple Google Cloud regions. EU data privacy laws require that the PII data must not be stored outside of the EU. To help meet this compliance requirement, you want to detect if Cloud Storage buckets outside of the EU contain healthcare data. What should you do?

  • A. Create a Sensitive Data Protection job. Specify the infoType of data to be detected and run the job across all Google Cloud Storage buckets.
  • B. Create a log sink with a filter on resourceLocation.currentLocations. Trigger an alert if a log message appears with a non-EU country.
  • C. Activate Security Command Center Premium. Use compliance monitoring to detect resources that do not follow the applicable healthcare regulation.
  • D. Enforce the gcp.resourceLocations organization policy and add "EU" in a custom rule that only applies on resources with the tag "healthcare".
Show Suggested Answer
Suggested Answer: A

Wyjaśnienie

1. Prawidłowa odpowiedź lub odpowiedzi:
A. Create a Sensitive Data Protection job. Specify the infoType of data to be detected and run the job across all Google Cloud Storage buckets.

2. Kompleksowe wyjaśnienie dlaczego dana odpowiedź jest prawidłowa (Analiza):
Odpowiedź A jest prawidłowa, ponieważ Sensitive Data Protection (dawniej Cloud Data Loss Prevention - Cloud DLP) jest jedynym dedykowanym narzędziem w GCP do głębokiego skanowania (inspection) zawartości plików i wykrywania danych wrażliwych (takich jak dane medyczne ICD-10, dane osobowe, numery kart) na podstawie zdefiniowanych typów informacji (infoTypes).

Jak to działa:
a. **Inspekcja zawartości:** Zwykły monitoring i logi sieciowe nie wiedzą, co znajduje się wewnątrz plików PDF czy CSV zapisanych w Cloud Storage.
b. **Konfiguracja zadania DLP:** Tworzymy zadanie inspekcji (Inspection Job) dla całej organizacji lub wybranych kubełków poza UE.
c. **Wykrywanie:** Wskazujemy infoType powiązane z danymi medycznymi (np. `US_HEALTHCARE_NPI`, `POLISH_PESEL` itp.). DLP przeskanuje obiekty i zgłosi raport o wykryciu wrażliwych danych medycznych, co pozwala na ich relokację lub usunięcie.

3. Wyjaśnienie z osobna każdej niepoprawnej odpowiedzi:
B. Create a log sink with a filter on resourceLocation... Trigger an alert...
   * Dlaczego nieprawidłowa: Logi audytowe (Audit Logs) oraz logi lokalizacji zasobów informują o tym, *gdzie* i *przez kogo* kubełek został utworzony lub zmodyfikowany. Nie analizują one zawartości plików wewnątrz kubełka i nie wiedzą, czy w pliku tekstowym znajdują się dane pacjentów.
C. Activate Security Command Center Premium. Use compliance monitoring to detect resources...
   * Dlaczego nieprawidłowa: Compliance Monitoring w SCC sprawdza zgodność konfiguracji chmury (np. czy kubełek ma włączone szyfrowanie). Nie skanuje zawartości plików pod kątem występowania w nich ciągów znaków reprezentujących dane medyczne (PII/PHI).
D. Enforce the gcp.resourceLocations organization policy and add "EU" in a custom rule...
   * Dlaczego nieprawidłowa: Polityka lokalizacji zasobów zablokuje tworzenie nowych kubełków poza UE. Jednak nie pomoże w wykryciu, czy w już istniejących kubełkach poza UE znajdują się nielegalnie zapisane pliki z danymi medycznymi.

4. Wskazówki, hinty, tips and tricks:
* Wykrywanie i analiza danych wrażliwych (PII, PHI, karty płatnicze) wewnątrz plików przechowywanych w GCP -> Zawsze używaj **Sensitive Data Protection (Cloud DLP)**.
* Skaner DLP potrafi klasyfikować dane bez modyfikowania oryginalnych plików.

5. Reguły wyboru odpowiedzi (Słowa kluczowe):
* Detect if Cloud Storage buckets contain healthcare data (PII) -> Sensitive Data Protection (Cloud DLP) job.
