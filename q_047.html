Question 47 / 361

A large e-retailer is moving to Google Cloud Platform with its ecommerce website. The company wants to ensure payment information is encrypted between the customer's browser and GCP when the customers checkout online. What should they do?

  • A. Configure an SSL Certificate on an L7 Load Balancer and require encryption.
  • B. Configure an SSL Certificate on a Network TCP Load Balancer and require encryption.
  • C. Configure the firewall to allow inbound traffic on port 443, and block all other inbound traffic.
  • D. Configure the firewall to allow outbound traffic on port 443, and block all other outbound traffic.
Show Suggested Answer Hide Answer
Suggested Answer: A

Wyjaśnienie

Potwierdzona odpowiedź: A (L7 Load Balancer + SSL Certificate)

Wyjaśnienie:
Aby zabezpieczyć dane płatnicze przesyłane przez stronę e-commerce (ruch HTTPS), konieczne jest zastosowanie szyfrowania TLS/SSL pomiędzy przeglądarką klienta a infrastrukturą GCP.
1. L7 Load Balancer (HTTP(S) Load Balancer): Jest to load balancer warstwy aplikacji, który natywnie wspiera "SSL Termination" (zakończenie sesji SSL). Pozwala on na zainstalowanie certyfikatu SSL na samym LB, co odciąża serwery backendowe z procesu szyfrowania/deszyfrowania.
2. Require encryption: Można skonfigurować LB tak, aby wymuszał ruch HTTPS (np. przekierowując cały ruch z HTTP na HTTPS) oraz używał nowoczesnych zestawów szyfrów (Cipher Suites). Jest to standardowe rozwiązanie dla aplikacji webowych.

Dlaczego pozostałe są błędne:
B. Network TCP Load Balancer: Działa w warstwie 4 (transportowej). Choć może on przekazywać ruch SSL do backendów (SSL pass-through), to zazwyczaj nie on służy do "zarządzania certyfikatem" i terminacji sesji dla aplikacji webowych w sposób tak zintegrowany jak L7 LB. L7 oferuje dodatkowe funkcje jak Cloud Armor, które są kluczowe dla e-commerce.
C i D. Firewall rules: Same reguły firewall otwierające port 443 pozwalają jedynie na przepływ pakietów, ale NIE zapewniają szyfrowania ani nie zarządzają certyfikatami SSL. Firewall to warstwa kontroli dostępu, a nie mechanizm szyfrowania sesji.

Wskazówki egzaminacyjne (Tips & Tricks):
- Strona internetowa + szyfrowanie = HTTP(S) Load Balancer (L7).
- "SSL Termination" na Load Balancerze to najlepsza praktyka (best practice) pozwalająca na centralne zarządzanie certyfikatami (np. Google-managed SSL certificates).
- Pamiętaj, że do spełnienia wymagań PCI DSS konieczne jest użycie TLS 1.2+.

Kluczowe zagadnienia do powtórzenia:
- Typy Load Balancerów w GCP (Global vs Regional, L4 vs L7).
- SSL Termination vs SSL Pass-through.
- Google-managed SSL certificates.

Analiza i Podsumowanie Dyskusji (AI)

Analiza i Wyjaśnienie

Sugerowana odpowiedź: A

Analiza spornych kwestii (AI): W e-commerce bezpieczeństwo warstwy aplikacji jest kluczowe. L7 Load Balancer pozwala na inspekcję nagłówków HTTP, stosowanie reguł WAF (Cloud Armor) i łatwą integrację z certyfikatami zarządzanymi przez Google, co czyni go jedynym rozsądnym wyborem w tym scenariuszu.

Wyjaśnienie Audytowe

Reguła Egzaminacyjna (Exam Rule):
Pamiętaj, że w egzaminie Professional Cloud Security Engineer kluczowe jest wybieranie rozwiązań najmniej uprzywilejowanych (Principle of Least Privilege), zoptymalizowanych kosztowo i spełniających wymogi compliancy (np. CMEK, Data Loss Prevention).

Haczyki egzaminacyjne (Exam Traps):
- Wybór rozwiązań, które wydają się wygodne, ale nie spełniają wymogów bezpieczeństwa (np. zbyt szerokie uprawnienia IAM).
- Mylenie usług: np. Cloud Armor (WAF) z Cloud IAP (Identity-Aware Proxy).

Głębokie wyjaśnienie techniczne (GCP Professional Cloud Security Engineer):
W każdym pytaniu analizuj warstwy: IAM (dostęp), Encryption (at rest/in transit), Logging/Monitoring (Audit Logs, Cloud Logging, Security Command Center) oraz Networking (VPC Service Controls, Firewall Rules). GCP kładzie duży nacisk na współdzieloną odpowiedzialność (Shared Responsibility Model) - klient odpowiada za konfigurację zabezpieczeń wewnątrz usług chmurowych.
