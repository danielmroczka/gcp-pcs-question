Question 47 / 361

A large e-retailer is moving to Google Cloud Platform with its ecommerce website. The company wants to ensure payment information is encrypted between the customer's browser and GCP when the customers checkout online. What should they do?

  • A. Configure an SSL Certificate on an L7 Load Balancer and require encryption.
  • B. Configure an SSL Certificate on a Network TCP Load Balancer and require encryption.
  • C. Configure the firewall to allow inbound traffic on port 443, and block all other inbound traffic.
  • D. Configure the firewall to allow outbound traffic on port 443, and block all other outbound traffic.
Show Suggested Answer Hide Answer
Suggested Answer: A

Wyjaśnienie

**Poprawna odpowiedź: A**

**1. Kompleksowe wyjaśnienie poprawnej odpowiedzi:**
Dla serwisu e-commerce kluczowe jest zabezpieczenie przesyłu danych płatniczych (kart kredytowych) za pomocą protokołu HTTPS (SSL/TLS) między przeglądarką klienta a chmurą GCP:
- **Skonfigurowanie certyfikatu SSL na warstwowym Load Balancerze L7 (HTTP(S) Load Balancer) i wymuszenie szyfrowania (A):** HTTPS Load Balancer (Load Balancer warstwy 7) umożliwia zainstalowanie certyfikatu SSL (zarządzanego przez Google lub własnego). Odpowiada za proces deszyfrowania (SSL termination) na brzegu sieci Google, odciążając serwery aplikacyjne backendu. L7 Load Balancer pozwala również na inteligentne kierowanie ruchem HTTP/HTTPS, wstrzykiwanie nagłówków bezpieczeństwa i integrację z zapaporą Cloud Armor WAF, co jest kluczowe dla witryn e-commerce.

**2. Wyjaśnienie niepoprawnych odpowiedzi:**
- **B. Certyfikat SSL na Network TCP Load Balancerze:** Network Load Balancer (NLB) działa w warstwie 4 (L4) i nie terminuje sesji SSL/TLS – przekazuje surowe pakiety TCP bezpośrednio do maszyn backendowych. Wymagałoby to instalacji i zarządzania certyfikatami SSL na każdej maszynie wirtualnej z osobna, co utrudnia administrację i nie realizuje centralnej terminacji na LB.
- **C. Konfiguracja firewall na ruch przychodzący portu 443 i blokowanie reszty:** Samo otwarcie portu 443 na zapaporze sieciowej nie konfiguruje szyfrowania ani nie instaluje certyfikatu SSL niezbędnego do bezpiecznej komunikacji HTTPS.
- **D. Konfiguracja firewall na ruch wychodzący portu 443:** Dotyczy filtrowania ruchu opuszczającego sieć VPC i nie ma wpływu na proces szyfrowania połączeń przychodzących od klientów zewnętrznych.

**3. Wskazówki i pułapki egzaminacyjne (Tips & Tricks):**
- Witryny webowe i e-commerce (ruch HTTP/HTTPS) wymagające terminacji certyfikatów SSL na poziomie chmury zawsze powinny korzystać z **HTTP(S) Load Balancer (L7)**.
- L7 Load Balancer obsługuje tzw. Google-managed SSL certificates (darmowe, automatycznie odnawiane certyfikaty).

**4. Reguły wyboru odpowiedzi:**
- Terminacja SSL dla ruchu webowego (HTTPS) -> L7 HTTP(S) Load Balancer.

**5. Dodatkowe źródła:**
- Google Cloud HTTP(S) Load Balancing overview: https://cloud.google.com/load-balancing/docs/https

Wyjaśnienie Audytowe

Reguła Egzaminacyjna (Exam Rule):
Pamiętaj, że w egzaminie Professional Cloud Security Engineer kluczowe jest wybieranie rozwiązań najmniej uprzywilejowanych (Principle of Least Privilege), zoptymalizowanych kosztowo i spełniających wymogi compliancy (np. CMEK, Data Loss Prevention).

Haczyki egzaminacyjne (Exam Traps):
- Wybór rozwiązań, które wydają się wygodne, ale nie spełniają wymogów bezpieczeństwa (np. zbyt szerokie uprawnienia IAM).
- Mylenie usług: np. Cloud Armor (WAF) z Cloud IAP (Identity-Aware Proxy).

Głębokie wyjaśnienie techniczne (GCP Professional Cloud Security Engineer):
W każdym pytaniu analizuj warstwy: IAM (dostęp), Encryption (at rest/in transit), Logging/Monitoring (Audit Logs, Cloud Logging, Security Command Center) oraz Networking (VPC Service Controls, Firewall Rules). GCP kładzie duży nacisk na współdzieloną odpowiedzialność (Shared Responsibility Model) - klient odpowiada za konfigurację zabezpieczeń wewnątrz usług chmurowych.
