Question 336 / 361

Your organization is storing regulated data in Cloud Storage. Data in Cloud Storage buckets is encrypted by Google-managed encryption keys. To meet compliance requirements, you need to update the existing data to use customer-managed encryption keys instead. What should you do?

  • A. Create a new key ring and key in the Cloud Key Management Service. In each Cloud Storage bucket configuration, change the encryption type to customer-managed encryption key.
  • B. Identify which projects contain Cloud Storage buckets with regulated data. Apply the restrictNonCmekServices organization policy constraint to the identified projects or parent folder.
Show Suggested Answer Hide Answer
Suggested Answer: B

Wskazówki egzaminacyjne (Tips & Tricks)

Reguła Egzaminacyjna (Exam Rule): 
W pytaniach typu 'Security in GCP', zawsze priorytetyzuj rozwiązania natywne (SCC, Cloud KMS, Secret Manager, VPC SC) nad rozwiązaniami typu 'third-party' lub 'self-managed', chyba że scenariusz wymaga specyficznej integracji hybrydowej.

Haczyki egzaminacyjne (Exam Traps):
- Pułapka 'Least Privilege': Egzamin często podpowiada role o szerokim zakresie (np. 'Editor' lub 'Owner') – zawsze odrzucaj je na rzecz ról predefiniowanych o najmniejszym zakresie uprawnień.
- Pułapka 'Logging vs Monitoring': Pamiętaj: Audit Logs służą do badania aktywności (Who/What/When), a Monitoring do zbierania metryk wydajnościowych.

Głębokie wyjaśnienie techniczne:
Każda architektura bezpieczeństwa w GCP powinna być projektowana w oparciu o 'Security by Default'. Oznacza to m.in. szyfrowanie w spoczynku (domyślne), tożsamość opartą na rolach (IAM) oraz pełną widoczność zapewnianą przez scentralizowane logowanie (Cloud Logging/SCC).

Wyjaśnienie

Poprawna odpowiedź: B (Identify which projects contain Cloud Storage buckets with regulated data. Apply the restrictNonCmekServices organization policy constraint to the identified projects or parent folder.)

Dlaczego ta odpowiedź jest poprawna:
- Pytanie dotyczy zgodności (compliance) i *wymuszenia* użycia CMEK dla *istniejących* lub nowych danych.
- Organization Policy constraint `restrictNonCmekServices` jest mechanizmem, który *wymusza* użycie CMEK w usługach (w tym Cloud Storage).
- Wersja A mówi o zmianie "konfiguracji bucketu" (zmiana typu szyfrowania w bucketach nie powoduje automatycznego przesyfrowania *istniejących* danych). Aby wymusić zgodność w skali organizacji/projektu, stosuje się politykę (Constraint), która odrzuca operacje zapisu, jeśli dane nie są szyfrowane przez CMEK.

Analiza niepoprawnych odpowiedzi:
- A. Zmiana konfiguracji w bucketach: Nie rozwiązuje problemu w sposób zautomatyzowany i wymuszony (enforcement). To podejście manualne i podatne na błędy.

Wskazówki i triki (Tips & Tricks):
- "Meet compliance requirements" + "Update existing data to use CMEK" + "Enforcement" = Organization Policy constraint (`restrictNonCmekServices`).

Praktyczne informacje na egzamin:
- Zapamiętaj: W GCP, gdy widzisz pytanie o wymuszanie określonego standardu bezpieczeństwa na poziomie projektów/folderów, odpowiedzią niemal zawsze jest "Organization Policy".
