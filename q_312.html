Question 312 / 361

A team at your organization collects logs in an on-premises security information and event management system (SIEM). You must provide a subset of Google Cloud logs for the SIEM, and minimize the risk of data exposure in your cloud environment. What should you do?

  • A. Create a new BigQuery dataset. Stream all logs to this dataset. Provide the on-premises SIEM system access to the data in BigQuery by using workload identity federation and let the SIEM team filter for the relevant log data.
  • B. Define a log view for the relevant logs. Provide access to the log view to a principal from your on-premises identity provider by using workforce identity federation.
  • C. Create a log sink for the relevant logs. Send the logs to Pub/Sub. Retrieve the logs from Pub/Sub and push the logs to the SIEM by using Dataflow.
  • D. Filter for the relevant logs. Store the logs in a Cloud Storage bucket. Grant the service account access to the bucket. Provide the service account key to the SIEM team.
Show Suggested Answer Hide Answer
Suggested Answer: C

Wyjaśnienie

✅ PRAWIDŁOWA ODPOWIEDŹ: C

Prawidłowa odpowiedź: C – Create a log sink for the relevant logs. Send the logs to Pub/Sub. Retrieve the logs from Pub/Sub in the on-premises SIEM.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
DLACZEGO C JEST PRAWIDŁOWE?
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
On-premises SIEM potrzebuje real-time logu z GCP. Log sink → Pub/Sub to standardowy wzorzec integracji GCP z zewnętrznymi systemami:
- Log sink filtruje tylko wybrane logi (subset).
- Pub/Sub dostarcza je w czasie rzeczywistym.
- SIEM może subskrybować Pub/Sub i przetwarzać logi na bieżąco.
- Pub/Sub obsługuje push/pull – SIEM może używać pull bez potrzeby otwierania ruchu inbound.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
DLACZEGO INNE OPCJE SĄ BŁĘDNE?
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
A. ❌ BigQuery = analityka batch, nie real-time streaming dla SIEM. Dostarczenie do on-premises wymaga dodatkowo kopii danych.
B. ❌ Log view + principal access = kontrola dostępu do logów w GCP, ale SIEM on-premises nadal musi aktywnie pobierać dane z Logging API. Brak natywnego streamingu.
D. ❌ Cloud Storage = pliki batch. Nie nadaje się do real-time integracji z SIEM.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
WSKAZÓWKI EGZAMINACYJNE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
• On-premises SIEM + GCP logs = Log Sink → Pub/Sub (standard pattern).
• Pub/Sub = real-time, skalowalne, zarządzane.
• BigQuery = analityka, nie real-time SIEM integration.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
REGUŁY
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
• Real-time log export do zewnętrznych systemów = Log Sink + Pub/Sub.
• Batch export = Log Sink + Cloud Storage lub BigQuery.
