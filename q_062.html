Question 62 / 361

A manager wants to start retaining security event logs for 2 years while minimizing costs. You write a filter to select the appropriate log entries. Where should you export the logs?

  • A. BigQuery datasets
  • B. Cloud Storage buckets
  • C. StackDriver logging
  • D. Cloud Pub/Sub topics
Show Suggested Answer Hide Answer
Suggested Answer: B

Wyjaśnienie

Potwierdzona odpowiedź: B (Cloud Storage buckets)

Wyjaśnienie:
Gdy głównym celem jest długoterminowe przechowywanie logów (retencja) przy jednoczesnej minimalizacji kosztów ("minimizing costs"), Cloud Storage jest bezkonkurencyjnym rozwiązaniem.
1. Niskie koszty: Przechowywanie danych w Cloud Storage (szczególnie w klasach Nearline, Coldline lub Archive) jest znacznie tańsze niż w BigQuery czy domyślnym systemie Cloud Logging (Stackdriver).
2. Długi czas retencji: Cloud Logging domyślnie przechowuje logi tylko przez 30-400 dni (zależnie od typu logów). Przechowywanie ich przez 2 lata wymaga eksportu (sink) do zewnętrznego systemu.
3. Object Lifecycle Management: Cloud Storage pozwala na automatyczne przenoszenie logów do tańszych klas (Archive) lub ich usuwanie po upływie dokładnie 2 lat, co dodatkowo optymalizuje koszty.

Dlaczego pozostałe są błędne:
A. BigQuery: Jest świetne do zaawansowanej analizy logów w czasie rzeczywistym przy użyciu SQL, ale jest droższe niż Cloud Storage przy czystym składowaniu danych ("at rest") przez tak długi czas.
C. StackDriver logging: Posiada sztywne limity retencji (zazwyczaj 30 dni dla logów administracyjnych, chyba że używasz log buckets z niestandardową retencją, ale Cloud Storage wciąż jest tańszą opcją "eksportową").
D. Cloud Pub/Sub: To usługa przesyłania wiadomości w czasie rzeczywistym. Nie służy do przechowywania (retencji) danych, a jedynie do ich przekazywania do innych systemów (np. SIEM on-premises).

Tips & Tricks:
- "Long-term retention" + "Minimum cost" = Cloud Storage.
- "Real-time analysis" + "SQL" = BigQuery.
- "Streaming to SIEM" = Pub/Sub.
- Pamiętaj o klasach Archive w Cloud Storage – są idealne na logi "na wszelki wypadek", których nikt nie planuje czytać regularnie.

Praktyczne wnioski: Eksport logów do Cloud Storage tworzy pliki w formacie JSON, które można później łatwo zaimportować do BigQuery, jeśli zajdzie potrzeba nagłej analizy incydentu sprzed roku.
