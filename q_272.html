Question 272 / 361

You work for a global company. Due to compliance requirements, certain Compute Engine instances that reside within specific projects must be located exclusively in cloud regions within the European Union (EU). You need to ensure that existing non-compliant workloads are remediated and prevent future Compute Engine instances from being launched in restricted regions. What should you do?

  • A. Use a third-party configuration management tool to monitor the location of Compute Engine instances. Automatically delete or migrate non-compliant instances, including existing deployments.
  • B. Deploy a Security Command Center source to detect Compute Engine instances created outside the EU. Use a custom remediation function to automatically relocate the instances, run the function once a day.
  • C. Use organization policy constraints in Resource Manager to enforce allowed regions for Compute Engine instance creation within specific projects.
  • D. Set an organization policy that denies the creation of Compute Engine instances outside the EU. Apply the policy to the appropriate projects. Identify existing non-compliant instances and migrate the instances to compliant EU regions.
Show Suggested Answer
Suggested Answer: D

Wyjaśnienie

1. Prawidłowa odpowiedź lub odpowiedzi:
D. Set an organization policy that denies the creation of Compute Engine instances outside the EU. Apply the policy to the appropriate projects. Identify existing non-compliant instances and migrate the instances to compliant EU regions.

2. Kompleksowe wyjaśnienie dlaczego dana odpowiedź jest prawidłowa (Analiza):
Odpowiedź D jest prawidłowa, ponieważ łączy prewencyjne egzekwowanie zasad za pomocą polityk organizacji (Resource Location Restriction) z niezbędnymi krokami operacyjnymi w celu doprowadzenia istniejącej infrastruktury do stanu zgodności (compliance).

Kluczowe kroki:
a. **Polityka prewencyjna (Org Policy):** Ustawienie ograniczenia `constraints/gcp.resourceLocations` typu `deny` dla wszystkich regionów poza UE (lub typu `allow` wyłącznie dla lokalizacji w Europie) gwarantuje, że od momentu jej wdrożenia żadne nowe maszyny Compute Engine nie powstaną w USA czy Azji.
b. **Audyt i migracja (Remediation):** Polityki organizacji działają prewencyjnie – nie modyfikują i nie usuwają automatycznie zasobów, które powstały przed wdrożeniem polityki. Aby zapewnić 100% zgodności, należy zidentyfikować istniejące maszyny w niedozwolonych regionach i ręcznie lub skryptowo zmigrować ich dyski i konfigurację do Europy.

3. Wyjaśnienie z osobna każdej niepoprawnej odpowiedzi:
A. Use a third-party configuration management tool to monitor... Automatically delete or migrate...
   * Dlaczego nieprawidłowa: Automatyczne usuwanie działających maszyn wirtualnych bez weryfikacji może doprowadzić do krytycznej awarii systemów produkcyjnych i utraty danych. Bezpieczniejszym i standardowym podejściem jest prewencyjna blokada w chmurze (Org Policy) i planowana migracja.
B. Deploy a Security Command Center source to detect... Use a custom remediation function... run once a day.
   * Dlaczego nieprawidłowa: Jest to podejście reaktywne. Maszyny byłyby tworzone, działałyby przez caly dzień, a funkcja usuwała/przenosiła by je raz na dobę. Narusza to ciągłość zgodności. Najlepszą praktyką jest blokada w momencie próby zapisu API chmury (prewencja u źródła).
C. Use organization policy constraints in Resource Manager to enforce allowed regions... within specific projects.
   * Dlaczego nieprawidłowa: Ta opcja konfiguruje blokadę dla nowych maszyn, ale całkowicie ignoruje problem już istniejących wdrożeń (existing deployments), które pozostałyby w niedozwolonych lokalizacjach, nie spełniając wymogów audytu.

4. Wskazówki, hinty, tips and tricks:
* Aby trwale zablokować tworzenie zasobów poza określonym obszarem geograficznym -> Używaj polityki organizacji **`constraints/gcp.resourceLocations`**.
* Pamiętaj, że polityki organizacji nie działają wstecz (they are not retroactive) – istniejące zasoby muszą być zmigrowane ręcznie.

5. Reguły wyboru odpowiedzi (Słowa kluczowe):
* Enforce allowed regions + existing deployments compliant -> Set organization policy (deny outside/allow inside) + migrate existing instances.
