Question 165 / 361

You are a security administrator at your company and are responsible for managing access controls (identification, authentication, and authorization) on Google Cloud. Which Google-recommended best practices should you follow when configuring authentication and authorization? (Choose two.)

  • A. Use Google default encryption.
  • B. Manually add users to Google Cloud.
  • C. Provision users with basic roles using Google's Identity and Access Management (IAM) service.
  • D. Use SSO/SAML integration with Cloud Identity for user authentication and user lifecycle management.
  • E. Provide granular access with predefined roles.
Show Suggested Answer Hide Answer
Suggested Answer: DE

Wyjaśnienie

1. Prawidłowa odpowiedź lub odpowiedzi:
D. Use SSO/SAML integration with Cloud Identity for user authentication and user lifecycle management.
E. Provide granular access with predefined roles.

2. Kompleksowe wyjaśnienie dlaczego dana odpowiedź jest prawidłowa (Analiza):
Pytanie dotyczy najlepszych praktyk Google Cloud w zakresie zarządzania tożsamością i dostępem (IAM):
- D (Uwierzytelnianie i Cykl życia): Integracja SSO/SAML z Cloud Identity pozwala na połączenie GCP z istniejącym korporacyjnym dostawcą tożsamości (IdP, np. Active Directory, Okta). Zapewnia to automatyzację procesu uwierzytelniania oraz cyklu życia kont (gdy pracownik odchodzi z firmy i jego konto jest usuwane w lokalnym AD, automatycznie traci on dostęp do GCP).
- E (Zasada najmniejszych uprawnień): Stosowanie ról predefiniowanych (Predefined Roles, np. `roles/storage.objectViewer`) zamiast ról podstawowych/prymitywnych (Owner, Editor, Viewer) pozwala na precyzyjne ograniczenie uprawnień użytkownika wyłącznie do tych, które są mu niezbędne do pracy, co minimalizuje ryzyko nadmiarowych uprawnień.

3. Wyjaśnienie z osobna każdej niepoprawnej odpowiedzi:
- A. Użycie domyślnego szyfrowania Google: Szyfrowanie danych w spoczynku jest mechanizmem ochrony danych (kryptografia), a nie mechanizmem uwierzytelniania czy autoryzacji użytkowników w IAM.
- B. Ręczne dodawanie użytkowników: Jest to rozwiązanie nieefektywne, podatne na błędy ludzkie i uniemożliwiające automatyczne odbieranie uprawnień (deprovisioning) po odejściu pracownika z firmy.
- C. Przypisywanie ról podstawowych (Basic Roles / Primitive Roles): Role podstawowe (Owner, Editor, Viewer) dają zbyt szerokie uprawnienia w obrębie całego projektu. Ich stosowanie w środowiskach produkcyjnych jest rażącym naruszeniem zasady najmniejszych uprawnień.

4. Wskazówki, hinty, tips and tricks:
- Dobre praktyki IAM w GCP:
  1. Zapomnij o rolach podstawowych (Basic Roles) – zawsze wybieraj role predefiniowane (Predefined) lub niestandardowe (Custom).
  2. Zawsze federuj tożsamości przy użyciu SSO i Cloud Identity dla kont enterprise, zamiast zarządzać nimi ręcznie.

5. Reguły wyboru odpowiedzi (Słowa kluczowe):
- Najlepsze praktyki uwierzytelniania w skali enterprise -> Integracja SSO/SAML + Cloud Identity.
- Najlepsze praktyki autoryzacji -> Predefined roles / granular access.

6. Dodatkowe źródła i dokumentacja:
- IAM best practices: https://cloud.google.com/iam/docs/using-predefined-roles
