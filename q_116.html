Question 116 / 361

You are exporting application logs to Cloud Storage. You encounter an error message that the log sinks don't support uniform bucket-level access policies. How should you resolve this error?

  • A. Change the access control model for the bucket
  • B. Update your sink with the correct bucket destination.
  • C. Add the roles/logging.logWriter Identity and Access Management (IAM) role to the bucket for the log sink identity.
  • D. Add the roles/logging.bucketWriter Identity and Access Management (IAM) role to the bucket for the log sink identity.
Show Suggested Answer Hide Answer
Suggested Answer: A

Wyjaśnienie

Potwierdzona odpowiedź: A (Change the access control model for the bucket)

Wyjaśnienie:
- Problem: Komunikat o błędzie wskazuje, że mechanizm eksportu logów (log sinks) w tym konkretnym scenariuszu nie obsługuje polityki "Uniform bucket-level access" (UBLA). UBLA wymusza zarządzanie dostępem wyłącznie przez IAM, wyłączając listy kontroli dostępu (ACL).
- Rozwiązanie: Aby umożliwić sinkowi zapis logów do kubełka w sytuacji, gdy wymaga on uprawnień opartych na ACL, należy zmienić model kontroli dostępu na "Fine-grained" (Drobnoziarnisty). Pozwala to na jednoczesne używanie IAM oraz ACL.
- Uwaga techniczna: Chociaż Google zaleca stosowanie UBLA dla większości kubełków, niektóre starsze mechanizmy lub specyficzne konfiguracje sinków mogą nadal polegać na uprawnieniach ACL do zapisu obiektów przez tożsamość sinka.

Dlaczego pozostałe są błędne:
- B: Aktualizacja celu sinka nie rozwiąże problemu, jeśli przyczyną jest niekompatybilność modelu uprawnień na samym kubełku docelowym.
- C i D: Nadanie ról IAM (`logging.logWriter` lub `logging.bucketWriter`) jest standardowym wymogiem dla sinka, ale błąd w pytaniu precyzuje, że problemem jest polityka "uniform bucket-level access", a nie brak samych uprawnień IAM. Jeśli kubełek wymusza UBLA, a mechanizm zapisu próbuje użyć ACL, same role IAM nie wystarczą bez zmiany modelu dostępu kubełka.

Wskazówki egzaminacyjne (Tips & Tricks):
- Jeśli usługa "nie wspiera uniform bucket-level access", jedynym wyjściem jest powrót do modelu "Fine-grained" (ACL).
- Zapamiętaj różnicę: Uniform = Tylko IAM; Fine-grained = IAM + ACL.

Kluczowe zagadnienia do powtórzenia:
- Modele kontroli dostępu w Cloud Storage (Uniform vs Fine-grained).
- Tożsamość i uprawnienia dla Cloud Logging Sinks.

Dokumentacja:
- Używanie Uniform bucket-level access
