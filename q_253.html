Question 253 / 361

Your organization is building a chatbot that is powered by generative AI to deliver automated conversations with internal employees. You must ensure that no data with personally identifiable information (PII) is communicated through the chatbot. What should you do?

  • A. Encrypt data at rest for both input and output by using Cloud KMS, and apply least privilege access to the encryption keys.
  • B. Discover and transform PII data in both input and output by using the Cloud Data Loss Prevention (Cloud DLP) API.
  • C. Prevent PII data exfiltration by using VPC-SC to create a safe scope around your chatbot.
  • D. Scan both input and output by using data encryption tools from the Google Cloud Marketplace.
Show Suggested Answer
Suggested Answer: B

Wyjaśnienie

1. Prawidłowa odpowiedź lub odpowiedzi:
B. Discover and transform PII data in both input and output by using the Cloud Data Loss Prevention (Cloud DLP) API.

2. Kompleksowe wyjaśnienie dlaczego dana odpowiedź jest prawidłowa (Analiza):
Odpowiedź B jest prawidłowa, ponieważ Cloud Data Loss Prevention (Cloud DLP) API jest dedykowaną usługą w GCP służącą do skanowania, wykrywania (discovery) i transformacji (np. maskowania, redagowania) danych wrażliwych w czasie rzeczywistym w strumieniach tekstowych.

Zastosowanie w chatbocie GenAI:
a. **Skanowanie wejścia (Input/Prompt):** Przed wysłaniem zapytania pracownika do modelu językowego (LLM), chatbot przesyła tekst do DLP API. Jeśli użytkownik wpisał w prompt PII (np. "Nazywam się Jan Kowalski, PESEL..."), DLP API może zredagować te dane (np. zamienić na `[NAME]`, `[ID]`), chroniąc dane przed wyciekiem do silnika AI.
b. **Skanowanie wyjścia (Output/Response):** Przed wyświetleniem odpowiedzi generowanej przez model użytkownikowi, chatbot ponownie skanuje tekst w DLP API w celu upewnienia się, że model nie wygenerował przypadkowo żadnych danych wrażliwych z bazy treningowej.

3. Wyjaśnienie z osobna każdej niepoprawnej odpowiedzi:
A. Encrypt data at rest... by using Cloud KMS...
   * Dlaczego nieprawidłowa: Szyfrowanie kluczem KMS chroni bazę danych w spoczynku, ale nie analizuje treści zapytań wpisywanych przez użytkowników. Gdy użytkownik korzysta z chata, dane są odszyfrowane i przetwarzane, co oznacza, że PII nadal trafia do modelu i na ekran.
C. Prevent PII data exfiltration by using VPC-SC to create a safe scope...
   * Dlaczego nieprawidłowa: VPC Service Controls zabezpiecza granice sieciowe usług (np. zapobiega kopiowaniu danych między projektami), ale nie filtruje tekstu wpisywanego w oknach czatu przez użytkowników w celu wykrywania i usuwania słów zawierających PII.
D. Scan both input and output by using data encryption tools from the Google Cloud Marketplace.
   * Dlaczego nieprawidłowa: Narzędzia szyfrujące (encryption tools) służą do kodowania danych w celu ochrony ich poufności, a nie do inteligentnej inspekcji tekstu, klasyfikacji danych wrażliwych i selektywnego ich usuwania/maskowania w locie, co jest domeną silnika NLP w Cloud DLP.

4. Wskazówki, hinty, tips and tricks:
* Jeśli celem jest zapobieganie wysyłaniu/przetwarzaniu PII w aplikacjach tekstowych (jak chatbots, formularze) -> Zawsze używaj **Cloud DLP API** w celu inspekcji i redagowania (inspect and redact) tekstu w locie.
* DLP API posiada predefiniowane detektory (infoTypes) dla setek typów danych wrażliwych z całego świata.

5. Reguły wyboru odpowiedzi (Słowa kluczowe):
* Chatbot + ensure no PII is communicated -> Cloud Data Loss Prevention (Cloud DLP) API.
