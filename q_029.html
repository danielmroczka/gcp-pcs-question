Question 29 / 361

Your team sets up a Shared VPC Network where project co-vpc-prod is the host project. Your team has configured the firewall rules, subnets, and VPN gateway on the host project. They need to enable Engineering Group A to attach a Compute Engine instance to only the 10.1.1.0/24 subnet.
What should your team grant to Engineering Group A to meet this requirement?

  • A. Compute Network User Role at the host project level.
  • B. Compute Network User Role at the subnet level.
  • C. Compute Shared VPC Admin Role at the host project level.
  • D. Compute Shared VPC Admin Role at the service project level.
Show Suggested Answer Hide Answer
Suggested Answer: B

Wyjaśnienie

Potwierdzona odpowiedź: B (Compute Network User Role at the subnet level.)

Wyjaśnienie: 
Shared VPC (Współdzielone VPC) to model, w którym jeden projekt (Host Project) udostępnia swoje zasoby sieciowe innym projektom (Service Projects). Aby użytkownik lub grupa mogła korzystać z konkretnej podsieci (subnet) w Host Project do przyłączania maszyn wirtualnych, musi posiadać rolę `Compute Network User` (roles/compute.networkUser). Najważniejszą zasadą bezpieczeństwa w GCP jest zasada najmniejszych uprawnień (Least Privilege). Aby ograniczyć dostęp inżynierów do "tylko jednej" podsieci, rolę tę należy nadać bezpośrednio na poziomie konkretnego zasobu (podsieci), a nie na poziomie całego projektu.

Dlaczego pozostałe są błędne:
A. Compute Network User at the host project level: Nadanie tej roli na poziomie projektu Host dałoby inżynierom uprawnienia do używania WSZYSTKICH podsieci znajdujących się w tym projekcie, co narusza wymóg ścisłego ograniczenia dostępu do jednej, konkretnej podsieci.
C, D. Compute Shared VPC Admin Role: Jest to rola o znacznie szerszych uprawnieniach administracyjnych. Pozwala ona na zarządzanie całym mechanizmem Shared VPC (kojarzenie projektów usługowych, tworzenie/usuwanie podsieci, zarządzanie trasami). Nadanie tej roli inżynierom chcącym jedynie tworzyć maszyny VM byłoby rażącym naruszeniem zasad bezpieczeństwa.

Wskazówki egzaminacyjne (Tips & Tricks):
- "Only the... subnet": To słowo-klucz. Jeśli masz ograniczyć dostęp do konkretnego zasobu, uprawnienie IAM musi być nadane na poziomie tego zasobu ("Resource-level IAM").
- "Shared VPC" + "Use/Attach": Prawie zawsze szukaj roli `Compute Network User`.
- Zapamiętaj: W GCP uprawnienia są dziedziczone w dół. Nadanie roli na poziomie projektu = dostęp do wszystkich podsieci; nadanie na poziomie podsieci = dostęp tylko do tej jednej.

Kluczowe zagadnienia do powtórzenia:
- IAM w Shared VPC (Network User vs Shared VPC Admin)
- Resource Hierarchy i dziedziczenie uprawnień
- Zarządzanie podsieciami w Host Project

**Reguła Egzaminacyjna (Exam Rule):**
Zawsze identyfikuj warstwę modelu OSI, na której operuje atak oraz rozwiązanie. DNSSEC działa na poziomie warstwy aplikacji dla DNS, zapobiegając zatruwaniu pamięci podręcznej (Cache Poisoning).

**Haczyki egzaminacyjne (Exam Traps):**
- Mylenie Cloud Armor (WAF - L7) z zabezpieczeniami DNS (DNSSEC - integralność danych DNS).
- Zakładanie, że TLS/SSL wystarczy do ochrony przed przekierowaniem całego ruchu DNS (DNSSEC zabezpiecza sam proces rezolucji, zanim nawiążesz bezpieczne połączenie TLS).

**Głębokie wyjaśnienie techniczne:**
DNSSEC wykorzystuje kryptografię klucza publicznego (RRSIG, DNSKEY, DS) do cyfrowego podpisywania rekordów DNS w strefach (Zone Signing). Dzięki temu resolver DNS może zweryfikować łańcuch zaufania aż do punktu głównego (root zone) bez konieczności polegania wyłącznie na adresie IP serwera autorytatywnego, co drastycznie ogranicza skuteczność ataków typu MITM i cache poisoning.
