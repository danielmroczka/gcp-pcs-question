Question 112 / 361

Your company has been creating users manually in Cloud Identity to provide access to Google Cloud resources. Due to continued growth of the environment, you want to authorize the Google Cloud Directory Sync (GCDS) instance and integrate it with your on-premises LDAP server to onboard hundreds of users. You are required to:
* Replicate user and group lifecycle changes from the on-premises LDAP server in Cloud Identity.
* Disable any manually created users in Cloud Identity.
You have already configured the LDAP search attributes to include the users and security groups in scope for Google Cloud. What should you do next to complete this solution?

  • A. 1. Configure the option to suspend domain users not found in LDAP. 2. Set up a recurring GCDS task.
  • B. 1. Configure the option to delete domain users not found in LDAP. 2. Run GCDS after user and group lifecycle changes.
  • C. 1. Configure the LDAP search attributes to exclude manually created Cloud Identity users not found in LDAP. 2. Set up a recurring GCDS task.
  • D. 1. Configure the LDAP search attributes to exclude manually created Cloud Identity users not found in LDAP. 2. Run GCDS after user and group lifecycle changes.
Show Suggested Answer Hide Answer
Suggested Answer: A

Wyjaśnienie

Potwierdzona odpowiedź: A (1. Configure the option to suspend domain users not found in LDAP. 2. Set up a recurring GCDS task.)

Wyjaśnienie:
- Suspend users (Zawieszenie użytkowników): Wybranie opcji zawieszenia użytkowników, których nie znaleziono w LDAP, gwarantuje, że każde konto w Cloud Identity, które zostało utworzone ręcznie lub przestało istnieć w źródłowym systemie LDAP, zostanie zablokowane. Jest to bezpieczniejsze niż usuwanie (Delete), ponieważ pozwala na zachowanie danych i ich ewentualne odzyskanie.
- Recurring task (Zadanie cykliczne): Aby GCDS skutecznie zarządzał cyklem życia kont (onboarding/offboarding), synchronizacja musi odbywać się automatycznie i regularnie. GCDS nie jest procesem działającym w tle (daemon), więc wymaga harmonogramu (np. cron lub Task Scheduler).

Dlaczego pozostałe są błędne:
- B: Usuwanie (Delete) kont, których nie ma w LDAP, jest ryzykowne, zwłaszcza na początku wdrażania GCDS, ponieważ może prowadzić do nieodwracalnej utraty danych użytkowników utworzonych wcześniej ręcznie. Dodatkowo, uruchamianie GCDS tylko po zmianach nie gwarantuje spójności przy braku automatyzacji.
- C i D: Skonfigurowanie atrybutów wyszukiwania w celu wykluczenia (Exclude) ręcznie utworzonych użytkowników spowodowałoby, że GCDS po prostu by ich ignorował. Oznacza to, że te konta pozostałyby aktywne i poza kontrolą, co bezpośrednio narusza wymóg "Disable any manually created users".

Wskazówki egzaminacyjne (Tips & Tricks):
- GCDS to synchronizacja jednostronna (LDAP -> Google).
- "Suspend" jest najlepszą praktyką (bezpieczeństwo danych + blokada dostępu).
- "Recurring task" to klucz do automatyzacji cyklu życia tożsamości.

Kluczowe zagadnienia do powtórzenia:
- Mechanizm synchronizacji Google Cloud Directory Sync (GCDS).
- Lifecycle management (zarządzanie cyklem życia użytkownika).
- Reguły wykluczania i zawieszania w GCDS.
