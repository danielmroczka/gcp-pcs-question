Question 112 / 361

Your company has been creating users manually in Cloud Identity to provide access to Google Cloud resources. Due to continued growth of the environment, you want to authorize the Google Cloud Directory Sync (GCDS) instance and integrate it with your on-premises LDAP server to onboard hundreds of users. You are required to:
* Replicate user and group lifecycle changes from the on-premises LDAP server in Cloud Identity.
* Disable any manually created users in Cloud Identity.
You have already configured the LDAP search attributes to include the users and security groups in scope for Google Cloud. What should you do next to complete this solution?

  • A. 1. Configure the option to suspend domain users not found in LDAP. 2. Set up a recurring GCDS task.
  • B. 1. Configure the option to delete domain users not found in LDAP. 2. Run GCDS after user and group lifecycle changes.
  • C. 1. Configure the LDAP search attributes to exclude manually created Cloud Identity users not found in LDAP. 2. Set up a recurring GCDS task.
  • D. 1. Configure the LDAP search attributes to exclude manually created Cloud Identity users not found in LDAP. 2. Run GCDS after user and group lifecycle changes.
Show Suggested Answer Hide Answer
Suggested Answer: A

Wyjaśnienie

1. Prawidłowa odpowiedź lub odpowiedzi:
A. 1. Configure the option to suspend domain users not found in LDAP. 2. Set up a recurring GCDS task.

2. Kompleksowe wyjaśnienie dlaczego dana odpowiedź jest prawidłowa (Analiza):
Wymagania zakładają zintegrowanie lokalnego LDAP z Cloud Identity przy użyciu GCDS, automatyczne replikowanie zmian oraz dezaktywowanie użytkowników, którzy zostali utworzeni ręcznie (czyli nie istnieją w LDAP):
- Wybranie opcji "suspend domain users not found in LDAP" (zawieszenie użytkowników) powoduje zablokowanie kont w Cloud Identity, które zostały utworzone ręcznie i nie posiadają swojego odpowiednika w lokalnym serwerze LDAP. Zawieszenie jest bezpieczniejsze niż trwałe usunięcie (delete), ponieważ chroni przed przypadkową utratą danych w przypadku błędów konfiguracyjnych synchronizacji.
- Konfiguracja cyklicznego zadania (recurring GCDS task) jest niezbędna, aby zmiany w strukturze pracowników i ich uprawnieniach były automatycznie i stale synchronizowane bez konieczności ręcznego uruchamiania narzędzia przez administratora.

3. Wyjaśnienie z osobna każdej niepoprawnej odpowiedzi:
- B. Opcja usuwania (delete) i ręczne uruchamianie: Trwałe usunięcie kont jest zbyt drastyczne (powoduje utratę danych użytkownika). Ręczne uruchamianie GCDS nie zapewnia ciągłości replikacji zmian w dynamicznym środowisku.
- C i D. Wykluczenie ręcznie utworzonych użytkowników z atrybutów wyszukiwania LDAP: Spowodowałoby to, że GCDS ignorowałby te konta i pozostawił je w pełni aktywne w Cloud Identity, co bezpośrednio łamie wymóg ich zablokowania ("Disable any manually created users").

4. Wskazówki, hinty, tips and tricks:
- GCDS zawsze synchronizuje tożsamości z lokalnego katalogu (LDAP/AD) do Google Cloud (jednokierunkowo).
- Na egzaminie opcja "Suspend" jest zawsze zalecana nad "Delete" jako bezpieczna metoda deprovisioningu.
- Automatyzacja synchronizacji cyklu życia tożsamości zawsze wymaga harmonogramu (recurring task).

5. Reguły wyboru odpowiedzi (Słowa kluczowe):
- AD/LDAP jako jedyne źródło prawdy + obsługa kont spoza katalogu -> Suspend users not found in LDAP.
- Automatyczne utrzymanie spójności tożsamości -> Recurring GCDS task.

6. Dodatkowe źródła i dokumentacja:
- GCDS user management settings: https://support.google.com/a/answer/6124299

Sugerowana odpowiedź: A

Głęboka analiza:

Analiza spornych kwestii (AI): Na forach administratorzy IT podkreślają: 'Nigdy nie wybieraj opcji Delete w GCDS na początku integracji'. Opcja A (Suspend) pozwala zachować zgodność z polityką bezpieczeństwa (nikt niepowołany nie wejdzie), dając jednocześnie czas na wyjaśnienie ewentualnych pomyłek bez niszczenia plików użytkownika na Google Drive.
