Question 49 / 361

You are in charge of migrating a legacy application from your company datacenters to GCP before the current maintenance contract expires. You do not know what ports the application is using and no documentation is available for you to check. You want to complete the migration without putting your environment at risk. What should you do?

  • A. Migrate the application into an isolated project using a "Lift & Shift" approach. Enable all internal TCP traffic using VPC Firewall rules. Use VPC Flow logs to determine what traffic should be allowed for the application to work properly.
  • B. Migrate the application into an isolated project using a "Lift & Shift" approach in a custom network. Disable all traffic within the VPC and look at the Firewall logs to determine what traffic should be allowed for the application to work properly.
  • C. Refactor the application into a micro-services architecture in a GKE cluster. Disable all traffic from outside the cluster using Firewall Rules. Use VPC Flow logs to determine what traffic should be allowed for the application to work properly.
  • D. Refactor the application into a micro-services architecture hosted in Cloud Functions in an isolated project. Disable all traffic from outside your project using Firewall Rules. Use VPC Flow logs to determine what traffic should be allowed for the application to work properly.
Show Suggested Answer Hide Answer
Suggested Answer: A

Wyjaśnienie

Potwierdzona odpowiedź: A (Isolated project + Lift & Shift + VPC Flow Logs)

Wyjaśnienie:
Mamy tutaj scenariusz z silną presją czasu (wygasający kontrakt) oraz brakiem wiedzy o aplikacji (brak dokumentacji portów).
1. Izolowany projekt: Przeniesienie aplikacji do osobnego, dedykowanego projektu GCP minimalizuje ryzyko dla reszty środowiska firmowego (blast radius), nawet jeśli reguły firewall w tym konkretnym projekcie będą tymczasowo zbyt luźne.
2. Lift & Shift: To najszybsza metoda migracji ("as-is"), polegająca na przeniesieniu maszyn wirtualnych bez zmiany ich architektury. Jest to jedyna realna opcja przy goniących terminach.
3. VPC Flow Logs: Włączając logi przepływów VPC, możemy monitorować, na jakich portach aplikacja faktycznie próbuje się komunikować. Pozwala to na późniejsze "zacieśnienie" reguł firewall do tylko niezbędnego minimum, bazując na empirycznych danych z działającej aplikacji.

Dlaczego pozostałe są błędne:
B. Disable all traffic: Jeśli wyłączymy cały ruch, aplikacja nie będzie działać, a my nie dowiemy się, jakie porty są jej potrzebne do poprawnej pracy. Firewall logs pokazałyby tylko próby połączeń (denied), ale aplikacja mogłaby zachowywać się nieprzewidywalnie.
C i D. Refactoring: Refaktoryzacja do mikrousług (GKE) lub Cloud Functions to proces długotrwały i skomplikowany. Przy braku dokumentacji i goniącym terminie wygaśnięcia kontraktu, jest to przepis na porażkę projektu migracyjnego.

Wskazówki egzaminacyjne (Tips & Tricks):
- "Contract expires soon" = szukaj "Lift & Shift" lub "Rehost". Odrzuć "Refactor" lub "Rewrite".
- "Unknown ports" = szukaj "VPC Flow Logs" do analizy ruchu.
- Izolacja projektu to standardowa metoda ograniczania ryzyka przy migracjach "legacy".

Kluczowe zagadnienia do powtórzenia:
- Strategie migracji (Lift & Shift, Improve & Move, Rip & Replace).
- VPC Flow Logs - co rejestrują i jak je analizować.
- Zasady projektowania izolowanych środowisk w GCP.

Analiza i Wyjaśnienie

Sugerowana odpowiedź: A

Analiza spornych kwestii (AI): Kluczowym elementem jest balans między bezpieczeństwem a dostępnością aplikacji. Opcja B jest zbyt restrykcyjna ("app doesn't work"), a opcje C i D są nierealne czasowo. Opcja A pozwala na szybkie uruchomienie biznesu w bezpiecznym, odizolowanym "piaskownicy", a następnie precyzyjne dostrojenie zabezpieczeń dzięki logom.

Wyjaśnienie Audytowe

Reguła Egzaminacyjna (Exam Rule):
Pamiętaj, że w egzaminie Professional Cloud Security Engineer kluczowe jest wybieranie rozwiązań najmniej uprzywilejowanych (Principle of Least Privilege), zoptymalizowanych kosztowo i spełniających wymogi compliancy (np. CMEK, Data Loss Prevention).

Haczyki egzaminacyjne (Exam Traps):
- Wybór rozwiązań, które wydają się wygodne, ale nie spełniają wymogów bezpieczeństwa (np. zbyt szerokie uprawnienia IAM).
- Mylenie usług: np. Cloud Armor (WAF) z Cloud IAP (Identity-Aware Proxy).

Głębokie wyjaśnienie techniczne (GCP Professional Cloud Security Engineer):
W każdym pytaniu analizuj warstwy: IAM (dostęp), Encryption (at rest/in transit), Logging/Monitoring (Audit Logs, Cloud Logging, Security Command Center) oraz Networking (VPC Service Controls, Firewall Rules). GCP kładzie duży nacisk na współdzieloną odpowiedzialność (Shared Responsibility Model) - klient odpowiada za konfigurację zabezpieczeń wewnątrz usług chmurowych.
