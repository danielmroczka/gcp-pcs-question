Your Google Cloud organization is subdivided into three folders: production, development, and networking. Networking resources for the organization are centrally managed in the networking folder. You discovered that projects in the production folder are attaching to Shared VPCs that are outside of the networking folder which could become a data exfiltration risk. You must resolve the production folder issue without impacting the development folder. You need to use the most efficient and least disruptive approach. What should you do?

  • A. Enable the Restrict Shared VPC Host Projects organization policy on the production folder. Create a custom rule and configure the policy type to Allow. In the Custom value section, enter under:folders/networking.
  • B. Enable the Restrict Shared VPC Host Projects organization policy on the networking folder only. Create a new custom rule and configure the policy type to Allow. In the Custom value section, enter under:organizations/123456739123.
  • C. Enable the Restrict Shared VPC Host Projects organization policy at the project level for each of the production projects. Create a custom rule and configure the policy type to Allow. In the Custom value section, enter under:folders/networking.
  • D. Enable the Restrict Shared VPC Host Projects organization policy at the organization level. Create a custom rule and configure the policy type to Allow. In the Custom value section, enter under:folders/networking.
Show Suggested Answer Hide Answer
Suggested Answer: A

Wskazówki egzaminacyjne (Tips & Tricks)

Reguła Egzaminacyjna (Exam Rule): 
W pytaniach typu 'Security in GCP', zawsze priorytetyzuj rozwiązania natywne (SCC, Cloud KMS, Secret Manager, VPC SC) nad rozwiązaniami typu 'third-party' lub 'self-managed', chyba że scenariusz wymaga specyficznej integracji hybrydowej.

Haczyki egzaminacyjne (Exam Traps):
- Pułapka 'Least Privilege': Egzamin często podpowiada role o szerokim zakresie (np. 'Editor' lub 'Owner') – zawsze odrzucaj je na rzecz ról predefiniowanych o najmniejszym zakresie uprawnień.
- Pułapka 'Logging vs Monitoring': Pamiętaj: Audit Logs służą do badania aktywności (Who/What/When), a Monitoring do zbierania metryk wydajnościowych.

Głębokie wyjaśnienie techniczne:
Każda architektura bezpieczeństwa w GCP powinna być projektowana w oparciu o 'Security by Default'. Oznacza to m.in. szyfrowanie w spoczynku (domyślne), tożsamość opartą na rolach (IAM) oraz pełną widoczność zapewnianą przez scentralizowane logowanie (Cloud Logging/SCC).

Wyjaśnienie

Potwierdzona odpowiedź: A (Enable the Restrict Shared VPC Host Projects organization policy on the production folder. Create a custom rule and configure the policy type to Allow. In the Custom value section, enter under:folders/networking.)

Wyjaśnienie:
Constraint polityki organizacji compute.restrictSharedVpcHostProjects pozwala na ograniczenie projektów, które mogą być używane jako hosty Shared VPC. Stosując to ograniczenie na poziomie folderu production i definiując regułę "Allow" dla zasobów znajdujących się "pod" (under) folderem networking, zapewniamy, że projekty wewnątrz folderu production będą mogły łączyć się tylko z sieciami Shared VPC zarządzanymi centralnie w folderze networking. Jest to podejście najbardziej efektywne (zarządzanie na poziomie folderu zamiast poszczególnych projektów) i najmniej zakłócające (nie wpływa na folder development).

Dlaczego pozostałe odpowiedzi są niepoprawne:
- B. Włączenie tej polityki tylko na folderze networking nie rozwiąże problemu projektów w folderze production, które już używają innych (nieautoryzowanych) hostów Shared VPC. Polityka musi być nałożona tam, gdzie chcemy ograniczyć zachowanie (czyli w folderze produkcyjnym).
- C. Choć nałożenie polityki na poziomie każdego projektu z osobna by zadziałało, nie jest to podejście najbardziej efektywne. Zarządzanie na poziomie folderu jest preferowane w dużych organizacjach, ponieważ automatycznie obejmuje nowe projekty tworzone w tym folderze.
- D. Nałożenie polityki na poziomie całej organizacji wpłynęłoby również na folder development, co jest sprzeczne z wymaganiem "without impacting the development folder".

Wskazówki i triki (Tips & Tricks):
- "Restrict Shared VPC Host Projects" to kluczowe narzędzie do zapobiega exfiltracji danych przez nieautoryzowane sieci.
- Pamiętaj o hierarchii zasobów: ustawienie polityki na folderze jest bardziej skalowalne niż na projekcie, ale mniej inwazyjne niż na całej organizacji.
- Wartość under:folders/ID w polityce pozwala na rekurencyjne zezwolenie na wszystkie projekty w danym folderze.

Praktyczne informacje na egzamin:
- Zapamiętaj nazwę constraintu: compute.restrictSharedVpcHostProjects.
- Shared VPC pozwala na oddzielenie administracji siecią (host project) od administracji zasobami (service projects).
- Zawsze wybieraj najwyższy możliwy poziom w hierarchii, który spełnia wymagania bez nadmiarowego ograniczania innych działów.

Dokumentacja i linki:
