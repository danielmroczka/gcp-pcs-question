Question 68 / 361

A customer terminates an engineer and needs to make sure the engineer's Google account is automatically deprovisioned. What should the customer do?

  • A. Remove IAM permissions in Cloud Identity.
  • B. Use Cloud SDK to deprovision users.
  • C. Configure Cloud Directory Sync (GCDS) with their directory service.
  • D. Manually delete the user in Admin Console.
Show Suggested Answer Hide Answer
Suggested Answer: C 
Poprawna odpowiedź: C

Analiza poprawności:
Zarządzanie cyklem życia tożsamości (Identity Lifecycle Management) w GCP powinno opierać się na źródle prawdy (LDAP/Active Directory).
1. GCDS (Google Cloud Directory Sync): Jest to narzędzie, które automatyzuje proces synchronizacji użytkowników i grup z on-premises Directory Service do Google Cloud Identity.
2. Automatyzacja: Po skonfigurowaniu GCDS, każda zmiana w LDAP (np. usunięcie pracownika) jest automatycznie (według harmonogramu) replikowana do Cloud Identity, co powoduje zablokowanie konta (deprovisioning).

Dlaczego pozostałe są błędne:
A/B. Cloud SDK: Służy do automatyzacji zadań operacyjnych (np. tworzenie instancji, zarządzanie zasobami), a nie do automatycznego, ciągłego zarządzania cyklem życia użytkowników w ramach całego katalogu.
D. Usuwanie IAM: GCDS nie zarządza bezpośrednio rolami IAM; zarządza tożsamościami użytkowników (kontami w Cloud Identity). Uprawnienia IAM są przyznawane tym tożsamościom, więc ich deprovisioning naturalnie usuwa dostęp.

Wskazówki egzaminacyjne:
- "Automatic deprovisioning" / "Source of truth" = Zawsze szukaj GCDS (Google Cloud Directory Sync).
- Pamiętaj, że GCDS jest narzędziem jednokierunkowym (LDAP -> Google).
- GCDS nie zarządza bezpośrednio IAM; zarządza tożsamością, która IAM konsumuje.
