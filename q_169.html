Question 169 / 361

You need to create a VPC that enables your security team to control network resources such as firewall rules. How should you configure the network to allow for separation of duties for network resources?

  • A. Set up multiple VPC networks, and set up multi-NIC virtual appliances to connect the networks.
  • B. Set up VPC Network Peering, and allow developers to peer their network with a Shared VPC.
  • C. Set up a VPC in a project. Assign the Compute Network Admin role to the security team, and assign the Compute Admin role to the developers.
  • D. Set up a Shared VPC where the security team manages the firewall rules, and share the network with developers via service projects.
Show Suggested Answer Hide Answer
Suggested Answer: D

Wyjaśnienie

Poprawna odpowiedź: D (Set up a Shared VPC where the security team manages the firewall rules, and share the network with developers via service projects)

Dlaczego ta odpowiedź jest poprawna:
- Shared VPC (Współdzielone VPC): Jest to kluczowa architektura w Google Cloud dla organizacji typu Enterprise. Pozwala ona na oddzielenie zarządzania siecią od zarządzania aplikacjami.
- Host Project: Zespół bezpieczeństwa lub sieciowy zarządza jednym centralnym projektem (Host Project), w którym zdefiniowana jest sieć VPC, podsieci i reguły firewall.
- Service Projects: Deweloperzy posiadają własne projekty (Service Projects), które są "podpięte" do projektu hosta. Mogą oni tworzyć tam swoje zasoby (np. VM, GKE), korzystając z bezpiecznej sieci z projektu hosta, ale NIE mają uprawnień do modyfikowania samej sieci ani jej reguł firewall.
- Separation of Duties (Separacja obowiązków): Ten model idealnie realizuje wymóg pytania. Zespół security ma pełną kontrolę nad infrastrukturą sieciową, a deweloperzy mogą swobodnie wdrażać aplikacje w wyznaczonych granicach.

Analiza niepoprawnych odpowiedzi:
- A. Multiple VPCs + Multi-NIC appliances: Jest to rozwiązanie bardzo skomplikowane i trudne w utrzymaniu. Wymaga zarządzania wieloma sieciami i wirtualnymi urządzeniami, co zwiększa narzut operacyjny i koszty, zamiast wykorzystać natywne funkcje platformy.
- B. VPC Peering with Shared VPC: Peering służy do łączenia niezależnych sieci. Choć pozwala na komunikację, nie zapewnia natywnej separacji obowiązków w taki sposób jak Shared VPC. W modelu peeringu deweloperzy wciąż mieliby pełną kontrolę nad firewallem w swojej sieci.
- C. Compute Network Admin role in a single project: W jednym projekcie bardzo trudno jest zapewnić czystą separację. Użytkownik z rolą Compute Admin wciąż mógłby mieć zbyt szerokie uprawnienia, a zarządzanie setkami deweloperów w jednym projekcie sieciowym jest błędem architektury (brak izolacji zasobów).

Wskazówki i triki (Tips & Tricks):
- "Separation of duties" + "Network resources" = Shared VPC.
- Host Project = Network/Security Team.
- Service Project = Application/Dev Team.
- Pamiętaj: Tylko JEDEN projekt może być Hostem dla danej sieci VPC.

Praktyczne informacje na egzamin:
- Aby skonfigurować Shared VPC, musisz posiadać uprawnienie "Shared VPC Admin" na poziomie organizacji.
- Deweloperzy w projektach serwisowych potrzebują roli "Compute Network User" na konkretnych podsieciach w projekcie hosta, aby móc z nich korzystać.
