Question 169 / 361

You need to create a VPC that enables your security team to control network resources such as firewall rules. How should you configure the network to allow for separation of duties for network resources?

  • A. Set up multiple VPC networks, and set up multi-NIC virtual appliances to connect the networks.
  • B. Set up VPC Network Peering, and allow developers to peer their network with a Shared VPC.
  • C. Set up a VPC in a project. Assign the Compute Network Admin role to the security team, and assign the Compute Admin role to the developers.
  • D. Set up a Shared VPC where the security team manages the firewall rules, and share the network with developers via service projects.
Show Suggested Answer Hide Answer
Suggested Answer: D

Wyjaśnienie

1. Prawidłowa odpowiedź lub odpowiedzi:
D. Set up a Shared VPC where the security team manages the firewall rules, and share the network with developers via service projects.

2. Kompleksowe wyjaśnienie dlaczego dana odpowiedź jest prawidłowa (Analiza):
Wymagane jest zapewnienie separacji obowiązków (separation of duties): zespół bezpieczeństwa musi kontrolować zasoby sieciowe (np. reguły firewalla), natomiast deweloperzy powinni mieć możliwość wdrażania swoich maszyn wirtualnych bez dostępu do konfiguracji sieci:
- **Shared VPC** (Współdzielone VPC) to podstawowy mechanizm GCP realizujący ten postulat.
- Zespół bezpieczeństwa i sieci zarządza centralnym Projektem Hosta (Host Project), gdzie skonfigurowane są sieci VPC, podsieci, trasy oraz reguły zapory sieciowej.
- Deweloperzy otrzymują dostęp do projektów usługowych (Service Projects), które są podpięte pod projekt hosta. Deweloperzy mogą tworzyć maszyny VM w dozwolonych podsieciach hosta, ale nie mają żadnych uprawnień sieciowych w projekcie hosta, co uniemożliwia im modyfikowanie reguł zapory i zapewnia ścisłą separację obowiązków.

3. Wyjaśnienie z osobna każdej niepoprawnej odpowiedzi:
- A. Wiele sieci VPC połączonych urządzeniami multi-NIC: Rozwiązanie bardzo skomplikowane i kosztowne. Nie rozwiązuje problemu uprawnień IAM i delegacji zadań w sposób natywny dla platformy GCP.
- B. VPC Peering dla sieci deweloperów z Shared VPC: Dając deweloperom własne sieci VPC, dajemy im też pełną kontrolę nad ich lokalnymi regułami zapory, co bezpośrednio łamie wymóg centralnej kontroli reguł firewalla przez zespół bezpieczeństwa.
- C. Pojedynczy projekt z podziałem ról IAM: Dzielenie ról wewnątrz jednego projektu jest trudne do zarządzania w skali przedsiębiorstwa. Rola Compute Admin pozwala deweloperom na szerokie interakcje w projekcie i nie zapewnia fizycznej ani logicznej izolacji środowisk deweloperskich.

4. Wskazówki, hinty, tips and tricks:
- Separacja obowiązków sieciowych w GCP (Security zarządza siecią/firewallem, App/Devs wdrażają aplikacje) to definicja i główne zastosowanie architektury **Shared VPC**.

5. Reguły wyboru odpowiedzi (Słowa kluczowe):
- Separacja obowiązków sieciowych + centralne zarządzanie firewallem -> Shared VPC.
