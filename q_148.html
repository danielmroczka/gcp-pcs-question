Question 148 / 361

Which Google Cloud service should you use to enforce access control policies for applications and resources?

  • A. Identity-Aware Proxy
  • B. Cloud NAT
  • C. Google Cloud Armor
  • D. Shielded VMs
Show Suggested Answer Hide Answer
Suggested Answer: A

Wyjaśnienie

Potwierdzona odpowiedź: A (Identity-Aware Proxy).

Wyjaśnienie:
Identity-Aware Proxy (IAP) to usługa GCP, która pozwala kontrolować dostęp do aplikacji HTTPS oraz zasobów (takich jak instancje Compute Engine przez SSH/TCP) na podstawie tożsamości użytkownika i kontekstu (np. stan urządzenia, lokalizacja). IAP działa jako warstwa uwierzytelniająca i autoryzująca przed aplikacją, co pozwala na wdrożenie modelu Zero Trust (BeyondCorp) bez konieczności korzystania z tradycyjnych sieci VPN.

Dlaczego pozostałe są błędne:
- B. Cloud NAT: Służy do umożliwienia maszynom bez publicznych adresów IP dostępu do internetu (ruch wychodzący), ale nie pełni funkcji kontroli dostępu do aplikacji dla użytkowników zewnętrznych.
- C. Google Cloud Armor: Chroni aplikacje przed atakami DDoS i zawiera reguły WAF (np. ochrona przed SQLi, XSS), ale podstawowym narzędziem do egzekwowania polityk dostępu opartych na tożsamości ("access control policies") jest IAP.
- D. Shielded VMs: Zapewniają bezpieczeństwo na poziomie integralności systemu operacyjnego i bootowania maszyn wirtualnych, ale nie zarządzają dostępem użytkowników do zasobów aplikacji.

Wskazówki egzaminacyjne (Tips & Tricks):
- "Enforce access control" + "Applications" -> IAP (Identity-Aware Proxy).
- IAP to kluczowy produkt dla strategii BeyondCorp (Zero Trust) w Google Cloud.
- Pamiętaj, że IAP sprawdza uprawnienia IAM przed dopuszczeniem ruchu do backendu.

Kluczowe zagadnienia do powtórzenia:
- Zasada działania Cloud IAP.
- Model bezpieczeństwa Zero Trust.
- Różnica między IAP, Cloud Armor i Cloud VPN.
