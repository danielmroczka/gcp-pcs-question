Question 238 / 361

Your company is concerned about unauthorized parties gaining access to the Google Cloud environment by using a fake login page. You must implement a solution to protect against person-in-the-middle attacks. Which security measure should you use?

  • A. Security key
  • B. Google prompt
  • C. Text message or phone call code
  • D. Google Authenticator application
Show Suggested Answer Hide Answer
Suggested Answer: A

Wyjaśnienie

1. Prawidłowa odpowiedź lub odpowiedzi:
A. Security key

2. Kompleksowe wyjaśnienie dlaczego dana odpowiedź jest prawidłowa (Analiza):
Odpowiedź A jest prawidłowa, ponieważ fizyczne klucze bezpieczeństwa (Security Keys) oparte na standardzie FIDO2 / WebAuthn są jedynym mechanizmem uwierzytelniania dwuskładnikowego (2FA/2SV), który jest w 100% odporny na ataki typu phishing i person-in-the-middle (MITM).

Dlaczego klucz bezpieczeństwa chroni przed fałszywą stroną logowania:
a. **Powiązanie z domeną (Origin binding):** Podczas rejestracji klucza bezpieczeństwa jest on powiązany kryptograficznie z domeną (np. `accounts.google.com`).
b. **Weryfikacja w locie:** Kiedy użytkownik próbuje zalogować się na fałszywej stronie (np. `accounts.go0gle.com`), przeglądarka przesyła rzeczywistą domenę witryny do klucza bezpieczeństwa. Klucz sprawdza, czy domena zgadza się z zarejestrowaną. Ponieważ domena fałszywej strony się nie zgadza, klucz odmawia podpisania żądania logowania i nie przekazuje żadnych sekretów.
c. Żadne inne metody 2FA nie weryfikują domeny w ten sposób i mogą zostać przechwycone przez fałszywy serwer proxy (phishing proxy).

3. Wyjaśnienie z osobna każdej niepoprawnej odpowiedzi:
B. Google prompt
   * Dlaczego nieprawidłowa: Powiadomienia w telefonie (Google Prompt) wymagają jedynie zatwierdzenia logowania na ekranie urządzenia. Jeśli użytkownik wpisze hasło na fałszywej stronie, napastnik natychmiast wyzwoli prompta. Użytkownik, myśląc, że loguje się na prawdziwej stronie, zatwierdzi komunikat w telefonie, umożliwiając napastnikowi dostęp.
C. Text message or phone call code
   * Dlaczego nieprawidłowa: Kody jednorazowe wysyłane SMS-em są bardzo podatne na phishing. Użytkownik po wpisaniu hasła na fałszywej stronie wpisze tam również otrzymany kod SMS, który napastnik natychmiast przekieruje do prawdziwej usługi (Real-time phishing/MITM).
D. Google Authenticator application
   * Dlaczego nieprawidłowa: Podobnie jak kody SMS, kody z aplikacji Authenticator (TOTP) mogą zostać łatwo skopiowane przez użytkownika i wklejone na fałszywej stronie logowania, a następnie użyte przez napastnika do zalogowania się.

4. Wskazówki, hinty, tips and tricks:
* Najwyższy poziom ochrony przed phishingiem / fałszywymi stronami logowania / man-in-the-middle -> **Security key** (FIDO2/WebAuthn).
* Tradycyjne kody (SMS, Authenticator) nie chronią przed zaawansowanym phishingiem przechwytującym dane w czasie rzeczywistym.

5. Reguły wyboru odpowiedzi (Słowa kluczowe):
* Protect against fake login page / person-in-the-middle / phishing -> Security key.

6. Dodatkowe źródła i dokumentacja:

Wskazówki egzaminacyjne (Tips & Tricks)

Reguła Egzaminacyjna (Exam Rule): 
Jeśli scenariusz dotyczy zabezpieczania zasobów chmurowych (GCP), zawsze wybieraj rozwiązanie typu Managed (SCC, Secret Manager, Cloud KMS), a unikaj rozwiązań self-managed, chyba że pytanie wyraźnie wymaga dostosowania niskopoziomowego.

Haczyki egzaminacyjne (Exam Traps):
- Pułapka IAM: Pytania o uprawnienia często sugerują 'Project Owner' – zawsze szukaj 'Least Privilege' (np. 'Role: Secret Manager Secret Accessor').
- Pułapka Sieciowa: Często mylone są VPC Peering (wydajność) oraz VPN (szyfrowanie/on-premise).

Głębokie wyjaśnienie techniczne:
Rozwiązanie bazuje na GCP Shared Responsibility Model. Google zarządza bezpieczeństwem infrastruktury (Physical, Network, Host), podczas gdy administrator zarządza tożsamością (IAM), danymi (Encryption, Cloud KMS) i regułami dostępu (VPC Firewall).

Analiza i Podsumowanie (AI)

Kluczowe zagadnienia

Sugerowana odpowiedź: A

Analiza strategiczna: To pytanie uderza w fundamenty ochrony tożsamości. W nowoczesnym modelu bezpieczeństwa, hasło (nawet z MFA typu SMS/kody) to za mało. Klucz fizyczny to jedyne rozwiązanie, które daje pewność, że użytkownik jest dokładnie tam, gdzie powinien być, a nie na stronie podstawionej przez atakującego.
