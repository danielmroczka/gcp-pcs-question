Question 23 / 361

When working with agents in the support center via online chat, your organization's customers often share pictures of their documents with personally identifiable information (PII). Your leadership team is concerned that this PII is being stored as part of the regular chat logs, which are reviewed by internal or external analysts for customer service trends.
You want to resolve this concern while still maintaining data utility. What should you do?

  • A. Use Cloud Key Management Service to encrypt PII shared by customers before storing it for analysis.
  • B. Use Object Lifecycle Management to make sure that all chat records containing PII are discarded and not saved for analysis.
  • C. Use the image inspection and redaction actions of the DLP API to redact PII from the images before storing them for analysis.
  • D. Use the generalization and bucketing actions of the DLP API solution to redact PII from the texts before storing them for analysis.
Show Suggested Answer Hide Answer
Suggested Answer: C

Wyjaśnienie

Potwierdzona odpowiedź: C (Use the image inspection and redaction actions of the DLP API to redact PII from the images before storing them for analysis.)

Wyjaśnienie: 
Cloud Data Loss Prevention (DLP) API to usługa zaprojektowana specjalnie do wykrywania i maskowania danych wrażliwych (PII). W scenariuszu, gdzie klienci przesyłają zdjęcia dokumentów, DLP API wykorzystuje mechanizmy optycznego rozpoznawania znaków (OCR) do odnalezienia tekstu na obrazach, a następnie funkcję "redaction" (redakcja/maskowanie), która pozwala na trwałe zakrycie wykrytych wrażliwych informacji (np. numerów dowodów, nazwisk) na samym obrazie. Pozwala to na zachowanie użyteczności reszty danych (Data Utility) do analizy, jednocześnie eliminując ryzyko przechowywania PII.

Dlaczego pozostałe są błędne:
A. Cloud KMS: Szyfrowanie przy użyciu KMS zabezpiecza dane przed niepowołanym dostępem, ale nie zmienia ich zawartości. PII nadal znajdowałoby się fizycznie w logach, co nie rozwiązuje problemu "czyszczenia" danych do celów analitycznych bez odszyfrowywania.
B. Object Lifecycle Management: Ta funkcja służy do automatycznego usuwania lub przenoszenia całych plików (np. po 30 dniach). Usunięcie całego pliku czatu uniemożliwia jakąkolwiek późniejszą analizę trendów, co narusza wymóg "maintaining data utility".
D. Generalization and bucketing: Są to techniki de-identyfikacji danych ustrukturyzowanych (np. zamiana wieku na zakres "20-30 lat"). Choć to funkcje DLP, nie mają one zastosowania bezpośrednio do procesowania obrazów (zrzutów dokumentów), gdzie wymagana jest redakcja wizualna (maskowanie pikseli).

Wskazówki egzaminacyjne (Tips & Tricks):
- "PII" + "Images" / "Pictures" + "Analyze": Twoją pierwszą myślą zawsze powinno być DLP API z funkcją Image Redaction.
- "Maintain data utility" to w języku egzaminacyjnym Google sygnał, że nie wolno usuwać całych rekordów (LifeCycle), lecz trzeba je "oczyścić" (DLP).

Kluczowe zagadnienia do powtórzenia:
- Możliwości Cloud DLP API w zakresie tekstów i obrazów
- Różnica między Redaction, Masking i De-identification
- Integracja Cloud Storage z DLP API

**Reguła Egzaminacyjna (Exam Rule):**
Zawsze identyfikuj warstwę modelu OSI, na której operuje atak oraz rozwiązanie. DNSSEC działa na poziomie warstwy aplikacji dla DNS, zapobiegając zatruwaniu pamięci podręcznej (Cache Poisoning).

**Haczyki egzaminacyjne (Exam Traps):**
- Mylenie Cloud Armor (WAF - L7) z zabezpieczeniami DNS (DNSSEC - integralność danych DNS).
- Zakładanie, że TLS/SSL wystarczy do ochrony przed przekierowaniem całego ruchu DNS (DNSSEC zabezpiecza sam proces rezolucji, zanim nawiążesz bezpieczne połączenie TLS).

**Głębokie wyjaśnienie techniczne:**
DNSSEC wykorzystuje kryptografię klucza publicznego (RRSIG, DNSKEY, DS) do cyfrowego podpisywania rekordów DNS w strefach (Zone Signing). Dzięki temu resolver DNS może zweryfikować łańcuch zaufania aż do punktu głównego (root zone) bez konieczności polegania wyłącznie na adresie IP serwera autorytatywnego, co drastycznie ogranicza skuteczność ataków typu MITM i cache poisoning.
