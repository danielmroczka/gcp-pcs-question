Question 361 / 361

Your company has deployed an artificial intelligence model in a central project. This model contains sensitive intellectual property and must be kept strictly isolated from the internet. You must expose the model endpoint only to a defined list of projects in your organization. What should you do?

  • A. Within the model project, create an internal Application Load Balancer that points to the model endpoint. Expose this load balancer with Private Service Connect to a configured list of projects.
  • B. Activate Private Google Access in both the model project and in each project that needs to connect to the model. Create a firewall policy to allow connectivity to Private Google Access addresses.
  • C. Create a central project to host Shared VPC networks that are provided to all other projects. Centrally administer all firewall rules in this project to grant access to the model.
  • D. Within the model project, create an external Application Load Balancer that points to the model endpoint. Create a Cloud Armor policy to restrict IP addresses to Google Cloud.
Show Suggested Answer Hide Answer
Suggested Answer: A

Wyjaśnienie

✅ PRAWIDŁOWA ODPOWIEDŹ: A

Prawidłowa odpowiedź: A – Within the model project, create an internal Application Load Balancer that points to the model endpoint. Expose the load balancer by using Private Service Connect (PSC). Allow consumer projects to access the PSC service.

DLACZEGO A JEST PRAWIDŁOWE?
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
Wymagania: AI model odizolowany od Internetu, dostępny dla innych projektów wewnętrznie. Private Service Connect (PSC):
- Internal Load Balancer = model nie jest dostępny z Internetu.
- PSC = bezpieczne, prywatne udostępnienie serwisu innym projektom/VPC.
- Consumer projects łączą się przez PSC endpoint (bez VPC peering, bez Shared VPC).
- Każdy projekt ma własny PSC endpoint = granularna kontrola dostępu.
- Ruch pozostaje w sieci Google (nie przez Internet).

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
DLACZEGO INNE OPCJE SĄ BŁĘDNE?
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
B. ❌ Private Google Access = dla dostępu do Google APIs z VM bez zewnętrznego IP. Nie służy do ekspozycji własnych endpointów innym projektom.
C. ❌ Shared VPC = współdzielona sieć, ale wymaga centralnego zarządzania i daje szerszy dostęp sieciowy. PSC jest bardziej granularny i izolowany.
D. ❌ External ALB = dostępny z Internetu. Naruszenie wymagania "strictly isolated from the internet".

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
WSKAZÓWKI EGZAMINACYJNE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
• Prywatna ekspozycja serwisu innym projektom = Private Service Connect (PSC).
• PSC = serwis jest "published", konsumenci tworzą własne endpoint w ich VPC.
• "Isolated from internet" + "accessible to other projects" = PSC + Internal LB.
• PSC > Shared VPC dla granularnej izolacji serwisów.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
REGUŁY
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
• Prywatny serwis dla wielu projektów = Private Service Connect.
• External LB = Internet = naruszenie izolacji.
• Shared VPC = wspólna sieć (szerszy dostęp), PSC = izolowany serwis.
