Question 216 / 361

Your organization wants to be continuously evaluated against CIS Google Cloud Computing Foundations Benchmark v1.3.0 (CIS Google Cloud Foundation 1.3). Some of the controls are irrelevant to your organization and must be disregarded in evaluation. You need to create an automated system or process to ensure that only the relevant controls are evaluated. What should you do?

  • A. Mark all security findings that are irrelevant with a tag and a value that indicates a security exception. Select all marked findings, and mute them on the console every time they appear. Activate Security Command Center (SCC) Premium.
  • B. Activate Security Command Center (SCC) Premium. Create a rule to mute the security findings in SCC so they are not evaluated.
  • C. Download all findings from Security Command Center (SCC) to a CSV file. Mark the findings that are part of CIS Google Cloud Foundation 1.3 in the file. Ignore the entries that are irrelevant and out of scope for the company.
  • D. Ask an external audit company to provide independent reports including needed CIS benchmarks. In the scope of the audit, clarify that some of the controls are not needed and must be disregarded.
Show Suggested Answer Hide Answer
Suggested Answer: B

Wyjaśnienie

1. Prawidłowa odpowiedź lub odpowiedzi:
B. Activate Security Command Center (SCC) Premium. Create a rule to mute the security findings in SCC so they are not evaluated.

2. Kompleksowe wyjaśnienie dlaczego dana odpowiedź jest prawidłowa (Analiza):
Odpowiedź B jest prawidłowa, ponieważ Security Command Center (SCC) Premium oferuje wbudowane i zautomatyzowane monitorowanie zgodności z benchmarkami CIS (w tym CIS Google Cloud Computing Foundations Benchmark) oraz natywną funkcję wyciszania (mute rules).

Zalety tego rozwiązania:
a. **SCC Premium Compliance Monitoring:** SCC automatycznie skanuje konfigurację chmury i generuje wykrycia (findings) niezgodności z CIS.
b. **Mute Rules (Zasady wyciszania):** Pozwalają na definiowanie filtrów wyciszających określone typy wykryć (np. te, które są uznane za nieistotne dla Twojej organizacji). Wyciszone wykrycia nie pojawiają się w domyślnych raportach i nie obniżają wskaźnika zgodności organizacji (compliance score), co pozwala na automatyczne odrzucenie niechcianych reguł.

3. Wyjaśnienie z osobna każdej niepoprawnej odpowiedzi:
A. Mark all security findings... mute them on the console every time they appear...
   * Dlaczego nieprawidłowa: Ręczne wyciszanie każdego wykrycia za każdym razem, gdy się pojawi, nie jest procesem zautomatyzowanym i generuje ogromny nakład pracy dla zespołu operacyjnego (brak skalowalności).
C. Download all findings from Security Command Center (SCC) to a CSV file... Ignore the entries...
   * Dlaczego nieprawidłowa: Praca na plikach CSV pobieranych ręcznie jest procesem statycznym, podatnym na błędy ludzkie i nie pozwala na ciągłą (continuous) ewaluację w czasie rzeczywistym.
D. Ask an external audit company to provide independent reports...
   * Dlaczego nieprawidłowa: Zewnętrzne audyty są przeprowadzane okresowo (np. raz w roku) i są bardzo kosztowne. Nie stanowią one "automatycznego systemu lub procesu ciągłej ewaluacji".

4. Wskazówki, hinty, tips and tricks:
* Ciągły audyt zgodności z CIS Benchmark w GCP -> Zawsze używaj **Security Command Center Premium**.
* Ignorowanie specyficznych reguł w SCC bez wpływania na wyniki ogólne realizuje się za pomocą **Mute Rules** (Reguł wyciszania).

5. Reguły wyboru odpowiedzi (Słowa kluczowe):
* CIS Benchmark compliance evaluation in GCP -> Security Command Center Premium + Mute Rules.

6. Dodatkowe źródła i dokumentacja:
Muting findings in Security Command Center
Compliance monitoring in Security Command Center

Wskazówki egzaminacyjne (Tips & Tricks)

Reguła Egzaminacyjna (Exam Rule): 
Jeśli scenariusz dotyczy zabezpieczania zasobów chmurowych (GCP), zawsze wybieraj rozwiązanie typu Managed (SCC, Secret Manager, Cloud KMS), a unikaj rozwiązań self-managed, chyba że pytanie wyraźnie wymaga dostosowania niskopoziomowego.

Haczyki egzaminacyjne (Exam Traps):
- Pułapka IAM: Pytania o uprawnienia często sugerują 'Project Owner' – zawsze szukaj 'Least Privilege' (np. 'Role: Secret Manager Secret Accessor').
- Pułapka Sieciowa: Często mylone są VPC Peering (wydajność) oraz VPN (szyfrowanie/on-premise).

Głębokie wyjaśnienie techniczne:
Rozwiązanie bazuje na GCP Shared Responsibility Model. Google zarządza bezpieczeństwem infrastruktury (Physical, Network, Host), podczas gdy administrator zarządza tożsamością (IAM), danymi (Encryption, Cloud KMS) i regułami dostępu (VPC Firewall).

Analiza i Podsumowanie (AI)

Kluczowe zagadnienia

Sugerowana odpowiedź: B

Analiza strategiczna: To pytanie testuje umiejętność zarządzania "Compliance Fatigue" (zmęczeniem audytowym). W dużych firmach SCC Premium generuje tysiące alertów. Kluczem do sukcesu jest "odszumianie" (noise reduction) poprzez automatyczne wyciszanie tego, co biznesowo zaakceptowano jako bezpieczne, aby zespół security mógł skupić się na prawdziwych problemach.

Dodatkowe wskazówki

  • Możesz wyciszyć znalezisko na poziomie organizacji, folderu lub projektu.
  • Każda reguła wyciszania musi zawierać wyjaśnienie (np. "Akceptowane ryzyko zgodnie z polityką firmy X"), co jest ważne dla celów audytowych.
