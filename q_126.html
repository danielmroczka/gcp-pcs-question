Question 126 / 361

Which type of load balancer should you use to maintain client IP by default while using the standard network tier?

  • A. SSL Proxy
  • B. TCP Proxy
  • C. Internal TCP/UDP
  • D. TCP/UDP Network
Show Suggested Answer Hide Answer
Suggested Answer: D

Wyjaśnienie

Potwierdzona odpowiedź: D (TCP/UDP Network)

Wyjaśnienie:
Zewnętrzny passthrough Network Load Balancer (TCP/UDP Network) działa na warstwie 4 modelu OSI i nie kończy sesji TCP/UDP na samym load balancerze. Zamiast tego pakiety są przekazywane bezpośrednio do instancji backendowych (pass-through). Dzięki temu adres źródłowy IP w pakiecie docierającym do maszyny wirtualnej pozostaje adresem IP klienta (Client IP preservation). Jest to domyślne zachowanie tego typu load balancera, również w Standard Network Tier.

Dlaczego pozostałe odpowiedzi są niepoprawne:
- A i B (SSL/TCP Proxy): Są to load balancery typu proxy. Kończą one połączenie klienta na brzegowym systemie Google i nawiązują nowe połączenie z backendem. W rezultacie backend widzi adres IP load balancera, a nie klienta (chyba że użyje się protokołu PROXY).
- C (Internal TCP/UDP): Jest to load balancer wewnętrzny, używany do ruchu wewnątrz sieci VPC. Chociaż również jest typu pass-through, nie jest przeznaczony do obsługi ruchu z publicznego internetu w kontekście Standard Network Tier.

Wskazówki i triki (Tips & Tricks):
- "Maintain client IP by default" = Network Load Balancer (passthrough).
- Load balancery typu Proxy (HTTP, SSL, TCP) zawsze maskują adres IP klienta (wymagają nagłówka X-Forwarded-For lub PROXY protocol).

Praktyczne informacje na egzamin:
- Network Load Balancer jest wybierany, gdy liczy się wydajność i niskie koszty (brak inspekcji warstwy 7).
- Standard Network Tier jest dostępny tylko dla wybranych typów zasobów zewnętrznych, w tym dla Network LB.

Analiza i Podsumowanie Dyskusji (AI)

Analiza i Wyjaśnienie

Sugerowana odpowiedź: D

Głęboka analiza: Wybór Network Load Balancera jest kluczowy, gdy aplikacja backendowa musi samodzielnie analizować źródłowe adresy IP (np. dla celów geolokalizacji lub logowania bezpieczeństwa bez dodatkowych nagłówków). Należy jednak pamiętać, że w przeciwieństwie do Load Balancerów HTTP(S), Network LB nie oferuje zaawansowanych funkcji Cloud Armor (WAF) w warstwie 7.
