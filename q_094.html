Question 94 / 361

You are responsible for protecting highly sensitive data in BigQuery. Your operations teams need access to this data, but given privacy regulations, you want to ensure that they cannot read the sensitive fields such as email addresses and first names. These specific sensitive fields should only be available on a need-to-know basis to the Human Resources team. What should you do?

  • A. Perform data masking with the Cloud Data Loss Prevention API, and store that data in BigQuery for later use.
  • B. Perform data redaction with the Cloud Data Loss Prevention API, and store that data in BigQuery for later use.
  • C. Perform data inspection with the Cloud Data Loss Prevention API, and store that data in BigQuery for later use.
  • D. Perform tokenization for Pseudonymization with the Cloud Data Loss Prevention API, and store that data in BigQuery for later use.
Show Suggested Answer Hide Answer
Suggested Answer: D

Wyjaśnienie

**Poprawna odpowiedź: D**

**1. Kompleksowe wyjaśnienie poprawnej odpowiedzi:**
Wymagane jest zabezpieczenie wrażliwych danych (takich jak adresy e-mail i imiona) w BigQuery przed dostępem zespołów operacyjnych, przy jednoczesnym zachowaniu możliwości odczytu tych danych przez zespół HR na zasadzie "need-to-know":
- **Wykonanie tokenizacji w celu pseudonimizacji (Tokenization for Pseudonymization) za pomocą Cloud Data Loss Prevention (Cloud DLP) API (D):** Tokenizacja (pseudonimizacja) polega na zastąpieniu wrażliwych danych (np. tekstu jawnego) unikalnym tokenem (kryptograficznym lub deterministycznym). Zespoły operacyjne mogą analizować dane w BigQuery, widząc jedynie tokeny, co uniemożliwia im identyfikację osób. Jednocześnie zespół HR (lub autoryzowana aplikacja) posiadający klucz deszyfrujący może zdetokenizować dane w razie potrzeby, odzyskując oryginalne wartości.

**2. Wyjaśnienie niepoprawnych odpowiedzi:**
- **A. Maskowanie danych (Data masking):** Zastępuje znaki stałym symbolem (np. `***@***.com`). Jest to proces nieodwracalny w miejscu zapisu – jeśli dane zostaną zamaskowane i zapisane w BigQuery, zespół HR również nie będzie mógł odzyskać oryginalnych adresów e-mail.
- **B. Redakcja danych (Data redaction):** Całkowicie usuwa wrażliwy tekst ze zbioru danych. Podobnie jak w przypadku maskowania, jest to proces jednostronny i nieodwracalny, co uniemożliwia zespołowi HR dostęp do oryginalnych danych.
- **C. Inspekcja danych (Data inspection):** Służy jedynie do wykrywania i raportowania obecności danych wrażliwych, ale nie zabezpiecza ich ani nie modyfikuje w bazie danych.

**3. Wskazówki i pułapki egzaminacyjne (Tips & Tricks):**
- **Pseudonimizacja/Tokenizacja:** Pozwala na odwrócenie procesu (odzyskanie danych pierwotnych) przez uprawnione osoby przy użyciu klucza.
- **Maskowanie/Redakcja:** Procesy nieodwracalne (destrukcyjne dla oryginalnej treści).
- Jeśli dane muszą być ukryte przed jednymi, ale dostępne dla innych w oryginalnej formie -> wybierz **Tokenizację/Pseudonimizację**.

**4. Reguły wyboru odpowiedzi:**
- Ukrycie danych wrażliwych z możliwością ich późniejszego odczytania (odwrócenie procesu) -> Tokenization for Pseudonymization (DLP).
