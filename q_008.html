Question 8 / 361

A customer implements Cloud Identity-Aware Proxy for their ERP system hosted on Compute Engine. Their security team wants to add a security layer so that the ERP systems only accept traffic from Cloud Identity-Aware Proxy. What should the customer do to meet these requirements?

  • A. Make sure that the ERP system can validate the JWT assertion in the HTTP requests.
  • B. Make sure that the ERP system can validate the identity headers in the HTTP requests.
  • C. Make sure that the ERP system can validate the x-forwarded-for headers in the HTTP requests.
  • D. Make sure that the ERP system can validate the user's unique identifier headers in the HTTP requests.
Show Suggested Answer Hide Answer
Suggested Answer: A

Wyjaśnienie

Poprawna odpowiedź: A (Make sure that the ERP system can validate the JWT assertion in the HTTP requests.)

Analiza poprawności:
Identity-Aware Proxy (IAP) dołącza do każdego żądania HTTP nagłówek `x-goog-iap-jwt-assertion`. Jest to token JWT (JSON Web Token) podpisany przez Google. Weryfikacja podpisu tego tokenu przez aplikację ERP (przy użyciu publicznych kluczy Google) daje pewność, że żądanie rzeczywiście przeszło przez IAP. Dzięki temu aplikacja nie musi ufać sieci i może odrzucić każde połączenie, które nie posiada poprawnego, zweryfikowanego podpisu Google, co chroni przed atakami typu "bypass" (połączenie bezpośrednie do serwera z pominięciem IAP).

Dlaczego pozostałe są błędne:
B, D: Nagłówki takie jak `x-goog-authenticated-user-email` czy inne identyfikatory użytkownika mogą być łatwo sfałszowane przez każdego, kto uzyska dostęp do sieci wewnętrznej (np. z innej maszyny w tym samym VPC). Sama obecność nagłówka nie jest dowodem autentyczności.
C: Nagłówek `x-forwarded-for` informuje o adresie IP klienta pierwotnego, ale nie pełni funkcji zabezpieczającej ani weryfikującej, że żądanie przeszło przez bezpieczną bramę IAP.

Wskazówki egzaminacyjne:
- Zero Trust: Zawsze wybieraj opcje, które zakładają, że sieć może być skompromitowana, a aplikacja musi sama weryfikować tożsamość żądania (podpis JWT).
- JWT assertion: To słowo-klucz w pytaniach o bezpieczeństwo IAP.
- Eliminacja: Jeśli widzisz "headers" w kontekście bezpieczeństwa IAP, zawsze szukaj słowa "signed" lub "JWT assertion".

Analiza i Wyjaśnienie

Sugerowana odpowiedź: A

Analiza spornych kwestii (AI): Wielu deweloperów uważa, że wystarczy firewall blokujący wszystko poza IP Load Balancera. Jednak eksperci security na forach podkreślają, że w modelu "Defense in Depth" aplikacja nigdy nie powinna ufać sieci. Weryfikacja JWT to jedyna metoda, która chroni przed atakami typu "lateral movement" wewnątrz chmury.
