Question 8 / 361

A customer implements Cloud Identity-Aware Proxy for their ERP system hosted on Compute Engine. Their security team wants to add a security layer so that the ERP systems only accept traffic from Cloud Identity-Aware Proxy. What should the customer do to meet these requirements?

  • A. Make sure that the ERP system can validate the JWT assertion in the HTTP requests.
  • B. Make sure that the ERP system can validate the identity headers in the HTTP requests.
  • C. Make sure that the ERP system can validate the x-forwarded-for headers in the HTTP requests.
  • D. Make sure that the ERP system can validate the user's unique identifier headers in the HTTP requests.
Show Suggested Answer Hide Answer
Suggested Answer: A

Wyjaśnienie

Potwierdzona odpowiedź: A (Make sure that the ERP system can validate the JWT assertion in the HTTP requests.)

**Reguła Egzaminacyjna (Exam Rule):**
Jeśli pytanie dotyczy zabezpieczenia aplikacji przed ruchem bezpośrednim (omijającym IAP), jedyną poprawną metodą jest weryfikacja podpisanego nagłówka JWT (Signed Header) przesyłanego przez IAP. Nagłówek ten nazywa się `x-goog-iap-jwt-assertion`.

**Haczyki egzaminacyjne (Exam Traps):**
- Pułapka: "Identity headers". Są one wysyłane przez IAP, ale nie są podpisane kryptograficznie, więc napastnik z dostępem sieciowym może je łatwo sfałszować.
- Pułapka: "x-forwarded-for". Służy do identyfikacji IP klienta, a nie do uwierzytelnienia faktu przejścia przez proxy IAP.
- Pułapka: "Unikalne identyfikatory". Bez podpisu cyfrowego nie zapewniają one integralności ani pewności co do źródła ruchu.

**Głębokie wyjaśnienie techniczne:**
Cloud IAP wstawia do każdego żądania HTTP nagłówek `x-goog-iap-jwt-assertion`. Jest to token JWT podpisany cyfrowo przez Google. Weryfikacja podpisu tego tokenu przez aplikację przy użyciu publicznych kluczy Google daje pewność, że:
1. Ruch faktycznie przeszedł przez IAP.
2. Token nie został sfałszowany.
3. Informacje o tożsamości użytkownika są wiarygodne.

Bez weryfikacji JWT, aplikacja jest narażona na ataki omijające IAP (tzw. bypassing IAP).

Analiza i Wyjaśnienie

Sugerowana odpowiedź: A

Analiza spornych kwestii (AI): Eksperci zwracają uwagę, że weryfikacja JWT jest jedynym sposobem na 'zero trust' wewnątrz sieci VPC. Jeśli Twoja aplikacja nie sprawdza podpisu, napastnik, który dostanie się do Twojej sieci (np. przez inną skompromitowaną maszynę), może wysłać spreparowane nagłówki z dowolnym adresem email i przejąć konto administratora ERP.
