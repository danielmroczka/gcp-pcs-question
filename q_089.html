Question 89 / 361

You are the security admin of your company. You have 3,000 objects in your Cloud Storage bucket. You do not want to manage access to each object individually.
You also do not want the uploader of an object to always have full control of the object. However, you want to use Cloud Audit Logs to manage access to your bucket.
What should you do?

  • A. Set up an ACL with OWNER permission to a scope of allUsers.
  • B. Set up an ACL with READER permission to a scope of allUsers.
  • C. Set up a default bucket ACL and manage access for users using IAM.
  • D. Set up Uniform bucket-level access on the Cloud Storage bucket and manage access for users using IAM.
Show Suggested Answer Hide Answer
Suggested Answer: D

Wyjaśnienie

**Poprawna odpowiedź: D**

**1. Kompleksowe wyjaśnienie poprawnej odpowiedzi:**
Wymaganiem jest zarządzanie dostępem do 3000 obiektów w kubłach Cloud Storage w sposób scentralizowany i zbiorowy, zapobieganie sytuacji, w której uploader automatycznie ma pełną kontrolę (np. nadpisuje polityki dostępu), oraz możliwość pełnego audytowania dostępu za pomocą Cloud Audit Logs:
- **Włączenie Uniform bucket-level access (UBLA) na kubełku i zarządzanie dostępem przez IAM (D):** UBLA wyłącza listy kontroli dostępu (ACL) na poziomie poszczególnych obiektów. Po jego włączeniu dostęp jest kontrolowany wyłącznie przez zasady IAM przypisane na poziomie całego kubełka (bucket). Zapobiega to sytuacji, w której użytkownik wgrywający plik konfiguruje niestandardowe uprawnienia (ACL) na obiekcie. Ponadto, wyłączenie ACL upraszcza zarządzanie bezpieczeństwem i pozwala na niezawodne raportowanie audytowe.

**2. Wyjaśnienie niepoprawnych odpowiedzi:**
- **A. Set up an ACL with OWNER permission to a scope of allUsers:** Dostęp typu `allUsers` oznacza, że obiekty stają się publicznie dostępne w internecie dla każdego, co jest poważnym błędem bezpieczeństwa.
- **B. Set up an ACL with READER permission to a scope of allUsers:** Podobnie jak w opcji A, czyni to dane publicznymi i narusza bezpieczeństwo danych.
- **C. Domyślne ACL i zarządzanie przez IAM:** Pozostawienie włączonych ACL (nawet z domyślnymi ustawieniami) sprawia, że uprawnienia na obiektach nadal mogą być modyfikowane niezależnie od IAM przez użytkowników posiadających uprawnienia zapisu, co uniemożliwia scentralizowaną i jednolitą kontrolę dostępu.

**3. Wskazówki i pułapki egzaminacyjne (Tips & Tricks):**
- **Uniform bucket-level access (UBLA):** Wyłącza ACL-e. Dostęp jest zarządzany wyłącznie przez IAM. Jest to domyślne i zalecane ustawienie bezpieczeństwa w Google Cloud.
- Zapamiętaj: Jeśli pytanie mówi o rezygnacji z zarządzania dostępem do pojedynczych plików na rzecz spójnego, scentralizowanego zarządzania -> kluczem jest **Uniform bucket-level access**.

**4. Reguły wyboru odpowiedzi:**
- Wyłączenie indywidualnych uprawnień per obiekt / ujednolicenie uprawnień w GCS -> Uniform bucket-level access.

**5. Dodatkowe źródła:**
- Uniform bucket-level access: https://cloud.google.com/storage/docs/uniform-bucket-level-access
