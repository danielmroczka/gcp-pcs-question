Question 285 / 361

Your organization is developing a new SaaS application on Google Cloud. Stringent compliance standards require visibility into privileged account activity, and potentially unauthorized changes and misconfigurations to the application's infrastructure. You need to monitor administrative actions, log changes to IAM roles and permissions, and be able to trace potentially unauthorized configuration changes. What should you do?

  • A. Create log sinks to Cloud Storage for long-term retention. Set up log-based alerts in Cloud Logging based on relevant log types. Enable VPC Flow Logs for network visibility.
  • B. Deploy Cloud IDS and activate Firewall Rules Logging. Create a custom dashboard in Security Command Center to visualize potential intrusion attempts.
  • C. Detect sensitive administrative actions by using Cloud Logging with custom filters. Enable VPC Flow Logs with BigQuery exports for rapid analysis of network traffic patterns.
  • D. Enable Event Threat Detection and Security Health Analytics in Security Command Center. Set up detailed logging for IAM-related activity and relevant project resources by deploying Cloud Audit Logs.
Show Suggested Answer Hide Answer
Suggested Answer: D

Wyjaśnienie

1. Prawidłowa odpowiedź lub odpowiedzi:
D. Enable Event Threat Detection and Security Health Analytics in Security Command Center. Set up detailed logging for IAM-related activity and relevant project resources by deploying Cloud Audit Logs.

2. Kompleksowe wyjaśnienie dlaczego dana odpowiedź jest prawidłowa (Analiza):
Odpowiedź D jest prawidłowa, ponieważ łączy wdrożenie podstawowych rejestrów zdarzeń (Cloud Audit Logs) ze zautomatyzowaną analizą i monitorowaniem w czasie rzeczywistym przy użyciu Security Command Center (SCC) Premium.

Analiza i korzyści:
a. **Cloud Audit Logs (Fundament audytu):** Zapewnia rejestrację wszystkich działań administracyjnych (Admin Activity) oraz zmian w uprawnieniach IAM (kto zmienił rolę, kto dodał użytkownika). Umożliwia to pełną identyfikację działań użytkowników uprzywilejowanych.
b. **Security Health Analytics (SHA):** Skanuje konfigurację zasobów chmurowych pod kątem błędów i nieuprawnionych zmian (np. publiczne kubełki GCS, wyłączone logowanie).
c. **Event Threat Detection (ETD):** Analizuje logi w poszukiwaniu podejrzanych zachowań (np. próby eskalacji uprawnień, logowanie z podejrzanych IP), co pozwala na natychmiastowe wykrycie incydentów.

3. Wyjaśnienie z osobna każdej niepoprawnej odpowiedzi:
A. Create log sinks to Cloud Storage for long-term retention... Enable VPC Flow Logs...
   * Dlaczego nieprawidłowa: Zapisywanie logów do Cloud Storage to świetna praktyka w celach retencji archiwalnej, ale nie pozwala na aktywne, zautomatyzowane monitorowanie i szybkie reagowanie w czasie rzeczywistym. VPC Flow Logs monitorują ruch sieciowy IP, co nie dostarcza informacji o zmianach uprawnień IAM w konsoli.
B. Deploy Cloud IDS and activate Firewall Rules Logging...
   * Dlaczego nieprawidłowa: Cloud IDS i logi zapory sieciowej (Firewall Logs) chronią warstwę sieciową przed atakami z zewnątrz (np. próby włamań). Nie monitorują one zmian w uprawnieniach IAM i konfiguracjach innych usług GCP, co było kluczowym wymaganiem audytowym.
C. Detect sensitive administrative actions by using Cloud Logging with custom filters...
   * Dlaczego nieprawidłowa: Samodzielne pisanie filtrów w Cloud Logging i analizowanie ruchu w BigQuery wymaga ciągłej pracy deweloperskiej i nie oferuje gotowych, inteligentnych algorytmów wykrywania zagrożeń, które SCC (ETD/SHA) dostarcza natywnie z pudełka.

4. Wskazówki, hinty, tips and tricks:
* Monitorowanie zmian w IAM, akcji administratorów oraz audyt konfiguracji chmury -> Zawsze włączaj **Cloud Audit Logs** (w tym Data Access Logs) i integruj je z **Security Command Center (SHA/ETD)**.
* Logi Admin Activity są włączone domyślnie i bezpłatnie w GCP.

5. Reguły wyboru odpowiedzi (Słowa kluczowe):
* Monitor administrative actions + IAM changes + trace unauthorized changes -> Cloud Audit Logs + Event Threat Detection + Security Health Analytics (SCC).
