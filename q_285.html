Question 285 / 361

Your organization is developing a new SaaS application on Google Cloud. Stringent compliance standards require visibility into privileged account activity, and potentially unauthorized changes and misconfigurations to the application's infrastructure. You need to monitor administrative actions, log changes to IAM roles and permissions, and be able to trace potentially unauthorized configuration changes. What should you do?

  • A. Create log sinks to Cloud Storage for long-term retention. Set up log-based alerts in Cloud Logging based on relevant log types. Enable VPC Flow Logs for network visibility.
  • B. Deploy Cloud IDS and activate Firewall Rules Logging. Create a custom dashboard in Security Command Center to visualize potential intrusion attempts.
  • C. Detect sensitive administrative actions by using Cloud Logging with custom filters. Enable VPC Flow Logs with BigQuery exports for rapid analysis of network traffic patterns.
  • D. Enable Event Threat Detection and Security Health Analytics in Security Command Center. Set up detailed logging for IAM-related activity and relevant project resources by deploying Cloud Audit Logs.
Show Suggested Answer Hide Answer
Suggested Answer: D

Wskazówki egzaminacyjne (Tips & Tricks)

Reguła Egzaminacyjna (Exam Rule): 
W pytaniach typu 'Security in GCP', zawsze priorytetyzuj rozwiązania natywne (SCC, Cloud KMS, Secret Manager, VPC SC) nad rozwiązaniami typu 'third-party' lub 'self-managed', chyba że scenariusz wymaga specyficznej integracji hybrydowej.

Haczyki egzaminacyjne (Exam Traps):
- Pułapka 'Least Privilege': Egzamin często podpowiada role o szerokim zakresie (np. 'Editor' lub 'Owner') – zawsze odrzucaj je na rzecz ról predefiniowanych o najmniejszym zakresie uprawnień.
- Pułapka 'Logging vs Monitoring': Pamiętaj: Audit Logs służą do badania aktywności (Who/What/When), a Monitoring do zbierania metryk wydajnościowych.

Głębokie wyjaśnienie techniczne:
Każda architektura bezpieczeństwa w GCP powinna być projektowana w oparciu o 'Security by Default'. Oznacza to m.in. szyfrowanie w spoczynku (domyślne), tożsamość opartą na rolach (IAM) oraz pełną widoczność zapewnianą przez scentralizowane logowanie (Cloud Logging/SCC).

Wyjaśnienie

Potwierdzona odpowiedź: D (Enable Event Threat Detection and Security Health Analytics in Security Command Center. Set up detailed logging for IAM-related activity and relevant project resources by deploying Cloud Audit Logs.)

Wyjaśnienie:
- SCC Suite: Zestaw ETD (wykrywanie włamań), SHA (wykrywanie błędów konfiguracji) oraz Cloud Audit Logs (ślad zmian IAM) pokrywa wszystkie wymogi monitoringu compliance dla aplikacji SaaS.

Dlaczego pozostałe odpowiedzi są niepoprawne:
- A, B, C: Są to rozwiązania fragmentaryczne, skupiające się tylko na sieci lub samej archiwizacji logów, bez inteligentnej analizy zagrożeń tożsamościowych i konfiguracyjnych.

Wskazówki i triki (Tips & Tricks):
- "Visibility into privileged account activity" + "Unauthorized changes" + "Compliance" = Security Command Center (SCC) Suite + Cloud Audit Logs.
- Pamiętaj: SCC jest scentralizowanym hubem bezpieczeństwa w GCP.

Praktyczne informacje na egzamin:
- Integracja SCC z Audit Logs pozwala na korelację zdarzeń - np. "ktoś z IP z Chin (ETD) zmienił rolę IAM (Audit Logs) na uprzywilejowaną".
