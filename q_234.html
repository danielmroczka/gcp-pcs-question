Question 234 / 361

Your organization uses BigQuery to process highly sensitive, structured datasets. Following the "need to know" principle, you need to create the Identity and Access Management (IAM) design to meet the needs of these users: - Business user: must access curated reports. - Data engineer: must administrate the data lifecycle in the platform. - Security operator: must review user activity on the data platform. What should you do?

  • A. Configure data access log for BigQuery services, and grant Project Viewer role to security operator.
  • B. Set row-based access control based on the "region" column, and filter the record from the United States for data engineers.
  • C. Create curated tables in a separate dataset and assign the role roles/bigquery.dataViewer.
  • D. Generate a CSV data file based on the business user's needs, and send the data to their email addresses.
Show Suggested Answer Hide Answer
Suggested Answer: C

Wyjaśnienie

Potwierdzona odpowiedź: C (Create curated tables in a separate dataset and assign the role roles/bigquery.dataViewer)

Wyjaśnienie:
- Zasada najniższych uprawnień (Least Privilege): Zamiast dawać dostęp do głównej tabeli z surowymi danymi, tworzymy "wyselekcjonowane" (curated) widoki lub tabele zawierające tylko to, co konkretna rola musi widzieć.
- Separacja danych: Umieszczenie tych tabel w oddzielnym zbiorze danych (dataset) pozwala na łatwe zarządzanie dostępem za pomocą IAM na poziomie zbioru. Rola `roles/bigquery.dataViewer` nadaje uprawnienia tylko do odczytu danych w tym konkretnym zbiorze, co jest klasyczną implementacją zasady "need-to-know".

Dlaczego pozostałe odpowiedzi są niepoprawne:
- A. Data access logs: Logi dają wgląd w to, kto co robił, ale nie ograniczają dostępu do samych danych.
- B. Row-based access control: Choć RLS jest świetne, poleganie wyłącznie na nim przy zróżnicowanych potrzebach użytkowników (Business User vs Data Engineer) jest trudniejsze do zarządzania niż logiczna separacja datasetów.
- D. CSV file email: Wysyłanie danych mailem jest krytycznym błędem bezpieczeństwa (dane przestają być pod kontrolą platformy, nie można ich wycofać).

Wskazówki i triki (Tips & Tricks):
- "Curated data" / "Different user roles" = Separate datasets + Granular IAM.
- Nigdy nie wybieraj opcji z ręcznym przesyłaniem danych mailem (CSV/Excel).

Praktyczne informacje na egzamin:
- Zapamiętaj: IAM jest pierwszym poziomem obrony w BigQuery. RLS/CLS to warstwa dodatkowa (fine-grained control).
- Zawsze wybieraj rozwiązanie natywne wewnątrz BigQuery (IAM), a nie eksport danych na zewnątrz.

Wskazówki egzaminacyjne (Tips & Tricks)

Reguła Egzaminacyjna (Exam Rule): 
Jeśli scenariusz dotyczy zabezpieczania zasobów chmurowych (GCP), zawsze wybieraj rozwiązanie typu Managed (SCC, Secret Manager, Cloud KMS), a unikaj rozwiązań self-managed, chyba że pytanie wyraźnie wymaga dostosowania niskopoziomowego.

Haczyki egzaminacyjne (Exam Traps):
- Pułapka IAM: Pytania o uprawnienia często sugerują 'Project Owner' – zawsze szukaj 'Least Privilege' (np. 'Role: Secret Manager Secret Accessor').
- Pułapka Sieciowa: Często mylone są VPC Peering (wydajność) oraz VPN (szyfrowanie/on-premise).

Głębokie wyjaśnienie techniczne:
Rozwiązanie bazuje na GCP Shared Responsibility Model. Google zarządza bezpieczeństwem infrastruktury (Physical, Network, Host), podczas gdy administrator zarządza tożsamością (IAM), danymi (Encryption, Cloud KMS) i regułami dostępu (VPC Firewall).

Analiza i Podsumowanie (AI)

Kluczowe zagadnienia

Sugerowana odpowiedź: C

Analiza strategiczna: To pytanie testuje Twoją zdolność do projektowania separacji danych w oparciu o ich przeznaczenie. W Data Warehousing standardem jest "Curated Data Zone" (dane wyselekcjonowane). Nadanie uprawnień do konkretnego, wyselekcjonowanego zbioru danych jest najbezpieczniejszym i najprostszym sposobem na egzekwowanie zasady "Need-to-know".
