Question 208 / 361

Your organization recently activated the Security Command Center (SCC) standard tier. There are a few Cloud Storage buckets that were accidentally made accessible to the public. You need to investigate the impact of the incident and remediate it.

  • A. 1. Remove the Identity and Access Management (IAM) granting access to all Users from the buckets. 2. Apply the organization policy storage.uniformBucketLevelAccess to prevent regressions. 3. Query the data access logs to report on unauthorized access.
  • B. 1. Change permissions to limit access for authorized users. 2. Enforce a VPC Service Controls perimeter around all the production projects to immediately stop any unauthorized access. 3. Review the administrator activity audit logs to report on any unauthorized access.
  • C. 1. Change the bucket permissions to limit access. 2. Query the bucket's usage logs to report on unauthorized access to the data. 3. Enforce the organization policy storage.publicAccessPrevention to avoid regressions.
  • D. 1. Change bucket permissions to limit access. 2. Query the data access audit logs for any unauthorized access to the buckets. 3. After the misconfiguration is corrected, mute the finding in the Security Command Center.
Show Suggested Answer Hide Answer
Suggested Answer: C

Wyjaśnienie

1. Prawidłowa odpowiedź lub odpowiedzi:
C. 1. Change the bucket permissions to limit access. 2. Query the bucket's usage logs to report on unauthorized access to the data. 3. Enforce the organization policy storage.publicAccessPrevention to avoid regressions.

2. Kompleksowe wyjaśnienie dlaczego dana odpowiedź jest prawidłowa (Analiza):
Odpowiedź C jest prawidłowa, ponieważ przedstawia kompletny i zgodny z najlepszymi praktykami GCP proces reagowania na incydenty bezpieczeństwa związany z wyciekiem danych z Cloud Storage.

Etapy procesu:
a. **Natychmiastowe usunięcie zagrożenia:** Pierwszym krokiem jest zmiana uprawnień (permissions) na kubełkach, aby zablokować dostęp dla użytkowników `allUsers` lub `allAuthenticatedUsers`.
b. **Analiza powłamaniowa (Forensics):** Aby sprawdzić, czy doszło do nieuprawnionego pobrania danych, należy przeanalizować dzienniki użycia (storage usage logs / data access logs). Pozwalają one na identyfikację adresów IP, tożsamości oraz obiektów, które zostały pobrane w czasie, gdy kubełek był publiczny.
c. **Zapobieganie ponownym incydentom (Remediation/Prevention):** Wdrożenie polityki organizacji `storage.publicAccessPrevention` na poziomie projektów lub folderów trwale blokuje możliwość ustawienia jakiegokolwiek kubełka jako publicznego w przyszłości, eliminując ryzyko błędu ludzkiego.

3. Wyjaśnienie z osobna każdej niepoprawnej odpowiedzi:
A. ...Apply the organization policy storage.uniformBucketLevelAccess to prevent regressions...
   * Dlaczego nieprawidłowa: Uniform Bucket-Level Access wymusza stosowanie IAM zamiast ACL na poziomie obiektów, ale samo w sobie nie zapobiega ustawieniu kubełka jako publicznego (nadal można nadać rolę Storage Object Viewer dla `allUsers`).
B. ...Enforce a VPC Service Controls perimeter around all the production projects...
   * Dlaczego nieprawidłowa: Wdrożenie VPC Service Controls to skomplikowany proces, który chroni przed eksfiltracją danych, ale nie zapobiega bezpośrednio publicznemu udostępnianiu kubełków przez błędne konfiguracje uprawnień IAM.
D. ...After the misconfiguration is corrected, mute the finding in the Security Command Center.
   * Dlaczego nieprawidłowa: Samo wyciszenie (mute) alertu w SCC to krok kosmetyczny w konsoli i nie stanowi zabezpieczenia zapobiegającego przyszłym błędom (brak wdrożenia polityki prewencyjnej takiej jak `publicAccessPrevention`).

4. Wskazówki, hinty, tips and tricks:
* Aby trwale zabronić publicznego udostępniania jakichkolwiek kubełków Cloud Storage w organizacji/projekcie, używa się polityki organizacji **`storage.publicAccessPrevention`**.
* Śledzenie operacji odczytu/zapisu na obiektach w Cloud Storage wymaga włączenia **Data Access Audit Logs** (część Cloud Audit Logs) lub analizy **Storage Usage Logs**.

5. Reguły wyboru odpowiedzi (Słowa kluczowe):
* Blokowanie publicznego dostępu do GCS w przyszłości -> `storage.publicAccessPrevention`.

6. Dodatkowe źródła i dokumentacja:
Using public access prevention
Access logs and storage usage logs

Analiza i Podsumowanie Dyskusji (AI)

Analiza i Wyjaśnienie

Sugerowana odpowiedź: C

Głęboka analiza: To pytanie testuje procesowy aspekt bezpieczeństwa. Sama naprawa błędu to tylko połowa sukcesu. Prawdziwy inżynier bezpieczeństwa musi wiedzieć "kto wchodził" (logs) i "jak zablokować to na zawsze" (org policy). Opcja C jako jedyna domyka pełny cykl życia incydentu od naprawy przez analizę powłamaniową po trwałe zabezpieczenie.
