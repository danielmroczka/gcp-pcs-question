Question 3 / 361

A customer needs an alternative to storing their plain text secrets in their source-code management (SCM) system. How should the customer achieve this using Google Cloud Platform?

  • A. Use Cloud Source Repositories, and store secrets in Cloud SQL.
  • B. Encrypt the secrets with a Customer-Managed Encryption Key (CMEK), and store them in Cloud Storage.
  • C. Run the Cloud Data Loss Prevention API to scan the secrets, and store them in Cloud SQL.
  • D. Deploy the SCM to a Compute Engine VM with local SSDs, and enable preemptible VMs.
Show Suggested Answer Hide Answer
Suggested Answer: B

Wyjaśnienie

**Poprawna odpowiedź: B**

**1. Kompleksowe wyjaśnienie poprawnej odpowiedzi:**
Aby bezpiecznie przechowywać sekrety i klucze bez umieszczania ich w postaci jawnego tekstu (plain text) w repozytorium kodu (SCM), należy je zaszyfrować. Najlepszym z dostępnych w tym pytaniu rozwiązań jest:
- **Szyfrowanie za pomocą CMEK (Customer-Managed Encryption Keys) i przechowywanie w Cloud Storage (B):** Pozwala to na pełną kontrolę dostępu do klucza szyfrującego w Cloud KMS. Nawet jeśli ktoś uzyska dostęp do plików w Cloud Storage, nie będzie mógł odczytać sekretów bez uprawnień do odszyfrowania kluczem w KMS.

**2. Wyjaśnienie niepoprawnych odpowiedzi:**
- **A. Przechowywanie w Cloud SQL:** Zapisanie sekretów w bazie danych bez dodatkowego szyfrowania nie rozwiązuje problemu bezpieczeństwa – nadal są one przechowywane w formie jawnej, a dodatkowo generuje to narzut administracyjny bazy danych.
- **C. DLP API i Cloud SQL:** DLP API służy do skanowania i wykrywania danych wrażliwych (np. PII), a nie do bezpiecznego zarządzania i przechowywania sekretów aplikacji.
- **D. Compute Engine z lokalnymi dyskami SSD i maszynami preemptible:** Ta opcja w ogóle nie odnosi się do bezpiecznego przechowywania sekretów aplikacji i wprowadza ryzyko utraty danych (dyski SSD są czyszczone przy wyłączeniu maszyny preemptible).

**3. Wskazówki i pułapki egzaminacyjne (Tips & Tricks):**
- Uwaga historyczna: Obecnie rekomendowanym narzędziem do zarządzania sekretami w GCP jest **Secret Manager**. Pytanie to pochodzi z okresu przed jego premierą, dlatego należy wybrać "najlepszą dostępną" opcję, którą jest połączenie Cloud Storage i KMS (CMEK).
- W pytaniach o sekrety unikaj przechowywania ich w bazach danych w formie jawnej.

**4. Reguły wyboru odpowiedzi:**
- Ochrona sekretów bez dedykowanego narzędzia -> Szyfrowanie kluczem KMS + bezpieczny obiekt w GCS.

**5. Dodatkowe źródła:**
