Question 124 / 361

You are working with protected health information (PHI) for an electronic health record system. The privacy officer is concerned that sensitive data is stored in the analytics system. You are tasked with anonymizing the sensitive data in a way that is not reversible. Also, the anonymized data should not preserve the character set and length. Which Google Cloud solution should you use?

  • A. Cloud Data Loss Prevention with deterministic encryption using AES-SIV
  • B. Cloud Data Loss Prevention with format-preserving encryption
  • C. Cloud Data Loss Prevention with cryptographic hashing
  • D. Cloud Data Loss Prevention with Cloud Key Management Service wrapped cryptographic keys
Show Suggested Answer Hide Answer
Suggested Answer: C

Wyjaśnienie

Potwierdzona odpowiedź: C (Cloud Data Loss Prevention with cryptographic hashing)

Wyjaśnienie:
Haszowanie kryptograficzne (Cryptographic Hashing) w usłudze Cloud DLP to proces jednokierunkowy i nieodwracalny, co spełnia wymóg "not reversible". Ponadto funkcja ta generuje skrót o stałej długości i określonym zestawie znaków (zazwyczaj hex), który nie zachowuje formatu, długości ani zestawu znaków danych wejściowych (spełnia wymóg "do not preserve character set and length"). Pozwala to na unikalną identyfikację rekordów (np. dla potrzeb agregacji w analityce) bez ujawniania rzeczywistych danych PHI.

Dlaczego pozostałe odpowiedzi są niepoprawne:
- A: Szyfrowanie deterministyczne (Deterministic encryption) jest procesem odwracalnym (reversible) przy użyciu klucza, co jest sprzeczne z wymaganiami zadania.
- B: Szyfrowanie zachowujące format (Format-preserving encryption - FPE) jest zaprojektowane tak, aby ZACHOWAĆ długość i zestaw znaków danych wejściowych (np. numer telefonu pozostaje numerem telefonu), co wprost łamie wymóg "do not preserve".
- D: Cloud Key Management Service (KMS) służy do zarządzania kluczami szyfrującymi (owijania ich), a nie do samej metody transformacji danych (haszowania/szyfrowania) w celu anonimizacji.

Wskazówki i triki (Tips & Tricks):
- Jeśli anonimizacja ma być NIEODWRACALNA = Haszowanie (Hashing).
- Jeśli anonimizacja ma ZACHOWAĆ FORMAT = Format-Preserving Encryption (FPE).
- Jeśli anonimizacja ma być ODWRACALNA (np. tokenizacja) = Szyfrowanie (Encryption).

Praktyczne informacje na egzamin:
- Cloud DLP oferuje wiele technik de-identyfikacji: od prostego maskowania znaków, przez kategoryzację (bucketing), po zaawansowane szyfrowanie kryptograficzne.
- Wybór metody zależy od tego, czy dane muszą być później przywrócone (odwracalność) i czy systemy analityczne wymagają zachowania formatu danych.

Analiza i Podsumowanie Dyskusji (AI)

Analiza i Wyjaśnienie

Sugerowana odpowiedź: C

Głęboka analiza: W scenariuszach analitycznych dla służby zdrowia (PHI), haszowanie jest często wybierane zamiast maskowania, ponieważ pozwala na zachowanie relacji między danymi. Jeśli ten sam pacjent pojawi się w dwóch różnych zbiorach danych, po haszowaniu z użyciem tej samej soli (salt), jego rekordy będą miały ten sam identyfikator, co umożliwi ich złączenie bez naruszania prywatności.
