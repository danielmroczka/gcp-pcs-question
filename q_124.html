Question 124 / 361

You are working with protected health information (PHI) for an electronic health record system. The privacy officer is concerned that sensitive data is stored in the analytics system. You are tasked with anonymizing the sensitive data in a way that is not reversible. Also, the anonymized data should not preserve the character set and length. Which Google Cloud solution should you use?

  • A. Cloud Data Loss Prevention with deterministic encryption using AES-SIV
  • B. Cloud Data Loss Prevention with format-preserving encryption
  • C. Cloud Data Loss Prevention with cryptographic hashing
  • D. Cloud Data Loss Prevention with Cloud Key Management Service wrapped cryptographic keys
Show Suggested Answer Hide Answer
Suggested Answer: C

Wyjaśnienie

1. Prawidłowa odpowiedź lub odpowiedzi:
C. Cloud Data Loss Prevention with cryptographic hashing

2. Kompleksowe wyjaśnienie dlaczego dana odpowiedź jest prawidłowa (Analiza):
Cel to deidentyfikacja (anonymizacja) wrażliwych danych PHI w systemie analitycznym. Wymagania: proces musi być nieodwracalny (not reversible), a zanonimizowane dane nie mogą zachowywać oryginalnego zestawu znaków ani długości:
- Haszowanie kryptograficzne (Cryptographic hashing) to funkcja jednokierunkowa, co oznacza, że wygenerowanie oryginalnej wartości na podstawie skrótu (hash) jest matematycznie niewykonalne (proces jest nieodwracalny).
- Haszowanie zwraca ciąg znaków o stałej, z góry określonej długości (np. 64 znaki dla SHA-256) składający się z zapisu szesnastkowego, niezależnie od tego, czy oryginalnym tekstem był krótki wyraz, czy długie zdanie. Spełnia to warunek niezachowywania zestawu znaków i długości (does not preserve character set and length).

3. Wyjaśnienie z osobna każdej niepoprawnej odpowiedzi:
- A. Szyfrowanie deterministyczne (Deterministic encryption): Jest procesem odwracalnym (reversible). Każdy, kto posiada odpowiedni klucz kryptograficzny, może odszyfrować dane z powrotem do postaci oryginalnej.
- B. Szyfrowanie zachowujące format (Format-preserving encryption - FPE): Z definicji ma na celu zachowanie dokładnie takiego samego formatu, zestawu znaków oraz długości danych wejściowych (np. zaszyfrowany numer PESEL nadal będzie 11-cyfrową liczbą), co jest bezpośrednim zaprzeczeniem wymagań pytania.
- D. Użycie kluczy opakowanych w Cloud KMS (wrapped keys): Jest to metoda zarządzania kluczami szyfrującymi (koperta kryptograficzna), a nie metoda bezpośredniej transformacji i anonimizacji danych w Cloud DLP.

4. Wskazówki, hinty, tips and tricks:
- Jeśli proces ma być **nieodwracalny** (non-reversible) i **nie może zachowywać formatu/długości**, właściwym rozwiązaniem w Cloud DLP jest **Cryptographic Hashing**.
- Jeśli proces ma być **odwracalny** i zachowywać spójność referencyjną (np. do operacji JOIN) -> Deterministic Encryption.
- Jeśli proces ma być **odwracalny** i zachowywać format (np. dla walidacji UI) -> Format-preserving encryption (FPE).

5. Reguły wyboru odpowiedzi (Słowa kluczowe):
- Nieodwracalna anonimizacja + zmiana długości i formatu -> Cryptographic hashing.
- Odwracalna tokenizacja + zachowanie spójności referencyjnej -> Deterministic encryption.
- Zachowanie formatu danych (np. nr telefonu) -> Format-preserving encryption.

6. Dodatkowe źródła i dokumentacja:
- Cloud DLP Pseudonymization concepts: https://cloud.google.com/dlp/docs/concepts-pseudonymization
