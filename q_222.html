Question 222 / 361

Your company recently published a security policy to minimize the usage of service account keys. On-premises Windows-based applications are interacting with Google Cloud APIs. You need to implement Workload Identity Federation (WIF) with your identity provider on-premises. What should you do?

  • A. Set up a workload identity pool with your corporate Active Directory Federation Service (ADFS). Configure a rule to let principals in the pool impersonate the Google Cloud service account.
  • B. Set up a workload identity pool with your corporate Active Directory Federation Service (ADFS). Let all principals in the pool impersonate the Google Cloud service account.
  • C. Set up a workload identity pool with an OpenID Connect (OIDC) service on the same machine. Configure a rule to let principals in the pool impersonate the Google Cloud service account.
  • D. Set up a workload identity pool with an OpenID Connect (OIDC) service on the same machine. Let all principals in the pool impersonate the Google Cloud service account.
Show Suggested Answer Hide Answer
Suggested Answer: A

Wskazówki egzaminacyjne (Tips & Tricks)

Reguła Egzaminacyjna (Exam Rule): 
Jeśli scenariusz dotyczy zabezpieczania zasobów chmurowych (GCP), zawsze wybieraj rozwiązanie typu Managed (SCC, Secret Manager, Cloud KMS), a unikaj rozwiązań self-managed, chyba że pytanie wyraźnie wymaga dostosowania niskopoziomowego.

Haczyki egzaminacyjne (Exam Traps):
- Pułapka IAM: Pytania o uprawnienia często sugerują 'Project Owner' – zawsze szukaj 'Least Privilege' (np. 'Role: Secret Manager Secret Accessor').
- Pułapka Sieciowa: Często mylone są VPC Peering (wydajność) oraz VPN (szyfrowanie/on-premise).

Głębokie wyjaśnienie techniczne:
Rozwiązanie bazuje na GCP Shared Responsibility Model. Google zarządza bezpieczeństwem infrastruktury (Physical, Network, Host), podczas gdy administrator zarządza tożsamością (IAM), danymi (Encryption, Cloud KMS) i regułami dostępu (VPC Firewall).

Wyjaśnienie

Potwierdzona odpowiedź: A (Set up a workload identity pool with your corporate Active Directory Federation Service (ADFS). Configure a rule to let principals in the pool impersonate the Google Cloud service account)

Wyjaśnienie:
- Workload Identity Federation (WIF): Pozwala aplikacjom działającym poza GCP (np. on-premises z Windows) na bezpieczne uwierzytelnianie się w Google Cloud bez potrzeby zarządzania długotrwałymi kluczami (JSON).
- Integracja z ADFS: ADFS (Active Directory Federation Services) może działać jako Identity Provider (IdP) korzystający z protokołu OIDC/SAML, co jest wspierane przez WIF.
- Zasada najniższych uprawnień: Opcja A jest lepsza niż B, ponieważ nakazuje "skonfigurowanie reguły" (rule) ograniczającej dostęp, zamiast "pozwolić wszystkim" (let all principals). W bezpieczeństwie chmurowym zawsze dążymy do precyzyjnego ograniczenia dostępu – im mniej podmiotów może przejąć tożsamość konta serwisowego, tym bezpieczniej.

Dlaczego pozostałe odpowiedzi są niepoprawne:
- B. Let all principals in the pool impersonate: Jest to ryzykowne podejście, naruszające zasadę najniższych uprawnień. Każdy użytkownik lub aplikacja w zdefiniowanej puli otrzymałaby dostęp do konta serwisowego, co jest nieakceptowalne w bezpiecznym środowisku.
- C i D. OIDC service on the same machine: To rozwiązanie jest technicznie niepoprawne w kontekście federacji z korporacyjnym AD/ADFS. WIF wymaga, aby IdP (tutaj ADFS) był zaufanym dostawcą tożsamości. OIDC "na tej samej maszynie" nie rozwiązuje problemu federacji tożsamości z Active Directory.

Wskazówki i triki (Tips & Tricks):
- "Least privilege" + "Workload Identity Federation" = Ograniczona reguła (konkretne principal) zamiast "All principals".
- WIF + ADFS = Bezpieczna tożsamość hybrydowa bez kluczy.

Praktyczne informacje na egzamin:
- Zapamiętaj: WIF to "Keyless Authentication".
- Zawsze wybieraj opcje, które sugerują granulację i ograniczenia, zamiast "wszyscy mają dostęp".

Analiza i Podsumowanie (AI)

Kluczowe zagadnienia

Sugerowana odpowiedź: A

Analiza strategiczna: Pytanie sprawdza nie tylko znajomość technologii (WIF), ale też dojrzałość w zarządzaniu uprawnieniami (Least Privilege). W świecie enterprise automatyzacja nie może odbywać się kosztem bezpieczeństwa – każda konfiguracja WIF musi być precyzyjnie przycięta do potrzeb danej aplikacji.

Dodatkowe wskazówki

  • WIF wspiera mapowanie atrybutów tokena (np. grupy AD -> rola GCP).
  • Pamiętaj o monitorowaniu logów audytowych pod kątem podejrzanych prób impersonacji kont serwisowych.
