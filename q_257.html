Question 257 / 361

You are running code in Google Kubernetes Engine (GKE) containers in Google Cloud that require access to objects stored in a Cloud Storage bucket. You need to securely grant the Pods access to the bucket while minimizing management overhead. What should you do?

  • A. Create a service account. Grant bucket access to the Pods by using Workload Identity Federation for GKE.
  • B. Create a service account with keys. Store the keys in Secret Manager with a 30-day rotation schedule. Reference the keys in the Pods.
  • C. Create a service account with keys. Store the keys as a Kubernetes secret. Reference the keys in the Pods.
  • D. Create a service account with keys. Store the keys in Secret Manager. Reference the keys in the Pods.
Show Suggested Answer
Suggested Answer: A

Wyjaśnienie

Potwierdzona odpowiedź: A

**Szczegółowe wyjaśnienie:**
Prawidłowa odpowiedź to A. Kluczowym zagadnieniem w tym pytaniu jest zrozumienie natywnych mechanizmów bezpieczeństwa Google Cloud, które najlepiej adresują przedstawiony scenariusz biznesowy. Wybór tej opcji zapewnia zgodność z najlepszymi praktykami GCP w zakresie zabezpieczeń i zgodności.

**Dlaczego inne odpowiedzi są błędne:**
- Pozostałe opcje nie rozwiązują problemu w sposób zintegrowany lub wprowadzają rozwiązania, które nie są zalecane w architekturze GCP dla tego konkretnego przypadku użycia.

**Reguła Egzaminacyjna (Exam Rule):**
Zawsze szukaj usług, które oferują rozwiązanie typu "managed" lub "natively integrated" w GCP dla danego problemu bezpieczeństwa.

**Haczyki egzaminacyjne (Exam Traps):**
- Unikaj odpowiedzi sugerujących manualne konfiguracje, jeśli dostępna jest zautomatyzowana usługa GCP.

**Głębokie wyjaśnienie techniczne:**
Usługi GCP (np. VPC Service Controls, DLP) działają na poziomie API platformy, co pozwala na egzekwowanie polityk bezpieczeństwa niezależnie od konfiguracji poszczególnych zasobów.
