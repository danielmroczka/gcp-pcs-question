Question 257 / 361

You are running code in Google Kubernetes Engine (GKE) containers in Google Cloud that require access to objects stored in a Cloud Storage bucket. You need to securely grant the Pods access to the bucket while minimizing management overhead. What should you do?

  • A. Create a service account. Grant bucket access to the Pods by using Workload Identity Federation for GKE.
  • B. Create a service account with keys. Store the keys in Secret Manager with a 30-day rotation schedule. Reference the keys in the Pods.
  • C. Create a service account with keys. Store the keys as a Kubernetes secret. Reference the keys in the Pods.
  • D. Create a service account with keys. Store the keys in Secret Manager. Reference the keys in the Pods.
Show Suggested Answer Hide Answer
Suggested Answer: A

Wyjaśnienie

Poprawna odpowiedź: A (Create a service account. Grant bucket access to the Pods by using Workload Identity Federation for GKE.)

Dlaczego ta odpowiedź jest poprawna:
- Workload Identity: To najbezpieczniejszy i zalecany przez Google sposób uwierzytelniania aplikacji działających w GKE (w tym pipeline'ów CI/CD) do usług Google Cloud. Eliminuje potrzebę generowania, pobierania i przechowywania statycznych kluczy JSON kont serwisowych (Service Account Keys), które są częstym źródłem wycieków danych.
- Mapowanie Tożsamości: Workload Identity wiąże konto serwisowe Kubernetes (KSA) z kontem serwisowym Google Cloud (GSA). Dzięki temu pod działający w klastrze automatycznie otrzymuje tokeny tożsamości GSA z serwera metadanych.

Analiza niepoprawnych odpowiedzi:
- B, C, D: Wszystkie te opcje sugerują użycie ręcznie zarządzanych kluczy JSON (service account keys), co jest praktyką niebezpieczną i niezgodną z modelem "keyless" promowanym przez Workload Identity.

Wskazówki i triki (Tips & Tricks):
- "GKE" + "Access Google Cloud APIs" + "Secure" = Workload Identity.
- Jeśli widzisz "Service Account Keys" lub "JSON keys" w opcjach dla GKE, zazwyczaj jest to błędna odpowiedź.

Praktyczne informacje na egzamin:
- Zapamiętaj: Workload Identity wymaga włączenia na poziomie klastra ORAZ na poziomie puli węzłów.
- Pamiętaj o strukturze wiązania: `serviceAccount:[PROJECT_ID].svc.id.goog[[NAMESPACE]/[KSA_NAME]]`.

Analiza strategiczna: To pytanie testuje znajomość nowoczesnych standardów bezpieczeństwa kontenerów. Przejście od uprawnień "maszyny" (Node SA) do uprawnień "procesu" (Workload Identity) jest fundamentalną zmianą w architekturze chmurowej, która radykalnie podnosi poziom zabezpieczeń klastra GKE.
