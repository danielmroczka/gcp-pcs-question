Question 121 / 361

You manage your organization's Security Operations Center (SOC). You currently monitor and detect network traffic anomalies in your Google Cloud VPCs based on packet header information. However, you want the capability to explore network flows and their payload to aid investigations. Which Google Cloud product should you use?

  • A. Marketplace IDS
  • B. VPC Flow Logs
  • C. VPC Service Controls logs
  • D. Packet Mirroring
  • E. Google Cloud Armor Deep Packet Inspection
Show Suggested Answer Hide Answer
Suggested Answer: D

Wyjaśnienie

1. Prawidłowa odpowiedź lub odpowiedzi:
D. Packet Mirroring

2. Kompleksowe wyjaśnienie dlaczego dana odpowiedź jest prawidłowa (Analiza):
Wymaganiem jest uzyskanie możliwości badania nie tylko nagłówków pakietów sieciowych (metadata), ale także ich pełnej zawartości (payload) na potrzeby analizy incydentów bezpieczeństwa i eksploracji przepływów:
- Packet Mirroring w GCP klonuje (kopiuje) cały ruch sieciowy – zarówno nagłówki, jak i pełną zawartość (payload) pakietów – z wybranych instancji maszyn wirtualnych, grup instancji lub całych podsieci. Skopiowany ruch jest następnie przesyłany do kolektora (np. instancji z zainstalowanym oprogramowaniem IDS/IPS lub snifferem pakietów). Umożliwia to przeprowadzenie pełnej inspekcji (Deep Packet Inspection), co jest kluczowe w zaawansowanych śledztwach cyberbezpieczeństwa.

3. Wyjaśnienie z osobna każdej niepoprawnej odpowiedzi:
- A. Marketplace IDS: Urządzenia IDS (Intrusion Detection System) z Google Cloud Marketplace służą do analizy ruchu, ale same z siebie nie mają możliwości przechwytywania ruchu z sieci VPC. Potrzebują do działania usługi Packet Mirroring jako źródła danych.
- B. VPC Flow Logs: Rejestruje wyłącznie metadane dotyczące połączeń (IP źródłowe/docelowe, porty, liczba bajtów, czas trwania). Ze względów bezpieczeństwa i oszczędności miejsca celowo nie rejestruje zawartości (payloadu) pakietów.
- C. VPC Service Controls logs: Są to logi audytowe dotyczące naruszenia granic perymetru API usług Google, nie rejestrują one ruchu sieciowego IP pomiędzy maszynami wirtualnymi w sieci VPC.
- E. Google Cloud Armor Deep Packet Inspection: Cloud Armor nie oferuje ogólnego mechanizmu Deep Packet Inspection dla całego ruchu wewnątrz sieci VPC (działa na brzegu sieci dla Load Balancerów HTTP/HTTPS).

4. Wskazówki, hinty, tips and tricks:
- Jeśli celem jest analiza zawartości/ładunku pakietów (**payload**) w sieci VPC, jedyną natywną usługą GCP, która to umożliwia, jest **Packet Mirroring**.
- VPC Flow Logs = tylko nagłówki (no payload). Packet Mirroring = pełny pakiet (headers + payload).

5. Reguły wyboru odpowiedzi (Słowa kluczowe):
- Badanie zawartości pakietów / payload / Deep Packet Inspection -> Packet Mirroring.

6. Dodatkowe źródła i dokumentacja:
- Packet Mirroring overview: https://cloud.google.com/vpc/docs/packet-mirroring
