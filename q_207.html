Question 207 / 361

Your DevOps team uses Packer to build Compute Engine images by using this process:
1. Create an ephemeral Compute Engine VM.
2. Copy a binary from a Cloud Storage bucket to the VM's file system.
3. Update the VM's package manager.
4. Install external packages from the internet onto the VM.
Your security team just enabled the organizational policy, constraints/compute.vmExternalIpAccess, to restrict the usage of public IP Addresses on VMs. In response, your DevOps team updated their scripts to remove public IP addresses on the Compute Engine VMs; however, the build pipeline is failing due to connectivity issues.
What should you do? (Choose two.)

  • A. Provision an HTTP load balancer with the VM in an unmanaged instance group to allow inbound connections from the internet to your VM.
  • B. Provision a Cloud NAT instance in the same VPC and region as the Compute Engine VM.
  • C. Enable Private Google Access on the subnet that the Compute Engine VM is deployed within.
  • D. Update the VPC routes to allow traffic to and from the internet.
  • E. Provision a Cloud VPN tunnel in the same VPC and region as the Compute Engine VM.
Show Suggested Answer Hide Answer
Suggested Answer: BC

Wyjaśnienie

Potwierdzona odpowiedź: BC (B. Provision a Cloud NAT instance, C. Enable Private Google Access).

Wyjaśnienie:
- Kontekst: Maszyna wirtualna nie posiada publicznego adresu IP ze względu na politykę organizacji, co uniemożliwia jej domyślną komunikację z internetem oraz usługami Google.
- Cloud NAT (B): Jest niezbędny, aby maszyna mogła pobrać aktualizacje systemu (krok 3) oraz pakiety zewnętrzne z internetu (krok 4). Cloud NAT pozwala instancjom z samym prywatnym adresem IP na inicjowanie połączeń wychodzących (outbound) do internetu, przy jednoczesnym blokowaniu ruchu przychodzącego (inbound).
- Private Google Access (PGA - C): Pozwala maszynom bez publicznego adresu IP na łączenie się z publicznymi adresami IP usług Google Cloud (np. `storage.googleapis.com` w celu skopiowania binariów w kroku 2). PGA jest włączane na poziomie podsieci (subnet).

Dlaczego pozostałe odpowiedzi są niepoprawne:
- A. HTTP Load Balancer: Służy do obsługi ruchu PRZYCHODZĄCEGO (inbound) od użytkowników do aplikacji. Nie pomaga maszynie w wyjściu do internetu po paczki ani w połączeniu z Cloud Storage.
- D. Update VPC routes: Same trasy (routes) nie wystarczą, jeśli maszyna nie ma adresu IP, który jest "rozumiany" w internecie. Bez mechanizmu translacji (NAT), pakiety z prywatnym IP zostaną odrzucone przez routery brzegowe internetu.
- E. Cloud VPN: Służy do łączenia sieci VPC z siecią lokalną (on-premises). Nie zapewnia on dostępu do publicznego internetu (w celu pobrania paczek) ani nie jest standardową metodą dostępu do GCS z wewnątrz tej samej chmury.

Wskazówki egzaminacyjne (Tips & Tricks):
- "VM without public IP" + "Access internet (apt-get/yum)" = Cloud NAT.
- "VM without public IP" + "Access Google APIs (GCS/BigQuery)" = Private Google Access.
- Pamiętaj: PGA jest darmowe i włączane na podsieci. Cloud NAT jest usługą płatną i wymaga Cloud Routera.

Kluczowe zagadnienia do powtórzenia:
- Cloud NAT i Cloud Router.
- Private Google Access (PGA).
- Organization Policy: compute.vmExternalIpAccess.
