Question 207 / 361

Your DevOps team uses Packer to build Compute Engine images by using this process:
1. Create an ephemeral Compute Engine VM.
2. Copy a binary from a Cloud Storage bucket to the VM's file system.
3. Update the VM's package manager.
4. Install external packages from the internet onto the VM.
Your security team just enabled the organizational policy, constraints/compute.vmExternalIpAccess, to restrict the usage of public IP Addresses on VMs. In response, your DevOps team updated their scripts to remove public IP addresses on the Compute Engine VMs; however, the build pipeline is failing due to connectivity issues.
What should you do? (Choose two.)

  • A. Provision an HTTP load balancer with the VM in an unmanaged instance group to allow inbound connections from the internet to your VM.
  • B. Provision a Cloud NAT instance in the same VPC and region as the Compute Engine VM.
  • C. Enable Private Google Access on the subnet that the Compute Engine VM is deployed within.
  • D. Update the VPC routes to allow traffic to and from the internet.
  • E. Provision a Cloud VPN tunnel in the same VPC and region as the Compute Engine VM.
Show Suggested Answer Hide Answer
Suggested Answer: BC

Wyjaśnienie

1. Prawidłowa odpowiedź lub odpowiedzi:
B. Provision a Cloud NAT instance in the same VPC and region as the Compute Engine VM.
C. Enable Private Google Access on the subnet that the Compute Engine VM is deployed within.

2. Kompleksowe wyjaśnienie dlaczego dana odpowiedź jest prawidłowa (Analiza):
Odpowiedzi B i C są prawidłowe, ponieważ umożliwiają maszynie wirtualnej pozbawionej publicznego adresu IP komunikację z usługami zewnętrznymi (internetem) oraz wewnętrznymi API Google w bezpieczny sposób.

Analiza scenariusza:
Polityka organizacji `compute.vmExternalIpAccess` zabrania przypisywania zewnętrznych (publicznych) adresów IP do maszyn wirtualnych Compute Engine. W rezultacie maszyna budująca (Packer VM) posiada wyłącznie prywatny adres IP. Aby proces budowania obrazu zakończył się sukcesem, maszyna musi wykonać dwie operacje sieciowe:
1. **Pobrać binarki z Cloud Storage (usługa Google):** Aby maszyna z prywatnym adresem IP mogła połączyć się z API Cloud Storage bez przechodzenia przez internet, na jej podsieci musi być włączone **Private Google Access (C)**.
2. **Pobrać pakiety z repozytoriów zewnętrznych (internet):** Ponieważ repozytoria te znajdują się w publicznym internecie, maszyna potrzebuje bramki sieciowej, która przetłumaczy jej adres prywatny na publiczny. Służy do tego usługa **Cloud NAT (B)**, która pozwala instancjom bez publicznego IP inicjować bezpieczne połączenia wychodzące do internetu.

3. Wyjaśnienie z osobna każdej niepoprawnej odpowiedzi:
A. Provision an HTTP load balancer...
   * Dlaczego nieprawidłowa: Load Balancer HTTP(S) służy do dystrybucji ruchu przychodzącego (inbound) z internetu do maszyn wirtualnych. Nie pozwala on maszynie wirtualnej na inicjowanie połączeń wychodzących (outbound) do internetu, co jest wymagane do aktualizacji systemu i pobierania pakietów.
D. Update the VPC routes to allow traffic to and from the internet.
   * Dlaczego nieprawidłowa: Same trasy VPC nie rozwiążą problemu braku publicznego adresu IP. Router internetowy odrzuci pakiety z prywatnymi adresami IP (RFC 1918), jeśli nie przejdą one przez bramę NAT (Network Address Translation).
E. Provision a Cloud VPN tunnel in the same VPC and region...
   * Dlaczego nieprawidłowa: Cloud VPN służy do łączenia sieci VPC z siecią lokalną (on-premises) lub inną chmurą. Nie służy do uzyskiwania dostępu do publicznych repozytoriów oprogramowania w internecie.

4. Wskazówki, hinty, tips and tricks:
* Maszyna wirtualna bez publicznego IP w GCP:
  - Dostęp do API Google (np. Cloud Storage) -> **Private Google Access**.
  - Dostęp do ogólnego internetu (wychodzący) -> **Cloud NAT**.
* Te dwa mechanizmy są podstawą bezpiecznego projektowania sieci w chmurze (Private-only VMs).

5. Reguły wyboru odpowiedzi (Słowa kluczowe):
* VM bez publicznego IP + dostęp do usług Google -> Private Google Access.
* VM bez publicznego IP + dostęp do internetu -> Cloud NAT.
