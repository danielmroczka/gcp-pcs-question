Question 287 / 361

You work for a banking organization. You are migrating sensitive customer data to Google Cloud that is currently encrypted at rest while on-premises. There are strict regulatory requirements when moving sensitive data to the cloud. Independent of the cloud service provider, you must be able to audit key usage and be able to deny certain types of decrypt requests. You must choose an encryption strategy that will ensure robust security and compliance with the regulations. What should you do?

  • A. Utilize Google default encryption and Cloud IAM to keep the keys within your organization's control.
  • B. Implement Cloud External Key Manager (Cloud EKM) with Access Approval, to integrate with your existing on-premises key management solution.
  • C. Implement Cloud External Key Manager (Cloud EKM) with Key Access Justifications to integrate with your existing on-premises key management solution.
  • D. Utilize customer-managed encryption keys (CMEK) created in a dedicated Google Compute Engine instance with Confidential Compute encryption, under your organization's control.
Show Suggested Answer Hide Answer
Suggested Answer: C

Wskazówki egzaminacyjne (Tips & Tricks)

Reguła Egzaminacyjna (Exam Rule): 
W pytaniach typu 'Security in GCP', zawsze priorytetyzuj rozwiązania natywne (SCC, Cloud KMS, Secret Manager, VPC SC) nad rozwiązaniami typu 'third-party' lub 'self-managed', chyba że scenariusz wymaga specyficznej integracji hybrydowej.

Haczyki egzaminacyjne (Exam Traps):
- Pułapka 'Least Privilege': Egzamin często podpowiada role o szerokim zakresie (np. 'Editor' lub 'Owner') – zawsze odrzucaj je na rzecz ról predefiniowanych o najmniejszym zakresie uprawnień.
- Pułapka 'Logging vs Monitoring': Pamiętaj: Audit Logs służą do badania aktywności (Who/What/When), a Monitoring do zbierania metryk wydajnościowych.

Głębokie wyjaśnienie techniczne:
Każda architektura bezpieczeństwa w GCP powinna być projektowana w oparciu o 'Security by Default'. Oznacza to m.in. szyfrowanie w spoczynku (domyślne), tożsamość opartą na rolach (IAM) oraz pełną widoczność zapewnianą przez scentralizowane logowanie (Cloud Logging/SCC).

Wyjaśnienie

Potwierdzona odpowiedź: C (Implement Cloud External Key Manager (Cloud EKM) with Key Access Justifications to integrate with your existing on-premises key management solution.)

Wyjaśnienie:
- Cloud EKM + KAJ: To najwyższy poziom suwerenności danych w chmurze. Cloud EKM pozwala na trzymanie klucza szyfrującego poza infrastrukturą Google (w Twoim własnym HSM). Key Access Justifications (KAJ) to mechanizm, w którym każdorazowo przed użyciem klucza Google musi podać uzasadnienie (justification), które jest weryfikowane przez Twój system. Możez automatycznie odrzucać (deny) żądania, których powód nie zgadza się z Twoją polityką, co daje Ci pełną niezależność od dostawcy (CSP) i realną kontrolę.

Dlaczego pozostałe odpowiedzi są niepoprawne:
- A. Default: Klucze zarządzane przez Google – brak kontroli klienta.
- B. Access Approval: Pozwala zatwierdzić dostęp personelu Google, ale nie daje automatycznej blokady operacji kryptograficznych na poziomie polityki tak jak KAJ.
- D. CMEK + VM: To błędne połączenie usług. CMEK (Cloud KMS) jest natywną usługą GCP, nie integruje się z zewnętrznymi HSM w sposób opisany w pytaniu (EKM służy do tego celu).

Wskazówki i triki (Tips & Tricks):
- "External HSM" + "Audit key usage" + "Deny decrypt requests" = Cloud EKM (External Key Manager) + Key Access Justifications (KAJ).
- Pamiętaj: KAJ to Twój "twardy" hamulec dla dostawcy chmury.

Praktyczne informacje na egzamin:
- Zapamiętaj: EKM to najlepszy sposób na uzyskanie pełnej kontroli nad kluczami szyfrującymi (i podpisującymi), gdy prawo wymusza trzymanie ich poza chmurą.

Analiza i Podsumowanie (AI)

Kluczowe zagadnienia

Sugerowana odpowiedź: C

Analiza strategiczna: To pytanie testuje Twoją wiedzę o "pełnej suwerenności danych". Cloud EKM z KAJ to rozwiązanie dla najbardziej wymagających klientów (bankowość, obronność), którzy chcą mieć fizyczną możliwość zablokowania dostępu do danych nawet dla inżynierów dostawcy chmury.
