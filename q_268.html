Question 268 / 361

Your organization has sensitive data stored in BigQuery and Cloud Storage. You need to design a solution that provides granular and flexible control authorization to read data. What should you do?

  • A. Deidentify sensitive fields within the dataset by using data leakage protection within the Sensitive Data Protection services.
  • B. Use Cloud External Key Manager (Cloud EKM) to encrypt the data in BigQuery and Cloud Storage.
  • C. Grant identity and access management (IAM) roles and permissions to principals.
  • D. Enable server-side encryption on the data in BigQuery and Cloud Storage.
Show Suggested Answer
Suggested Answer: C

Wyjaśnienie

1. Prawidłowa odpowiedź lub odpowiedzi:
C. Grant identity and access management (IAM) roles and permissions to principals.

2. Kompleksowe wyjaśnienie dlaczego dana odpowiedź jest prawidłowa (Analiza):
Odpowiedź C jest prawidłowa, ponieważ Identity and Access Management (IAM) to fundamentalna, natywna i najbardziej elastyczna usługa w Google Cloud służąca do autoryzacji i precyzyjnego zarządzania dostępem do odczytu danych w usługach takich jak BigQuery oraz Cloud Storage.

Zalety IAM:
a. **Granularność uprawnień:** IAM pozwala na przydzielanie precyzyjnych ról (np. `roles/bigquery.dataViewer` dla odczytu tabel lub `roles/storage.objectViewer` dla pobierania plików z GCS) określonym tożsamościom (principals: użytkownicy, grupy, konta serwisowe).
b. **Elastyczność i kontrola:** Możemy ograniczyć zasięg ról do konkretnego projektu, pojedynczego kubełka lub zbioru danych (dataset), a także stosować warunki IAM (IAM Conditions), co zapewnia pełne bezpieczeństwo dostępu.

3. Wyjaśnienie z osobna każdej niepoprawnej odpowiedzi:
A. Deidentify sensitive fields within the dataset by using data leakage protection...
   * Dlaczego nieprawidłowa: Deidentyfikacja (Cloud DLP) chroni prywatność danych poprzez usuwanie lub maskowanie PII, ale sama w sobie nie jest systemem autoryzacji (authorization system) – nie kontroluje, *kto* ma prawo odpytać bazę lub pobrać pliki.
B. Use Cloud External Key Manager (Cloud EKM) to encrypt the data...
   * Dlaczego nieprawidłowa: Cloud EKM szyfruje dane w spoczynku. Szyfrowanie to usługa ochrony danych (confidentiality), ale nie zarządza uprawnieniami dostępu i prawami odczytu dla użytkowników w sposób tak elastyczny i granularny jak system IAM.
D. Enable server-side encryption on the data in BigQuery and Cloud Storage.
   * Dlaczego nieprawidłowa: Szyfrowanie po stronie serwera (Server-Side Encryption) jest domyślnie i bezwyjątkowo włączone w GCP dla wszystkich danych. Służy do ochrony przed fizyczną kradzieżą dysków, ale nie filtruje i nie autoryzuje dostępu logicznego dla użytkowników próbujących odczytać dane z poziomu API.

4. Wskazówki, hinty, tips and tricks:
* Autoryzacja i kontrola dostępu (authorization / access control) w GCP -> Zawsze używaj **Identity and Access Management (IAM)**.
* Szyfrowanie (encryption) i DLP chronią same dane, ale nie zastępują polityk autoryzacji użytkowników.

5. Reguły wyboru odpowiedzi (Słowa kluczowe):
* Granular and flexible control authorization to read data -> Grant IAM roles and permissions.
