Question 143 / 361

Your organization hosts a financial services application running on Compute Engine instances for a third-party company. The third-party company's servers that will consume the application also run on Compute Engine in a separate Google Cloud organization. You need to configure a secure network connection between the Compute Engine instances. You have the following requirements:
- The network connection must be encrypted.
- The communication between servers must be over private IP addresses.
What should you do?

  • A. Configure a Cloud VPN connection between your organization's VPC network and the third party's that is controlled by VPC firewall rules.
  • B. Configure a VPC peering connection between your organization's VPC network and the third party's that is controlled by VPC firewall rules.
  • C. Configure a VPC Service Controls perimeter around your Compute Engine instances, and provide access to the third party via an access level.
  • D. Configure an Apigee proxy that exposes your Compute Engine-hosted application as an API, and is encrypted with TLS which allows access only to the third party.
Show Suggested Answer Hide Answer
Suggested Answer: B

Wyjaśnienie

1. Prawidłowa odpowiedź lub odpowiedzi:
B. Configure a VPC peering connection between your organization's VPC network and the third party's that is controlled by VPC firewall rules.

2. Kompleksowe wyjaśnienie dlaczego dana odpowiedź jest prawidłowa (Analiza):
Należy połączyć instancje Compute Engine należące do Twojej organizacji z instancjami firmy trzeciej w osobnej organizacji Google Cloud. Wymagania: komunikacja musi być szyfrowana oraz odbywać się przy użyciu prywatnych adresów IP:
- VPC Network Peering umożliwia bezpieczne, bezpośrednie połączenie sieci VPC w różnych projektach i organizacjach Google Cloud. Ruch sieciowy odbywa się wewnątrz prywatnej sieci Google przy użyciu adresów prywatnych (Internal IP addresses).
- Co istotne, Google Cloud automatycznie szyfruje cały ruch w sieci fizycznej między maszynami wirtualnymi (VM-to-VM encryption in transit) na poziomie warstwy fizycznej/wirtualizacji, spełniając wymóg szyfrowania bez konieczności wdrażania dodatkowego oprogramowania. Zapewnia to maksymalną wydajność i niskie opóźnienia bez kosztów bramek VPN. Dostęp jest kontrolowany regułami zapory (VPC firewall rules).

3. Wyjaśnienie z osobna każdej niepoprawnej odpowiedzi:
- A. Konfiguracja połączenia Cloud VPN: Cloud VPN zapewnia szyfrowane tunele IPSec po adresach prywatnych, ale wymaga wdrożenia bram VPN, konfiguracji tras i generuje dodatkowe koszty za godzinę działania bramy oraz transfer danych. VPC Peering jest rozwiązaniem natywnym, o wyższej przepustowości i darmowym szyfrowaniu fizycznym wewnątrz infrastruktury Google.
- C. Konfiguracja perymetru VPC Service Controls z Access Level: VPC Service Controls zabezpiecza interfejsy API usług Google Cloud (np. BigQuery, Storage), a nie bezpośredni ruch sieciowy IP na poziomie maszyn wirtualnych Compute Engine.
- D. Użycie bramy Apigee z szyfrowaniem TLS: Apigee to platforma do zarządzania API. Wymagałaby wystawienia aplikacji na zewnątrz i komunikacji protokołem HTTPS (często po adresach publicznych), co nie zapewnia bezpośredniego połączenia maszyn po IP prywatnych i jest znacznie bardziej skomplikowane niż proste połączenie sieciowe.

4. Wskazówki, hinty, tips and tricks:
- Zapamiętaj: Google Cloud **automatycznie szyfruje w locie ruch między wszystkimi maszynami wirtualnymi** w sieciach VPC oraz w sieciach połączonych za pomocą VPC Peering. Z tego powodu VPC Network Peering jest bezpiecznym i szyfrowanym połączeniem hybrydowym wewnątrz GCP.
- Peering działa między różnymi organizacjami GCP bez problemu.

5. Reguły wyboru odpowiedzi (Słowa kluczowe):
- Prywatne IP + Szyfrowana komunikacja między VM w różnych projektach/org -> VPC Network Peering.
