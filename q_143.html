Question 143 / 361

Your organization hosts a financial services application running on Compute Engine instances for a third-party company. The third-party company's servers that will consume the application also run on Compute Engine in a separate Google Cloud organization. You need to configure a secure network connection between the Compute Engine instances. You have the following requirements:
- The network connection must be encrypted.
- The communication between servers must be over private IP addresses.
What should you do?

  • A. Configure a Cloud VPN connection between your organization's VPC network and the third party's that is controlled by VPC firewall rules.
  • B. Configure a VPC peering connection between your organization's VPC network and the third party's that is controlled by VPC firewall rules.
  • C. Configure a VPC Service Controls perimeter around your Compute Engine instances, and provide access to the third party via an access level.
  • D. Configure an Apigee proxy that exposes your Compute Engine-hosted application as an API, and is encrypted with TLS which allows access only to the third party.
Show Suggested Answer Hide Answer
Suggested Answer: A

Wyjaśnienie

Potwierdzona odpowiedź: A (Configure a Cloud VPN connection between your organization's VPC network and the third party's that is controlled by VPC firewall rules).

Wyjaśnienie:
Cloud VPN umożliwia bezpieczne połączenie dwóch sieci VPC (nawet w różnych organizacjach) za pomocą tunelu IPsec. Spełnia oba kluczowe wymagania zadania: ruch jest szyfrowany (protokół IPsec) oraz odbywa się za pomocą prywatnych adresów IP (RFC 1918). Jest to standardowe rozwiązanie w GCP do bezpiecznego łączenia odizolowanych środowisk różnych organizacji.

Dlaczego pozostałe są błędne:
- B. VPC Peering: Chociaż pozwala na komunikację po prywatnych adresach IP i Google szyfruje ruch wewnątrz swojej sieci, w kontekście egzaminacyjnym Cloud VPN jest wskazywany jako rozwiązanie spełniające wymóg "encrypted connection" w sposób jawny i konfigurowalny (IPsec). Peering jest częściej wybierany dla wydajności (niskie opóźnienia, wysoka przepustowość).
- C. VPC Service Controls: To rozwiązanie służy do tworzenia obwodów bezpieczeństwa (perimeters) wokół usług zarządzanych (SaaS/PaaS jak Cloud Storage czy BigQuery), a nie do nawiązywania bezpośredniej łączności sieciowej między instancjami Compute Engine.
- D. Apigee: Jest to platforma do zarządzania API. Chociaż obsługuje TLS, jest to rozwiązanie warstwy aplikacji (L7), a nie warstwy sieciowej (L3/L4), o którą pyta scenariusz dotyczący bezpośredniej komunikacji między serwerami.

Wskazówki egzaminacyjne (Tips & Tricks):
- Jeśli widzisz wymagania: "Encrypted" + "Private IP" + "Separate Organizations/Networks" -> najsilniejszym kandydatem jest Cloud VPN.
- Pamiętaj, że VPC Peering nie jest przechodni (non-transitive) – jeśli sieć A jest połączona z B, a B z C, to A nie widzi C.
- Cloud VPN zawsze wiąże się z kosztami za tunel i ruch, podczas gdy Peering jest zazwyczaj tańszy, ale oferuje mniejszą kontrolę nad "izolacją" tunelu.

Kluczowe zagadnienia do powtórzenia:
- Rodzaje Cloud VPN (HA VPN vs Classic VPN).
- Różnice między VPC Peering a Cloud VPN.
- Szyfrowanie w tranzycie (Encryption in transit) w Google Cloud.
