Question 143 / 361

Your organization hosts a financial services application running on Compute Engine instances for a third-party company. The third-party company's servers that will consume the application also run on Compute Engine in a separate Google Cloud organization. You need to configure a secure network connection between the Compute Engine instances. You have the following requirements:
- The network connection must be encrypted.
- The communication between servers must be over private IP addresses.
What should you do?

  • A. Configure a Cloud VPN connection between your organization's VPC network and the third party's that is controlled by VPC firewall rules.
  • B. Configure a VPC peering connection between your organization's VPC network and the third party's that is controlled by VPC firewall rules.
  • C. Configure a VPC Service Controls perimeter around your Compute Engine instances, and provide access to the third party via an access level.
  • D. Configure an Apigee proxy that exposes your Compute Engine-hosted application as an API, and is encrypted with TLS which allows access only to the third party.
Show Suggested Answer Hide Answer
Suggested Answer: B

Wyjaśnienie

Potwierdzona odpowiedź: B (Configure a VPC peering connection...)

Wyjaśnienie:
- Szyfrowanie: Cały ruch wewnątrz sieci Google (VPC-to-VPC) jest domyślnie szyfrowany w warstwie fizycznej (MACsec). VPC Peering w pełni spełnia wymóg "encrypted connection" bez konieczności tworzenia dodatkowych tuneli.
- Prywatne IP: Peering natywnie wspiera routing po prywatnych adresach IP (RFC 1918) między VPC.
- Wydajność: Peering jest rozwiązaniem o najniższych opóźnieniach (low latency) i najwyższej przepustowości (high bandwidth), co jest kluczowe w architekturze typu "fintech".

Dlaczego pozostałe są błędne:
- A: Cloud VPN jest rozwiązaniem "nadmiarowym" wewnątrz sieci Google. Szyfrowanie IPsec generuje niepotrzebny narzut CPU i opóźnienia, skoro sieć Google jest już bezpieczna. VPN stosuje się głównie w połączeniach hybrydowych (z on-premises).
- C: VPC Service Controls chroni przed eksfiltracją danych, ale nie służy do nawiązywania bezpośredniej łączności sieciowej między instancjami.
- D: Apigee to rozwiązanie warstwy aplikacji (L7), które służy do udostępniania API, a nie do bezpośredniego łączenia sieci serwerów (L3).

Wskazówki egzaminacyjne (Tips & Tricks):
- Jeśli wymagane jest "prywatne IP" + "wydajność" + "bezpieczeństwo wewnątrz sieci Google" -> **VPC Peering**.
- Jeśli wymagane jest "połączenie z on-premises" -> **Cloud VPN**.

Kluczowe zagadnienia do powtórzenia:
- Szyfrowanie wewnątrz sieci Google (Encryption-in-transit).
- VPC Peering vs Cloud VPN.
