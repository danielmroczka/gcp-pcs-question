Question 181 / 361

Your organization operates Virtual Machines (VMs) with only private IPs in the Virtual Private Cloud (VPC) with internet access through Cloud NAT. Everyday, you must patch all VMs with critical OS updates and provide summary reports. What should you do?

  • A. Validate that the egress firewall rules allow any outgoing traffic. Log in to each VM and execute OS specific update commands. Configure the Cloud Scheduler job to update with critical patches daily for daily updates.
  • B. Copy the latest patches to the Cloud Storage bucket. Log in to each VM, download the patches from the bucket, and install them.
  • C. Assign public IPs to VMs. Validate that the egress firewall rules allow any outgoing traffic. Log in to each VM, and configure a daily cron job to enable for OS updates at night during low activity periods.
  • D. Ensure that VM Manager is installed and running on the VMs. In the OS patch management service, configure the patch jobs to update with critical patches daily.
Show Suggested Answer Hide Answer
Suggested Answer: D

Wyjaśnienie

Potwierdzona odpowiedź: D (Ensure that VM Manager is installed and running on the VMs. In the OS patch management service, configure the patch jobs to update with critical patches daily).

Wyjaśnienie:
VM Manager to natywny zestaw narzędzi Google Cloud do zarządzania systemami operacyjnymi na instancjach Compute Engine. Jego kluczowym modułem jest OS Patch Management, który pozwala na automatyzację aktualizacji (fleet patching). Usługa ta potrafi zarządzać poprawkami krytycznymi, definiować harmonogramy oraz generować raporty podsumowujące (summary reports) stan zgodności całej floty maszyn. Co ważne, rozwiązanie to działa bezpiecznie z instancjami posiadającymi tylko prywatne adresy IP (poprzez Cloud NAT lub Private Google Access).

Dlaczego pozostałe są błędne:
- A. Manual log-in + Cloud Scheduler: Ręczne logowanie się na każdą instancję ("log in to each VM") jest niemożliwe do wykonania w skali i narusza zasady automatyzacji. Cloud Scheduler nie służy do bezpośredniego wykonywania komend w systemach operacyjnych.
- B. Copy patches to Cloud Storage: Ręczne zarządzanie poprawkami w Cloud Storage wprowadza niepotrzebny narzut operacyjny i ryzyko błędów. Nie zapewnia też wymaganych natywnych raportów podsumowujących.
- C. Assign public IPs: Przypisywanie publicznych adresów IP do prywatnych instancji tylko w celu aktualizacji drastycznie zwiększa powierzchnię ataku i jest sprzeczne z dobrą praktyką ograniczania ekspozycji na internet.

Wskazówki egzaminacyjne (Tips & Tricks):
- Słowa klucze: "patch all VMs", "summary reports", "at scale" zazwyczaj wskazują na VM Manager (OS Patch Management).
- Unikaj rozwiązań wymagających manualnych kroków na poszczególnych instancjach w zadaniach dotyczących floty maszyn.

Kluczowe zagadnienia do powtórzenia:
- Funkcje VM Manager (Patch, Inventory, Policy Management).
- Konfiguracja agenta OS Config w metadanych.
- Rola Cloud NAT i Private Google Access w dostępie do aktualizacji.

Głęboka analiza: Zadanie wymaga automatyzacji aktualizacji dla floty maszyn z prywatnymi adresami IP oraz generowania raportów. VM Manager (z usługą OS Patch Management) jest jedynym natywnym rozwiązaniem GCP, które adresuje wszystkie te potrzeby jednocześnie. Pozostałe opcje są albo niebezpieczne (publiczne IP), albo skrajnie nieefektywne (manualne logowanie).
