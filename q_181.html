Question 181 / 361

Your organization operates Virtual Machines (VMs) with only private IPs in the Virtual Private Cloud (VPC) with internet access through Cloud NAT. Everyday, you must patch all VMs with critical OS updates and provide summary reports. What should you do?

  • A. Validate that the egress firewall rules allow any outgoing traffic. Log in to each VM and execute OS specific update commands. Configure the Cloud Scheduler job to update with critical patches daily for daily updates.
  • B. Copy the latest patches to the Cloud Storage bucket. Log in to each VM, download the patches from the bucket, and install them.
  • C. Assign public IPs to VMs. Validate that the egress firewall rules allow any outgoing traffic. Log in to each VM, and configure a daily cron job to enable for OS updates at night during low activity periods.
  • D. Ensure that VM Manager is installed and running on the VMs. In the OS patch management service, configure the patch jobs to update with critical patches daily.
Show Suggested Answer Hide Answer
Suggested Answer: D

Wyjaśnienie

Poprawna odpowiedź: D (Ensure that VM Manager is installed and running on the VMs. In the OS patch management service, configure the patch jobs to update with critical patches daily)

Dlaczego ta odpowiedź jest poprawna:
- VM Manager: Jest to pakiet narzędzi w Google Cloud służący do zarządzania systemami operacyjnymi na instancjach Compute Engine. Jego częścią jest usługa OS Patch Management.
- OS Patch Management: Pozwala na automatyzację procesu patchowania całych grup maszyn (fleet patching). Możesz zdefiniować harmonogram (np. codziennie), zakres (tylko poprawki krytyczne) oraz sposób postępowania po instalacji (np. restart).
- Raportowanie: VM Manager natywnie zbiera dane o stanie maszyn i pozwala na generowanie raportów z podsumowaniem, które maszyny są "zgodne" (compliant), a które wymagają uwagi, co spełnia wymóg pytania o "summary reports".
- Skala i Prywatność: Rozwiązanie to działa doskonale z instancjami posiadającymi tylko prywatne IP (wymaga jedynie zainstalowanego agenta OS Config i dostępu do API Google, np. przez Cloud NAT lub Private Google Access).

Analiza niepoprawnych odpowiedzi:
- A. Manual log-in + Cloud Scheduler: Logowanie się ręczne na każdą maszynę ("log in to each VM") jest niemożliwe do wykonania w dużej skali i skrajnie nieefektywne. Cloud Scheduler sam w sobie nie potrafi wykonywać komend wewnątrz systemów operacyjnych VM.
- B. Copy patches to Cloud Storage: To podejście "zrób to sam" (DIY) wprowadza ogromny narzut operacyjny. Musiałbyś sam zarządzać wersjami patchy, ich bezpieczeństwem i skryptami instalacyjnymi.
- C. Assign public IPs: Przypisywanie publicznych adresów IP tylko po to, by pobrać aktualizacje, jest rażącym błędem bezpieczeństwa (zwiększa "attack surface"). Od tego służy Cloud NAT (który już jest w tym scenariuszu) lub Private Google Access.

Wskazówki i triki (Tips & Tricks):
- "Patch all VMs" + "Summary reports" = VM Manager (OS Patch Management).
- Słowo klucz "at scale" (w skali) w GCP niemal zawsze eliminuje odpowiedzi typu "log in to each VM".
- Pamiętaj: Aby VM Manager działał, agent `OS Config` musi być włączony w metadanych projektu lub instancji.

Praktyczne informacje na egzamin:
- Zapamiętaj trzy główne funkcje VM Manager: OS Patch Management, OS Inventory Management (lista zainstalowanych paczek) oraz OS Policy Management (wymuszanie konfiguracji).
- VM Manager jest darmowy dla pierwszych 100 maszyn (w momencie tworzenia tego pytania), co czyni go atrakcyjnym kosztowo.

Kluczowe zagadnienia

Sugerowana odpowiedź: D

Analiza strategiczna: To pytanie testuje Twoją wiedzę o nowoczesnych narzędziach do zarządzania flotą maszyn (Fleet Management). Google Cloud stawia na automatyzację i natywne usługi. VM Manager zastępuje stare, manualne skrypty czy zewnętrzne narzędzia (jak Ansible/Chef) w podstawowych zadaniach związanych z bezpieczeństwem systemu operacyjnego.

Dodatkowe wskazówki

  • VM Manager integruje się z Cloud Monitoring, więc możesz ustawić alerty, jeśli patchowanie się nie powiedzie.
  • Pamiętaj o uprawnieniach IAM: musisz mieć rolę `Compute OS Config Service Agent` przypisaną do konta serwisowego usługi.
