Question 264 / 361

Customers complain about error messages when they access your organization's website. You suspect that the web application firewall rules configured in Cloud Armor are too strict. You want to collect request logs to investigate what triggered the rules and blocked the traffic. What should you do?

  • A. Modify the Application Load Balancer backend and increase the log sample rate to a higher number.
  • B. Enable logging in the Application Load Balancer backend and set the log level to VERBOSE in the Cloud Armor policy.
  • C. Change the configuration of suspicious web application firewall rules in the Cloud Armor policy to preview mode.
  • D. Create a log sink with a filter for logs containing redirected_by_security_policy and set a BigQuery dataset as destination.
Show Suggested Answer
Suggested Answer: B

Wyjaśnienie

1. Prawidłowa odpowiedź lub odpowiedzi:
B. Enable logging in the Application Load Balancer backend and set the log level to VERBOSE in the Cloud Armor policy.

2. Kompleksowe wyjaśnienie dlaczego dana odpowiedź jest prawidłowa (Analiza):
Odpowiedź B jest prawidłowa, ponieważ Cloud Armor generuje szczegółowe logi dotyczące zablokowanych lub dopuszczonych żądań, a logi te są zapisywane i analizowane jako część logów powiązanego zewnętrznego Load Balancera (Application Load Balancer).

Dlaczego te kroki są konieczne:
a. **Logowanie na backendzie:** Logi Cloud Armor nie istnieją samodzielnie – są one zintegrowane z logami żądań HTTP(S) Load Balancera. Należy upewnić się, że usługa backendowa ma włączone logowanie (HTTP logging enabled).
b. **Log Level VERBOSE:** Ustawienie poziomu logowania na `VERBOSE` w polityce bezpieczeństwa Cloud Armor gwarantuje, że w logach znajdą się szczegółowe informacje na temat reguł, które zostały dopasowane (np. dopasowane sygnatury WAF, dokładna reguła, która zablokowała żądanie). Umożliwia to precyzyjną diagnostykę fałszywych alarmów (false positives).

3. Wyjaśnienie z osobna każdej niepoprawnej odpowiedzi:
A. Modify the Application Load Balancer backend and increase the log sample rate...
   * Dlaczego nieprawidłowa: Zwiększenie częstotliwości próbkowania logów (sample rate) sprawi jedynie, że będziemy zbierać więcej logów ogólnych ruchu. Nie zmieni to poziomu szczegółowości logów Cloud Armor i nie pomoże, jeśli poziom logowania w polityce nie został ustawiony na właściwy (VERBOSE) w celu diagnostyki reguł.
C. Change the configuration of suspicious web application firewall rules in the Cloud Armor policy to preview mode.
   * Dlaczego nieprawidłowa: Przełączenie reguł w tryb podglądu (preview mode) sprawi, że reguły przestaną blokować ruch (będą jedynie logować dopasowania). Pomaga to sprawdzić działanie reguł w tle, ale samo w sobie nie włącza zbierania i nie konfiguruje szczegółowości logów wymaganych do analizy przyczyn blokad dla dotychczas zgłaszanych błędów.
D. Create a log sink with a filter for logs containing redirected_by_security_policy...
   * Dlaczego nieprawidłowa: Stworzenie log sinka do BigQuery pozwala na długoterminowe analizowanie logów, ale najpierw te logi muszą zostać wygenerowane we właściwym formacie i szczegółowości na poziomie Load Balancera i Cloud Armor (co konfiguruje opcja B). Sam sink bez włączonego szczegółowego logowania będzie pusty lub niekompletny.

4. Wskazówki, hinty, tips and tricks:
* Logi Cloud Armor są częścią logów zewnętrznego Load Balancera HTTP(S).
* Aby analizować szczegóły blokad WAF (np. fałszywe alarmy) -> Ustaw log level w polityce Cloud Armor na **`VERBOSE`**.

5. Reguły wyboru odpowiedzi (Słowa kluczowe):
* Investigate blocked traffic by Cloud Armor / collect request logs -> Enable logging in ALB backend + set log level to VERBOSE in Cloud Armor.
