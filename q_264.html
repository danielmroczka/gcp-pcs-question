Question 264 / 361

Customers complain about error messages when they access your organization's website. You suspect that the web application firewall rules configured in Cloud Armor are too strict. You want to collect request logs to investigate what triggered the rules and blocked the traffic. What should you do?

  • A. Modify the Application Load Balancer backend and increase the log sample rate to a higher number.
  • B. Enable logging in the Application Load Balancer backend and set the log level to VERBOSE in the Cloud Armor policy.
  • C. Change the configuration of suspicious web application firewall rules in the Cloud Armor policy to preview mode.
  • D. Create a log sink with a filter for logs containing redirected_by_security_policy and set a BigQuery dataset as destination.
Show Suggested Answer Hide Answer
Suggested Answer: B

Wyjaśnienie

Poprawna odpowiedź: B (Enable logging in the Application Load Balancer backend and set the log level to VERBOSE in the Cloud Armor policy)

Dlaczego ta odpowiedź jest poprawna:
- ALB Request Logging: Logi Cloud Armor są dołączane do logów żądań Load Balancera (GCLB). Jeśli nie włączysz logowania na 'Backend Service' Load Balancera, nie zobaczysz dlaczego użytkownicy są blokowani. 
- Poziom logowania: Włączenie pełnego logowania (VERBOSE) dla polityki Cloud Armor pozwala na zarejestrowanie szczegółów żądania, w tym identyfikatora reguły (Security Policy Rule ID), która doprowadziła do odrzucenia (DENY) połączenia. Bez tego wglądu, debugowanie "zbyt restrykcyjnych" reguł jest niemożliwe.

Analiza niepoprawnych odpowiedzi:
- A. Log sample rate: Zwiększenie częstotliwości próbkowania logów pomoże tylko wtedy, gdy logowanie jest już włączone. Sam parametr próbkowania nie aktywuje logowania szczegółów reguł Armor.
- C. Preview mode: Służy do testowania NOWYCH reguł (czy czegoś nie zablokują), a nie do badania przyczyn blokowania ruchu przez reguły JUŻ DZIAŁAJĄCE (aktywne).
- D. Log sink: Log sink służy do eksportu logów (np. do BigQuery/PubSub), ale nie generuje samych logów w źródle (Load Balancer/Cloud Armor). Jeśli nie włączysz logowania na poziomie backendu, nie będzie czego eksportować.

Wskazówki i triki (Tips & Tricks):
- "Troubleshoot blocked traffic" + "Cloud Armor" = Włącz logowanie na Backend Service (Load Balancer).
- "Why was it blocked?" = Szukaj pola `enforcedSecurityPolicy` w logach Load Balancera.

Praktyczne informacje na egzamin:
- Zapamiętaj: Logi Cloud Armor są ściśle powiązane z logami Load Balancera. Nie analizujesz ich oddzielnie.

Kluczowe zagadnienia

Sugerowana odpowiedź: B

Analiza strategiczna: To pytanie testuje Twoją zdolność do diagnozowania problemów bezpieczeństwa w usługach zarządzanych. Cloud Armor to potężne narzędzie, ale bez odpowiedniego wglądu w logi (visibility) staje się "czarną skrzynką". Kluczem dla inżyniera bezpieczeństwa jest poprawne skonfigurowanie logowania w momencie wdrożenia, aby w razie awarii szybko zidentyfikować przyczynę blokady.
