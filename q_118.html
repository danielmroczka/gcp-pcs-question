Question 118 / 361

You need to set up two network segments: one with an untrusted subnet and the other with a trusted subnet. You want to configure a virtual appliance such as a next-generation firewall (NGFW) to inspect all traffic between the two network segments. How should you design the network to inspect the traffic?

  • A. 1. Set up one VPC with two subnets: one trusted and the other untrusted. 2. Configure a custom route for all traffic (0.0.0.0/0) pointed to the virtual appliance.
  • B. 1. Set up one VPC with two subnets: one trusted and the other untrusted. 2. Configure a custom route for all RFC1918 subnets pointed to the virtual appliance.
  • C. 1. Set up two VPC networks: one trusted and the other untrusted, and peer them together. 2. Configure a custom route on each network pointed to the virtual appliance.
  • D. 1. Set up two VPC networks: one trusted and the other untrusted. 2. Configure a virtual appliance using multiple network interfaces, with each interface connected to one of the VPC networks.
Show Suggested Answer Hide Answer
Suggested Answer: D

Wyjaśnienie

1. Prawidłowa odpowiedź lub odpowiedzi:
D. 1. Set up two VPC networks: one trusted and the other untrusted. 2. Configure a virtual appliance using multiple network interfaces, with each interface connected to one of the VPC networks.

2. Kompleksowe wyjaśnienie dlaczego dana odpowiedź jest prawidłowa (Analiza):
Wymaganiem jest wdrożenie wirtualnego urządzenia zabezpieczającego (np. zapory NGFW), które będzie analizować cały ruch sieciowy przechodzący pomiędzy dwoma segmentami (zaufanym i niezaufanym):
- Aby wirtualne urządzenie mogło skutecznie filtrować ruch sieciowy i zapobiegać bezpośredniemu obchodzeniu zabezpieczeń, segmenty sieciowe muszą być fizycznie odizolowane. Najlepszym rozwiązaniem w GCP jest stworzenie dwóch odrębnych sieci VPC (trusted i untrusted).
- Wirtualne urządzenie (VM) jest uruchamiane jako instancja wielointerfejsowa (Multi-NIC VM). Jeden interfejs sieciowy (np. nic0) jest podłączony do sieci untrusted VPC, a drugi (nic1) do sieci trusted VPC. W ten sposób ruch nie może przepływać bezpośrednio z jednej sieci do drugiej z pominięciem maszyny NGFW, co wymusza inspekcję każdego pakietu na poziomie appliance.

3. Wyjaśnienie z osobna każdej niepoprawnej odpowiedzi:
- A i B. Umieszczenie obu podsieci w tej samej sieci VPC i kierowanie ruchu trasami: W obrębie jednej sieci VPC ruch pomiędzy podsieciami (nawet zaufaną i niezaufaną) jest kierowany automatycznie za pomocą lokalnej, nieusuwalnej trasy systemowej (subnet route). Nie można jej nadpisać trasami użytkownika (Custom Routes) w taki sposób, aby zmusić ruch wewnętrzny do przejścia przez wirtualne urządzenie.
- C. Połączenie sieci VPC za pomocą Peeringu (VPC Network Peering): Peering sieci automatycznie wymienia bezpośrednie trasy routingu między nimi. Po zestawieniu peeringu ruch będzie płynął optymalną, bezpośrednią ścieżką z pominięciem wirtualnego urządzenia.

4. Wskazówki, hinty, tips and tricks:
- W chmurach publicznych (w tym GCP), aby filtrować ruch za pomocą NGFW (np. Palo Alto, Fortinet) pomiędzy dwoma strefami, należy użyć **architektury wielo-VPC** (multi-VPC) oraz maszyn wirtualnych z wieloma kartami sieciowymi (**Multi-NIC VMs**).
- Każdy interfejs sieciowy maszyny VM musi być podłączony do innej sieci VPC.

5. Reguły wyboru odpowiedzi (Słowa kluczowe):
- Inspekcja ruchu przez NGFW/Appliance -> Odrębne sieci VPC + Multi-NIC VM (multiple network interfaces).

6. Dodatkowe źródła i dokumentacja:
- Multiple network interfaces overview: https://cloud.google.com/vpc/docs/multiple-network-interfaces-overview
