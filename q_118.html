Question 118 / 361

You need to set up two network segments: one with an untrusted subnet and the other with a trusted subnet. You want to configure a virtual appliance such as a next-generation firewall (NGFW) to inspect all traffic between the two network segments. How should you design the network to inspect the traffic?

  • A. 1. Set up one VPC with two subnets: one trusted and the other untrusted. 2. Configure a custom route for all traffic (0.0.0.0/0) pointed to the virtual appliance.
  • B. 1. Set up one VPC with two subnets: one trusted and the other untrusted. 2. Configure a custom route for all RFC1918 subnets pointed to the virtual appliance.
  • C. 1. Set up two VPC networks: one trusted and the other untrusted, and peer them together. 2. Configure a custom route on each network pointed to the virtual appliance.
  • D. 1. Set up two VPC networks: one trusted and the other untrusted. 2. Configure a virtual appliance using multiple network interfaces, with each interface connected to one of the VPC networks.
Show Suggested Answer Hide Answer
Suggested Answer: D

Wyjaśnienie

Potwierdzona odpowiedź: D (1. Set up two VPC networks: one trusted and the other untrusted. 2. Configure a virtual appliance using multiple network interfaces, with each interface connected to one of the VPC networks.)

Wyjaśnienie:
- Architektura Multi-NIC: Jest to standardowy i zalecany wzorzec projektowy dla urządzeń typu "virtual appliance" (np. firewalli NGFW, systemów IDS/IPS) w Google Cloud. Maszyna VM działająca jako urządzenie posiada interfejsy sieciowe (NIC) w dwóch różnych sieciach VPC.
- Separacja ruchu: Jedna sieć VPC działa jako strefa "niezaufana" (np. ruch z internetu), a druga jako "zaufana" (zasoby wewnętrzne). Dzięki temu, że sieci te są od siebie odizolowane, ruch nie może przepływać między nimi bezpośrednio.
- Inspekcja: Cały ruch musi zostać przetworzony przez system operacyjny urządzenia wirtualnego, który decyduje o jego przepuszczeniu lub zablokowaniu, zapewniając pełną inspekcję (L7, deep packet inspection).

Dlaczego pozostałe są błędne:
- A i B: W ramach jednej sieci VPC podsieci (subnets) komunikują się ze sobą bezpośrednio za pomocą domyślnego routingu. Próba wymuszenia przejścia przez appliance wewnątrz tej samej sieci jest znacznie trudniejsza (wymaga skomplikowanych tras statycznych i Policy Based Routing) i mniej bezpieczna niż izolacja na poziomie osobnych sieci VPC.
- C: VPC Peering łączy sieci bezpośrednio na poziomie kontroli ruchu Google Cloud, co powoduje, że ruch omija urządzenie wirtualne, chyba że zastosowano by bardzo specyficzne konfiguracje, które są mniej stabilne i wydajne niż model z wieloma interfejsami (Multi-NIC).

Wskazówki egzaminacyjne (Tips & Tricks):
- "Inspect traffic between segments" + "NGFW/Appliance" = Model z wieloma sieciami VPC i maszynami Multi-NIC.
- Pamiętaj: w GCP maszyna VM nie może mieć wielu interfejsów w tej samej sieci VPC. Każdy interfejs musi należeć do innej sieci.

Kluczowe zagadnienia do powtórzenia:
- Multiple Network Interfaces (Multi-NIC) w Compute Engine.
- Projektowanie bezpiecznych sieci Hub-and-Spoke.
- Ograniczenia routingu wewnątrz VPC.

Dokumentacja:
- Konfiguracje z wieloma interfejsami sieciowymi
