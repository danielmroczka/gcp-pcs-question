Question 261 / 361

Your organization utilizes Cloud Run services within multiple projects underneath the non-production folder which requires primarily internal communication. Some services need external access to approved fully qualified domain names (FQDN) while other external traffic must be blocked. Internal applications must not be exposed. You must achieve this granular control with allowlists overriding broader restrictions only for designated VPCs. What should you do?

  • A. Implement a global-level allowlist rule for the necessary FQDNs within a hierarchical firewall policy. Apply this policy across all VPCs in the organization and configure Cloud NAT without any additional filtering.
  • B. Create a folder-level deny-all rule for outbound traffic within a hierarchical firewall policy. Define FQDN allowlist rules in separate policies and associate them with the necessary VPCs. Configure Cloud NAT for these VPCs.
  • C. Create a project-level deny-all rule within a hierarchical structure and apply it broadly. Override this rule with separate FQDN allowlists defined in VPC-level firewall policies associated with the relevant VPCs.
  • D. Configure Cloud NAT with IP-based filtering to permit outbound traffic only to the allowlisted FQDNs' IP ranges. Apply Cloud NAT uniformly to all VPCs within the organization's folder structure.
Show Suggested Answer Hide Answer
Suggested Answer: B

Wyjaśnienie

Poprawna odpowiedź: B (Create a folder-level deny-all rule for outbound traffic within a hierarchical firewall policy. Define FQDN allowlist rules in separate policies and associate them with the necessary VPCs. Configure Cloud NAT for these VPCs.)

Dlaczego ta odpowiedź jest poprawna:
- Hierarchiczne polityki firewalla (Hierarchical Firewall Policies): Pozwalają na definiowanie i wymuszanie reguł na poziomie całej organizacji lub folderów. Są one sprawdzane PRZED tradycyjnymi regułami firewalla VPC w poszczególnych projektach, co czyni je doskonałymi "barierami ochronnymi" (guardrails).
- Kontrola na poziomie folderu: Zastosowanie polityki na poziomie folderu pozwala objąć nią wszystkie projekty wewnątrz folderu, co zapewnia spójność bez ręcznej konfiguracji w każdym projekcie osobno.
- FQDN Allowlists: Cloud Firewall Enterprise pozwala na filtrowanie ruchu wychodzącego (egress) na podstawie nazw domenowych (FQDN), co jest bezpieczniejsze i łatwiejsze w utrzymaniu niż zarządzanie listami IP.

Analiza niepoprawnych odpowiedzi:
- A. Global-level allowlist: Nie pozwala na rozróżnienie między różnymi sieciami VPC, co jest wymagane w scenariuszu.
- C. Project-level: Niezarządzalne przy dużej skali projektów serverless.
- D. Cloud NAT: Ma ograniczone funkcje filtrowania FQDN w porównaniu do dedykowanych polityk firewall klasy Enterprise.

Wskazówki i triki (Tips & Tricks):
- "Manage/Enforce on folder level" + "Limited egress" = Hierarchical Firewall Policies.
- "Minimize effort" = Zawsze polityki hierarchiczne (Folder/Org) zamiast ręcznego konfigurowania w projektach.

Praktyczne informacje na egzamin:
- Zapamiętaj: Reguły hierarchiczne "wygrywają" z regułami projektowymi.
- Zrozum akcje: `allow`, `deny`, `goto_next`.

Analiza strategiczna: To pytanie testuje Twoją znajomość centralizacji bezpieczeństwa. W dużych organizacjach musisz narzucać standardy, których zespoły nie mogą ominąć. Hierarchiczne polityki firewalla to narzędzie, które pozwala administratorowi bezpieczeństwa (na poziomie folderu) zablokować "wyjście" całego środowiska, jednocześnie pozwalając na konkretne, dozwolone wyjątki.
