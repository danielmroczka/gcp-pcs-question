Question 261 / 361

Your organization utilizes Cloud Run services within multiple projects underneath the non-production folder which requires primarily internal communication. Some services need external access to approved fully qualified domain names (FQDN) while other external traffic must be blocked. Internal applications must not be exposed. You must achieve this granular control with allowlists overriding broader restrictions only for designated VPCs. What should you do?

  • A. Implement a global-level allowlist rule for the necessary FQDNs within a hierarchical firewall policy. Apply this policy across all VPCs in the organization and configure Cloud NAT without any additional filtering.
  • B. Create a folder-level deny-all rule for outbound traffic within a hierarchical firewall policy. Define FQDN allowlist rules in separate policies and associate them with the necessary VPCs. Configure Cloud NAT for these VPCs.
  • C. Create a project-level deny-all rule within a hierarchical structure and apply it broadly. Override this rule with separate FQDN allowlists defined in VPC-level firewall policies associated with the relevant VPCs.
  • D. Configure Cloud NAT with IP-based filtering to permit outbound traffic only to the allowlisted FQDNs' IP ranges. Apply Cloud NAT uniformly to all VPCs within the organization's folder structure.
Show Suggested Answer
Suggested Answer: B

Wyjaśnienie

1. Prawidłowa odpowiedź lub odpowiedzi:
B. Create a folder-level deny-all rule for outbound traffic within a hierarchical firewall policy. Define FQDN allowlist rules in separate policies and associate them with the necessary VPCs. Configure Cloud NAT for these VPCs.

2. Kompleksowe wyjaśnienie dlaczego dana odpowiedź jest prawidłowa (Analiza):
Odpowiedź B jest prawidłowa, ponieważ łączy centralne zarządzanie bezpieczeństwem sieciowym na poziomie folderu z granularną kontrolą FQDN (Fully Qualified Domain Name) na poziomie poszczególnych sieci VPC, co pozwala na bezpieczną i wysoce kontrolowaną komunikację wychodzącą.

Mechanizm działania:
a. **Folder-level deny-all (Blokada centralna):** Polityka hierarchiczna przypisana na poziomie folderu z regułą blokującą cały ruch wychodzący (deny egress) gwarantuje, że domyślnie żadna maszyna/usługa w żadnym podrzędnym projekcie nie połączy się z internetem.
b. **FQDN allowlist (Granularne wyjątki):** Definiujemy osobne polityki zapory sieciowej z regułami zezwalającymi na ruch wychodzący wyłącznie do zatwierdzonych domen (np. `*.api.company.com`). Powiązanie tych polityk z konkretnymi sieciami VPC pozwala na precyzyjne odblokowanie dostępu tylko tam, gdzie to konieczne.
c. **Cloud NAT:** Umożliwia maszynom wewnątrz prywatnych sieci VPC na bezpieczną komunikację wychodzącą bez posiadania publicznych adresów IP.

3. Wyjaśnienie z osobna każdej niepoprawnej odpowiedzi:
A. Implement a global-level allowlist rule... Apply this policy across all VPCs...
   * Dlaczego nieprawidłowa: Zastosowanie jednej globalnej listy dopuszczeń (allowlist) dla wszystkich sieci VPC łamie zasadę najmniejszych uprawnień. Usługi w niektórych projektach otrzymałyby dostęp do domen, których nie potrzebują.
C. Create a project-level deny-all rule within a hierarchical structure...
   * Dlaczego nieprawidłowa: Polityki hierarchiczne zapory sieciowej nie są tworzone na poziomie "projektu" – są one tworzone na poziomie folderów lub organizacji w celu zarządzania wieloma projektami. Poziom projektu służy do lokalnych reguł VPC Firewall, które nie mają struktury hierarchicznej zapory.
D. Configure Cloud NAT with IP-based filtering to permit outbound traffic only to the allowlisted FQDNs' IP ranges.
   * Dlaczego nieprawidłowa: Standardowy Cloud NAT nie posiada wbudowanych funkcji głębokiej inspekcji pakietów do filtrowania ruchu na podstawie nazw domenowych (FQDN). Wymaga to użycia Secure Web Proxy lub zaawansowanych reguł zapory sieciowej. Ponadto, samo IP-based filtering jest nieskuteczne dla nowoczesnych usług chmurowych, których adresy IP zmieniają się dynamicznie (np. CDN).

4. Wskazówki, hinty, tips and tricks:
* Aby zablokować ruch wychodzący dla wielu projektów i pozwolić tylko na wybrane FQDN dla konkretnych sieci -> Połącz **Hierarchical Firewall Policy (deny egress)** z **FQDN rules / Cloud NAT** na poziomie wybranych VPC.
* Filtrowanie po nazwach FQDN chroni przed ominięciem reguł przez dynamicznie zmieniające się adresy IP.

5. Reguły wyboru odpowiedzi (Słowa kluczowe):
* Granular outbound FQDN control + deny-all folder level -> Folder-level deny-all in hierarchical firewall policy + FQDN allowlist on VPC level.
