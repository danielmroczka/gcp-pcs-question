Question 251 / 361

Your organization has a centralized identity provider that is used to manage human and machine access. You want to leverage this existing identity management system to enable on-premises applications to access Google Cloud without hard coded credentials. What should you do?

  • A. Enable Secure Web Proxy. Create a proxy subnet for each region that Secure Web Proxy will be deployed. Deploy an SSL certificate to Certificate Manager. Create a Secure Web Proxy policy and rules that allow access to Google Cloud services.
  • B. Enable Workforce Identity Federation. Create a workforce identity pool and specify the on-premises identity provider as a workforce identity pool provider. Create an attribute mapping to map the on-premises identity provider token to a Google STS token. Create an IAM binding that binds the required role(s) to the external identity by specifying the project ID, workload identity pool, and attribute that should be matched.
  • C. Enable Identity-Aware Proxy (IAP). Configure IAP by specifying the groups and service accounts that should have access to the application. Grant these identities the IAP-secured web app user role.
  • D. Enable Workload Identity Federation. Create a workload identity pool and specify the on-premises identity provider as a workload identity pool provider. Create an attribute mapping to map the on-premises identity provider token to a Google STS token. Create a service account with the necessary permissions for the workload. Grant the external identity the Workload Identity user role on the service account.
Show Suggested Answer
Suggested Answer: D

Wyjaśnienie

1. Prawidłowa odpowiedź lub odpowiedzi:
D. Enable Workload Identity Federation. Create a workload identity pool and specify the on-premises identity provider as a workforce identity pool provider. Create an attribute mapping to map the on-premises identity provider token to a Google STS token. Create a service account with the necessary permissions for the workload. Grant the external identity the Workload Identity user role on the service account.

2. Kompleksowe wyjaśnienie dlaczego dana odpowiedź jest prawidłowa (Analiza):
Odpowiedź D jest prawidłowa, ponieważ Workload Identity Federation (WIF) jest oficjalnym i najbezpieczniejszym mechanizmem Google Cloud do nadawania tożsamości aplikacjom i obciążeniom działającym poza GCP (on-premises) bez konieczności generowania i zarządzania kluczami długoterminowymi (pliki JSON kont serwisowych).

Zasada działania WIF:
a. **Brak kluczy:** Aplikacje on-premises uwierzytelniają się w swoim lokalnym IdP (np. Active Directory, Okta, Kubernetes), uzyskując token OIDC lub SAML.
b. **Wymiana tokenów:** Aplikacja przesyła ten zewnętrzny token do Google Security Token Service (STS). STS weryfikuje token u skonfigurowanego dostawcy w puli (Workload Identity Pool Provider).
c. **Mapowanie atrybutów:** STS mapuje roszczenia (claims) z zewnętrznego tokena na atrybuty Google Cloud.
d. **Impersonacja konta serwisowego:** Na podstawie mapowania, STS wydaje tymczasowy, krótkotrwały token dostępu OAuth 2.0 dla przypisanego konta serwisowego GCP (`Workload Identity User`). Aplikacja wykonuje operacje w GCP za pomocą tego bezpiecznego, tymczasowego tokena.

3. Wyjaśnienie z osobna każdej niepoprawnej odpowiedzi:
A. Enable Secure Web Proxy... Create a proxy subnet... Create a Secure Web Proxy policy...
   * Dlaczego nieprawidłowa: Secure Web Proxy (SWP) to usługa służąca do filtrowania i zabezpieczania wychodzącego ruchu internetowego (egress HTTP/S) z zasobów chmurowych GCP. Nie służy do uwierzytelniania i autoryzacji aplikacji lokalnych (on-premises) próbujących uzyskać dostęp do usług w chmurze GCP bez kluczy.
B. Enable Workforce Identity Federation... Create a workforce identity pool...
   * Dlaczego nieprawidłowa: Workforce Identity Federation służy do uwierzytelniania ludzi (pracowników, kontrahentów) w celu uzyskania dostępu do konsoli GCP lub CLI za pomocą zewnętrznego IdP. Pytanie dotyczy dostępu dla maszyn / aplikacji (on-premises applications), do czego służy wyłącznie **Workload** Identity Federation (WIF).
C. Enable Identity-Aware Proxy (IAP). Configure IAP by specifying the groups...
   * Dlaczego nieprawidłowa: IAP służy do zabezpieczania dostępu użytkowników do aplikacji webowych lub SSH/RDP działających w GCP. Nie rozwiązuje problemu autoryzacji i bezpiecznego wywoływania API Google Cloud (np. Cloud Storage, BigQuery) przez lokalne aplikacje automatyczne bez wpisanych na stałe kluczy.

4. Wskazówki, hinty, tips and tricks:
* Uwierzytelnianie bez kluczy (keyless authentication) dla zewnętrznych zasobów:
  - Użytkownicy (ludzie) -> **Workforce Identity Federation**.
  - Aplikacje / Serwery (maszyny) -> **Workload Identity Federation**.
* WIF eliminuje potrzebę generowania i przechowywania niebezpiecznych plików kluczy JSON.

5. Reguły wyboru odpowiedzi (Słowa kluczowe):
* On-premises applications + access Google Cloud + without hardcoded credentials -> Workload Identity Federation (WIF).
