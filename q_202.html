Question 202 / 361

Your Google Cloud organization allows for administrative capabilities to be distributed to each team through provision of a Google Cloud project with Owner role (roles/owner). The organization contains thousands of Google Cloud projects. Security Command Center Premium has surfaced multiple OPEN_MYSQL_PORT findings. You are enforcing the guardrails and need to prevent these types of common misconfigurations.

  • A. Create a hierarchical firewall policy configured at the organization to deny all connections from 0.0.0.0/0.
  • B. Create a hierarchical firewall policy configured at the organization to allow connections only from internal IP ranges.
  • C. Create a Google Cloud Armor security policy to deny traffic from 0.0.0.0/0.
  • D. Create a firewall rule for each virtual private cloud (VPC) to deny traffic from 0.0.0.0/0 with priority 0.
Show Suggested Answer Hide Answer
Suggested Answer: B

Wyjaśnienie

1. Prawidłowa odpowiedź lub odpowiedzi:
B. Create a hierarchical firewall policy configured at the organization to allow connections only from internal IP ranges.

2. Kompleksowe wyjaśnienie dlaczego dana odpowiedź jest prawidłowa (Analiza):
Odpowiedź B jest prawidłowa, ponieważ pozwala na wdrożenie nadrzędnych reguł bezpieczeństwa (guardrails) na poziomie całej organizacji, które automatycznie blokują lub ograniczają dostęp sieciowy dla wszystkich podrzędnych sieci VPC. 

Kluczowe cechy tego podejścia:
a. **Polityki hierarchiczne zapory sieciowej (Hierarchical Firewall Policies):** Pozwalają one na tworzenie i egzekwowanie reguł zapory sieciowej na poziomie Organizacji lub Folderów. Reguły te są oceniane przed jakimikolwiek regułami zapory sieciowej zdefiniowanymi w konkretnych sieciach VPC przez lokalne zespoły projektowe.
b. **Ograniczenie do wewnętrznych adresów IP:** Tworząc regułę, która zezwala na dostęp do portów MySQL (domyślnie 3306) tylko z zaufanych, wewnętrznych zakresów IP (np. RFC 1918), a w przeciwnym razie blokuje ruch z zewnątrz, skutecznie neutralizujemy zagrożenie wystawienia MySQL na świat, niezależnie od tego, co lokalni administratorzy (posiadający rolę Owner) ustawią w swoich projektach. Zapobiega to powstawaniu alertów `OPEN_MYSQL_PORT`.

3. Wyjaśnienie z osobna każdej niepoprawnej odpowiedzi:
A. Create a hierarchical firewall policy configured at the organization to deny all connections from 0.0.0.0/0.
   * Dlaczego nieprawidłowa: Zablokowanie WSZYSTKICH połączeń z adresu 0.0.0.0/0 na poziomie organizacji całkowicie odcięłoby cały ruch przychodzący z internetu do wszystkich aplikacji w organizacji, co uniemożliwiłoby działanie jakichkolwiek publicznych usług webowych.
C. Create a Google Cloud Armor security policy to deny traffic from 0.0.0.0/0.
   * Dlaczego nieprawidłowa: Cloud Armor działa na poziomie zewnętrznych Load Balancerów HTTP(S) i TCP/SSL proxy. Nie chroni bezpośrednio instancji bazodanowych MySQL w sieci VPC, które mogą mieć przypisane publiczne adresy IP i być wystawione bezpośrednio przez reguły zapory sieciowej VPC.
D. Create a firewall rule for each virtual private cloud (VPC) to deny traffic from 0.0.0.0/0 with priority 0.
   * Dlaczego nieprawidłowa: Wymagałoby to ręcznego lub skryptowego tworzenia reguł w tysiącach projektów, co jest podatne na błędy. Ponadto właściciele projektów (Owners) posiadają pełne uprawnienia i mogliby te reguły usunąć lub zmodyfikować.

4. Wskazówki, hinty, tips and tricks:
* Aby zapobiec miskonfiguracjom robionym przez administratorów projektów (np. Ownerów), zawsze stosuje się mechanizmy nadrzędne, których nie mogą modyfikować. W kwestiach sieciowych są to **Hierarchical Firewall Policies**.
* Właściciel projektu (Owner) nie ma uprawnień do modyfikowania reguł zapory sieciowej przypisanych na poziomie organizacji lub folderu.

5. Reguły wyboru odpowiedzi (Słowa kluczowe):
* Narzucenie centralnych ograniczeń zapory sieciowej w skali całej organizacji -> Hierarchical firewall policy.
