You manage a Google Cloud organization with many projects located in various regions around the world. The projects are protected by the same Access Context Manager access policy. You created a new folder that will host two projects that process protected health information (PHI) for US-based customers. The two projects will be separately managed and require stricter protections. You are setting up the VPC Service Controls configuration for the new folder. You must ensure that only US-based personnel can access these projects and restrict Google Cloud API access to only BigQuery and Cloud Storage within these projects. What should you do?

  • A. Create a scoped access policy, add the new folder under "Select resources to include in the policy," and assign an administrator under "Manage principals." For the service perimeter, specify the two new projects as "Resources to protect" in the service perimeter configuration. Set "Restricted services" to "all services," set "VPC accessible services" to "Selected services," and specify only BigQuery and Cloud Storage under "Selected services."
  • B. Enable Identity Aware Proxy in the new projects. Create an Access Context Manager access level with an "IP Subnetworks" attribute condition set to the US-based corporate IP range. Enable the "Restrict Resource Service Usage" organization policy at the new folder level with an "Allow" policy type and set both "storage.googleapis.com" and "bigquery.googleapis.com" under "Custom values."
  • C. Edit the organization-level access policy and add the new folder under "Select resources to include in the policy." Specify the two new projects as "Resources to protect" in the service perimeter configuration. Set "Restricted services" to "all services," set "VPC accessible services" to "Selected services," and specify only BigQuery and Cloud Storage. Edit the existing access level to add a "Geographic locations" condition set to "US."
  • D. Configure a Cloud Interconnect connection or a Virtual Private Network (VPN) between the on-premises environment and the Google Cloud organization. Configure the VPC firewall policies within the new projects to only allow connections from the on-premises IP address range. Enable the Restrict Resource Service Usage organization policy on the new folder with an "Allow" policy type, and set both "storage.googleapis.com" and "bigquery.googleapis.com" under "Custom values."

Suggested Answer: A

Wyjaśnienie

Potwierdzona odpowiedź: A (Create a scoped access policy, add the new folder under "Select resources to include in the policy," and assign an administrator under "Manage principals." For the service perimeter, specify the two new projects as "Resources to protect" in the service perimeter configuration. Set "Restricted services" to "all services," set "VPC accessible services" to "Selected services," and specify only BigQuery and Cloud Storage under "Selected services.")

Wyjaśnienie:
- Scoped Access Policy: Jest to mechanizm, który pozwala na odizolowanie zarządzania polityką dostępu (Access Policy) dla określonych zasobów (w tym przypadku folderu z projektami PHI). Jest to najlepsza praktyka dla "stricter protections".
- VPC Service Controls: Mechanizm chroniący zasoby przed eksfiltracją.
- VPC Accessible Services: Funkcja ta pozwala na ograniczenie dostępu do usług Google Cloud wewnątrz perymetru tylko do wybranych API (w tym przypadku BigQuery i GCS). To drastycznie zmniejsza powierzchnię ataku.

Dlaczego pozostałe odpowiedzi są niepoprawne:
- B, C, D: Żadna z tych opcji nie realizuje wymogu BLOKADY API na poziomie sieciowym tak precyzyjnie jak VPC Service Controls w połączeniu z funkcją "VPC accessible services". Org Policy (B, D) blokuje tylko włączenie usługi, ale nie blokuje DOSTĘPU do API, jeśli usługa jest już włączona przez kogoś innego.

Wskazówki i triki (Tips & Tricks):
- "Granular/Stricter protection" + "Restrict API access" = VPC Service Controls + VPC Accessible Services.
- Zapamiętaj: Tylko VPC SC pozwala fizycznie "odciąć" API wewnątrz projektu.

Praktyczne informacje na egzamin:
- Zapamiętaj, że "VPC accessible services" jest kluczowe w architekturze "Zero Trust API".

Dokumentacja i linki:
- VPC Service Controls: VPC accessible services

Wskazówki egzaminacyjne (Tips & Tricks)

Reguła Egzaminacyjna (Exam Rule): 
W pytaniach typu 'Security in GCP', zawsze priorytetyzuj rozwiązania natywne (SCC, Cloud KMS, Secret Manager, VPC SC) nad rozwiązaniami typu 'third-party' lub 'self-managed', chyba że scenariusz wymaga specyficznej integracji hybrydowej.

Haczyki egzaminacyjne (Exam Traps):
- Pułapka 'Least Privilege': Egzamin często podpowiada role o szerokim zakresie (np. 'Editor' lub 'Owner') – zawsze odrzucaj je na rzecz ról predefiniowanych o najmniejszym zakresie uprawnień.
- Pułapka 'Logging vs Monitoring': Pamiętaj: Audit Logs służą do badania aktywności (Who/What/When), a Monitoring do zbierania metryk wydajnościowych.

Głębokie wyjaśnienie techniczne:
Każda architektura bezpieczeństwa w GCP powinna być projektowana w oparciu o 'Security by Default'. Oznacza to m.in. szyfrowanie w spoczynku (domyślne), tożsamość opartą na rolach (IAM) oraz pełną widoczność zapewnianą przez scentralizowane logowanie (Cloud Logging/SCC).

Analiza i Podsumowanie (AI)

Kluczowe zagadnienia

Sugerowana odpowiedź: A

Analiza strategiczna: To pytanie testuje zrozumienie architektury "VPC Service Controls". W nowoczesnych, wieloprojektowych środowiskach, izolacja usług jest kluczowa. Reguły Ingress/Egress oraz ograniczenie dostępnych API to "bezpieczne furtki" w tej izolacji, pozwalające na precyzyjne sterowanie przepływem danych bez niszczenia bariery ochronnej.
