Question 85 / 361

You want to synchronize security groups with email addresses from LDAP to Cloud IAM. What should you do?

  • A. Configure GCDS to sync security groups using LDAP search rules with 'user email address' attribute.
  • B. Configure GCDS for bidirectional sync.
  • C. Use a management tool for subset sync based on email.
  • D. Sync based on group object class attribute.
Show Suggested Answer Hide Answer
Suggested Answer: A

Wyjaśnienie

Odpowiedź: A.

Wyjaśnienie (Dlaczego poprawna):
A. GCDS search rules: Google Cloud Directory Sync pozwala na precyzyjne określenie, które grupy z LDAP mają zostać przeniesione do chmury. Filtrowanie po atrybucie adresu e-mail zapewnia, że zsynchronizowane zostaną tylko grupy, które mogą funkcjonować w ekosystemie Google (gdzie tożsamość oparta jest na e-mailu).

Dlaczego inne są błędne:
B. Bidirectional sync: GCDS wspiera tylko synchronizację JEDNOSTRONNĄ (LDAP -> Google). Google nie pozwala na wypychanie zmian z chmury z powrotem do Twojego AD/LDAP tym narzędziem.
C. Subset sync tool: Brzmi jak ogólnik, podczas gdy A precyzuje jak to zrobić w oficjalnym narzędziu GCDS.
D. Object class attribute: Sama klasa obiektu (np. groupOfNames) nie gwarantuje, że grupa ma przypisany adres e-mail, co jest wymagane do jej poprawnego działania w IAM.

Konsensus społeczności ExamTopics: Zdecydowane A. Skuteczna synchronizacja wymaga dobrze zdefiniowanych reguł wyszukiwania (Search Rules).

Analiza i Podsumowanie Dyskusji (AI)

Analiza i Wyjaśnienie

Sugerowana odpowiedź: A

Głęboka analiza: GCDS to narzędzie działające w modelu 'state comparison'. Przed każdą synchronizacją generuje raport zmian, który administrator musi zatwierdzić.
