Question 280 / 361

Your organization has an application hosted in Cloud Run. You must control access to the application by using Cloud Identity-Aware Proxy (IAP) with these requirements: • Only users from the AppDev group may have access. • Access must be restricted to internal network IP addresses. What should you do?

  • A. Deploy a VPN gateway and instruct the AppDev group to connect to the company network before accessing the application.
  • B. Create an access level that includes conditions for internal IP address ranges and AppDev groups. Apply this access level to the application's IAP policy.
  • C. Configure firewall rules to limit access to IAP based on the AppDev group and source IP addresses.
  • D. Configure IAP to enforce multi-factor authentication (MFA) for all users and use network intrusion detection systems (NIDS) to block unauthorized access attempts.
Show Suggested Answer
Suggested Answer: B

Wyjaśnienie

1. Prawidłowa odpowiedź lub odpowiedzi:
B. Create an access level that includes conditions for internal IP address ranges and AppDev groups. Apply this access level to the application's IAP policy.

2. Kompleksowe wyjaśnienie dlaczego dana odpowiedź jest prawidłowa (Analiza):
Odpowiedź B jest prawidłowa, ponieważ łączy weryfikację tożsamości użytkownika (IAM) z weryfikacją kontekstu sieciowego (Access Context Manager) w ramach jednej spójnej polityki Identity-Aware Proxy (IAP).

Zasada działania:
a. **Identity-Aware Proxy (IAP):** Zabezpiecza aplikację w Cloud Run. Aby użytkownik mógł wejść do aplikacji, IAP musi autoryzować jego tożsamość.
b. **Access Context Manager (ACM) & Access Levels:** Tworzymy poziom dostępu (Access Level) w ACM. Definiujemy w nim warunki: adres IP klienta musi należeć do wewnętrznych zakresów firmowych (IP ranges), a tożsamość musi być członkiem grupy `AppDev`.
c. **Powiązanie z IAP:** Ten poziom dostępu aplikujemy bezpośrednio do polityki IAP dla Cloud Run. W rezultacie użytkownicy z grupy AppDev będą mieli dostęp wyłącznie wtedy, gdy będą łączyć się z biura lub przez firmowy VPN (pochodząc z dozwolonego IP). Ruch z innych lokalizacji zostanie zablokowany na poziomie IAP.

3. Wyjaśnienie z osobna każdej niepoprawnej odpowiedzi:
A. Deploy a VPN gateway and instruct the AppDev group to connect...
   * Dlaczego nieprawidłowa: Sam VPN pozwala na dostęp do sieci wewnętrznej GCP, ale bez IAP nie wymusza autoryzacji opartej o tożsamość grupy AppDev dla samej aplikacji w Cloud Run. Ponadto instruowanie użytkowników (human procedure) nie zastępuje prewencyjnego wymuszenia technicznego (technical enforcement) na poziomie IAP.
C. Configure firewall rules to limit access to IAP based on the AppDev group...
   * Dlaczego nieprawidłowa: Klasyczne reguły zapory sieciowej (firewall rules) działają w warstwach 3/4 (IP/Porty) i nie posiadają żadnych funkcji pozwalających na identyfikację przynależności użytkowników do grup Cloud Identity/IAM. Zapora sieciowa nie potrafi filtrować ruchu na podstawie grup użytkowników.
D. Configure IAP to enforce multi-factor authentication (MFA) for all users and use network intrusion detection...
   * Dlaczego nieprawidłowa: Włączenie MFA zwiększa bezpieczeństwo logowania, ale nie ogranicza dostępu fizycznego wyłącznie do określonych zakresów adresów IP (internal network IPs), co było kluczowym wymaganiem sieciowym zadania.

4. Wskazówki, hinty, tips and tricks:
* Ograniczenie dostępu do aplikacji za IAP na podstawie adresu IP i tożsamości użytkownika -> Zawsze używaj **Access Context Manager (Access Levels)** i przypisz je do polityki IAP.
* IAP w pełni współpracuje z Access Context Manager w celu wdrażania zasad Zero Trust.

5. Reguły wyboru odpowiedzi (Słowa kluczowe):
* Cloud Run + IAP + restrict to group and internal IP -> Create access level in Access Context Manager + Apply to IAP.
