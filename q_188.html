Question 188 / 361

A company is using Google Kubernetes Engine (GKE) with container images of a mission-critical application. The company wants to scan the images for known security issues and securely share the report with the security team without exposing them outside Google Cloud.
What should you do?

  • A. 1. Enable Container Threat Detection in the Security Command Center Premium tier. 2. Upgrade all clusters that are not on a supported version of GKE to the latest possible GKE version. 3. View and share the results from the Security Command Center.
  • B. 1. Use an open source tool in Cloud Build to scan the images. 2. Upload reports to publicly accessible buckets in Cloud Storage by using gsutil. 3. Share the scan report link with your security department.
  • C. 1. Enable vulnerability scanning in the Artifact Registry settings. 2. Use Cloud Build to build the images. 3. Push the images to the Artifact Registry for automatic scanning. 4. View the reports in the Artifact Registry.
  • D. 1. Get a GitHub subscription. 2. Build the images in Cloud Build and store them in GitHub for automatic scanning. 3. Download the report from GitHub and share with the Security Team.
Show Suggested Answer Hide Answer
Suggested Answer: C

Wyjaśnienie

1. Prawidłowa odpowiedź lub odpowiedzi:
C. 1. Enable vulnerability scanning in the Artifact Registry settings. 2. Use Cloud Build to build the images. 3. Push the images to the Artifact Registry for automatic scanning. 4. View the reports in the Artifact Registry.

2. Kompleksowe wyjaśnienie dlaczego dana odpowiedź jest prawidłowa (Analiza):
Wymaganiem jest skanowanie obrazów kontenerów pod kątem znanych podatności (CVE) oraz bezpieczne udostępnienie tych raportów zespołowi bezpieczeństwa w taki sposób, aby żadne dane ne zostały ujawnione na zewnątrz Google Cloud.
Artifact Registry posiada wbudowaną usługę automatycznego skanowania podatności (Vulnerability Scanning), która wchodzi w skład Container Analysis API.
Proces ten działa w pełni natywnie w chmurze Google:
1. Włączenie skanowania podatności w Artifact Registry.
2. Zastosowanie Cloud Build jako narzędzia CI/CD do budowania obrazów.
3. Wypchnięcie (push) zbudowanych obrazów do repozytorium w Artifact Registry, co automatycznie wyzwala skanowanie.
4. Raporty są przechowywane i przeglądane bezpośrednio w konsoli Artifact Registry w Google Cloud. Uprawnieni członkowie zespołu bezpieczeństwa mają do nich dostęp przy użyciu ról IAM, co gwarantuje pełną poufność i brak jakiejkolwiek ekspozycji na świat zewnętrzny.

3. Wyjaśnienie z osobna każdej niepoprawnej odpowiedzi:
- A. Enable Container Threat Detection in the Security Command Center Premium tier...: Container Threat Detection służy do monitorowania i wykrywania podejrzanego zachowania kontenerów w czasie rzeczywistym (np. próba wykonania reverse shell w uruchomionym podzie w GKE). Nie jest to narzędzie do statycznej analizy podatności obrazów w rejestrze przed ich wdrożeniem.
- B. Use an open source tool... Upload reports to publicly accessible buckets...: Umieszczenie raportów o podatnościach aplikacji w publicznym (publicly accessible) buckecie Cloud Storage bezpośrednio narusza wymóg zachowania poufności raportów ("without exposing them outside Google Cloud") i stanowi ogromne ryzyko bezpieczeństwa.
- D. Get a GitHub subscription. Build the images in Cloud Build and store them in GitHub...: Przesyłanie obrazów i generowanie raportów w zewnętrznej usłudze (GitHub) wyprowadza dane poza obręb Google Cloud, co stoi w sprzeczności z wymaganiem zachowania danych wewnątrz infrastruktury GCP.

4. Wskazówki, hinty, tips and tricks:
- Skanowanie obrazów kontenerów w GCP przed wdrożeniem (Shift-Left Security) najprościej i najbezpieczniej realizuje się za pomocą **Artifact Registry Vulnerability Scanning**.
- Zwróć uwagę na słowa kluczowe mówiące o braku ekspozycji na zewnątrz – rozwiązania publiczne lub zewnętrzne platformy (jak GitHub) są odrzucane na rzecz rozwiązań natywnych z autoryzacją IAM.

5. Reguły wyboru odpowiedzi (Słowa kluczowe):
- "scan container images for security issues" + "without exposing outside Google Cloud" -> Artifact Registry Settings -> Vulnerability Scanning.

6. Dodatkowe źródła i dokumentacja:
- Vulnerability scanning in Artifact Registry: https://cloud.google.com/artifact-registry/docs/analysis/vulnerability-scanning

Analiza i Wyjaśnienie

Sugerowana odpowiedź: C

Głęboka analiza: Zadanie wymaga bezpiecznego i natywnego procesu skanowania. Artifact Registry w połączeniu z Container Analysis oferuje w pełni zautomatyzowane rozwiązanie, które nie wymaga przesyłania danych do zewnętrznych dostawców. To standardowa metoda budowania bezpiecznego łańcucha dostaw oprogramowania (Secure Software Supply Chain) w Google Cloud.
