Question 75 / 361

A workforce needs to access a CRM hosted on GCP. It requires an authentication layer that supports two-factor authentication. Which GCP product should be implemented?

  • A. Cloud Identity-Aware Proxy
  • B. Cloud Armor
  • C. Cloud Endpoints
  • D. Cloud VPN
Show Suggested Answer Hide Answer
Suggested Answer: A

Wyjaśnienie

1. Prawidłowa odpowiedź lub odpowiedzi:
A. Cloud Identity-Aware Proxy

2. Kompleksowe wyjaśnienie dlaczego dana odpowiedź jest prawidłowa (Analiza):
Prawidłową odpowiedzią jest Cloud Identity-Aware Proxy (IAP), ponieważ jest to usługa GCP zaprojektowana specjalnie do zapewniania bezpiecznego dostępu do aplikacji webowych i zasobów backendowych, bazując na tożsamości użytkownika i kontekście dostępu, a nie tylko na adresie IP. W scenariuszu, gdzie pracownicy (workforce) potrzebują dostępu do aplikacji CRM hostowanej na GCP i wymagane jest uwierzytelnianie z dwuskładnikową autoryzacją (two-factor authentication - 2FA), IAP jest idealnym rozwiązaniem.

Cloud IAP działa jako brama autoryzacyjna. Zamiast otwierać zasoby na publiczny internet lub wymagać skomplikowanej konfiguracji VPN, IAP przechwytuje wszystkie żądania przychodzące do aplikacji i sprawdza tożsamość użytkownika oraz jego uprawnienia IAM przed przekazaniem żądania do backendu. Integruje się z Cloud Identity (lub Google Workspace), co oznacza, że może wykorzystywać istniejące konta użytkowników Google i ich metody uwierzytelniania, w tym wbudowaną obsługę 2FA/MFA (Multi-Factor Authentication). Dzięki temu użytkownicy mogą logować się przy użyciu swoich standardowych danych logowania Google, a polityki 2FA są automatycznie egzekwowane zgodnie z konfiguracją organizacji w Cloud Identity.

Kluczowe zalety IAP w tym kontekście to:
  Bezpieczeństwo oparte na tożsamości: Zamiast polegać na zabezpieczeniach sieciowych, IAP koncentruje się na tym, KIM jest użytkownik i CZY MA odpowiednie uprawnienia IAM do dostępu do konkretnego zasobu. To realizuje model bezpieczeństwa Zero Trust, gdzie dostęp jest domyślnie odmawiany, a udzielany tylko po pomyślnej weryfikacji tożsamości i autoryzacji.
  Obsługa 2FA/MFA: IAP automatycznie dziedziczy i egzekwuje polityki uwierzytelniania z Cloud Identity, w tym wymóg 2FA, co jest bezpośrednią odpowiedzią na wymagania pytania.
  Eliminacja VPN: IAP pozwala na bezpieczny dostęp do wewnętrznych aplikacji bez konieczności wdrażania i zarządzania sieciami VPN. Upraszcza to doświadczenie użytkownika i redukuje obciążenie administracyjne.
  Granularna kontrola dostępu: Możliwość definiowania bardzo szczegółowych zasad dostępu za pomocą IAM, na przykład, kto i z jakiego miejsca może uzyskać dostęp do konkretnej instancji VM, grupy instancji, aplikacji App Engine lub usługi Cloud Run.
  Zmniejszenie powierzchni ataku: Zasoby objęte IAP mogą być całkowicie prywatne, bez publicznego adresu IP, co znacznie zmniejsza ich ekspozycję na ataki z internetu. IAP działa jako jedyny publicznie dostępny punkt wejścia, który jest zarządzany i zabezpieczony przez Google.
  Skalowalność i niezawodność: Jako usługa zarządzana przez Google, IAP skaluje się automatycznie, aby sprostać zapotrzebowaniu i oferuje wysoką dostępność.

Podsumowując, Cloud IAP to precyzyjne rozwiązanie dla wymogu bezpiecznego dostępu pracowników do aplikacji webowej (CRM) z obowiązkową warstwą uwierzytelniania dwuskładnikowego, wpisujące się w nowoczesne podejście Zero Trust.

3. Wyjaśnienie z osobna każdej niepoprawnej odpowiedzi:

B. Cloud Armor
  Dlaczego jest niepoprawna: Cloud Armor jest usługą chroniącą przed atakami DDoS (Distributed Denial of Service) i pełni funkcję zapory aplikacji webowych (Web Application Firewall - WAF). Jej głównym zadaniem jest filtrowanie złośliwego ruchu internetowego, takiego jak ataki DDoS warstwy 3 i 4, a także ataki warstwy 7, takie jak SQL injection czy cross-site scripting (XSS). Cloud Armor nie jest jednak warstwą uwierzytelniania dla użytkowników końcowych. Nie zarządza tożsamością użytkowników ani nie egzekwuje uwierzytelniania dwuskładnikowego. Może chronić aplikację CRM przed atakami, ale nie zapewnia mechanizmu logowania i weryfikacji tożsamości pracowników.

C. Cloud Endpoints
  Dlaczego jest niepoprawna: Cloud Endpoints to usługa służąca do zarządzania, wdrażania i monitorowania interfejsów API (Application Programming Interface). Jest wykorzystywana do tworzenia i zabezpieczania API, które inne aplikacje lub usługi mogą wykorzystywać do interakcji. Chociaż Cloud Endpoints może integrować się z usługami uwierzytelniania (takimi jak Firebase Authentication, Auth0, czy też OAuth 2.0/JWT), jego głównym celem nie jest zapewnianie bezpośredniego dostępu użytkownikom końcowym do aplikacji webowej (CRM) i zarządzanie ich tożsamością w kontekście przeglądarkowym z wymogiem 2FA. Pytanie dotyczy dostępu workforce do aplikacji hostowanej, a nie konsumpcji API przez inne programy.

D. Cloud VPN
  Dlaczego jest niepoprawna: Cloud VPN (Virtual Private Network) umożliwia bezpieczne połączenie sieciowe między lokalną siecią organizacji a siecią Virtual Private Cloud (VPC) w GCP (site-to-site VPN) lub między pojedynczym urządzeniem użytkownika a siecią VPC (client-to-site VPN). Chociaż VPN zapewnia bezpieczny kanał komunikacji i może być używany do uzyskania dostępu do aplikacji hostowanej na GCP, ma kilka wad w porównaniu do IAP w tym scenariuszu. Po pierwsze, Cloud VPN sam w sobie nie jest warstwą uwierzytelniania tożsamości na poziomie aplikacji; zapewnia dostęp na poziomie sieci. Wymagałoby to dodatkowej konfiguracji serwera uwierzytelniania w sieci lokalnej lub na GCP, aby wymusić 2FA dla dostępu do samej sieci VPN. Po drugie, VPN jest rozwiązaniem opartym na sieci, co oznacza, że po nawiązaniu połączenia użytkownik uzyskuje dostęp do całej sieci lub jej części, a nie tylko do konkretnej aplikacji, co jest mniej granularne i trudniejsze do zarządzania w modelu Zero Trust. Ponadto, wymaga instalacji klienta VPN na urządzeniu użytkownika i może być mniej elastyczne w zarządzaniu dostępem niż IAP, które działa na zasadzie kontekstowo-tożsamościowej.

4. Wskazówki, hinty, tips and tricks:
  Zawsze zwracaj uwagę na SŁOWA KLUCZOWE w pytaniu. W tym przypadku "authentication layer", "two-factor authentication" i "workforce needs to access a CRM hosted on GCP" są kluczowe. Oznaczają one, że potrzebujemy rozwiązania zarządzającego tożsamością i dostępem do aplikacji webowej.
  Rozróżnij bezpieczeństwo sieciowe od bezpieczeństwa tożsamościowego. Produkty takie jak Cloud Armor czy Cloud VPN koncentrują się na zabezpieczaniu ruchu sieciowego lub połączeń. Produkty takie jak Cloud IAP koncentrują się na zabezpieczaniu dostępu na podstawie tożsamości użytkownika.
  Myśl o modelu Zero Trust. Jeśli pytanie sugeruje potrzebę bardzo granularnej kontroli dostępu opartej na tożsamości, bez ufania sieci, IAP jest zazwyczaj najlepszym wyborem.
  Zrozum podstawowe przeznaczenie każdej usługi GCP. Cloud Endpoints jest do API, Cloud Armor do ochrony DDoS/WAF, Cloud VPN do połączeń sieciowych, IAP do tożsamościowego dostępu do aplikacji.
  Jeśli pytanie mówi o "użytkownikach końcowych" lub "pracownikach" i "dostępie do aplikacji webowej", IAP jest często poprawną odpowiedzią. Jeśli mówi o "ochronie przed atakami", myślimy o Cloud Armor. Jeśli o "bezpiecznym połączeniu między centrami danych", myślimy o Cloud VPN.

5. Reguły wyboru odpowiedzi (Słowa kluczowe):
  Jeśli pytanie wspomina o "dostępie do aplikacji webowych lub usług wewnętrznych" oraz "uwierzytelnianiu użytkowników końcowych" lub "wymogu 2FA/MFA", szukaj odpowiedzi zawierającej "Cloud Identity-Aware Proxy (IAP)".
  Gdy celem jest "ochrona przed atakami DDoS" lub "Web Application Firewall (WAF)", wybierz "Cloud Armor".
  Jeśli scenariusz dotyczy "zarządzania interfejsami API", "generowania specyfikacji API" lub "monitorowania użycia API", odpowiedź to "Cloud Endpoints".
  Gdy chodzi o "bezpieczne połączenie sieciowe typu site-to-site" lub "client-to-site VPN" między siecią lokalną a GCP, wybierz "Cloud VPN".
  Jeśli pytanie podkreśla "kontrolę dostępu opartą na tożsamości", "model Zero Trust" lub "eliminację VPN dla dostępu do aplikacji", Cloud IAP jest bardzo silnym kandydatem.
