Question 88 / 361

Your company operates an application instance group that is currently deployed behind a Google Cloud load balancer in us-central-1 and is configured to use the Standard Tier network. The infrastructure team wants to expand to a second Google Cloud region, us-east-2. You need to set up a single external IP address to distribute new requests to the instance groups in both regions.
What should you do?

  • A. Change the load balancer backend configuration to use network endpoint groups instead of instance groups.
  • B. Change the load balancer frontend configuration to use the Premium Tier network, and add the new instance group.
  • C. Create a new load balancer in us-east-2 using the Standard Tier network, and assign a static external IP address.
  • D. Create a Cloud VPN connection between the two regions, and enable Google Private Access.
Show Suggested Answer Hide Answer
Suggested Answer: B

Wyjaśnienie

**Poprawna odpowiedź: B**

**1. Kompleksowe wyjaśnienie poprawnej odpowiedzi:**
Firma chce rozszerzyć aplikację o drugi region (us-east-2) i kierować ruch do obu regionów za pomocą jednego zewnętrznego adresu IP:
- **Zmiana konfiguracji frontendowej Load Balancera na Premium Tier network (B):** W Google Cloud, Globalne równoważenie obciążenia (Global HTTP(S) Load Balancing) wymaga użycia sieci w trybie **Premium Tier**. Premium Tier kieruje ruch przez globalną, prywatną sieć szkieletową Google (Google global backbone) i pozwala na przypisanie pojedynczego, globalnego adresu IP typu anycast, który automatycznie kieruje użytkowników do najbliższego zdrowego regionu (us-central-1 lub us-east-2). Standard Tier nie pozwala na globalny load balancing i kieruje ruch przez publiczny internet, ograniczając load balancing do poziomu regionalnego.

**2. Wyjaśnienie niepoprawnych odpowiedzi:**
- **A. Zmiana backendu na Network Endpoint Groups (NEG):** Wybór między NEG a Instance Groups nie wpływa na to, czy load balancer może kierować ruch globalnie do wielu regionów pod jednym adresem IP.
- **C. Utworzenie nowego Load Balancera w us-east-2 przy użyciu Standard Tier:** Standard Tier wymaga osobnego zewnętrznego adresu IP dla każdego regionu. Spowodowałoby to posiadanie dwóch różnych adresów IP dla us-central-1 i us-east-2, co narusza wymóg posiadania pojedynczego zewnętrznego adresu IP ("single external IP address").
- **D. Cloud VPN i Private Access:** VPN i Private Google Access są technologiami sieci prywatnej/hybrydowej, a nie rozwiązaniami do globalnego równoważenia publicznego ruchu przychodzącego z internetu.

**3. Wskazówki i pułapki egzaminacyjne (Tips & Tricks):**
- **Premium Tier:** Ruch wchodzi do sieci Google jak najbliżej użytkownika i podróżuje przez szybką sieć szkieletową Google. Wspiera globalny load balancing z jednym adresem IP anycast.
- **Standard Tier:** Ruch podróżuje przez publiczny internet i wchodzi do sieci Google dopiero w regionie docelowym. Wspiera tylko regionalny load balancing.
- Pojedynczy globalny IP do wielu regionów -> **Premium Tier Network**.

**4. Reguły wyboru odpowiedzi:**
- Globalny load balancing / jeden zewnętrzny IP dla wielu regionów -> Premium Tier.
