Question 185 / 361

Your organization is moving virtual machines (VMs) to Google Cloud. You must ensure that operating system images that are used across your projects are trusted and meet your security requirements.
What should you do?

  • A. Implement an organization policy to enforce that boot disks can only be created from images that come from the trusted image project.
  • B. Implement an organization policy constraint that enables the Shielded VM service on all projects to enforce the trusted image repository usage.
  • C. Create a Cloud Function that is automatically triggered when a new virtual machine is created from the trusted image repository. Verify that the image is not deprecated.
  • D. Automate a security scanner that verifies that no common vulnerabilities and exposures (CVEs) are present in your trusted image repository.
Show Suggested Answer Hide Answer
Suggested Answer: A

Wyjaśnienie

Poprawna odpowiedź: A (Implement an organization policy to enforce that boot disks can only be created from images that come from the trusted image project)

Dlaczego ta odpowiedź jest poprawna:
- compute.trustedImageProjects: Jest to specyficzny constraint polityki organizacji (Organization Policy), który pozwala administratorowi na zdefiniowanie listy projektów, z których można pobierać obrazy systemowe (images) do tworzenia dysków rozruchowych (boot disks).
- Wymuszenie (Enforcement): Włączenie tej polityki sprawia, że każda próba stworzenia VM na podstawie obrazu spoza dozwolonej listy (np. z obrazów publicznych Google, jeśli nie zostały dodane do białej listy) zostanie zablokowana przez API Google Cloud.
- Skuteczność: Jest to najbardziej bezpośrednia i skuteczna metoda zapewnienia, że wszystkie VM w organizacji korzystają wyłącznie z obrazów zatwierdzonych przez zespół bezpieczeństwa (tzw. "Golden Images").

Analiza niepoprawnych odpowiedzi:
- B. Shielded VM service: Shielded VMs to funkcja zapewniająca integralność procesu startu systemu (Secure Boot, vTPM). Choć zwiększają bezpieczeństwo, same w sobie nie ograniczają listy projektów, z których można pobierać obrazy. Możesz uruchomić "Shielded VM" z niezaufanego obrazu.
- C. Cloud Function trigger: To rozwiązanie reaktywne. Funkcja uruchomiłaby się PO stworzeniu VM. Nawet jeśli usunęłaby maszynę natychmiast, przez kilka sekund niebezpieczny system byłby uruchomiony. Rozwiązanie to jest skomplikowane w utrzymaniu w porównaniu do natywnej polityki organizacji.
- D. Automated security scanner (CVE): Skanowanie obrazów pod kątem podatności (CVE) jest bardzo dobrą praktyką (część procesu budowania obrazu), ale samo w sobie nie uniemożliwia użytkownikom użycia innego, nieprzeskanowanego obrazu do stworzenia VM.

Wskazówki i triki (Tips & Tricks):
- "Trusted OS images" + "Across projects" = Organization Policy (Trusted Image Projects).
- Zapamiętaj: Ta polityka dotyczy tylko dysków rozruchowych (boot disks).
- Pamiętaj, aby dodać projekt `projects/debian-cloud` itp., jeśli chcesz pozwolić również na standardowe obrazy publiczne obok swoich własnych.

Praktyczne informacje na egzamin:
- Zrozum hierarchię: Najpierw tworzysz bezpieczny obraz w centralnym projekcie, potem nadajesz uprawnienia `imageUser`, a na końcu włączasz Org Policy `trustedImageProjects`, aby zablokować inne źródła.

Analiza i Podsumowanie (AI)

Kluczowe zagadnienia

Sugerowana odpowiedź: A

Analiza strategiczna: To pytanie sprawdza znajomość mechanizmów kontroli nad cyklem życia zasobów obliczeniowych. W dużej firmie nie możesz polegać na dobrej woli deweloperów. Musisz technicznie uniemożliwić uruchamianie systemów, które nie przeszły przez Twój proces utwardzania (hardeningu). `trustedImageProjects` to standardowe narzędzie do tego celu w GCP.

Dodatkowe wskazówki

  • Polityka ta może być nakładana na poziomie całej organizacji lub konkretnych folderów (np. bardziej restrykcyjna dla folderu PROD).
  • Uważaj, aby nie zablokować sobie możliwości odzyskiwania systemu (Recovery) poprzez zbyt rygorystyczne listy projektów.
