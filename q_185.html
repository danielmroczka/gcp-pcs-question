Question 185 / 361

Your organization is moving virtual machines (VMs) to Google Cloud. You must ensure that operating system images that are used across your projects are trusted and meet your security requirements.
What should you do?

  • A. Implement an organization policy to enforce that boot disks can only be created from images that come from the trusted image project.
  • B. Implement an organization policy constraint that enables the Shielded VM service on all projects to enforce the trusted image repository usage.
  • C. Create a Cloud Function that is automatically triggered when a new virtual machine is created from the trusted image repository. Verify that the image is not deprecated.
  • D. Automate a security scanner that verifies that no common vulnerabilities and exposures (CVEs) are present in your trusted image repository.
Show Suggested Answer Hide Answer
Suggested Answer: A

Wyjaśnienie

1. Prawidłowa odpowiedź lub odpowiedzi:
A. Implement an organization policy to enforce that boot disks can only be created from images that come from the trusted image project.

2. Kompleksowe wyjaśnienie dlaczego dana odpowiedź jest prawidłowa (Analiza):
Wymaganie polega na zapewnieniu, że obrazy systemów operacyjnych (OS images) używane do tworzenia maszyn wirtualnych (VM) we wszystkich projektach w organizacji są zaufane i spełniają wymagania bezpieczeństwa. W Google Cloud najlepszą i najbardziej proaktywną metodą na zrealizowanie tego celu na poziomie całej hierarchii zasobów (organizacja/foldery) jest zastosowanie polityki organizacji (Organization Policy).
Ograniczenie (constraint) `constraints/compute.trustedImageProjects` pozwala na zdefiniowanie białej listy projektów (np. centralnego projektu zarządzanego przez zespół bezpieczeństwa), z których dozwolone jest tworzenie dysków rozruchowych (boot disks). Każda próba wdrożenia maszyny wirtualnej z obrazu pochodzącego z innego, niezatwierdzonego projektu zostanie natychmiast zablokowana przez API Compute Engine przed utworzeniem zasobu.

3. Wyjaśnienie z osobna każdej niepoprawnej odpowiedzi:
- B. Implement an organization policy constraint that enables the Shielded VM service on all projects...: Funkcja Shielded VM zwiększa bezpieczeństwo na poziomie bootowania systemu (zabezpieczenie przed rootkitami poprzez Secure Boot i vTPM), jednak samo jej włączenie nie filtruje źródła pochodzenia obrazów. Nadal można wdrożyć maszynę jako Shielded VM z niezaufanego projektu.
- C. Create a Cloud Function that is automatically triggered when a new virtual machine is created...: Jest to podejście reaktywne. Funkcja uruchamiana na podstawie logów usunęłaby maszynę dopiero po jej utworzeniu. Ponadto wymaga to utrzymywania własnego kodu i architektury event-driven, co jest gorszym rozwiązaniem niż natywna polityka organizacji.
- D. Automate a security scanner that verifies that no common vulnerabilities and exposures (CVEs)...: Skanowanie obrazów pod kątem podatności (CVE) jest kluczowe w procesie budowania obrazu (złotego obrazu), ale samo skanowanie nie blokuje użytkownikom możliwości uruchomienia maszyny z innego, dowolnego publicznego obrazu w GCP.

4. Wskazówki, hinty, tips and tricks:
- Kiedy pytanie dotyczy wymuszenia używania wyłącznie autoryzowanych obrazów maszyn wirtualnych w całej organizacji, szukaj polityki organizacji `compute.trustedImageProjects`.
- Zapamiętaj, że ta polityka kontroluje źródło obrazów tylko dla dysków rozruchowych (boot disks), a nie zwykłych dysków z danymi.

5. Reguły wyboru odpowiedzi (Słowa kluczowe):
- "operating system images used across projects are trusted" -> Organization Policy -> `trustedImageProjects` / `compute.trustedImageProjects`.

6. Dodatkowe źródła i dokumentacja:
- Restricting image access in Google Cloud: https://cloud.google.com/compute/docs/images/restricting-image-access

Analiza i Podsumowanie Dyskusji (AI)

Analiza i Wyjaśnienie

Sugerowana odpowiedź: A

Głęboka analiza: W środowiskach korporacyjnych kontrola nad systemami operacyjnymi jest krytyczna dla zachowania zgodności (compliance). Google Cloud oferuje natywny mechanizm `trustedImageProjects`, który pozwala oddzielić projekt "budujący obrazy" (zarządzany przez zespół bezpieczeństwa) od projektów "użytkowych". To rozwiązanie jest skalowalne i niemożliwe do obejścia przez standardowych użytkowników.
