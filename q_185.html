Question 185 / 361

Your organization is moving virtual machines (VMs) to Google Cloud. You must ensure that operating system images that are used across your projects are trusted and meet your security requirements.
What should you do?

  • A. Implement an organization policy to enforce that boot disks can only be created from images that come from the trusted image project.
  • B. Implement an organization policy constraint that enables the Shielded VM service on all projects to enforce the trusted image repository usage.
  • C. Create a Cloud Function that is automatically triggered when a new virtual machine is created from the trusted image repository. Verify that the image is not deprecated.
  • D. Automate a security scanner that verifies that no common vulnerabilities and exposures (CVEs) are present in your trusted image repository.
Show Suggested Answer Hide Answer
Suggested Answer: A

Wyjaśnienie

Potwierdzona odpowiedź: A (Implement an organization policy to enforce that boot disks can only be created from images that come from the trusted image project).

Wyjaśnienie:
Ograniczenie `compute.trustedImageProjects` w polityce organizacji Google Cloud pozwala na zdefiniowanie białej listy projektów, z których użytkownicy mogą pobierać obrazy systemowe (images) do tworzenia dysków rozruchowych. Jest to najskuteczniejszy i najbardziej proaktywny sposób wymuszenia stosowania wyłącznie zaufanych i utwardzonych (hardened) obrazów OS w całej organizacji. Każda próba użycia obrazu spoza listy zostanie natychmiast zablokowana przez API.

Dlaczego pozostałe są błędne:
- B. Shielded VM service: Shielded VM to funkcja zwiększająca bezpieczeństwo startu systemu (Secure Boot, vTPM), ale sama w sobie nie ogranicza źródła obrazów. Można uruchomić "Shielded VM" z niezaufanego projektu.
- C. Cloud Function trigger: To rozwiązanie reaktywne. Funkcja usuwałaby maszyny PO ich stworzeniu, co nie zapobiega samemu incydentowi i jest trudniejsze w utrzymaniu niż natywna polityka organizacji.
- D. Automated security scanner: Skanowanie obrazów pod kątem podatności (CVE) jest kluczowe w procesie CI/CD budowania obrazu, ale samo w sobie nie uniemożliwia użytkownikom uruchomienia maszyny z innego, niebezpiecznego źródła.

Wskazówki egzaminacyjne (Tips & Tricks):
- "Trusted OS images" + "Across projects" = szukaj "Organization Policy" oraz "trustedImageProjects".
- Zapamiętaj: Ta polityka dotyczy dysków rozruchowych (boot disks), a nie wszystkich dysków w ogóle.

Kluczowe zagadnienia do powtórzenia:
- Hierarchia polityk organizacji (Organization Policy Service).
- Proces tworzenia i udostępniania obrazów (Golden Images).
- Rola uprawnienia `compute.imageUser`.

Analiza i Podsumowanie Dyskusji (AI)

Analiza i Wyjaśnienie

Sugerowana odpowiedź: A

Głęboka analiza: W środowiskach korporacyjnych kontrola nad systemami operacyjnymi jest krytyczna dla zachowania zgodności (compliance). Google Cloud oferuje natywny mechanizm `trustedImageProjects`, który pozwala oddzielić projekt "budujący obrazy" (zarządzany przez zespół bezpieczeństwa) od projektów "użytkowych". To rozwiązanie jest skalowalne i niemożliwe do obejścia przez standardowych użytkowników.
