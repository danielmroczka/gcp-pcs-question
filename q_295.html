Question 295 / 361

Your organization heavily utilizes serverless applications while prioritizing security best practices. You are responsible for enforcing image provenance and compliance with security standards before deployment. You leverage Cloud Build as your continuous integration and continuous deployment (CI/CD) tool for building container images. You must configure Binary Authorization to ensure that only images built by your Cloud Build pipeline are deployed and that the images pass security standard compliance checks. What should you do?

  • A. Create a Binary Authorization attestor that uses a scanner to assess source code management repositories. Deploy images only if the attestor validates results against a security policy.
  • B. Create a Binary Authorization attestor that utilizes a scanner to evaluate container image build processes. Define a policy that requires deployment of images only if this attestation is present.
  • C. Create a Binary Authorization attestor that retrieves the Cloud Build build ID of the container image. Configure a policy to allow deployment only if there's a matching build ID attestation.
  • D. Utilize a custom Security Health Analytics module to create a policy. Enforce the policy through Binary Authorization to prevent deployment of images that do not meet predefined security standards.
Show Suggested Answer Hide Answer
Suggested Answer: C

Wyjaśnienie

1. Prawidłowa odpowiedź lub odpowiedzi:
C. Create a Binary Authorization attestor that retrieves the Cloud Build build ID of the container image. Configure a policy to allow deployment only if there's a matching build ID attestation.

2. Kompleksowe wyjaśnienie dlaczego dana odpowiedź jest prawidłowa (Analiza):
Odpowiedź C jest prawidłowa, ponieważ weryfikacja identyfikatora kompilacji (build ID) z Cloud Build przez Atestatora Binary Authorization pozwala na precyzyjne potwierdzenie pochodzenia obrazu (provenance) – czyli udowodnienie, że dany kontener został zbudowany przez autoryzowany potok CI/CD chmury, a nie wgrany z zewnątrz.

Mechanizm działania:
a. **Integracja Cloud Build i Artifact Analysis:** Podczas procesu budowania obrazu, Cloud Build generuje metadane dotyczące pochodzenia (provenance metadata), w tym unikalny identyfikator buildu (build ID).
b. **Podpisywanie (Atestacja):** Atestator Binary Authorization podpisuje te metadane kluczem kryptograficznym KMS.
c. **Admission Control (Binary Authorization):** Podczas próby wdrożenia obrazu na Cloud Run lub GKE, usługa weryfikuje podpis atestatora i sprawdza, czy build ID w atestacji zgadza się z metadanymi obrazu. Jeśli obraz pochodzi z nieautoryzowanego źródła (np. został zbudowany lokalnie u dewelopera i wypchnięty do rejestru), wdrożenie zostanie zablokowane.

3. Wyjaśnienie z osobna każdej niepoprawnej odpowiedzi:
A. Create a Binary Authorization attestor that uses a scanner to assess source code management repositories...
   * Dlaczego nieprawidłowa: Binary Authorization działa na poziomie gotowych obrazów kontenerowych w momencie ich wdrażania (deployment). Nie ma możliwości bezpośredniego skanowania i weryfikowania repozytoriów kodu źródłowego (git) w locie podczas uruchamiania kontenera na klastrze.
B. Create a Binary Authorization attestor that utilizes a scanner to evaluate container image build processes...
   * Dlaczego nieprawidłowa: Atestator sam w sobie nie jest "skanerem", który uruchamia i ocenia proces budowania obrazu. Atestator to tożsamość/klucz, który podpisuje stwierdzenia (atestacje) wygenerowane przez inne narzędzia (np. Cloud Build lub skanery podatności). Ta opcja błędnie definiuje rolę atestatora.
D. Utilize a custom Security Health Analytics module to create a policy...
   * Dlaczego nieprawidłowa: Security Health Analytics (SHA) w Security Command Center służy do wykrywania miskonfiguracji zasobów chmurowych (np. publiczne IP). Nie uczestniczy w procesie wdrażania kontenerów i nie potrafi generować ani weryfikować podpisów kryptograficznych obrazów kontenerowych dla Binary Authorization.

4. Wskazówki, hinty, tips and tricks:
* Pochodzenie obrazu (image provenance) w GCP CI/CD -> Wykorzystanie **Cloud Build** w połączeniu z **Binary Authorization** w celu weryfikacji podpisanych metadanych kompilacji (build ID/provenance).
* Zapewnia to, że deweloperzy nie mogą wdrożyć do produkcji kontenera zbudowanego na własnym laptopie.

5. Reguły wyboru odpowiedzi (Słowa kluczowe):
* Enforce image provenance + Cloud Build + Binary Authorization -> Attestor retrieves Cloud Build build ID + policy requires matching build ID attestation.

6. Dodatkowe źródła i dokumentacja:

Verifying build provenance in Cloud Build
