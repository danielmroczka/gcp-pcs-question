Question 295 / 361

Your organization heavily utilizes serverless applications while prioritizing security best practices. You are responsible for enforcing image provenance and compliance with security standards before deployment. You leverage Cloud Build as your continuous integration and continuous deployment (CI/CD) tool for building container images. You must configure Binary Authorization to ensure that only images built by your Cloud Build pipeline are deployed and that the images pass security standard compliance checks. What should you do?

  • A. Create a Binary Authorization attestor that uses a scanner to assess source code management repositories. Deploy images only if the attestor validates results against a security policy.
  • B. Create a Binary Authorization attestor that utilizes a scanner to evaluate container image build processes. Define a policy that requires deployment of images only if this attestation is present.
  • C. Create a Binary Authorization attestor that retrieves the Cloud Build build ID of the container image. Configure a policy to allow deployment only if there's a matching build ID attestation.
  • D. Utilize a custom Security Health Analytics module to create a policy. Enforce the policy through Binary Authorization to prevent deployment of images that do not meet predefined security standards.
Show Suggested Answer Hide Answer
Suggested Answer: C

Wyjaśnienie

Potwierdzona odpowiedź: C (Create a Binary Authorization attestor that retrieves the Cloud Build build ID of the container image. Configure a policy to allow deployment only if there's a matching build ID attestation.)

Wyjaśnienie:
- Cloud Build Attestation: Cloud Build posiada natywną funkcjonalność generowania podpisanej atestacji (z build ID) po pomyślnym zbudowaniu obrazu. Binary Authorization w klastrze (GKE/Cloud Run) weryfikuje ten podpis. Jest to złoty standard (SLSA) gwarantujący, że wdrożony obraz pochodzi z Twojego zaufanego potoku CI/CD (provenance).

Dlaczego pozostałe odpowiedzi są niepoprawne:
- A, B: Są to opisy ogólne lub nieistniejące funkcjonalności w Binary Authorization.
- D. Security Health Analytics: Służy do audytu konfiguracji, a nie do "enforcement" (wymuszania) przepływu obrazów w potoku CI/CD.

Wskazówki i triki (Tips & Tricks):
- "Only images built by your Cloud Build pipeline" + "Binary Authorization" = Cloud Build Attestation (matching build ID).

Praktyczne informacje na egzamin:
- Zapamiętaj: Binary Authorization to brama bezpieczeństwa, która sprawdza cyfrowe podpisy (atestacje) na obrazach przed ich uruchomieniem.

Dokumentacja i linki:
- Binary Authorization: Cloud Build attestations

Analiza i Podsumowanie (AI)

Kluczowe zagadnienia

Sugerowana odpowiedź: C

Analiza strategiczna: Pytanie sprawdza znajomość integracji Binary Authorization z CI/CD (Cloud Build). Kluczem jest automatyczna weryfikacja pochodzenia (provenance) obrazu przez podpisaną atestację z identyfikatorem buildu.
