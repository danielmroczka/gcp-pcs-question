Question 11 / 361

A customer needs to prevent attackers from hijacking their domain/IP and redirecting users to a malicious site through a man-in-the-middle attack. Which solution should this customer use?

  • A. VPC Flow Logs
  • B. Cloud Armor
  • C. DNS Security Extensions
  • D. Cloud Identity-Aware Proxy
Show Suggested Answer Hide Answer
Suggested Answer: C

Wyjaśnienie

Potwierdzona odpowiedź: C (DNS Security Extensions - DNSSEC)

Wyjaśnienie: 
Aby zapobiec przejęciu domeny/IP (hijacking) i atakom typu man-in-the-middle polegającym na fałszowaniu odpowiedzi DNS (np. DNS cache poisoning), należy zastosować DNSSEC. DNSSEC dodaje cyfrowe podpisy do rekordów DNS, co pozwala serwerom rozwiązującym nazwy (resolvers) na zweryfikowanie, czy odpowiedź pochodzi z autentycznego źródła i nie została zmodyfikowana w trakcie przesyłania.

Dlaczego pozostałe są błędne:
A. VPC Flow Logs: Służą do monitorowania i rejestrowania ruchu IP w sieciach VPC. Pomagają w analizie incydentów, ale nie zapobiegają fałszowaniu rekordów DNS na poziomie publicznego internetu.
B. Cloud Armor: Jest to WAF (Web Application Firewall) i ochrona przed DDoS. Chroni aplikacje przed atakami L7 (np. SQLi, XSS), ale nie zabezpiecza integralności samego protokołu DNS.
D. Cloud Identity-Aware Proxy: Zarządza dostępem do aplikacji na podstawie tożsamości użytkownika. Nie chroni infrastruktury DNS przed atakami typu spoofing czy hijacking.

Wskazówki egzaminacyjne (Tips & Tricks):
- "Hijacking domain/IP" + "Man-in-the-middle" + "DNS context" = DNSSEC.
- Pamiętaj, że DNSSEC zapewnia integralność i autentyczność, ale NIE zapewnia poufności (dane DNS wciąż są jawne, tylko podpisane).

Kluczowe zagadnienia do powtórzenia:
- DNSSEC (Domain Name System Security Extensions)
- DNS Cache Poisoning / Spoofing
- Cloud DNS security features

Dokumentacja:
https://cloud.google.com/dns/docs/dnssec

**Reguła Egzaminacyjna (Exam Rule):**
Zawsze identyfikuj warstwę modelu OSI, na której operuje atak oraz rozwiązanie. DNSSEC działa na poziomie warstwy aplikacji dla DNS, zapobiegając zatruwaniu pamięci podręcznej (Cache Poisoning).

**Haczyki egzaminacyjne (Exam Traps):**
- Mylenie Cloud Armor (WAF - L7) z zabezpieczeniami DNS (DNSSEC - integralność danych DNS).
- Zakładanie, że TLS/SSL wystarczy do ochrony przed przekierowaniem całego ruchu DNS (DNSSEC zabezpiecza sam proces rezolucji, zanim nawiążesz bezpieczne połączenie TLS).

**Głębokie wyjaśnienie techniczne:**
DNSSEC wykorzystuje kryptografię klucza publicznego (RRSIG, DNSKEY, DS) do cyfrowego podpisywania rekordów DNS w strefach (Zone Signing). Dzięki temu resolver DNS może zweryfikować łańcuch zaufania aż do punktu głównego (root zone) bez konieczności polegania wyłącznie na adresie IP serwera autorytatywnego, co drastycznie ogranicza skuteczność ataków typu MITM i cache poisoning.

Sugerowana odpowiedź: C

Analiza spornych kwestii (AI): Niektórzy kursanci mylą przejęcie domeny (hijacking) z atakami na aplikację (WAF). DNSSEC jest jedyną technologią w tym zestawieniu, która bezpośrednio adresuje 'zaufanie' do odpowiedzi z serwerów DNS, co jest fundamentem ochrony przed przekierowaniem użytkowników na fałszywe strony.
