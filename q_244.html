Question 244 / 361

Your company's users access data in a BigQuery table. You want to ensure they can only access the data during working hours. What should you do?

  • A. Assign a BigQuery Data Viewer role along with an IAM condition that limits the access to specified working hours.
  • B. Run a gsutil script that assigns a BigQuery Data Viewer role, and remove it only during the specified working hours.
  • C. Assign a BigQuery Data Viewer role to a service account that adds and removes the users daily during the specified working hours.
  • D. Configure Cloud Scheduler so that it triggers a Cloud Functions instance that modifies the organizational policy constraint for BigQuery during the specified working hours.
Show Suggested Answer Hide Answer
Suggested Answer: A

Wyjaśnienie

1. Prawidłowa odpowiedź lub odpowiedzi:
A. Assign a BigQuery Data Viewer role along with an IAM condition that limits the access to specified working hours.

2. Kompleksowe wyjaśnienie dlaczego dana odpowiedź jest prawidłowa (Analiza):
Odpowiedź A jest prawidłowa, ponieważ warunki IAM (IAM Conditions) są wbudowanym, deklaratywnym i w pełni zarządzanym przez GCP mechanizmem do ograniczania dostępu do zasobów na podstawie czasu (temporal access control).

Dlaczego to najlepsze rozwiązanie:
a. **IAM Conditions:** Pozwalają na definiowanie reguł sprawdzających atrybuty żądania. Możemy użyć atrybutu `request.time` i zdefiniować zakres godzin (np. 9:00 - 17:00 od poniedziałku do piątku).
b. **Automatyzacja i brak skryptów:** System IAM sam decyduje w locie, czy w momencie wysłania zapytania do BigQuery warunek czasu jest spełniony. Jeśli użytkownik spróbuje uzyskać dostęp o 20:00, otrzyma odmowę dostępu (Access Denied). Nie wymaga to uruchamiania żadnych zewnętrznych skryptów, zadań cron ani modyfikowania uprawnień w bazie danych.

3. Wyjaśnienie z osobna każdej niepoprawnej odpowiedzi:
B. Run a gsutil script that assigns a BigQuery Data Viewer role, and remove it only...
   * Dlaczego nieprawidłowa: Narzędzie `gsutil` służy do zarządzania zasobami w Cloud Storage (GCS), a nie w BigQuery. Ponadto ciągłe uruchamianie skryptów dodających i usuwających uprawnienia (tzw. provisioning/deprovisioning) jest podatne na awarie (np. jeśli skrypt nie zadziała, użytkownicy zachowają dostęp na noc) i generuje niepotrzebny narzut operacyjny.
C. Assign a BigQuery Data Viewer role to a service account that adds and removes the users daily...
   * Dlaczego nieprawidłowa: Podobnie jak opcja B, to podejście opiera się na zawodnych procesach automatyzacji (skrypty/konta serwisowe modyfikujące IAM w pętli). Może prowadzić do opóźnień (API rate limits dla IAM) oraz stwarza zagrożenie bezpieczeństwa, jeśli proces sprzątania uprawnień ulegnie awarii.
D. Configure Cloud Scheduler so that it triggers a Cloud Functions instance that modifies the organizational policy constraint...
   * Dlaczego nieprawidłowa: Polityki organizacji (Organization Policies) nakładają globalne ograniczenia na konfigurację zasobów (np. zakaz publicznego GCS, ograniczenie regionów), ale nie służą do przyznawania lub odbierania uprawnień do odczytu danych w BigQuery dla poszczególnych użytkowników w zależności od pory dnia.

4. Wskazówki, hinty, tips and tricks:
* Jeśli wymagane jest ograniczenie dostępu (Access Control) w określonych godzinach (working hours / specific time window) -> Zawsze używaj **IAM Conditions** z atrybutem czasu (`request.time`).
* Jest to rozwiązanie wbudowane bezpośrednio w system autoryzacji GCP i nie wymaga pisania kodu.

5. Reguły wyboru odpowiedzi (Słowa kluczowe):
* Access only during working hours -> IAM condition that limits the access.
