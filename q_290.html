Question 290 / 361

You are implementing communications restrictions for specific services in your Google Cloud organization. Your data analytics team works in a dedicated folder. You need to ensure that access to BigQuery is controlled for that folder and its projects. The data analytics team must be able to control the restrictions only at the folder level. What should you do?

  • A. Create an organization-level access policy with a service perimeter to restrict BigQuery access. Assign the data analytics team the Access Context Manager Editor role on the access policy to allow the team to configure the access policy.
  • B. Create a scoped policy on the folder with a service perimeter to restrict BigQuery access. Assign the data analytics team the Access Context Manager Editor role on the scoped policy to allow the team to configure the scoped policy.
  • C. Define a hierarchical firewall policy on the folder to deny BigQuery access. Assign the data analytics team the Compute Organization Firewall Policy Admin role to allow the team to configure rules for the firewall policy.
  • D. Enforce the Restrict Resource Service Usage organization policy constraint on the folder to restrict BigQuery access. Assign the data analytics team the Organization Policy Administrator role to allow the team to manage exclusions within the folder.
Show Suggested Answer Hide Answer
Suggested Answer: B

Wyjaśnienie

1. Prawidłowa odpowiedź lub odpowiedzi:
B. Create a scoped policy on the folder with a service perimeter to restrict BigQuery access. Assign the data analytics team the Access Context Manager Editor role on the scoped policy to allow the team to configure the scoped policy.

2. Kompleksowe wyjaśnienie dlaczego dana odpowiedź jest prawidłowa (Analiza):
Odpowiedź B jest prawidłowa, ponieważ scoped access policies (polityki o ograniczonym zasięgu) w ramach VPC Service Controls (VPC SC) pozwalają na bezpieczną delegację uprawnień administracyjnych perymetru do wybranego poziomu w hierarchii zasobów (np. folderu).

Mechanizm działania:
a. **Scoped Policy (Polityka z zakresem):** Tradycyjne polityki dostępu w Access Context Managerze są globalne dla całej organizacji. Stworzenie polityki o ograniczonym zasięgu (scoped policy) pozwala na powiązanie jej wyłącznie z określonym folderem (data analytics folder).
b. **Delegacja uprawnień (Least Privilege):** Nadanie zespołowi analitycznemu roli `Access Context Manager Editor` (Edytor Access Context Managera) bezpośrednio na tej scoped policy pozwala im na samodzielne tworzenie, modyfikowanie i usuwanie perymetrów oraz poziomów dostępu w obrębie ich folderu.
c. Zespół analityczny nie otrzymuje żadnych uprawnień administracyjnych do zasobów poza ich folderem (np. w projektach produkcyjnych innych działów), co gwarantuje pełne bezpieczeństwo i izolację administracyjną.

3. Wyjaśnienie z osobna każdej niepoprawnej odpowiedzi:
A. Create an organization-level access policy... Assign the data analytics team the Access Context Manager Editor role on the access policy...
   * Dlaczego nieprawidłowa: Przyznanie tej roli na poziomie polityki organizacji dałoby zespołowi analitycznemu uprawnienia do modyfikowania perymetrów bezpieczeństwa we WSZYSTKICH folderach i projektach w całej firmie. Narusza to wymóg ograniczający kontrolę "wyłącznie do ich folderu" (only at the folder level).
C. Define a hierarchical firewall policy on the folder to deny BigQuery access...
   * Dlaczego nieprawidłowa: Hierarchical firewall policies filtrują ruch sieciowy IP na poziomie maszyn wirtualnych. Nie kontrolują dostępu do API usług zarządzanych Google, takich jak BigQuery, które są chronione na poziomie tożsamości i za pomocą VPC Service Controls, a nie reguł sieciowych L3/L4.
D. Enforce the Restrict Resource Service Usage organization policy constraint...
   * Dlaczego nieprawidłowa: Ograniczenie polityki organizacji `gcp.restrictServiceUsage` całkowicie blokuje możliwość włączania i używania danej usługi (np. deweloperzy nie mogliby w ogóle uruchomić BigQuery). Pytanie wymaga kontrolowania bezpiecznego dostępu do BigQuery (za pomocą perymetru sieciowego VPC SC), a nie jego całkowitego zablokowania w folderze.

4. Wskazówki, hinty, tips and tricks:
* Delegacja zarządzania VPC Service Controls do określonego Folderu lub Projektu -> Używaj **Scoped Access Policies** w Access Context Managerze.
* Zapobiega to nadawaniu uprawnień administracyjnych w skali całej organizacji.

5. Reguły wyboru odpowiedzi (Słowa kluczowe):
* Control VPC SC restrictions only at the folder level -> Scoped policy on the folder + Access Context Manager Editor role.

6. Dodatkowe źródła i dokumentacja:
Scoped access policies for VPC Service Controls
IAM roles for Access Context Manager

Wskazówki egzaminacyjne (Tips & Tricks)

Reguła Egzaminacyjna (Exam Rule): 
W pytaniach typu 'Security in GCP', zawsze priorytetyzuj rozwiązania natywne (SCC, Cloud KMS, Secret Manager, VPC SC) nad rozwiązaniami typu 'third-party' lub 'self-managed', chyba że scenariusz wymaga specyficznej integracji hybrydowej.

Haczyki egzaminacyjne (Exam Traps):
- Pułapka 'Least Privilege': Egzamin często podpowiada role o szerokim zakresie (np. 'Editor' lub 'Owner') – zawsze odrzucaj je na rzecz ról predefiniowanych o najmniejszym zakresie uprawnień.
- Pułapka 'Logging vs Monitoring': Pamiętaj: Audit Logs służą do badania aktywności (Who/What/When), a Monitoring do zbierania metryk wydajnościowych.

Głębokie wyjaśnienie techniczne:
Każda architektura bezpieczeństwa w GCP powinna być projektowana w oparciu o 'Security by Default'. Oznacza to m.in. szyfrowanie w spoczynku (domyślne), tożsamość opartą na rolach (IAM) oraz pełną widoczność zapewnianą przez scentralizowane logowanie (Cloud Logging/SCC).
