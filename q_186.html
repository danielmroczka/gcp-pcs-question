Question 186 / 361

You have stored company approved compute images in a single Google Cloud project that is used as an image repository. This project is protected with VPC Service Controls and exists in the perimeter along with other projects in your organization. This lets other projects deploy images from the image repository project. A team requires deploying a third-party disk image that is stored in an external Google Cloud organization. You need to grant read access to the disk image so that it can be deployed into the perimeter.
What should you do?

  • A. Allow the external project by using the organizational policy, constraints/compute.trustedImageProjects.
  • B. 1. Update the perimeter. 2. Configure the egressTo field to include the external Google Cloud project number as an allowed resource and the serviceName to compute.googleapis.com. 3. Configure the egressFrom field to set identityType to ANY_IDENTITY.
  • C. 1. Update the perimeter. 2. Configure the ingressFrom field to set identityType to ANY_IDENTITY. 3. Configure the ingressTo field to include the external Google Cloud project number as an allowed resource and the serviceName to compute.googleapis.com.
  • D. 1. Update the perimeter. 2. Configure the egressTo field to set identityType to ANY_IDENTITY. 3. Configure the egressFrom field to include the external Google Cloud project number as an allowed resource and the serviceName to compute.googleapis.com.

Suggested Answer: B

Wyjaśnienie

Poprawna odpowiedź: B (1. Update the perimeter. 2. Configure the egressTo field to include the external Google Cloud project number as an allowed resource and the serviceName to compute.googleapis.com. 3. Configure the egressFrom field to set identityType to ANY_IDENTITY)

Dlaczego ta odpowiedź jest poprawna:
- Kierunek ruchu (Egress): Żądanie o pobranie obrazu wychodzi z Twojego perymetru do zewnętrznego projektu Google Cloud. W terminologii VPC SC jest to ruch typu "Egress" (wyjście).
- egressTo: To pole definiuje CEL wyjścia. Musisz określić projekt zewnętrzny (jako zasób) oraz konkretną usługę Google Cloud, z której chcesz skorzystać (w tym przypadku `compute.googleapis.com` dla obrazów dysków).
- egressFrom: To pole definiuje ŹRÓDŁO (tożsamość) żądania. Ustawienie `identityType: ANY_IDENTITY` pozwala każdemu uwierzytelnionemu użytkownikowi/kontu serwisowemu wewnątrz perymetru na próbę połączenia z tym zewnętrznym celem (o ile posiadają odpowiednie uprawnienia IAM).
- VPC Service Controls: Standardowo perymetr blokuje wszelką komunikację z usługami Google Cloud poza perymetrem. Reguły Egress są jedynym bezpiecznym sposobem na "wycięcie dziury" w perymetrze dla konkretnych, zaufanych celów zewnętrznych.

Analiza niepoprawnych odpowiedzi:
- A. Organization policy (trustedImageProjects): Ta polityka ogranicza to, co MOŻNA zrobić w Twoim projekcie, ale nie znosi blokady sieciowej narzuconej przez VPC Service Controls. Nawet jeśli polityka pozwoli na obraz, VPC SC zablokuje samo wywołanie API do zewnętrznego projektu.
- C. Ingress rule: Reguły Ingress służą do wpuszczania ruchu Z ZEWNĄTRZ perymetru do Twoich chronionych zasobów. Tutaj sytuacja jest odwrotna – to Ty chcesz sięgnąć "na zewnątrz".
- D. Egress swap: Ta opcja błędnie przypisuje parametry. `egressTo` powinno zawierać cel (projekt/usługa), a `egressFrom` tożsamość.

Wskazówki i triki (Tips & Tricks):
- "External project" + "Inside perimeter" = VPC SC Egress/Ingress Rule.
- Egress = Wychodzimy z perymetru do zewnętrznego API Google.
- Ingress = Ktoś z zewnątrz perymetru puka do naszego API Google.
- Pamiętaj: Reguły VPC SC działają na poziomie API, a nie na poziomie IP (to nie jest firewall VPC).

Praktyczne informacje na egzamin:
- Zrozum strukturę reguły: FROM (kto pyta?) -> TO (o co pyta?).
- Egress rules są kluczowe w scenariuszach B2B i współpracy między różnymi organizacjami GCP.

Analiza i Podsumowanie (AI)

Kluczowe zagadnienia

Sugerowana odpowiedź: B

Analiza strategiczna: To pytanie testuje Twoją znajomość zaawansowanych konfiguracji "Data Exfiltration Protection". VPC SC to nie tylko blokowanie, ale precyzyjne sterowanie przepływem danych między organizacjami. Zrozumienie, że pobranie zasobu z zewnątrz to "Egress" żądania API, jest kluczowe dla inżyniera bezpieczeństwa.

Dodatkowe wskazówki

  • Możesz używać "Perimeter Bridges" zamiast reguł Egress, jeśli oba projekty są w tej samej organizacji, ale Egress/Ingress jest bardziej elastyczny dla współpracy międzyorganizacyjnej.
  • Pamiętaj o audycie: Blokady VPC SC są logowane w Cloud Audit Logs (policy denied), co pomaga w debugowaniu tych reguł.
