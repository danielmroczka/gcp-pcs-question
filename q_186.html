Question 186 / 361

You have stored company approved compute images in a single Google Cloud project that is used as an image repository. This project is protected with VPC Service Controls and exists in the perimeter along with other projects in your organization. This lets other projects deploy images from the image repository project. A team requires deploying a third-party disk image that is stored in an external Google Cloud organization. You need to grant read access to the disk image so that it can be deployed into the perimeter.
What should you do?

  • A. Allow the external project by using the organizational policy, constraints/compute.trustedImageProjects.
  • B. 1. Update the perimeter. 2. Configure the egressTo field to include the external Google Cloud project number as an allowed resource and the serviceName to compute.googleapis.com. 3. Configure the egressFrom field to set identityType to ANY_IDENTITY.
  • C. 1. Update the perimeter. 2. Configure the ingressFrom field to set identityType to ANY_IDENTITY. 3. Configure the ingressTo field to include the external Google Cloud project number as an allowed resource and the serviceName to compute.googleapis.com.
  • D. 1. Update the perimeter. 2. Configure the egressTo field to set identityType to ANY_IDENTITY. 3. Configure the egressFrom field to include the external Google Cloud project number as an allowed resource and the serviceName to compute.googleapis.com.
Show Suggested Answer Hide Answer
Suggested Answer: B

Wyjaśnienie

1. Prawidłowa odpowiedź lub odpowiedzi:
B. 1. Update the perimeter. 2. Configure the egressTo field to include the external Google Cloud project number as an allowed resource and the serviceName to compute.googleapis.com. 3. Configure the egressFrom field to set identityType to ANY_IDENTITY.

2. Kompleksowe wyjaśnienie dlaczego dana odpowiedź jest prawidłowa (Analiza):
Perymetr VPC Service Controls (VPC SC) chroni zasoby wewnątrz przed nieuprawnionym wyciekiem danych (eksfiltracją) oraz przed komunikacją z zewnętrznymi usługami API Google Cloud. W tym przypadku projekt będący repozytorium obrazów znajduje się wewnątrz perymetru, a zespół musi wdrożyć obraz z zewnętrznego projektu (znajdującego się poza organizacją/perymetrem).
Połączenie w celu pobrania zewnętrznego dysku wychodzi z wewnątrz perymetru do zewnętrznego projektu Google Cloud. W terminologii VPC SC jest to ruch wychodzący (Egress).
Aby to umożliwić:
1. Należy zmodyfikować konfigurację perymetru.
2. W sekcji `egressTo` należy określić cel – numer zewnętrznego projektu jako dozwolony zasób (resource) oraz usługę API, z którą się łączymy (`compute.googleapis.com`).
3. W sekcji `egressFrom` ustalamy tożsamość, która może to wyjście zainicjować. Ustawienie `identityType` na `ANY_IDENTITY` zezwala na to dowolnej uwierzytelnionej tożsamości z wewnątrz perymetru (która posiada również odpowiednie uprawnienia IAM do pobrania obrazu).

3. Wyjaśnienie z osobna każdej niepoprawnej odpowiedzi:
- A. Allow the external project by using the organizational policy, constraints/compute.trustedImageProjects: Polityka organizacji `compute.trustedImageProjects` pozwala autoryzować projekty wewnątrz architektury GCP pod kątem uprawnień, ale nie znosi sieciowych blokad dostępu do API nakładanych przez perymetr VPC SC. Usługa Compute Engine wciąż nie mogłaby pobrać obrazu z zewnętrznego projektu z powodu blokady API przez VPC SC.
- C. Configure the ingressFrom... ingressTo...: Reguły Ingress służą do wpuszczania ruchu z zewnątrz perymetru do wewnątrz. Tutaj inicjatorem połączenia jest usługa wewnątrz perymetru próbująca sięgnąć po zewnętrzny obraz – jest to typowy scenariusz Egress.
- D. Configure the egressTo field to set identityType to ANY_IDENTITY...: Opcja ta zamienia konfigurację pól miejscami – tożsamość źródłowa (`ANY_IDENTITY`) musi być zdefiniowana w sekcji `egressFrom` (skąd ruch wychodzi), a cel (zewnętrzny projekt i usługa) w sekcji `egressTo` (dokąd ruch zmierza).

4. Wskazówki, hinty, tips and tricks:
- Egress = ruch wychodzący z perymetru na zewnątrz. Ingress = ruch wchodzący do perymetru z zewnątrz.
- `egressFrom` odpowiada na pytanie "kto/skąd" (identity, source).
- `egressTo` odpowiada na pytanie "dokąd/co" (destination resource, service name).

5. Reguły wyboru odpowiedzi (Słowa kluczowe):
- "VPC Service Controls perimeter" + "deploy image from external project" -> Egress Rule -> `egressTo` (external project, compute.googleapis.com) + `egressFrom` (ANY_IDENTITY).

6. Dodatkowe źródła i dokumentacja:
- Ingress and egress rules configuration: https://cloud.google.com/vpc-service-controls/docs/ingress-egress-rules
