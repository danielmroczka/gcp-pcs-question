Question 53 / 361

A customer deployed an application on Compute Engine that takes advantage of the elastic nature of cloud computing. How can you work with Infrastructure Operations Engineers to best ensure that Windows Compute Engine VMs are up to date with all the latest OS patches?

  • A. Build new base images when patches are available, and use a CI/CD pipeline to rebuild VMs, deploying incrementally.
  • B. Federate a Domain Controller into Compute Engine, and roll out weekly patches via Group Policy Object.
  • C. Use Deployment Manager to provision updated VMs into new serving Instance Groups (IGs).
  • D. Reboot all VMs during the weekly maintenance window and allow the StartUp Script to download the latest patches from the internet.
Show Suggested Answer Hide Answer
Suggested Answer: A

Wyjaśnienie

Potwierdzona odpowiedź: A

Wyjaśnienie:
W nowoczesnych środowiskach chmurowych najlepszą praktyką zarządzania aktualizacjami jest stosowanie koncepcji "Immutable Infrastructure" (infrastruktura niezmienna). Zamiast aktualizować (patchować) działające instancje, co może prowadzić do tzw. "configuration drift" (rozbieżności w konfiguracji), tworzy się nowy, zaktualizowany obraz bazowy (tzw. Golden Image). Następnie, za pomocą potoku CI/CD, stare instancje są zastępowane nowymi, utworzonymi z tego obrazu, przy użyciu mechanizmów takich jak "Rolling Updates" w Managed Instance Groups (MIGs). Gwarantuje to spójność, testowalność i szybkość przywracania środowiska.

Dlaczego pozostałe opcje są niepoprawne:
- B: Stosowanie GPO (Group Policy Objects) to tradycyjne podejście on-premises. W chmurze jest ono trudniejsze do monitorowania, wolniejsze i nie zapewnia, że nowo wyskalowane instancje będą miały poprawki od razu po uruchomieniu (zanim GPO się zaaplikuje).
- C: Sam Deployment Manager służy do definiowania zasobów (IaC), ale bez integracji z procesem budowania obrazów i automatyzacją wdrożeń (CI/CD) nie stanowi kompletnego rozwiązania problemu regularnego patchowania.
- D: Pobieranie aktualizacji przez StartUp Script przy każdym starcie instancji drastycznie wydłuża czas jej gotowości do pracy (co psuje zaletę elastyczności/autoskalowania). Ponadto wprowadza ryzyko, że błąd w zewnętrznym repozytorium uniemożliwi uruchomienie nowych serwerów.

Tips & Tricks:
- Gdy widzisz "latest OS patches" + "elastic/cloud-native", szukaj odpowiedzi promujących automatyzację budowania obrazów (Golden Images) i potoki CI/CD.
- Unikaj rozwiązań, które aktualizują system "w locie" na działających maszynach (In-place patching).
- "Immutable Infrastructure" to kluczowe hasło w egzaminach architektonicznych i bezpieczeństwa GCP.

Zagadnienia:
- Immutable Infrastructure (Infrastruktura niezmienna)
- Golden Images (Wzorcowe obrazy)
- Managed Instance Groups (MIGs) Rolling Updates
- CI/CD dla Infrastruktury

Analiza i Podsumowanie (Egzamin)

Kluczowe wnioski

Potwierdzona odpowiedź: A

Zapewnienie bezpieczeństwa na poziomie systemu operacyjnego w chmurze wymaga odejścia od manualnego patchowania. Google promuje automatyzację cyklu życia obrazów, co pozwala na szybką reakcję na nowe podatności (Zero-day vulnerabilities) poprzez szybkie wypchnięcie nowej wersji obrazu do floty serwerów.

Praktyczne wskazówki

  • Warto znać narzędzie VM Manager (Cloud OS Config), które w rzeczywistości pomaga zarządzać patchami w GCP, ale w kontekście tego pytania egzaminacyjnego nacisk położony jest na architektoniczną koncepcję niezmienności.
  • Jeśli pytanie wspomina o "autoskalowaniu" lub "elastyczności", odrzuć rozwiązania spowalniające start instancji (jak duże skrypty startowe).
