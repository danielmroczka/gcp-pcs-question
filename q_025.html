Question 25 / 361

Your team needs to configure their Google Cloud Platform (GCP) environment so they can centralize the control over networking resources like firewall rules, subnets, and routes. They also have an on-premises environment where resources need access back to the GCP resources through a private VPN connection.
The networking resources will need to be controlled by the network security team.
Which type of networking design should your team use to meet these requirements?

  • A. Shared VPC Network with a host project and service projects
  • B. Grant Compute Admin role to the networking team for each engineering project
  • C. VPC peering between all engineering projects using a hub and spoke model
  • D. Cloud VPN Gateway between all engineering projects using a hub and spoke model
Show Suggested Answer Hide Answer
Suggested Answer: A

Wyjaśnienie

**Poprawna odpowiedź: A**

**1. Kompleksowe wyjaśnienie poprawnej odpowiedzi:**
Wymagania to:
- Scentralizowanie kontroli nad zasobami sieciowymi (firewalle, podsieci, trasy) w jednym ręku (zespół ds. bezpieczeństwa sieci).
- Połączenie sieci hybrydowej (VPN) z on-premises.
- Możliwość tworzenia zasobów przez inne zespoły inżynieryjne w dedykowanych projektach.
Idealnym wzorcem projektowym dla takich założeń w GCP jest:
- **Shared VPC Network (Współdzielona sieć VPC) z projektem hosta i projektami usługowymi (A):** Projekt hosta (host project) zawiera wspólną sieć VPC, podsieci, bramę VPN i reguły zapory sieciowej kontrolowane przez zespół sieciowy. Projekty usługowe (service projects) są podpięte pod hosta, co pozwala deweloperom na uruchamianie swoich maszyn VM, ale uniemożliwia im modyfikowanie konfiguracji sieci i zapór.

**2. Wyjaśnienie niepoprawnych odpowiedzi:**
- **B. Przypisanie roli Compute Admin w każdym projekcie:** Narusza to zasadę najmniejszych uprawnień. Zespół sieciowy miałby pełne prawa administracyjne do maszyn wirtualnych deweloperów, a z kolei deweloperzy mogliby tworzyć własne sieci lokalnie, co uniemożliwia centralizację.
- **C. VPC Peering w modelu hub and spoke:** Przy dużej skali zarządzanie peeringami staje się skomplikowane (limity peeringów w VPC) i nie pozwala na tak ścisłą centralizację zasobów sieciowych jak Shared VPC (każda sieć VPC w peeringu nadal ma własne reguły zapory).
- **D. Cloud VPN Gateway między wszystkimi projektami:** Tworzenie tuneli VPN między projektami wewnątrz chmury generuje ogromne koszty, narzut konfiguracyjny i opóźnienia sieciowe.

**3. Wskazówki i pułapki egzaminacyjne (Tips & Tricks):**
- Słowo-klucz: **centralize control over networking resources** w organizacji o wielu projektach. Prawidłową odpowiedzią jest zawsze **Shared VPC**.
- W Shared VPC rozróżnia się projekt hosta (zawiera sieć) i projekty usługowe (konsumują sieć).

**4. Reguły wyboru odpowiedzi:**
- Centralny zespół sieciowy + wiele projektów korzystających z sieci -> Shared VPC.

**5. Dodatkowe źródła:**
- Shared VPC Overview: https://cloud.google.com/vpc/docs/shared-vpc

Analiza i Wyjaśnienie

Sugerowana odpowiedź: A

Analiza spornych kwestii (AI): Shared VPC rozwiązuje problem tzw. "Shadow IT" w sieciach. Deweloperzy mogą bezpiecznie tworzyć zasoby (VM, klastry), ale to zespół bezpieczeństwa i sieci decyduje, jakie porty są otwarte i jak wygląda routing, co jest kluczowe w regulowanych środowiskach (np. PCI DSS).
