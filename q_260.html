Question 260 / 361

Your organization uses Google Cloud to process large amounts of location data for analysis and visualization. The location data is potentially sensitive. You must design a solution that allows storing and processing the location data securely, minimizing data exposure risks, and adhering to both regulatory guidelines and your organization's internal data residency policies. What should you do?

  • A. Enable location restrictions on Compute Engine instances and virtual disk resources where the data is handled. Apply labels to tag geographic metadata for all stored data.
  • B. Use the Cloud Data Loss Prevention (Cloud DLP) API to scan for sensitive location data before any storage or processing. Create Cloud Storage buckets with global availability for optimal performance, relying on Cloud DLP results to filter and control data access.
  • C. Create regional Cloud Storage buckets with Object

Suggested Answer: N/A

Wyjaśnienie

1. Prawidłowa odpowiedź lub odpowiedzi:
C. Create regional Cloud Storage buckets with Object [Lifecycle Management to transition data and encrypt with CMEK].

2. Kompleksowe wyjaśnienie dlaczego dana odpowiedź jest prawidłowa (Analiza):
Odpowiedź C jest prawidłowa, ponieważ użycie regionalnych kubełków Cloud Storage (Regional Buckets) w wyznaczonych lokalizacjach geograficznych bezpośrednio spełnia wymagania dotyczące rezydentności danych (Data Residency). Dane w regionalnym kubełku fizycznie rezydują w wybranym centrum danych (np. europe-west1) i nie są replikowane poza ten obszar.

Dlaczego to najlepsze podejście:
a. **Spełnienie polityk rezydentności:** Wybór konkretnego regionu w Europie (np. regional bucket) gwarantuje zgodność z wewnętrznymi i prawnymi zasadami suwerenności danych.
b. **Zarządzanie cyklem życia (Object Lifecycle Management):** Pozwala na automatyczne usuwanie lub przenoszenie starych danych lokalizacyjnych do tańszych klas przechowywania (optymalizacja kosztów i minimalizacja ekspozycji danych).
c. **Ochrona danych wrażliwych:** Połączenie regionalności z szyfrowaniem kluczami zarządzanymi przez klienta (CMEK) zapewnia, że dane są chronione na najwyższym poziomie i w pełni kontrolowane przez firmę.

3. Wyjaśnienie z osobna każdej niepoprawnej odpowiedzi:
A. Enable location restrictions on Compute Engine instances... Apply labels...
   * Dlaczego nieprawidłowa: Same etykiety (labels) to tylko metadane organizacyjne. Nie wymuszają fizycznej blokady zapisu i lokalizacji danych. Ponadto polityka musi dotyczyć bezpośrednio przechowywania (Storage), a nie tylko maszyn wirtualnych Compute Engine.
B. Use the Cloud Data Loss Prevention (Cloud DLP) API... Create Cloud Storage buckets with global availability...
   * Dlaczego nieprawidłowa: Stworzenie kubła o globalnej dostępności (multi-region lub global) powoduje, że dane są automatycznie replikowane do różnych regionów na świecie (np. poza Europę). Narusza to podstawowe wymaganie dotyczące lokalnych polityk rezydentności danych, nawet jeśli Cloud DLP zidentyfikuje wrażliwe dane.

4. Wskazówki, hinty, tips and tricks:
* Wymagania dotyczące suwerenności i rezydentności danych (Data Residency) w Cloud Storage -> Zawsze używaj **Regional Buckets** w zdefiniowanych, zgodnych regionach (compliant regions).
* Unikaj kubełków wieloregionowych (multi-region) lub globalnych, jeśli prawo nakazuje przechowywanie danych wyłącznie w określonym państwie/kontynencie.

5. Reguły wyboru odpowiedzi (Słowa kluczowe):
* Adhering to data residency policies for storage -> Regional Cloud Storage buckets.
