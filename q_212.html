Question 212 / 361

Your company is moving to Google Cloud. You plan to sync your users first by using Google Cloud Directory Sync (GCDS). Some employees have already created Google Cloud accounts by using their company email addresses that were created outside of GCDS. You must create your users on Cloud Identity. What should you do?

  • A. Configure GCDS and use GCDS search rules to sync these users.
  • B. Use the transfer tool to migrate unmanaged users.
  • C. Write a custom script to identify existing Google Cloud users and call the Admin SDK: Directory API to transfer their account.
  • D. Configure GCDS and use GCDS exclusion rules to ensure users are not suspended.
Show Suggested Answer Hide Answer
Suggested Answer: B

Wyjaśnienie

Potwierdzona odpowiedź: B (Use the transfer tool to migrate unmanaged users)

Wyjaśnienie:
- Konta niezarządzane (Unmanaged Users): To konta osobiste Google, które pracownicy założyli samodzielnie przy użyciu służbowych adresów e-mail (np. przed wdrożeniem Cloud Identity w firmie). Gdy firma zaczyna zarządzać swoją domeną w Google, konta te stają się tzw. "kontami konfliktowymi".
- Transfer Tool for Unmanaged Users (TTUU): Jest to dedykowane narzędzie w konsoli administracyjnej Google, stworzone dokładnie po to, aby:
  1. Odkryć wszystkich pracowników, którzy posiadają takie konta osobiste w domenie firmy.
  2. Wysłanie im oficjalnej prośby (zaproszenia) o przeniesienie konta pod zarząd organizacji.
  3. Po zaakceptowaniu przez użytkownika, konto staje się kontem zarządzanym, a administrator zyskuje nad nim pełną kontrolę (hasło, MFA, audyt).
- Skuteczność: Jest to jedyny zautomatyzowany sposób na migrację istniejących kont osobistych do Cloud Identity przy jednoczesnym zachowaniu danych użytkownika (np. plików na Google Drive).

Dlaczego pozostałe odpowiedzi są niepoprawne:
- A. GCDS search rules: Google Cloud Directory Sync (GCDS) służy do tworzenia NOWYCH kont w Google na podstawie danych z Twojego lokalnego katalogu (np. Active Directory). Jeśli GCDS spróbuje stworzyć konto dla adresu, który już istnieje jako konto osobiste, wystąpi błąd konfliktu. GCDS nie potrafi samodzielnie migrować typów kont.
- C. Custom script and Admin SDK: Choć Admin SDK pozwala na wiele operacji, transfer konta wymaga interakcji z użytkownikiem (zgodna na transfer) ze względów prawnych i prywatności. Pisanie własnego skryptu do tego procesu jest niepotrzebnie skomplikowane i ryzykowne, skoro istnieje gotowe narzędzie (TTUU).
- D. GCDS exclusion rules: Reguły wykluczenia (exclusion rules) służą jedynie do pomijania pewnych użytkowników podczas synchronizacji (np. aby GCDS ich nie usunął lub nie zawiesił). Nie pomagają w żaden sposób w migracji kont niezarządzanych.

Wskazówki i triki (Tips & Tricks):
- "Unmanaged users" / "Corporate email used for personal accounts" = Transfer Tool.
- "Sync users from AD" = GCDS.
- Pamiętaj o procesie: Najpierw używasz Transfer Tool, aby "przejąć" istniejące konta, a potem GCDS, aby utrzymać synchronizację danych (np. nazwisko, przynależność do grup).

Praktyczne informacje na egzamin:
- Zrozum konsekwencje: Jeśli użytkownik odmówi transferu, administrator może wymusić na nim zmianę adresu e-mail konta osobistego na inny (np. @gmail.com), co "uwalnia" adres służbowy dla nowego konta zarządzanego.
- Transfer Tool pozwala na monitorowanie postępu migracji w czasie rzeczywistym.

Wskazówki egzaminacyjne (Tips & Tricks)

Reguła Egzaminacyjna (Exam Rule): 
Jeśli scenariusz dotyczy zabezpieczania zasobów chmurowych (GCP), zawsze wybieraj rozwiązanie typu Managed (SCC, Secret Manager, Cloud KMS), a unikaj rozwiązań self-managed, chyba że pytanie wyraźnie wymaga dostosowania niskopoziomowego.

Haczyki egzaminacyjne (Exam Traps):
- Pułapka IAM: Pytania o uprawnienia często sugerują 'Project Owner' – zawsze szukaj 'Least Privilege' (np. 'Role: Secret Manager Secret Accessor').
- Pułapka Sieciowa: Często mylone są VPC Peering (wydajność) oraz VPN (szyfrowanie/on-premise).

Głębokie wyjaśnienie techniczne:
Rozwiązanie bazuje na GCP Shared Responsibility Model. Google zarządza bezpieczeństwem infrastruktury (Physical, Network, Host), podczas gdy administrator zarządza tożsamością (IAM), danymi (Encryption, Cloud KMS) i regułami dostępu (VPC Firewall).

Analiza i Podsumowanie (AI)

Kluczowe zagadnienia

Sugerowana odpowiedź: B

Analiza strategiczna: To klasyczne pytanie o proces "Onboarding" organizacji do Google Cloud. Największym wyzwaniem nie jest technologia, ale ludzie i ich przyzwyczajenia. Transfer Tool jest eleganckim rozwiązaniem, które balansuje potrzeby bezpieczeństwa korporacyjnego z prawami użytkowników do ich danych. Pamiętaj, że w GCP tożsamość użytkownika jest nadrzędna nad wszystkim innym.

Dodatkowe wskazówki

  • Warto wiedzieć, że po transferze użytkownik może otrzymać rolę "Conflicting Account User", co ułatwia administratorowi ich identyfikację w systemie.
  • Narzędzie to jest darmowe i dostępne w konsoli administracyjnej pod adresem: Menu > Katalog > Użytkownicy > Narzędzie do przenoszenia użytkowników niezarządzanych.
