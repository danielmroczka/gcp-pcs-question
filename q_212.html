Question 212 / 361

Your company is moving to Google Cloud. You plan to sync your users first by using Google Cloud Directory Sync (GCDS). Some employees have already created Google Cloud accounts by using their company email addresses that were created outside of GCDS. You must create your users on Cloud Identity. What should you do?

  • A. Configure GCDS and use GCDS search rules to sync these users.
  • B. Use the transfer tool to migrate unmanaged users.
  • C. Write a custom script to identify existing Google Cloud users and call the Admin SDK: Directory API to transfer their account.
  • D. Configure GCDS and use GCDS exclusion rules to ensure users are not suspended.
Show Suggested Answer Hide Answer
Suggested Answer: B

Wyjaśnienie

1. Prawidłowa odpowiedź lub odpowiedzi:
B. Use the transfer tool to migrate unmanaged users.

2. Kompleksowe wyjaśnienie dlaczego dana odpowiedź jest prawidłowa (Analiza):
Odpowiedź B jest prawidłowa, ponieważ narzędzie do transferu użytkowników niezarządzanych (Transfer Tool for Unmanaged Users) jest oficjalnym i bezpiecznym mechanizmem Google służącym do przejmowania kontroli nad osobistymi kontami Google, które pracownicy utworzyli samodzielnie przy użyciu służbowych adresów e-mail.

Mechanizm działania:
a. Kiedy weryfikujesz domenę firmy w Cloud Identity/Workspace, system wykrywa tzw. konta konfliktowe (unmanaged accounts) – konta konsumenckie zarejestrowane na e-maile w tej domenie.
b. Narzędzie transferu pozwala administratorowi wysłać zaproszenie do tych użytkowników z prośbą o przeniesienie ich konta pod zarządzanie organizacji.
c. Po zaakceptowaniu zaproszenia przez pracownika, jego konto (wraz z istniejącymi danymi GCP/Drive) staje się kontem zarządzanym centralnie przez Twoją firmę, a jego cykl życia może być kontrolowany przez GCDS.

3. Wyjaśnienie z osobna każdej niepoprawnej odpowiedzi:
A. Configure GCDS and use GCDS search rules to sync these users.
   * Dlaczego nieprawidłowa: GCDS służy do jednostronnej synchronizacji (aprowizacji) tożsamości z LDAP do Google. Jeśli spróbujemy zsynchronizować użytkownika o tym samym adresie e-mail bez uprzedniego rozwiązania konfliktu kont, proces zakończy się błędem lub utworzeniem konta tymczasowego, a istniejące dane użytkownika nie zostaną zmigrowane.
C. Write a custom script to identify existing Google Cloud users and call the Admin SDK...
   * Dlaczego nieprawidłowa: Pisanie niestandardowych skryptów jest skomplikowane i niepotrzebne, ponieważ Google udostępnia gotowe, wbudowane narzędzie w konsoli administracyjnej do tego celu. Ponadto Admin API nie pozwala na wymuszenie transferu konta osobistego bez zgody użytkownika i przejścia procesu migracji.
D. Configure GCDS and use GCDS exclusion rules to ensure users are not suspended.
   * Dlaczego nieprawidłowa: Reguły wykluczenia (exclusion rules) zapobiegają modyfikacjom określonych kont w GCP przez proces synchronizacji GCDS, ale nie rozwiązują problemu unmanaged users – te konta nadal pozostaną osobiste i poza kontrolą bezpieczeństwa firmy.

4. Wskazówki, hinty, tips and tricks:
* Konta konfliktowe (konfiguracyjne adresy e-mail powtarzające się jako konta osobiste Google i konta firmowe) -> Rozwiązaniem jest zawsze **Transfer Tool for Unmanaged Users** w Google Admin Console.
* GCDS nie potrafi samodzielnie migrować lub łączyć kont osobistych z firmowymi bez zgody użytkownika.

5. Reguły wyboru odpowiedzi (Słowa kluczowe):
* Istniejące konta Google utworzone poza organizacją (unmanaged users) -> Transfer tool.

6. Dodatkowe źródła i dokumentacja:
Transfer tool for unmanaged users
Migrating consumer accounts to Cloud Identity

Wskazówki egzaminacyjne (Tips & Tricks)

Reguła Egzaminacyjna (Exam Rule): 
Jeśli scenariusz dotyczy zabezpieczania zasobów chmurowych (GCP), zawsze wybieraj rozwiązanie typu Managed (SCC, Secret Manager, Cloud KMS), a unikaj rozwiązań self-managed, chyba że pytanie wyraźnie wymaga dostosowania niskopoziomowego.

Haczyki egzaminacyjne (Exam Traps):
- Pułapka IAM: Pytania o uprawnienia często sugerują 'Project Owner' – zawsze szukaj 'Least Privilege' (np. 'Role: Secret Manager Secret Accessor').
- Pułapka Sieciowa: Często mylone są VPC Peering (wydajność) oraz VPN (szyfrowanie/on-premise).

Głębokie wyjaśnienie techniczne:
Rozwiązanie bazuje na GCP Shared Responsibility Model. Google zarządza bezpieczeństwem infrastruktury (Physical, Network, Host), podczas gdy administrator zarządza tożsamością (IAM), danymi (Encryption, Cloud KMS) i regułami dostępu (VPC Firewall).

Analiza i Podsumowanie (AI)

Kluczowe zagadnienia

Sugerowana odpowiedź: B

Analiza strategiczna: To klasyczne pytanie o proces "Onboarding" organizacji do Google Cloud. Największym wyzwaniem nie jest technologia, ale ludzie i ich przyzwyczajenia. Transfer Tool jest eleganckim rozwiązaniem, które balansuje potrzeby bezpieczeństwa korporacyjnego z prawami użytkowników do ich danych. Pamiętaj, że w GCP tożsamość użytkownika jest nadrzędna nad wszystkim innym.

Dodatkowe wskazówki

  • Warto wiedzieć, że po transferze użytkownik może otrzymać rolę "Conflicting Account User", co ułatwia administratorowi ich identyfikację w systemie.
  • Narzędzie to jest darmowe i dostępne w konsoli administracyjnej pod adresem: Menu > Katalog > Użytkownicy > Narzędzie do przenoszenia użytkowników niezarządzanych.
