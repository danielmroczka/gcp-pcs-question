Question 277 / 361

You work for a large organization that is using Cloud Identity as the identity provider (IdP) on Google Cloud. Your InfoSec team has mandated the enforcement of a strong password with a length between 12 and 16 characters for all users. After configuring this requirement, users are still able to access the Google Cloud console with passwords that are less than 12 characters. You need to fix this problem within the Admin console. What should you do?

  • A. Review each user's password configuration and reset existing passwords.
  • B. Review the organization password management setting and select Enforce password policy at the next sign-in.
  • C. Review each user's password configuration and select Enforce strong password.
  • D. Review the organization password management setting and select Enforce strong password.
Show Suggested Answer
Suggested Answer: B

Wyjaśnienie

1. Prawidłowa odpowiedź lub odpowiedzi:
B. Review the organization password management setting and select Enforce password policy at the next sign-in.

2. Kompleksowe wyjaśnienie dlaczego dana odpowiedź jest prawidłowa (Analiza):
Odpowiedź B jest prawidłowa, ponieważ zmiana ustawień polityki haseł (np. wymuszenie minimalnej długości 12 znaków) w konsoli administracyjnej Google Workspace / Cloud Identity domyślnie dotyczy tylko nowych haseł lub kolejnych zmian haseł wykonywanych przez użytkowników.

Dlaczego ten krok jest wymagany:
a. Użytkownicy posiadający aktualnie słabsze hasła (np. 8 znaków) mogą nadal logować się do konsoli GCP przy użyciu swoich dotychczasowych, aktywnych haseł, ponieważ system nie zmusza ich automatycznie do zmiany.
b. Zaznaczenie opcji "Enforce password policy at the next sign-in" (Wymuś politykę haseł przy następnym logowaniu) sprawia, że przy kolejnej próbie wejścia do GCP, użytkownicy ze słabymi hasłami zostaną natychmiast zablokowani i zmuszeni do zmiany hasła na nowe, zgodne z nowym limitem 12-16 znaków.

3. Wyjaśnienie z osobna każdej niepoprawnej odpowiedzi:
A. Review each user's password configuration and reset existing passwords.
   * Dlaczego nieprawidłowa: Ręczne resetowanie haseł dla wszystkich użytkowników w organizacji generuje ogromny nakład pracy administracyjnej i paraliżuje pracę działu IT. Jest to nieefektywne.
C. Review each user's password configuration and select Enforce strong password.
   * Dlaczego nieprawidłowa: Włączanie polityki indywidualnie dla każdego użytkownika z osobna (per-user basis) jest czasochłonne i nie zapobiega logowaniu użytkowników z aktualnymi, słabymi hasłami bez wyzwolenia wymuszenia zmiany.
D. Review the organization password management setting and select Enforce strong password.
   * Dlaczego nieprawidłowa: Samo włączenie opcji "Enforce strong password" w ustawieniach ogólnych wymusza reguły tylko w momencie tworzenia lub zmiany hasła przez użytkownika w przyszłości. Nie resetuje automatycznie sesji użytkownikom z już istniejącymi słabymi hasłami.

4. Wskazówki, hinty, tips and tricks:
* Nowe reguły haseł w Google Cloud Identity nie wpływają automatycznie na aktualne hasła użytkowników.
* Aby natychmiast wyegzekwować nowe reguły u wszystkich użytkowników, wybierz opcję **Enforce password policy at the next sign-in**.

5. Reguły wyboru odpowiedzi (Słowa kluczowe):
* Policy configured but users still logging in with weak passwords -> Enforce password policy at next sign-in.
