Question 160 / 361

You are working with a client that is concerned about control of their encryption keys for sensitive data. The client does not want to store encryption keys at rest in the same cloud service provider (CSP) as the data that the keys are encrypting. Which Google Cloud encryption solutions should you recommend to this client? (Choose two.)

  • A. Customer-supplied encryption keys.
  • B. Google default encryption
  • C. Secret Manager
  • D. Cloud External Key Manager
  • E. Customer-managed encryption keys
Show Suggested Answer Hide Answer
Suggested Answer: AD

Wyjaśnienie

1. Prawidłowa odpowiedź lub odpowiedzi:
A. Customer-supplied encryption keys.
D. Cloud External Key Manager

2. Kompleksowe wyjaśnienie dlaczego dana odpowiedź jest prawidłowa (Analiza):
Klient chce zachować pełną kontrolę nad swoimi kluczami szyfrującymi i kategorycznie nie zgadza się na przechowywanie kluczy w spoczynku (at rest) w tej samej infrastrukturze chmurowej (Google Cloud), w której przechowywane są jego dane:
- A (CSEK - Customer-Supplied Encryption Keys): W tym modelu klient przesyła klucz szyfrujący bezpośrednio w nagłówkach żądania API (np. przy zapisie/odczycie dysku VM lub obiektu GCS). Klucz jest przechowywany wyłącznie w pamięci ulotnej (RAM) maszyn Google podczas operacji i natychmiast usuwany. Nigdy nie jest zapisywany w spoczynku w infrastrukturze GCP.
- D (Cloud EKM - External Key Manager): Pozwala na integrację usług GCP (CMEK) z zewnętrznym systemem zarządzania kluczami (on-premises lub u innego dostawcy chmury). Klucze fizyczne (Key Material) pozostają w zewnętrznym systemie klienta, a Google Cloud odpytuje zewnętrzny system o operacje kryptograficzne przez bezpieczne API, spełniając wymaganie separacji lokalizacji kluczy i danych.

3. Wyjaśnienie z osobna każdej niepoprawnej odpowiedzi:
- B. Google default encryption: Klucze szyfrujące są generowane, rotowane i przechowywane w spoczynku bezpośrednio przez Google Cloud na tej samej platformie, na której leżą dane.
- C. Secret Manager: Jest to usługa hostowana wewnątrz Google Cloud. Przechowywanie tam kluczy oznaczałoby zapisanie ich w spoczynku w tej samej chmurze co dane aplikacji.
- E. Customer-managed encryption keys (CMEK): Choć klient zarządza cyklem życia kluczy (KMS), sam surowy materiał kluczy szyfrujących jest przechowywany w spoczynku wewnątrz sprzętowych modułów bezpieczeństwa (HSM) Google Cloud, co łamie wymaganie klienta o zakazie przechowywania kluczy u tego samego dostawcy chmury.

4. Wskazówki, hinty, tips and tricks:
- Zapamiętaj dwie metody na zachowanie suwerenności kluczy poza Google:
  1. **CSEK** -> Dostarczasz klucz w locie przy każdym zapytaniu API (brak klucza w spoczynku w GCP).
  2. **EKM** -> Klucz leży fizycznie w zewnętrznym HSM poza infrastrukturą Google Cloud.

5. Reguły wyboru odpowiedzi (Słowa kluczowe):
- Klucze nie mogą leżeć w spoczynku u dostawcy chmury (GCP) -> Customer-supplied encryption keys (CSEK) + Cloud External Key Manager (EKM).

6. Dodatkowe źródła i dokumentacja:
