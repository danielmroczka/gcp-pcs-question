Question 199 / 361

As part of your organization's zero trust strategy, you use Identity-Aware Proxy (IAP) to protect multiple applications. You need to ingest logs into a Security Information and Event Management (SIEM) system so that you are alerted to possible intrusions. Which logs should you analyze?

  • A. Data Access audit logs
  • B. Policy Denied audit logs
  • C. Cloud Identity user log events
  • D. Admin Activity audit logs
Show Suggested Answer Hide Answer
Suggested Answer: A

Wyjaśnienie

1. Prawidłowa odpowiedź lub odpowiedzi:
A. Data Access audit logs

2. Kompleksowe wyjaśnienie dlaczego dana odpowiedź jest prawidłowa (Analiza):
Identity-Aware Proxy (IAP) jest kluczowym elementem architektury Zero Trust w GCP, kontrolującym dostęp użytkowników do aplikacji. Aby wykrywać potencjalne włamania (intrusions) za pomocą systemu SIEM, należy analizować logi, które rejestrują szczegóły dotyczące każdej próby dostępu użytkownika do chronionych zasobów (kto się logował, kiedy, z jakiego IP, czy żądanie zostało autoryzowane).
W Google Cloud logi IAP są zapisywane jako **Data Access audit logs** (logi dostępu do danych). Rejestrują one szczegółowe interakcje z API i zasobami chronionymi przez IAP (zarówno próby udane, jak i zablokowane z powodu braku uprawnień). Ingestowanie tych logów do SIEM pozwala na wykrywanie anomalii (np. ataki brute-force, spray attack czy podejrzane próby logowania).

3. Wyjaśnienie z osobna każdej niepoprawnej odpowiedzi:
- B. Policy Denied audit logs: Taki typ logów audytowych w standardowej strukturze Cloud Audit Logs nie istnieje jako oddzielna kategoria dla IAP. Informacje o odmowie dostępu ze względu na politykę IAP są częścią logów Data Access.
- C. Cloud Identity user log events: Logi te rejestrują zdarzenia administracyjne i operacyjne w samej usłudze Cloud Identity (np. reset hasła użytkownika, modyfikacja grupy). Nie zawierają one jednak informacji o bezpośrednich zapytaniach HTTP i próbach autoryzacji do konkretnych aplikacji chronionych przez IAP.
- D. Admin Activity audit logs: Logi te rejestrują wyłącznie operacje konfiguracyjne (np. włączenie/wyłączenie IAP dla danego backendu, zmiana uprawnień IAM). Są one zawsze włączone i bezpłatne, lecz nie rejestrują codziennego ruchu użytkowników (user access requests), przez co są bezużyteczne do wykrywania prób włamań na poziomie aplikacji.

4. Wskazówki, hinty, tips and tricks:
- Logi audytowe w GCP dzielą się na: Admin Activity (zmiany konfiguracji - zawsze włączone) oraz Data Access (odczyt/zapis danych i żądania użytkowników - domyślnie wyłączone ze względu na wolumen danych).
- Monitorowanie prób autoryzacji i dostępu użytkowników do aplikacji przez IAP wymaga włączenia i analizy logów **Data Access**.

5. Reguły wyboru odpowiedzi (Słowa kluczowe):
- "IAP" + "ingest logs into SIEM" + "alerted to possible intrusions" -> Data Access audit logs.

6. Dodatkowe źródła i dokumentacja:
- IAP audit logging documentation: https://cloud.google.com/iap/docs/audit-logging

Analiza i Podsumowanie Dyskusji (AI)

Analiza i Wyjaśnienie

Sugerowana odpowiedź: A

Głęboka analiza: To pytanie testuje Twoją znajomość "Visibility" w modelu Zero Trust. W IAP tożsamość jest nowym obwodem bezpieczeństwa. Dlatego logowanie samej tożsamości i jej prób dostępu (Data Access) jest ważniejsze dla bezpieczeństwa aplikacji niż tradycyjne logi sieciowe. Inżynier bezpieczeństwa musi wiedzieć, że te logi generują koszt i wymagają ręcznej aktywacji w celu zasilenia systemu SIEM.
