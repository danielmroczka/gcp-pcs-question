Question 199 / 361

As part of your organization's zero trust strategy, you use Identity-Aware Proxy (IAP) to protect multiple applications. You need to ingest logs into a Security Information and Event Management (SIEM) system so that you are alerted to possible intrusions.
Which logs should you analyze?

  • A. Data Access audit logs
  • B. Policy Denied audit logs
  • C. Cloud Identity user log events
  • D. Admin Activity audit logs
Show Suggested Answer Hide Answer
Suggested Answer: A

Wyjaśnienie

Poprawna odpowiedź: A (Data Access audit logs)

Dlaczego ta odpowiedź jest poprawna:
- Identity-Aware Proxy (IAP) Audit Logs: IAP generuje logi audytowe, które rejestrują interakcje użytkowników z chronionymi zasobami.
- Data Access Logs: Są to jedyne logi, które rejestrują każde pojedyncze żądanie dostępu (zarówno udane, jak i odrzucone) od konkretnych użytkowników. W kontekście wykrywania włamań (intrusions), informacje o tym, kto próbował się zalogować, z jakiego IP i czy mu się udało, są absolutnie kluczowe dla systemu SIEM.
- SIEM i Intrusion Detection: Systemy SIEM potrzebują granularnych danych o "zdarzeniach dostępowych", aby móc korelować je i wykrywać wzorce ataków (np. brute-force, spray attack czy logowanie z nietypowych lokalizacji).

Analiza niepoprawnych odpowiedzi:
- B. Policy Denied audit logs: Te logi rejestrują naruszenia Polityk Organizacji (Organization Policies), a nie próby logowania poszczególnych użytkowników do aplikacji przez IAP.
- C. Cloud Identity user log events: Logi te dotyczą zdarzeń administracyjnych w samej usłudze Cloud Identity (np. zmiana hasła, dodanie użytkownika do grupy). Choć ważne, nie dają one bezpośredniego wglądu w ruch do aplikacji chronionych przez IAP.
- D. Admin Activity audit logs: Te logi są zawsze włączone i rejestrują ZMIANY W KONFIGURACJI (np. ktoś wyłączył IAP dla danego backendu). Nie rejestrują one jednak standardowego ruchu użytkowników (access attempts), który jest esencją monitorowania włamań.

Wskazówki i triki (Tips & Tricks):
- "User access attempts" / "SIEM intrusion detection" + "IAP" = Data Access Logs.
- Pamiętaj: Logi Data Access są domyślnie WYŁĄCZONE (z wyjątkiem BigQuery). Musisz je jawnie włączyć dla usługi `iap.googleapis.com`.
- Jeśli SIEM ma wykryć atak -> potrzebuje logów "Data Read" i "Data Write".

Praktyczne informacje na egzamin:
- Zrozum strukturę logu IAP: zawiera on `principalEmail` (kto), `callerIp` (skąd) oraz `status` (czy się udało).
- Aby przesłać te logi do SIEM, musisz skonfigurować "Log Sink" (np. do Pub/Sub lub BigQuery).

Analiza i Podsumowanie (AI)

Kluczowe zagadnienia

Sugerowana odpowiedź: A

Analiza strategiczna: To pytanie testuje Twoją znajomość "Visibility" w modelu Zero Trust. W IAP tożsamość jest nowym obwodem bezpieczeństwa. Dlatego logowanie samej tożsamości i jej prób dostępu (Data Access) jest ważniejsze dla bezpieczeństwa aplikacji niż tradycyjne logi sieciowe (Flow Logs). Inżynier bezpieczeństwa musi wiedzieć, że te logi generują koszt i wymagają ręcznej aktywacji.

Dodatkowe wskazówki

  • Włączenie logów Data Access dla wszystkich usług może być bardzo kosztowne. Zaleca się włączanie ich tylko dla krytycznych punktów styku, takich jak IAP.
  • SIEM (np. Google Chronicle) potrafi automatycznie parsować te logi i nanosić je na mapę zagrożeń.
