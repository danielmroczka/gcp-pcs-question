Question 7 / 361

A company is running workloads in a dedicated server room. They must only be accessed from within the private company network. You need to connect to these workloads from Compute Engine instances within a Google Cloud Platform project. Which two approaches can you take to meet the requirements? (Choose two.)

  • A. Configure the project with Cloud VPN.
  • B. Configure the project with Shared VPC.
  • C. Configure the project with Cloud Interconnect.
  • D. Configure the project with VPC peering.
  • E. Configure all Compute Engine instances with Private Access.
Show Suggested Answer Hide Answer
Suggested Answer: AC

Wyjaśnienie

**Poprawna odpowiedź: AC**

**1. Kompleksowe wyjaśnienie poprawnej odpowiedzi:**
Wymagane jest ustanowienie bezpiecznego, prywatnego połączenia między dedykowaną serwerownią firmy (on-premises) a siecią VPC w Google Cloud Platform. Google oferuje dwa natywne rozwiązania hybrydowe:
- **Cloud VPN (A):** Umożliwia bezpieczne połączenie sieci lokalnej z VPC za pomocą tuneli IPSec przez publiczny internet. Jest to rozwiązanie szybkie do wdrożenia i tańsze.
- **Cloud Interconnect (C):** Zapewnia bezpośrednie, fizyczne połączenie o wysokiej przepustowości i niskich opóźnieniach (Dedicated lub Partner Interconnect) z pominięciem publicznego internetu.

**2. Wyjaśnienie niepoprawnych odpowiedzi:**
- **B. Shared VPC:** Służy do współdzielenia sieci VPC pomiędzy wieloma projektami w ramach jednej organizacji w GCP, ale nie łączy GCP z siecią on-premises.
- **D. VPC Peering:** Służy do bezpośredniego łączenia dwóch niezależnych sieci VPC w GCP, a nie do łączenia z fizyczną serwerownią lokalną.
- **E. Private Access:** Private Google Access pozwala maszynom z prywatnymi IP na dostęp do API Google, ale nie tworzy połączenia routowalnego między serwerownią a VPC.

**3. Wskazówki i pułapki egzaminacyjne (Tips & Tricks):**
- Gdy pytanie dotyczy łączenia on-premises z GCP w bezpieczny, prywatny sposób, jedynymi poprawnymi odpowiedziami są **Cloud VPN** lub **Cloud Interconnect**.
- VPN jest szyfrowany (IPsec), natomiast Interconnect nie szyfruje ruchu domyślnie (wymaga dodatkowo MACsec lub VPN over Interconnect), ale zapewnia prywatną ścieżkę fizyczną.

**4. Reguły wyboru odpowiedzi:**
- Łączenie chmury z on-premises -> VPN (tani/szybki/szyfrowany) lub Interconnect (droższy/dedykowany/wysoka wydajność).

**5. Dodatkowe źródła:**
- Google Cloud Hybrid Connectivity: https://cloud.google.com/hybrid-connectivity
