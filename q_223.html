Question 223 / 361

After completing a security vulnerability assessment, you learned that cloud administrators leave Google Cloud CLI sessions open for days. You need to reduce the risk of attackers who might exploit these open sessions by setting these sessions to the minimum duration. What should you do?

  • A. Set the session duration for the Google session control to one hour.
  • B. Set the reauthentication frequency for the Google Cloud Session Control to one hour.
  • C. Set the organization policy constraint constraints/iam.allowServiceAccountCredentialLifetimeExtension to one hour.
  • D. Set the organization policy constraint constraints/iam.serviceAccountKeyExpiryHours to one hour and inheritFromParent to false.
Show Suggested Answer Hide Answer
Suggested Answer: B

Wyjaśnienie

1. Prawidłowa odpowiedź lub odpowiedzi:
B. Set the reauthentication frequency for the Google Cloud Session Control to one hour.

2. Kompleksowe wyjaśnienie dlaczego dana odpowiedź jest prawidłowa (Analiza):
Odpowiedź B jest prawidłowa, ponieważ skrócenie czasu trwania sesji (reauthentication frequency) w ramach Google Cloud Session Control bezpośrednio wymusza na administratorach ponowne logowanie po wskazanym czasie (minimum 1 godzina), co minimalizuje czas w jakim skradziony token sesyjny lub pozostawiona bez nadzoru konsola/CLI pozostają aktywne.

Mechanizm działania:
a. W konsoli administracyjnej Google Workspace / Cloud Identity można ustawić politykę częstotliwości ponownego uwierzytelniania dla Google Cloud Console oraz narzędzi Google Cloud SDK/CLI.
b. Ustawienie wartości na 1 godzinę (minimum) sprawia, że po tym czasie sesja wygasa i gcloud CLI odmówi wykonania jakichkolwiek poleceń bez ponownej weryfikacji tożsamości (np. MFA).

3. Wyjaśnienie z osobna każdej niepoprawnej odpowiedzi:
A. Set the session duration for the Google session control to one hour.
   * Dlaczego nieprawidłowa: Chociaż cel jest podobny, pojęciem używanym w konsoli administracyjnej Google dla usług chmurowych GCP jest "reauthentication frequency" (częstotliwość ponownego uwierzytelniania), a nie ogólna kontrola sesji Google, która ma inne limity i zachowania dla zwykłych usług typu Gmail.
C. Set the organization policy constraint constraints/iam.allowServiceAccountCredentialLifetimeExtension to one hour.
   * Dlaczego nieprawidłowa: Ograniczenie `iam.allowServiceAccountCredentialLifetimeExtension` służy do kontrolowania maksymalnego czasu życia tokenów krótkotrwałych (OAuth access tokens) generowanych przez konta serwisowe (pozwala na wydłużenie czasu życia z domyślnego 1h do maksymalnie 12h), a nie do wymuszania reuwierzytelniania dla sesji użytkowników ludzkich korzystających z gcloud CLI.
D. Set the organization policy constraint constraints/iam.serviceAccountKeyExpiryHours...
   * Dlaczego nieprawidłowa: Ta polityka dotyczy maksymalnego czasu ważności generowanych kluczy prywatnych kont serwisowych (Service Account Keys), a nie sesji interaktywnych użytkowników (administratorów) korzystających z interfejsu CLI.

4. Wskazówki, hinty, tips and tricks:
* Ochrona sesji administratorów przed nieautoryzowanym użyciem (np. pozostawienie otwartej konsoli/CLI) -> Zmiana **reauthentication frequency** w Google Cloud Session Control.
* Minimalny możliwy czas ponownej weryfikacji tożsamości dla sesji to **1 godzina**.

5. Reguły wyboru odpowiedzi (Słowa kluczowe):
* CLI sessions open for days / reduce session lifetime -> Set reauthentication frequency in Session Control to 1 hour.

6. Dodatkowe źródła i dokumentacja:
Set session length for Google Cloud services
Control session duration with Cloud IAP

Wskazówki egzaminacyjne (Tips & Tricks)

Reguła Egzaminacyjna (Exam Rule): 
Jeśli scenariusz dotyczy zabezpieczania zasobów chmurowych (GCP), zawsze wybieraj rozwiązanie typu Managed (SCC, Secret Manager, Cloud KMS), a unikaj rozwiązań self-managed, chyba że pytanie wyraźnie wymaga dostosowania niskopoziomowego.

Haczyki egzaminacyjne (Exam Traps):
- Pułapka IAM: Pytania o uprawnienia często sugerują 'Project Owner' – zawsze szukaj 'Least Privilege' (np. 'Role: Secret Manager Secret Accessor').
- Pułapka Sieciowa: Często mylone są VPC Peering (wydajność) oraz VPN (szyfrowanie/on-premise).

Głębokie wyjaśnienie techniczne:
Rozwiązanie bazuje na GCP Shared Responsibility Model. Google zarządza bezpieczeństwem infrastruktury (Physical, Network, Host), podczas gdy administrator zarządza tożsamością (IAM), danymi (Encryption, Cloud KMS) i regułami dostępu (VPC Firewall).

Analiza i Podsumowanie (AI)

Kluczowe zagadnienia

Sugerowana odpowiedź: B

Analiza strategiczna: To pytanie testuje umiejętność zarządzania sesjami w środowiskach pracy zdalnej. Sesje są słabym punktem nowoczesnych aplikacji webowych. Wymuszenie reautentykacji (MFA) po pewnym czasie to najskuteczniejsza metoda ochrony przed skutkami kradzieży ciasteczek sesyjnych (session hijacking).

Dodatkowe wskazówki

  • Możesz konfigurować różne czasy dla różnych grup użytkowników (np. krótszy dla Super Administratorów, dłuższy dla Deweloperów).
  • Zawsze monitoruj "Suspicious Activity" w panelu bezpieczeństwa Google Workspace jako uzupełnienie Session Control.
