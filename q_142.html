Question 142 / 361

You have noticed an increased number of phishing attacks across your enterprise user accounts. You want to implement the Google 2-Step Verification (2SV) option that uses a cryptographic signature to authenticate a user and verify the URL of the login page. Which Google 2SV option should you use?

  • A. Titan Security Keys
  • B. Google prompt
  • C. Google Authenticator app
  • D. Cloud HSM keys
Show Suggested Answer Hide Answer
Suggested Answer: A

Wyjaśnienie

Potwierdzona odpowiedź: A (Titan Security Keys)

Wyjaśnienie:
Klucze bezpieczeństwa Titan (Titan Security Keys) wykorzystują standardy FIDO (Fast Identity Online), w tym U2F (Universal 2nd Factor) i FIDO2. Są to jedyne opcje 2-stopniowej weryfikacji (2SV) w ekosystemie Google, które zapewniają kryptograficzną weryfikację adresu URL strony logowania. Oznacza to, że klucz nie wyśle podpisu kryptograficznego, jeśli strona logowania jest fałszywa (phishingowa), nawet jeśli wygląda identycznie jak prawdziwa strona Google. Klucz generuje podpis unikalny dla danej sesji logowania, którego nie da się przejąć ani wykorzystać powtórnie przez atakującego.

Dlaczego pozostałe są błędne:
B. Google prompt: Przesyła powiadomienie "Czy to Ty?" na urządzenie mobilne. Chociaż jest znacznie bezpieczniejszy niż SMS, nie oferuje sprzętowej weryfikacji adresu URL strony logowania i może być podatny na błąd użytkownika (przypadkowe kliknięcie "Tak" przy zmęczeniu decyzją/spamowaniu powiadomieniami).
C. Google Authenticator app: Generuje kody czasowe (TOTP). Użytkownik musi ręcznie przepisać kod na stronę. Nie ma tu mechanizmu sprawdzającego, czy strona, na której wpisywany jest kod, nie jest stroną phishingową – atakujący może natychmiast użyć przechwyconego kodu na prawdziwej stronie Google.
D. Cloud HSM keys: Służą do przechowywania kluczy szyfrujących dane w chmurze (np. dla usługi Cloud KMS), a nie do uwierzytelniania użytkowników podczas logowania do konta Google. To usługa infrastrukturalna, a nie metoda 2SV dla personelu.

Wskazówki egzaminacyjne (Tips & Tricks):
- Słowa kluczowe: "phishing protection", "cryptographic signature", "verify URL". Jeśli je widzisz, odpowiedzią prawie zawsze są Klucze Bezpieczeństwa (Security Keys).
- Program Ochrony Zaawansowanej (Advanced Protection Program) Google wymaga właśnie użycia kluczy bezpieczeństwa jako najmocniejszej formy ochrony.

Kluczowe zagadnienia do powtórzenia:
- Metody 2-stopniowej weryfikacji (2SV) w Cloud Identity.
- Różnica między TOTP (aplikacje), Push (Prompt) a FIDO/U2F (Security Keys).
- Cloud Identity Advanced Protection.
