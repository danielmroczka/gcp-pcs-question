Question 147 / 361

You are responsible for managing your company's identities in Google Cloud. Your company enforces 2-Step Verification (2SV) for all users. You need to reset a user's access, but the user lost their second factor for 2SV. You want to minimize risk. What should you do?

  • A. On the Google Admin console, select the appropriate user account, and generate a backup code to allow the user to sign in. Ask the user to update their second factor.
  • B. On the Google Admin console, temporarily disable the 2SV requirements for all users. Ask the user to log in and add their new second factor to their account. Re-enable the 2SV requirement for all users.
  • C. On the Google Admin console, select the appropriate user account, and temporarily disable 2SV for this account. Ask the user to update their second factor, and then re-enable 2SV for this account.
  • D. On the Google Admin console, use a super administrator account to reset the user account's credentials. Ask the user to update their credentials after their first login.
Show Suggested Answer Hide Answer
Suggested Answer: A

Wyjaśnienie

1. Prawidłowa odpowiedź lub odpowiedzi:
A. On the Google Admin console, select the appropriate user account, and generate a backup code to allow the user to sign in. Ask the user to update their second factor.

2. Kompleksowe wyjaśnienie dlaczego dana odpowiedź jest prawidłowa (Analiza):
Użytkownik zgubił swój drugi składnik weryfikacji dwuetapowej (2SV), a w firmie obowiązuje wymóg 2SV dla wszystkich kont. Należy zresetować dostęp w sposób bezpieczny i minimalizujący ryzyko:
- Najbardziej bezpieczną metodą odzyskiwania dostępu w Google Workspace/Cloud Identity jest wygenerowanie jednorazowych kodów zapasowych (backup verification codes) dla konkretnego konta użytkownika w konsoli administratora Google Admin.
- Kod zapasowy działa jak jednorazowy token drugiego etapu logowania. Pozwala użytkownikowi na bezpieczne zalogowanie się i samodzielne dodanie nowego klucza/telefonu do weryfikacji dwuetapowej. W ten sposób nie wyłączamy zabezpieczeń konta ani nie obniżamy poziomu bezpieczeństwa całej firmy.

3. Wyjaśnienie z osobna każdej niepoprawnej odpowiedzi:
- B. Wyłączenie weryfikacji dwuetapowej (2SV) dla wszystkich użytkowników: Tworzy krytyczne zagrożenie bezpieczeństwa w skali całej firmy, pozbawiając wszystkie konta ochrony na czas logowania jednego użytkownika.
- C. Tymczasowe wyłączenie 2SV dla tego jednego konta: Jest to gorsze i bardziej ryzykowne rozwiązanie. Jeśli użytkownik zaloguje się, ale nie skonfiguruje od razu nowego drugiego składnika, jego konto pozostanie całkowicie bez ochrony 2SV (tylko z hasłem), co stwarza okno podatności na ataki.
- D. Reset poświadczeń przez super administratora: Reset samego hasła nie omija żądania drugiego składnika (2SV). Przy próbie zalogowania użytkownik nadal zostanie poproszony o zgubiony klucz.

4. Wskazówki, hinty, tips and tricks:
- Generowanie kodów zapasowych (Backup verification codes) to standardowa procedura wsparcia IT dla użytkowników Google Workspace, którzy utracili dostęp do swoich telefonów lub kluczy bezpieczeństwa U2F/MFA.

5. Reguły wyboru odpowiedzi (Słowa kluczowe):
- Zgubiony klucz 2FA/2SV + bezpieczne przywrócenie dostępu -> Wygenerowanie kodów zapasowych (backup verification codes) w Google Admin console.
