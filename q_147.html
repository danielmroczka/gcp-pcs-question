Question 147 / 361

You are responsible for managing your company's identities in Google Cloud. Your company enforces 2-Step Verification (2SV) for all users. You need to reset a user's access, but the user lost their second factor for 2SV. You want to minimize risk. What should you do?

  • A. On the Google Admin console, select the appropriate user account, and generate a backup code to allow the user to sign in. Ask the user to update their second factor.
  • B. On the Google Admin console, temporarily disable the 2SV requirements for all users. Ask the user to log in and add their new second factor to their account. Re-enable the 2SV requirement for all users.
  • C. On the Google Admin console, select the appropriate user account, and temporarily disable 2SV for this account. Ask the user to update their second factor, and then re-enable 2SV for this account.
  • D. On the Google Admin console, use a super administrator account to reset the user account's credentials. Ask the user to update their credentials after their first login.
Show Suggested Answer Hide Answer
Suggested Answer: A

Wyjaśnienie

Potwierdzona odpowiedź: A (On the Google Admin console, select the appropriate user account, and generate a backup code to allow the user to sign in. Ask the user to update their second factor).

Wyjaśnienie:
W sytuacji, gdy użytkownik utraci dostęp do swojego urządzenia MFA/2SV, najbezpieczniejszą metodą przywrócenia dostępu przy minimalizacji ryzyka jest wygenerowanie jednorazowego kodu zapasowego (backup code) przez administratora. Pozwala to użytkownikowi na bezpieczne zalogowanie się i natychmiastowe ustawienie nowej metody drugiego składnika. Ta procedura nie wymaga wyłączania ochrony 2SV dla całego konta, co czyni ją najbardziej bezpieczną.

Dlaczego pozostałe są błędne:
- B. Wyłączenie 2SV dla wszystkich: Jest to niedopuszczalne naruszenie bezpieczeństwa całej organizacji z powodu problemu jednego użytkownika.
- C. Tymczasowe wyłączenie 2SV dla konta: Jest to mniej ryzykowne niż opcja B, ale nadal pozostawia konto całkowicie bez ochrony drugiego składnika na czas logowania. Opcja A (kod zapasowy) jest uważana za "best practice" w Google Workspace/Cloud Identity.
- D. Reset poświadczeń (hasła): Samo zresetowanie hasła nie pomoże, ponieważ system nadal będzie wymagał drugiego składnika (2SV) podczas próby logowania z nowym hasłem.

Wskazówki egzaminacyjne (Tips & Tricks):
- "Lost 2SV" + "Minimize risk" -> administrator generuje "backup code".
- Nigdy nie wybieraj odpowiedzi sugerującej "wyłączenie" (Disable) globalnych zabezpieczeń, jeśli dostępna jest opcja bardziej precyzyjna (jak kod zapasowy).

Kluczowe zagadnienia do powtórzenia:
- Zarządzanie tożsamościami i 2-Step Verification (2SV) w Cloud Identity.
- Role Super Admina w Google Workspace/GCP.
