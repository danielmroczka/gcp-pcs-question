Question 40 / 361

You want to evaluate your organization's Google Cloud instance for PCI compliance. You need to identify Google's inherent controls. Which document should you review to find the information?

  • A. Google Cloud Platform: Customer Responsibility Matrix
  • B. PCI DSS Requirements and Security Assessment Procedures
  • C. PCI SSC Cloud Computing Guidelines
  • D. Product documentation for Compute Engine
Show Suggested Answer Hide Answer
Suggested Answer: A

Wyjaśnienie

**Poprawna odpowiedź: A**

**1. Kompleksowe wyjaśnienie poprawnej odpowiedzi:**
Podczas audytu zgodności z normą PCI DSS w chmurze, należy określić, które zabezpieczenia są wdrażane bezpośrednio przez infrastrukturę Google Cloud, a które leżą po stronie klienta:
- **Google Cloud Platform: Customer Responsibility Matrix (Macierz Odpowiedzialności Klienta) (A):** Jest to oficjalny dokument dostarczany przez Google Cloud. Mapuje on wymagania PCI DSS i jasno określa podział obowiązków (np. które wymagania są w pełni pokrywane przez Google, które są współdzielone, a które leżą wyłącznie po stronie klienta). Pozwala to audytorowi na szybką weryfikację wbudowanych zabezpieczeń Google (inherent controls).

**2. Wyjaśnienie niepoprawnych odpowiedzi:**
- **B. PCI DSS Requirements and Security Assessment Procedures:** Jest to ogólny dokument organizacji PCI SSC opisujący sam standard, nie zawiera specyficznych informacji o architekturze i wbudowanych zabezpieczeniach infrastruktury Google Cloud.
- **C. PCI SSC Cloud Computing Guidelines:** To ogólny zbiór dobrych praktyk dla systemów chmurowych od konsorcjum PCI, nie odnosi się bezpośrednio do implementacji w GCP.
- **D. Dokumentacja Compute Engine:** Zawiera instrukcje techniczne konfiguracji maszyn VM, ale nie jest formalnym dokumentem audytowym opisującym podział odpowiedzialności PCI.

**3. Wskazówki i pułapki egzaminacyjne (Tips & Tricks):**
- Każdy główny dostawca chmury udostępnia **Shared Responsibility Matrix** (lub Customer Responsibility Matrix) dla różnych norm (PCI, SOC, ISO), aby ułatwić klientom przechodzenie audytów zewnętrznych.
- Dokument ten wskazuje tzw. **inherent controls** (zabezpieczenia wbudowane/dziedziczone od dostawcy).

**4. Reguły wyboru odpowiedzi:**
- Podział obowiązków PCI / audyt zabezpieczeń Google -> Customer Responsibility Matrix.

**5. Dodatkowe źródła:**
- Google Cloud Compliance Reports Manager: https://cloud.google.com/security/compliance/compliance-reports-manager

Analiza i Wyjaśnienie

Sugerowana odpowiedź: A

Analiza spornych kwestii (AI): Pytanie dotyczy konkretnego artefaktu audytowego. Podczas audytu PCI, auditor zapyta: "Jakie macie dowody na to, że warstwa fizyczna jest zabezpieczona?". Odpowiedzią nie jest "Standard PCI", lecz właśnie Macierz Odpowiedzialności dostarczona przez Google, która wskazuje na odpowiednie certyfikacje infrastruktury bazowej.

Wyjaśnienie Audytowe

Reguła Egzaminacyjna (Exam Rule):
Pamiętaj, że w egzaminie Professional Cloud Security Engineer kluczowe jest wybieranie rozwiązań najmniej uprzywilejowanych (Principle of Least Privilege), zoptymalizowanych kosztowo i spełniających wymogi compliancy (np. CMEK, Data Loss Prevention).

Haczyki egzaminacyjne (Exam Traps):
- Wybór rozwiązań, które wydają się wygodne, ale nie spełniają wymogów bezpieczeństwa (np. zbyt szerokie uprawnienia IAM).
- Mylenie usług: np. Cloud Armor (WAF) z Cloud IAP (Identity-Aware Proxy).

Głębokie wyjaśnienie techniczne (GCP Professional Cloud Security Engineer):
W każdym pytaniu analizuj warstwy: IAM (dostęp), Encryption (at rest/in transit), Logging/Monitoring (Audit Logs, Cloud Logging, Security Command Center) oraz Networking (VPC Service Controls, Firewall Rules). GCP kładzie duży nacisk na współdzieloną odpowiedzialność (Shared Responsibility Model) - klient odpowiada za konfigurację zabezpieczeń wewnątrz usług chmurowych.
