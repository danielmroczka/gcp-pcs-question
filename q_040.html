Question 40 / 361

You want to evaluate your organization's Google Cloud instance for PCI compliance. You need to identify Google's inherent controls. Which document should you review to find the information?

  • A. Google Cloud Platform: Customer Responsibility Matrix
  • B. PCI DSS Requirements and Security Assessment Procedures
  • C. PCI SSC Cloud Computing Guidelines
  • D. Product documentation for Compute Engine
Show Suggested Answer Hide Answer
Suggested Answer: A

Wyjaśnienie

Potwierdzona odpowiedź: A (Google Cloud Platform: Customer Responsibility Matrix)

Wyjaśnienie:
W modelu współdzielonej odpowiedzialności (Shared Responsibility Model), dostawcy usług chmurowych tacy jak Google Cloud publikują dokumenty określające, które zabezpieczenia (kontrole) są realizowane przez dostawcę, a które przez klienta.
1. Customer Responsibility Matrix (Macierz Odpowiedzialności Klienta): Jest to kluczowy dokument przy audytach PCI DSS. Precyzuje on, które wymagania standardu PCI są "inherentne" (zapewnione przez infrastrukturę Google, np. fizyczna ochrona centrum danych), które są współdzielone, a które leżą wyłącznie po stronie klienta (np. konfiguracja firewalli wewnątrz VPC).
2. "Inherent controls": To te mechanizmy, które klient otrzymuje "w pakiecie" z usługą chmurową i za które odpowiada Google.

Dlaczego pozostałe są błędne:
B. PCI DSS Requirements and Security Assessment Procedures to ogólny standard wydany przez PCI SSC, który opisuje wymagania dla wszystkich firm, ale nie zawiera specyficznych informacji o tym, co konkretnie Google robi dla swoich klientów.
C. PCI SSC Cloud Computing Guidelines to ogólny przewodnik dobrych praktyk dotyczący chmury, nie jest to specyficzny dokument techniczny/audytowy Google Cloud.
D. Dokumentacja produktu (np. Compute Engine) opisuje jak korzystać z usługi, ale nie jest oficjalnym dokumentem audytowym PCI mapującym odpowiedzialność w zakresie kontroli bezpieczeństwa.

Wskazówki egzaminacyjne (Tips & Tricks):
- Słowa klucze: "PCI compliance", "Shared Responsibility", "Inherent controls" = szukaj "Customer Responsibility Matrix".
- Pamiętaj, że Google udostępnia te raporty (np. SOC 3, PCI Attestation of Compliance) przez "Compliance Reports Manager".

Kluczowe zagadnienia do powtórzenia:
- Shared Responsibility Model (Model Współdzielonej Odpowiedzialności).
- PCI DSS w chmurze.
- Inherent vs. Shared vs. Customer controls.

Analiza i Wyjaśnienie

Sugerowana odpowiedź: A

Analiza spornych kwestii (AI): Pytanie dotyczy konkretnego artefaktu audytowego. Podczas audytu PCI, auditor zapyta: "Jakie macie dowody na to, że warstwa fizyczna jest zabezpieczona?". Odpowiedzią nie jest "Standard PCI", lecz właśnie Macierz Odpowiedzialności dostarczona przez Google, która wskazuje na odpowiednie certyfikacje infrastruktury bazowej.

Wyjaśnienie Audytowe

Reguła Egzaminacyjna (Exam Rule):
Pamiętaj, że w egzaminie Professional Cloud Security Engineer kluczowe jest wybieranie rozwiązań najmniej uprzywilejowanych (Principle of Least Privilege), zoptymalizowanych kosztowo i spełniających wymogi compliancy (np. CMEK, Data Loss Prevention).

Haczyki egzaminacyjne (Exam Traps):
- Wybór rozwiązań, które wydają się wygodne, ale nie spełniają wymogów bezpieczeństwa (np. zbyt szerokie uprawnienia IAM).
- Mylenie usług: np. Cloud Armor (WAF) z Cloud IAP (Identity-Aware Proxy).

Głębokie wyjaśnienie techniczne (GCP Professional Cloud Security Engineer):
W każdym pytaniu analizuj warstwy: IAM (dostęp), Encryption (at rest/in transit), Logging/Monitoring (Audit Logs, Cloud Logging, Security Command Center) oraz Networking (VPC Service Controls, Firewall Rules). GCP kładzie duży nacisk na współdzieloną odpowiedzialność (Shared Responsibility Model) - klient odpowiada za konfigurację zabezpieczeń wewnątrz usług chmurowych.
