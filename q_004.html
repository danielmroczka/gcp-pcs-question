Question 4 / 361

Your team wants to centrally manage GCP IAM permissions from their on-premises Active Directory Service. Your team wants to manage permissions by AD group membership. What should your team do to meet these requirements?

  • A. Set up Cloud Directory Sync to sync groups, and set IAM permissions on the groups.
  • B. Set up SAML 2.0 Single Sign-On (SSO), and assign IAM permissions to the groups.
  • C. Use the Cloud Identity and Access Management API to create groups and IAM permissions from Active Directory.
  • D. Use the Admin SDK to create groups and assign IAM permissions from Active Directory.
Show Suggested Answer Hide Answer
Suggested Answer: A

Wyjaśnienie

**Potwierdzona odpowiedź: (Wymagane doprecyzowanie)**

**Reguła Egzaminacyjna (Exam Rule):**
Jeśli pytanie dotyczy synchronizacji tożsamości (użytkownicy/grupy) z lokalnego AD do Google Cloud (Cloud Identity) w celu zarządzania IAM, zawsze wybieraj "Cloud Directory Sync" (GCDS). 

**Haczyki egzaminacyjne (Exam Traps):**
- Wybór SAML 2.0/SSO: SSO służy wyłącznie do uwierzytelniania (logowania). Samo w sobie nie synchronizuje informacji o przynależności do grup, które są wymagane przez system IAM.
- Wybór rozwiązań programistycznych (Cloud IAM API / Admin SDK) dla prostego zadania synchronizacji, dla którego Google dostarcza gotowe narzędzie.

**Głębokie wyjaśnienie techniczne:**
1. **Cloud Directory Sync (GCDS)**: Działa w modelu "push" (z AD do Cloud Identity). Replikuje strukturę grup i użytkowników. Dzięki temu grupy z AD stają się obiektami w GCP, do których można przypisywać role IAM.
2. **Separacja Uwierzytelniania i Autoryzacji**: GCDS odpowiada za *Autoryzację* (dostarcza informacje, kim jest użytkownik i w jakich grupach jest – potrzebne do IAM), a SSO/SAML odpowiada za *Uwierzytelnienie* (logowanie).

Analiza i Podsumowanie Dyskusji (AI)

Analiza i Wyjaśnienie

Sugerowana odpowiedź: A

Analiza spornych kwestii (AI): Częstym błędem w tej dyskusji jest mylenie logowania (SSO) z autoryzacją (IAM). Eksperci podkreślają: SSO sprawia, że użytkownik MOŻE się zalogować, ale to GCDS sprawia, że system IAM WIE, jakie uprawnienia mu nadać na podstawie jego przynależności do grup zsynchronizowanych z AD.
