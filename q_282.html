Question 282 / 361

You have just created a new log bucket to replace the _Default log bucket. You want to route all log entries that are currently routed to the _Default log bucket to this new log bucket, in the most efficient manner. What should you do?

  • A. Create exclusion filters for the _Default sink to prevent it from receiving new logs. Create a user-defined sink, and select the new log bucket as the sink destination.
  • B. Disable the _Default sink. Create a user-defined sink and select the new log bucket as the sink destination.
  • C. Create a user-defined sink with inclusion filters copied from the _Default sink. Select the new log bucket as the sink destination.
  • D. Edit the _Default sink, and select the new log bucket as the sink destination.
Show Suggested Answer Hide Answer
Suggested Answer: D

Wyjaśnienie

1. Prawidłowa odpowiedź lub odpowiedzi:
D. Edit the _Default sink, and select the new log bucket as the sink destination.

2. Kompleksowe wyjaśnienie dlaczego dana odpowiedź jest prawidłowa (Analiza):
Odpowiedź D jest prawidłowa, ponieważ edycja domyślnego odbiornika logów (`_Default` sink) jest najbardziej bezpośrednim, zautomatyzowanym i efektywnym (najmniejszy narzut operacyjny) sposobem na przekierowanie strumienia logów do nowo utworzonego kubełka.

Dlaczego to najlepsze podejście:
a. **Domyślna konfiguracja:** Odbiornik `_Default` jest automatycznie tworzony w każdym projekcie GCP i zawiera predefiniowane filtry przechwytujące większość typowych logów systemowych (poza logami audytowymi zbieranymi przez `_Required`).
b. **Brak duplikacji:** Zamiast tworzyć nowe filtry i wyłączać stare, zmieniamy jedynie pole `destination` w istniejącym sinku `_Default` na wskazanie nowego log bucketa. Zapobiega to powstawaniu zduplikowanych reguł i gwarantuje, że proces logowania nie ulegnie przerwaniu ani nie wygeneruje dodatkowych kosztów za podwójny transfer logów.

3. Wyjaśnienie z osobna każdej niepoprawnej odpowiedzi:
A. Create exclusion filters for the _Default sink... Create a user-defined sink...
   * Dlaczego nieprawidłowa: Choć to podejście zadziała, jest nieefektywne. Tworzenie dodatkowego wykluczenia (exclusion) oraz tworzenie nowego, niezależnego sinka od zera generuje niepotrzebny narzut konfiguracyjny i zwiększa stopień skomplikowania środowiska loggingu.
B. Disable the _Default sink. Create a user-defined sink...
   * Dlaczego nieprawidłowa: Wyłączenie (lub wyciszenie) sinka `_Default` i budowanie własnego od nowa wymaga dokładnego skopiowania skomplikowanych domyślnych filtrów Google. Jeśli pomylimy się w filtrach, stracimy ważne logi. Edycja celu (opcja D) jest bezpieczniejsza i szybsza.
C. Create a user-defined sink with inclusion filters copied from the _Default sink...
   * Dlaczego nieprawidłowa: Podobnie jak w opcji B, ta metoda tworzy nadmiarową konfigurację. Nowy sink działałby równolegle z wciąż aktywnym sinkiem `_Default` (jeśli go nie wyłączymy), co doprowadziłoby do podwójnego zapisywania tych samych logów (do starych i nowych kubełków), podwajając koszty przechowywania logów.

4. Wskazówki, hinty, tips and tricks:
* Odbiorniki logów `_Required` i `_Default` są wbudowane w GCP.
* Możesz edytować destynację (destination) sinka `_Default` w celu przekierowania logów do regionalnego lub niestandardowego kubełka logów.
* Zawsze szukaj rozwiązań o najmniejszym narzucie konfiguracyjnym (most efficient).

5. Reguły wyboru odpowiedzi (Słowa kluczowe):
* Route logs from _Default sink to new bucket efficiently -> Edit the _Default sink and change destination.
