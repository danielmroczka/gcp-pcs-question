Question 184 / 361

You have a highly sensitive BigQuery workload that contains personally identifiable information (PII) that you want to ensure is not accessible from the internet. To prevent data exfiltration, only requests from authorized IP addresses are allowed to query your BigQuery tables.
What should you do?

  • A. Use service perimeter and create an access level based on the authorized source IP address as the condition.
  • B. Use Google Cloud Armor security policies defining an allowlist of authorized IP addresses at the global HTTPS load balancer.
  • C. Use the Restrict Resource Service Usage organization policy constraint along with Cloud Data Loss Prevention (DLP).
  • D. Use the Restrict allowed Google Cloud APIs and services organization policy constraint along with Cloud Data Loss Prevention (DLP).
Show Suggested Answer Hide Answer
Suggested Answer: A

Wyjaśnienie

Potwierdzona odpowiedź: A (Use service perimeter and create an access level based on the authorized source IP address as the condition).

Wyjaśnienie:
VPC Service Controls (VPC SC) to kluczowy mechanizm bezpieczeństwa w Google Cloud, który pozwala na stworzenie "perymetru" wokół usług takich jak BigQuery. Perymetr ten izoluje usługę od internetu oraz od innych projektów wewnątrz Google Cloud. Aby umożliwić dostęp do tak zabezpieczonego BigQuery z określonych lokalizacji, należy użyć Access Context Manager do zdefiniowania "Poziomu dostępu" (Access Level). Warunkiem w tym poziomie dostępu będzie lista autoryzowanych adresów IP. Takie połączenie skutecznie zapobiega eksfiltracji danych, ponieważ dostęp jest rygorystycznie ograniczony zarówno pod względem tożsamości (IAM), jak i kontekstu sieciowego (IP).

Dlaczego pozostałe są błędne:
- B. Google Cloud Armor: Służy do ochrony aplikacji webowych wystawionych za Load Balancerem (ochrona przed L7 DDoS, SQLi, XSS). Nie jest to narzędzie przeznaczone do ograniczania dostępu do natywnego API BigQuery i nie zapobiega eksfiltracji danych w taki sposób jak VPC SC.
- C/D. Organization Policy constraints: Polityki organizacji (np. Restrict Resource Service Usage) pozwalają kontrolować, jakie usługi mogą być używane w danym projekcie, ale nie oferują mechanizmu filtrowania ruchu do tych usług na podstawie adresu IP klienta.

Wskazówki egzaminacyjne (Tips & Tricks):
- "Prevent data exfiltration" + "BigQuery/Storage/SQL" = szukaj odpowiedzi z VPC Service Controls (VPC SC).
- "Access based on IP for Google APIs" = Access Context Manager + Access Levels.
- Zapamiętaj: IAM decyduje "kto", a VPC SC decyduje "skąd" (context-aware access).

Kluczowe zagadnienia do powtórzenia:
- Architektura VPC Service Controls.
- Access Context Manager i tworzenie Access Levels.
- Różnica między bezpieczeństwem tożsamości (IAM) a bezpieczeństwem sieciowym (VPC SC).

Analiza i Wyjaśnienie

Sugerowana odpowiedź: A

Głęboka analiza: BigQuery jest usługą typu multi-tenant dostępną publicznie przez API. W przypadku danych wrażliwych (PII), standardowe zabezpieczenia IAM mogą być niewystarczające (np. w przypadku kradzieży klucza serwisowego). VPC Service Controls dodaje warstwę bezpieczeństwa sieciowego, która "zamyka" API BigQuery wewnątrz perymetru, a Access Levels wpuszczają tylko ruch z autoryzowanych adresów IP firmowych.
