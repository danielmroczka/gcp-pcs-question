Question 224 / 361

You have numerous private virtual machines on Google Cloud. You occasionally need to manage the servers through Secure Socket Shell (SSH) from a remote location. You want to configure remote access to the servers in a manner that optimizes security and cost efficiency. What should you do?

  • A. Create a site-to-site VPN from your corporate network to Google Cloud.
  • B. Configure server instances with public IP addresses. Create a firewall rule to only allow traffic from your corporate IPs.
  • C. Create a firewall rule to allow access from the Identity-Aware Proxy (IAP) IP range. Grant the role of an IAP-secured Tunnel User to the administrators.
  • D. Create a jump host instance with public IP. Manage the instances by connecting through the jump host.
Show Suggested Answer Hide Answer
Suggested Answer: C

Wyjaśnienie

1. Prawidłowa odpowiedź lub odpowiedzi:
C. Create a firewall rule to allow access from the Identity-Aware Proxy (IAP) IP range. Grant the role of an IAP-secured Tunnel User to the administrators.

2. Kompleksowe wyjaśnienie dlaczego dana odpowiedź jest prawidłowa (Analiza):
Odpowiedź C jest prawidłowa, ponieważ Identity-Aware Proxy (IAP) TCP Forwarding (tunelowanie TCP) to najbardziej bezpieczne, elastyczne i bezkosztowe rozwiązanie do zdalnego zarządzania maszynami prywatnymi w GCP.

Jak to działa:
a. Maszyny wirtualne nie potrzebują zewnętrznych (publicznych) adresów IP, co redukuje powierzchnię ataku i eliminuje koszty związane z publicznymi IP.
b. Zamiast łączyć się bezpośrednio, administratorzy inicjują tunel SSH za pomocą narzędzia gcloud (`gcloud compute ssh --tunnel-through-iap`).
c. Ruch z internetu trafia najpierw do punktu końcowego IAP, który weryfikuje tożsamość użytkownika za pomocą IAM oraz wymusza uwierzytelnienie wieloskładnikowe (MFA).
d. Po pomyślnej weryfikacji, IAP przekazuje ruch do maszyny wirtualnej. Do poprawnego działania wymagana jest jedynie reguła zapory sieciowej (firewall) w sieci VPC zezwalająca na ruch przychodzący na port 22 (SSH) wyłącznie z dedykowanego zakresu IP Google IAP: `35.235.240.0/20`.
e. Jest to rozwiązanie w pełni darmowe (optymalizacja kosztów) i nie wymaga utrzymywania dodatkowej infrastruktury (VPN, Bastion).

3. Wyjaśnienie z osobna każdej niepoprawnej odpowiedzi:
A. Create a site-to-site VPN from your corporate network to Google Cloud.
   * Dlaczego nieprawidłowa: Utworzenie i utrzymywanie tunelu VPN (Cloud VPN) generuje stałe koszty godzinowe oraz wymaga konfiguracji urządzeń sieciowych po stronie lokalnej. Jest to rozwiązanie znacznie droższe i bardziej złożone niż darmowy IAP TCP forwarding, zwłaszcza do "okazjonalnego" zarządzania serwerami.
B. Configure server instances with public IP addresses. Create a firewall rule...
   * Dlaczego nieprawidłowa: Przypisanie publicznych IP do maszyn wirtualnych wystawia je na ataki skanowania sieci w internecie. Ponadto publiczne adresy IP w GCP generują dodatkowe koszty, a filtrowanie ruchu wyłącznie po adresach IP jest mniej bezpieczne niż weryfikacja tożsamości IAM.
D. Create a jump host instance with public IP. Manage the instances by connecting through...
   * Dlaczego nieprawidłowa: Maszyna typu jump host (Bastion) musi być stale uruchomiona, co generuje koszty obliczeniowe (Compute Engine). Ponadto serwer Bastion staje się pojedynczym punktem awarii oraz celem ataków, wymagającym ciągłego patchowania i monitorowania.

4. Wskazówki, hinty, tips and tricks:
* Bezpieczny, tani dostęp SSH/RDP do maszyn prywatnych w GCP -> Zawsze **IAP TCP Forwarding** (IAP-secured tunnel).
* Zakres adresów IP dla reguły firewall IAP to **`35.235.240.0/20`**.
* Rola IAM wymagana do tunelowania to **`roles/iap.tunnelResourceAccessor`** (IAP-secured Tunnel User).

5. Reguły wyboru odpowiedzi (Słowa kluczowe):
* Manage private VMs via SSH / optimize cost and security -> IAP IP range (35.235.240.0/20) + IAP-secured Tunnel User.

Wskazówki egzaminacyjne (Tips & Tricks)

Reguła Egzaminacyjna (Exam Rule): 
Jeśli scenariusz dotyczy zabezpieczania zasobów chmurowych (GCP), zawsze wybieraj rozwiązanie typu Managed (SCC, Secret Manager, Cloud KMS), a unikaj rozwiązań self-managed, chyba że pytanie wyraźnie wymaga dostosowania niskopoziomowego.

Haczyki egzaminacyjne (Exam Traps):
- Pułapka IAM: Pytania o uprawnienia często sugerują 'Project Owner' – zawsze szukaj 'Least Privilege' (np. 'Role: Secret Manager Secret Accessor').
- Pułapka Sieciowa: Często mylone są VPC Peering (wydajność) oraz VPN (szyfrowanie/on-premise).

Głębokie wyjaśnienie techniczne:
Rozwiązanie bazuje na GCP Shared Responsibility Model. Google zarządza bezpieczeństwem infrastruktury (Physical, Network, Host), podczas gdy administrator zarządza tożsamością (IAM), danymi (Encryption, Cloud KMS) i regułami dostępu (VPC Firewall).

Analiza i Podsumowanie (AI)

Kluczowe zagadnienia

Sugerowana odpowiedź: C

Analiza strategiczna: IAP to fundament modelu "Zero Trust" w GCP. Zastąpienie starych, niebezpiecznych metod (Jump Hosts) usługą zarządzaną (IAP) jest kluczowym elementem modernizacji bezpieczeństwa. Dla egzaminu ważne jest zrozumienie, że IAP eliminuje potrzebę ekspozycji SSH na świat i upraszcza architekturę.

Dodatkowe wskazówki

  • Możesz połączyć IAP z IAM Conditions, aby ograniczyć dostęp do SSH tylko w godzinach pracy (np. 9:00-17:00).
  • Pamiętaj o audycie: każde użycie tunelu IAP jest rejestrowane w logach audytowych (Data Access).
