Question 224 / 361

You have numerous private virtual machines on Google Cloud. You occasionally need to manage the servers through Secure Socket Shell (SSH) from a remote location. You want to configure remote access to the servers in a manner that optimizes security and cost efficiency. What should you do?

  • A. Create a site-to-site VPN from your corporate network to Google Cloud.
  • B. Configure server instances with public IP addresses. Create a firewall rule to only allow traffic from your corporate IPs.
  • C. Create a firewall rule to allow access from the Identity-Aware Proxy (IAP) IP range. Grant the role of an IAP-secured Tunnel User to the administrators.
  • D. Create a jump host instance with public IP. Manage the instances by connecting through the jump host.
Show Suggested Answer Hide Answer
Suggested Answer: C

Wyjaśnienie

Potwierdzona odpowiedź: C (Create a firewall rule to allow access from the Identity-Aware Proxy (IAP) IP range. Grant the role of an IAP-secured Tunnel User to the administrators)

Wyjaśnienie:
- IAP for TCP Forwarding: Jest to mechanizm, który pozwala na bezpieczne tunelowanie ruchu TCP (SSH/RDP) do maszyn wirtualnych bez konieczności nadawania im publicznych adresów IP lub konfigurowania VPN.
- Bezpieczeństwo: IAP uwierzytelnia użytkownika przez Google Cloud IAM. Ruch jest przesyłany przez infrastrukturę Google, co eliminuje konieczność otwierania portów SSH (22) lub RDP (3389) dla całego internetu.
- IAP IP Range: Aby IAP mógł komunikować się z Twoimi instancjami, musisz pozwolić na ruch z zakresu IP: `35.235.240.0/20` w regułach firewalla VPC.

Dlaczego pozostałe odpowiedzi są niepoprawne:
- A. Site-to-site VPN: Jest to rozwiązanie do łączenia sieci, a nie do zarządzania konkretnymi maszynami. VPN jest znacznie droższy i trudniejszy w utrzymaniu niż IAP, jeśli potrzebujesz tylko dostępu SSH/RDP.
- B. Public IP + Firewall: Nadawanie publicznych IP maszynom wirtualnym (nawet z restrykcją firewall) jest przeciwieństwem "optymalizacji bezpieczeństwa" (zwiększa powierzchnię ataku).
- D. Jump host: Jump host (bramka) z publicznym IP sam w sobie jest punktem, który musisz dodatkowo zabezpieczać, łatać i monitorować. IAP (C) jest usługą zarządzaną przez Google, więc nie musisz dbać o jej infrastrukturę.

Wskazówki i triki (Tips & Tricks):
- "Manage VMs via SSH/RDP" + "No public IP" + "Secure & Cost efficient" = IAP-secured Tunnel User.
- Zakres IP IAP: `35.235.240.0/20` (konieczne zapamiętanie na egzamin!).

Praktyczne informacje na egzamin:
- Aby użyć IAP TCP forwarding, musisz mieć zainstalowany `gcloud` i skonfigurowany dostęp do tunelu (np. `gcloud compute ssh ... --tunnel-through-iap`).
- Użytkownik musi mieć rolę `IAP-Secured Tunnel User` (nie `Web App User`!).

Analiza i Podsumowanie (AI)

Kluczowe zagadnienia

Sugerowana odpowiedź: C

Analiza strategiczna: IAP to fundament modelu "Zero Trust" w GCP. Zastąpienie starych, niebezpiecznych metod (Jump Hosts) usługą zarządzaną (IAP) jest kluczowym elementem modernizacji bezpieczeństwa. Dla egzaminu ważne jest zrozumienie, że IAP eliminuje potrzebę ekspozycji SSH na świat i upraszcza architekturę.

Dodatkowe wskazówki

  • Możesz połączyć IAP z IAM Conditions, aby ograniczyć dostęp do SSH tylko w godzinach pracy (np. 9:00-17:00).
  • Pamiętaj o audycie: każde użycie tunelu IAP jest rejestrowane w logach audytowych (Data Access).
