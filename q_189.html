Question 189 / 361

Your application is deployed as a highly available, cross-region solution behind a global external HTTP(S) load balancer. You notice significant spikes in traffic from multiple IP addresses, but it is unknown whether the IPs are malicious. You are concerned about your application's availability. You want to limit traffic from these clients over a specified time interval.
What should you do?

  • A. Configure a throttle action by using Google Cloud Armor to limit the number of requests per client over a specified time interval.
  • B. Configure a rate_based_ban action by using Google Cloud Armor and set the ban_duration_sec parameter to the specified time interval.
  • C. Configure a firewall rule in your VPC to throttle traffic from the identified IP addresses.
  • D. Configure a deny action by using Google Cloud Armor to deny the clients that issued too many requests over the specified time interval.
Show Suggested Answer Hide Answer
Suggested Answer: A

Wyjaśnienie

Poprawna odpowiedź: A (Configure a throttle action by using Google Cloud Armor to limit the number of requests per client over a specified time interval)

Dlaczego ta odpowiedź jest poprawna:
- Cloud Armor Rate Limiting: Pozwala na kontrolowanie natężenia ruchu przychodzącego do aplikacji za Load Balancerem.
- Akcja Throttle (Ograniczenie): Służy do nakładania limitu na liczbę żądań w danym czasie (np. max 100 żądań na minutę na jeden adres IP). Nadmiarowe żądania są odrzucane (zazwyczaj błąd 429), ale po upływie interwału klient może spróbować ponownie. Jest to idealne rozwiązanie, gdy "nie wiadomo, czy IP są złośliwe" – chronimy dostępność aplikacji, ale nie odcinamy całkowicie potencjalnych użytkowników.
- Kontekst: Pytanie wspomina o spike'ach z wielu IP i niepewności co do ich intencji. "Throttle" zapewnia balans między bezpieczeństwem a dostępnością (User Experience).

Analiza niepoprawnych odpowiedzi:
- B. rate_based_ban action: Ta akcja jest bardziej agresywna. Jeśli klient przekroczy próg, zostaje całkowicie ZABLOKOWANY (zbanowany) na określony czas (np. 10 minut). Jest to lepsze przy wyraźnych atakach DoS, ale może uderzyć w legalnych użytkowników przy błędnej konfiguracji w scenariuszu "niepewnym".
- C. VPC Firewall rule: Tradycyjne firewalle VPC działają na warstwie 3/4 (IP/Port) i nie posiadają natywnej funkcji "throttlingu" (ograniczania liczby żądań HTTP na sekundę). Firewalle są typu "zezwól" lub "zablokuj".
- D. Deny action: Zwykłe "deny" po prostu blokuje ruch z danego IP bez względu na natężenie. Nie jest to mechanizm rate-limitingu, o który prosi pytanie.

Wskazówki i triki (Tips & Tricks):
- "Limit traffic" + "Unknown if malicious" = Cloud Armor Throttle.
- "Identify and block attacks" + "Threshold exceeded" = Cloud Armor Rate-based Ban.
- Pamiętaj: Cloud Armor konfigurujesz w "Security Policies" przypisanych do "Backend Services" Load Balancera.

Praktyczne informacje na egzamin:
- Zrozum parametry rate-limitingu: `rate_limit_threshold` (ile?), `conform_action` (co jeśli ok?), `exceed_action` (co jeśli za dużo?).
- Cloud Armor chroni przed atakami OWASP Top 10 (SQLi, XSS) oraz przed atakami DDoS w warstwie 7.

Analiza i Podsumowanie (AI)

Kluczowe zagadnienia

Sugerowana odpowiedź: A

Analiza strategiczna: To pytanie testuje umiejętność zarządzania dostępnością aplikacji w sytuacjach niejednoznacznych. W bezpieczeństwie "False Positives" (błędne uznanie legalnego ruchu za atak) są dużym problemem. Throttling jest techniką łagodniejszą niż banowanie, pozwalającą systemowi "przetrwać" nagły wzrost ruchu bez całkowitego odcinania użytkowników, którzy mogą po prostu intensywniej korzystać z serwisu.

Dodatkowe wskazówki

  • Możesz używać kluczy rate-limitingu innych niż adres IP, np. ciasteczka sesyjne lub nagłówki HTTP, co jest bardziej precyzyjne przy użytkownikach za NAT-em.
  • Dzięki Cloud Armor możesz również skonfigurować strony błędów (Custom Error Pages) dla odrzuconych żądań.
