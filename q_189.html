Question 189 / 361

Your application is deployed as a highly available, cross-region solution behind a global external HTTP(S) load balancer. You notice significant spikes in traffic from multiple IP addresses, but it is unknown whether the IPs are malicious. You are concerned about your application's availability. You want to limit traffic from these clients over a specified time interval.
What should you do?

  • A. Configure a throttle action by using Google Cloud Armor to limit the number of requests per client over a specified time interval.
  • B. Configure a rate_based_ban action by using Google Cloud Armor and set the ban_duration_sec parameter to the specified time interval.
  • C. Configure a firewall rule in your VPC to throttle traffic from the identified IP addresses.
  • D. Configure a deny action by using Google Cloud Armor to deny the clients that issued too many requests over the specified time interval.
Show Suggested Answer Hide Answer
Suggested Answer: A

Wyjaśnienie

Potwierdzona odpowiedź: A (Configure a throttle action by using Google Cloud Armor to limit the number of requests per client over a specified time interval).

Wyjaśnienie:
Google Cloud Armor oferuje funkcję Rate Limiting (ograniczanie natężenia ruchu), która jest idealna do ochrony dostępności aplikacji przed nagłymi wzrostami ruchu (spikes). Akcja "Throttle" pozwala na ustawienie limitu żądań w określonym czasie (np. 100 na minutę na dany IP). Żądania powyżej limitu są odrzucane, ale po upływie interwału klient znów może wysyłać zapytania. Jest to najlepszy wybór, gdy "nie wiadomo, czy ruch jest złośliwy" – chronimy infrastrukturę przed przeciążeniem, ale nie odcinamy całkowicie potencjalnych, legalnych użytkowników (jak w przypadku blokady stałej).

Dlaczego pozostałe są błędne:
- B. rate_based_ban action: Ta akcja jest bardziej restrykcyjna – po przekroczeniu progu klient zostaje całkowicie zablokowany (zbanowany) na określony czas. Może to być zbyt agresywne, jeśli nie mamy pewności co do złośliwości ruchu.
- C. Firewall rule: Tradycyjne reguły zapory sieciowej VPC działają na warstwie 3/4 (IP/port) i nie posiadają natywnej funkcji ograniczania liczby żądań HTTP (warstwa 7) w czasie (throttlingu).
- D. Deny action: Zwykła akcja "deny" po prostu blokuje cały ruch bez względu na jego natężenie i limity czasowe. Nie jest to mechanizm rate-limitingu.

Wskazówki egzaminacyjne (Tips & Tricks):
- "Limit traffic spikes" + "Unknown intent" = Cloud Armor Throttle (najbezpieczniejszy balans).
- "Identify and stop DDoS/Brute-force" = Cloud Armor Rate-based Ban.
- Pamiętaj, że Cloud Armor działa na poziomie Global External HTTP(S) Load Balancera.

Kluczowe zagadnienia do powtórzenia:
- Parametry rate-limitingu w Cloud Armor (threshold, interval, exceed_action).
- Różnica między throttlingiem a banowaniem.
- Ochrona warstwy 7 (L7) w Google Cloud.

Analiza i Podsumowanie Dyskusji (AI)

Analiza i Wyjaśnienie

Sugerowana odpowiedź: A

Głęboka analiza: W sytuacjach awaryjnych priorytetem jest utrzymanie serwisu online (Availability). Jeśli nie mamy dowodów na atak, całkowite blokowanie IP może prowadzić do utraty klientów. Throttling w Cloud Armor pozwala "wygładzić" szczyty ruchu, dając aplikacji czas na przetworzenie żądań bez ryzyka awarii backendu.
