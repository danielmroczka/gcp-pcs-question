Question 189 / 361

Your application is deployed as a highly available, cross-region solution behind a global external HTTP(S) load balancer. You notice significant spikes in traffic from multiple IP addresses, but it is unknown whether the IPs are malicious. You are concerned about your application's availability. You want to limit traffic from these clients over a specified time interval.
What should you do?

  • A. Configure a throttle action by using Google Cloud Armor to limit the number of requests per client over a specified time interval.
  • B. Configure a rate_based_ban action by using Google Cloud Armor and set the ban_duration_sec parameter to the specified time interval.
  • C. Configure a firewall rule in your VPC to throttle traffic from the identified IP addresses.
  • D. Configure a deny action by using Google Cloud Armor to deny the clients that issued too many requests over the specified time interval.
Show Suggested Answer Hide Answer
Suggested Answer: A

Wyjaśnienie

1. Prawidłowa odpowiedź lub odpowiedzi:
A. Configure a throttle action by using Google Cloud Armor to limit the number of requests per client over a specified time interval.

2. Kompleksowe wyjaśnienie dlaczego dana odpowiedź jest prawidłowa (Analiza):
Aplikacja doświadcza nagłych skoków natężenia ruchu (traffic spikes) z wielu adresów IP. Ponieważ intencje klientów i status adresów IP (czy są złośliwe, czy to np. nagły wzrost popularności serwisu) nie są znane, priorytetem jest zabezpieczenie dostępności aplikacji przy jednoczesnym uniknięciu fałszywych dopasowań (false positives) i całkowitego zablokowania potencjalnych, prawdziwych klientów.
Google Cloud Armor posiada mechanizm ograniczania natężenia ruchu (Rate Limiting). Konfiguracja akcji typu **Throttle** pozwala na nałożenie limitu na liczbę żądań HTTP(S), jakie dany klient może wysłać w określonym przedziale czasu (np. maksymalnie 100 żądań na minutę). Jeśli limit zostanie przekroczony, nadmiarowy ruch jest odrzucany, a po zresetowaniu licznika czasu klient może ponownie wysyłać zapytania. Jest to optymalny kompromis chroniący serwery aplikacyjne przed przeciążeniem bez odcinania dostępu klientom na stałe.

3. Wyjaśnienie z osobna każdej niepoprawnej odpowiedzi:
- B. Configure a rate_based_ban action...: Akcja typu ban całkowicie blokuje (zrzuca cały ruch) z danego adresu IP na określony czas (np. 5 minut) po przekroczeniu limitu. Przy braku pewności, czy ruch jest złośliwy, może to doprowadzić do zablokowania prawdziwych użytkowników na długi czas.
- C. Configure a firewall rule in your VPC to throttle traffic...: Zapory sieciowe VPC (VPC Firewall Rules) działają w warstwach 3 i 4 modelu OSI (IP/porty) i nie posiadają funkcji inspekcji warstwy aplikacyjnej L7 ani natywnej obsługi throttlingu zapytań HTTP w czasie.
- D. Configure a deny action by using Google Cloud Armor to deny the clients that issued too many requests...: Zwykła akcja `deny` w Cloud Armor po prostu bezwarunkowo blokuje ruch na podstawie reguły (np. adresu IP), ale nie jest to mechanizm dynamicznego rate-limitingu (nie potrafi zliczać zapytań w oknie czasowym per-client).

4. Wskazówki, hinty, tips and tricks:
- Jeśli ruch pochodzi z nieznanych źródeł (nie wiemy, czy to atak, czy legalni klienci) i celem jest ochrona wydajności / dostępności (availability), wybieramy **Throttle** (dławienie ruchu ponad limit).
- Jeśli celem jest twarde odcięcie ataku typu Brute Force lub DDoS ze znanych złośliwych IP, wybieramy **rate_based_ban**.

5. Reguły wyboru odpowiedzi (Słowa kluczowe):
- "limit traffic from clients" + "unknown whether IPs are malicious" + "limit over time interval" -> Cloud Armor -> throttle action.
