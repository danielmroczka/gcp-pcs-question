Question 131 / 361

You perform a security assessment on a customer architecture and discover that multiple VMs have public IP addresses. After providing a recommendation to remove the public IP addresses, you are told those VMs need to communicate to external sites as part of the customer's typical operations. What should you recommend to reduce the need for public IP addresses in your customer's VMs?

  • A. Google Cloud Armor
  • B. Cloud NAT
  • C. Cloud Router
  • D. Cloud VPN
Show Suggested Answer Hide Answer
Suggested Answer: B

Wyjaśnienie

**Potwierdzona odpowiedź: AC**

Wyjaśnienie: 
Aby całkowicie odizolować instancję Compute Engine zarówno od internetu, jak i od usług/API Google, należy zablokować dwie główne drogi komunikacji zewnętrznej:
1. Public IP: Brak publicznego adresu IP uniemożliwia bezpośrednią, dwukierunkową komunikację z internetem. Instancja z samym prywatnym IP nie może inicjować połączeń ze światem zewnętrznym bez bramy NAT lub serwera proxy.
2. Private Google Access (PGA): Jest to ustawienie na poziomie podsieci, które pozwala instancjom posiadającym wyłącznie prywatne adresy IP na łączenie się z publicznymi adresami IP usług Google (takich jak Cloud Storage, BigQuery czy KMS). Jeśli PGA pozostanie włączone, instancja mimo braku publicznego IP wciąż będzie miała dostęp do API Google. Wyłączenie PGA domyka tę lukę.

Dlaczego pozostałe są błędne:
B. IP Forwarding: To ustawienie pozwala instancji na przekazywanie pakietów, które nie są adresowane do niej samej (wymagane np. przy budowie własnych bram NAT lub routerów programowych). Wyłączenie tego nie blokuje dostępu samej instancji do internetu czy API Google.
D. Static routes: Trasy statyczne służą do definiowania ścieżek ruchu wewnątrz sieci VPC lub do sieci zewnętrznych (np. przez VPN). Chociaż można by ich użyć do przekierowania ruchu w 'czarną dziurę', samo ich istnienie nie jest domyślnym mechanizmem zapewniającym dostęp do internetu czy API Google w taki sposób jak Public IP czy PGA.

Wskazówki egzaminacyjne (Tips & Tricks):
- Jeśli pytanie wspomina o dostępie do 'Google Services/APIs' z instancji bez publicznego IP, kluczem zawsze jest 'Private Google Access'.
- VPC Networking - Public vs Private IP
- Zasady routingu w GCP

Analiza i Podsumowanie Dyskusji (AI)

Reguła Egzaminacyjna (Exam Rule)

Dla każdej architektury, która wymaga "izolacji publicznej" przy jednoczesnym zachowaniu łączności wychodzącej, Cloud NAT jest jedyną słuszną odpowiedzią w GCP.

Haczyki Egzaminacyjne (Exam Traps)

  • Cloud Router vs Cloud NAT: Egzamin często zestawia te usługi. Zapamiętaj: Router to "mózg" (zarządzanie trasami BGP), NAT to "narzędzie" (translacja adresów). Sam Router nie zapewni wyjścia do internetu.
  • Myśl o NAT jako o firewallu: Pamiętaj, że Cloud NAT nie otwiera połączeń przychodzących. Jeśli pytanie wspomina o potrzebie przyjmowania ruchu (np. web server), NAT nie wystarczy – potrzebny będzie Load Balancer.

Głębokie wyjaśnienie techniczne (GCP Professional Cloud Security Engineer)

Cloud NAT działa jako usługa typu Software-Defined Networking (SDN) w warstwie zarządzanej GCP. Wykorzystuje IP masquerading, mapując prywatne adresy IP instancji (z zakresu RFC 1918) na jeden lub więcej publicznych adresów IP zarezerwowanych dla bramy NAT. Z punktu widzenia bezpieczeństwa, pozwala to na utrzymanie "Zero Trust" wewnątrz sieci VPC: maszyny nie są osiągalne z Internetu, co eliminuje ryzyko skanowania portów czy ataków typu brute-force bezpośrednio na instancje.
