Question 61 / 361

You need to ensure that specific sensitive data in a BigQuery table is only visible to authorized users. What is the most granular way to achieve this?

  • A. Dataset-level permissions
  • B. Table-level permissions
  • C. Row-level security
  • D. Column-level security using policy tags
Show Suggested Answer Hide Answer
Suggested Answer: D

Wyjaśnienie

Poprawna odpowiedź: D (Column-level security using policy tags)

Analiza poprawności:
Column-level security (CLS) to najbardziej precyzyjne narzędzie kontroli dostępu do danych wewnątrz tabeli BigQuery. Dzięki integracji z Data Catalog i mechanizmowi "policy tags" (tagi polityk), administrator może przypisać określone etykiety (np. "PII-Data") do konkretnych kolumn. Następnie, stosując polityki IAM na poziomie tych tagów, możesz precyzyjnie określić, które grupy użytkowników mają prawo "odczytu" danych z tak oznaczonej kolumny. Nawet jeśli użytkownik ma uprawnienia `Data Viewer` na całej tabeli, zablokowanie dostępu do tagu uniemożliwi mu wyświetlenie zawartości danej kolumny (zwrócony zostanie błąd lub wartość NULL).

Dlaczego pozostałe są błędne:
A (Dataset-level): To uprawnienie do całego zbioru (wszystkich tabel w danym zbiorze). Jest zbyt szerokie i nie spełnia wymogu "most granular" (najbardziej precyzyjnego).
B (Table-level): Ogranicza dostęp do całej tabeli, co również nie jest rozwiązaniem "na poziomie kolumny" (granularności).
C (Row-level security): To filtrowanie wierszy (np. użytkownik widzi tylko wiersze dla swojego regionu). Choć to precyzyjna metoda, nie pozwala ukryć konkretnych *atrybutów* (kolumn) wewnątrz wiersza, które użytkownik może zobaczyć.

Wskazówki egzaminacyjne:
- "Granular" + "BigQuery" + "Sensitive data" / "Visible": Zawsze szukaj "Column-level security" lub "policy tags".
- "PII": To słowo klucz, które powinno automatycznie kierować Cię w stronę zabezpieczeń na poziomie kolumn.
- Eliminacja: Jeśli pytanie mówi o kolumnach/atrybutach – nigdy nie wybieraj Dataset lub Table level.

Analiza i Wyjaśnienie

Sugerowana odpowiedź: D

Analiza spornych kwestii (AI): Wiele osób myli Row-level security z Column-level security. Row-level służy do "segregacji użytkowników" (kto widzi jakie wiersze), natomiast Column-level służy do "ochrony danych wrażliwych" (kto widzi jakie kolumny/atrybuty).
