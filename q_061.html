Question 61 / 361

A customer wants to deploy a large number of 3-tier web applications on Compute Engine. How should the customer ensure authenticated network separation between the different tiers of the application?

  • A. Run each tier in its own Project, and segregate using Project labels.
  • B. Run each tier with a different Service Account (SA), and use SA-based firewall rules.
  • C. Run each tier in its own subnet, and use subnet-based firewall rules.
  • D. Run each tier with its own VM tags, and use tag-based firewall rules.
Show Suggested Answer Hide Answer
Suggested Answer: B

Wyjaśnienie

Potwierdzona odpowiedź: B (Run each tier with a different Service Account (SA), and use SA-based firewall rules.)

Wyjaśnienie:
Używanie kont serwisowych (Service Accounts) do definiowania reguł firewall jest zalecaną praktyką Google Cloud ("best practice") dla dynamicznych środowisk.
1. Authenticated Separation: W przeciwieństwie do tagów sieciowych (network tags), które są tylko etykietami tekstowymi, konta serwisowe są tożsamościami (IAM identities). Reguły firewall oparte na SA są bezpieczniejsze, ponieważ wymagają uprawnień `iam.serviceAccounts.actAs`, aby przypisać daną tożsamość do instancji.
2. Skalowalność: Jeśli Twoja aplikacja się skaluje (np. dodajesz nowe instancje w Managed Instance Group), automatycznie dziedziczą one konto serwisowe i powiązane z nim reguły firewall.
3. Precyzja: Możesz pozwolić warstwie "Frontend" na komunikację z warstwą "Backend" tylko wtedy, gdy instancja Backend używa specyficznego konta serwisowego, niezależnie od jej adresu IP czy podsieci.

Dlaczego pozostałe są błędne:
A. Project labels: Etykiety projektów służą do celów organizacyjnych i bilingowych. Nie mają żadnego wpływu na filtrowanie ruchu sieciowego wewnątrz VPC.
C. Subnet-based firewall: Ograniczanie ruchu na podstawie podsieci jest podejściem tradycyjnym. W chmurze jest ono mało elastyczne i utrudnia zarządzanie w dużych skalach, szczególnie gdy aplikacje są rozproszone.
D. Tag-based firewall: Tagi są łatwe w użyciu, ale mniej bezpieczne niż SA. Każdy, kto ma uprawnienia do edycji instancji (Compute Instance Admin), może dodać lub usunąć tag, zmieniając tym samym profil bezpieczeństwa sieciowego maszyny bez dodatkowej weryfikacji tożsamości.

Tips & Tricks:
- Słowo "Authenticated" w pytaniu o firewall niemal zawsze wskazuje na "Service Accounts".
- Tagi (Tags) są dobre dla prostych środowisk; Service Accounts (SA) są dla środowisk produkcyjnych i regulowanych (compliance).

Zagadnienia:
- VPC Firewall Rules - Source/Target filtering.
- Service Account as a security identity.
- Least Privilege in Network Design.

Sugerowana odpowiedź: B

Praktyczne wnioski: Stosowanie SA-based firewall rules pozwala na stworzenie mikro-segmentacji sieci, która jest niezależna od fizycznej (lub logicznej w chmurze) topologii adresacji IP.
