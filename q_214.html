Question 214 / 361

Your organization processes sensitive health information. You want to ensure that data is encrypted while in use by the virtual machines (VMs). You must create a policy that is enforced across the entire organization. What should you do?

  • A. Implement an organization policy that ensures that all VM resources created across your organization use customer-managed encryption keys (CMEK) protection.
  • B. Implement an organization policy that ensures all VM resources created across your organization are Confidential VM instances.
  • C. Implement an organization policy that ensures that all VM resources created across your organization use Cloud External Key Manager (EKM) protection.
  • D. No action is necessary because Google encrypts data while it is in use by default.
Show Suggested Answer Hide Answer
Suggested Answer: B

Wyjaśnienie

1. Prawidłowa odpowiedź lub odpowiedzi:
B. Implement an organization policy that ensures all VM resources created across your organization are Confidential VM instances.

2. Kompleksowe wyjaśnienie dlaczego dana odpowiedź jest prawidłowa (Analiza):
Odpowiedź B jest prawidłowa, ponieważ Confidential VMs (Poufne Maszyny Wirtualne) to technologia Google Cloud, która szyfruje dane w pamięci RAM podczas ich przetwarzania (encryption in-use). Zastosowanie polityki organizacji gwarantuje centralne i bezwyjątkowe egzekwowanie tej reguły.

Szczegóły techniczne:
a. **Szyfrowanie danych w użyciu (Encryption in-use):** Tradycyjne szyfrowanie chroni dane w spoczynku (at-rest) i w transporcie (in-transit). Dane w pamięci RAM procesora są jednak jawne. Confidential VMs wykorzystują sprzętowe wsparcie procesorów (np. AMD SEV - Secure Encrypted Virtualization) do szyfrowania pamięci maszyn wirtualnych za pomocą kluczy generowanych sprzętowo, do których nie ma dostępu nawet hypervisor Google.
b. **Wymuszenie w skali organizacji:** Poprzez wdrożenie ograniczenia polityki organizacji `constraints/compute.requireConfidentialCompute` (wymagaj poufnych obliczeń), administrator zabezpiecza całe środowisko przed uruchomieniem standardowej (nienależącej do kategorii Confidential) maszyny wirtualnej.

3. Wyjaśnienie z osobna każdej niepoprawnej odpowiedzi:
A. ...use customer-managed encryption keys (CMEK) protection.
   * Dlaczego nieprawidłowa: Szyfrowanie CMEK zabezpiecza dane w spoczynku (na dyskach persistent disks lub w kubełkach GCS). Nie chroni danych w użyciu (w pamięci RAM podczas wykonywania obliczeń przez procesor).
C. ...use Cloud External Key Manager (EKM) protection.
   * Dlaczego nieprawidłowa: Cloud EKM służy do przechowywania kluczy szyfrujących w zewnętrznym systemie poza GCP w celu szyfrowania danych w spoczynku. Nie chroni pamięci RAM działającej maszyny wirtualnej.
D. No action is necessary because Google encrypts data while it is in use by default.
   * Dlaczego nieprawidłowa: Jest to nieprawda. Domyślnie Google szyfruje dane w spoczynku oraz w transporcie. Szyfrowanie danych w użyciu (w pamięci) nie jest włączone domyślnie dla standardowych maszyn VM, ponieważ wymaga specjalnego typu maszyn (Confidential VMs) i niesie minimalny narzut wydajnościowy.

4. Wskazówki, hinty, tips and tricks:
* Szyfrowanie danych w spoczynku -> CMEK / CSEK.
* Szyfrowanie danych w transporcie -> TLS / IPsec.
* Szyfrowanie danych w użyciu (in-use / in memory) -> **Confidential VMs / Confidential Computing**.
* Ograniczenie polityki organizacji dla Confidential VM to `compute.requireConfidentialCompute`.

5. Reguły wyboru odpowiedzi (Słowa kluczowe):
* Encrypted while in use / encryption in-use -> Confidential VMs / Confidential Computing.
