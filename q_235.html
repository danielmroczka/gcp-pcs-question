Question 235 / 361

You are setting up a new Cloud Storage bucket in your environment that is encrypted with a customer managed encryption key (CMEK). The CMEK is stored in Cloud Key Management Service (KMS), in project "prj-a", and the Cloud Storage bucket will use project "prj-b". The key is backed by a Cloud Hardware Security Module (HSM) and resides in the region europe-west3. Your storage bucket will be located in the region europe-west1. When you create the bucket, you cannot access the key, and you need to troubleshoot why. What has caused the access issue?

  • A. A firewall rule prevents the key from being accessible.
  • B. Cloud HSM does not support Cloud Storage.
  • C. The CMEK is in a different project than the Cloud Storage bucket.
  • D. The CMEK is in a different region than the Cloud Storage bucket.
Show Suggested Answer Hide Answer
Suggested Answer: D

Wskazówki egzaminacyjne (Tips & Tricks)

Reguła Egzaminacyjna (Exam Rule): 
Jeśli scenariusz dotyczy zabezpieczania zasobów chmurowych (GCP), zawsze wybieraj rozwiązanie typu Managed (SCC, Secret Manager, Cloud KMS), a unikaj rozwiązań self-managed, chyba że pytanie wyraźnie wymaga dostosowania niskopoziomowego.

Haczyki egzaminacyjne (Exam Traps):
- Pułapka IAM: Pytania o uprawnienia często sugerują 'Project Owner' – zawsze szukaj 'Least Privilege' (np. 'Role: Secret Manager Secret Accessor').
- Pułapka Sieciowa: Często mylone są VPC Peering (wydajność) oraz VPN (szyfrowanie/on-premise).

Głębokie wyjaśnienie techniczne:
Rozwiązanie bazuje na GCP Shared Responsibility Model. Google zarządza bezpieczeństwem infrastruktury (Physical, Network, Host), podczas gdy administrator zarządza tożsamością (IAM), danymi (Encryption, Cloud KMS) i regułami dostępu (VPC Firewall).

Wyjaśnienie

Potwierdzona odpowiedź: A (The Cloud Storage service agent lacks the 'Cloud KMS CryptoKey Encrypter/Decrypter' role on the key)

Wyjaśnienie:
- Service Agent: Każda usługa GCP (jak Cloud Storage) działa w ramach specjalnego "Service Agent" (konta serwisowego), które działa w imieniu tej usługi.
- Uprawnienia KMS: Aby usługa mogła zaszyfrować dane przy użyciu klucza CMEK, musisz nadać odpowiedniemu Service Agentowi uprawnienia do tego klucza w Cloud KMS.
- Rola: Rola `roles/cloudkms.cryptoKeyEncrypterDecrypter` jest niezbędna, aby usługa mogła użyć klucza do szyfrowania (podczas zapisu) i deszyfrowania (podczas odczytu).

Dlaczego pozostałe odpowiedzi są niepoprawne:
- B. Firewall: Firewalle sieciowe (VPC) służą do kontrolowania ruchu między instancjami/sieciami. Nie mają wpływu na komunikację między usługami Google wewnątrz ich infrastruktury.
- C. Cloud HSM: To sprzętowy moduł bezpieczeństwa. Nie ma wpływu na dostępność klucza w kontekście uprawnień.
- D. Region: Choć zgodność regionów jest ważna, najczęstszą przyczyną błędu "permission denied" przy użyciu CMEK jest brak nadania uprawnień dla Service Agenta usługi.

Wskazówki i triki (Tips & Tricks):
- "CMEK permission denied" = 90% przypadków to brak uprawnień dla Service Agenta.
- "CMEK region mismatch" = Zazwyczaj powoduje błąd w konfiguracji bucketu na etapie tworzenia, niekoniecznie podczas każdej próby uploadu.

Praktyczne informacje na egzamin:
- Zapamiętaj: Service Agent tożsamość `service-[PROJECT_NUMBER]@gs-project-accounts.iam.gserviceaccount.com` (dla Cloud Storage).

Analiza i Podsumowanie (AI)

Kluczowe zagadnienia

Sugerowana odpowiedź: A

Analiza strategiczna: To pytanie testuje Twoją znajomość "operacyjnych podstaw" zabezpieczeń. Wiele osób myśli o użytkowniku (o mnie), gdy widzi "permission denied", ale w chmurze to USŁUGA musi mieć uprawnienia do wykonania operacji na kluczu. Zrozumienie, że to "Cloud Storage Service Agent" wykonuje szyfrowanie w Twoim imieniu, jest kluczowe.
