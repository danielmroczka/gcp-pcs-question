Question 150 / 361

Your organization's Google Cloud VMs are deployed via an instance template that configures them with a public IP address in order to host web services for external users. The VMs reside in a service project that is attached to a host (VPC) project containing one custom Shared VPC for the VMs. You have been asked to reduce the exposure of the VMs to the internet while continuing to service external users. You have already recreated the instance template without a public IP address configuration to launch the managed instance group (MIG). What should you do?

  • A. Deploy a Cloud NAT Gateway in the service project for the MIG.
  • B. Deploy a Cloud NAT Gateway in the host (VPC) project for the MIG.
  • C. Deploy an external HTTP(S) load balancer in the service project with the MIG as a backend.
  • D. Deploy an external HTTP(S) load balancer in the host (VPC) project with the MIG as a backend.
Show Suggested Answer Hide Answer
Suggested Answer: C

Wyjaśnienie

1. Prawidłowa odpowiedź lub odpowiedzi:
C. Deploy an external HTTP(S) load balancer in the service project with the MIG as a backend.

2. Kompleksowe wyjaśnienie dlaczego dana odpowiedź jest prawidłowa (Analiza):
Chcesz udostępniać usługi webowe użytkownikom zewnętrznym, ale jednocześnie usunąć publiczne adresy IP z maszyn wirtualnych MIG, które działają w projekcie usługowym (Service Project) podłączonym do Shared VPC (Host Project):
- Usunięcie publicznych adresów IP z maszyn wirtualnych minimalizuje powierzchnię ataku. Aby ruch z internetu mógł docierać do maszyn prywatnych, przed grupą instancji (MIG) należy umieścić zewnętrzny Load Balancer HTTP(S) (External HTTP(S) Load Balancer).
- Load Balancer posiada publiczny adres IP na brzegu sieci Google i przekazuje ruch HTTP/HTTPS do prywatnych adresów IP maszyn wirtualnych backendu.
- Zgodnie z dobrymi praktykami Shared VPC, zasoby aplikacyjne (MIG oraz przypisany do niego Load Balancer) muszą być wdrażane w **projekcie usługowym** (Service Project), gdzie deweloperzy zarządzają swoimi aplikacjami, a nie w projekcie hosta (który powinien służyć wyłącznie do zarządzania infrastrukturą sieciową).

3. Wyjaśnienie z osobna każdej niepoprawnej odpowiedzi:
- A i B. Wdrożenie bramy Cloud NAT: Cloud NAT umożliwia maszynom bez publicznych adresów IP na inicjowanie połączeń *wychodzących* do internetu (np. aktualizacja systemu), ale całkowicie blokuje i nie obsługuje ruchu *przychodzącego* inicjowanego z zewnątrz, co uniemożliwiłoby serwowanie ruchu webowego dla użytkowników.
- D. Wdrożenie Load Balancera w projekcie hosta (VPC project): Jest to antywzorzec architektury Shared VPC. Projekt hosta powinien zawierać wyłącznie współdzielone zasoby sieciowe (VPC, subnets, VPNs, routing). Komponenty aplikacji i ich load balancery powinny znajdować się w projektach usługowych, aby zachować separację obowiązków.

4. Wskazówki, hinty, tips and tricks:
- W architekturze Shared VPC:
  - Projekt Host -> Sieć (VPC, subnets, firewall rules, routing).
  - Projekt Service -> Workload (VMs, MIGs, Load Balancers, Databases).
- Dostęp z internetu do maszyn prywatnych -> Zewnętrzny Load Balancer L7.

5. Reguły wyboru odpowiedzi (Słowa kluczowe):
- Udostępnienie webowe maszyn bez publicznych adresów IP -> External HTTP(S) Load Balancer.
- Separacja obowiązków w Shared VPC -> Wdrożenie w projekcie usługowym (Service Project).
