Question 150 / 361

Your organization's Google Cloud VMs are deployed via an instance template that configures them with a public IP address in order to host web services for external users. The VMs reside in a service project that is attached to a host (VPC) project containing one custom Shared VPC for the VMs. You have been asked to reduce the exposure of the VMs to the internet while continuing to service external users. You have already recreated the instance template without a public IP address configuration to launch the managed instance group (MIG). What should you do?

  • A. Deploy a Cloud NAT Gateway in the service project for the MIG.
  • B. Deploy a Cloud NAT Gateway in the host (VPC) project for the MIG.
  • C. Deploy an external HTTP(S) load balancer in the service project with the MIG as a backend.
  • D. Deploy an external HTTP(S) load balancer in the host (VPC) project with the MIG as a backend.
Show Suggested Answer Hide Answer
Suggested Answer: C

Wyjaśnienie

Poprawna odpowiedź: C (Deploy an external HTTP(S) load balancer in the service project with the MIG as a backend)

Dlaczego ta odpowiedź jest poprawna:
- Cel: Ograniczenie wystawienia VM na internet ("reduce exposure") przy zachowaniu dostępności dla użytkowników zewnętrznych.
- Rozwiązanie: Usunięcie publicznych adresów IP z maszyn wirtualnych i umieszczenie ich za zewnętrznym Load Balancerem (HTTP(S) LB). Load Balancer posiada publiczny adres IP i przyjmuje ruch, a następnie przekazuje go do maszyn wirtualnych w sieci wewnętrznej (VPC).
- Shared VPC: W architekturze Shared VPC, Load Balancer dla aplikacji zazwyczaj wdraża się w projekcie serwisowym (Service Project), w którym znajduje się grupa instancji (MIG). Choć sieć jest współdzielona z projektu hosta, zasoby aplikacji (takie jak LB) powinny być zarządzane w projekcie aplikacji.

Analiza niepoprawnych odpowiedzi:
- A i B. Cloud NAT: Bramka NAT służy do umożliwienia maszynom bez publicznego adresu IP wyjścia na zewnątrz (ruch wychodzący - outbound), np. w celu pobrania aktualizacji. NIE służy ona do przyjmowania ruchu od użytkowników zewnętrznych (ruch przychodzący - inbound).
- D. LB w projekcie hosta: Choć technicznie możliwe, narusza to zasadę separacji obowiązków (separation of duties). Projekt hosta powinien zarządzać infrastrukturą sieciową (VPC, subnets, firewall), a projekty serwisowe powinny zarządzać swoimi aplikacjami, w tym ich Load Balancerami.

Wskazówki i triki (Tips & Tricks):
- Jeśli widzisz "Reduce exposure" + "Service external users" -> szukaj Load Balancera.
- Jeśli widzisz "VMs without public IP" + "Access internet for updates" -> szukaj Cloud NAT.
- W Shared VPC: Zasoby "network-level" (IP, subnets) są w Host Project. Zasoby "application-level" (VMs, LB, MIG) są w Service Project.

Praktyczne informacje na egzamin:
- Zewnętrzny HTTP(S) LB to tzw. proxy load balancer. Klient łączy się z LB, a LB otwiera nowe połączenie do VM. Dzięki temu VM nigdy nie "widzi" bezpośrednio adresu IP klienta (chyba że sprawdzisz nagłówek X-Forwarded-For).
- Pamiętaj o regułach Firewall: Musisz pozwolić na ruch z zakresów IP Load Balancera (Google health check ranges: 130.211.0.0/22 i 35.191.0.0/16) do Twoich VM.
