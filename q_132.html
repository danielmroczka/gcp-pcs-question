Question 132 / 361

You are tasked with exporting and auditing security logs for login activity events for Google Cloud console and API calls that modify configurations to Google Cloud resources. Your export must meet the following requirements: Export related logs for all projects in the Google Cloud organization. Export logs in near real-time to an external SIEM. What should you do? (Choose two.)

  • A. Create a Log Sink at the organization level with a Pub/Sub destination.
  • B. Create a Log Sink at the organization level with the includeChildren parameter, and set the destination to a Pub/Sub topic.
  • C. Enable Data Access audit logs at the organization level to apply to all projects.
  • D. Enable Google Workspace audit logs to be shared with Google Cloud in the Admin Console.
  • E. Ensure that the SIEM processes the AuthenticationInfo field in the audit log entry to gather identity information.
Show Suggested Answer Hide Answer
Suggested Answer: BC

Wyjaśnienie

1. Prawidłowa odpowiedź lub odpowiedzi:
B. Create a Log Sink at the organization level with the includeChildren parameter, and set the destination to a Pub/Sub topic.
C. Enable Data Access audit logs at the organization level to apply to all projects.

2. Kompleksowe wyjaśnienie dlaczego dana odpowiedź jest prawidłowa (Analiza):
Wymagane jest eksportowanie logów aktywności logowania do konsoli oraz wywołań API modyfikujących konfiguracje dla wszystkich projektów w organizacji, w czasie zbliżonym do rzeczywistego (near real-time) do zewnętrznego systemu SIEM:
- C (Włączenie logów): Działania użytkowników modyfikujące konfiguracje są rejestrowane w logach Admin Activity (zawsze włączone). Jednak szczegółowa aktywność logowania oraz odczyty konfiguracji wymagają włączenia dzienników Data Access audit logs. Włączenie ich na poziomie organizacji gwarantuje, że będą zbierane dla wszystkich projektów.
- B (Eksport aggregated w czasie rzeczywistym): Aby eksportować logi ze wszystkich projektów w organizacji, należy utworzyć zlew logów (Log Sink) na poziomie organizacji z parametrem `includeChildren=true` (tzw. Aggregated Sink). Ustawienie celu eksportu na Pub/Sub zapewnia niskie opóźnienia i strumieniowanie logów w czasie rzeczywistym, co jest niezbędnym warunkiem integracji z systemami SIEM.

3. Wyjaśnienie z osobna każdej niepoprawnej odpowiedzi:
- A. Log Sink na poziomie organizacji bez `includeChildren`: Taki zlew wyeksportuje wyłącznie logi wygenerowane bezpośrednio przez zasób organizacji (np. zmiany w IAM na poziomie org), ale całkowicie zignoruje logi generowane wewnątrz poszczególnych projektów (child projects).
- D. Włączenie współdzielenia logów Google Workspace: Dotyczy zdarzeń z pakietu Workspace (np. Gmail, Dysk), a nie logowania do konsoli chmurowej GCP i zmian konfiguracji zasobów GCP.
- E. Przetwarzanie pola AuthenticationInfo przez SIEM: Jest to operacja po stronie systemu SIEM do interpretacji danych, a nie krok konfiguracyjny w Google Cloud niezbędny do wyeksportowania logów.

4. Wskazówki, hinty, tips and tricks:
- Prawdziwy czas rzeczywisty (near real-time) eksportu logów do systemów trzecich (SIEM, Elasticsearch) w GCP osiąga się wyłącznie za pomocą **Pub/Sub**.
- Eksport z całej hierarchii (wszystkich projektów) wymaga **Aggregated Sink** na poziomie folderu lub organizacji, co definiuje się za pomocą flagi `includeChildren`.

5. Reguły wyboru odpowiedzi (Słowa kluczowe):
- Real-time SIEM integration + cała organizacja -> Pub/Sub destination + Log Sink z includeChildren.
- Zbieranie logów dostępu/odczytów -> Data Access audit logs.

6. Dodatkowe źródła i dokumentacja:
- Aggregated sinks overview: https://cloud.google.com/logging/docs/export/aggregated_sinks
- Configure Data Access audit logs: https://cloud.google.com/logging/docs/audit/configure-data-access
