Question 243 / 361

An administrative application is running on a virtual machine (VM) in a managed group at port 5601 inside a Virtual Private Cloud (VPC) instance without access to the internet currently. You want to expose the web interface at port 5601 to users and enforce authentication and authorization Google credentials. What should you do?

  • A. Configure the bastion host with OS Login enabled and allow connection to port 5601 at VPC firewall. Log in to the bastion host from the Google Cloud console by using SSH-in-browser and then to the web application.
  • B. Modify the VPC routing with the default route point to the default internet gateway. Modify the VPC Firewall rule to allow access from the internet 0.0.0.0/0 to port 5601 on the application instance.
  • C. Configure Secure Shell Access (SSH) bastion host in a public network, and allow only the bastion host to connect to the application on port 5601. Use a bastion host as a jump host to connect to the application.
  • D. Configure an HTTP Load Balancing instance that points to the managed group with Identity-Aware Proxy (IAP) protection with Google credentials. Modify the VPC firewall to allow access from IAP network range.
Show Suggested Answer Hide Answer
Suggested Answer: D

Wyjaśnienie

1. Prawidłowa odpowiedź lub odpowiedzi:
D. Configure an HTTP Load Balancing instance that points to the managed group with Identity-Aware Proxy (IAP) protection with Google credentials. Modify the VPC firewall to allow access from IAP network range.

2. Kompleksowe wyjaśnienie dlaczego dana odpowiedź jest prawidłowa (Analiza):
Odpowiedź D jest prawidłowa, ponieważ Identity-Aware Proxy (IAP) zintegrowany z zewnętrznym Load Balancerem HTTP(S) (Application Load Balancer) jest najlepszym i zalecanym sposobem na bezpieczne udostępnienie aplikacji webowej użytkownikom zewnętrznym z wymuszeniem autoryzacji opartej na tożsamości Google.

Korzyści z tego podejścia:
a. **Brak publicznego IP na VM:** Maszyny wirtualne w grupie zarządzanej mogą pozostać całkowicie prywatne i nie mieć bezpośredniego dostępu do internetu ani publicznych adresów IP.
b. **Centralna kontrola dostępu (IAP):** Gdy użytkownik próbuje wejść na adres Load Balancera, IAP przechwytuje żądanie i przekierowuje do ekranu logowania Google. Dostęp jest przyznawany tylko wtedy, gdy użytkownik posiada rolę `IAP-secured Web App User` w IAM.
c. **Konfiguracja zapory sieciowej:** Zapora sieciowa VPC (firewall) musi zezwalać na ruch przychodzący do maszyn na port 5601 wyłącznie z zakresu adresów IP Google Front End (GFE) i IAP proxy, co zapobiega ominięciu zabezpieczeń.

3. Wyjaśnienie z osobna każdej niepoprawnej odpowiedzi:
A. Configure the bastion host with OS Login... Log in... by using SSH-in-browser and then to the web application.
   * Dlaczego nieprawidłowa: OS Login i bastion host służą do dostępu administracyjnego przez protokół SSH. Używanie SSH-in-browser do normalnego korzystania z aplikacji webowej przez użytkowników końcowych jest nieporęczne, nie skaluje się i nie stanowi standardowego interfejsu aplikacji webowych.
B. Modify the VPC routing... allow access from the internet 0.0.0.0/0 to port 5601...
   * Dlaczego nieprawidłowa: Otwarcie portu 5601 na cały świat (0.0.0.0/0) bez bramy pośredniczącej wystawia aplikację bezpośrednio na ataki sieciowe w internecie. Ponadto sama zapora sieciowa nie zapewnia uwierzytelniania użytkowników za pomocą kont Google.
C. Configure Secure Shell Access (SSH) bastion host in a public network... Use a bastion host as a jump host...
   * Dlaczego nieprawidłowa: Podobnie jak opcja A, to rozwiązanie jest przeznaczone dla administratorów IT (zarządzanie serwerem przez tunelowanie SSH), a nie dla zwykłych użytkowników aplikacji webowej, którzy potrzebują prostego dostępu przez przeglądarkę (HTTP/S).

4. Wskazówki, hinty, tips and tricks:
* Bezpieczne udostępnianie wewnętrznych aplikacji webowych (web interfaces/port HTTP) w GCP z logowaniem Google -> Zawsze **Identity-Aware Proxy (IAP)** na **HTTP(S) Load Balancerze**.
* Zapora sieciowa (firewall) dla IAP na backendzie musi pozwalać na ruch z zakresów IP proxy Google.

5. Reguły wyboru odpowiedzi (Słowa kluczowe):
* Expose web interface without internet access to VMs + enforce Google credentials -> HTTP Load Balancer + Identity-Aware Proxy (IAP).
