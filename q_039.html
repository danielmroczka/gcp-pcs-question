Question 39 / 361

A customer has 300 engineers. The company wants to grant different levels of access and efficiently manage IAM permissions between users in the development and production environment projects. Which two steps should the company take to meet these requirements? (Choose two.)

  • A. Create a project with multiple VPC networks for each environment.
  • B. Create a folder for each development and production environment.
  • C. Create a Google Group for the Engineering team, and assign permissions at the folder level.
  • D. Create an Organizational Policy constraint for each folder environment.
  • E. Create projects for each environment, and grant IAM rights to each engineering user.
Show Suggested Answer Hide Answer
Suggested Answer: BC

Wyjaśnienie

Potwierdzona odpowiedź: BC (Foldery dla środowisk oraz Grupy Google)

Wyjaśnienie:
Efektywne zarządzanie uprawnieniami w dużej organizacji (300 inżynierów) wymaga zastosowania hierarchii zasobów oraz abstrakcji tożsamości:
1. Foldery (Folders): Pozwalają na logiczne pogrupowanie projektów należących do tego samego środowiska (np. Dev, Prod). Uprawnienia nadane na poziomie folderu są dziedziczone przez wszystkie projekty wewnątrz niego, co eliminuje konieczność konfigurowania każdego projektu z osobna.
2. Grupy Google (Google Groups): Zamiast nadawać uprawnienia 300 inżynierom indywidualnie, należy stworzyć grupę (np. engineers-prod@company.com), nadać jej odpowiednie role w IAM na poziomie folderu i zarządzać dostępem poprzez dodawanie/usuwanie członków grupy. Jest to zgodne z zasadą "best practice" w GCP.

Dlaczego pozostałe są błędne:
A. VPC to warstwa sieciowa, a nie narzędzie do zarządzania uprawnieniami IAM. Chociaż separacja sieciowa jest ważna, nie rozwiązuje problemu zarządzania dostępem użytkowników.
D. Organizational Policy (polityki organizacji) służą do nakładania restrykcji na zasoby (np. zakaz tworzenia zewnętrznych IP), a nie do nadawania uprawnień użytkownikom (IAM).
E. Nadawanie uprawnień każdemu użytkownikowi z osobna ("per user") przy 300 osobach jest skrajnie nieefektywne, podatne na błędy i trudne do audytowania.

Wskazówki egzaminacyjne (Tips & Tricks):
- Widząc "large number of users" i "IAM management", zawsze szukaj odpowiedzi zawierającej "Google Groups".
- Foldery są kluczowym elementem skalowalnego zarządzania uprawnieniami w GCP.
- "Assign permissions at the folder level" to najszybszy sposób na zapewnienie spójnego dostępu w wielu projektach.

Kluczowe zagadnienia do powtórzenia:
- Hierarchia zasobów GCP (Organization -> Folders -> Projects -> Resources).
- IAM Best Practices (używanie grup, zasada najmniejszych uprawnień).
- Dziedziczenie uprawnień w GCP.

Dokumentacja:
https://cloud.google.com/iam/docs/groups-in-iam

Analiza i Podsumowanie Dyskusji (AI)

Analiza i Wyjaśnienie

Sugerowana odpowiedź: BC

Analiza spornych kwestii (AI): Głównym celem pytania jest wskazanie mechanizmów pozwalających na zarządzanie dostępem w skali. Kombinacja folderów (struktura) i grup (tożsamość) jest jedynym rozwiązaniem, które nie wymaga ręcznej pracy przy każdym nowym projekcie czy pracowniku. Opcja E jest klasyczną pułapką "technicznie możliwą, ale operacyjnie błędną" (anti-pattern).

Dodatkowe Zasoby (Linki)

Wyjaśnienie Audytowe

Reguła Egzaminacyjna (Exam Rule):
Pamiętaj, że w egzaminie Professional Cloud Security Engineer kluczowe jest wybieranie rozwiązań najmniej uprzywilejowanych (Principle of Least Privilege), zoptymalizowanych kosztowo i spełniających wymogi compliancy (np. CMEK, Data Loss Prevention).

Haczyki egzaminacyjne (Exam Traps):
- Wybór rozwiązań, które wydają się wygodne, ale nie spełniają wymogów bezpieczeństwa (np. zbyt szerokie uprawnienia IAM).
- Mylenie usług: np. Cloud Armor (WAF) z Cloud IAP (Identity-Aware Proxy).

Głębokie wyjaśnienie techniczne (GCP Professional Cloud Security Engineer):
W każdym pytaniu analizuj warstwy: IAM (dostęp), Encryption (at rest/in transit), Logging/Monitoring (Audit Logs, Cloud Logging, Security Command Center) oraz Networking (VPC Service Controls, Firewall Rules). GCP kładzie duży nacisk na współdzieloną odpowiedzialność (Shared Responsibility Model) - klient odpowiada za konfigurację zabezpieczeń wewnątrz usług chmurowych.
