Question 12 / 361

A customer deploys an application to App Engine and needs to check for Open Web Application Security Project (OWASP) vulnerabilities. Which service should be used to accomplish this?

  • A. Cloud Armor
  • B. Google Cloud Audit Logs
  • D. Anomaly Detection
Show Suggested Answer Hide Answer
Suggested Answer: C

Wyjaśnienie

Potwierdzona odpowiedź: C (Web Security Scanner)

Wyjaśnienie: 
Web Security Scanner to dedykowane narzędzie w Google Cloud przeznaczone do identyfikowania luk w zabezpieczeniach aplikacji internetowych (App Engine, GKE, Compute Engine). Skaner automatycznie sprawdza aplikację pod kątem typowych podatności z listy OWASP Top 10, takich jak:
- Cross-Site Scripting (XSS)
- Flash injection
- Mixed content (HTTP in HTTPS)
- Outdated / insecure libraries (użycie niebezpiecznych bibliotek)
Jest to narzędzie typu DAST (Dynamic Application Security Testing).

Dlaczego pozostałe są błędne:
A. Cloud Armor: Jest to Web Application Firewall (WAF). Służy do ochrony aplikacji w czasie rzeczywistym przed atakami (np. filtrowanie ruchu, ochrona DDoS), ale nie służy do skanowania i wykrywania podatności w kodzie/konfiguracji samej aplikacji.
B. Google Cloud Audit Logs: Rejestrują one, "kto zrobił co i kiedy" w infrastrukturze GCP. Są niezbędne do analizy po incydencie, ale nie potrafią wykryć luk OWASP wewnątrz aplikacji.
D. Anomaly Detection: To ogólny termin dotyczący wykrywania nietypowych wzorców zachowań (np. w logach lub ruchu sieciowym), często realizowany przez Security Command Center lub Cloud Monitoring, ale nie jest to skaner podatności OWASP.

Wskazówki egzaminacyjne (Tips & Tricks):
- Słowo klucz: "Check for OWASP vulnerabilities" = Web Security Scanner.
- Pamiętaj: Web Security Scanner jest narzędziem "skanującym" (proaktywnym), a Cloud Armor jest narzędziem "blokującym" (reaktywnym).

Kluczowe zagadnienia do powtórzenia:
- Web Security Scanner - funkcje i zakres działania
- OWASP Top 10
- Różnice między WAF (Cloud Armor) a Skanerem Podatności

Dokumentacja:
https://cloud.google.com/security-command-center/docs/concepts-web-security-scanner-overview

**Reguła Egzaminacyjna (Exam Rule):**
Zawsze identyfikuj warstwę modelu OSI, na której operuje atak oraz rozwiązanie. DNSSEC działa na poziomie warstwy aplikacji dla DNS, zapobiegając zatruwaniu pamięci podręcznej (Cache Poisoning).

**Haczyki egzaminacyjne (Exam Traps):**
- Mylenie Cloud Armor (WAF - L7) z zabezpieczeniami DNS (DNSSEC - integralność danych DNS).
- Zakładanie, że TLS/SSL wystarczy do ochrony przed przekierowaniem całego ruchu DNS (DNSSEC zabezpiecza sam proces rezolucji, zanim nawiążesz bezpieczne połączenie TLS).

**Głębokie wyjaśnienie techniczne:**
DNSSEC wykorzystuje kryptografię klucza publicznego (RRSIG, DNSKEY, DS) do cyfrowego podpisywania rekordów DNS w strefach (Zone Signing). Dzięki temu resolver DNS może zweryfikować łańcuch zaufania aż do punktu głównego (root zone) bez konieczności polegania wyłącznie na adresie IP serwera autorytatywnego, co drastycznie ogranicza skuteczność ataków typu MITM i cache poisoning.

Sugerowana odpowiedź: C

Analiza spornych kwestii (AI): W dyskusjach eksperci podkreślają, że Web Security Scanner jest częścią pakietu Security Command Center (SCC). Najważniejsze to nie pomylić go z Cloud Armor – Armor 'stoi przed' aplikacją i odbija ataki, podczas gdy Scanner 'przeczesuje' aplikację w poszukiwaniu błędów programistycznych.
