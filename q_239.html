Question 239 / 361

You control network traffic for a folder in your Google Cloud environment. Your folder includes multiple projects and Virtual Private Cloud (VPC) networks. You want to enforce on the folder level that egress connections are limited only to IP range 10.58.5.0/24 and only from the VPC network "dev-vpc". You want to minimize implementation and maintenance effort. What should you do?

  • A. 1. Leave the network configuration of the VMs in scope unchanged. 2. Create a new project including a new VPC network "new-vpc". 3. Deploy a network appliance in "new-vpc" to filter access requests and only allow egress connections from "dev-vpc" to 10.58.5.0/24.
  • B. 1. Leave the network configuration of the VMs in scope unchanged. 2. Enable Cloud NAT for "dev-vpc" and restrict the target range in Cloud NAT to 10.58.5.0/24.
  • C. 1. Attach external IP addresses to the VMs in scope. 2. Define and apply a hierarchical firewall policy on folder level to deny all egress connections and to allow egress to IP range 10.58.5.0/24 from network dev-vpc.
  • D. 1. Attach external IP addresses to the VMs in scope. 2. Configure a VPC Firewall rule in "dev-vpc" that allows egress connectivity to IP range 10.58.5.0/24 for all source addresses in this network.
Show Suggested Answer Hide Answer
Suggested Answer: C

Wyjaśnienie

1. Prawidłowa odpowiedź lub odpowiedzi:
C. 1. Attach external IP addresses to the VMs in scope. 2. Define and apply a hierarchical firewall policy on folder level to deny all egress connections and to allow egress to IP range 10.58.5.0/24 from network dev-vpc.

2. Kompleksowe wyjaśnienie dlaczego dana odpowiedź jest prawidłowa (Analiza):
Odpowiedź C jest prawidłowa, ponieważ polityka hierarchiczna zapory sieciowej (Hierarchical Firewall Policy) pozwala na centralne narzucenie i egzekwowanie reguł sieciowych na poziomie Folderu dla wielu projektów i sieci VPC, co minimalizuje wysiłek wdrożeniowy i administracyjny.

Dlaczego to rozwiązanie działa:
a. **Folder-level enforcement:** Aplikując politykę na poziomie folderu, automatycznie obejmujemy nią wszystkie projekty i sieci VPC wewnątrz tego folderu. Nie musimy konfigurować reguł oddzielnie w każdej sieci.
b. **Reguły polityki:** Definiujemy regułę blokującą cały ruch wychodzący (deny egress) oraz regułę zezwalającą na wyjście (allow egress) wyłącznie do docelowego zakresu `10.58.5.0/24` dla sieci `dev-vpc`.
c. **Przypisanie zewnętrznych IP:** Umożliwia maszynom bezpośrednią komunikację zewnętrzną (jeśli jest wymagana) pod warunkiem przejścia przez filtry zapory sieciowej.

3. Wyjaśnienie z osobna każdej niepoprawnej odpowiedzi:
A. ...Deploy a network appliance in "new-vpc" to filter access requests...
   * Dlaczego nieprawidłowa: Wdrożenie zewnętrznego urządzenia sieciowego (network appliance / wirtualny firewall) wymaga skomplikowanej konfiguracji routingu (route tables), konfiguracji interfejsów sieciowych maszyn oraz wiąże się z wysokimi kosztami licencyjnymi i operacyjnymi. Nie spełnia to warunku "minimalizacji wysiłku".
B. ...Enable Cloud NAT for "dev-vpc" and restrict the target range in Cloud NAT to 10.58.5.0/24.
   * Dlaczego nieprawidłowa: Cloud NAT nie służy do bezpośredniego filtrowania i ograniczania ruchu sieciowego (nie zastępuje zapory sieciowej). Służy do translacji adresów IP dla połączeń wychodzących.
D. ...Configure a VPC Firewall rule in "dev-vpc" that allows egress connectivity...
   * Dlaczego nieprawidłowa: Konfiguracja reguł na poziomie pojedynczej sieci VPC (VPC Firewall) nie działa na poziomie Folderu. Jeśli w folderze pojawią się nowe sieci VPC lub projekty, reguły te nie zostaną na nich automatycznie zastosowane, co zwiększa narzut na utrzymanie.

4. Wskazówki, hinty, tips and tricks:
* Narzucanie reguł sieciowych dla całego Folderu (folder level) -> **Hierarchical Firewall Policy**.
* Polityki hierarchiczne ułatwiają centralne zarządzanie bezpieczeństwem sieciowym w środowiskach wieloprojektowych.

5. Reguły wyboru odpowiedzi (Słowa kluczowe):
* Enforce network rules on folder level -> Hierarchical firewall policy.
