Question 331 / 361

Your organization uses a microservices architecture based on Google Kubernetes Engine (GKE). Recent security reviews recommend tighter controls around deployed container images to reduce potential vulnerabilities and maintain compliance. You need to implement an automated system by using managed services to ensure that only approved container images are deployed to the GKE clusters. What should you do?

  • A. Develop custom organization policies that restrict GKE cluster deployments to container images hosted within a specific Artifact Registry project where your approved images reside.
  • B. Enforce Binary Authorization in your GKE clusters. Integrate container image vulnerability scanning into the CI/CD pipeline and require vulnerability scan results to be used for Binary Authorization policy decisions.
  • C. Automatically deploy new container images upon successful CI/CD builds by using Cloud Build triggers. Set up firewall rules to limit and control access to instances to mitigate malware injection.
  • D. Build a system using third-party vulnerability databases and custom scripts to identify potential Common Vulnerabilities and Exposures (CVEs) in your container images. Prevent image deployment if the CVE impact score is beyond a specified threshold.
Show Suggested Answer Hide Answer
Suggested Answer: B

Wyjaśnienie

Poprawna odpowiedź: B (Enforce Binary Authorization in your GKE clusters. Integrate container image vulnerability scanning into the CI/CD pipeline and require vulnerability scan results to be used for Binary Authorization policy decisions.)

Dlaczego ta odpowiedź jest poprawna:
- Binary Authorization: To standardowa usługa w GCP służąca do wymuszania wdrożeń tylko zweryfikowanych obrazów w GKE.
- "Automated system" + "Managed services" + "Only approved images": Binary Authorization w połączeniu ze skanerem podatności (Artifact Analysis) to rozwiązanie w pełni zarządzane i automatyczne.

Analiza niepoprawnych odpowiedzi:
- A. Custom Org Policies: Nie pozwalają na tak szczegółową kontrolę nad tym *czy obraz przeszedł skanowanie*. Org Policy ogranicza *skąd* (z jakiego projektu/registry), ale nie *czy* obraz jest bezpieczny.
- C. Cloud Build/Firewall: To narzędzia CI/CD i sieciowe – nie zapewniają wymuszenia (enforcement) na poziomie GKE.
- D. Third-party/Custom scripts: To podejście "manualne" i "niemanaged", co stoi w sprzeczności z wymaganiem "automated system by using managed services".

Wskazówki i triki (Tips & Tricks):
- "Only approved container images" + "GKE" = Binary Authorization.
- Unikaj "custom scripts" na egzaminie.

Praktyczne informacje na egzamin:
- Zapamiętaj: Binary Authorization to kluczowy element "Software Supply Chain Security".

Dokumentacja i linki:
- Binary Authorization overview

Wskazówki egzaminacyjne (Tips & Tricks)

Reguła Egzaminacyjna (Exam Rule): 
W pytaniach typu 'Security in GCP', zawsze priorytetyzuj rozwiązania natywne (SCC, Cloud KMS, Secret Manager, VPC SC) nad rozwiązaniami typu 'third-party' lub 'self-managed', chyba że scenariusz wymaga specyficznej integracji hybrydowej.

Haczyki egzaminacyjne (Exam Traps):
- Pułapka 'Least Privilege': Egzamin często podpowiada role o szerokim zakresie (np. 'Editor' lub 'Owner') – zawsze odrzucaj je na rzecz ról predefiniowanych o najmniejszym zakresie uprawnień.
- Pułapka 'Logging vs Monitoring': Pamiętaj: Audit Logs służą do badania aktywności (Who/What/When), a Monitoring do zbierania metryk wydajnościowych.

Głębokie wyjaśnienie techniczne:
Każda architektura bezpieczeństwa w GCP powinna być projektowana w oparciu o 'Security by Default'. Oznacza to m.in. szyfrowanie w spoczynku (domyślne), tożsamość opartą na rolach (IAM) oraz pełną widoczność zapewnianą przez scentralizowane logowanie (Cloud Logging/SCC).

Analiza i Podsumowanie (AI)

Kluczowe zagadnienia

Sugerowana odpowiedź: B

Analiza strategiczna: Pytanie o automatyzację bezpieczeństwa w procesie CI/CD i GKE. Binary Authorization jest natywnym rozwiązaniem GCP do wymuszania polityk bezpieczeństwa na poziomie obrazów kontenerowych przed ich uruchomieniem w klastrze.
