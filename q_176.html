Question 176 / 361

You need to enforce a security policy in your Google Cloud organization that prevents users from exposing objects in their buckets externally. There are currently no buckets in your organization. Which solution should you implement proactively to achieve this goal with the least operational overhead?

  • A. Create an hourly cron job to run a Cloud Function that finds public buckets and makes them private.
  • B. Enable the constraints/storage.publicAccessPrevention constraint at the organization level.
  • C. Enable the constraints/storage.uniformBucketLevelAccess constraint at the organization level.
  • D. Create a VPC Service Controls perimeter that protects the storage.googleapis.com service in your projects that contains buckets. Add any new project that contains a bucket to the perimeter.
Show Suggested Answer Hide Answer
Suggested Answer: B

Wyjaśnienie

1. Prawidłowa odpowiedź lub odpowiedzi:
B. Enable the constraints/storage.publicAccessPrevention constraint at the organization level.

2. Kompleksowe wyjaśnienie dlaczego dana odpowiedź jest prawidłowa (Analiza):
Należy wdrożyć politykę bezpieczeństwa, która proaktywnie uniemożliwi użytkownikom upublicznianie obiektów w kubełkach Cloud Storage na poziomie całej organizacji, przy minimalnym narzucie operacyjnym:
- Najbardziej efektywnym rozwiązaniem jest włączenie polityki organizacji (Organization Policy) z ograniczeniem **`storage.publicAccessPrevention`** na poziomie węzła organizacji.
- Włączenie tej polityki powoduje automatyczne i natychmiastowe zablokowanie możliwości konfiguracji publicznego dostępu (np. przypisywania roli Storage Object Viewer dla tożsamości `allUsers` lub `allAuthenticatedUsers`) do jakichkolwiek kubełków w aktualnych i nowo tworzonych projektach. Działa to w pełni proaktywnie i nie wymaga pisania kodu ani stałego monitorowania.

3. Wyjaśnienie z osobna każdej niepoprawnej odpowiedzi:
- A. Skrypt cron z funkcją Cloud Function: Jest to rozwiązanie reaktywne. Kubełek może być publiczny przez czas do kolejnego uruchomienia skryptu (np. do godziny), co stwarza okno podatności na wyciek. Dodatkowo wymaga to pisania kodu i monitorowania działania infrastruktury bezserwerowej.
- C. Enforce `storage.uniformBucketLevelAccess`: Wymuszenie jednolitego dostępu (UBLA) wyłącza obsługę list ACL, ale nie zapobiega udostępnieniu całego kubełka publicznie przy użyciu polityki IAM (użytkownik wciąż może nadać dostęp publiczny w IAM).
- D. VPC Service Controls: Perymetr VPC SC chroni przed wyciekiem danych do zewnętrznych projektów, ale konfiguracja perymetru dla każdego nowego projektu z kubełkiem generuje ogromny narzut operacyjny i administracyjny, co narusza wymóg minimalizacji overheadu.

4. Wskazówki, hinty, tips and tricks:
- W chmurze Google Cloud standardowym sposobem na zablokowanie możliwości upubliczniania kubełków w skali firmy jest wdrożenie polityki organizacji **Public Access Prevention (PAP)**.

5. Reguły wyboru odpowiedzi (Słowa kluczowe):
- Proaktywna blokada publicznego dostępu do Storage na poziomie organizacji -> Enforce constraints/storage.publicAccessPrevention.

6. Dodatkowe źródła i dokumentacja:
- Public Access Prevention: https://cloud.google.com/storage/docs/public-access-prevention
