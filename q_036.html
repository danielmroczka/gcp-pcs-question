Question 36 / 361

A retail customer allows users to upload comments and product reviews. The customer needs to make sure the text does not include sensitive data before the comments or reviews are published.
Which Google Cloud Service should be used to achieve this?

  • A. Cloud Key Management Service
  • B. Cloud Data Loss Prevention API
  • C. BigQuery
  • D. Web Security Scanner
Show Suggested Answer Hide Answer
Suggested Answer: B

Wyjaśnienie

Potwierdzona odpowiedź: B (Cloud Data Loss Prevention API)

Wyjaśnienie:
Cloud Data Loss Prevention (DLP) API (część pakietu Sensitive Data Protection) jest usługą zaprojektowaną specjalnie do wykrywania, klasyfikowania i maskowania (redakcji) danych wrażliwych w tekstach, obrazach i bazach danych. W opisanym scenariuszu, gdzie użytkownicy przesyłają recenzje, DLP API może automatycznie przeskanować tekst przed jego publikacją, identyfikując takie informacje jak numery kart kredytowych, adresy, numery telefonów czy inne dane osobowe (PII), a następnie pozwolić na ich usunięcie lub zamaskowanie.

Dlaczego pozostałe są błędne:
A. Cloud Key Management Service: KMS służy do zarządzania kluczami szyfrującymi. Pozwala na szyfrowanie danych "w spoczynku", ale nie posiada funkcji analizy treści tekstu w celu wykrywania konkretnych typów informacji (jak PII).
C. BigQuery: Jest to hurtownia danych analitycznych. Choć można w niej przechowywać recenzje i integrować ją z DLP, sama usługa BigQuery nie służy do skanowania treści pod kątem danych wrażliwych w locie przed publikacją.
D. Web Security Scanner: Jest to narzędzie do skanowania aplikacji webowych pod kątem luk technicznych (np. XSS, SQL Injection). Nie służy do analizy merytorycznej treści wprowadzanych przez użytkowników pod kątem ochrony prywatności.

Wskazówki egzaminacyjne (Tips & Tricks):
- Słowa klucze: "sensitive data", "PII", "redact", "mask", "classify text" -> zawsze wskazują na Cloud DLP API.
- Cloud DLP może działać na danych nieustrukturyzowanych (tekst, obrazy) oraz ustrukturyzowanych (bazy danych).
- Pamiętaj, że DLP to "content awareness" (świadomość treści), a KMS to "encryption" (szyfrowanie).

Kluczowe zagadnienia do powtórzenia:
- Typy infoTypes w Cloud DLP (Globalne i regionalne)
- Techniki de-identyfikacji (masking, tokenization, bucketing)
- Integracja DLP z innymi usługami GCP

Analiza i Podsumowanie Dyskusji (AI)

Analiza i Wyjaśnienie

Sugerowana odpowiedź: B

Analiza spornych kwestii (AI): DLP może działać w trybie 'Inspect' (znajdź) lub 'De-identify' (zamaskuj/zastąp). W tym scenariuszu aplikacja wysyłałaby recenzję do API DLP przed zapisem w bazie, co pozwala na bezpieczne "przecedzenie" treści.

Wyjaśnienie Audytowe

Reguła Egzaminacyjna (Exam Rule):
Pamiętaj, że w egzaminie Professional Cloud Security Engineer kluczowe jest wybieranie rozwiązań najmniej uprzywilejowanych (Principle of Least Privilege), zoptymalizowanych kosztowo i spełniających wymogi compliancy (np. CMEK, Data Loss Prevention).

Haczyki egzaminacyjne (Exam Traps):
- Wybór rozwiązań, które wydają się wygodne, ale nie spełniają wymogów bezpieczeństwa (np. zbyt szerokie uprawnienia IAM).
- Mylenie usług: np. Cloud Armor (WAF) z Cloud IAP (Identity-Aware Proxy).

Głębokie wyjaśnienie techniczne (GCP Professional Cloud Security Engineer):
W każdym pytaniu analizuj warstwy: IAM (dostęp), Encryption (at rest/in transit), Logging/Monitoring (Audit Logs, Cloud Logging, Security Command Center) oraz Networking (VPC Service Controls, Firewall Rules). GCP kładzie duży nacisk na współdzieloną odpowiedzialność (Shared Responsibility Model) - klient odpowiada za konfigurację zabezpieczeń wewnątrz usług chmurowych.
