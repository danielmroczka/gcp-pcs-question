Question 36 / 361

Retail customer needs to make sure reviews do not include sensitive data before they are published. Which service should be used?

  • A. Cloud KMS
  • B. Cloud DLP API
  • C. BigQuery
  • D. Web Security Scanner
Show Suggested Answer Hide Answer
Suggested Answer: B

Wyjaśnienie

Poprawna odpowiedź: B (Cloud DLP API)

Analiza poprawności:
Cloud DLP API (obecnie znane jako Sensitive Data Protection) to usługa zaprojektowana specjalnie do automatycznego wykrywania, klasyfikowania i maskowania danych wrażliwych (PII, numery kart, adresy itp.) w strumieniach tekstowych, logach czy obrazach. Jest to idealne narzędzie do skanowania treści generowanych przez użytkowników (np. recenzji) w czasie rzeczywistym przed ich publikacją, aby upewnić się, że nie zawierają danych wrażliwych.

Dlaczego pozostałe są błędne:
A (Cloud KMS): KMS służy do szyfrowania danych ("w spoczynku" lub "w tranzycie"), ale nie posiada inteligencji potrzebnej do "rozumienia" treści, wykrywania imion czy numerów kart w tekście.
C (BigQuery): BigQuery to baza danych analitycznych (Data Warehouse). Można w niej przechowywać dane, ale sama w sobie nie skanuje tekstu pod kątem wrażliwości (chyba że użyjesz w niej funkcji DLP jako rozszerzenia).
D (Web Security Scanner): To narzędzie typu DAST (Dynamic Application Security Testing), które szuka luk technicznych w aplikacji webowej, takich jak XSS, SQL Injection czy błędy w konfiguracji SSL. Nie służy do wykrywania danych osobowych (PII).

Wskazówki egzaminacyjne:
- "Sensitive data" / "PII": Jeśli w pytaniu o bezpieczeństwo danych pojawiają się te sformułowania – szukaj "Cloud DLP API".
- "Review" / "Content": Jeśli chcesz czyścić dane wpisywane przez użytkowników (np. czaty, recenzje) – DLP API jest jedyną słuszną drogą.
- Eliminacja: Jeśli opcja dotyczy bezpieczeństwa aplikacji (skanowanie luk) – to Web Security Scanner. Jeśli danych (PII) – to DLP API.

Sugerowana odpowiedź: B

Analiza spornych kwestii (AI): DLP może działać w trybie 'Inspect' (znajdź) lub 'De-identify' (zamaskuj/zastąp). W tym scenariuszu aplikacja wysyłałaby recenzję do API DLP przed zapisem w bazie, co pozwala na bezpieczne "przecedzenie" treści.
