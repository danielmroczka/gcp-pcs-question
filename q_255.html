Question 255 / 361

Your organization's financial modeling application is already deployed on Google Cloud. The application processes large amounts of sensitive customer financial data. Application code is old and poorly understood by your current software engineers. Recent threat modeling exercises have highlighted the potential risk of sophisticated side-channel attacks against the application while the application is running. You need to further harden the Google Cloud solution to mitigate the risk of these side-channel attacks, ensuring maximum protection for the confidentiality of financial data during processing, while minimizing application problems. What should you do?

  • A. Enforce stricter access controls for Compute Engine instances by using service accounts, least privilege IAM policies, and limit network access.
  • B. Implement a runtime library designed to introduce noise and timing variations into the application's execution which will disrupt side-channel attack.
  • C. Migrate the application to Confidential VMs to provide hardware-level encryption of memory and protect sensitive data during processing.
  • D. Utilize customer-managed encryption keys (CMEK) to ensure complete control over the encryption process.
Show Suggested Answer
Suggested Answer: C

Wyjaśnienie

1. Prawidłowa odpowiedź lub odpowiedzi:
C. Migrate the application to Confidential VMs to provide hardware-level encryption of memory and protect sensitive data during processing.

2. Kompleksowe wyjaśnienie dlaczego dana odpowiedź jest prawidłowa (Analiza):
Odpowiedź C jest prawidłowa, ponieważ Poufne Maszyny Wirtualne (Confidential VMs) oferują sprzętowe szyfrowanie pamięci operacyjnej (RAM encryption) w czasie rzeczywistym, co bezpośrednio chroni dane przed zaawansowanymi atakami typu side-channel (takimi jak ataki czasowe czy wyciąganie danych z pamięci fizycznej przez system hosta).

Dlaczego to najlepsze rozwiązanie dla starego kodu:
a. **Sprzętowe szyfrowanie (AMD SEV):** Klucze szyfrujące pamięć są generowane przez procesor wewnątrz bezpiecznej enklawy i nie są znane oprogramowaniu Google ani systemowi hosta. Chroni to dane w użyciu (in-use).
b. **Brak modyfikacji kodu:** Confidential VMs działają transparentnie dla systemu operacyjnego i aplikacji. Przeniesienie aplikacji na ten typ maszyn nie wymaga przepisywania starego kodu ani zmian w architekturze oprogramowania, co minimalizuje ryzyko błędów (application problems).

3. Wyjaśnienie z osobna każdej niepoprawnej odpowiedzi:
A. Enforce stricter access controls for Compute Engine... least privilege IAM...
   * Dlaczego nieprawidłowa: Kontrola dostępu IAM oraz ograniczenia sieciowe chronią przed nieautoryzowanym wywołaniem API i logowaniem. Nie chronią jednak przed atakami typu side-channel na poziomie procesora fizycznego, jeśli złośliwy proces działa na tym samym hoście fizycznym lub w przypadku naruszenia hypervisora.
B. Implement a runtime library designed to introduce noise and timing variations...
   * Dlaczego nieprawidłowa: Wprowadzanie sztucznych opóźnień (noise) do kodu starej aplikacji finansowej wymaga głębokiej modyfikacji kodu i środowiska uruchomieniowego, co niesie ogromne ryzyko zepsucia aplikacji (naruszenie warunku "minimizing application problems") i może drastycznie obniżyć jej wydajność.
D. Utilize customer-managed encryption keys (CMEK)...
   * Dlaczego nieprawidłowa: Klucze CMEK chronią dane w spoczynku (at-rest) na dyskach oraz w kubełkach. Nie chronią danych w momencie, gdy są one ładowane w postaci jawnej do pamięci RAM procesora w celu wykonania obliczeń finansowych.

4. Wskazówki, hinty, tips and tricks:
* Ochrona danych w użyciu (data in use) przed atakami na poziomie sprzętowym/pamięci RAM (side-channel attacks) -> **Confidential VMs**.
* Confidential VMs nie wymagają żadnych modyfikacji w kodzie aplikacji.

5. Reguły wyboru odpowiedzi (Słowa kluczowe):
* Side-channel attacks / protect data in memory during processing + minimize application problems -> Confidential VMs.
