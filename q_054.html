Question 54 / 361

Your team needs to make sure that their backend database can only be accessed by the frontend application and no other instances on the network. How should your team design this network?

  • A. Create an ingress firewall rule to allow access only from the application to the database using firewall tags.
  • B. Create a different subnet for the frontend application and database to ensure network isolation.
  • C. Create two VPC networks, and connect the two networks using Cloud VPN gateways to ensure network isolation.
  • D. Create two VPC networks, and connect the two networks using VPC peering to ensure network isolation.
Show Suggested Answer Hide Answer
Suggested Answer: A

Wyjaśnienie

Potwierdzona odpowiedź: A

Reguła Egzaminacyjna (Exam Rule):
W Google Cloud podsieci nie zapewniają izolacji sieciowej. Aby uzyskać izolację między warstwami wewnątrz jednej sieci VPC, należy stosować VPC Firewall Rules oparte na tagach sieciowych (network tags) lub, co jest jeszcze bezpieczniejsze, na kontach usług (Service Accounts).

Haczyki egzaminacyjne (Exam Traps):
- Zmylenie podsieciami: Opcja B (różne podsieci) sugeruje, że to izoluje ruch – jest to mit często sprawdzany na egzaminie.
- Nadmiarowa złożoność: Opcje C i D (wiele sieci VPC + łączenie) są niepotrzebnie kosztowne i skomplikowane dla prostego wymogu segmentacji wewnątrz aplikacji.

Głębokie wyjaśnienie techniczne:
Reguły firewall w GCP są globalne dla danej sieci VPC i pozwalają na definiowanie reguł "Ingress" (przychodzących) na podstawie tagów. Właściwa konfiguracja to:
1. Nadanie tagu (np. `frontend`) wszystkim maszynom aplikacji.
2. Nadanie tagu (np. `database`) wszystkim maszynom bazy danych.
3. Utworzenie reguły Ingress: Allow traffic from Source Tag: frontend to Target Tag: database.
Dzięki temu, nawet jeśli maszyny znajdują się w tej samej podsieci, ruch między nimi jest ograniczony zgodnie z zasadą najniższych uprawnień (Least Privilege).
