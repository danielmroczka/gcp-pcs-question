Question 180 / 361

Your organization develops software involved in many open source projects and is concerned about software supply chain threats. You need to deliver provenance for the build to demonstrate the software is untampered. What should you do?

  • A. 1. Hire an external auditor to review and provide provenance. 2. Define the scope and conditions. 3. Get support from the Security department or representative. 4. Publish the attestation to your public web page.
  • B. 1. Review the software process. 2. Generate private and public key pairs and use Pretty Good Privacy (PGP) protocols to sign the output software artifacts together with a file containing the address of your enterprise and point of contact. 3. Publish the PGP signed attestation to your public web page.
  • C. 1. Publish the software code on GitHub as open source. 2. Establish a bug bounty program, and encourage the open source community to review, report, and fix the vulnerabilities.
  • D. 1. Generate Supply Chain Levels for Software Artifacts (SLSA) level 3 assurance by using Cloud Build. 2. View the build provenance in the Security insights side panel within the Google Cloud console.
Show Suggested Answer Hide Answer
Suggested Answer: D

Wskazówki egzaminacyjne (Tips & Tricks)

Reguła Egzaminacyjna (Exam Rule): 
Jeśli scenariusz dotyczy zabezpieczania zasobów chmurowych (GCP), zawsze wybieraj rozwiązanie typu Managed (SCC, Secret Manager, Cloud KMS), a unikaj rozwiązań self-managed, chyba że pytanie wyraźnie wymaga dostosowania niskopoziomowego.

Haczyki egzaminacyjne (Exam Traps):
- Pułapka IAM: Pytania o uprawnienia często sugerują 'Project Owner' – zawsze szukaj 'Least Privilege' (np. 'Role: Secret Manager Secret Accessor').
- Pułapka Sieciowa: Często mylone są VPC Peering (wydajność) oraz VPN (szyfrowanie/on-premise).

Głębokie wyjaśnienie techniczne:
Rozwiązanie bazuje na GCP Shared Responsibility Model. Google zarządza bezpieczeństwem infrastruktury (Physical, Network, Host), podczas gdy administrator zarządza tożsamością (IAM), danymi (Encryption, Cloud KMS) i regułami dostępu (VPC Firewall).

Wyjaśnienie

Poprawna odpowiedź: D (1. Generate Supply Chain Levels for Software Artifacts (SLSA) level 3 assurance by using Cloud Build. 2. View the build provenance in the Security insights side panel within the Google Cloud console)

Dlaczego ta odpowiedź jest poprawna:
- SLSA (Supply-chain Levels for Software Artifacts): Jest to standard branżowy (framework) stworzony m.in. przez Google, który definiuje poziomy bezpieczeństwa łańcucha dostaw oprogramowania. Poziom 3 (SLSA Level 3) gwarantuje, że proces budowania jest odporny na próby manipulacji i dostarcza wiarygodnych danych o pochodzeniu artefaktu (provenance).
- Cloud Build Provenance: Cloud Build natywnie generuje dane o pochodzeniu dla obrazów kontenerów. Są to podpisane cyfrowo metadane, które opisują: skąd pochodzi kod źródłowy, jakie kroki zostały wykonane podczas budowania i jakie artefakty powstały. Ponieważ metadane te są generowane automatycznie przez usługę Google, są one trudne do sfałszowania (untampered).
- Security Insights: Google Cloud Console posiada dedykowany panel "Security insights", który pozwala na łatwą weryfikację poziomu SLSA i danych provenance dla poszczególnych obrazów, co spełnia wymóg "demonstrate the software is untampered".

Analiza niepoprawnych odpowiedzi:
- A. External auditor: Audyt zewnętrzny jest kosztowny, powolny i nie zapewnia technicznej ciągłości provenance dla każdego pojedynczego buildu w dynamicznym środowisku CI/CD.
- B. Manual PGP signing: Ręczne podpisywanie artefaktów kluczami PGP jest trudne do skalowania i nie gwarantuje nienaruszalności samego *procesu* budowania (ktoś mógł podmienić kod przed podpisaniem). SLSA Level 3 skupia się na bezpieczeństwie całego procesu, a nie tylko finalnego pliku.
- C. GitHub open source + bug bounty: To dobre praktyki dla bezpieczeństwa kodu, ale nie dostarczają one technicznych dowodów na to, że konkretny binarny plik lub obraz kontenera został zbudowany dokładnie z tego konkretnego kodu bez modyfikacji "w locie".

Wskazówki i triki (Tips & Tricks):
- "Software supply chain" + "Provenance" = SLSA (Supply-chain Levels for Software Artifacts).
- "Untampered build" = Cloud Build SLSA Level 3.
- Szukaj odpowiedzi wykorzystujących natywne, zautomatyzowane narzędzia Google (Cloud Build, Binary Authorization, Artifact Registry).

Praktyczne informacje na egzamin:
- Zapamiętaj, że SLSA skupia się na trzech filarach: Source (kod), Build (proces) i Provenance (dowód).
- Cloud Build jest jednym z pierwszych systemów CI/CD na świecie, który natywnie wspiera SLSA Level 3.
- Dane provenance są przechowywane w formacie In-toto.

Analiza i Podsumowanie (AI)

Kluczowe zagadnienia

Sugerowana odpowiedź: D

Analiza strategiczna: To pytanie dotyczy jednego z najbardziej aktualnych tematów w bezpieczeństwie IT - ataków na łańcuch dostaw (jak np. ataki na SolarWinds czy Log4j). Google Cloud promuje tutaj standard SLSA jako nowoczesną odpowiedź na te zagrożenia. Automatyzacja dowodów (provenance) wewnątrz usługi Cloud Build eliminuje ryzyko błędu ludzkiego i zapewnia skalowalny dowód autentyczności oprogramowania.

Dodatkowe wskazówki

  • W połączeniu z Binary Authorization, możesz zablokować uruchamianie w GKE obrazów, które nie posiadają dowodu provenance SLSA Level 3.
  • Panel Security insights pokazuje również skany podatności (vulnerability scans) oraz listę pakietów (SBOM - Software Bill of Materials).
