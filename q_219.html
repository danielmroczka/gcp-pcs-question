Question 219 / 361

You are migrating an on-premises data warehouse to BigQuery, Cloud SQL, and Cloud Storage. You need to configure security services in the data warehouse. Your company compliance policies mandate that the data warehouse must: • Protect data at rest with full lifecycle management on cryptographic keys. • Implement a separate key management provider from data management. • Provide visibility into all encryption key requests. What services should be included in the data warehouse implementation? (Choose two.)

  • A. Customer-managed encryption keys
  • B. Customer-Supplied Encryption Keys
  • C. Key Access Justifications
  • D. Access Transparency and Approval
  • E. Cloud External Key Manager
Show Suggested Answer Hide Answer
Suggested Answer: CE

Wyjaśnienie

1. Prawidłowa odpowiedź lub odpowiedzi:
C. Key Access Justifications
E. Cloud External Key Manager

2. Kompleksowe wyjaśnienie dlaczego dana odpowiedź jest prawidłowa (Analiza):
Odpowiedzi C i E są prawidłowe, ponieważ wspólnie realizują wymagania suwerenności danych oraz pełnej separacji dostawcy usług danych od dostawcy kluczy szyfrujących.

Analiza wymagań:
a. **Separacja zarządzania kluczami od zarządzania danymi:** Cloud External Key Manager (Cloud EKM) (E) umożliwia przechowywanie i zarządzanie kluczami szyfrującymi w zewnętrznym systemie zarządzania kluczami (np. Thales, Fortanix), który znajduje się fizycznie poza infrastrukturą Google Cloud. Usługi takie jak BigQuery czy Cloud SQL przy każdej operacji zapisu/odczytu muszą wysłać żądanie odszyfrowania do zewnętrznego EKM.
b. **Widoczność i kontrola żądań szyfrowania:** Key Access Justifications (KAJ) (C) działa w parze z EKM. Przy każdym żądaniu klucza, Google przesyła do EKM zakodowane uzasadnienie (np. żądanie od klienta, automatyczne zadanie systemowe). Klient może skonfigurować swój zewnętrzny system EKM tak, by automatycznie odrzucał żądania bez prawidłowego uzasadnienia. Daje to pełny audyt i ostateczną kontrolę nad tym, kiedy i dlaczego dane są odszyfrowywane.

3. Wyjaśnienie z osobna każdej niepoprawnej odpowiedzi:
A. Customer-managed encryption keys (CMEK)
   * Dlaczego nieprawidłowa: Choć CMEK pozwala klientowi na zarządzanie kluczami za pomocą Cloud KMS, to same klucze nadal fizycznie znajdują się w infrastrukturze Google Cloud. Nie realizuje to wymogu pełnego odseparowania dostawcy kluczy od dostawcy danych (Google zarządza zarówno danymi, jak i kluczami w KMS).
B. Customer-Supplied Encryption Keys (CSEK)
   * Dlaczego nieprawidłowa: CSEK polega na dostarczeniu klucza w nagłówku API przy każdym zapytaniu. CSEK nie jest wspierany przez BigQuery ani Cloud SQL w taki sposób jak CMEK/EKM, i nie oferuje zaawansowanej integracji z Key Access Justifications.
D. Access Transparency and Approval
   * Dlaczego nieprawidłowa: Access Transparency i Access Approval dają wgląd i wymagają zatwierdzenia dostępu personelu Google do zasobów, ale nie są bezpośrednim mechanizmem zarządzania kluczami kryptograficznymi szyfrującymi dane w spoczynku.

4. Wskazówki, hinty, tips and tricks:
* Integracja zewnętrznego systemu zarządzania kluczami z GCP -> **Cloud EKM (External Key Manager)**.
* Widoczność i decyzyjność o powodach użycia klucza -> **Key Access Justifications (KAJ)**.
* KAJ i Cloud EKM to kluczowe elementy oferty "Sovereign Cloud" w Google Cloud.

5. Reguły wyboru odpowiedzi (Słowa kluczowe):
* Separate key management provider from Google -> Cloud EKM.
* Visibility/justification for key requests -> Key Access Justifications (KAJ).

Wskazówki egzaminacyjne (Tips & Tricks)

Reguła Egzaminacyjna (Exam Rule): 
Jeśli scenariusz dotyczy zabezpieczania zasobów chmurowych (GCP), zawsze wybieraj rozwiązanie typu Managed (SCC, Secret Manager, Cloud KMS), a unikaj rozwiązań self-managed, chyba że pytanie wyraźnie wymaga dostosowania niskopoziomowego.

Haczyki egzaminacyjne (Exam Traps):
- Pułapka IAM: Pytania o uprawnienia często sugerują 'Project Owner' – zawsze szukaj 'Least Privilege' (np. 'Role: Secret Manager Secret Accessor').
- Pułapka Sieciowa: Często mylone są VPC Peering (wydajność) oraz VPN (szyfrowanie/on-premise).

Głębokie wyjaśnienie techniczne:
Rozwiązanie bazuje na GCP Shared Responsibility Model. Google zarządza bezpieczeństwem infrastruktury (Physical, Network, Host), podczas gdy administrator zarządza tożsamością (IAM), danymi (Encryption, Cloud KMS) i regułami dostępu (VPC Firewall).

Analiza i Podsumowanie (AI)

Kluczowe zagadnienia

Sugerowana odpowiedź: CE

Analiza strategiczna: To pytanie jest testem zrozumienia najwyższych standardów "Sovereignty" (suwerenności) w chmurze. EKM fizycznie oddziela "skarb" (klucz) od "domu skarbu" (Google Cloud), a KAJ daje właścicielowi "klucza do drzwi" pełny wgląd w to, kto i dlaczego chce do niego zajrzeć. To idealna konfiguracja dla najbardziej wrażliwych danych.

Dodatkowe wskazówki

  • Wdróż KAJ w trybie "Log-only", aby najpierw zobaczyć, jakie żądania zgłasza Google, zanim przełączysz się na tryb wymuszania zgód.
  • EKM i KAJ są dostępne tylko dla organizacji w wybranych regionach i dla wybranych usług.
