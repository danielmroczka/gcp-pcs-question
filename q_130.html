Question 130 / 361

You plan to use a Google Cloud Armor policy to prevent common attacks such as cross-site scripting (XSS) and SQL injection (SQLi) from reaching your web application's backend. What are two requirements for using Google Cloud Armor security policies? (Choose two.)

  • A. The load balancer must be an external SSL proxy load balancer.
  • B. Google Cloud Armor Policy rules can only match on Layer 7 (L7) attributes.
  • C. The load balancer must use the Premium Network Service Tier.
  • D. The backend service's load balancing scheme must be EXTERNAL.
  • E. The load balancer must be an external HTTP(S) load balancer.
Show Suggested Answer Hide Answer
Suggested Answer: DE

Wyjaśnienie

1. Prawidłowa odpowiedź lub odpowiedzi:
D. The backend service's load balancing scheme must be EXTERNAL.
E. The load balancer must be an external HTTP(S) load balancer.

2. Kompleksowe wyjaśnienie dlaczego dana odpowiedź jest prawidłowa (Analiza):
Wymaganiem jest użycie polityki Google Cloud Armor w celu ochrony aplikacji webowej przed podatnościami warstwy 7, takimi jak Cross-Site Scripting (XSS) i SQL Injection (SQLi):
- Reguły WAF Cloud Armor (w tym predefiniowane reguły XSS i SQLi) wymagają terminowania i głębokiej inspekcji ruchu HTTP(S). Funkcjonalność ta jest dostępna wyłącznie dla zewnętrznych Load Balancerów HTTP(S) (External HTTP(S) Load Balancers) - stąd poprawność odpowiedzi E.
- Dodatkowo, backend podpięty pod Load Balancer musi mieć schemat wdrażania zdefiniowany jako EXTERNAL (lub EXTERNAL_MANAGED) w swojej konfiguracji (Load Balancing Scheme) - stąd poprawność odpowiedzi D.

3. Wyjaśnienie z osobna każdej niepoprawnej odpowiedzi:
- A. Zewnętrzny load balancer SSL Proxy: Obsługuje tylko ruch TCP w warstwie 4. Cloud Armor może chronić go na poziomie L3/L4 (np. blokowanie IP), ale nie potrafi deszyfrować i analizować żądań HTTP pod kątem luk aplikacyjnych typu XSS czy SQLi.
- B. Reguły Cloud Armor mogą pasować tylko do atrybutów L7: Nieprawda. Reguły Cloud Armor mogą filtrować ruch również na poziomie warstw L3/L4 (np. na podstawie adresów IP źródłowych, zakresów CIDR, portów itp.).
- C. Wymóg sieci Premium Network Service Tier: Cloud Armor może działać również z regionalnymi load balancerami, które mogą być skonfigurowane w Standard Tier. Premium Tier nie jest technicznym warunkiem koniecznym do włączenia samych polityk bezpieczeństwa.

4. Wskazówki, hinty, tips and tricks:
- Ochrona WAF w GCP (SQLi, XSS, L7 DDoS) = **Cloud Armor + Zewnętrzny (External) Load Balancer HTTP(S)**.
- Cloud Armor nie chroni bezpośrednio instancji Compute Engine czy kubełków GCS – musi być zawsze przypisany do usługi backendowej (Backend Service) Load Balancera o schemacie zewnętrznym.

5. Reguły wyboru odpowiedzi (Słowa kluczowe):
- Zastosowanie Cloud Armor WAF (XSS/SQLi) -> External HTTP(S) Load Balancer + EXTERNAL load balancing scheme.

6. Dodatkowe źródła i dokumentacja:
- Cloud Armor security policy concepts: https://cloud.google.com/armor/docs/security-policy-concepts
