Question 319 / 361

The InfoSec team has mandated that all new Cloud Run jobs and services in production must have Binary Authorization enabled. You need to enforce this requirement. What should you do?

  • A. Configure an organization policy to require Binary Authorization enforcement on images deployed to Cloud Run.
  • B. Configure a Security Health Analytics (SHA) custom rule that prevents the execution of Cloud Run jobs and services without Binary Authorization.
  • C. Ensure the Cloud Run admin role is not assigned to developers.
  • D. Configure a Binary Authorization custom policy that is not editable by developers and auto-attaches to all Cloud Run jobs and services.
Show Suggested Answer Hide Answer
Suggested Answer: A

Wyjaśnienie

Potwierdzona odpowiedź: A

Wyjaśnienie: 
Organization Policy (Polityka Organizacyjna) jest kluczowym narzędziem w GCP do wymuszania (enforcement) reguł bezpieczeństwa w skali całej organizacji, folderu lub projektu. W przypadku Binary Authorization istnieje dedykowana polityka (constraints/run.binaryAuthorizationEnforcement), która pozwala na zablokowanie wdrożeń obrazów w Cloud Run, które nie spełniają określonych reguł atestacji. Jest to jedyny mechanizm z wymienionych, który aktywnie blokuje niezgodne operacje przed ich wykonaniem, co jest wymagane przez "mandat" zespołu InfoSec.

Dlaczego pozostałe odpowiedzi są niepoprawne:
- B. Security Health Analytics (SHA) to funkcja Security Command Center służąca do wykrywania (detekcji) podatności i błędnych konfiguracji. SHA może zaraportować brak Binary Authorization jako "finding", ale nie potrafi samodzielnie zablokować wdrożenia usługi.
- C. Ograniczenie uprawnień IAM (usunięcie roli admina) to dobra praktyka (zasada najmniejszych uprawnień), ale nie rozwiązuje problemu technicznego wymuszenia Binary Authorization. Nawet użytkownik z ograniczonymi uprawnieniami mógłby wdrożyć obraz bez tej funkcji, jeśli nie jest ona wymuszona systemowo.
- D. Binary Authorization custom policy to konfiguracja reguł, które mechanizm ma sprawdzać (np. kto musi podpisać obraz). Sama obecność polityki w Binary Auth nie oznacza jej automatycznego wymuszenia na wszystkich usługach Cloud Run w organizacji bez użycia Organization Policy.

Wskazówki i triki (Tips & Tricks):
- Słowo "mandate" (nakaz) lub "enforce" (wymusić) w kontekście całej organizacji lub wielu projektów niemal zawsze wskazuje na użycie Organization Policy.
- Binary Authorization działa jako "bramkarz" (gatekeeper) sprawdzający atestacje przed uruchomieniem kontenera.

Praktyczne informacje na egzamin:
- Zapamiętaj nazwę ograniczenia: constraints/run.binaryAuthorizationEnforcement.
- Rozróżniaj detekcję (SHA) od prewencji (Organization Policy).
- Binary Authorization wspiera GKE, Cloud Run oraz Cloud Functions (2nd gen).

Wskazówki egzaminacyjne (Tips & Tricks)

Reguła Egzaminacyjna (Exam Rule): 
W pytaniach typu 'Security in GCP', zawsze priorytetyzuj rozwiązania natywne (SCC, Cloud KMS, Secret Manager, VPC SC) nad rozwiązaniami typu 'third-party' lub 'self-managed', chyba że scenariusz wymaga specyficznej integracji hybrydowej.

Haczyki egzaminacyjne (Exam Traps):
- Pułapka 'Least Privilege': Egzamin często podpowiada role o szerokim zakresie (np. 'Editor' lub 'Owner') – zawsze odrzucaj je na rzecz ról predefiniowanych o najmniejszym zakresie uprawnień.
- Pułapka 'Logging vs Monitoring': Pamiętaj: Audit Logs służą do badania aktywności (Who/What/When), a Monitoring do zbierania metryk wydajnościowych.

Głębokie wyjaśnienie techniczne:
Każda architektura bezpieczeństwa w GCP powinna być projektowana w oparciu o 'Security by Default'. Oznacza to m.in. szyfrowanie w spoczynku (domyślne), tożsamość opartą na rolach (IAM) oraz pełną widoczność zapewnianą przez scentralizowane logowanie (Cloud Logging/SCC).

Analiza i Podsumowanie (AI)

Kluczowe zagadnienia

Sugerowana odpowiedź: A

Analiza strategiczna: Pytanie skupia się na zarządzaniu bezpieczeństwem na poziomie korporacyjnym. W architekturze GCP, Organization Policy służy do ustawiania globalnych "guardrails", których nie można obejść lokalnymi uprawnieniami IAM. Integracja Binary Authorization z Organization Policy dla Cloud Run to nowoczesne podejście do zabezpieczania łańcucha dostaw oprogramowania (software supply chain security).

Praktyczny przykład

Wyobraź sobie, że deweloper próbuje wdrożyć usługę Cloud Run za pomocą `gcloud run deploy`. Jeśli Organization Policy jest włączona, a Binary Authorization nie jest skonfigurowane w definicji usługi lub obraz nie jest podpisany, wdrożenie zostanie odrzucone z błędem 403 Forbidden, zanim jeszcze kontener zostanie pobrany.
