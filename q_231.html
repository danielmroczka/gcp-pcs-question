Question 231 / 361

You are migrating an application into the cloud. The application will need to read data from a Cloud Storage bucket. Due to local regulatory requirements, you need to hold the key material used for encryption fully under your control and you require a valid rationale for accessing the key material. What should you do?

  • A. Encrypt the data in the Cloud Storage bucket by using Customer Managed Encryption Keys. Configure an IAM deny policy for unauthorized groups.
  • B. Generate a key in your on-premises environment to encrypt the data before you upload the data to the Cloud Storage bucket. Upload the key to the Cloud Key Management Service (KMS). Activate Key Access Justifications (KAJ) and have the external key system reject unauthorized accesses.
  • C. Encrypt the data in the Cloud Storage bucket by using Customer Managed Encryption Keys backed by a Cloud Hardware Security Module (HSM). Enable data access logs.
  • D. Generate a key in your on-premises environment and store it in a Hardware Security Module (HSM) that is managed on-premises. Use this key as an external key in the Cloud Key Management Service (KMS). Activate Key Access Justifications (KAJ) and set the external key system to reject unauthorized accesses.
Show Suggested Answer Hide Answer
Suggested Answer: D

Wskazówki egzaminacyjne (Tips & Tricks)

Reguła Egzaminacyjna (Exam Rule): 
Jeśli scenariusz dotyczy zabezpieczania zasobów chmurowych (GCP), zawsze wybieraj rozwiązanie typu Managed (SCC, Secret Manager, Cloud KMS), a unikaj rozwiązań self-managed, chyba że pytanie wyraźnie wymaga dostosowania niskopoziomowego.

Haczyki egzaminacyjne (Exam Traps):
- Pułapka IAM: Pytania o uprawnienia często sugerują 'Project Owner' – zawsze szukaj 'Least Privilege' (np. 'Role: Secret Manager Secret Accessor').
- Pułapka Sieciowa: Często mylone są VPC Peering (wydajność) oraz VPN (szyfrowanie/on-premise).

Głębokie wyjaśnienie techniczne:
Rozwiązanie bazuje na GCP Shared Responsibility Model. Google zarządza bezpieczeństwem infrastruktury (Physical, Network, Host), podczas gdy administrator zarządza tożsamością (IAM), danymi (Encryption, Cloud KMS) i regułami dostępu (VPC Firewall).

Wyjaśnienie

Potwierdzona odpowiedź: D (Generate a key in your on-premises environment and store it in a Hardware Security Module (HSM) that is managed on-premises. Use this key as an external key in the Cloud Key Management Service (KMS). Activate Key Access Justifications (KAJ) and set the external key system to reject unauthorized accesses)

Wyjaśnienie:
- Cloud External Key Manager (EKM): Pozwala na przechowywanie klucza w systemie zewnętrznym (on-premises HSM), co w pełni spełnia wymóg posiadania kontroli nad materiałem klucza ("hold the key material... fully under your control").
- Key Access Justifications (KAJ): To usługa, która wymusza uzasadnienie dla każdego żądania użycia klucza przez Google (np. wsparcie techniczne), co spełnia wymóg "valid rationale for accessing the key material".
- Połączenie: EKM + KAJ to standard "Sovereign Cloud" w Google Cloud.

Dlaczego pozostałe odpowiedzi są niepoprawne:
- A. Customer Managed Encryption Keys (CMEK): Klucze te są zarządzane przez Google wewnątrz Cloud KMS (infrastruktura Google). Nie spełnia to wymogu trzymania materiału klucza "fully under your control" poza GCP.
- B. Upload key to Cloud KMS: Przesłanie własnego klucza (nawet z on-prem) do Cloud KMS oznacza, że staje się on kluczem zarządzanym przez Google (importowanym). Nie spełnia to wymogu "hold the key material fully under your control".
- C. Cloud HSM: Cloud HSM to usługa sprzętowa Google Cloud. Klucze są w niej przechowywane, ale są one pod kontrolą Google (jako dostawcy usługi).

Wskazówki i triki (Tips & Tricks):
- "Hold key material fully under your control" = EKM (External Key Manager).
- "Valid rationale for accessing key" = KAJ (Key Access Justifications).
- Pamiętaj: KAJ jest "strażnikiem" Twoich kluczy EKM.

Praktyczne informacje na egzamin:
- Zapamiętaj: KAJ nie jest tylko logiem, to mechanizm "Justification-based access", który może zablokować użycie klucza, jeśli uzasadnienie jest niewystarczające.
- KAJ jest krytyczny dla zgodności z surowymi regulacjami prawnymi (np. w bankowości).

Analiza i Podsumowanie (AI)

Kluczowe zagadnienia

Sugerowana odpowiedź: D

Analiza strategiczna: To pytanie sprawdza najwyższy poziom dojrzałości bezpieczeństwa (Sovereignty). EKM to separacja fizyczna, a KAJ to kontrola logiczna (użytkownik podejmuje decyzję o dostępności klucza w czasie rzeczywistym). To kompletne rozwiązanie dla regulacji wymagających, by "nikt z zewnątrz nie mógł dotknąć danych bez mojej wyraźnej wiedzy i zgody".
