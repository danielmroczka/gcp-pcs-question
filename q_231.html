Question 231 / 361

You are migrating an application into the cloud. The application will need to read data from a Cloud Storage bucket. Due to local regulatory requirements, you need to hold the key material used for encryption fully under your control and you require a valid rationale for accessing the key material. What should you do?

  • A. Encrypt the data in the Cloud Storage bucket by using Customer Managed Encryption Keys. Configure an IAM deny policy for unauthorized groups.
  • B. Generate a key in your on-premises environment to encrypt the data before you upload the data to the Cloud Storage bucket. Upload the key to the Cloud Key Management Service (KMS). Activate Key Access Justifications (KAJ) and have the external key system reject unauthorized accesses.
  • C. Encrypt the data in the Cloud Storage bucket by using Customer Managed Encryption Keys backed by a Cloud Hardware Security Module (HSM). Enable data access logs.
  • D. Generate a key in your on-premises environment and store it in a Hardware Security Module (HSM) that is managed on-premises. Use this key as an external key in the Cloud Key Management Service (KMS). Activate Key Access Justifications (KAJ) and set the external key system to reject unauthorized accesses.
Show Suggested Answer Hide Answer
Suggested Answer: D

Wyjaśnienie

1. Prawidłowa odpowiedź lub odpowiedzi:
D. Generate a key in your on-premises environment and store it in a Hardware Security Module (HSM) that is managed on-premises. Use this key as an external key in the Cloud Key Management Service (KMS). Activate Key Access Justifications (KAJ) and set the external key system to reject unauthorized accesses.

2. Kompleksowe wyjaśnienie dlaczego dana odpowiedź jest prawidłowa (Analiza):
Odpowiedź D jest prawidłowa, ponieważ w pełni realizuje zaawansowane wymagania suwerenności danych oraz pełnej kontroli klienta nad procesem odszyfrowywania za pomocą zewnętrznego zarządzania kluczami (Cloud EKM) oraz Key Access Justifications (KAJ).

Analiza krok po kroku:
a. **Kontrola klucza on-premises:** Klucz generowany i przechowywany w lokalnym module HSM (on-premises HSM) gwarantuje, że materiał klucza (key material) nigdy nie znajdzie się w chmurze Google.
b. **Integracja z GCP:** Cloud EKM pozwala na odwołanie się do tego zewnętrznego klucza podczas szyfrowania kubełka Cloud Storage.
c. **Key Access Justifications (KAJ):** Przy każdej próbie odczytu danych przez GCP, Google przesyła do zewnętrznego HSM uzasadnienie (rationale) dostępu. Lokalny HSM klienta analizuje to uzasadnienie i jeśli żądanie nie jest autoryzowane (lub brak poprawnego uzasadnienia), odrzuca operację odszyfrowania, co uniemożliwia dostęp do danych.

3. Wyjaśnienie z osobna każdej niepoprawnej odpowiedzi:
A. Encrypt the data... using Customer Managed Encryption Keys. Configure an IAM deny policy...
   * Dlaczego nieprawidłowa: Zwykłe klucze CMEK w Cloud KMS są przechowywane i kontrolowane przez infrastrukturę Google Cloud, a nie lokalnie na fizycznym HSM klienta. Ponadto IAM deny policy nie dostarcza mechanizmu wymuszania racjonalizacji (Key Access Justifications) przy dostępie do kluczy przez systemy Google.
B. Generate a key in your on-premises environment... Upload the key to the Cloud Key Management Service (KMS)...
   * Dlaczego nieprawidłowa: Przesłanie (import) klucza do Cloud KMS powoduje, że materiał klucza trafia do chmury Google. Przestaje on być "w pełni pod kontrolą on-premises" i wyklucza integrację z zewnętrznymi mechanizmami decyzji HSM klienta w locie.
C. Encrypt the data... using Customer Managed Encryption Keys backed by a Cloud Hardware Security Module (HSM). Enable data access logs.
   * Dlaczego nieprawidłowa: Cloud HSM to usługa zarządzana w chmurze Google. Klucze nie są przechowywane w lokalnej serwerowni klienta. Logi dostępu (Data Access Logs) są jedynie mechanizmem audytowym po fakcie, a nie aktywnym systemem odrzucania nieautoryzowanych zapytań o klucz na bazie KAJ.

4. Wskazówki, hinty, tips and tricks:
* Pełna kontrola nad kluczami poza GCP + wymaganie uzasadnienia żądań dostępu -> **External HSM (Cloud EKM)** + **Key Access Justifications (KAJ)**.
* KAJ pozwala na blokowanie żądań bezpośrednio na zewnętrznym systemie klienta (external key coordinator/system).

5. Reguły wyboru odpowiedzi (Słowa kluczowe):
* Hold key material fully under control on-premises + rationale for accessing -> External HSM/KMS + Key Access Justifications (KAJ).
