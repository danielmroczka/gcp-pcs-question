Question 45 / 361

A large financial institution is moving its Big Data analytics to Google Cloud Platform. They want to have maximum control over the encryption process of data stored at rest in BigQuery. What technique should the institution use?

  • A. Use Cloud Storage as a federated Data Source.
  • B. Use a Cloud Hardware Security Module (Cloud HSM).
  • C. Customer-managed encryption keys (CMEK).
  • D. Customer-supplied encryption keys (CSEK).
Show Suggested Answer Hide Answer
Suggested Answer: C

Wyjaśnienie

**Poprawna odpowiedź: C**

**1. Kompleksowe wyjaśnienie poprawnej odpowiedzi:**
Instytucja finansowa chce mieć **maksymalną kontrolę nad procesem szyfrowania danych w BigQuery** (szyfrowanie danych w spoczynku):
- **Customer-Managed Encryption Keys (CMEK) (C):** BigQuery natywnie integruje się z Cloud Key Management Service (KMS), umożliwiając korzystanie z kluczy zarządzanych przez klienta (CMEK). Klient może samodzielnie zarządzać rotacją, wyłączaniem i niszczeniem klucza KEK. Ponieważ klucz leży w KMS, klient kontroluje uprawnienia dostępu do niego za pomocą IAM, zachowując pełną kontrolę nad dostępem do tabel BigQuery.

**2. Wyjaśnienie niepoprawnych odpowiedzi:**
- **A. Cloud Storage jako zewnętrzne źródło danych:** BigQuery może odpytywać dane w GCS (Federated Queries), ale to nie rozwiązuje problemu natywnego szyfrowania danych przechowywanych wewnątrz samego BigQuery i nie daje lepszej kontroli nad kluczami.
- **B. Użycie Cloud HSM:** Cloud HSM to sprzętowy moduł bezpieczeństwa, który przechowuje klucze w KMS. Jest to fizyczna lokalizacja klucza, a nie technika integracji z BigQuery. Klient nadal potrzebuje wdrożyć mechanizm CMEK, by BigQuery korzystało z kluczy w HSM.
- **D. Customer-Supplied Encryption Keys (CSEK):** BigQuery **nie wspiera** kluczy dostarczanych przez użytkownika (CSEK). CSEK są wspierane wyłącznie przez Compute Engine i Cloud Storage.

**3. Wskazówki i pułapki egzaminacyjne (Tips & Tricks):**
- Zapamiętaj bardzo ważną różnicę w obsłudze kluczy:
  - **Cloud Storage i Compute Engine:** Wspierają zarówno **CMEK**, jak i **CSEK**.
  - **BigQuery (oraz większość innych usług GCP):** Wspierają wyłącznie **CMEK**. CSEK jest tu niedostępny.
- Dlatego w BigQuery maksymalną formą kontroli szyfrowania jest **CMEK**.

**4. Reguły wyboru odpowiedzi:**
- Szyfrowanie w BigQuery pod kontrolą klienta -> CMEK.

**5. Dodatkowe źródła:**
- Protect BigQuery data with CMEK: https://cloud.google.com/bigquery/docs/customer-managed-keys

Wyjaśnienie Audytowe

Reguła Egzaminacyjna (Exam Rule):
Pamiętaj, że w egzaminie Professional Cloud Security Engineer kluczowe jest wybieranie rozwiązań najmniej uprzywilejowanych (Principle of Least Privilege), zoptymalizowanych kosztowo i spełniających wymogi compliancy (np. CMEK, Data Loss Prevention).

Haczyki egzaminacyjne (Exam Traps):
- Wybór rozwiązań, które wydają się wygodne, ale nie spełniają wymogów bezpieczeństwa (np. zbyt szerokie uprawnienia IAM).
- Mylenie usług: np. Cloud Armor (WAF) z Cloud IAP (Identity-Aware Proxy).

Głębokie wyjaśnienie techniczne (GCP Professional Cloud Security Engineer):
W każdym pytaniu analizuj warstwy: IAM (dostęp), Encryption (at rest/in transit), Logging/Monitoring (Audit Logs, Cloud Logging, Security Command Center) oraz Networking (VPC Service Controls, Firewall Rules). GCP kładzie duży nacisk na współdzieloną odpowiedzialność (Shared Responsibility Model) - klient odpowiada za konfigurację zabezpieczeń wewnątrz usług chmurowych.
