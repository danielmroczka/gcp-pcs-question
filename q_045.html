Question 45 / 361

A large financial institution is moving its Big Data analytics to Google Cloud Platform. They want to have maximum control over the encryption process of data stored at rest in BigQuery. What technique should the institution use?

  • A. Use Cloud Storage as a federated Data Source.
  • B. Use a Cloud Hardware Security Module (Cloud HSM).
  • C. Customer-managed encryption keys (CMEK).
  • D. Customer-supplied encryption keys (CSEK).
Show Suggested Answer Hide Answer
Suggested Answer: C

Wyjaśnienie

Potwierdzona odpowiedź: C (Customer-managed encryption keys - CMEK)

Wyjaśnienie:
Gdy klient potrzebuje "maksymalnej kontroli" nad kluczami szyfrującymi dane w spoczynku (at rest) w usłudze BigQuery, właściwym rozwiązaniem jest CMEK.
1. CMEK (Customer-managed encryption keys): Pozwala klientowi na tworzenie i zarządzanie kluczami w usłudze Cloud KMS (Key Management Service). Klient ma kontrolę nad rotacją kluczy, ich wyłączaniem oraz niszczeniem. BigQuery używa tych kluczy do szyfrowania danych zamiast domyślnych kluczy zarządzanych przez Google.
2. BigQuery Support: Ważne jest, aby pamiętać, że BigQuery wspiera CMEK, ale NIE wspiera CSEK (kluczy dostarczanych przez klienta w każdym żądaniu).

Dlaczego pozostałe są błędne:
A. Federated Data Source: To metoda odpytywania danych znajdujących się poza BigQuery (np. w Cloud Storage). Nie jest to technika szyfrowania zapewniająca kontrolę nad danymi wewnątrz BigQuery.
B. Cloud HSM: To sprzętowy moduł bezpieczeństwa (FIPS 140-2 L3), który może przechowywać klucze dla Cloud KMS. Chociaż zwiększa on poziom bezpieczeństwa fizycznego kluczy, sam w sobie nie jest "techniką" szyfrowania BigQuery. Klucze z Cloud HSM są używane w ramach CMEK.
D. CSEK (Customer-supplied encryption keys): W tej metodzie klient wysyła surowy klucz w każdym żądaniu API. CSEK jest wspierany przez Cloud Storage i Compute Engine, ale BigQuery go nie obsługuje. Dlatego CMEK jest jedyną poprawną opcją dla BigQuery przy wymogu kontroli klucza przez klienta.

Wskazówki egzaminacyjne (Tips & Tricks):
- Zapamiętaj: BigQuery = CMEK (Tak), CSEK (Nie).
- Jeśli pytanie pyta o "control" w BigQuery, szukaj CMEK.
- Pamiętaj, że CMEK wymaga nadania uprawnień (role/cloudkms.cryptoKeyEncrypterDecrypter) kontu serwisowemu BigQuery do klucza w KMS.

Kluczowe zagadnienia do powtórzenia:
- Różnica między Default encryption, CMEK i CSEK.
- Wsparcie dla CSEK w różnych usługach GCP.
- Integracja BigQuery z Cloud KMS.

Analiza i Podsumowanie Dyskusji (AI)

Analiza i Wyjaśnienie

Sugerowana odpowiedź: C

Analiza spornych kwestii (AI): Pułapką w tym pytaniu jest opcja D. Inżynierowie przyzwyczajeni do Cloud Storage często szukają CSEK jako formy "największej kontroli". Jednak w BigQuery najwyższą dostępną formą kontroli klucza zarządzanego przez klienta jest CMEK (z ewentualnym wsparciem Cloud HSM dla najwyższej zgodności).

Wyjaśnienie Audytowe

Reguła Egzaminacyjna (Exam Rule):
Pamiętaj, że w egzaminie Professional Cloud Security Engineer kluczowe jest wybieranie rozwiązań najmniej uprzywilejowanych (Principle of Least Privilege), zoptymalizowanych kosztowo i spełniających wymogi compliancy (np. CMEK, Data Loss Prevention).

Haczyki egzaminacyjne (Exam Traps):
- Wybór rozwiązań, które wydają się wygodne, ale nie spełniają wymogów bezpieczeństwa (np. zbyt szerokie uprawnienia IAM).
- Mylenie usług: np. Cloud Armor (WAF) z Cloud IAP (Identity-Aware Proxy).

Głębokie wyjaśnienie techniczne (GCP Professional Cloud Security Engineer):
W każdym pytaniu analizuj warstwy: IAM (dostęp), Encryption (at rest/in transit), Logging/Monitoring (Audit Logs, Cloud Logging, Security Command Center) oraz Networking (VPC Service Controls, Firewall Rules). GCP kładzie duży nacisk na współdzieloną odpowiedzialność (Shared Responsibility Model) - klient odpowiada za konfigurację zabezpieczeń wewnątrz usług chmurowych.
