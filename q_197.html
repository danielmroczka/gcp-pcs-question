Question 197 / 361

You run applications on Cloud Run. You already enabled container analysis for vulnerability scanning. However, you are concerned about the lack of control on the applications that are deployed. You must ensure that only trusted container images are deployed on Cloud Run. What should you do? (Choose two.)

  • A. Enable Binary Authorization on the existing Cloud Run service.
  • B. Set the organization policy constraint constraints/run.allowedBinaryAuthorizationPolicies to the list or allowed Binary Authorization policy names.
  • C. Enable Binary Authorization on the existing Kubernetes cluster.
  • D. Use Cloud Run breakglass to deploy an image that meets the Binary Authorization policy by default.
  • E. Set the organization policy constraint constraints/compute.trustedImageProjects to the list of projects that contain the trusted container images.
Show Suggested Answer Hide Answer
Suggested Answer: AB

Wyjaśnienie

1. Prawidłowa odpowiedź lub odpowiedzi:
A. Enable Binary Authorization on the existing Cloud Run service.
B. Set the organization policy constraint constraints/run.allowedBinaryAuthorizationPolicies to the list or allowed Binary Authorization policy names.

2. Kompleksowe wyjaśnienie dlaczego dana odpowiedź jest prawidłowa (Analiza):
Wymaganiem jest zabezpieczenie wdrożeń na usłudze Cloud Run tak, aby uruchamiane były wyłącznie zaufane obrazy kontenerów, a zasady te były wymuszone w skali całej organizacji.
W Google Cloud usługą, która działa jako brama (gatekeeper) kontrolująca i weryfikująca obrazy kontenerów przed wdrożeniem pod kątem atestów i podpisów, jest **Binary Authorization**.
Prawidłowe kroki to:
- **A (Włączenie na usłudze):** Aby dana usługa Cloud Run weryfikowała obrazy przy każdym deployu, należy włączyć Binary Authorization bezpośrednio w konfiguracji usługi Cloud Run (ustawienie sprawdzania polityki).
- **B (Polityka organizacji):** Aby zapobiec omijaniu tych zasad przez deweloperów i zapewnić spójną politykę bezpieczeństwa w firmie, należy zastosować politykę organizacji (Organization Policy) z ograniczeniem `constraints/run.allowedBinaryAuthorizationPolicies`. Określa ona listę dozwolonych polityk Binary Authorization, które mogą być powiązane z usługami Cloud Run w organizacji.

3. Wyjaśnienie z osobna każdej niepoprawnej odpowiedzi:
- C. Enable Binary Authorization on the existing Kubernetes cluster: Choć Binary Authorization integruje się z GKE, w tym scenariuszu aplikacja działa na usłudze Cloud Run (platforma serverless), a nie na klastrze GKE. Włączenie polityki na klastrze GKE nie zabezpieczy wdrożeń na Cloud Run.
- D. Use Cloud Run breakglass to deploy an image that meets the Binary Authorization policy by default: Funkcja "breakglass" służy do awaryjnego pominięcia (obejścia) reguł Binary Authorization (np. w przypadku awarii na produkcji, gdy musimy szybko wdrożyć poprawkę, a system atestacji nie działa). Używanie breakglass "by default" podważa cały sens wdrożenia polityki bezpieczeństwa.
- E. Set the organization policy constraint constraints/compute.trustedImageProjects...: To ograniczenie polityki organizacji służy do ograniczania źródła obrazów maszyn wirtualnych dla usługi Compute Engine (VM instances). Nie dotyczy ono obrazów kontenerów wdrażanych na Cloud Run.

4. Wskazówki, hinty, tips and tricks:
- Gdy celem jest wdrażanie wyłącznie zaufanych kontenerów (trusted container images) na Cloud Run lub GKE, rozwiązaniem jest **Binary Authorization**.
- Zwracaj uwagę na to, gdzie uruchamiana jest aplikacja – dla Cloud Run odpowiednie są reguły z prefiksem `run.`, a nie `compute.` czy GKE.

5. Reguły wyboru odpowiedzi (Słowa kluczowe):
- "Cloud Run" + "only trusted container images are deployed" -> Binary Authorization -> `run.allowedBinaryAuthorizationPolicies`.

6. Dodatkowe źródła i dokumentacja:
- Binary Authorization for Cloud Run overview: https://cloud.google.com/binary-authorization/docs/cloud-run/overview
