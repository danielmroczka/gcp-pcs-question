Question 196 / 361

Your organization previously stored files in Cloud Storage by using Google Managed Encryption Keys (GMEK), but has recently updated the internal policy to require Customer Managed Encryption Keys (CMEK). You need to re-encrypt the files quickly and efficiently with minimal cost. What should you do?

  • A. Reupload the files to the same Cloud Storage bucket specifying a key file by using gsutil.
  • B. Encrypt the files locally, and then use gsutil to upload the files to a new bucket.
  • C. Copy the files to a new bucket with CMEK enabled in a secondary region.
  • D. Change the encryption type on the bucket to CMEK, and rewrite the objects.
Show Suggested Answer Hide Answer
Suggested Answer: D

Wyjaśnienie

1. Prawidłowa odpowiedź lub odpowiedzi:
D. Change the encryption type on the bucket to CMEK, and rewrite the objects.

2. Kompleksowe wyjaśnienie dlaczego dana odpowiedź jest prawidłowa (Analiza):
Organizacja wymaga zmiany metody szyfrowania danych w Cloud Storage z domyślnego klucza zarządzanego przez Google (GMEK) na klucze zarządzane przez klienta (CMEK). Proces ten musi zostać wykonany szybko, efektywnie i przy minimalnych kosztach.
Prawidłowa procedura re-szyfrowania w Cloud Storage składa się z dwóch etapów:
1. **Zmiana domyślnego klucza na buckecie:** W ustawieniach bucketu konfiguruje się domyślne szyfrowanie przy użyciu wybranego klucza Cloud KMS (CMEK). Od tego momentu każdy nowo zapisany obiekt będzie szyfrowany tym kluczem.
2. **Re-szyfrowanie istniejących obiektów (Rewrite):** Obiekty, które już znajdowały się w buckecie przed zmianą ustawień, nadal są zaszyfrowane starym kluczem (GMEK). Aby zmienić ich szyfrowanie "w miejscu" na nowy klucz, stosuje się operację **Rewrite** (w CLI `gsutil rewrite`).
Operacja ta jest wykonywana w całości wewnątrz infrastruktury Google Cloud. Dane nie są pobierane na zewnątrz, co minimalizuje czas wykonania oraz eliminuje koszty transferu sieciowego (egress fees), czyniąc tę metodę najbardziej efektywną kosztowo.

3. Wyjaśnienie z osobna każdej niepoprawnej odpowiedzi:
- A. Reupload the files to the same Cloud Storage bucket specifying a key file by using gsutil: Pobieranie wszystkich plików na lokalną maszynę i ich ponowne wysyłanie (re-upload) wiąże się z ogromnym czasem pracy, narzutem sieciowym oraz potencjalnymi kosztami transferu danych, jeśli maszyna lokalna znajduje się poza siecią GCP.
- B. Encrypt the files locally, and then use gsutil to upload...: Szyfrowanie lokalne przed wysyłką oznacza przejście na model CSEK (Customer-Supplied Encryption Keys), co jest niezgodne z wymaganiem wdrożenia CMEK (klucze w Cloud KMS). Podobnie jak opcja A, generuje to niepotrzebne koszty transferu i narzut operacyjny.
- C. Copy the files to a new bucket with CMEK enabled in a secondary region: Kopiowanie danych do innego regionu geograficznego generuje wysokie opłaty za transfer danych między regionami (cross-region egress), co stoi w sprzeczności z wymaganiem minimalizacji kosztów.

4. Wskazówki, hinty, tips and tricks:
- Zmiana szyfrowania istniejących plików w Cloud Storage w miejscu (in-place re-encryption) zawsze wiąże się z użyciem polecenia **rewrite** (`gsutil rewrite`).
- Zmiana domyślnego klucza szyfrowania bucketu wpływa tylko na nowo wgrywane pliki. Istniejące obiekty wymagają jawnego przepisania (rewrite).

5. Reguły wyboru odpowiedzi (Słowa kluczowe):
- "re-encrypt files quickly" + "Cloud Storage" + "require CMEK" + "minimal cost" -> Change encryption on bucket to CMEK -> rewrite objects.
