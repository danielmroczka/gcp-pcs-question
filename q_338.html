Question 338 / 361

Your organization is planning to deploy a large number of Google Kubernetes Engine (GKE) clusters to run business applications in different folders and projects. You must ensure that all GKE nodes always run the latest release to minimize vulnerability risk and administrative effort. What should you do?

  • A. Configure node auto-upgrades for node pools in the maintenance windows.
  • B. Create a custom organization policy constraint resource.management.autoUpgrade == true with an action type of ALLOW at the organization level before deployment.
  • C. Create a new node pool with the newer version for each cluster. Migrate the workload. Eliminate the outdated node pool.
  • D. Manually run the Google Cloud console gcloud container clusters upgrade CLUSTER_NAME--node-pool=NODE_POOL_NAME --cluster-version VERSION command on newly created clusters regularly.
Show Suggested Answer Hide Answer
Suggested Answer: A

Wyjaśnienie

Poprawna odpowiedź: A (Configure node auto-upgrades for node pools in the maintenance windows.)

Dlaczego ta odpowiedź jest poprawna:
- Node Auto-upgrades: To funkcja GKE, która automatycznie dba o to, aby węzły (nodes) miały najnowszą wersję Kubernetes i poprawki bezpieczeństwa.
- "Latest release" + "Minimize vulnerability risk" + "Administrative effort" = Node Auto-upgrades.

Analiza niepoprawnych odpowiedzi:
- B. Organization Policy: Nie istnieje taka polityka "autoUpgrade".
- C. Manual migration: Bardzo pracochłonne, zwiększa "administrative effort".
- D. Manual gcloud upgrade: Również manualne, zwiększa "administrative effort".

Wskazówki i triki (Tips & Tricks):
- "GKE nodes" + "latest release" + "minimize administrative effort" = Auto-upgrades.

Praktyczne informacje na egzamin:
- Zapamiętaj: W GKE najlepiej zostawić zarządzanie wersjami (upgrade) usłudze zarządzanej Google.

Wskazówki egzaminacyjne (Tips & Tricks)

Reguła Egzaminacyjna (Exam Rule): 
W pytaniach typu 'Security in GCP', zawsze priorytetyzuj rozwiązania natywne (SCC, Cloud KMS, Secret Manager, VPC SC) nad rozwiązaniami typu 'third-party' lub 'self-managed', chyba że scenariusz wymaga specyficznej integracji hybrydowej.

Haczyki egzaminacyjne (Exam Traps):
- Pułapka 'Least Privilege': Egzamin często podpowiada role o szerokim zakresie (np. 'Editor' lub 'Owner') – zawsze odrzucaj je na rzecz ról predefiniowanych o najmniejszym zakresie uprawnień.
- Pułapka 'Logging vs Monitoring': Pamiętaj: Audit Logs służą do badania aktywności (Who/What/When), a Monitoring do zbierania metryk wydajnościowych.

Głębokie wyjaśnienie techniczne:
Każda architektura bezpieczeństwa w GCP powinna być projektowana w oparciu o 'Security by Default'. Oznacza to m.in. szyfrowanie w spoczynku (domyślne), tożsamość opartą na rolach (IAM) oraz pełną widoczność zapewnianą przez scentralizowane logowanie (Cloud Logging/SCC).
