Question 267 / 361

Your organization operates in a highly regulated industry and needs to implement strict controls around temporary access to sensitive Google Cloud resources. You have been using Access Approval to manage this access, but your compliance team has mandated the use of a custom signing key. Additionally, they require that the key be stored in a hardware security module (HSM) located outside Google Cloud. You need to configure Access Approval to use a custom signing key that meets the compliance requirements. What should you do?

  • A. Create a new asymmetric signing key in Cloud Key Management System (Cloud KMS) using a supported algorithm and grant the Access Approval service account the IAM signerVerifier role on the key.
  • B. Export your existing Access Approval signing key as a PEM file. Upload the file to your external HSM and reconfigure Access Approval to use the key from the HSM.
  • C. Create a signing key in your external HSM. Integrate the HSM with Cloud External Key Manager (Cloud EKM) and make the key available within your project. Configure Access Approval to use this key.
  • D. Create a new asymmetric signing key in Cloud KMS and configure the key with a rotation period of 30 days. Add the corresponding public key to your external HSM.
Show Suggested Answer
Suggested Answer: C

Wyjaśnienie

1. Prawidłowa odpowiedź lub odpowiedzi:
C. Create a signing key in your external HSM. Integrate the HSM with Cloud External Key Manager (Cloud EKM) and make the key available within your project. Configure Access Approval to use this key.

2. Kompleksowe wyjaśnienie dlaczego dana odpowiedź jest prawidłowa (Analiza):
Odpowiedź C jest prawidłowa, ponieważ w pełni spełnia rygorystyczne wymagania zgodności (compliance) dotyczące przechowywania klucza podpisującego zatwierdzenia dostępu (Access Approval) w fizycznym module HSM zlokalizowanym całkowicie poza chmurą Google (on-premises / zewnętrzny partner).

Szczegóły integracji:
a. **External HSM:** Klucz podpisujący jest generowany i stale przechowywany w zewnętrznym module bezpieczeństwa klienta.
b. **Cloud EKM (External Key Manager):** GCP integruje się z tym zewnętrznym HSM za pomocą interfejsu Cloud EKM. Pozwala to usłudze Access Approval na wysyłanie żądań kryptograficznego podpisania decyzji o zatwierdzeniu dostępu do zewnętrznego HSM bez ujawniania samego materiału klucza chmurze Google.
c. **Ostateczna kontrola:** Jeśli klient zablokuje dostęp do klucza na swoim zewnętrznym HSM, personel Google nie będzie mógł uzyskać dostępu do danych, nawet jeśli zatwierdzenie zostało kliknięte w konsoli, co daje klientowi pełną suwerenność operacyjną.

3. Wyjaśnienie z osobna każdej niepoprawnej odpowiedzi:
A. Create a new asymmetric signing key in Cloud Key Management System (Cloud KMS)...
   * Dlaczego nieprawidłowa: Klucze w standardowym Cloud KMS są generowane i przechowywane w infrastrukturze chmurowej Google. Narusza to wymóg przechowywania klucza w module HSM zlokalizowanym *poza* Google Cloud.
B. Export your existing Access Approval signing key as a PEM file. Upload the file to your external HSM...
   * Dlaczego nieprawidłowa: Eksportowanie klucza prywatnego jako pliku tekstowego PEM i przesyłanie go przez sieć jest skrajnie niebezpieczne. Ponadto klucze generowane w Cloud KMS nie są zaprojektowane do eksportowania ich kluczy prywatnych na zewnątrz (są one bezpiecznie zamknięte w modułach HSM Google).
D. Create a new asymmetric signing key in Cloud KMS... Add the corresponding public key to your external HSM.
   * Dlaczego nieprawidłowa: Przesłanie klucza publicznego (public key) do zewnętrznego HSM nie pozwala na wykonywanie operacji podpisywania za pomocą tego HSM. To klucz prywatny (private key) musi być używany do podpisywania zatwierdzeń, a ta opcja pozostawia klucz prywatny w chmurze Google (Cloud KMS).

4. Wskazówki, hinty, tips and tricks:
* Access Approval pozwala klientom na jawne zatwierdzanie dostępu inżynierów Google do ich danych w celach wsparcia.
* Wymóg przechowywania kluczy kryptograficznych poza infrastrukturą Google (outside Google Cloud) -> Zawsze używaj **Cloud EKM (External Key Manager)**.

5. Reguły wyboru odpowiedzi (Słowa kluczowe):
* Access Approval + signing key stored in HSM outside Google Cloud -> Integrate external HSM with Cloud External Key Manager (Cloud EKM).
