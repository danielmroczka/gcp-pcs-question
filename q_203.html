Question 203 / 361

Your organization must comply with the regulation to keep instance logging data within Europe. Your workloads will be hosted in the Netherlands in region europe-west4 in a new project. You must configure Cloud Logging to keep your data in the country.

  • A. Configure the organization policy constraint gcp.resourceLocations to europe-west4.
  • B. Configure log sink to export all logs into a Cloud Storage bucket in europe-west4.
  • C. Create a new log bucket in europe-west4, and redirect the _Default bucket to the new bucket.
  • D. Set the logging storage region to europe-west4 by using the gcloud CLI logging settings update.
Show Suggested Answer Hide Answer
Suggested Answer: D

Wyjaśnienie

1. Prawidłowa odpowiedź lub odpowiedzi:
D. Set the logging storage region to europe-west4 by using the gcloud CLI logging settings update.

2. Kompleksowe wyjaśnienie dlaczego dana odpowiedź jest prawidłowa (Analiza):
Odpowiedź D jest prawidłowa, ponieważ najskuteczniejszym i zalecanym sposobem na wymuszenie rezydentności danych logów (data residency) w konkretnym regionie geograficznym dla domyślnych kubełków logów (`_Required` i `_Default`) jest zmiana globalnych ustawień Cloud Logging dla projektu, folderu lub organizacji.

Mechanizm działania:
a. Domyślnie Cloud Logging przechowuje logi w regionie `global`.
b. Użycie polecenia `gcloud logging settings update` pozwala administratorowi zdefiniować domyślną lokalizację przechowywania logów (np. `europe-west4` w Holandii).
c. Wszystkie nowo tworzone zasobniki logów (`_Required` i `_Default`) zostaną automatycznie utworzone w wskazanym regionie, gwarantując, że dane logowania nie opuszczą terytorium Europy, co spełnia wymogi regulacyjne.

3. Wyjaśnienie z osobna każdej niepoprawnej odpowiedzi:
A. Configure the organization policy constraint gcp.resourceLocations to europe-west4.
   * Dlaczego nieprawidłowa: Ta polityka organizacji ogranicza lokalizację tworzenia zasobów (np. maszyn VM, dysków), ale nie wpływa automatycznie na wewnętrzne mechanizmy i domyślne lokalizacje przechowywania danych w Cloud Logging, które wymagają dedykowanej konfiguracji.
B. Configure log sink to export all logs into a Cloud Storage bucket in europe-west4.
   * Dlaczego nieprawidłowa: Chociaż wyeksportowanie logów do kubła GCS w Europie zapisze tam ich kopię, to domyślne logi wciąż będą zapisywane i przechowywane w domyślnych kubełkach `_Default` i `_Required` w lokalizacji `global`, co narusza wymóg przechowywania wszystkich logów wyłącznie w Europie.
C. Create a new log bucket in europe-west4, and redirect the _Default bucket to the new bucket.
   * Dlaczego nieprawidłowa: Choć przekierowanie logów do nowego kubełka jest wykonalne, nie rozwiązuje to problemu kubełka `_Required`, który nadal zbiera logi audytowe (Admin Activity) i jest przechowywany w lokalizacji domyślnej (`global`). Tylko aktualizacja ustawień domyślnych (opcja D) rozwiązuje ten problem kompleksowo.

4. Wskazówki, hinty, tips and tricks:
* Aby zmienić lokalizację domyślnych kubełków logowania (`_Default` i `_Required`), należy skonfigurować ustawienia domyślne (default settings) dla Cloud Logging za pomocą narzędzi gcloud lub API.
* Pamiętaj o różnicy między eksportem logów (sink) a konfiguracją domyślnego miejsca zapisu logów.

5. Reguły wyboru odpowiedzi (Słowa kluczowe):
* Zmiana domyślnej lokalizacji przechowywania logów (Cloud Logging data residency) -> `logging settings update`.
