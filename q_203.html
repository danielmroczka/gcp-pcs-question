Question 203 / 361

Your organization must comply with the regulation to keep instance logging data within Europe. Your workloads will be hosted in the Netherlands in region europe-west4 in a new project. You must configure Cloud Logging to keep your data in the country.

  • A. Configure the organization policy constraint gcp.resourceLocations to europe-west4.
  • B. Configure log sink to export all logs into a Cloud Storage bucket in europe-west4.
  • C. Create a new log bucket in europe-west4, and redirect the _Default bucket to the new bucket.
  • D. Set the logging storage region to europe-west4 by using the gcloud CLI logging settings update.
Show Suggested Answer Hide Answer
Suggested Answer: D

Wyjaśnienie

Potwierdzona odpowiedź: D (Set the logging storage region to europe-west4 by using the gcloud CLI logging settings update).

Wyjaśnienie:
- Rezydencja danych (Data Residency): Niektóre regulacje (np. RODO/GDPR w specyficznych interpretacjach lub lokalne prawo holenderskie) wymagają, aby logi nie tylko były "dostępne" w regionie, ale fizycznie tam składowane.
- gcloud logging settings update: Jest to najskuteczniejszy i najbardziej elegancki sposób na wymuszenie rezydencji danych dla całego projektu. Komenda ta pozwala na ustawienie domyślnej lokalizacji (storage location) dla automatycznie tworzonych bucketów logów (`_Default` i `_Required`).
- Automatyzacja: Zmieniając to ustawienie na poziomie projektu, masz pewność, że wszystkie logi systemowe i aplikacyjne trafią do właściwego regionu bez konieczności ręcznego tworzenia nowych bucketów i konfigurowania skomplikowanych sinków.

Dlaczego pozostałe odpowiedzi są niepoprawne:
- A. resourceLocations organization policy: Ta polityka ogranicza to, GDZIE można tworzyć zasoby (np. w którym regionie postawić maszynę VM), ale nie kontroluje ona bezpośrednio fizycznej lokalizacji składowania logów wewnątrz samej usługi Cloud Logging.
- B. Log sink to Cloud Storage: Choć eksport logów do GCS w konkretnym regionie zapewnia kopię danych w tym regionie, nie rozwiązuje problemu "głównych" logów, które wciąż trafiałyby do domyślnej lokalizacji Cloud Logging (często Global lub US).
- C. Redirect _Default bucket: Jest to technicznie możliwe i często stosowane (stworzenie własnego bucketu i ustawienie sinka), ale opcja D jest uznawana za bardziej "natywną" i systemową metodę zarządzania ustawieniami regionalnymi Cloud Logging w nowoczesnej infrastrukturze GCP.

Wskazówki egzaminacyjne (Tips & Tricks):
- "Keep logging data within [REGION]" = `gcloud logging settings update --storage-location=[REGION]`.
- Pamiętaj: Zmiana lokalizacji składowania logów dotyczy tylko NOWYCH logów od momentu zmiany. Stare logi pozostają w poprzedniej lokalizacji.
- Google Cloud Logging domyślnie przechowuje logi w lokalizacji "Global", co oznacza replikację danych na cały świat. Dla compliance w UE zawsze wymagana jest zmiana na konkretny region.

Kluczowe zagadnienia do powtórzenia:
- Cloud Logging Regionalization (Regionalizacja logów).
- Cloud Audit Logs i ich składowanie.
- Rezydencja danych w chmurze (Data Sovereignty).

Analiza i Podsumowanie Dyskusji (AI)

Analiza i Wyjaśnienie

Sugerowana odpowiedź: D

Głęboka analiza: To pytanie testuje znajomość "Sovereignty" (suwerenności) w chmurze. Google Cloud oferuje dedykowane parametry konfiguracyjne (Settings), które zastępują starsze metody oparte na sinkach. Ustawienie lokalizacji na poziomie projektu (D) jest metodą preferowaną przez audytorów, ponieważ działa jako globalny przełącznik dla całej usługi Logging w danym kontekście.
