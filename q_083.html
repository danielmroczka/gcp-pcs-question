Question 83 / 361

As adoption of the Cloud Data Loss Prevention (Cloud DLP) API grows within your company, you need to optimize usage to reduce cost. Cloud DLP target data is stored in Cloud Storage and BigQuery. The location and region are identified as a suffix in the resource name.
Which cost reduction options should you recommend?

  • A. Set appropriate rowsLimit value on BigQuery data hosted outside the US and set appropriate bytesLimitPerFile value on multiregional Cloud Storage buckets.
  • B. Set appropriate rowsLimit value on BigQuery data hosted outside the US, and minimize transformation units on multiregional Cloud Storage buckets.
  • C. Use rowsLimit and bytesLimitPerFile to sample data and use CloudStorageRegexFileSet to limit scans.
  • D. Use FindingLimits and TimespanContfig to sample data and minimize transformation units.
Show Suggested Answer Hide Answer
Suggested Answer: C

Wyjaśnienie

**Poprawna odpowiedź: C**

**1. Kompleksowe wyjaśnienie poprawnej odpowiedzi:**
Celem jest optymalizacja kosztów korzystania z Cloud DLP (Data Loss Prevention) przy skanowaniu dużych ilości danych w Cloud Storage i BigQuery:
- **Zastosowanie `rowsLimit` (dla BigQuery) oraz `bytesLimitPerFile` (dla Cloud Storage) w celu próbkowania danych (sampling) oraz `CloudStorageRegexFileSet` do ograniczenia skanowanych plików (C):** Skanowanie całych gigabajtowych lub terabajtowych zbiorów danych w poszukiwaniu danych wrażliwych jest bardzo kosztowne. Próbkowanie pozwala na przeskanowanie reprezentatywnej próbki (np. pierwszych 1000 wierszy w BigQuery lub określonej liczby bajtów na plik w GCS). `CloudStorageRegexFileSet` pozwala na zawężenie skanowania tylko do plików o określonych nazwach lub rozszerzeniach (np. pasujących do wyrażenia regularnego), co zapobiega skanowaniu niepotrzebnych plików binarnych lub logów.

**2. Wyjaśnienie niepoprawnych odpowiedzi:**
- **A. rowsLimit i bytesLimitPerFile bez ograniczenia zestawu plików:** Próbkowanie pomaga, ale brak ograniczenia skanowanych plików za pomocą filtrów/wyrażeń regularnych oznacza, że DLP i tak będzie analizować każdy plik w kubełkach, co generuje niepotrzebne koszty transakcyjne i skanowania.
- **B. rowsLimit i minimalizacja jednostek transformacji (transformation units):** Jednostki transformacji dotyczą modyfikacji danych (deidentyfikacji/maskowania). Pytanie dotyczy optymalizacji kosztów samego skanowania i wyszukiwania (inspection), a nie transformacji.
- **D. FindingLimits i TimespanConfig:** `FindingLimits` ogranicza maksymalną liczbę wykrytych trafień raportowanych na dysku, ale nie zmniejsza ilości skanowanych danych (płacisz za ilość przeskanowanych bajtów, a nie za liczbę znalezionych wyników).

**3. Wskazówki i pułapki egzaminacyjne (Tips & Tricks):**
- Najlepszym sposobem na obniżenie kosztów skanowania Cloud DLP jest **próbkowanie (sampling)** poprzez limity rozmiarów/wierszy oraz **filtrowanie plików** (np. regexy w ścieżkach) zamiast skanowania całych zasobów.
- Pamiętaj, że DLP pobiera opłaty za każdy gigabajt przeskanowanych danych.

**4. Reguły wyboru odpowiedzi:**
- Optymalizacja kosztów skanowania DLP -> rowsLimit (BQ), bytesLimitPerFile (GCS) oraz filtrowanie/regex dla zestawów plików.
