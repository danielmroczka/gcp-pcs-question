Question 9 / 361

A company has been running their application on Compute Engine. A bug in the application allowed a malicious user to repeatedly execute a script that results in the Compute Engine instance crashing. Although the bug has been fixed, you want to get notified in case this hack re-occurs. What should you do?

  • A. Create an Alerting Policy in Stackdriver using a Process Health condition, checking that the number of executions of the script remains below the desired threshold. Enable notifications.
  • B. Create an Alerting Policy in Stackdriver using the CPU usage metric. Set the threshold to 80% to be notified when the CPU usage goes above this 80%.
  • C. Log every execution of the script to Stackdriver Logging. Create a User-defined metric in Stackdriver Logging on the logs, and create a Stackdriver Dashboard displaying the metric.
  • D. Log every execution of the script to Stackdriver Logging. Configure BigQuery as a log sink, and create a BigQuery scheduled query to count the number of executions in a specific timeframe.
Show Suggested Answer Hide Answer
Suggested Answer: A

Wyjaśnienie

Potwierdzona odpowiedź: A (Create an Alerting Policy in Stackdriver using a Process Health condition, checking that the number of executions of the script remains below the desired threshold. Enable notifications.)

**Reguła Egzaminacyjna (Exam Rule):**
Jeśli pytanie dotyczy "powiadomienia" (get notified) w czasie rzeczywistym o wystąpieniu specyficznego zdarzenia (np. uruchomienie skryptu), zawsze wybieraj "Alerting Policy". Jeśli dotyczy "monitorowania procesów", szukaj warunku "Process Health".

**Haczyki egzaminacyjne (Exam Traps):**
- Pułapka: "Dashboardy". Służą one do wizualizacji danych, ale nie generują powiadomień (alertów) dla administratorów. 
- Pułapka: "BigQuery / Log Sink". Eksport logów do BigQuery i analiza za pomocą zapytań jest świetna dla analizy śledczej (post-mortem), ale jest procesem zbyt wolnym, aby pełnić rolę natychmiastowego systemu alarmowego.
- Pułapka: "CPU Usage". Jest to metryka zbyt ogólna, która nie potwierdza ataku, a jedynie obciążenie maszyny.

**Głębokie wyjaśnienie techniczne:**
Cloud Monitoring (dawniej Stackdriver) pozwala na definiowanie polityk alertów (Alerting Policies). Warunek "Process Health" pozwala monitorować aktywność konkretnych procesów lub skryptów. Gdy monitorowany parametr (np. liczba uruchomień procesu) przekroczy ustalony próg, system automatycznie wyśle alert do skonfigurowanego kanału powiadomień (np. e-mail, PagerDuty, Slack), co jest kluczowe w scenariuszach security response.

Sugerowana odpowiedź: A

Analiza spornych kwestii (AI): Główna różnica między opcją A i C polega na słowie 'notified'. Dashboardy są świetne do analizy trendów, ale egzamin GCP Security kładzie nacisk na proaktywne bezpieczeństwo, które wymaga mechanizmów alertowania. Process Health jest najbardziej precyzyjnym narzędziem do śledzenia konkretnego wykonania kodu na maszynie VM.
