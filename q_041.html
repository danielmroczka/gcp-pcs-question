Question 41 / 361

Your company runs a website that will store PII on Google Cloud Platform. To comply with data privacy regulations, this data can only be stored for a specific amount of time and must be fully deleted after this specific period. Data that has not yet reached the time period should not be deleted. You want to automate the process of complying with this regulation. What should you do?

  • A. Store the data in a single Persistent Disk, and delete the disk at expiration time.
  • B. Store the data in a single BigQuery table and set the appropriate table expiration time.
  • C. Store the data in a single Cloud Storage bucket and configure the bucket's Time to Live.
  • D. Store the data in a single BigTable table and set an expiration time on the column families.
Show Suggested Answer Hide Answer
Suggested Answer: C

Wyjaśnienie

**Poprawna odpowiedź: C**

**1. Kompleksowe wyjaśnienie poprawnej odpowiedzi:**
Wymaganie polega na przechowywaniu danych osobowych (PII) przez określony czas, a następnie ich pełnym i automatycznym usunięciu po tym okresie (retencja danych/usuwanie po upływie TTL) bez ryzyka usunięcia nowszych danych:
- **Przechowywanie danych w Cloud Storage i skonfigurowanie cyklu życia obiektu (Object Lifecycle Management) na poziomie kubła (C):** Cloud Storage umożliwia zdefiniowanie reguł cyklu życia (np. akcja `Delete` dla obiektów o wieku powyżej określonej liczby dni). Google automatycznie i bezpłatnie dba o to, by obiekty, które przekroczyły wiek (Age), były bezpowrotnie usuwane, podczas gdy nowo utworzone obiekty pozostają bezpieczne. Jest to rozwiązanie w pełni zautomatyzowane, niezawodne i najbardziej opłacalne kosztowo.

**2. Wyjaśnienie niepoprawnych odpowiedzi:**
- **A. Pojedynczy Persistent Disk i usunięcie dysku:** Usunięcie całego dysku spowodowałoby skasowanie *wszystkich* danych jednocześnie, w tym tych, które jeszcze nie przekroczyły limitu czasu przechowywania (narusza to warunek nieusuwania nowszych danych).
- **B. Pojedyncza tabela BigQuery z wygaśnięciem:** BigQuery pozwala na ustawianie wygaśnięcia tabel (Table Expiration), ale usunięcie tabeli powoduje skasowanie wszystkich wierszy jednocześnie. Podobnie jak w A, skasowałoby to nowo dodane dane. Wygaśnięcie partycji mogłoby pomóc, ale Cloud Storage jest domyślnym i bardziej dopasowanym obiektowym systemem retencji plików.
- **D. BigTable z wygaśnięciem rodzin kolumn (TTL):** BigTable obsługuje TTL (Time to Live) na poziomie komórek, ale jest to bardzo droga, wysoce wydajna baza danych NoSQL, nieprzeznaczona do taniej, długoterminowej retencji plików z danymi osobowymi.

**3. Wskazówki i pułapki egzaminacyjne (Tips & Tricks):**
- Jeśli mowa o automatycznej retencji i usuwaniu całych plików/obiektów z danymi osobowymi, najtańszym i najprostszym mechanizmem w GCP jest **Object Lifecycle Management w Cloud Storage**.
- Zapamiętaj: Reguły cyklu życia obiektów w GCS działają na poziomie poszczególnych obiektów, więc każdy plik jest usuwany indywidualnie na podstawie swojej daty utworzenia.

**4. Reguły wyboru odpowiedzi:**
- Retencja plików/obiektów i usuwanie po czasie -> Cloud Storage Lifecycle Management.

**5. Dodatkowe źródła:**
- Object Lifecycle Management: https://cloud.google.com/storage/docs/lifecycle

Analiza i Wyjaśnienie

Sugerowana odpowiedź: C

Analiza spornych kwestii (AI): Niektórzy mogą wskazywać na BigQuery (B), ponieważ również posiada mechanizmy retencji. Jednak w kontekście egzaminacyjnym GCP, jeśli mowa o "bucket", "object lifecycle" i "automatyzacji usuwania danych wrażliwych", Cloud Storage jest odpowiedzią wzorcową ze względu na najniższy koszt i najprostszą implementację (native TTL).

Wyjaśnienie Audytowe

Reguła Egzaminacyjna (Exam Rule):
Pamiętaj, że w egzaminie Professional Cloud Security Engineer kluczowe jest wybieranie rozwiązań najmniej uprzywilejowanych (Principle of Least Privilege), zoptymalizowanych kosztowo i spełniających wymogi compliancy (np. CMEK, Data Loss Prevention).

Haczyki egzaminacyjne (Exam Traps):
- Wybór rozwiązań, które wydają się wygodne, ale nie spełniają wymogów bezpieczeństwa (np. zbyt szerokie uprawnienia IAM).
- Mylenie usług: np. Cloud Armor (WAF) z Cloud IAP (Identity-Aware Proxy).

Głębokie wyjaśnienie techniczne (GCP Professional Cloud Security Engineer):
W każdym pytaniu analizuj warstwy: IAM (dostęp), Encryption (at rest/in transit), Logging/Monitoring (Audit Logs, Cloud Logging, Security Command Center) oraz Networking (VPC Service Controls, Firewall Rules). GCP kładzie duży nacisk na współdzieloną odpowiedzialność (Shared Responsibility Model) - klient odpowiada za konfigurację zabezpieczeń wewnątrz usług chmurowych.
