Question 149 / 361

You want to update your existing VPC Service Controls perimeter with a new access level. You need to avoid breaking the existing perimeter with this change, and ensure the least disruptions to users while minimizing overhead. What should you do?

  • A. Create an exact replica of your existing perimeter. Add your new access level to the replica. Update the original perimeter after the access level has been vetted.
  • B. Update your perimeter with a new access level that never matches. Update the new access level to match your desired state one condition at a time to avoid being overly permissive.
  • C. Enable the dry run mode on your perimeter. Add your new access level to the perimeter configuration. Update the perimeter configuration after the access level has been vetted.
  • D. Enable the dry run mode on your perimeter. Add your new access level to the perimeter dry run configuration. Update the perimeter configuration after the access level has been vetted.
Show Suggested Answer Hide Answer
Suggested Answer: D

Wyjaśnienie

Potwierdzona odpowiedź: D (Enable the dry run mode on your perimeter. Add your new access level to the perimeter dry run configuration. Update the perimeter configuration after the access level has been vetted).

Wyjaśnienie:
VPC Service Controls oferuje tryb "Dry Run", który pozwala administratorom na testowanie zmian w konfiguracji perymetru (takich jak dodanie nowego poziomu dostępu - Access Level) bez faktycznego blokowania ruchu. Logi generowane w tym trybie pokazują, jakie żądania zostałyby zablokowane lub dopuszczone, co pozwala na bezpieczną walidację zmian przed ich wdrożeniem ("enforce"). Jest to najlepsza praktyka zapobiegająca przerwom w działaniu usług produkcyjnych.

Dlaczego pozostałe są błędne:
- A. Tworzenie repliki: Jest to proces ręczny, czasochłonny i podatny na błędy. Google Cloud oferuje natywny tryb Dry Run właśnie po to, by uniknąć takich obejść.
- B. Dodawanie warunków jeden po drugim: Jest ryzykowne i może prowadzić do tymczasowych przerw w dostępie lub luk w bezpieczeństwie na żywym systemie.
- C. Dodanie do głównej konfiguracji w trybie Dry Run: Ta opcja sugeruje dodanie zmian do sekcji aktywnej (enforced) przy włączonym globalnie trybie Dry Run, co jest mniej precyzyjne niż użycie dedykowanej sekcji "dry run configuration", która pozwala na współistnienie starej i nowej (testowej) konfiguracji równolegle.

Wskazówki egzaminacyjne (Tips & Tricks):
- "Update VPC SC" + "Least disruptions" -> Dry Run.
- Pamiętaj, że logi Dry Run trafiają do Cloud Logging i można je filtrować, aby zobaczyć potencjalne naruszenia.
- Access Context Manager służy do definiowania Access Levels używanych w VPC SC.

Kluczowe zagadnienia do powtórzenia:
- Tryby pracy VPC Service Controls (Enforced vs Dry Run).
- Access Context Manager i Access Levels.
- Analiza logów VPC SC w Logs Explorer.
