Question 35 / 361

You are a member of the security team at an organization. Your team has a single GCP project with credit card payment processing systems alongside web applications and data processing systems. You want to reduce the scope of systems subject to PCI audit standards.
What should you do?

  • A. Use multi-factor authentication for admin access to the web application.
  • B. Use only applications certified compliant with PA-DSS.
  • C. Move the cardholder data environment into a separate GCP project.
  • D. Use VPN for all connections between your office and cloud environments.
Show Suggested Answer Hide Answer
Suggested Answer: C

Wyjaśnienie

Potwierdzona odpowiedź: C (Move the cardholder data environment into a separate GCP project.)

Wyjaśnienie:
Podstawową strategią ograniczania kosztów i złożoności audytu PCI DSS jest redukcja jego zakresu (scope reduction). W modelu chmurowym najlepszym sposobem na osiągnięcie tego celu jest logiczna i fizyczna izolacja środowiska przetwarzającego dane kart płatniczych (CDE - Cardholder Data Environment). Przeniesienie CDE do osobnego projektu Google Cloud tworzy silną barierę izolacyjną. Dzięki temu audytor może skupić się wyłącznie na tym jednym projekcie, a pozostałe systemy organizacji (nieprzetwarzające danych kart) mogą zostać wyłączone z rygorystycznego i kosztownego procesu audytu.

Dlaczego pozostałe są błędne:
A. Use multi-factor authentication for admin access to the web application: Chociaż MFA jest wymagane przez PCI DSS (wymóg 8.3), jego włączenie nie zmniejsza zakresu (scope) audytu. Audytor nadal musiałby badać wszystkie systemy w projekcie.
B. Use only applications certified compliant with PA-DSS: PA-DSS (Payment Application Data Security Standard) dotyczy oprogramowania firm trzecich. Używanie certyfikowanych aplikacji pomaga w zachowaniu zgodności, ale nie izoluje systemów i nie zmniejsza zakresu audytu infrastruktury.
D. Use VPN for all connections between your office and cloud environments: VPN zapewnia bezpieczny kanał komunikacji (szyfrowanie w tranzycie), ale nie stanowi mechanizmu separacji logicznej, który pozwoliłby na wyłączenie innych systemów w tym samym projekcie z zakresu audytu PCI.

Wskazówki egzaminacyjne (Tips & Tricks):
- Słowo klucz: "Reduce the scope" w kontekście PCI DSS prawie zawsze oznacza "izolację" lub "segmentację".
- W Google Cloud "Project" jest podstawową granicą izolacji (Trust Boundary).
- Pamiętaj, że PCI DSS dotyczy wszystkiego, co ma kontakt z danymi posiadaczy kart (PAN - Primary Account Number).

Kluczowe zagadnienia do powtórzenia:
- PCI DSS Scope Reduction techniques
- Shared Responsibility Model for PCI in GCP
- Network segmentation and IAM isolation

Analiza i Podsumowanie Dyskusji (AI)

Analiza i Wyjaśnienie

Sugerowana odpowiedź: C

Analiza spornych kwestii (AI): Segmentacja to jedyny skuteczny sposób, by audytor mógł przyjąć "ograniczony zakres". W GCP projekt jest najsilniejszą granicą administracyjną i sieciową, co czyni go naturalnym kontenerem dla CDE.

Wyjaśnienie Audytowe

Reguła Egzaminacyjna (Exam Rule):
Pamiętaj, że w egzaminie Professional Cloud Security Engineer kluczowe jest wybieranie rozwiązań najmniej uprzywilejowanych (Principle of Least Privilege), zoptymalizowanych kosztowo i spełniających wymogi compliancy (np. CMEK, Data Loss Prevention).

Haczyki egzaminacyjne (Exam Traps):
- Wybór rozwiązań, które wydają się wygodne, ale nie spełniają wymogów bezpieczeństwa (np. zbyt szerokie uprawnienia IAM).
- Mylenie usług: np. Cloud Armor (WAF) z Cloud IAP (Identity-Aware Proxy).

Głębokie wyjaśnienie techniczne (GCP Professional Cloud Security Engineer):
W każdym pytaniu analizuj warstwy: IAM (dostęp), Encryption (at rest/in transit), Logging/Monitoring (Audit Logs, Cloud Logging, Security Command Center) oraz Networking (VPC Service Controls, Firewall Rules). GCP kładzie duży nacisk na współdzieloną odpowiedzialność (Shared Responsibility Model) - klient odpowiada za konfigurację zabezpieczeń wewnątrz usług chmurowych.
