Question 325 / 361

Your organization manages a critical web application that serves international customers on Google Cloud. An increase in malicious traffic targeting this application has strained resources and caused periods of downtime. You need to design security measures to increase the application's resilience against web attacks, enhance perimeter protection, and provide access control. What should you do?

  • A. Employ network load balancing for traffic distribution. Update Identity-Aware Proxy (IAP) policies to allow only administrative access. Implement custom firewall rules on all external IP addresses.
  • B. Set up firewall rules on Compute Engine instances within the application's environment. Rely on load balancers for threat detection. Increase instance resources to cope with attack volume.
  • C. Configure firewall rules to block traffic from known malicious IP ranges. Set up Google Cloud Armor and implement Identity-Aware Proxy (IAP) for granular access control.
  • D. Add firewall rules that restrict all internal IP ranges. Establish Cloud DNS security policies. Disable external IP addresses to reduce the attack surface. Create user groups for access control.
Show Suggested Answer Hide Answer
Suggested Answer: C

Wyjaśnienie

Poprawna odpowiedź: C (Configure firewall rules to block traffic from known malicious IP ranges. Set up Google Cloud Armor and implement Identity-Aware Proxy (IAP) for granular access control.)

Dlaczego ta odpowiedź jest poprawna:
- Google Cloud Armor: To dedykowane narzędzie do ochrony przed atakami webowymi (WAF), które świetnie radzi sobie z atakami DDoS na poziomie aplikacji i posiada listę znanych zagrożeń (malicious IPs).
- Identity-Aware Proxy (IAP): Zapewnia "granular access control" (dostęp per użytkownik/grupa, a nie tylko per sieć), co jest wymogiem bezpieczeństwa Zero Trust.
- Firewall rules: Pomagają w blokowaniu niechcianego ruchu na poziomie infrastruktury (sieci).

Analiza niepoprawnych odpowiedzi:
- A. Custom firewall rules on external IPs: Ręczne zarządzanie listą IP jest nieefektywne i uciążliwe.
- B. Rely on load balancers for threat detection: Load Balancer sam w sobie nie jest WAF-em (wymaga Cloud Armor). Samo zwiększanie zasobów to skalowanie, a nie ochrona.
- D. Disable external IPs: Jeśli aplikacja służy "international customers", musi mieć publiczny dostęp. Wyłączenie external IP uniemożliwi dostęp klientom.

Wskazówki i triki (Tips & Tricks):
- "Web attacks" + "Perimeter protection" + "Access control" = Cloud Armor + IAP.
- Pamiętaj: Cloud Armor chroni aplikację, IAP chroni dostęp do niej.

Praktyczne informacje na egzamin:
- Zapamiętaj: Google Cloud Armor oferuje gotowe reguły WAF (np. przeciwko OWASP Top 10).

Dokumentacja i linki:
- Cloud Armor security policies

Wskazówki egzaminacyjne (Tips & Tricks)

Reguła Egzaminacyjna (Exam Rule): 
W pytaniach typu 'Security in GCP', zawsze priorytetyzuj rozwiązania natywne (SCC, Cloud KMS, Secret Manager, VPC SC) nad rozwiązaniami typu 'third-party' lub 'self-managed', chyba że scenariusz wymaga specyficznej integracji hybrydowej.

Haczyki egzaminacyjne (Exam Traps):
- Pułapka 'Least Privilege': Egzamin często podpowiada role o szerokim zakresie (np. 'Editor' lub 'Owner') – zawsze odrzucaj je na rzecz ról predefiniowanych o najmniejszym zakresie uprawnień.
- Pułapka 'Logging vs Monitoring': Pamiętaj: Audit Logs służą do badania aktywności (Who/What/When), a Monitoring do zbierania metryk wydajnościowych.

Głębokie wyjaśnienie techniczne:
Każda architektura bezpieczeństwa w GCP powinna być projektowana w oparciu o 'Security by Default'. Oznacza to m.in. szyfrowanie w spoczynku (domyślne), tożsamość opartą na rolach (IAM) oraz pełną widoczność zapewnianą przez scentralizowane logowanie (Cloud Logging/SCC).

Kluczowe zagadnienia

Sugerowana odpowiedź: C

Analiza strategiczna: Pytanie o standardowe zestawienie usług bezpieczeństwa brzegowego GCP. Cloud Armor zapewnia ochronę WAF/DDoS, a IAP pozwala na implementację modelu Zero Trust (dostęp oparty na tożsamości, a nie na sieci).
