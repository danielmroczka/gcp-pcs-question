Question 44 / 361

Your company is using GSuite and has developed an application meant for internal usage on Google App Engine. You need to make sure that an external user cannot gain access to the application even when an employee's password has been compromised. What should you do?

  • A. Enforce 2-factor authentication in GSuite for all users.
  • B. Configure Cloud Identity-Aware Proxy for the App Engine Application.
  • C. Provision user passwords using GSuite Password Sync.
  • D. Configure Cloud VPN between your private network and GCP.
Show Suggested Answer Hide Answer
Suggested Answer: A

Wyjaśnienie

**Poprawna odpowiedź: A**

**1. Kompleksowe wyjaśnienie poprawnej odpowiedzi:**
Celem jest uniemożliwienie zewnętrznemu atakującemu dostępu do wewnętrznej aplikacji App Engine, nawet w przypadku przejęcia/skompromitowania hasła pracownika:
- **Wymuszenie dwuskładnikowego uwierzytelniania (2-Factor Authentication / 2SV) w G Suite dla wszystkich użytkowników (A):** W modelu tożsamości opartym na kontach Google (G Suite/Workspace), autoryzacja do aplikacji App Engine przechodzi przez ekrany logowania Google. Wdrożenie 2FA (MFA) sprawia, że samo skradzione hasło jest bezużyteczne dla napastnika – do zalogowania wymagany jest drugi składnik (np. klucz bezpieczeństwa U2F, aplikacja uwierzytelniająca lub kod SMS).

**2. Wyjaśnienie niepoprawnych odpowiedzi:**
- **B. Skonfigurowanie Cloud IAP:** IAP jest świetnym narzędziem do kontroli dostępu, ale IAP opiera się na uwierzytelnieniu konta Google. Jeśli hasło użytkownika wyciekło, a na koncie nie ma włączonego MFA, atakujący zaloguje się do konta Google i bez przeszkód ominie bramkę IAP.
- **C. G Suite Password Sync (GSPS):** GSPS synchronizuje hasła z Active Directory do Google Workspace, ale nie dodaje żadnego dodatkowego składnika uwierzytelniania chroniącego przed skompromitowanym hasłem.
- **D. Skonfigurowanie Cloud VPN:** VPN chroni na poziomie sieciowym, ale nie uniemożliwi zalogowania się z przejętymi poświadczeniami bezpośrednio przez przeglądarkę z dowolnego urządzenia podłączonego do internetu (App Engine ma publiczne punkty końcowe).

**3. Wskazówki i pułapki egzaminacyjne (Tips & Tricks):**
- Pułapka: Wielu inżynierów wybiera IAP (B), ponieważ jest to usługa bezpieczeństwa sieciowego w GCP. IAP kontroluje *kto* ma dostęp, ale to **MFA (Multi-Factor Authentication)** zapewnia ochronę tożsamości w przypadku przejęcia hasła.
- Pytanie wyraźnie zaznacza: "even when an employee's password has been compromised" -> Odpowiedzią musi być mechanizm zabezpieczający sam proces logowania (MFA/2FA).

**4. Reguły wyboru odpowiedzi:**
- Ochrona przed skradzionym hasłem -> Dwuetapowa weryfikacja / 2-Factor Authentication.

**5. Dodatkowe źródła:**
- Google Workspace 2-Step Verification: https://support.google.com/a/answer/175197

Analiza i Podsumowanie Dyskusji (AI)

Analiza i Wyjaśnienie

Sugerowana odpowiedź: A

Analiza spornych kwestii (AI): Wiele osób skłania się ku odpowiedzi B (IAP), ponieważ jest to "nowoczesne" narzędzie GCP. Jednak IAP samo w sobie nie chroni przed skradzionym hasłem, jeśli proces logowania do konta Google jest słaby. Dopiero wymuszenie MFA (opcja A) tworzy barierę, której samo hasło nie jest w stanie pokonać. W realnych scenariuszach stosuje się oba te rozwiązania jednocześnie.

Wyjaśnienie Audytowe

Reguła Egzaminacyjna (Exam Rule):
Pamiętaj, że w egzaminie Professional Cloud Security Engineer kluczowe jest wybieranie rozwiązań najmniej uprzywilejowanych (Principle of Least Privilege), zoptymalizowanych kosztowo i spełniających wymogi compliancy (np. CMEK, Data Loss Prevention).

Haczyki egzaminacyjne (Exam Traps):
- Wybór rozwiązań, które wydają się wygodne, ale nie spełniają wymogów bezpieczeństwa (np. zbyt szerokie uprawnienia IAM).
- Mylenie usług: np. Cloud Armor (WAF) z Cloud IAP (Identity-Aware Proxy).

Głębokie wyjaśnienie techniczne (GCP Professional Cloud Security Engineer):
W każdym pytaniu analizuj warstwy: IAM (dostęp), Encryption (at rest/in transit), Logging/Monitoring (Audit Logs, Cloud Logging, Security Command Center) oraz Networking (VPC Service Controls, Firewall Rules). GCP kładzie duży nacisk na współdzieloną odpowiedzialność (Shared Responsibility Model) - klient odpowiada za konfigurację zabezpieczeń wewnątrz usług chmurowych.
