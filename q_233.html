Question 233 / 361

You manage a fleet of virtual machines (VMs) in your organization. You have encountered issues with lack of patching in many VMs. You need to automate regular patching in your VMs and view the patch management data across multiple projects. What should you do? (Choose two.)

  • A. View patch management data in VM Manager by using OS patch management.
  • B. View patch management data in Artifact Registry.
  • C. View patch management data in a Security Command Center dashboard.
  • D. Deploy patches with Security Command Center by using Rapid Vulnerability Detection.
  • E. Deploy patches with VM Manager by using OS patch management.
Show Suggested Answer Hide Answer
Suggested Answer: AE

Wyjaśnienie

1. Prawidłowa odpowiedź lub odpowiedzi:
A. View patch management data in VM Manager by using OS patch management.
E. Deploy patches with VM Manager by using OS patch management.

2. Kompleksowe wyjaśnienie dlaczego dana odpowiedź jest prawidłowa (Analiza):
Odpowiedzi A i E są prawidłowe, ponieważ VM Manager (część pakietu OS Configuration Management) jest oficjalną, natywną usługą Google Cloud zaprojektowaną do automatyzacji aktualizacji systemów operacyjnych i zarządzania poprawkami (patch management) na maszynach wirtualnych Compute Engine w skali wielu projektów.

Komponenty rozwiązania:
a. **Automatyzacja wdrażania poprawek (E):** Usługa OS Patch Management w VM Manager pozwala na definiowanie zadań wdrażania poprawek (patch jobs) na grupach maszyn wirtualnych. Zadania te można zaplanować, określić okna serwisowe (maintenance windows) oraz zasady restartu maszyn.
b. **Wizualizacja stanu poprawek (A):** VM Manager oferuje centralny pulpit nawigacyjny w konsoli GCP, który zbiera i wyświetla stan zgodności z poprawkami (compliance data) dla wszystkich maszyn wirtualnych w wielu projektach, ułatwiając audyt bezpieczeństwa.

3. Wyjaśnienie z osobna każdej niepoprawnej odpowiedzi:
B. View patch management data in Artifact Registry.
   * Dlaczego nieprawidłowa: Artifact Registry służy do przechowywania i zarządzania pakietami oprogramowania (np. Docker images, Maven, npm artifacts) oraz obrazami maszyn. Nie monitoruje ani nie wdraża poprawek bezpośrednio w systemach operacyjnych uruchomionych maszyn VM.
C. View patch management data in a Security Command Center dashboard.
   * Dlaczego nieprawidłowa: Security Command Center Premium integruje się z wieloma usługami i może zgłaszać luki w zabezpieczeniach (vulnerabilities), ale nie jest głównym panelem do natywnego zarządzania operacyjnego i monitorowania szczegółowych wdrożeń OS patch management z VM Managera.
D. Deploy patches with Security Command Center by using Rapid Vulnerability Detection.
   * Dlaczego nieprawidłowa: Rapid Vulnerability Detection w SCC służy do wykrywania podatności sieciowych (np. słabe hasła, znane exploity portów). SCC nie posiada funkcji aktywnego instalowania poprawek (patching) wewnątrz systemów operacyjnych maszyn VM.

4. Wskazówki, hinty, tips and tricks:
* Narzędziem do patchowania systemów operacyjnych (OS patching) maszyn Compute Engine w GCP jest **VM Manager** (OS patch management).
* VM Manager wymaga włączenia odpowiedniego agenta (OS Config agent) na instancjach VM.

5. Reguły wyboru odpowiedzi (Słowa kluczowe):
* Automate regular patching / patch management data -> VM Manager / OS patch management.
