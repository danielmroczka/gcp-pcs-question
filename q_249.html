Question 249 / 361

Your organization has an operational image classification model running on a managed AI service on Google Cloud. You are in a configuration review with stakeholders and must describe the security responsibilities for the image classification model. What should you do?

  • A. Explain that using platform-as-a-service (PaaS) transfers security concerns to Google. Describe the need for strict API usage limits to protect against unexpected usage and billing spikes.
  • B. Explain the security aspects of the code that transforms user-uploaded images using Google's service. Define Cloud IAM for fine-grained access control within the development team.
  • C. Explain Google's shared responsibility model. Focus the configuration review on Identity and Access Management (IAM) permissions, secure data upload/download procedures, and monitoring logs for any potential malicious activity.
  • D. Explain the development of custom network firewalls around the image classification service for deep intrusion detection and prevention. Describe vulnerability scanning tools for known vulnerabilities.
Show Suggested Answer Hide Answer
Suggested Answer: C

Wyjaśnienie

1. Prawidłowa odpowiedź lub odpowiedzi:
C. Explain Google's shared responsibility model. Focus the configuration review on Identity and Access Management (IAM) permissions, secure data upload/download procedures, and monitoring logs for any potential malicious activity.

2. Kompleksowe wyjaśnienie dlaczego dana odpowiedź jest prawidłowa (Analiza):
Odpowiedź C jest prawidłowa, ponieważ model współdzielonej odpowiedzialności (Shared Responsibility Model) w chmurze precyzyjnie definiuje granice bezpieczeństwa między dostawcą chmury (Google) a klientem, zwłaszcza w usługach zarządzanych typu PaaS/SaaS (takich jak managed AI/Vertex AI).

Podział odpowiedzialności w usługach zarządzanych AI:
a. **Odpowiedzialność Google (Security OF the Cloud):** Google odpowiada za bezpieczeństwo infrastruktury fizycznej, sieci szkieletowej, hypervisora, kodu samej usługi AI oraz zabezpieczenie przed podatnościami platformy.
b. **Odpowiedzialność Klienta (Security IN the Cloud):** Klient odpowiada za poprawne skonfigurowanie dostępu do usługi (uprawnienia IAM – kto może wywoływać model lub modyfikować konfigurację), bezpieczeństwo przesyłanych danych (szyfrowanie CMEK, bezpieczne przesyłanie do Cloud Storage), oraz monitorowanie logów użycia (Cloud Audit Logs) w celu wykrycia nadużyć. Opcja C skupia się dokładnie na tych elementach, które leżą w gestii klienta.

3. Wyjaśnienie z osobna każdej niepoprawnej odpowiedzi:
A. Explain that using platform-as-a-service (PaaS) transfers security concerns to Google...
   * Dlaczego nieprawidłowa: Korzystanie z PaaS nie zwalnia klienta ze wszystkich obaw o bezpieczeństwo (security concerns). Klient nadal ponosi pełną odpowiedzialność za dostęp (IAM) i ochronę przesyłanych danych. Skupienie się wyłącznie na limitach billingowych i API ignoruje kluczowe aspekty ochrony danych przed nieautoryzowanym dostępem.
B. Explain the security aspects of the code that transforms user-uploaded images... Define Cloud IAM...
   * Dlaczego nieprawidłowa: Skupienie się wyłącznie na kodzie transformacji i zespole deweloperskim jest zbyt wąskie. Ignoruje ogólne zasady modelu współdzielonej odpowiedzialności oraz procedury bezpiecznego przesyłania danych (data upload/download), które są kluczowe dla interesariuszy biznesowych i operacyjnych.
D. Explain the development of custom network firewalls... Describe vulnerability scanning...
   * Dlaczego nieprawidłowa: Usługi zarządzane AI (PaaS) są utrzymywane przez Google i klient nie ma technicznej możliwości wdrażania "własnych zapor sieciowych" (custom network firewalls) wokół silnika AI ani skanowania kodu samej usługi zarządzanej pod kątem podatności systemowych – te zadania leżą w 100% po stronie Google.

4. Wskazówki, hinty, tips and tricks:
* Pamiętaj o modelu współdzielonej odpowiedzialności (Shared Responsibility Model):
  - IaaS (np. Compute Engine) -> klient zarządza systemem operacyjnym, poprawkami, aplikacją i zaporą.
  - PaaS/SaaS (np. Vertex AI, Cloud Run) -> Google zarządza infrastrukturą i OS, klient odpowiada za konfigurację IAM, dane i logi.
* Na egzaminie zawsze odrzucaj opcje sugerujące, że klient musi patchować systemy operacyjne lub budować firewalle dla usług w pełni zarządzanych przez Google.

5. Reguły wyboru odpowiedzi (Słowa kluczowe):
* Managed AI service security responsibilities -> Shared responsibility model + IAM + secure data procedures.

Wskazówki egzaminacyjne (Tips & Tricks)

Reguła Egzaminacyjna (Exam Rule): 
Jeśli scenariusz dotyczy zabezpieczania zasobów chmurowych (GCP), zawsze wybieraj rozwiązanie typu Managed (SCC, Secret Manager, Cloud KMS), a unikaj rozwiązań self-managed, chyba że pytanie wyraźnie wymaga dostosowania niskopoziomowego.

Haczyki egzaminacyjne (Exam Traps):
- Pułapka IAM: Pytania o uprawnienia często sugerują 'Project Owner' – zawsze szukaj 'Least Privilege' (np. 'Role: Secret Manager Secret Accessor').
- Pułapka Sieciowa: Często mylone są VPC Peering (wydajność) oraz VPN (szyfrowanie/on-premise).

Głębokie wyjaśnienie techniczne:
Rozwiązanie bazuje na GCP Shared Responsibility Model. Google zarządza bezpieczeństwem infrastruktury (Physical, Network, Host), podczas gdy administrator zarządza tożsamością (IAM), danymi (Encryption, Cloud KMS) i regułami dostępu (VPC Firewall).

Analiza i Podsumowanie (AI)

Kluczowe zagadnienia

Sugerowana odpowiedź: C

Analiza strategiczna: To pytanie testuje Twoją świadomość granic odpowiedzialności. Wiele incydentów wynika z błędnego założenia, że "usługa w chmurze jest bezpieczna sama z siebie". Twoim zadaniem jako inżyniera bezpieczeństwa jest monitorowanie "granic" (IAM) i "wartości" (danych), niezależnie od tego, jak zarządzana jest platforma.
