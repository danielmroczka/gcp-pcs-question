Question 249 / 361

Your organization has an operational image classification model running on a managed AI service on Google Cloud. You are in a configuration review with stakeholders and must describe the security responsibilities for the image classification model. What should you do?

  • A. Explain that using platform-as-a-service (PaaS) transfers security concerns to Google. Describe the need for strict API usage limits to protect against unexpected usage and billing spikes.
  • B. Explain the security aspects of the code that transforms user-uploaded images using Google's service. Define Cloud IAM for fine-grained access control within the development team.
  • C. Explain Google's shared responsibility model. Focus the configuration review on Identity and Access Management (IAM) permissions, secure data upload/download procedures, and monitoring logs for any potential malicious activity.
  • D. Explain the development of custom network firewalls around the image classification service for deep intrusion detection and prevention. Describe vulnerability scanning tools for known vulnerabilities.
Show Suggested Answer Hide Answer
Suggested Answer: C

Wyjaśnienie

Poprawna odpowiedź: C (Explain Google's shared responsibility model. Focus the configuration review on Identity and Access Management (IAM) permissions, secure data upload/download procedures, and monitoring logs for any potential malicious activity.)

Dlaczego ta odpowiedź jest poprawna:
- Model Współdzielonej Odpowiedzialności (Shared Responsibility Model): To fundamentalna koncepcja chmurowa. Google odpowiada za bezpieczeństwo "chmury" (infrastruktura, sprzęt, hypervisor), natomiast klient odpowiada za bezpieczeństwo "w chmurze" (dane, IAM, konfiguracja aplikacji, logi).
- Konfiguracja review: Przegląd bezpieczeństwa usługi zarządzanej (PaaS/SaaS) powinien skupiać się na tym, na co klient ma realny wpływ:
    - IAM (kto ma dostęp?)
    - Secure procedures (jak dane są przesyłane?)
    - Monitoring (czy widzimy, że coś złego się dzieje?)

Analiza niepoprawnych odpowiedzi:
- A. PaaS transfers security concerns: To błędne założenie. PaaS zdejmuje z klienta obowiązek zarządzania łatami systemu operacyjnego czy sprzętem, ale NIE zdejmuje odpowiedzialności za bezpieczeństwo danych, konfigurację dostępu (IAM) czy monitorowanie zagrożeń.
- B. Security aspects of code: Choć bezpieczny kod jest ważny, to przegląd konfiguracji powinien skupiać się na polityce dostępu (IAM) i monitoringu, a nie tylko na samym kodzie.
- D. Deep intrusion detection at firewall level: Usługi zarządzane (jak AI service) zazwyczaj nie pozwalają na "tworzenie custom firewalls" wokół siebie. To nie jest poziom odpowiedzialności klienta w PaaS.

Wskazówki i triki (Tips & Tricks):
- "PaaS" / "Managed service" + "Security review" = IAM + Data protection + Monitoring.
- Nigdy nie zakładaj, że PaaS oznacza "Google dba o wszystko". Klient zawsze odpowiada za IAM i dane!

Praktyczne informacje na egzamin:
- Zapamiętaj: IAM, Monitoring i Data Encryption to zawsze "Twoja" działka w GCP.
- Egzamin Professional Security Engineer sprawdza, czy rozumiesz granicę między tym, co robi Google, a co musisz zrobić Ty.

Sugerowana odpowiedź: C

Analiza strategiczna: To pytanie testuje Twoją świadomość granic odpowiedzialności. Wiele incydentów wynika z błędnego założenia, że "usługa w chmurze jest bezpieczna sama z siebie". Twoim zadaniem jako inżyniera bezpieczeństwa jest monitorowanie "granic" (IAM) i "wartości" (danych), niezależnie od tego, jak zarządzana jest platforma.
