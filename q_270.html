Question 270 / 361

You work for a healthcare provider that is expanding into the cloud to store and process sensitive patient data. You must ensure the chosen Google Cloud configuration meets these strict regulatory requirements: • Data must reside within specific geographic regions. • Certain administrative actions on patient data require explicit approval from designated compliance officers. • Access to patient data must be auditable. What should you do?

  • A. Select a standard Google Cloud region. Restrict access to patient data based on user location and job function by using Access Context Manager. Enable both Cloud Audit Logging and Access Transparency.
  • B. Deploy an Assured Workloads environment in an approved region. Configure Access Approval for sensitive operations on patient data. Enable both Cloud Audit Logs and Access Transparency.
  • C. Deploy an Assured Workloads environment in multiple regions for redundancy. Utilize custom IAM roles with granular permissions. Isolate network-level data by using VPC Service Controls.
  • D. Select multiple standard Google Cloud regions for high availability. Implement Access Control Lists (ACLs) on individual storage objects containing patient data. Enable Cloud Audit Logs.
Show Suggested Answer
Suggested Answer: B

Wyjaśnienie

1. Prawidłowa odpowiedź lub odpowiedzi:
B. Deploy an Assured Workloads environment in an approved region. Configure Access Approval for sensitive operations on patient data. Enable both Cloud Audit Logs and Access Transparency.

2. Kompleksowe wyjaśnienie dlaczego dana odpowiedź jest prawidłowa (Analiza):
Odpowiedź B jest prawidłowa, ponieważ łączy cztery kluczowe technologie Google Cloud wymagane do spełnienia rygorystycznych wymogów prawnych (takich jak HIPAA czy GDPR) w sektorze medycznym.

Spełnienie wymagań krok po kroku:
a. **Rezydentność danych (Data Residency):** Assured Workloads (AW) automatycznie wymusza na folderze ograniczenia lokalizacji geograficznej (np. tylko regiony europejskie), gwarantując, że dane medyczne fizycznie nie opuszczą dozwolonych obszarów.
b. **Zatwierdzanie akcji administracyjnych:** Usługa Access Approval (AA) wymaga, aby każda próba dostępu personelu Google do danych pacjenta (np. podczas rozwiązywania problemów technicznych) została zatwierdzona przez wyznaczonego oficera ds. zgodności (compliance officer) w Twojej firmie.
c. **Audytowalność dostępu:** Cloud Audit Logs rejestruje wszystkie operacje użytkowników wewnątrz projektu, natomiast Access Transparency (AT) dostarcza logi z działań i powodów dostępu inżynierów samego Google, co zapewnia pełną rozliczalność i przejrzystość audytową.

3. Wyjaśnienie z osobna każdej niepoprawnej odpowiedzi:
A. Select a standard Google Cloud region... restrict access... using Access Context Manager...
   * Dlaczego nieprawidłowa: Standardowy region bez Assured Workloads nie gwarantuje zgodności z wymogami suwerenności personelu wsparcia. Sam Access Context Manager kontroluje dostęp użytkowników firmowych, ale nie dostarcza mechanizmu zatwierdzania akcji administracyjnych personelu wsparcia technicznego Google (brak Access Approval).
C. Deploy an Assured Workloads environment in multiple regions... Isolate network-level data by using VPC Service Controls.
   * Dlaczego nieprawidłowa: Choć AW i VPC SC są bardzo bezpieczne, ta opcja pomija kluczowe wymaganie dotyczące konieczności zatwierdzania akcji administracyjnych (Access Approval) oraz audytowalności dostępu inżynierów wsparcia chmury (Access Transparency).
D. Select multiple standard Google Cloud regions... Implement Access Control Lists (ACLs) on individual storage objects...
   * Dlaczego nieprawidłowa: Używanie list ACL na obiektach Cloud Storage jest przestarzałą praktyką (zaleca się Uniform IAM). Ta opcja całkowicie ignoruje wymogi dotyczące zatwierdzania działań administracyjnych oraz rezydentności wsparcia technicznego.

4. Wskazówki, hinty, tips and tricks:
* Spełnienie surowych wymogów regulacyjnych (rezydentność, zatwierdzanie dostępu Google, logowanie) -> Złote trio: **Assured Workloads** + **Access Approval** + **Access Transparency**.
* Access Transparency rejestruje działania Google, Access Approval pozwala na ich akceptację/odrzucenie przed wykonaniem.

5. Reguły wyboru odpowiedzi (Słowa kluczowe):
* Data reside in region + administrative actions require approval + auditable -> Assured Workloads + Access Approval + Access Transparency.
