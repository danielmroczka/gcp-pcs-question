Question 294 / 361

Your organization has an internet-facing application behind a load balancer. Your regulators require end-to-end encryption of user login credentials. You must implement this requirement. What should you do?

  • A. Generate a symmetric key with Cloud KMS. Encrypt client-side user credentials by using the symmetric key.
  • B. Concatenate the credential with a timestamp. Submit the timestamp and hashed value of credentials to the network.
  • C. Deploy the TLS certificate at Google Cloud Global HTTPs Load Balancer, and submit the user credentials through HTTPs.
  • D. Generate an asymmetric key with Cloud KMS. Encrypt client-side user credentials using the public key.
Show Suggested Answer Hide Answer
Suggested Answer: C

Wyjaśnienie

Potwierdzona odpowiedź: C (Deploy the TLS certificate at Google Cloud Global HTTPs Load Balancer, and submit the user credentials through HTTPs.)

Wyjaśnienie:
- HTTPS (TLS): To branżowy standard szyfrowania komunikacji sieciowej. Zapewnia ochronę poufności (encryption) oraz integralności danych przesyłanych między klientem a load balancerem. W połączeniu z poprawnie skonfigurowanym TLS między load balancerem a backendem (jeśli wymagane), zapewnia pełną ochronę typu "end-to-end".

Dlaczego pozostałe odpowiedzi są niepoprawne:
- A, D: Szyfrowanie danych po stronie klienta (przeglądarki) przy użyciu kluczy KMS jest technicznie trudne, niepraktyczne i w zupełności zbędne, gdy HTTPS (TLS) rozwiązuje problem szyfrowania kanału transmisyjnego.
- B: Hashing (haszowanie) nie jest szyfrowaniem. Samo haszowanie danych (np. SHA-256) bez kanału szyfrowanego pozwala na atak typu "Replay Attack" (przejęcie zahaszowanego hasła i jego odtworzenie).

Wskazówki i triki (Tips & Tricks):
- "End-to-end encryption" + "User credentials" + "Web application" = HTTPS/TLS.
- Zapamiętaj: Zawsze szukaj najprostszego i standardowego rozwiązania – w tym przypadku jest to HTTPS.

Praktyczne informacje na egzamin:
- Zapamiętaj: Load Balancer w GCP posiada natywną obsługę certyfikatów SSL/TLS.

Wskazówki egzaminacyjne (Tips & Tricks)

Reguła Egzaminacyjna (Exam Rule): 
W pytaniach typu 'Security in GCP', zawsze priorytetyzuj rozwiązania natywne (SCC, Cloud KMS, Secret Manager, VPC SC) nad rozwiązaniami typu 'third-party' lub 'self-managed', chyba że scenariusz wymaga specyficznej integracji hybrydowej.

Haczyki egzaminacyjne (Exam Traps):
- Pułapka 'Least Privilege': Egzamin często podpowiada role o szerokim zakresie (np. 'Editor' lub 'Owner') – zawsze odrzucaj je na rzecz ról predefiniowanych o najmniejszym zakresie uprawnień.
- Pułapka 'Logging vs Monitoring': Pamiętaj: Audit Logs służą do badania aktywności (Who/What/When), a Monitoring do zbierania metryk wydajnościowych.

Głębokie wyjaśnienie techniczne:
Każda architektura bezpieczeństwa w GCP powinna być projektowana w oparciu o 'Security by Default'. Oznacza to m.in. szyfrowanie w spoczynku (domyślne), tożsamość opartą na rolach (IAM) oraz pełną widoczność zapewnianą przez scentralizowane logowanie (Cloud Logging/SCC).

Analiza i Podsumowanie (AI)

Kluczowe zagadnienia

Sugerowana odpowiedź: C

Analiza strategiczna: Pytanie o standardowe praktyki zabezpieczania danych w przesyłach internetowych. Wykorzystanie HTTPS/TLS na Load Balancerze jest jedynym właściwym i rekomendowanym przez Google sposobem ochrony poświadczeń w aplikacjach webowych.
