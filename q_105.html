Question 105 / 361

You want to use the gcloud command-line tool to authenticate using a third-party single sign-on (SSO) SAML identity provider. Which options are necessary to ensure that authentication is supported by the third-party identity provider (IdP)? (Choose two.)

  • A. SSO SAML as a third-party IdP
  • B. Identity Platform
  • C. OpenID Connect
  • D. Identity-Aware Proxy
  • E. Cloud Identity
Show Suggested Answer Hide Answer
Suggested Answer: AE

Wyjaśnienie

1. Prawidłowa odpowiedź lub odpowiedzi:
A. SSO SAML as a third-party IdP
E. Cloud Identity

2. Kompleksowe wyjaśnienie dlaczego dana odpowiedź jest prawidłowa (Analiza):
Pytanie dotyczy konfiguracji uwierzytelniania gcloud CLI z użyciem zewnętrznego dostawcy tożsamości (IdP) opartego na protokole SAML SSO. Aby gcloud mógł uwierzytelniać użytkowników przez zewnętrzny IdP, potrzebne są dwa kluczowe komponenty.

SSO SAML jako zewnętrzny IdP (A) jest oczywistym wymaganiem — to sam mechanizm federacji tożsamości oparty na protokole SAML 2.0. Zewnętrzny IdP (np. Okta, Azure AD, ADFS, Ping Identity) jest odpowiedzialny za faktyczne uwierzytelnienie użytkownika (weryfikacja hasła, MFA itp.) i wygenerowanie asercji SAML, która potwierdza tożsamość użytkownika.

Cloud Identity (E) jest niezbędnym komponentem po stronie Google Cloud. Cloud Identity (lub Google Workspace) pełni rolę dostawcy usług (Service Provider) w architekturze SAML. Każdy użytkownik, który chce korzystać z gcloud, musi mieć konto w domenie Google (zarządzane przez Cloud Identity lub Google Workspace). Cloud Identity jest skonfigurowane tak, aby przekierowywać żądania uwierzytelnienia do zewnętrznego IdP SAML. Proces wygląda następująco: gcloud otwiera przeglądarkę → Google (Cloud Identity) rozpoznaje domenę i przekierowuje do IdP SAML → użytkownik loguje się w IdP → IdP wysyła asercję SAML z powrotem do Google → Google wydaje token → gcloud otrzymuje token i jest uwierzytelniony.

Bez Cloud Identity nie ma "domeny Google", do której można by podpiąć federację SAML, a bez konfiguracji SSO SAML nie ma mechanizmu przekierowania do zewnętrznego IdP. Oba komponenty są niezbędne.

3. Wyjaśnienie z osobna każdej niepoprawnej odpowiedzi:
B. Identity Platform
   * Dlaczego nieprawidłowa: Identity Platform (dawniej Firebase Authentication) jest usługą przeznaczoną do uwierzytelniania użytkowników końcowych (end-users) aplikacji budowanych na Google Cloud. Służy do dodawania funkcji logowania (email/hasło, social login, telefon) do aplikacji mobilnych i webowych. Nie jest używana do uwierzytelniania administratorów i deweloperów korzystających z narzędzi CLI jak gcloud. To usługa typu CIAM (Customer Identity and Access Management), nie workforce IAM.

C. OpenID Connect
   * Dlaczego nieprawidłowa: OpenID Connect (OIDC) jest alternatywnym protokołem federacji tożsamości. Pytanie jednak wyraźnie precyzuje, że organizacja chce używać "SAML identity provider", nie OIDC. Choć OIDC jest również wspierany przez Google Cloud (np. w Workload Identity Federation), w tym scenariuszu IdP obsługuje SAML, więc OIDC nie jest odpowiednim wyborem. Ponadto, gcloud CLI w kontekście SSO pracuje natywnie z SAML przez Cloud Identity/Workspace.

D. Identity-Aware Proxy
   * Dlaczego nieprawidłowa: Identity-Aware Proxy (IAP) jest usługą służącą do ochrony dostępu do aplikacji webowych i zasobów GCP (np. VM przez tunel SSH) na podstawie tożsamości użytkownika i kontekstu żądania. IAP nie uczestniczy w procesie uwierzytelniania użytkownika do gcloud CLI. IAP działa na warstwie HTTP/HTTPS jako proxy weryfikujące tożsamość przed przekazaniem żądania do aplikacji backendowej.

4. Wskazówki, hinty, tips and tricks:
* Cloud Identity = "brama wejściowa" Google dla federacji tożsamości z zewnętrznymi IdP.
* Pamiętaj: gcloud → Google (Cloud Identity) → redirect do SAML IdP → logowanie → SAML assertion → Google token → gcloud authenticated.
* Identity Platform ≠ Cloud Identity: Platform = dla klientów Twojej aplikacji; Cloud Identity = dla Twoich pracowników.
* Na egzaminie, gdy mowa o "gcloud" + "SSO" + "SAML" → zawsze potrzebujesz Cloud Identity + SAML IdP.

5. Reguły wyboru odpowiedzi (Słowa kluczowe):
* "gcloud" + "third-party SSO SAML" → Cloud Identity + SSO SAML IdP
* "authenticate users of your app" → Identity Platform
* "protect web applications" → Identity-Aware Proxy
* "federation" + "workforce" → Cloud Identity + SAML/OIDC
