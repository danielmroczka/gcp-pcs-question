Question 122 / 361

Your organization acquired a new workload. The Web and Application (App) servers will be running on Compute Engine in a newly created custom VPC. You are responsible for configuring a secure network communication solution that meets the following requirements: Only allows communication between the Web and App tiers. Enforces consistent network security when autoscaling the Web and App tiers. Prevents Compute Engine Instance Admins from altering network traffic. What should you do?

  • A. 1. Configure all running Web and App servers with respective network tags. 2. Create an allow VPC firewall rule that specifies the target/source with respective network tags.
  • B. 1. Configure all running Web and App servers with respective service accounts. 2. Create an allow VPC firewall rule that specifies the target/source with respective service accounts.
  • C. 1. Re-deploy the Web and App servers with instance templates configured with respective network tags. 2. Create an allow VPC firewall rule that specifies the target/source with respective network tags.
  • D. 1. Re-deploy the Web and App servers with instance templates configured with respective service accounts. 2. Create an allow VPC firewall rule that specifies the target/source with respective service accounts.
Show Suggested Answer Hide Answer
Suggested Answer: D

Wyjaśnienie

1. Prawidłowa odpowiedź lub odpowiedzi:
D. 1. Re-deploy the Web and App servers with instance templates configured with respective service accounts. 2. Create an allow VPC firewall rule that specifies the target/source with respective service accounts.

2. Kompleksowe wyjaśnienie dlaczego dana odpowiedź jest prawidłowa (Analiza):
Wymagania bezpieczeństwa to: 1) zezwolenie na ruch wyłącznie pomiędzy warstwą Web a App, 2) zachowanie spójności bezpieczeństwa przy autoskalowaniu, 3) uniemożliwienie administratorom maszyn (Instance Admins) modyfikowania reguł przepływu ruchu:
- Używanie kont serwisowych (Service Accounts) jako źródła i celu w regułach zapory (firewall rules) opiera się na tożsamości (identity-based firewall), co jest znacznie bezpieczniejsze niż stosowanie tagów sieciowych. Administrator maszyn wirtualnych (Compute Instance Admin) nie może zmienić konta serwisowego przypisanego do instancji bez posiadania specjalnej roli IAM `iam.serviceAccounts.actAs`, co uniemożliwia mu nieautoryzowane modyfikowanie reguł ruchu.
- Konfiguracja kont serwisowych w szablonach instancji (Instance Templates) gwarantuje, że każda nowo utworzona maszyna w procesie autoskalowania automatycznie otrzyma odpowiednią tożsamość i zostanie natychmiast objęta właściwymi regułami zapory.

3. Wyjaśnienie z osobna każdej niepoprawnej odpowiedzi:
- A i C. Stosowanie tagów sieciowych (network tags): Tagi sieciowe nie są zabezpieczone uprawnieniami IAM w taki sposób jak konta serwisowe. Każdy administrator maszyn wirtualnych może dodać lub usunąć tag z instancji, co pozwala na łatwe obejście reguł zapory i narusza trzecie wymaganie.
- B. Konfiguracja na uruchomionych serwerach bez szablonów instancji: W przypadku autoskalowania, nowe instancje nie byłyby automatycznie konfigurowane z odpowiednim kontem serwisowym, co doprowadziłoby do niespójności bezpieczeństwa.

4. Wskazówki, hinty, tips and tricks:
- Konta serwisowe w regułach firewalla zapewniają ochronę przed nieautoryzowanymi zmianami przez administratorów maszyn (brak możliwości manipulacji tagami).
- Zawsze w przypadku autoskalowania (autoscaling) maszyn na Compute Engine konieczne jest użycie Szablonów Instancji (Instance Templates).

5. Reguły wyboru odpowiedzi (Słowa kluczowe):
- Zabezpieczenie przed manipulacją admina instancji + firewall -> Szyfrowanie/filtrowanie oparte na kontach serwisowych (Service Accounts).
- Spójność przy autoskalowaniu -> Użycie Instance Templates.

6. Dodatkowe źródła i dokumentacja:
- VPC firewall rules service accounts vs network tags: https://cloud.google.com/vpc/docs/firewalls#service-accounts-vs-tags
