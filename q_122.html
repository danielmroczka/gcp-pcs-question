Question 122 / 361

Your organization acquired a new workload. The Web and Application (App) servers will be running on Compute Engine in a newly created custom VPC. You are responsible for configuring a secure network communication solution that meets the following requirements: Only allows communication between the Web and App tiers. Enforces consistent network security when autoscaling the Web and App tiers. Prevents Compute Engine Instance Admins from altering network traffic. What should you do?

  • A. 1. Configure all running Web and App servers with respective network tags. 2. Create an allow VPC firewall rule that specifies the target/source with respective network tags.
  • B. 1. Configure all running Web and App servers with respective service accounts. 2. Create an allow VPC firewall rule that specifies the target/source with respective service accounts.
  • C. 1. Re-deploy the Web and App servers with instance templates configured with respective network tags. 2. Create an allow VPC firewall rule that specifies the target/source with respective network tags.
  • D. 1. Re-deploy the Web and App servers with instance templates configured with respective service accounts. 2. Create an allow VPC firewall rule that specifies the target/source with respective service accounts.
Show Suggested Answer Hide Answer
Suggested Answer: D

Wyjaśnienie

Potwierdzona odpowiedź: D (1. Re-deploy the Web and App servers with instance templates configured with respective service accounts. 2. Create an allow VPC firewall rule that specifies the target/source with respective service accounts.)

Wyjaśnienie:
- Service Accounts (Konta serwisowe): Użycie kont serwisowych zamiast tagów sieciowych w regułach firewalla jest zalecaną praktyką bezpieczeństwa (identity-based firewalls). Tożsamość konta serwisowego jest trwale przypisana do instancji i znacznie trudniejsza do nieautoryzowanej zmiany niż proste tagi tekstowe.
- Instance Templates (Szablony instancji): Zapewniają one spójność konfiguracji podczas autoskalowania. Każda nowa instancja utworzona przez mechanizm automatycznego skalowania otrzyma identyczną tożsamość (konto serwisowe), co gwarantuje poprawne działanie reguł sieciowych bez ręcznej interwencji.
- Separation of Duties: "Compute Engine Instance Admins" zazwyczaj mogą edytować tagi sieciowe na VM, ale zmiana konta serwisowego wymaga znacznie wyższych uprawnień (`iam.serviceAccounts.actAs`). Dzięki temu administratorzy maszyn nie mogą łatwo omijać restrykcji sieciowych poprzez zmianę tagów.

Dlaczego pozostałe są błędne:
- A i C: Tagi sieciowe (network tags) są mniej bezpieczne, ponieważ mogą być swobodnie modyfikowane przez osoby z uprawnieniami do edycji metadanych maszyn wirtualnych, co umożliwia nieautoryzowaną zmianę priorytetów lub obejście reguł firewalla.
- B: Sama konfiguracja kont serwisowych na już działających serwerach nie zapewnia skalowalności i konsystencji (wymóg autoskalowania) – tylko użycie szablonów (D) gwarantuje, że nowe maszyny będą od razu bezpieczne.

Wskazówki egzaminacyjne (Tips & Tricks):
- "Consistent network security when autoscaling" = Instance Templates.
- "Prevent admins from altering traffic" = Użyj Service Accounts zamiast Network Tags w regułach firewalla.
- Reguły oparte na kontach serwisowych działają niezależnie od adresów IP.

Kluczowe zagadnienia do powtórzenia:
- Reguły firewalla VPC oparte na kontach serwisowych.
- Rola `iam.serviceAccounts.actAs` w bezpieczeństwie.
- Korzystanie z szablonów instancji w Managed Instance Groups (MIG).
