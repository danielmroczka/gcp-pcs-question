Question 276 / 361

You are creating a secure network architecture. You must fully isolate development and production environments, and prevent any network traffic between the two environments. The network team requires that there is only one central entry point to the cloud network from the on-premises environment. What should you do?

  • A. Create one Virtual Private Cloud (VPC) network per environment. Add the on-premises entry point to the production VPC. Peer the VPCs with each other and create firewall rules to prevent traffic.
  • B. Create one shared Virtual Private Cloud (VPC) network and use it as the entry point to the cloud network. Create separate subnets per environment. Create firewall rules to prevent traffic.
  • C. Create one Virtual Private Cloud (VPC) network per environment. Create a VPC Service Controls perimeter per environment and add one environment VPC to each.
  • D. Create one Virtual Private Cloud (VPC) network per environment. Create one additional VPC for the entry point to the cloud network. Peer the entry point VPC with the environment VPCs.
Show Suggested Answer
Suggested Answer: D

Wyjaśnienie

1. Prawidłowa odpowiedź lub odpowiedzi:
D. Create one Virtual Private Cloud (VPC) network per environment. Create one additional VPC for the entry point to the cloud network. Peer the entry point VPC with the environment VPCs.

2. Kompleksowe wyjaśnienie dlaczego dana odpowiedź jest prawidłowa (Analiza):
Odpowiedź D jest prawidłowa, ponieważ wykorzystuje architekturę sieci tranzytowej (hub-and-spoke) oraz fundamentalną cechę braku przechodniości (non-transitivity) połączeń VPC Network Peering w Google Cloud w celu zapewnienia izolacji środowisk.

Szczegóły architektury:
a. **Izolacja środowisk:** Tworzymy osobną sieć VPC dla produkcji (`prod-vpc`) oraz dla deweloperów (`dev-vpc`). Maszyny w tych sieciach nie mają żadnego bezpośredniego routingu między sobą.
b. **Wspólny punkt wejścia (Transit VPC):** Tworzymy trzecią sieć VPC (`transit-vpc`), do której podłączamy łącze VPN/Interconnect z on-premises. Sieć ta jest jedyną bramą wejściową do chmury.
c. **VPC Peering bez przechodniości:** Łączymy `transit-vpc` za pomocą peerowania z `prod-vpc` oraz osobno z `dev-vpc`. Zgodnie z zasadami sieciowymi GCP, połączenia peeringowe nie są przechodnie (non-transitive). Ruch z sieci lokalnej może trafić do Dev lub Prod, ale ruch z sieci Dev nie może przejść przez sieć tranzytową do sieci Prod. Gwarantuje to 100% separację środowisk dev i prod przy zachowaniu jednego punktu wejścia.

3. Wyjaśnienie z osobna każdej niepoprawnej odpowiedzi:
A. Create one VPC... Peer the VPCs with each other and create firewall rules...
   * Dlaczego nieprawidłowa: Bezpośrednie peerowanie sieci `dev-vpc` z `prod-vpc` tworzy między nimi bezpośredni routing IP. Poleganie wyłącznie na regułach zapory sieciowej (firewall rules) do blokowania ruchu niesie duże ryzyko błędu konfiguracyjnego (jeśli ktoś usunie lub zmieni regułę, środowiska zostaną połączone). Prawidłowa architektura powinna izolować sieci na poziomie routingu.
B. Create one shared VPC network... Create separate subnets per environment...
   * Dlaczego nieprawidłowa: Umieszczenie Dev i Prod w jednej sieci VPC (nawet w różnych podsieciach) oznacza, że mają one domyślny routing lokalny i mogą się komunikować. Ponadto błędy w regułach firewall mogą łatwo doprowadzić do wycieku danych z produkcji na dev.
C. Create one VPC... Create a VPC Service Controls perimeter per environment...
   * Dlaczego nieprawidłowa: VPC Service Controls chroni interfejsy API usług zarządzanych Google (np. BigQuery, Storage). Nie izoluje ruchu sieciowego IP na poziomie maszyn wirtualnych i tras sieciowych wewnątrz sieci VPC.

4. Wskazówki, hinty, tips and tricks:
* Peering w GCP **nie jest przechodni** (VPC Peering is non-transitive). Jeśli sieć A jest połączona z B, a B z C, to sieć A NIE MOŻE komunikować się z C.
* Wykorzystaj ten mechanizm (Hub-and-Spoke z tranzytowym hubem) do izolacji środowisk przy zachowaniu jednego punktu wejścia z on-premises.

5. Reguły wyboru odpowiedzi (Słowa kluczowe):
* Fully isolate dev and prod + single entry point from on-premises -> Transit VPC peered with environment VPCs (Hub and Spoke).
