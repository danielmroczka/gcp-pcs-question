Question 50 / 361

Your company has deployed an application on Compute Engine. The application is accessible by clients on port 587. You need to balance the load between the different instances running the application. The connection should be secured using TLS, and terminated by the Load Balancer. What type of Load Balancing should you use?

  • A. Network Load Balancing
  • B. HTTP(S) Load Balancing
  • C. TCP Proxy Load Balancing
  • D. SSL Proxy Load Balancing
Show Suggested Answer Hide Answer
Suggested Answer: D

Wyjaśnienie

**Poprawna odpowiedź: D**

**1. Kompleksowe wyjaśnienie poprawnej odpowiedzi:**
Wymagania dotyczące Load Balancera to:
- Równoważenie obciążenia dla ruchu niebędącego ruchem HTTP/HTTPS (port 587 - SMTP).
- Wymóg szyfrowania TLS zakończonego (terminowanego) na Load Balancerze (SSL termination).
- **SSL Proxy Load Balancing (D):** Jest to globalny Load Balancer przeznaczony dla ruchu szyfrowanego SSL/TLS nie-HTTP (takiego jak SMTP na porcie 587). SSL Proxy przyjmuje połączenie SSL od klienta, deszyfruje je na brzegu sieci Google przy użyciu zainstalowanego certyfikatu i przesyła czysty ruch TCP do instancji backendowych w chmurze. Zapewnia to centralne zarządzanie certyfikatami i odciąża procesory maszyn wirtualnych.

**2. Wyjaśnienie niepoprawnych odpowiedzi:**
- **A. Network Load Balancing (NLB):** Działa w warstwie 4 i nie ma możliwości deszyfrowania ani terminacji SSL/TLS na poziomie Load Balancera. Przekazuje zaszyfrowany ruch bezpośrednio do maszyn backendowych, co zmusza do instalacji certyfikatów na każdej maszynie.
- **B. HTTP(S) Load Balancing:** Działa w warstwie 7, ale obsługuje wyłącznie ruch protokołów HTTP i HTTPS. Nie może obsługiwać innych protokołów TCP takich jak bezpieczny SMTP na porcie 587.
- **C. TCP Proxy Load Balancing:** Równoważy ruch TCP nie-HTTP i terminuje połączenia TCP na LB, ale nie obsługuje natywnej terminacji i deszyfrowania SSL/TLS przy użyciu certyfikatów w taki sposób jak SSL Proxy.

**3. Wskazówki i pułapki egzaminacyjne (Tips & Tricks):**
- Słowo-klucz: **secured using TLS** (szyfrowanie SSL) oraz **terminated by the Load Balancer** (terminacja na LB) dla ruchu nie-HTTP (port 587). Prawidłową odpowiedzią jest **SSL Proxy Load Balancing**.
- Jeśli ruch byłby czystym TCP bez deszyfrowania -> TCP Proxy. Jeśli ruchem byłby HTTPS -> HTTP(S) LB.

**4. Reguły wyboru odpowiedzi:**
- Szyfrowanie SSL (nie-HTTP) + terminacja na Load Balancerze -> SSL Proxy Load Balancer.

**5. Dodatkowe źródła:**
- SSL Proxy Load Balancing overview: https://cloud.google.com/load-balancing/docs/ssl

Analiza i Podsumowanie Dyskusji (AI)

Analiza i Wyjaśnienie

Sugerowana odpowiedź: D

Analiza spornych kwestii (AI): Pytanie precyzyjnie wskazuje na potrzebę terminacji SSL na LB dla ruchu na porcie 587. W ekosystemie Google Cloud jedynym natywnym rozwiązaniem pasującym do tego opisu jest SSL Proxy Load Balancer. Użycie Network LB wymagałoby zarządzania certyfikatami na każdej z maszyn z osobna, co jest zaprzeczeniem "terminacji przez Load Balancer".

Pamiętaj, że w egzaminie Professional Cloud Security Engineer kluczowe jest wybieranie rozwiązań najmniej uprzywilejowanych (Principle of Least Privilege), zoptymalizowanych kosztowo i spełniających wymogi compliancy (np. CMEK, Data Loss Prevention).

- Mylenie usług: np. Cloud Armor (WAF) z Cloud IAP (Identity-Aware Proxy).
