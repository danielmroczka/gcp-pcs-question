Question 50 / 361

Your company has deployed an application on Compute Engine. The application is accessible by clients on port 587. You need to balance the load between the different instances running the application. The connection should be secured using TLS, and terminated by the Load Balancer. What type of Load Balancing should you use?

  • A. Network Load Balancing
  • B. HTTP(S) Load Balancing
  • C. TCP Proxy Load Balancing
  • D. SSL Proxy Load Balancing
Show Suggested Answer Hide Answer
Suggested Answer: D

Wyjaśnienie

Potwierdzona odpowiedź: D (SSL Proxy Load Balancing)

Wyjaśnienie:
Mamy tutaj specyficzne wymagania dotyczące równoważenia obciążenia: ruch inny niż HTTP (port 587 - SMTP/TLS), konieczność terminacji sesji SSL/TLS na Load Balancerze oraz potrzebę globalnego równoważenia ruchu.
1. SSL Proxy Load Balancing: Jest to globalny load balancer dla ruchu TCP zabezpieczonego protokołem SSL/TLS. Pozwala on na zakończenie sesji SSL na samym LB (terminacja), co odciąża serwery backendowe. Jest idealny dla ruchu, który nie jest protokołem HTTP(S), ale wymaga szyfrowania (np. poczta e-mail, bazy danych).
2. Port 587: Choć ten port jest standardowo kojarzony z protokołem SMTP, w kontekście GCP i wyboru Load Balancera, kluczowe jest to, że wymaga on terminacji SSL/TLS dla ruchu TCP niebędącego HTTP.

Dlaczego pozostałe są błędne:
A. Network Load Balancing: Działa w warstwie 4 (L4) i jest pasywny (pass-through). Nie wspiera terminacji SSL/TLS – pakiety są przesyłane bezpośrednio do instancji w niezmienionej formie.
B. HTTP(S) Load Balancing: Jest przeznaczony wyłącznie dla ruchu HTTP i HTTPS (porty 80 i 443). Nie obsłuży ruchu na porcie 587.
C. TCP Proxy Load Balancing: Jest bardzo podobny do SSL Proxy, ale służy do równoważenia czystego ruchu TCP bez wbudowanej funkcji terminacji SSL/TLS (choć technicznie mogą współdzielić infrastrukturę, to dla ruchu szyfrowanego z terminacją na LB poprawną odpowiedzią egzaminacyjną jest SSL Proxy).

Wskazówki egzaminacyjne (Tips & Tricks):
- "Terminated by the Load Balancer" + "SSL/TLS" + "Non-HTTP port" = SSL Proxy Load Balancing.
- Jeśli port to 80/443 = HTTP(S) LB.
- Jeśli port to cokolwiek innego i NIE ma terminacji SSL = Network LB (regional) lub TCP Proxy (global).
- Pamiętaj, że SSL Proxy i TCP Proxy są dostępne tylko dla określonych portów (GCP ma ich listę, 587 jest na niej wspierany przez SSL Proxy).

Analiza i Podsumowanie Dyskusji (AI)

Analiza i Wyjaśnienie

Sugerowana odpowiedź: D

Analiza spornych kwestii (AI): Pytanie precyzyjnie wskazuje na potrzebę terminacji SSL na LB dla ruchu na porcie 587. W ekosystemie Google Cloud jedynym natywnym rozwiązaniem pasującym do tego opisu jest SSL Proxy Load Balancer. Użycie Network LB wymagałoby zarządzania certyfikatami na każdej z maszyn z osobna, co jest zaprzeczeniem "terminacji przez Load Balancer".
