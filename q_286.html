Question 286 / 361

Your application development team is releasing a new critical feature. To complete their final testing, they requested 10 thousand real transaction records. The new feature includes format checking on the primary account number (PAN) of a credit card. You must support the request and minimize the risk of unintended personally identifiable information (PII) exposure. What should you do?

  • A. Run the new application by using Confidential Computing to ensure PII and card PAN is encrypted in use.
  • B. Scan and redact PII from the records by using the Cloud Data Loss Prevention API. Perform format-preserving encryption on the card PAN.
  • C. Encrypt the records by using Cloud Key Management Service to protect the PII and card PAN.
  • D. Build a tool to replace the card PAN and PII fields with randomly generated values.
Show Suggested Answer Hide Answer
Suggested Answer: B

Wyjaśnienie

1. Prawidłowa odpowiedź lub odpowiedzi:
B. Scan and redact PII from the records by using the Cloud Data Loss Prevention API. Perform format-preserving encryption on the card PAN.

2. Kompleksowe wyjaśnienie dlaczego dana odpowiedź jest prawidłowa (Analiza):
Odpowiedź B jest prawidłowa, ponieważ łączy ochronę danych osobowych (redagowanie PII) z zachowaniem użyteczności danych testowych przy użyciu szyfrowania zachowującego format (Format-Preserving Encryption - FPE) dla numeru karty kredytowej (PAN).

Dlaczego to najlepsza metoda:
a. **Zachowanie formatu (FPE):** Aplikacja testuje funkcję sprawdzania formatu numeru karty (np. algorytm Luhna, długość 16 cyfr). Zwykłe zaszyfrowanie kluczem KMS zamieniłoby numer karty na losowy ciąg znaków alfanumerycznych, co uniemożliwiłoby testowanie formatu. FPE szyfruje numer tak, że wynikowy ciąg nadal wygląda jak poprawny numer karty (np. 16 cyfr), co pozwala na przeprowadzenie testów.
b. **Usuwanie danych wrażliwych (Redaction):** Pozostałe dane osobowe (np. imiona, adresy, e-maile), które nie są potrzebne do testowania tej funkcji, są całkowicie usuwane (redagowane) przez Cloud DLP, co eliminuje ryzyko wycieku PII.

3. Wyjaśnienie z osobna każdej niepoprawnej odpowiedzi:
A. Run the new application by using Confidential Computing...
   * Dlaczego nieprawidłowa: Poufne obliczenia (Confidential Computing) szyfrują pamięć RAM podczas działania programu. Nie chronią jednak danych przed deweloperami wykonującymi testy, którzy nadal mieliby pełny wgląd w surowe, niezaszyfrowane transakcje na ekranie lub w logach testowych.
C. Encrypt the records by using Cloud Key Management Service...
   * Dlaczego nieprawidłowa: Szyfrowanie KMS zamienia dane w nieczytelny szyfrogram (ciphertext). Odszyfrowanie danych w środowisku testowym ujawni oryginalne numery kart deweloperom (ryzyko wycieku), a nieodszyfrowane dane uniemożliwią przetestowanie funkcji sprawdzania formatu (brak formatu karty).
D. Build a tool to replace the card PAN and PII fields with randomly generated values.
   * Dlaczego nieprawidłowa: Pisanie własnego narzędzia do maskowania i generowania poprawnych numerów kart (zgodnych z algorytmami kart płatniczych) wymaga dużego nakładu pracy programistycznej. Google udostępnia gotowe, certyfikowane narzędzie w postaci Cloud DLP (Sensitive Data Protection), które wykonuje te transformacje automatycznie i bezpiecznie.

4. Wskazówki, hinty, tips and tricks:
* Jeśli testowana funkcja wymaga zachowania struktury/formatu danych (np. format numeru PESEL, karty kredytowej PAN) -> Zawsze używaj **Format-Preserving Encryption (FPE)** w Cloud DLP.
* Inne zbędne dane wrażliwe należy zredagować (redact).

5. Reguły wyboru odpowiedzi (Słowa kluczowe):
* Format checking on PAN + minimize PII exposure -> Cloud DLP + Format-preserving encryption (FPE).

6. Dodatkowe źródła i dokumentacja:
Format-preserving encryption in Cloud DLP
De-identifying sensitive data in Cloud DLP

Wskazówki egzaminacyjne (Tips & Tricks)

Reguła Egzaminacyjna (Exam Rule): 
W pytaniach typu 'Security in GCP', zawsze priorytetyzuj rozwiązania natywne (SCC, Cloud KMS, Secret Manager, VPC SC) nad rozwiązaniami typu 'third-party' lub 'self-managed', chyba że scenariusz wymaga specyficznej integracji hybrydowej.

Haczyki egzaminacyjne (Exam Traps):
- Pułapka 'Least Privilege': Egzamin często podpowiada role o szerokim zakresie (np. 'Editor' lub 'Owner') – zawsze odrzucaj je na rzecz ról predefiniowanych o najmniejszym zakresie uprawnień.
- Pułapka 'Logging vs Monitoring': Pamiętaj: Audit Logs służą do badania aktywności (Who/What/When), a Monitoring do zbierania metryk wydajnościowych.

Głębokie wyjaśnienie techniczne:
Każda architektura bezpieczeństwa w GCP powinna być projektowana w oparciu o 'Security by Default'. Oznacza to m.in. szyfrowanie w spoczynku (domyślne), tożsamość opartą na rolach (IAM) oraz pełną widoczność zapewnianą przez scentralizowane logowanie (Cloud Logging/SCC).

Analiza i Podsumowanie (AI)

Kluczowe zagadnienia

Sugerowana odpowiedź: B

Analiza strategiczna: To pytanie testuje Twoją zdolność do projektowania bezpiecznych środowisk testowych. W środowiskach testowych często używa się danych rzeczywistych, co jest naruszeniem standardów bezpieczeństwa. Użycie natywnych funkcji "Format Preserving" pozwala zachować użyteczność aplikacji, przy jednoczesnej eliminacji ryzyka wycieku rzeczywistych danych PII.
