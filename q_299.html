Question 299 / 361

You manage multiple internal-only applications that are hosted within different Google Cloud projects. You are deploying a new application that requires external internet access. To maintain security, you want to clearly separate this new application from internal systems. Your solution must have effective security isolation for the new externally-facing application. What should you do?

  • A. Deploy the application within the same project as an internal application. Use a Shared VPC model to manage network configurations.
  • B. Place the application in the same project as an existing internal application, and adjust firewall rules to allow external traffic.
  • C. Create a VPC Service Controls perimeter, and place the new application's project within that perimeter.
  • D. Create a new project for the application, and use VPC Network Peering to access necessary resources in the internal projects.
Show Suggested Answer Hide Answer
Suggested Answer: D

Wyjaśnienie

1. Prawidłowa odpowiedź lub odpowiedzi:
D. Create a new project for the application, and use VPC Network Peering to access necessary resources in the internal projects.

2. Kompleksowe wyjaśnienie dlaczego dana odpowiedź jest prawidłowa (Analiza):
Odpowiedź D jest prawidłowa, ponieważ umieszczenie nowej aplikacji zewnętrznej w wydzielonym projekcie (Dedicated Project) oraz sieci VPC jest podstawową zasadą izolacji bezpieczeństwa (security isolation) w chmurze.

Dlaczego to zapewnia najlepszą izolację:
a. **Izolacja na poziomie projektu (Blast Radius):** Projekt jest główną granicą bezpieczeństwa w GCP. Jeśli zewnętrzna aplikacja zostanie zhakowana (skompromitowana), napastnik nie uzyska automatycznie dostępu do zasobów wewnętrznych aplikacji, które znajdują się w innych projektach.
b. **Kontrolowana łączność (VPC Peering):** Użycie VPC Network Peering pozwala na bezpieczną, prywatną komunikację sieciową między siecią VPC aplikacji zewnętrznej a sieciami wewnętrznymi tylko na portach i dla zasobów, które zostaną jawnie dopuszczone przez reguły firewall.
c. **Separacja administracyjna:** Pozwala na przydzielenie zespołowi deweloperskiemu uprawnień do zarządzania tą jedną aplikacją bez dawania im dostępu do systemów wewnętrznych.

3. Wyjaśnienie z osobna każdej niepoprawnej odpowiedzi:
A. Deploy the application within the same project as an internal application. Use a Shared VPC model...
   * Dlaczego nieprawidłowa: Umieszczenie publicznej aplikacji w tym samym projekcie co krytyczne systemy wewnętrzne drastycznie zwiększa ryzyko (blast radius). Napastnik, przejmując uprawnienia w projekcie (np. przez podatność aplikacji), uzyska bezpośredni dostęp do innych zasobów w tym samym projekcie. Shared VPC współdzieli sieć, ale nie naprawia braku izolacji na poziomie zasobów projektu.
B. Place the application in the same project... and adjust firewall rules to allow external traffic.
   * Dlaczego nieprawidłowa: Podobnie jak opcja A, brak separacji na poziomie projektu jest poważnym błędem. Otwarcie zapory sieciowej dla ruchu zewnętrznego bezpośrednio do projektu z zasobami wewnętrznymi stwarza wysokie ryzyko wycieku danych w przypadku błędnej konfiguracji firewall.
C. Create a VPC Service Controls perimeter, and place the new application's project within that perimeter.
   * Dlaczego nieprawidłowa: Perymetr VPC Service Controls (VPC SC) służy do izolowania usług zarządzanych (np. zakaz wywoływania API BigQuery z zewnątrz perymetru). Sam perymetr nie służy do separacji ruchu sieciowego dla nowo wdrażanej publicznej aplikacji webowej i nie zastępuje potrzeby wdrożenia jej w osobnym projekcie w celu izolacji maszyn.

4. Wskazówki, hinty, tips and tricks:
* Podstawową granicą izolacji (security boundary) w GCP jest **Projekt (Project)**.
* Zawsze wdrażaj aplikacje o różnym profilu ryzyka (np. publiczne vs. wewnętrzne) w osobnych projektach GCP.
* Używaj VPC Peering lub Shared VPC do bezpiecznego łączenia wydzielonych środowisk.

5. Reguły wyboru odpowiedzi (Słowa kluczowe):
* Separate external application from internal systems + security isolation -> Create a new project for the application.
