Question 299 / 361

You manage multiple internal-only applications that are hosted within different Google Cloud projects. You are deploying a new application that requires external internet access. To maintain security, you want to clearly separate this new application from internal systems. Your solution must have effective security isolation for the new externally-facing application. What should you do?

  • A. Deploy the application within the same project as an internal application. Use a Shared VPC model to manage network configurations.
  • B. Place the application in the same project as an existing internal application, and adjust firewall rules to allow external traffic.
  • C. Create a VPC Service Controls perimeter, and place the new application's project within that perimeter.
  • D. Create a new project for the application, and use VPC Network Peering to access necessary resources in the internal projects.
Show Suggested Answer Hide Answer
Suggested Answer: D

Wskazówki egzaminacyjne (Tips & Tricks)

Reguła Egzaminacyjna (Exam Rule): 
W pytaniach typu 'Security in GCP', zawsze priorytetyzuj rozwiązania natywne (SCC, Cloud KMS, Secret Manager, VPC SC) nad rozwiązaniami typu 'third-party' lub 'self-managed', chyba że scenariusz wymaga specyficznej integracji hybrydowej.

Haczyki egzaminacyjne (Exam Traps):
- Pułapka 'Least Privilege': Egzamin często podpowiada role o szerokim zakresie (np. 'Editor' lub 'Owner') – zawsze odrzucaj je na rzecz ról predefiniowanych o najmniejszym zakresie uprawnień.
- Pułapka 'Logging vs Monitoring': Pamiętaj: Audit Logs służą do badania aktywności (Who/What/When), a Monitoring do zbierania metryk wydajnościowych.

Głębokie wyjaśnienie techniczne:
Każda architektura bezpieczeństwa w GCP powinna być projektowana w oparciu o 'Security by Default'. Oznacza to m.in. szyfrowanie w spoczynku (domyślne), tożsamość opartą na rolach (IAM) oraz pełną widoczność zapewnianą przez scentralizowane logowanie (Cloud Logging/SCC).

Wyjaśnienie

Potwierdzona odpowiedź: D (Create a new project for the application, and use VPC Network Peering to access necessary resources in the internal projects.)

Wyjaśnienie:
- Izolacja projektowa: Umieszczenie nowej, wystawionej na internet aplikacji w osobnym projekcie (D) zapewnia najsilniejszą izolację na poziomie zasobów i uprawnień (IAM). Dzięki temu ewentualne przejęcie tej aplikacji nie daje automatycznego dostępu do innych projektów.
- VPC Network Peering: Pozwala na kontrolowaną komunikację z wewnętrznymi systemami w innych projektach bez wystawiania ich na internet, przy jednoczesnym zachowaniu separacji administracyjnej projektów.

Dlaczego pozostałe odpowiedzi są niepoprawne:
- A, B. Same project: Trzymanie aplikacji publicznej i wewnętrznej w tym samym projekcie to wysokie ryzyko ("blast radius"). Błąd w konfiguracji firewall w tym jednym projekcie może odsłonić systemy wewnętrzne.
- C. VPC Service Controls: Służy do ochrony przed eksfiltracją danych z usług zarządzanych (jak Cloud Storage czy BigQuery), a nie do izolacji sieciowej maszyn wirtualnych wystawionych na internet. Perimeter wręcz utrudnia dostęp z zewnątrz, co kłóci się z wymogiem dostępu internetowego dla tej aplikacji.

Wskazówki i triki (Tips & Tricks):
- "External access" + "Isolation from internal systems" = Separate Project + VPC Peering (lub Shared VPC z restrykcjami).
- Zawsze separuj środowiska o różnym poziomie zaufania (Trust Levels) na poziomie projektów.

Praktyczne informacje na egzamin:
- Zapamiętaj: Projekt w GCP jest główną granicą izolacji (Trust Boundary).

Analiza i Podsumowanie (AI)

Kluczowe zagadnienia

Sugerowana odpowiedź: D

Analiza strategiczna: Pytanie dotyczy architektury bezpieczeństwa (Security Architecture). Zasada separacji (Segregation) nakazuje, aby systemy o różnej ekspozycji na zagrożenia (internet vs sieć wewnętrzna) były od siebie odizolowane na najwyższym możliwym poziomie hierarchii chmurowej.
