Question 117 / 361

You plan to deploy your cloud infrastructure using a CI/CD cluster hosted on Compute Engine. You want to minimize the risk of its credentials being stolen by a third party. What should you do?

  • A. Create a dedicated Cloud Identity user account for the cluster. Use a strong self-hosted vault solution to store the user's temporary credentials.
  • B. Create a dedicated Cloud Identity user account for the cluster. Enable the constraints/iam.disableServiceAccountCreation organization policy at the project level.
  • C. Create a custom service account for the cluster. Enable the constraints/iam.disableServiceAccountKeyCreation organization policy at the project level
  • D. Create a custom service account for the cluster. Enable the constraints/iam.allowServiceAccountCredentialLifetimeExtension organization policy at the project level.
Show Suggested Answer Hide Answer
Suggested Answer: C

Wyjaśnienie

Potwierdzona odpowiedź: C (Create a custom service account for the cluster. Enable the constraints/iam.disableServiceAccountKeyCreation organization policy at the project level)

Wyjaśnienie:
- Custom Service Account (Niestandardowe konto serwisowe): Zgodnie z zasadą najniższych uprawnień (Least Privilege), klaster CI/CD powinien używać dedykowanego konta serwisowego z ograniczonymi uprawnieniami, zamiast domyślnego konta Compute Engine, które jest zbyt uprzywilejowane.
- disableServiceAccountKeyCreation: Jest to jedna z najskuteczniejszych metod ograniczania ryzyka kradzieży poświadczeń. Klucze kont serwisowych w formie plików JSON są "wieczne" i ich wyciek jest najczęstszą przyczyną włamań. Wyłączenie możliwości ich tworzenia wymusza stosowanie bezpieczniejszych, krótkotrwałych metod uwierzytelniania (np. Workload Identity lub bezpośrednie użycie tożsamości maszyny VM).

Dlaczego pozostałe są błędne:
- A: "Cloud Identity user account" to konto przeznaczone dla człowieka (z hasłem). Używanie go do procesów automatycznych (CI/CD) jest niezgodne z praktykami bezpieczeństwa GCP i trudniejsze w zarządzaniu niż Service Account.
- B: `constraints/iam.disableServiceAccountCreation` całkowicie zablokowałoby możliwość tworzenia nowych kont serwisowych, co uniemożliwiłoby realizację pierwszej części poprawnego rozwiązania (stworzenia dedykowanego konta).
- D: `constraints/iam.allowServiceAccountCredentialLifetimeExtension` pozwala na WYDŁUŻENIE czasu życia tokenów, co zwiększa ryzyko w przypadku ich przejęcia. Bezpieczeństwo polega na skracaniu, a nie wydłużaniu ważności poświadczeń.

Wskazówki egzaminacyjne (Tips & Tricks):
- Słowo klucz "Minimize risk of credentials stolen" + "Service Account" = Zablokuj tworzenie kluczy JSON (Key Creation).
- Zawsze wybieraj konta serwisowe (Service Accounts) dla maszyn i procesów, a nie konta użytkowników (User Accounts).

Kluczowe zagadnienia do powtórzenia:
- Najlepsze praktyki zarządzania kontami serwisowymi.
- Ograniczenia polityki organizacji (Organization Policy Service).
- Ryzyka związane z statycznymi kluczami kont serwisowych.

Dokumentacja:
- Zarządzanie kluczami kont serwisowych
