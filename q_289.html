Question 289 / 361

You work for an organization that handles sensitive customer data. You must secure a series of Google Cloud Storage buckets housing this data and meet these requirements:
- Multiple teams need varying access levels (some read-only, some read-write).
- Data must be protected in storage and at rest.
- It's critical to track file changes and audit access for compliance purposes.
- For compliance purposes, the organization must have control over the encryption keys.

  • A. Create IAM groups for each team and manage permissions at the group level. Employ server-side encryption and Object Versioning by Google Cloud Storage. Configure cloud monitoring tools to alert on anomalous data access patterns.
  • B. Set individual permissions for each team and apply access control lists (ACLs) to each bucket and file. Enforce TLS encryption for file transfers. Enable Object Versioning and Cloud Audit Logs for the storage buckets.
  • C. Use predefined IAM roles tailored to each team's access needs, such as Storage Object Viewer and Storage Object User. Utilize customer-supplied encryption keys (CSEK) and enforce TLS encryption. Turn on both Object Versioning and Cloud Audit Logs for the storage buckets.
  • D. Assign IAM permissions for all teams at the object level. Implement third-party software to encrypt data at rest. Track data access by using network logs.
Show Suggested Answer Hide Answer
Suggested Answer: C

Wyjaśnienie

1. Prawidłowa odpowiedź lub odpowiedzi:
C. Use predefined IAM roles tailored to each team's access needs, such as Storage Object Viewer and Storage Object User. Utilize customer-supplied encryption keys (CSEK) and enforce TLS encryption. Turn on both Object Versioning and Cloud Audit Logs for the storage buckets.

2. Kompleksowe wyjaśnienie dlaczego dana odpowiedź jest prawidłowa (Analiza):
Odpowiedź C jest prawidłowa, ponieważ kompleksowo spełnia wszystkie cztery wymagania bezpieczeństwa i zgodności postawione przed systemem przechowywania danych w Cloud Storage.

Spełnienie wymagań krok po kroku:
a. **Zróżnicowany dostęp (Least Privilege):** Zastosowanie predefiniowanych ról IAM (np. `Storage Object Viewer` dla odczytu oraz `Storage Object User` dla zapisu i odczytu) pozwala na precyzyjne przydzielenie uprawnień zespołom bez nadmiarowych uprawnień administracyjnych.
b. **Ochrona danych w spoczynku i kontrola kluczy:** Wykorzystanie kluczy szyfrujących dostarczanych przez klienta (Customer-Supplied Encryption Keys - CSEK) gwarantuje, że bank/organizacja ma 100% kontroli nad kluczami, ponieważ Google nie zapisuje ich na dyskach i są one dostarczane w wywołaniach API.
c. **Ochrona w locie:** Wymuszenie szyfrowania TLS (HTTPS) zabezpiecza dane przed podsłuchem podczas przesyłania.
d. **Śledzenie zmian i audyt:** Włączenie wersjonowania obiektów (Object Versioning) pozwala na odzyskanie i śledzenie zmian w plikach, a aktywacja Cloud Audit Logs zapewnia pełną rozliczalność (kto i kiedy uzyskał dostęp do plików).

3. Wyjaśnienie z osobna każdej niepoprawnej odpowiedzi:
A. ...Employ server-side encryption and Object Versioning by Google Cloud Storage...
   * Dlaczego nieprawidłowa: Domyślne szyfrowanie po stronie serwera Google (Google-managed keys) nie daje organizacji kontroli nad kluczami szyfrującymi (klucze są w pełni kontrolowane przez Google), co narusza czwarty wymóg zadania.
B. ...apply access control lists (ACLs) to each bucket and file...
   * Dlaczego nieprawidłowa: Stosowanie list ACL na poziomie pojedynczych plików jest przestarzałą i trudną do audytowania praktyką. Google zaleca stosowanie Uniform IAM na poziomie kubełka w celu zachowania spójności bezpieczeństwa. Ponadto, ta opcja nie wspomina o wymaganiu kontroli nad kluczami szyfrującymi (brak CSEK/CMEK).
D. Assign IAM permissions for all teams at the object level... Implement third-party software to encrypt...
   * Dlaczego nieprawidłowa: Przypisywanie uprawnień na poziomie obiektów jest skomplikowane i nieefektywne. Używanie oprogramowania firm trzecich (third-party software) do szyfrowania danych w locie wprowadza niepotrzebną złożoność i nie integruje się natywnie z Cloud Storage. Ponadto logi sieciowe (network logs) nie dostarczają szczegółowych informacji o operacjach na plikach API GCS (brak audytu specyficznego dla przechowywania obiektów).

4. Wskazówki, hinty, tips and tricks:
* Kontrola nad kluczami szyfrującymi w GCS -> **Customer-Supplied Encryption Keys (CSEK)** lub **Customer-Managed Encryption Keys (CMEK)**.
* Śledzenie zmian plików w GCS -> **Object Versioning**.
* Audytowanie dostępu do obiektów -> **Cloud Audit Logs** (Data Access Logs).

5. Reguły wyboru odpowiedzi (Słowa kluczowe):
* Track file changes + audit access + organization control keys -> Object Versioning + Cloud Audit Logs + CSEK/CMEK.
