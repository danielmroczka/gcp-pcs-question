Question 289 / 361

You work for an organization that handles sensitive customer data. You must secure a series of Google Cloud Storage buckets housing this data and meet these requirements:
- Multiple teams need varying access levels (some read-only, some read-write).
- Data must be protected in storage and at rest.
- It's critical to track file changes and audit access for compliance purposes.
- For compliance purposes, the organization must have control over the encryption keys.

  • A. Create IAM groups for each team and manage permissions at the group level. Employ server-side encryption and Object Versioning by Google Cloud Storage. Configure cloud monitoring tools to alert on anomalous data access patterns.
  • B. Set individual permissions for each team and apply access control lists (ACLs) to each bucket and file. Enforce TLS encryption for file transfers. Enable Object Versioning and Cloud Audit Logs for the storage buckets.
  • C. Use predefined IAM roles tailored to each team's access needs, such as Storage Object Viewer and Storage Object User. Utilize customer-supplied encryption keys (CSEK) and enforce TLS encryption. Turn on both Object Versioning and Cloud Audit Logs for the storage buckets.
  • D. Assign IAM permissions for all teams at the object level. Implement third-party software to encrypt data at rest. Track data access by using network logs.
Show Suggested Answer Hide Answer
Suggested Answer: C

Wskazówki egzaminacyjne (Tips & Tricks)

Reguła Egzaminacyjna (Exam Rule): 
W pytaniach typu 'Security in GCP', zawsze priorytetyzuj rozwiązania natywne (SCC, Cloud KMS, Secret Manager, VPC SC) nad rozwiązaniami typu 'third-party' lub 'self-managed', chyba że scenariusz wymaga specyficznej integracji hybrydowej.

Haczyki egzaminacyjne (Exam Traps):
- Pułapka 'Least Privilege': Egzamin często podpowiada role o szerokim zakresie (np. 'Editor' lub 'Owner') – zawsze odrzucaj je na rzecz ról predefiniowanych o najmniejszym zakresie uprawnień.
- Pułapka 'Logging vs Monitoring': Pamiętaj: Audit Logs służą do badania aktywności (Who/What/When), a Monitoring do zbierania metryk wydajnościowych.

Głębokie wyjaśnienie techniczne:
Każda architektura bezpieczeństwa w GCP powinna być projektowana w oparciu o 'Security by Default'. Oznacza to m.in. szyfrowanie w spoczynku (domyślne), tożsamość opartą na rolach (IAM) oraz pełną widoczność zapewnianą przez scentralizowane logowanie (Cloud Logging/SCC).

Wyjaśnienie

Potwierdzona odpowiedź: C (Use predefined IAM roles tailored to each team's access needs, such as Storage Object Viewer and Storage Object User. Utilize customer-supplied encryption keys (CSEK) and enforce TLS encryption. Turn on both Object Versioning and Cloud Audit Logs for the storage buckets.)

Wyjaśnienie:
- CSEK (Customer-Supplied Encryption Keys): Spełnia wymóg "pełnej kontroli nad kluczami" (organizacja dostarcza własny klucz przy każdej operacji).
- IAM Predefined Roles: Spełnia wymóg różnych poziomów dostępu (Viewer vs User).
- Object Versioning: Pozwala śledzić zmiany i odzyskiwać poprzednie wersje plików.
- Cloud Audit Logs: Zapewnia ścieżkę audytu (kto i kiedy uzyskał dostęp).

Dlaczego pozostałe odpowiedzi są niepoprawne:
- A. Server-side encryption: Zazwyczaj odnosi się do kluczy zarządzanych przez Google (Google-managed), co nie daje organizacji pełnej kontroli wymaganej w pytaniu.
- B. ACLs: Są mniej wydajne i trudniejsze w audycie niż IAM; ACL nie są zalecane jako główny mechanizm kontroli w skali enterprise.
- D. Third-party software: GCP posiada natywne mechanizmy (CSEK/CMEK), które są preferowane i łatwiejsze w integracji niż oprogramowanie zewnętrzne.

Wskazówki i triki (Tips & Tricks):
- "Organization must have control over the encryption keys" = Szukaj CSEK (najwyższa kontrola) lub CMEK.
- "Audit access" = Zawsze Cloud Audit Logs.

Praktyczne informacje na egzamin:
- Zapamiętaj różnicę: CSEK (Klucz dostarczasz Ty), CMEK (Klucz w Cloud KMS, Ty nim zarządzasz), Google-managed (Wszystko robi Google).
