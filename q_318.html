Question 318 / 361

Your organization must store highly sensitive data within Google Cloud. You need to design a solution that provides the strongest level of security and control. What should you do?

  • A. Use Cloud Storage with customer-supplied encryption keys (CSEK), VPC Service Controls for network isolation, and Cloud DLP for data inspection.
  • B. Use Cloud Storage with customer-managed encryption keys (CMEK), Cloud DLP for data classification, and Secret Manager for storing API access tokens.
  • C. Use Cloud Storage with client-side encryption, Cloud KMS for key management, and Cloud HSM for cryptographic operations.
  • D. Use Cloud Storage with server-side encryption, BigQuery with column-level encryption, and IAM roles for access control.
Show Suggested Answer Hide Answer
Suggested Answer: C

Wyjaśnienie

✅ PRAWIDŁOWA ODPOWIEDŹ: C

Prawidłowa odpowiedź: C – Use Cloud Storage with client-side encryption, Cloud KMS for key management, and VPC Service Controls to prevent unauthorized access.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
DLACZEGO C JEST PRAWIDŁOWE?
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
"Strongest level of security" wymaga wielowarstwowej ochrony:
1. Client-side encryption = dane są szyfrowane ZANIM trafią do Google Cloud (nawet Google nie widzi plaintext).
2. Cloud KMS = zarządzanie kluczami z pełną kontrolą i audytowalnością.
3. VPC Service Controls = perymetr zapobiegający eksfiltracji danych.

Client-side encryption > CMEK > CSEK > Server-side encryption (pod względem kontroli klienta).

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
DLACZEGO INNE OPCJE SĄ BŁĘDNE?
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
A. ❌ CSEK = server-side encryption z kluczami klienta. Google widzi plaintext podczas szyfrowania. Silniejsze niż CMEK, ale słabsze niż client-side.
B. ❌ CMEK = Google zarządza kluczami w KMS, ale Google Cloud widzi dane podczas przetwarzania. Cloud DLP to dodatkowa warstwa, nie silniejsza.
D. ❌ Server-side encryption = Google kontroluje szyfrowanie. Najsłabsza opcja z perspektywy klienta.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
WSKAZÓWKI EGZAMINACYJNE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
• Hierarchia siły szyfrowania (od najsilniejszej kontroli klienta):
  Client-side > CSEK > CMEK > Server-side (Google managed)
• "Strongest/maximum security" = client-side encryption.
• Client-side + KMS + VPC SC = kompletna ochrona.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
REGUŁY
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
• Maximum kontrola klienta = client-side encryption.
• Prevent exfiltration = VPC Service Controls.
• Key management = Cloud KMS.
