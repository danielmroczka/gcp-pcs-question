Question 92 / 361

You are on your company's development team. You noticed that your web application hosted in staging on GKE dynamically includes user data in web pages without first properly validating the inputted data. This could allow an attacker to execute gibberish commands and display arbitrary content in a victim user's browser in a production environment.
How should you prevent and fix this vulnerability?

  • A. Use Cloud IAP based on IP address or end-user device attributes to prevent and fix the vulnerability.
  • B. Set up an HTTPS load balancer, and then use Cloud Armor for the production environment to prevent the potential XSS attack.
  • C. Use Web Security Scanner to validate the usage of an outdated library in the code, and then use a secured version of the included library.
  • D. Use Web Security Scanner in staging to simulate an XSS injection attack, and then use a templating system that supports contextual auto-escaping.
Show Suggested Answer Hide Answer
Suggested Answer: D

Wyjaśnienie

Reguła Egzaminacyjna (Exam Rule):
Podatności wewnątrz kodu aplikacji (takie jak XSS - Cross-Site Scripting) muszą być rozwiązane na poziomie kodu (App Code), a nie poprzez mechanizmy brzegowe (WAF/Cloud Armor), które jedynie ograniczają ryzyko, ale nie usuwają przyczyny źródłowej (root cause).

Haczyki egzaminacyjne (Exam Traps):
- Opcja A: Cloud IAP (Identity-Aware Proxy) służy do uwierzytelniania, a nie do poprawy bezpieczeństwa kodu aplikacji.
- Opcja B: Cloud Armor pomaga w mitigacji XSS na poziomie WAF (Edge Security), ale nie jest "naprawą" luki w aplikacji. Egzamin wymaga wyboru "naprawy" (fix).

Głębokie wyjaśnienie techniczne:
Luka XSS wynika z braku poprawnego sanitizowania (sanitization) lub ucieczkowania (escaping) danych wejściowych przed wyświetleniem ich w przeglądarce.
1. Web Security Scanner: Narzędzie Google, które automatycznie skanuje aplikację (w tym staging) w poszukiwaniu typowych podatności OWASP (w tym XSS).
2. Contextual Auto-escaping: Najlepsza praktyka inżynierska. Templating system (np. Jinja2, Go templates) automatycznie dobiera metodę maskowania znaków specjalnych w zależności od kontekstu (czy dane wchodzą do atrybutu HTML, czy do wnętrza tagu). Jest to znacznie bezpieczniejsze niż ręczne czyszczenie danych.
