Question 237 / 361

Your organization wants full control of the keys used to encrypt data at rest in their Google Cloud environments. Keys must be generated and stored outside of Google and integrate with many Google Services including BigQuery. What should you do?

  • A. Use customer-supplied encryption keys (CSEK) with keys generated on trusted external systems. Provide the raw CSEK as part of the API call.
  • B. Create a KMS key that is stored on a Google managed FIPS 140-2 level 3 Hardware Security Module (HSM). Manage the Identity and Access Management (IAM) permissions settings, and set up the key rotation period.
  • C. Use Cloud External Key Management (EKM) that integrates with an external Hardware Security Module (HSM) system from supported vendors.
  • D. Create a Cloud Key Management Service (KMS) key with imported key material. Wrap the key for protection during import. Import the key generated on a trusted system in Cloud KMS.
Show Suggested Answer Hide Answer
Suggested Answer: C

Wyjaśnienie

1. Prawidłowa odpowiedź lub odpowiedzi:
C. Use Cloud External Key Management (EKM) that integrates with an external Hardware Security Module (HSM) system from supported vendors.

2. Kompleksowe wyjaśnienie dlaczego dana odpowiedź jest prawidłowa (Analiza):
Odpowiedź C jest prawidłowa, ponieważ Cloud External Key Manager (Cloud EKM) pozwala na pełną kontrolę nad cyklem życia kluczy szyfrujących (generowanie, przechowywanie, rotacja) na zewnętrznych systemach bezpieczeństwa (HSM) poza infrastrukturą Google Cloud, jednocześnie oferując bezszwową integrację z natywnymi usługami chmurowymi (takimi jak BigQuery czy Compute Engine).

Jak to działa:
a. Klucz główny (KEK) nigdy nie opuszcza fizycznego modułu HSM klienta (który może znajdować się on-premises lub u zaufanego zewnętrznego dostawcy tożsamości kluczy).
b. Podczas operacji zapisu/odczytu w BigQuery, usługa wysyła zapytanie szyfrujące do Cloud KMS, który z kolei odwołuje się do Cloud EKM w celu wykonania operacji kryptograficznej na zewnętrznym HSM.
c. Daje to klientowi ostateczną kontrolę – wyłączenie zewnętrznego HSM natychmiast blokuje dostęp do danych w GCP.

3. Wyjaśnienie z osobna każdej niepoprawnej odpowiedzi:
A. Use customer-supplied encryption keys (CSEK) with keys generated on trusted external systems. Provide the raw CSEK as part of the API call.
   * Dlaczego nieprawidłowa: Klucze CSEK nie są wspierane przez wiele kluczowych usług GCP (w tym nie są bezpośrednio wspierane w zaawansowanych scenariuszach BigQuery w taki sposób jak EKM). Ponadto dostarczanie surowego klucza (raw key) w każdym wywołaniu API jest trudne do zarządzania i stwarza ryzyko wycieku klucza w kodzie aplikacji.
B. Create a KMS key that is stored on a Google managed FIPS 140-2 level 3 Hardware Security Module (HSM)...
   * Dlaczego nieprawidłowa: Cloud HSM to usługa w 100% zarządzana przez Google w chmurze GCP. Klucze nie są generowane ani przechowywane "outside of Google" (poza strukturami Google), co było głównym wymaganiem.
D. Create a Cloud Key Management Service (KMS) key with imported key material...
   * Dlaczego nieprawidłowa: Importowanie materiału klucza (Imported Key Material) do Cloud KMS powoduje, że kopia materiału klucza zostaje zapisana i jest przechowywana w chmurze Google. W tym momencie klucze nie znajdują się już wyłącznie na zewnątrz Google.

4. Wskazówki, hinty, tips and tricks:
* Pełna kontrola kluczy poza chmurą Google (Keys stored outside of Google) + integracja z usługami GCP -> **Cloud EKM (External Key Manager)**.
* Cloud HSM = klucze w chmurze Google na sprzętowych modułach HSM.
* Cloud EKM = klucze u klienta / zewnętrznego partnera.

5. Reguły wyboru odpowiedzi (Słowa kluczowe):
* Keys generated and stored outside of Google + integrate with GCP -> Cloud External Key Management (EKM).

6. Dodatkowe źródła i dokumentacja:

Wskazówki egzaminacyjne (Tips & Tricks)

Reguła Egzaminacyjna (Exam Rule): 
Jeśli scenariusz dotyczy zabezpieczania zasobów chmurowych (GCP), zawsze wybieraj rozwiązanie typu Managed (SCC, Secret Manager, Cloud KMS), a unikaj rozwiązań self-managed, chyba że pytanie wyraźnie wymaga dostosowania niskopoziomowego.

Haczyki egzaminacyjne (Exam Traps):
- Pułapka IAM: Pytania o uprawnienia często sugerują 'Project Owner' – zawsze szukaj 'Least Privilege' (np. 'Role: Secret Manager Secret Accessor').
- Pułapka Sieciowa: Często mylone są VPC Peering (wydajność) oraz VPN (szyfrowanie/on-premise).

Głębokie wyjaśnienie techniczne:
Rozwiązanie bazuje na GCP Shared Responsibility Model. Google zarządza bezpieczeństwem infrastruktury (Physical, Network, Host), podczas gdy administrator zarządza tożsamością (IAM), danymi (Encryption, Cloud KMS) i regułami dostępu (VPC Firewall).

Analiza i Podsumowanie (AI)

Kluczowe zagadnienia

Sugerowana odpowiedź: C

Analiza strategiczna: To pytanie testuje Twoją wiedzę o różnicy między zarządzaniem cyklem życia klucza (KMS/HSM) a posiadaniem materiału klucza (EKM). EKM jest jedyną odpowiedzią, gdy klient musi technicznie uniemożliwić Google dostęp do surowego klucza w stanie spoczynku.
