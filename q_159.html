Question 159 / 361

You discovered that sensitive personally identifiable information (PII) is being ingested to your Google Cloud environment in the daily ETL process from an on-premises environment to your BigQuery datasets. You need to redact this data to obfuscate the PII, but need to re-identify it for data analytics purposes. Which components should you use in your solution? (Choose two.)

  • A. Secret Manager
  • B. Cloud Key Management Service
  • C. Cloud Data Loss Prevention with cryptographic hashing
  • D. Cloud Data Loss Prevention with automatic text redaction
  • E. Cloud Data Loss Prevention with deterministic encryption using AES-SIV
Show Suggested Answer Hide Answer
Suggested Answer: BE

Wyjaśnienie

1. Prawidłowa odpowiedź lub odpowiedzi:
B. Cloud Key Management Service
E. Cloud Data Loss Prevention with deterministic encryption using AES-SIV

2. Kompleksowe wyjaśnienie dlaczego dana odpowiedź jest prawidłowa (Analiza):
W procesie ETL dane PII trafiają do BigQuery. Wymagane jest zaciemnienie (obfuscate) PII w taki sposób, aby proces był odwracalny (re-identify) na potrzeby zaawansowanej analityki danych:
- E (Szyfrowanie deterministyczne): Szyfrowanie deterministyczne (Deterministic encryption) za pomocą algorytmu AES-SIV w Cloud DLP jest metodą pseudonimizacji, która dla tej samej wartości wejściowej zawsze generuje identyczną wartość wyjściową (surrogate). Pozwala to na wykonywanie zapytań analitycznych (np. JOIN, GROUP BY) bezpośrednio na zaszyfrowanych danych, a co najważniejsze — proces ten jest w pełni odwracalny (można odzyskać oryginalne dane PII).
- B (Zarządzanie kluczami): Cloud DLP wykorzystuje mechanizmy kryptograficzne, które potrzebują klucza opakowującego (wrapped key). Usługa Cloud KMS (Key Management Service) przechowuje i zarządza kluczem głównym (KEK) użytym w tym procesie, zapewniając kontrolę nad tym, kto ma prawo do odszyfrowania (re-identyfikacji) danych.

3. Wyjaśnienie z osobna każdej niepoprawnej odpowiedzi:
- A. Secret Manager: Służy do bezpiecznego przechowywania sekretów aplikacji (haseł, kluczy API), nie posiada funkcji transformacji danych w strumieniach ETL ani integracji z silnikiem deidentyfikacji Cloud DLP.
- C. Szyfrowanie z haszowaniem kryptograficznym (Cryptographic hashing): Haszowanie jest procesem jednokierunkowym (irreversible). Po zahaszowaniu danych nie ma technicznej możliwości ich ponownej re-identyfikacji, co łamie kluczowy wymóg zadania.
- D. Automatyczne usuwanie/redagowanie tekstu (automatic text redaction): Trwale zastępuje wrażliwy tekst maską (np. zastępuje nazwisko tekstem `[NAME]`), co jest procesem nieodwracalnym i niszczy spójność referencyjną danych analitycznych.

4. Wskazówki, hinty, tips and tricks:
- Kiedy wymagane jest zaciemnienie danych z możliwością ich **późniejszego odczytania/odwrócenia (re-identify)**, poprawnym wyborem jest **Deterministic Encryption (AES-SIV)** z kluczami zarządzanymi w **Cloud KMS**.
- Haszowanie i klasyczna redakcja (redaction) są nieodwracalne.

5. Reguły wyboru odpowiedzi (Słowa kluczowe):
- Odwracalna deidentyfikacja danych (re-identify) w ETL/BigQuery -> Cloud DLP Deterministic encryption (AES-SIV) + Cloud KMS.
