Question 159 / 361

You discovered that sensitive personally identifiable information (PII) is being ingested to your Google Cloud environment in the daily ETL process from an on-premises environment to your BigQuery datasets. You need to redact this data to obfuscate the PII, but need to re-identify it for data analytics purposes. Which components should you use in your solution? (Choose two.)

  • A. Secret Manager
  • B. Cloud Key Management Service
  • C. Cloud Data Loss Prevention with cryptographic hashing
  • D. Cloud Data Loss Prevention with automatic text redaction
  • E. Cloud Data Loss Prevention with deterministic encryption using AES-SIV
Show Suggested Answer Hide Answer
Suggested Answer: BE

Wyjaśnienie

Poprawna odpowiedź: BE (B: Cloud Key Management Service, E: Cloud Data Loss Prevention with deterministic encryption using AES-SIV)

Dlaczego te odpowiedzi są poprawne:
- Cloud Data Loss Prevention (DLP) - De-identification: DLP oferuje zaawansowane techniki de-identyfikacji danych, w tym pseudonimizację.
- Deterministic encryption (AES-SIV): Jest to metoda szyfrowania, która dla tej samej wartości wejściowej zawsze generuje tę samą wartość zaszyfrowaną (przy użyciu tego samego klucza). Dzięki temu analitycy mogą np. łączyć tabele (JOIN) po zaszyfrowanym identyfikatorze użytkownika, nie znając jego prawdziwej tożsamości. Co najważniejsze, proces ten jest odwracalny (re-identification), co pozwala na przywrócenie oryginalnych danych, jeśli zajdzie taka potrzeba.
- Cloud Key Management Service (KMS): DLP wymaga klucza do wykonania szyfrowania deterministycznego. Najlepszą praktyką bezpieczeństwa w GCP jest przechowywanie i zarządzanie tymi kluczami w Cloud KMS. DLP używa klucza z KMS do "owinięcia" (wrap) klucza kryptograficznego używanego w procesie transformacji.

Analiza niepoprawnych odpowiedzi:
- A. Secret Manager: Służy do przechowywania haseł, kluczy API i certyfikatów, ale nie jest natywnie zintegrowany z procesami transformacji de-identyfikacyjnej DLP tak jak KMS.
- C. Cryptographic hashing: Hashing (skrót kryptograficzny) jest z reguły procesem jednostronnym. Choć DLP go oferuje, re-identyfikacja (odwrócenie procesu) jest bardzo trudna lub niemożliwa bez posiadania oryginalnych danych, co nie spełnia wymogu "need to re-identify it".
- D. Automatic text redaction: Polega na trwałym usunięciu tekstu (np. zastąpienie go znakiem [REDACTED]). Jest to proces nieodwracalny, więc uniemożliwia re-identyfikację.

Wskazówki i triki (Tips & Tricks):
- "Re-identify" / "Reversible" + "DLP" = Deterministic Encryption (AES-SIV).
- "Join data without knowing PII" = Deterministic Encryption.
- Jeśli DLP potrzebuje klucza do operacji kryptograficznych -> KMS.

Praktyczne informacje na egzamin:
- Zrozum różnicę między de-identyfikacją (usuwanie PII) a pseudonimizacją (zastępowanie PII tokenem).
- AES-SIV (Synthetic Initialization Vector) jest specyficznym trybem AES, który zapewnia determinizm przy jednoczesnym zachowaniu wysokiego bezpieczeństwa.
- Pamiętaj, że do re-identyfikacji potrzebujesz tych samych ustawień DLP oraz dostępu do tego samego klucza w KMS.
