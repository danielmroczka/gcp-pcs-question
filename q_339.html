Question 339 / 361

Your company is migrating a three-tier web application to Google Cloud. The application consists of a web frontend, an application backend, and a database. Due to regulatory requirements and existing on-premises infrastructure dependencies, you need to implement a hybrid cloud architecture. The web frontend will be hosted on Google Cloud, while the application backend and the database will remain on-premises initially. You need to ensure secure and efficient communication between the cloud-based frontend and the on-premises backend and database, minimizing latency and maximizing availability. What should you do?

  • A. Establish a Dedicated Interconnect connection between the Google Cloud VPC network and the on-premises network. Configure firewall rules to allow communication between the three tiers.
  • B. Establish a direct internet connection between the Google Cloud VPC network hosting the web frontend and the on-premises network that hosts the backend and database. Configure firewall rules to allow communication between the three tiers.
  • C. Replicate the on-premises backend and database to Google Cloud. Use a hybrid connectivity network endpoint group for the primary. Backup to the zonal network endpoint group.
  • D. Use a highly-available Cloud VPN connection over the public internet to connect the Google Cloud VPC network to the on-premises network.
Show Suggested Answer Hide Answer
Suggested Answer: A

Wskazówki egzaminacyjne (Tips & Tricks)

Reguła Egzaminacyjna (Exam Rule): 
W pytaniach typu 'Security in GCP', zawsze priorytetyzuj rozwiązania natywne (SCC, Cloud KMS, Secret Manager, VPC SC) nad rozwiązaniami typu 'third-party' lub 'self-managed', chyba że scenariusz wymaga specyficznej integracji hybrydowej.

Haczyki egzaminacyjne (Exam Traps):
- Pułapka 'Least Privilege': Egzamin często podpowiada role o szerokim zakresie (np. 'Editor' lub 'Owner') – zawsze odrzucaj je na rzecz ról predefiniowanych o najmniejszym zakresie uprawnień.
- Pułapka 'Logging vs Monitoring': Pamiętaj: Audit Logs służą do badania aktywności (Who/What/When), a Monitoring do zbierania metryk wydajnościowych.

Głębokie wyjaśnienie techniczne:
Każda architektura bezpieczeństwa w GCP powinna być projektowana w oparciu o 'Security by Default'. Oznacza to m.in. szyfrowanie w spoczynku (domyślne), tożsamość opartą na rolach (IAM) oraz pełną widoczność zapewnianą przez scentralizowane logowanie (Cloud Logging/SCC).

Wyjaśnienie

Poprawna odpowiedź: A (Establish a Dedicated Interconnect connection between the Google Cloud VPC network and the on-premises network. Configure firewall rules to allow communication between the three tiers.)

Dlaczego ta odpowiedź jest poprawna:
- Dedicated Interconnect: To usługa zapewniająca bezpośrednie (private), stabilne, o wysokiej przepustowości połączenie z GCP.
- "Minimizing latency and maximizing availability": Dedicated Interconnect jest najlepszym rozwiązaniem dla środowisk hybrydowych (Enterprise), oferującym stałą przepustowość i znacznie mniejsze opóźnienia niż internet (VPN).

Analiza niepoprawnych odpowiedzi:
- B. Internet connection: Bardzo niebezpieczne (dane w sieci publicznej) i nieprzewidywalne pod kątem wydajności/latencji.
- C. Replicate: To nie jest "hybrid cloud architecture", to migracja (wymóg mówi o pozostawieniu backendu on-premises).
- D. Cloud VPN: VPN jest OK, ale Dedicated Interconnect oferuje lepszą wydajność ("maximizing availability" i wydajność dla trzech warstw aplikacji) i jest bardziej standardowy w dużych środowiskach "regulated".

Wskazówki i triki (Tips & Tricks):
- "Hybrid" + "High bandwidth/Availability/Security" = Dedicated Interconnect.
- Internet to NIGDY nie jest odpowiedź w pytaniach o wysoką wydajność/bezpieczeństwo.

Praktyczne informacje na egzamin:
- Zapamiętaj: Interconnect = Private, High Speed. VPN = Private, Public internet based.

Analiza i Podsumowanie (AI)

Kluczowe zagadnienia

Sugerowana odpowiedź: A

Analiza strategiczna: Pytanie o wybór mechanizmu łączności hybrydowej. Wymogi wysokiej dostępności, niskiej latencji oraz "bezpieczeństwa" dla dużych przedsiębiorstw kierują wybór ku fizycznym połączeniom typu Dedicated Interconnect, a nie VPN przez internet.
