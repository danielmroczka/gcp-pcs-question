Question 258 / 361

Your organization has adopted a "Zero Trust" security model and wants to ensure that only corporate-managed devices can access the Google Cloud console. You need to implement a solution that verifies the device's security posture before granting access. What should you do?

  • A. Create an access level named "Authorized Devices." Utilize the Device Policy attribute to require corporate-managed devices. Apply the access level to the Google Cloud project and instruct all employees to enroll their devices in the organization's management system.
  • B. Configure VPC firewall policy to restrict traffic to the Google Cloud console IP ranges only from corporate-managed IP addresses.
  • C. Implement organization policies to restrict access to the Google Cloud console to specific regions and IP addresses.
  • D. Assign IAM conditional policies to require device-based authentication for all users accessing the Google Cloud console.
Show Suggested Answer Hide Answer
Suggested Answer: A

Wyjaśnienie

Poprawna odpowiedź: A (Create an access level named "Authorized Devices." Utilize the Device Policy attribute to require corporate-managed devices. Apply the access level to the Google Cloud project and instruct all employees to enroll their devices in the organization's management system.)

Dlaczego ta odpowiedź jest poprawna:
- BeyondCorp Enterprise (Context-Aware Access): Jest to rozwiązanie Google Cloud typu Zero Trust, które pozwala na kontrolowanie dostępu do aplikacji i konsoli Google Cloud w oparciu o kontekst (tożsamość, lokalizacja, stan urządzenia).
- Weryfikacja certyfikatu/urządzenia: BeyondCorp pozwala na zdefiniowanie poziomów dostępu (Access Levels), które sprawdzają, czy urządzenie, z którego loguje się użytkownik, posiada poprawny, korporacyjny certyfikat X.509.
- Access Policy: Stworzenie polityki dostępu (Access Policy) i powiązanie jej z konsolą Google Cloud (poprzez Access Binding) jest standardową metodą wymuszenia, aby tylko autoryzowane urządzenia miały dostęp.

Analiza niepoprawnych odpowiedzi:
- B. VPC firewall policy: Firewalle VPC działają wewnątrz sieci wirtualnej i chronią ruch między maszynami lub ruch do internetu. Nie służą do kontrolowania dostępu użytkowników do samej konsoli Google Cloud.
- C. Organization policy: Polityki organizacji służą do narzucania ograniczeń konfiguracyjnych na zasoby (np. "zakaz tworzenia publicznych IP"), ale nie posiadają natywnej funkcji weryfikacji certyfikatów na urządzeniach końcowych użytkowników.
- D. IAM conditional policy: Choć IAM Conditions pozwalają na pewną kontrolę kontekstową (np. IP źródłowe, czas), nie mają one bezpośredniego wglądu w certyfikaty sprzętowe urządzenia tak jak BeyondCorp.

Wskazówki i triki (Tips & Tricks):
- "Corporate-issued devices" + "Device certificate" + "Access to Console" = BeyondCorp Enterprise / Context-Aware Access.
- Szukaj słów takich jak "Access Context Manager" lub "Access Level".

Praktyczne informacje na egzamin:
- Zapamiętaj: BeyondCorp Enterprise jest usługą płatną, ale Context-Aware Access w wersji podstawowej jest dostępny w Cloud Identity Premium / Workspace.
