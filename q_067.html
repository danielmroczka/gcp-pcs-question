Question 67 / 361

A company is backing up logs to Cloud Storage. Analysts should only access logs without PII. Log files with PII should be moved to another bucket accessible only by the admin. What should you do?

  • A. Use Cloud Pub/Sub and Cloud Functions to trigger a DLP scan on upload and move files with PII.
  • B. Upload logs to both buckets and delete PII files from the shared one.
  • C. Use Object Lifecycle Management to delete PII objects.
  • D. Configure a Cloud Storage Trigger for PII data.
Show Suggested Answer Hide Answer
Suggested Answer: A

Wyjaśnienie

1. Prawidłowa odpowiedź lub odpowiedzi:
   A (Use Cloud Pub/Sub and Cloud Functions to trigger a DLP scan on upload and move files with PII.)

2. Kompleksowe wyjaśnienie dlaczego dana odpowiedź jest prawidłowa (Analiza):
   Prawidłowa odpowiedź A proponuje architekturę sterowaną zdarzeniami (event-driven), która jest wiodącą praktyką bezpieczeństwa i efektywności w Google Cloud Platform (GCP) dla automatycznego przetwarzania danych w czasie rzeczywistym.
   
   Mechanizmy leżące u podstaw tej opcji:
   a.   Cloud Storage Event Notifications: Kiedy plik (obiekt) jest przesyłany (UPLOAD) do Cloud Storage, generowane jest zdarzenie. Zamiast bezpośredniego wywoływania Cloud Functions, rekomendowaną praktyką w bardziej złożonych scenariuszach jest użycie Cloud Pub/Sub jako pośrednika. Cloud Storage może wysyłać powiadomienia o zdarzeniach (na przykład OBJECT_FINALIZE, które sygnalizuje zakończenie przesyłania obiektu) bezpośrednio do topiców Cloud Pub/Sub. To podejście zapewnia asynchroniczność, trwałość wiadomości oraz decoupling (rozdzielenie) producenta (Cloud Storage) od konsumenta (Cloud Functions), zwiększając niezawodność i skalowalność systemu.
   b.   Cloud Pub/Sub: Działa jako niezawodny, skalowalny system kolejkowania wiadomości. Powiadomienia o przesłanych plikach są publikowane do topicu Pub/Sub. Zaletą tego rozwiązania jest to, że Cloud Functions może subskrybować ten topic. Jeśli Cloud Functions z jakiegoś powodu chwilowo nie działa lub jest przeciążone, wiadomości pozostają w kolejce Pub/Sub i zostaną dostarczone, gdy usługa będzie ponownie dostępna, zapobiegając utracie zdarzeń. Zapewnia to również wysoką przepustowość i elastyczność w obsłudze zmiennego obciążenia.
   c.   Cloud Functions: Jest to bezserwerowa platforma obliczeniowa, która automatycznie wykonuje kod w odpowiedzi na zdarzenia. W tym scenariuszu, Cloud Function jest skonfigurowana do subskrybowania topicu Cloud Pub/Sub. Gdy tylko nowe zdarzenie "przesłania pliku" zostanie opublikowane w Pub/Sub, Cloud Function jest wyzwalana. Jej kod jest odpowiedzialny za pobranie przesłanego pliku z Cloud Storage i przekazanie go do usługi Cloud DLP. Cloud Functions umożliwia szybkie i efektywne wykonanie logiki biznesowej bez zarządzania infrastrukturą serwerową.
   d.   Cloud DLP (Data Loss Prevention): To kluczowy element rozwiązania. Cloud DLP jest usługą zaprojektowaną do identyfikacji, klasyfikowania i anonimizowania wrażliwych danych. Cloud Function wykorzystuje Cloud DLP API do skanowania zawartości przesłanego pliku w poszukiwaniu danych osobowych (PII - Personally Identifiable Information), takich jak numery kart kredytowych, PESEL, adresy e-mail itp. Cloud DLP oferuje szeroką gamę wbudowanych detektorów (infoTypes) i pozwala na tworzenie własnych, niestandardowych.
   e.   Logika przenoszenia plików: Jeśli Cloud DLP wykryje PII w pliku, Cloud Function, na podstawie tej detekcji, automatycznie przenosi plik z początkowego "bucketu logów" do dedykowanego "bucketu administratora". Ten drugi bucket ma ściśle ograniczone uprawnienia dostępu, dostępne tylko dla administratorów, co zapewnia izolację danych wrażliwych. Jeśli PII nie zostanie wykryte, plik pozostaje w początkowym buckecie, dostępnym dla analityków.

   Dlaczego jest to zalecana praktyka (best practice) i lepsze, bezpieczniejsze i bardziej skalowalne rozwiązanie:
   - Zasada najmniejszych uprawnień (Least Privilege): Analitycy nigdy nie mają dostępu do danych zawierających PII. Pliki są skanowane i segregowane ZANIM staną się dostępne dla analityków. Minimalizuje to ryzyko przypadkowego lub celowego ujawnienia danych.
   - Automatyzacja i przetwarzanie w czasie rzeczywistym: Proces skanowania i przenoszenia odbywa się automatycznie i natychmiast po przesłaniu pliku, eliminując potrzebę interwencji manualnej i zmniejszając okno czasowe, w którym PII mogłoby być narażone.
   - Zgodność z regulacjami: Pomaga firmom spełniać wymagania regulacyjne dotyczące ochrony danych (np. RODO/GDPR, HIPAA), zapewniając, że dane wrażliwe są odpowiednio identyfikowane i izolowane.
   - Skalowalność i niezawodność: Wszystkie użyte usługi (Cloud Storage, Pub/Sub, Cloud Functions, Cloud DLP) są w pełni zarządzane przez Google, co gwarantuje wysoką dostępność, elastyczną skalowalność i odporność na awarie bez konieczności zarządzania infrastrukturą. Architektura oparta na Pub/Sub zwiększa elastyczność i tolerancję na błędy.
   - Elastyczność: Możliwość rozszerzenia logiki Cloud Functions o dodatkowe kroki, takie jak powiadomienia, audyty, anonimizacja danych w locie, czy integracja z innymi systemami bezpieczeństwa.

3. Wyjaśnienie z osobna każdej niepoprawnej odpowiedzi:
   B. Upload logs to both buckets and delete PII files from the shared one.
      Wyjaśnienie dlaczego jest błędne: Ta opcja jest fundamentalnie niezgodna z najlepszymi praktykami bezpieczeństwa, zwłaszcza zasadą najmniejszych uprawnień i minimalizacji ekspozycji danych wrażliwych. Przesyłanie logów zawierających PII do "współdzielonego" bucketu, nawet z zamiarem późniejszego ich usunięcia, tworzy krytyczne okno czasowe (time window) ekspozycji. W tym czasie, zanim pliki z PII zostaną zidentyfikowane i usunięte, analitycy mogą mieć do nich dostęp. PII mogłoby zostać odczytane, skopiowane lub przypadkowo ujawnione. Nawet krótkotrwałe przechowywanie danych wrażliwych w miejscu, do którego mają dostęp nieuprawnione osoby, stanowi poważne naruszenie bezpieczeństwa danych i może prowadzić do niezgodności z regulacjami (np. RODO/GDPR). Ponadto, ręczne usuwanie plików jest podatne na błędy i nie jest skalowalne.

   C. Use Object Lifecycle Management to delete PII objects.
      Wyjaśnienie dlaczego jest błędne: Object Lifecycle Management (OLM) w Cloud Storage jest potężnym narzędziem do automatyzacji zarządzania cyklem życia obiektów, ale jego funkcjonalność opiera się wyłącznie na metadanych obiektu, a nie na jego zawartości. Reguły OLM mogą być skonfigurowane w oparciu o takie kryteria jak wiek obiektu (np. usuń po 30 dniach), klasa pamięci masowej (np. przenieś do Coldline Storage po 60 dniach), liczba wersji (np. zachowaj tylko 3 najnowsze wersje), czy istnienie obiektu w danej wersji. OLM nie posiada wbudowanych możliwości skanowania zawartości plików w poszukiwaniu PII lub jakichkolwiek innych wzorców danych. Zatem, nie jest w stanie rozróżnić plików z PII od tych bez PII w celu ich usunięcia lub przeniesienia. Jego celem jest optymalizacja kosztów i utrzymanie porządku w bucketach, a nie analiza bezpieczeństwa danych.

   D. Configure a Cloud Storage Trigger for PII data.
      Wyjaśnienie dlaczego jest błędne: Ta opcja sugeruje istnienie natywnego Cloud Storage Triggera, który bezpośrednio reagowałby na "dane PII". Taki trigger nie istnieje w Cloud Storage. Cloud Storage Triggers (czyli powiadomienia o zdarzeniach, Event Notifications) reagują na zdarzenia operacyjne związane z obiektami, takie jak OBJECT_FINALIZE (nowy obiekt został przesłany), OBJECT_DELETE (obiekt został usunięty), ARCHIVE (obiekt został zarchiwizowany), itp. Te triggery informują o tym, że coś stało się z obiektem, ale nie analizują jego zawartości. Aby podjąć decyzję w oparciu o zawartość pliku (np. czy zawiera PII), wymagane jest zintegrowanie triggera (np. wysyłającego zdarzenie do Cloud Pub/Sub, a następnie do Cloud Functions) z usługą taką jak Cloud DLP, która przeprowadzi faktyczną analizę treści. Sama konfiguracja "Cloud Storage Trigger for PII data" jest niemożliwa bezpośrednio.

4. Wskazówki, hinty, tips and tricks:
   -   Rozpoznawaj wzorce architektury: Na egzaminie Google Cloud Certified Professional Cloud Security Engineer, pytania często testują znajomość typowych wzorców architektonicznych dla rozwiązań bezpieczeństwa. Gdy pytanie dotyczy automatycznego reagowania na zawartość plików w Cloud Storage, wzorzec Cloud Storage Event Notification (często przez Pub/Sub) -> Cloud Function -> Cloud DLP API jest niemalże standardową odpowiedzią.
   -   Zwracaj uwagę na słowa kluczowe: Słowa takie jak "PII", "dane wrażliwe", "automatyczne wykrywanie", "segregacja danych", "zapobieganie wyciekom danych" (DLP) jednoznacznie wskazują na potrzebę użycia Cloud DLP.
   -   Zrozumienie funkcji usług: Upewnij się, że znasz podstawowe możliwości i ograniczenia każdej usługi GCP. Na przykład, Object Lifecycle Management dotyczy metadanych, nie zawartości. Cloud Functions to orkiestrator logiki biznesowej, a Pub/Sub to broker wiadomości dla skalowalnych, asynchronicznych systemów.
   -   Zasada najmniejszych uprawnień (Least Privilege): Szukaj rozwiązań, które minimalizują dostęp do wrażliwych danych, upewniając się, że tylko uprawnione podmioty mają do nich dostęp, i to tylko w niezbędnym zakresie. Opcje, które tymczasowo wystawiają PII (nawet na krótki czas), są zazwyczaj błędne.
   -   Unikaj rozwiązań manualnych lub podatnych na błędy: Egzamin promuje rozwiązania automatyczne, skalowalne i odporne na błędy. Opcje wymagające ręcznej interwencji lub wprowadzające ryzyko ludzkiego błędu są często gorszym wyborem.

5. Reguły wyboru odpowiedzi (Słowa kluczowe):
   -   Reguła 1: Jeśli pytanie wspomina o "automatycznym wykrywaniu danych wrażliwych" LUB "PII" LUB "identyfikacji treści w plikach" LUB "zgodności z regulacjami dotyczącymi prywatności danych (np. RODO/GDPR, HIPAA)" w kontekście danych przechowywanych w Cloud Storage, to prawidłowa odpowiedź niemal zawsze będzie zawierała "Cloud DLP" jako kluczowy komponent.
   -   Reguła 2: Gdy celem jest "reagowanie na zdarzenia związane z plikami w Cloud Storage" LUB "wykonywanie niestandardowej logiki po przesłaniu pliku" LUB "orchestrowanie procesów przetwarzania danych", szukaj odpowiedzi zawierającej "Cloud Functions" jako mechanizm wykonawczy.
   -   Reguła 3: W przypadku złożonych, asynchronicznych architektur sterowanych zdarzeniami, które wymagają "rozdzielenia usług (decoupling)" LUB "niezawodnego dostarczania wiadomości" LUB "skalowalnej kolejki wiadomości" pomiędzy producentem (np. Cloud Storage) a konsumentem (np. Cloud Functions), szukaj "Cloud Pub/Sub" jako pośrednika.
   -   Reguła 4: Jeśli pytanie dotyczy "zarządzania czasem życia obiektów" LUB "automatycznej zmiany klasy pamięci masowej" LUB "usuwania starych wersji" obiektów na podstawie ich metadanych (nie zawartości), wybierz "Object Lifecycle Management". Nie wybieraj tej opcji do zadań wymagających analizy zawartości.
   -   Reguła 5: Wszelkie opcje, które sugerują "tymczasową ekspozycję danych wrażliwych" LUB "manualne interwencje w celu usunięcia PII" LUB "duplikowanie danych wrażliwych w nieuprawnionych lokalizacjach", są z reguły błędne z perspektywy bezpieczeństwa i najlepszych praktyk GCP.
