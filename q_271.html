You work for a multinational organization that has systems deployed across multiple cloud providers, including Google Cloud. Your organization maintains an extensive on-premises security information and event management (SIEM) system. New security compliance regulations require that relevant Google Cloud logs be integrated seamlessly with the existing SIEM to provide a unified view of security events. You need to implement a solution that exports Google Cloud logs to your on-premises SIEM by using a push-based, near real-time approach. You must prioritize fault tolerance, security, and auto scaling capabilities. In particular, you must ensure that if a log delivery fails, logs are re-sent. What should you do?

  • A. Create a Pub/Sub topic for log aggregation. Write a custom Python script on a Cloud Function Leverage the Cloud Logging API to periodically pull logs from Google Cloud and forward the logs to the SIEM. Schedule the Cloud Function to run twice per day.
  • B. Collect all logs into an organization-level aggregated log sink and send the logs to a Pub/Sub topic. Implement a primary Dataflow pipeline that consumes logs from this Pub/Sub topic and delivers the logs to the SIEM. Implement a secondary Dataflow pipeline that replays failed messages.
  • C. Deploy a Cloud Logging sink with a filter that routes all logs directly to a syslog endpoint. The endpoint is based on a single Compute Engine hosted on Google Cloud that routes all logs to the on-premises SIEM. Implement a Cloud Function that triggers a retry action in case of failure.
  • D. Utilize custom firewall rules to allow your SIEM to directly query Google Cloud logs. Implement a Cloud Function that notifies the SIEM of a failed delivery and triggers a retry action.
Show Suggested Answer Hide Answer
Suggested Answer: B

Wyjaśnienie

Poprawna odpowiedź: B (Collect all logs into an organization-level aggregated log sink and send the logs to a Pub/Sub topic. Implement a primary Dataflow pipeline that consumes logs from this Pub/Sub topic and delivers the logs to the SIEM. Implement a secondary Dataflow pipeline that replays failed messages.)

Dlaczego ta odpowiedź jest poprawna:
- Dataflow pipeline: Dataflow jest jedyną usługą w tym zestawieniu, która jest w 100% zarządzana, skaluje się automatycznie (auto scaling) i posiada wbudowane mechanizmy obsługi błędów i ponowień (fault tolerance, retry) dla strumieni danych z Pub/Sub. Model primary/secondary zapewnia wysoką dostępność.

Analiza niepoprawnych odpowiedzi:
- A. Cloud Function: Przy ogromnej liczbie logów (near real-time) funkcje te są mniej efektywne kosztowo i trudniejsze w zarządzaniu niż dedykowany rurociąg Dataflow.
- C. Syslog CE: VM z syslogiem to "single point of failure" i brak automatycznego skalowania.
- D. Firewall query: Bardzo wolne i nie jest to metoda "near real-time log export".

Wskazówki i triki (Tips & Tricks):
- "Near real-time log export" + "Fault tolerance" + "Auto scaling" = Pub/Sub + Dataflow.
- Zapamiętaj: Dataflow to standard przemysłowy dla potoków danych w GCP (zmiennych w czasie i objętości).

Praktyczne informacje na egzamin:
- Google udostępnia gotowe szablony Dataflow (np. Pub/Sub to Splunk, Pub/Sub to Elasticsearch), co jest najbardziej preferowanym rozwiązaniem w architekturze GCP.

Kluczowe zagadnienia

Sugerowana odpowiedź: B

Analiza strategiczna: To pytanie testuje Twoją znajomość architektury danych w GCP. W rozwiązaniach klasy Enterprise (SIEM integration) kluczowa jest niezawodność i skalowalność. Dataflow jako usługa "serverless streaming" eliminuje problemy z zarządzaniem infrastrukturą i zapewnia mechanizmy "exactly-once" lub "at-least-once" przetwarzania, co jest krytyczne dla logów bezpieczeństwa.
