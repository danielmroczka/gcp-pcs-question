Question 271 / 361

You work for a multinational organization that has systems deployed across multiple cloud providers, including Google Cloud. Your organization maintains an extensive on-premises security information and event management (SIEM) system. New security compliance regulations require that relevant Google Cloud logs be integrated seamlessly with the existing SIEM to provide a unified view of security events. You need to implement a solution that exports Google Cloud logs to your on-premises SIEM by using a push-based, near real-time approach. You must prioritize fault tolerance, security, and auto scaling capabilities. In particular, you must ensure that if a log delivery fails, logs are re-sent. What should you do?

  • A. Create a Pub/Sub topic for log aggregation. Write a custom Python script on a Cloud Function Leverage the Cloud Logging API to periodically pull logs from Google Cloud and forward the logs to the SIEM. Schedule the Cloud Function to run twice per day.
  • B. Collect all logs into an organization-level aggregated log sink and send the logs to a Pub/Sub topic. Implement a primary Dataflow pipeline that consumes logs from this Pub/Sub topic and delivers the logs to the SIEM. Implement a secondary Dataflow pipeline that replays failed messages.
  • C. Deploy a Cloud Logging sink with a filter that routes all logs directly to a syslog endpoint. The endpoint is based on a single Compute Engine hosted on Google Cloud that routes all logs to the on-premises SIEM. Implement a Cloud Function that triggers a retry action in case of failure.
  • D. Utilize custom firewall rules to allow your SIEM to directly query Google Cloud logs. Implement a Cloud Function that notifies the SIEM of a failed delivery and triggers a retry action.
Show Suggested Answer
Suggested Answer: B

Wyjaśnienie

1. Prawidłowa odpowiedź lub odpowiedzi:
B. Collect all logs into an organization-level aggregated log sink and send the logs to a Pub/Sub topic. Implement a primary Dataflow pipeline that consumes logs from this Pub/Sub topic and delivers the logs to the SIEM. Implement a secondary Dataflow pipeline that replays failed messages.

2. Kompleksowe wyjaśnienie dlaczego dana odpowiedź jest prawidłowa (Analiza):
Odpowiedź B jest prawidłowa, ponieważ przedstawia wysoce niezawodną, skalowalną i odporną na awarie (fault-tolerant) architekturę przesyłania logów w czasie rzeczywistym z Google Cloud do lokalnego systemu SIEM, zgodną z najlepszymi praktykami Google.

Analiza techniczna:
a. **Zagregowany log sink (Aggregated Log Sink):** Zbiera logi ze wszystkich projektów w organizacji w jednym miejscu, co gwarantuje pełną widoczność.
b. **Pub/Sub jako bufor:** Zapewnia asynchroniczne i odporne na skoki obciążenia kolejkowanie logów. Działa w trybie "at-least-once delivery", gwarantując, że żadna wiadomość nie zostanie utracona w przypadku niedostępności SIEM.
c. **Dataflow (Autoscaling & Reliability):** Usługa Dataflow automatycznie dopasowuje liczbę procesów do ilości generowanych logów. Użycie szablonu Pub/Sub to Splunk/SIEM pozwala na bezpieczne przesyłanie logów przez HTTPS.
d. **Obsługa błędów (Dead-Letter Queue / Replay):** Zdefiniowanie zapasowego potoku Dataflow do ponownego wysyłania nieudanych dostarczeń (np. z powodu chwilowej awarii sieci on-premises) gwarantuje spełnienie wymogu bezwzględnego dostarczenia wszystkich logów (fault tolerance).

3. Wyjaśnienie z osobna każdej niepoprawnej odpowiedzi:
A. ...Write a custom Python script on a Cloud Function... Schedule... twice per day.
   * Dlaczego nieprawidłowa: Cloud Function uruchamiana dwa razy dziennie to proces wsadowy (batch), a nie rozwiązanie w czasie zbliżonym do rzeczywistego (near real-time). Ponadto, odpytywanie API (pull) dwa razy na dobę przy dużej ilości logów doprowadzi do przepełnienia limitów i utraty logów.
C. ...route all logs directly to a syslog endpoint. The endpoint is based on a single Compute Engine hosted...
   * Dlaczego nieprawidłowa: Pojedyncza maszyna wirtualna Compute Engine działająca jako serwer syslog stanowi pojedynczy punkt awarii (single point of failure - brak fault tolerance) i nie posiada wbudowanych funkcji automatycznego skalowania (auto scaling) w przypadku nagłego skoku liczby logów.
D. Utilize custom firewall rules to allow your SIEM to directly query Google Cloud logs...
   * Dlaczego nieprawidłowa: Bezpośrednie odpytywanie (querying) logów GCP przez lokalny SIEM przez sieć zewnętrzną jest nieefektywne, generuje ogromne koszty zapytań API i transferu oraz nie jest rozwiązaniem typu "push" w czasie rzeczywistym.

4. Wskazówki, hinty, tips and tricks:
* Przesyłanie logów do SIEM (np. Splunk) w czasie rzeczywistym z obsługą błędów -> Standardowy wzorzec architektoniczny: **Cloud Logging -> Pub/Sub -> Dataflow (z obsługą nieudanych zapytań) -> SIEM**.
* Pub/Sub i Dataflow są w pełni zarządzanymi usługami, które automatycznie skalują się do dowolnego wolumenu danych.

5. Reguły wyboru odpowiedzi (Słowa kluczowe):
* Export logs to on-premises SIEM + push near real-time + fault tolerance -> Aggregated sink + Pub/Sub + Dataflow.
