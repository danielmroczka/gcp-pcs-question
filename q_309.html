Question 309 / 361

Your development team is launching a new application. The new application has a microservices architecture on Compute Engine instances and serverless components, including Cloud Functions. This application will process financial transactions that require temporary, highly sensitive data in memory. You need to secure data in use during computations with a focus on minimizing the risk of unauthorized access to memory for this financial application. What should you do?

  • A. Enable Confidential VM instances for Compute Engine, and ensure that relevant Cloud Functions can leverage hardware-based memory isolation.
  • B. Use data masking and tokenization techniques on sensitive financial data fields throughout the application and the application's data processing workflows.
  • C. Use the Cloud Data Loss Prevention (Cloud DLP) API to scan and mask sensitive data before feeding the data into any compute environment.
  • D. Store all sensitive data during processing in Cloud Storage by using customer-managed encryption keys (CMEK), and set strict bucket-level permissions.
Show Suggested Answer Hide Answer
Suggested Answer: A

Wyjaśnienie

Potwierdzona odpowiedź: A (Enable Confidential VM instances for Compute Engine, and ensure that relevant Cloud Functions can leverage hardware-based memory isolation.)

Wyjaśnienie:
- Confidential Computing: To jedyna technologia chroniąca dane 'w użyciu' (in memory). Dla CE są to Confidential VMs (AMD SEV). Dla Cloud Functions Google zapewnia sprzętową izolację pamięci na poziomie mikro-VM (gVisor) w swojej infrastrukturze, co minimalizuje ryzyko nieuprawnionego odczytu RAM.

Dlaczego pozostałe odpowiedzi są niepoprawne:
- B, C: Chronią treść danych logicznie, ale nie zapobiegają technicznemu odczytowi pamięci RAM przez złośliwy proces na hoście.
- D. GCS CMEK: Chroni dane na dysku, nie ma wpływu na bezpieczeństwo pamięci RAM procesora.

Wskazówki i triki (Tips & Tricks):
- "Data in use" / "Encrypt memory" = Confidential VMs.

Praktyczne informacje na egzamin:
- Zapamiętaj, że Confidential Computing jest kluczowe w branżach takich jak bankowość (dane transakcyjne) czy medycyna (dane pacjentów), gdzie suwerenność danych w każdym stanie jest wymogiem prawnym.

Wskazówki egzaminacyjne (Tips & Tricks)

Reguła Egzaminacyjna (Exam Rule): 
W pytaniach typu 'Security in GCP', zawsze priorytetyzuj rozwiązania natywne (SCC, Cloud KMS, Secret Manager, VPC SC) nad rozwiązaniami typu 'third-party' lub 'self-managed', chyba że scenariusz wymaga specyficznej integracji hybrydowej.

Haczyki egzaminacyjne (Exam Traps):
- Pułapka 'Least Privilege': Egzamin często podpowiada role o szerokim zakresie (np. 'Editor' lub 'Owner') – zawsze odrzucaj je na rzecz ról predefiniowanych o najmniejszym zakresie uprawnień.
- Pułapka 'Logging vs Monitoring': Pamiętaj: Audit Logs służą do badania aktywności (Who/What/When), a Monitoring do zbierania metryk wydajnościowych.

Głębokie wyjaśnienie techniczne:
Każda architektura bezpieczeństwa w GCP powinna być projektowana w oparciu o 'Security by Default'. Oznacza to m.in. szyfrowanie w spoczynku (domyślne), tożsamość opartą na rolach (IAM) oraz pełną widoczność zapewnianą przez scentralizowane logowanie (Cloud Logging/SCC).
