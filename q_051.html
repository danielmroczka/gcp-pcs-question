Question 51 / 361

You want to limit the images that can be used as the source for boot disks. These images will be stored in a dedicated project. What should you do?

  • A. Use the Organization Policy Service to create a compute.trustedimageProjects constraint on the organization level. List the trusted project as the whitelist in an allow operation.
  • B. Use the Organization Policy Service to create a compute.trustedimageProjects constraint on the organization level. List the trusted projects as the exceptions in a deny operation.
  • C. In Resource Manager, edit the project permissions for the trusted project. Add the organization as member with the role: Compute Image User.
  • D. In Resource Manager, edit the organization permissions. Add the project ID as member with the role: Compute Image User.
Show Suggested Answer Hide Answer
Suggested Answer: A

Wyjaśnienie

Potwierdzona odpowiedź: A

Wyjaśnienie:
Ograniczenie polityki organizacji (Organization Policy) o nazwie `compute.trustedimageProjects` jest dedykowanym mechanizmem do kontrolowania, z których projektów mogą pochodzić obrazy używane jako dyski rozruchowe (boot disks) w Twojej organizacji. Konfigurując to ograniczenie na poziomie organizacji i definiując listę "allow" (whitelist), wymuszasz, aby każdy nowy dysk rozruchowy w dowolnym projekcie wewnątrz organizacji korzystał wyłącznie z obrazów przechowywanych w jawnie wskazanych, zaufanych projektach.

Dlaczego pozostałe opcje są niepoprawne:
- B: Choć technicznie można używać reguł "deny", w przypadku `compute.trustedimageProjects` standardową i zalecaną praktyką jest whitelisting (lista allow). Podejście z listą wyjątków w operacji deny jest bardziej skomplikowane w utrzymaniu i mniej bezpieczne (domyślnie pozwala na wszystko, co nie jest zablokowane).
- C: Nadanie roli `Compute Image User` (roles/compute.imageUser) na poziomie projektu pozwala użytkownikom na korzystanie z obrazów w tym projekcie, ale NIE blokuje im możliwości korzystania z obrazów z innych projektów (np. publicznych obrazów Google lub ich własnych projektów). Nie realizuje więc wymogu "ograniczenia" (limit) źródeł.
- D: Dodanie projektu jako członka organizacji z rolą `Compute Image User` nie jest poprawnym sposobem konfiguracji dostępu do obrazów ani nie służy do ograniczania wyboru obrazów dla użytkowników w całej organizacji.

Tips & Tricks:
- Gdy widzisz "limit images" + "boot disks" + "central/organization level", Twoją pierwszą myślą powinno być `compute.trustedimageProjects`.
- Zapamiętaj, że whitelisting (Allow) jest preferowaną metodą dla tej polityki.
- Organization Policy służy do narzucania ograniczeń (constraints), podczas gdy IAM służy do nadawania uprawnień (permissions). Jeśli celem jest zabronienie czegoś (ograniczenie wyboru), używamy Organization Policy.

Zagadnienia:
- Organization Policy Service (Więzy/Constraints)
- Resource Hierarchy (Hierarchia zasobów)
- Trusted Images (Zaufane obrazy)

W egzaminie Google Cloud Security Professional kluczowe jest rozróżnienie między przyznawaniem dostępu (IAM) a narzucaniem ograniczeń (Organization Policy). To pytanie testuje znajomość konkretnego ograniczenia compute.trustedimageProjects, które jest krytyczne dla zapewnienia, że w środowisku uruchamiane są tylko sprawdzone i bezpieczne systemy operacyjne.

Praktyczne wskazówki

  • Zawsze szukaj słów kluczowych takich jak "enforce", "limit", "restrict" na poziomie "Organization" lub "Folder" – to sygnały dla Organization Policy.
  • Pamiętaj, że polityka trustedimageProjects może być dziedziczona, więc ustawienie jej na górze hierarchii zabezpiecza wszystkie podległe projekty.
