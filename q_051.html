Question 51 / 361

You want to limit the images that can be used as the source for boot disks. These images will be stored in a dedicated project. What should you do?

  • A. Use the Organization Policy Service to create a compute.trustedimageProjects constraint on the organization level. List the trusted project as the whitelist in an allow operation.
  • B. Use the Organization Policy Service to create a compute.trustedimageProjects constraint on the organization level. List the trusted projects as the exceptions in a deny operation.
  • C. In Resource Manager, edit the project permissions for the trusted project. Add the organization as member with the role: Compute Image User.
  • D. In Resource Manager, edit the organization permissions. Add the project ID as member with the role: Compute Image User.
Show Suggested Answer Hide Answer
Suggested Answer: A

Wyjaśnienie

Potwierdzona odpowiedź: A

Reguła Egzaminacyjna (Exam Rule):
Gdy wymagane jest narzucenie ograniczeń na poziomie organizacji dla całej hierarchii (np. "limitowanie obrazów", "blokowanie publicznych IP"), pierwszym i jedynym słusznym wyborem w Google Cloud jest Organization Policy Service (polityka organizacji).

Haczyki egzaminacyjne (Exam Traps):
- Zmylenie kandydatów rolami IAM: Opcje C i D sugerują użycie ról IAM (np. Compute Image User) do "ograniczania". Role IAM służą do nadawania uprawnień (autoryzacja), a nie do blokowania/ograniczania wyboru zasobów na poziomie organizacji.
- Zmylenie mechanizmem "deny": Opcja B sugeruje "deny", podczas gdy standardem dla `trustedimageProjects` jest whitelisting (allow), co zapewnia tzw. "default-deny posture" (bezpieczniejszy model).

Głębokie wyjaśnienie techniczne:
Ograniczenie `compute.trustedimageProjects` (Constraint) działa poprzez wstrzyknięcie kontroli w warstwę API Google Compute Engine. Kiedy użytkownik próbuje utworzyć instancję (VM) i wskazuje obraz, Compute Engine sprawdza, czy projekt, w którym znajduje się obraz, znajduje się na dozwolonej liście w polityce. Jeśli nie – operacja zostaje odrzucona przez system. Jest to mechanizm Guardrail, który działa niezależnie od uprawnień IAM użytkownika (nawet jeśli użytkownik ma `Owner`, polityka organizacji zablokuje użycie obrazu z niedozwolonego projektu).
