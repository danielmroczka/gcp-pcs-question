Question 51 / 361

You want to limit the images that can be used as the source for boot disks. These images will be stored in a dedicated project. What should you do?

  • A. Use the Organization Policy Service to create a compute.trustedimageProjects constraint on the organization level. List the trusted project as the whitelist in an allow operation.
  • B. Use the Organization Policy Service to create a compute.trustedimageProjects constraint on the organization level. List the trusted projects as the exceptions in a deny operation.
  • C. In Resource Manager, edit the project permissions for the trusted project. Add the organization as member with the role: Compute Image User.
  • D. In Resource Manager, edit the organization permissions. Add the project ID as member with the role: Compute Image User.
Show Suggested Answer Hide Answer
Suggested Answer: A

Wyjaśnienie

**Poprawna odpowiedź: A**

**1. Kompleksowe wyjaśnienie poprawnej odpowiedzi:**
Wymagane jest zablokowanie możliwości tworzenia dysków startowych z nieautoryzowanych obrazów i dopuszczenie obrazów wyłącznie z jednego, zaufanego i dedykowanego projektu:
- **Skorzystanie z usługi Polityki Organizacji (Organization Policy Service) i nałożenie ograniczenia `compute.trustedimageProjects` na poziomie organizacji, definiując zaufany projekt jako dozwolony (A):** Ograniczenie `compute.trustedimageProjects` to wbudowana reguła polityki organizacji w GCP. Umożliwia ona zdefiniowanie białej listy (whitelist) projektów, z których użytkownicy w całej organizacji mogą pobierać obrazy systemowe do tworzenia maszyn VM. Każda próba użycia obrazu spoza tej listy (np. obrazów publicznych) zostanie natychmiast zablokowana przez system.

**2. Wyjaśnienie niepoprawnych odpowiedzi:**
- **B. Ograniczenie z regułą deny (blokuj):** Ograniczenie `compute.trustedimageProjects` wymaga zdefiniowania projektów, które są zaufane (reguła Allow). Próba definiowania wyjątków przez "Deny" jest nieefektywna i trudna w utrzymaniu, ponieważ domyślnie pozwalałaby na pobieranie obrazów z każdego nowo powstałego projektu w internecie.
- **C. IAM role Compute Image User dla organizacji na projekcie zaufanym:** Nadanie tej roli pozwala użytkownikom na dostęp do obrazów w tym projekcie, ale w żaden sposób nie zabrania im korzystania z innych publicznych lub prywatnych projektów z obrazami (brak wymuszenia ograniczenia).
- **D. IAM role Compute Image User dla projektu na organizacji:** Przypisanie roli IAM w ten sposób jest logicznie niepoprawne i nie blokuje tworzenia dysków ze źródeł zewnętrznych.

**3. Wskazówki i pułapki egzaminacyjne (Tips & Tricks):**
- Ograniczanie źródeł obrazów maszyn wirtualnych w GCP realizuje się wyłącznie za pomocą polityki organizacji z ograniczeniem **`compute.trustedimageProjects`**.
- Pamiętaj, że polityki organizacji (Organization Policies) wymuszają twarde limity (guardrails) niezależnie od uprawnień IAM użytkowników.

**4. Reguły wyboru odpowiedzi:**
- Ograniczenie dozwolonych obrazów maszyn wirtualnych -> Org Policy + `compute.trustedimageProjects` (Allow whitelist).
