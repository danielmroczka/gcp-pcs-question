Question 17 / 361

An employer wants to track how bonus compensations have changed over time to identify employee outliers and correct earning disparities. This task must be performed without exposing the sensitive compensation data for any individual and must be reversible to identify the outlier. Which Cloud Data Loss Prevention API technique should you use to accomplish this?

  • A. Generalization
  • B. Redaction
  • C. CryptoHashConfig
  • D. CryptoReplaceFfxFpeConfig
Show Suggested Answer Hide Answer
Suggested Answer: D

Wyjaśnienie

**Poprawna odpowiedź: D**

**1. Kompleksowe wyjaśnienie poprawnej odpowiedzi:**
Wymagania to:
- Ukrycie wrażliwych danych płacowych pracowników.
- Zachowanie spójności i formatu danych (aby móc analizować trendy i odnajdywać anomalie).
- **Odwracalność procesu** (reversible) – możliwość powrotu do oryginalnych danych pracownika w przypadku wykrycia anomalii.
Te kryteria idealnie spełnia technika z użyciem Cloud DLP:
- **CryptoReplaceFfxFpeConfig (D):** Jest to szyfrowanie zachowujące format (Format-Preserving Encryption - FPE) w trybie FFX. Zastępuje dane wejściowe zaszyfrowanym tokenem o dokładnie takim samym formacie (np. ta sama liczba cyfr czy struktura). Ponieważ jest to proces kryptograficzny oparty na kluczu szyfrującym, uprawniony użytkownik posiadający ten klucz może odszyfrować token i przywrócić oryginalną tożsamość.

**2. Wyjaśnienie niepoprawnych odpowiedzi:**
- **A. Generalization (Generalizacja):** Polega na zastępowaniu szczegółowych wartości przedziałami (np. wiek 25 zamienia na 20-30). Proces ten jest nieodwracalny i uniemożliwia precyzyjne cofnięcie zmian dla konkretnej osoby.
- **B. Redaction (Redagowanie/Usuwanie):** Polega na całkowitym usunięciu tekstu lub zastąpieniu go czarnym blokiem (np. [REDACTED]). Proces ten jest całkowicie nieodwracalny.
- **C. CryptoHashConfig (Haszowanie kryptograficzne):** Haszowanie (np. SHA-256) jest z definicji funkcją jednokierunkową. Nie można odwrócić haszu w celu odczytania oryginalnej wartości (brak odwracalności).

**3. Wskazówki i pułapki egzaminacyjne (Tips & Tricks):**
- Słowo-klucz: **reversible** (odwracalny) oraz **DLP API**. Zapamiętaj, że z technik deidentyfikacji w DLP API tylko **FPE (Format Preserving Encryption)** oraz **Crypto Deterministic Token** pozwalają na pełne odwrócenie procesu (odszyfrowanie).
- Zwykły Hash (C) jest zawsze nieodwracalny.

**4. Reguły wyboru odpowiedzi:**
- Odwracalna deidentyfikacja z zachowaniem formatu w DLP -> CryptoReplaceFfxFpeConfig (FPE).

**5. Dodatkowe źródła:**
- Cloud DLP De-identification techniques: https://cloud.google.com/dlp/docs/deidentify-sensitive-data

Analiza i Podsumowanie Dyskusji (AI)

Analiza i Wyjaśnienie

Sugerowana odpowiedź: D

Analiza spornych kwestii (AI): Głównym punktem analizy jest wymóg 'odwracalności'. Wiele osób wybiera haszowanie (C), myśląc, że jest to standard. Jednak w kryptografii hasz jest z definicji jednostronny. FPE (D) pozwala na zachowanie struktury danych, co jest kluczowe przy analizie w bazach danych, i daje administratorowi posiadającemu klucz drogę powrotną do danych osobowych.
