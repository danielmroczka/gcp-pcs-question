Question 76 / 361

Your company is storing sensitive data in Cloud Storage. You want a key generated on-premises to be used in the encryption process. What should you do?

  • A. Use the Cloud Key Management Service to manage a data encryption key (DEK).
  • B. Use the Cloud Key Management Service to manage a key encryption key (KEK).
  • C. Use customer-supplied encryption keys to manage the data encryption key (DEK).
  • D. Use customer-supplied encryption keys to manage the key encryption key (KEK).
Show Suggested Answer Hide Answer
Suggested Answer: C

Wyjaśnienie

Poprawna odpowiedź: C

Analiza poprawności:
Google Cloud umożliwia korzystanie z kluczy generowanych i zarządzanych przez klienta poza platformą (on-premises).
1. CSEK (Customer-Supplied Encryption Keys): To właśnie mechanizm pozwalający na użycie własnego klucza (dostarczonego przez klienta) do szyfrowania danych w usłudze Cloud Storage. 
2. Mechanizm działania: Klient dostarcza klucz szyfrujący (DEK) w każdym żądaniu wysyłanym do Cloud Storage. Google używa tego klucza do zaszyfrowania danych, po czym klucz ten jest usuwany z pamięci Google – Google go nie przechowuje.

Dlaczego pozostałe są błędne:
A. Cloud KMS DEK: Cloud KMS służy do zarządzania kluczami wewnątrz GCP. W pytaniu mowa jest o kluczu generowanym na miejscu (on-premises), co wyklucza KMS jako zarządcę klucza (KMS nie przechowuje kluczy dostarczanych przez CSEK).
B. Cloud KMS KEK: KEK to klucz szyfrujący inne klucze (w KMS). Użycie KMS wyklucza "customer-supplied encryption key" w kontekście tego konkretnego pytania.
D. CSEK dla KEK: Terminologia CSEK w GCP odnosi się do szyfrowania danych (DEK), a nie do zarządzania KEK w KMS.

Wskazówki egzaminacyjne:
- "Key generated on-premises" = prawie zawsze CSEK.
- "Manage key in Google Cloud" = KMS.
- Pamiętaj: W modelu CSEK to klient odpowiada za przechowywanie klucza. Jeśli go zgubisz – dane są nieodwracalnie stracone.
