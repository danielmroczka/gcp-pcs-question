Question 65 / 361

A customer has an analytics workload running on Compute Engine. Your team created an egress firewall rule to deny (priority 1000) all traffic to the internet. The instances now need to reach out to a public repository for updates. What should you do?

  • A. Create an egress rule to allow traffic to the repository CIDR with priority > 1000.
  • B. Create an egress rule to allow traffic to the repository CIDR with priority < 1000.
  • C. Create an egress rule to allow traffic to the hostname with priority > 1000.
  • D. Create an egress rule to allow traffic to the hostname with priority < 1000.
Show Suggested Answer Hide Answer
Suggested Answer: B

Wyjaśnienie

Potwierdzona odpowiedź: B (Egress allow repository CIDR, priority < 1000)

Wyjaśnienie: 
W Google Cloud VPC Firewall, priorytety reguł są określane przez liczby od 0 do 65535, przy czym niższa liczba oznacza wyższy priorytet. Jeśli istnieje reguła 'deny' o priorytecie 1000, musimy stworzyć regułę 'allow' o priorytecie mniejszym niż 1000 (np. 900), aby została ona przetworzona jako pierwsza i zezwoliła na ruch do konkretnego zakresu CIDR repozytorium.

Dlaczego pozostałe są błędne:
A. Priorytet większy niż 1000 oznacza niższe pierwszeństwo, więc reguła 'deny' (1000) nadal będzie blokować ruch.
C. Reguły firewalla VPC działają w warstwach 3 i 4 (IP/Port), nie obsługują nazw domenowych (hostname). Dodatkowo priorytet jest błędny.
D. Firewall VPC nie obsługuje filtrowania po nazwach hostów.

Wskazówki egzaminacyjne (Tips & Tricks):
Zapamiętaj: Niższy numer = Wyższy priorytet (0 to najwyższy priorytet). Firewall VPC nie rozumie domen (FQDN/Hostname).

Kluczowe zagadnienia do powtórzenia:
- VPC Firewall Rules priority
- Egress/Ingress rules
- VPC Layer 3/4 filtering

Analiza i Podsumowanie Dyskusji (AI)

Analiza i Wyjaśnienie

Sugerowana odpowiedź: B

Głęboka analiza: Najczęstszą pułapką w tym pytaniu jest mylenie numeracji priorytetów firewalla w GCP. Wiele osób myśli, że wyższa liczba to wyższy priorytet, co w GCP jest odwrotne. Dodatkowo, testowana jest znajomość modelu OSI – VPC Firewall to nie jest WAF, więc FQDN/hostname nie wchodzą w grę.
