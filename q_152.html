Question 152 / 361

You need to centralize your team's logs for production projects. You want your team to be able to search and analyze the logs using Logs Explorer. What should you do?

  • A. Enable Cloud Monitoring workspace, and add the production projects to be monitored.
  • B. Use Logs Explorer at the organization level and filter for production project logs.
  • C. Create an aggregate org sink at the parent folder of the production projects, and set the destination to a Cloud Storage bucket.
  • D. Create an aggregate org sink at the parent folder of the production projects, and set the destination to a logs bucket.
Show Suggested Answer Hide Answer
Suggested Answer: D

Wyjaśnienie

Poprawna odpowiedź: D (Create an aggregate org sink at the parent folder of the production projects, and set the destination to a logs bucket)

Dlaczego ta odpowiedź jest poprawna:
- Agregowanie logów (Aggregate Sinks): Pozwala na zbieranie logów z wielu projektów, folderów lub całej organizacji do jednego, centralnego miejsca. 
- Log Bucket: Jest to natywne miejsce przechowywania logów w Cloud Logging. W przeciwieństwie do Cloud Storage, logi w Log Bucket są indeksowane i można je przeszukiwać bezpośrednio za pomocą narzędzia Logs Explorer.
- Centralizacja: Przesyłając logi z folderu "production" do centralnego Log Bucketa w dedykowanym projekcie (np. "security-logs-project"), zespół ma jeden punkt dostępu do analizy wszystkich zdarzeń produkcyjnych.

Analiza niepoprawnych odpowiedzi:
- A. Cloud Monitoring workspace: Cloud Monitoring służy do zbierania metryk, dashboardów i alertów, a nie do centralizacji i przeszukiwania surowych logów (choć oba narzędzia należą do pakietu Operations Suite, ich przeznaczenie jest inne).
- B. Use Logs Explorer at the organization level: Choć możliwe jest przeglądanie logów na poziomie organizacji, nie zapewnia to fizycznej centralizacji logów w jednym miejscu (np. dla potrzeb retencji lub bezpieczeństwa). Ponadto przeszukiwanie całego orgu bez agregacji może być mniej wydajne i trudniejsze do zarządzania uprawnieniami.
- C. Aggregate org sink to a Cloud Storage bucket: Cloud Storage jest doskonałym miejscem na długoterminową archiwizację logów (compliance) ze względu na niskie koszty, ale logi tam składowane NIE są bezpośrednio dostępne w Logs Explorerze. Wymagałoby to ich pobrania lub zaimportowania do BigQuery.

Wskazówki i triki (Tips & Tricks):
- Słowo klucz "Search and analyze using Logs Explorer" + "Centralize" = Log Bucket.
- Słowo klucz "Compliance" / "Long-term storage" / "Archival" = Cloud Storage.
- Słowo klucz "SQL analysis" / "BI tools" = BigQuery.
- Słowo klucz "Real-time streaming" / "Third-party SIEM (Splunk/Datadog)" = Pub/Sub.

Praktyczne informacje na egzamin:
- Zapamiętaj, że Log Buckets oferują teraz funkcję "Log Analytics", która pozwala na zapytania SQL bezpośrednio na logach bez przesyłania ich do BigQuery.
- Zwróć uwagę na zakres (scope) sinka. Jeśli pytanie mówi o projektach produkcyjnych, "parent folder" tych projektów jest idealnym miejscem na umieszczenie sinka agregującego.
