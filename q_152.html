Question 152 / 361

You need to centralize your team's logs for production projects. You want your team to be able to search and analyze the logs using Logs Explorer. What should you do?

  • A. Enable Cloud Monitoring workspace, and add the production projects to be monitored.
  • B. Use Logs Explorer at the organization level and filter for production project logs.
  • C. Create an aggregate org sink at the parent folder of the production projects, and set the destination to a Cloud Storage bucket.
  • D. Create an aggregate org sink at the parent folder of the production projects, and set the destination to a logs bucket.
Show Suggested Answer Hide Answer
Suggested Answer: D

Wyjaśnienie

1. Prawidłowa odpowiedź lub odpowiedzi:
D. Create an aggregate org sink at the parent folder of the production projects, and set the destination to a logs bucket.

2. Kompleksowe wyjaśnienie dlaczego dana odpowiedź jest prawidłowa (Analiza):
Należy scentralizować logi z projektów produkcyjnych w taki sposób, aby zespół mógł je przeszukiwać i analizować bezpośrednio przy użyciu narzędzia Logs Explorer:
- Tworząc zlew logów (Log Sink) na poziomie nadrzędnego folderu (parent folder) z flagą `includeChildren=true` (tzw. Aggregate Sink), automatycznie zbieramy logi ze wszystkich projektów produkcyjnych znajdujących się w tym folderze.
- Aby te logi były przeszukiwalne w Logs Explorerze, celem (destination) agregacji musi być dedykowany kubełek logów (Log Bucket) w centralnym projekcie audytowym. Cloud Logging pozwala na bezpośrednie odpytywanie i przeszukiwanie Log Bucketów za pomocą interfejsu Logs Explorer.

3. Wyjaśnienie z osobna każdej niepoprawnej odpowiedzi:
- A. Włączenie obszaru roboczego Cloud Monitoring: Cloud Monitoring służy do zbierania i wizualizacji metryk wydajnościowych (CPU, RAM, sieć) oraz ustawiania alertów, a nie do agregowania surowych logów tekstowych do analizy w Logs Explorerze.
- B. Użycie Logs Explorera na poziomie organizacji: Pozwala na wyszukiwanie logów w locie, ale bez centralizacji logi pozostają rozproszone po projektach, co utrudnia zarządzanie uprawnieniami dostępu do logów audytowych i nie realizuje wymogu centralizacji ("centralize your team's logs").
- C. Eksport do kubełka Cloud Storage (GCS): Cloud Storage jest świetnym i tanim rozwiązaniem do długoterminowej archiwizacji logów (Cold Storage/Audyt), ale pliki logów są tam zapisywane w formie obiektów JSON/CSV. Nie można ich bezpośrednio przeszukiwać w interaktywnym narzędziu Logs Explorer (wymagałoby to importu do BigQuery lub pobierania plików).

4. Wskazówki, hinty, tips and tricks:
- Aby logi były przeszukiwalne w **Logs Explorer**, celem eksportu musi być **Log Bucket** (`logging.googleapis.com/.../buckets/...`).
- Zlew zagregowany (Aggregate Sink) z opcją `includeChildren` to standardowy sposób zbierania logów z wielu projektów w strukturze folderów/organizacji.

5. Reguły wyboru odpowiedzi (Słowa kluczowe):
- Agregacja logów z wielu projektów w strukturze folderu -> Parent folder aggregate sink.
- Analiza i przeszukiwanie logów w Logs Explorer -> Log Bucket destination.

6. Dodatkowe źródła i dokumentacja:
- Route logs to a log bucket: https://cloud.google.com/logging/docs/routing/overview#destinations
- Aggregated sinks: https://cloud.google.com/logging/docs/export/aggregated_sinks
