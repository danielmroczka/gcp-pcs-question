Question 153 / 361

You need to use Cloud External Key Manager to create an encryption key to encrypt specific BigQuery data at rest in Google Cloud. Which steps should you do first?

  • A. 1. Create or use an existing key with a unique uniform resource identifier (URI) in your Google Cloud project. 2. Grant your Google Cloud project access to a supported external key management partner system.
  • B. 1. Create or use an existing key with a unique uniform resource identifier (URI) in Cloud Key Management Service (Cloud KMS). 2. In Cloud KMS, grant your Google Cloud project access to use the key.
  • C. 1. Create or use an existing key with a unique uniform resource identifier (URI) in a supported external key management partner system. 2. In the external key management partner system, grant access for this key to use your Google Cloud project.
  • D. 1. Create an external key with a unique uniform resource identifier (URI) in Cloud Key Management Service (Cloud KMS). 2. In Cloud KMS, grant your Google Cloud project access to use the key.
Show Suggested Answer Hide Answer
Suggested Answer: C

Wyjaśnienie

1. Prawidłowa odpowiedź lub odpowiedzi:
C. 1. Create or use an existing key with a unique uniform resource identifier (URI) in a supported external key management partner system. 2. In the external key management partner system, grant access for this key to use your Google Cloud project.

2. Kompleksowe wyjaśnienie dlaczego dana odpowiedź jest prawidłowa (Analiza):
Wdrożenie szyfrowania Cloud External Key Manager (EKM) wymaga konfiguracji komunikacji z zewnętrznym dostawcą kluczy (np. Fortanix, Thales):
- Klucz fizyczny (Key Material) w architekturze EKM z założenia musi znajdować się całkowicie poza infrastrukturą Google Cloud.
- Krok 1: Klucz musi zostać utworzony na zewnętrznym urządzeniu HSM partnera, które wygeneruje dla niego unikalny identyfikator URI.
- Krok 2: Aby Google Cloud mogło wysyłać zapytania o zaszyfrowanie/deszyfrowanie, musisz w panelu administracyjnym systemu partnerskiego nadać uprawnienia dostępu (autoryzację) dla tożsamości konta serwisowego usługi KMS z Twojego projektu GCP.

3. Wyjaśnienie z osobna każdej niepoprawnej odpowiedzi:
- A. Tworzenie klucza z URI w projekcie Google Cloud: W systemie EKM nie tworzy się fizycznego klucza wewnątrz projektu GCP. Tworzy się go na zewnętrznym HSM, a w GCP tworzy się jedynie referencję (External Key) wskazującą na zewnętrzny URI.
- B i D. Tworzenie klucza w Cloud KMS: Cloud KMS nie generuje klucza EKM wewnątrz własnej infrastruktury. EKM służy właśnie do tego, aby Google nie miało fizycznego dostępu do surowego materiału klucza w spoczynku.

4. Wskazówki, hinty, tips and tricks:
- W konfiguracji Cloud EKM fizyczny klucz leży u zewnętrznego partnera (External Partner). Pierwszym krokiem jest zawsze wygenerowanie klucza w tym zewnętrznym systemie i pobranie jego URI, a następnie autoryzowanie konta serwisowego GCP w systemie partnera.

5. Reguły wyboru odpowiedzi (Słowa kluczowe):
- Wdrożenie Cloud EKM -> Utworzenie klucza w systemie partnera (external partner system) + nadanie tam uprawnień dla projektu Google Cloud.

6. Dodatkowe źródła i dokumentacja:
- Cloud EKM setup overview: https://cloud.google.com/kms/docs/ekm
