Question 153 / 361

You need to use Cloud External Key Manager to create an encryption key to encrypt specific BigQuery data at rest in Google Cloud. Which steps should you do first?

  • A. 1. Create or use an existing key with a unique uniform resource identifier (URI) in your Google Cloud project. 2. Grant your Google Cloud project access to a supported external key management partner system.
  • B. 1. Create or use an existing key with a unique uniform resource identifier (URI) in Cloud Key Management Service (Cloud KMS). 2. In Cloud KMS, grant your Google Cloud project access to use the key.
  • C. 1. Create or use an existing key with a unique uniform resource identifier (URI) in a supported external key management partner system. 2. In the external key management partner system, grant access for this key to use your Google Cloud project.
  • D. 1. Create an external key with a unique uniform resource identifier (URI) in Cloud Key Management Service (Cloud KMS). 2. In Cloud KMS, grant your Google Cloud project access to use the key.
Show Suggested Answer Hide Answer
Suggested Answer: C

Wyjaśnienie

Poprawna odpowiedź: C (1. Create or use an existing key with a unique URI in a supported external key management partner system. 2. In the external key management partner system, grant access for this key to use your Google Cloud project)

Dlaczego ta odpowiedź jest poprawna:
- Cloud External Key Manager (EKM): Pozwala na szyfrowanie danych w Google Cloud za pomocą kluczy, które są przechowywane i zarządzane poza infrastrukturą Google (u zewnętrznych partnerów, takich jak Equinix, Thales, Fortanix).
- Workflow: Aby zacząć korzystać z EKM, klucz musi najpierw fizycznie istnieć w systemie zewnętrznym. Musisz mieć unikalny identyfikator URI tego klucza. 
- Uprawnienia: Musisz również skonfigurować system zewnętrzny tak, aby "ufał" Twojemu projektowi Google Cloud i pozwalał mu na wysyłanie żądań o użycie tego klucza (wrap/unwrap).

Analiza niepoprawnych odpowiedzi:
- A. Grant access to external system in GCP: To drugi krok. Najpierw musisz stworzyć klucz i nadać uprawnienia "od strony" systemu zewnętrznego.
- B. Create key in Cloud KMS: EKM polega na tym, że klucz NIE jest tworzony w Cloud KMS. W KMS tworzysz tylko "wskaźnik" (EKM key version), który odsyła do zewnętrznego URI.
- D. Create external key in Cloud KMS: Choć w KMS tworzy się zasób typu "External Key", nie jest to pierwszy krok procesu. Bez istniejącego klucza u partnera i nadanych tam uprawnień, próba stworzenia klucza w KMS zakończy się błędem walidacji URI.

Wskazówki i triki (Tips & Tricks):
- Pamiętaj o kolejności: Zewnętrzny Partner (Klucz + URI + ACL) -> Google Cloud (EKM Key + URI).
- EKM to jedyne rozwiązanie w GCP, które daje tzw. "Data Sovereignty" (suwerenność danych) - Google nie może odszyfrować danych bez Twojej zgody w systemie zewnętrznym.

Praktyczne informacje na egzamin:
- Zwróć uwagę na "Key Access Justifications" (KAJ). Jest to funkcja często łączona z EKM, która pozwala Ci zobaczyć powód, dla którego Google chce użyć klucza, i automatycznie odrzucić żądanie, jeśli powód jest nieuzasadniony.
- EKM jest znacznie droższy i trudniejszy w utrzymaniu niż CMEK. Wybieraj go tylko, gdy wymagają tego specyficzne regulacje prawne.
