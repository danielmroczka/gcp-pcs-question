Question 34 / 361

Your company is using Cloud Dataproc for its Spark and Hadoop jobs. You want to be able to create, rotate, and destroy symmetric encryption keys used for the persistent disks used by Cloud Dataproc. Keys can be stored in the cloud.
What should you do?

  • A. Use the Cloud Key Management Service to manage the data encryption key (DEK).
  • B. Use the Cloud Key Management Service to manage the key encryption key (KEK).
  • C. Use customer-supplied encryption keys to manage the data encryption key (DEK).
  • D. Use customer-supplied encryption keys to manage the key encryption key (KEK).
Show Suggested Answer Hide Answer
Suggested Answer: B

Wyjaśnienie

Potwierdzona odpowiedź: B (Use the Cloud Key Management Service to manage the key encryption key (KEK).)

Wyjaśnienie:
Aby zarządzać cyklem życia kluczy (tworzenie, rotacja, niszczenie) przechowywanych w chmurze Google, należy użyć usługi Cloud Key Management Service (KMS). W modelu szyfrowania kopertowego (envelope encryption) stosowanym w GCP, użytkownik zarządza kluczem szyfrującym klucze (KEK - Key Encryption Key), który chroni (szyfruje) klucze danych (DEK - Data Encryption Key). Cloud KMS pozwala na pełną kontrolę nad KEK, w tym na automatyczną rotację i definiowanie polityk dostępu IAM.

Dlaczego pozostałe są błędne:
A. Use the Cloud Key Management Service to manage the data encryption key (DEK): W modelu GCP to system automatycznie zarządza kluczami DEK. Użytkownik zarządza kluczami KEK w KMS, które z kolei szyfrują DEK-i. Nie zarządza się DEK-ami bezpośrednio w KMS.
C. Use customer-supplied encryption keys to manage the data encryption key (DEK): CSEK (Customer-Supplied Encryption Keys) oznacza, że klucze są dostarczane przez użytkownika z zewnątrz przy każdej operacji i nie są trwale przechowywane w chmurze. Pytanie mówi o kluczach, które mogą być przechowywane w chmurze. Dodatkowo, użytkownik nie zarządza bezpośrednio DEK-ami w tym modelu.
D. Use customer-supplied encryption keys to manage the key encryption key (KEK): CSEK nie służy do zarządzania KEK w taki sposób, jak opisano w pytaniu (tworzenie, rotacja, niszczenie wewnątrz infrastruktury chmurowej). Do tego celu służy Cloud KMS (CMEK - Customer-Managed Encryption Keys).

Wskazówki egzaminacyjne (Tips & Tricks):
- Jeśli pytanie wspomina o "zarządzaniu cyklem życia" (create, rotate, destroy) i "kluczach w chmurze", prawie zawsze chodzi o Cloud KMS.
- Pamiętaj o hierarchii: Użytkownik (KMS) -> KEK -> DEK -> Dane.
- "Symmetric encryption keys" w kontekście zarządzania przez użytkownika w chmurze to domyślnie KEK w KMS.

Kluczowe zagadnienia do powtórzenia:
- Szyfrowanie kopertowe (Envelope Encryption)
- Różnica między CMEK (Cloud KMS) a CSEK (Customer-Supplied)
- Zarządzanie kluczami w Cloud KMS

Analiza i Podsumowanie Dyskusji (AI)

Analiza i Wyjaśnienie

Sugerowana odpowiedź: B

Analiza spornych kwestii (AI): Kluczem do zrozumienia tego modelu jest fakt, że kontrola nad kluczem nadrzędnym (KEK) daje Ci "wyłącznik bezpieczeństwa" dla wszystkich danych zaszyfrowanych kluczami DEK z tego "kopertowego" łańcucha. Jeśli zniszczysz KEK, wszystkie dane chronione tym łańcuchem stają się trwale nieczytelne.

Wyjaśnienie Audytowe

Reguła Egzaminacyjna (Exam Rule):
Pamiętaj, że w egzaminie Professional Cloud Security Engineer kluczowe jest wybieranie rozwiązań najmniej uprzywilejowanych (Principle of Least Privilege), zoptymalizowanych kosztowo i spełniających wymogi compliancy (np. CMEK, Data Loss Prevention).

Haczyki egzaminacyjne (Exam Traps):
- Wybór rozwiązań, które wydają się wygodne, ale nie spełniają wymogów bezpieczeństwa (np. zbyt szerokie uprawnienia IAM).
- Mylenie usług: np. Cloud Armor (WAF) z Cloud IAP (Identity-Aware Proxy).

Głębokie wyjaśnienie techniczne (GCP Professional Cloud Security Engineer):
W każdym pytaniu analizuj warstwy: IAM (dostęp), Encryption (at rest/in transit), Logging/Monitoring (Audit Logs, Cloud Logging, Security Command Center) oraz Networking (VPC Service Controls, Firewall Rules). GCP kładzie duży nacisk na współdzieloną odpowiedzialność (Shared Responsibility Model) - klient odpowiada za konfigurację zabezpieczeń wewnątrz usług chmurowych.
