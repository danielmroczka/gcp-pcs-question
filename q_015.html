Question 15 / 361

An application running on a Compute Engine instance needs to read data from a Cloud Storage bucket. Your team does not allow Cloud Storage buckets to be globally readable and wants to ensure the principle of least privilege. Which option meets the requirement of your team?

  • A. Create a Cloud Storage ACL that allows read-only access from the Compute Engine instance's IP address and allows the application to read from the bucket without credentials.
  • B. Use a service account with read-only access to the Cloud Storage bucket, and store the credentials to the service account in the config of the application on the Compute Engine instance.
  • D. Encrypt the data in the Cloud Storage bucket using Cloud KMS, and allow the application to decrypt the data with the KMS key.
Show Suggested Answer Hide Answer
Suggested Answer: C

Wyjaśnienie

**Poprawna odpowiedź: C**

**1. Kompleksowe wyjaśnienie poprawnej odpowiedzi:**
Aplikacja na maszynie VM Compute Engine musi mieć dostęp do prywatnego kubła Cloud Storage (GCS) z zachowaniem zasady minimalnych uprawnień (least privilege) i bez narażania kluczy na wyciek:
- **Użycie konta usługowego (Service Account) z uprawnieniami tylko do odczytu i pobieranie poświadczeń z serwera metadanych instancji (C):** Jest to standardowa, zalecana praktyka Google Cloud. Do maszyny VM przypisuje się konto usługowe. Aplikacja nie potrzebuje żadnych zapisanych plików kluczy (.json) na dysku – biblioteki klienckie Google automatycznie pobierają tymczasowe tokeny dostępu z lokalnego serwera metadanych instancji (`http://metadata.google.internal`). Zapobiega to wyciekowi kluczy i ogranicza uprawnienia.

**2. Wyjaśnienie niepoprawnych odpowiedzi:**
- **A. Cloud Storage ACL oparty na IP:** ACL w Cloud Storage nie obsługują filtrowania na podstawie adresów IP maszyn wirtualnych. Udostępnianie bez uwierzytelniania ("without credentials") narusza zasady bezpieczeństwa.
- **B. Zapisywanie kluczy konta usługowego w konfiguracji aplikacji:** Przechowywanie kluczy prywatnych konta usługowego (plików JSON) na dysku maszyny wirtualnej lub w kodzie aplikacji jest poważnym naruszeniem bezpieczeństwa (ryzyko wycieku w przypadku skompromitowania maszyny lub kodu).
- **D. Szyfrowanie KMS:** Szyfrowanie danych kluczem KMS chroni dane w spoczynku, ale samo w sobie nie zastępuje autoryzacji dostępu do samego kubła Cloud Storage. Maszyna nadal musi uwierzytelnić się, by pobrać obiekt.

**3. Wskazówki i pułapki egzaminacyjne (Tips & Tricks):**
- **NIGDY** nie zapisuj kluczy kont usługowych (Service Account Keys / pliki JSON) na instancjach VM, jeśli aplikacja działa wewnątrz GCP. Serwer metadanych (Metadata Server) dostarcza tokeny automatycznie i bezpiecznie.
- Zasada Least Privilege w GCP w odniesieniu do maszyn VM = Przypisanie Service Account do VM + rola Storage Object Viewer.

**4. Reguły wyboru odpowiedzi:**
- Autoryzacja maszyny VM w GCP do innych usług -> Zawsze używaj konta usługowego przypisanego do VM i pobieraj token z Metadata Server.

**5. Dodatkowe źródła:**
- GCP Service Accounts overview: https://cloud.google.com/compute/docs/access/create-enable-service-accounts-for-instances
