Question 15 / 361

An application running on a Compute Engine instance needs to read data from a Cloud Storage bucket. Your team does not allow Cloud Storage buckets to be globally readable and wants to ensure the principle of least privilege. Which option meets the requirement of your team?

  • A. Create a Cloud Storage ACL that allows read-only access from the Compute Engine instance's IP address and allows the application to read from the bucket without credentials.
  • B. Use a service account with read-only access to the Cloud Storage bucket, and store the credentials to the service account in the config of the application on the Compute Engine instance.
  • C. Use a service account with read-only access to the Cloud Storage bucket to retrieve the credentials from the instance metadata.
  • D. Encrypt the data in the Cloud Storage bucket using Cloud KMS, and allow the application to decrypt the data with the KMS key.
Show Suggested Answer Hide Answer
Suggested Answer: C

Wyjaśnienie

Poprawna odpowiedź: C (Use a service account with read-only access to the Cloud Storage bucket to retrieve the credentials from the instance metadata.)

Analiza poprawności:
To jest "złoty standard" bezpieczeństwa w GCP. Zamiast ręcznie zarządzać kluczami (które mogą wyciec) i przechowywać je w plikach konfiguracyjnych, używamy "tożsamości instancji". Przypisujemy do VM (Compute Engine) konto serwisowe (Service Account) z odpowiednimi uprawnieniami (read-only do bucketu). Aplikacja działająca na tej VM automatycznie (przez biblioteki klienta GCP) pobiera tymczasowe tokeny dostępu z lokalnego serwera metadanych (http://metadata.google.internal). Jest to bezpieczne, nie wymaga zarządzania hasłami i spełnia zasadę najmniejszych uprawnień.

Dlaczego pozostałe są błędne:
A (ACL by IP): Cloud Storage nie oferuje natywnej możliwości ograniczenia dostępu do bucketu na podstawie adresu IP źródłowej instancji Compute Engine. To podejście jest niemożliwe technicznie.
B (Store credentials in config): Przechowywanie kluczy (np. pliki JSON) na dysku maszyny wirtualnej jest skrajnie niebezpieczne. Jeśli haker przejmie VM, natychmiast przejmie też klucze.
D (Encrypt with Cloud KMS): Szyfrowanie danych w bucketcie (KMS) jest świetne dla bezpieczeństwa danych w spoczynku, ale w żaden sposób nie rozwiązuje problemu autoryzacji aplikacji do odczytu bucketu. Aplikacja nadal musi mieć uprawnienia IAM do bucketu, aby w ogóle pobrać obiekt.

Wskazówki egzaminacyjne:
- "Credentials" + "Compute Engine": Jeśli masz opcję użycia "Service Account attached to VM" – to prawie zawsze jest poprawna odpowiedź.
- "No local credentials": Nigdy nie wybieraj odpowiedzi, która sugeruje trzymanie haseł/kluczy w konfiguracji (config).
- Metadata Server: Pamiętaj, że instancje GCP pobierają tożsamość z serwera metadanych (`http://metadata.google.internal`).

Sugerowana odpowiedź: C

Analiza spornych kwestii (AI): Mechanizm ten nazywa się "impersonacją konta serwisowego" przez instancję VM. Jest to fundament bezpieczeństwa w chmurze (IaaS), który całkowicie eliminuje potrzebę "zarządzania hasłami" przez deweloperów.
