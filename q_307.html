Question 307 / 361

Your organization is developing a sophisticated machine learning (ML) model to predict customer behavior for targeted marketing campaigns. The BigQuery dataset used for training includes sensitive personal information. You must design the security controls around the AI/ML pipeline. Data privacy must be maintained throughout the model's lifecycle and you must ensure that personal data is not used in the training process. Additionally, you must restrict access to the dataset to an authorized subset of people only. What should you do?

  • A. De-identify sensitive data before model training by using Cloud Data Loss Prevention (DLP) APIs, and implement strict Identity and Access Management (IAM) policies to control access to BigQuery.
  • B. Implement Identity-Aware Proxy to enforce context-aware access to BigQuery and models based on user identity and device.
  • C. Implement at-rest encryption by using customer-managed encryption keys (CMEK) for the pipeline. Implement strict Identity and Access Management (IAM) policies to control access to BigQuery.
  • D. Deploy the model on Confidential VMs for enhanced protection of data and code while in use. Implement strict Identity and Access Management (IAM) policies to control access to BigQuery.
Show Suggested Answer Hide Answer
Suggested Answer: A

Wyjaśnienie

✅ PRAWIDŁOWA ODPOWIEDŹ: A

Prawidłowa odpowiedź: A – De-identify sensitive data before model training by using Cloud Data Loss Prevention (Cloud DLP).

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
DLACZEGO A JEST PRAWIDŁOWE?
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
Model ML trenowany na danych z BigQuery może przechowywać i "zapamiętywać" wrażliwe dane (PII). De-identyfikacja (tokenizacja, pseudonimizacja, maskowanie) przez Cloud DLP PRZED treningiem eliminuje problem u źródła – model nigdy nie widzi prawdziwych danych PII. To zgodne z zasadą privacy by design i standardami jak GDPR.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
DLACZEGO INNE OPCJE SĄ BŁĘDNE?
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
B. ❌ IAP kontroluje dostęp do aplikacji webowych, nie chroni danych w BigQuery przed modelem ML. Nie rozwiązuje problemu PII w danych treningowych.
C. ❌ CMEK szyfruje dane w spoczynku, ale model ML i tak ma dostęp do odszyfrowanych danych podczas treningu – nie chroni przed PII w modelu.
D. ❌ Confidential VMs chronią dane w użyciu (in-use encryption), ale nie usuwają PII z danych treningowych. Model i tak może "nauczyć się" PII.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
WSKAZÓWKI EGZAMINACYJNE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
• ML + PII w danych treningowych = Cloud DLP de-identification PRZED treningiem.
• CMEK/Confidential VM chronią infrastrukturę, nie usuną PII z danych.
• "Privacy by design" = eliminacja PII przed przetwarzaniem, nie po.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
REGUŁY
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
• Ochrona PII w danych treningowych ML = Cloud DLP de-identification.
• CMEK = encryption at rest (nie usuwa PII).
• Confidential VM = encryption in use (nie usuwa PII).
