Question 307 / 361

Your organization is developing a sophisticated machine learning (ML) model to predict customer behavior for targeted marketing campaigns. The BigQuery dataset used for training includes sensitive personal information. You must design the security controls around the AI/ML pipeline. Data privacy must be maintained throughout the model's lifecycle and you must ensure that personal data is not used in the training process. Additionally, you must restrict access to the dataset to an authorized subset of people only. What should you do?

  • A. De-identify sensitive data before model training by using Cloud Data Loss Prevention (DLP) APIs, and implement strict Identity and Access Management (IAM) policies to control access to BigQuery.
  • B. Implement Identity-Aware Proxy to enforce context-aware access to BigQuery and models based on user identity and device.
  • C. Implement at-rest encryption by using customer-managed encryption keys (CMEK) for the pipeline. Implement strict Identity and Access Management (IAM) policies to control access to BigQuery.
  • D. Deploy the model on Confidential VMs for enhanced protection of data and code while in use. Implement strict Identity and Access Management (IAM) policies to control access to BigQuery.
Show Suggested Answer Hide Answer
Suggested Answer: A

Wskazówki egzaminacyjne (Tips & Tricks)

Reguła Egzaminacyjna (Exam Rule): 
W pytaniach typu 'Security in GCP', zawsze priorytetyzuj rozwiązania natywne (SCC, Cloud KMS, Secret Manager, VPC SC) nad rozwiązaniami typu 'third-party' lub 'self-managed', chyba że scenariusz wymaga specyficznej integracji hybrydowej.

Haczyki egzaminacyjne (Exam Traps):
- Pułapka 'Least Privilege': Egzamin często podpowiada role o szerokim zakresie (np. 'Editor' lub 'Owner') – zawsze odrzucaj je na rzecz ról predefiniowanych o najmniejszym zakresie uprawnień.
- Pułapka 'Logging vs Monitoring': Pamiętaj: Audit Logs służą do badania aktywności (Who/What/When), a Monitoring do zbierania metryk wydajnościowych.

Głębokie wyjaśnienie techniczne:
Każda architektura bezpieczeństwa w GCP powinna być projektowana w oparciu o 'Security by Default'. Oznacza to m.in. szyfrowanie w spoczynku (domyślne), tożsamość opartą na rolach (IAM) oraz pełną widoczność zapewnianą przez scentralizowane logowanie (Cloud Logging/SCC).

Wyjaśnienie

Potwierdzona odpowiedź: A (De-identify sensitive data before model training by using Cloud Data Loss Prevention (DLP) APIs, and implement strict Identity and Access Management (IAM) policies to control access to BigQuery.)

Wyjaśnienie:
- DLP De-identification: Jedyną gwarancją, że dane osobowe 'nie zostaną użyte w treningu' (co mogłoby doprowadzić do wycieku danych przez gotowy model AI), jest ich usunięcie lub zamaskowanie (DLP) przed rozpoczęciem procesu uczenia. DLP API jest do tego dedykowanym i najbardziej skutecznym narzędziem w GCP.

Dlaczego pozostałe odpowiedzi są niepoprawne:
- B. IAP: Kontroluje kto wchodzi do systemu, nie kontroluje treści danych używanych przez algorytmy.
- C. CMEK: Chroni dane przed hakerem z zewnątrz, ale model AI widzi dane odszyfrowane podczas treningu, więc nadal 'widzi' PII i może się ich 'nauczyć'.
- D. Confidential VMs: Chronią pamięć RAM, ale nie zapobiegają 'zapamiętaniu' przez model danych wrażliwych, które mu podasz w zestawie treningowym.

Wskazówki i triki (Tips & Tricks):
- "Format checking" + "PII" + "Security" = DLP + Format-Preserving Encryption (FPE).
- FPE = Zmieniasz dane, zachowujesz ich format/użyteczność.

Praktyczne informacje na egzamin:
- Zapamiętaj: Modele generatywne (LLM) są szczególnie podatne na 'cytowanie' unikalnych danych z zestawu treningowego, dlatego DLP jest krytycznym elementem pipeline'u AI.

Analiza i Podsumowanie (AI)

Kluczowe zagadnienia

Sugerowana odpowiedź: A

Analiza strategiczna: To pytanie testuje Twoją zdolność do projektowania bezpiecznych środowisk testowych/treningowych. W środowiskach AI często używa się danych rzeczywistych, co jest naruszeniem standardów bezpieczeństwa. Użycie natywnych funkcji "De-identification" pozwala zachować użyteczność modelu, przy jednoczesnej eliminacji ryzyka wycieku rzeczywistych danych PII.
