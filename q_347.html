Question 347 / 361

Your company has recently enabled Security Command Center at the organization level. You need to implement runtime threat detection for applications running in containers within projects residing in the production folder. Specifically, you need to be notified if additional libraries are loaded or malicious scripts are executed within these running containers. You need to configure Security Command Center to meet this requirement while ensuring findings are visible within Security Command Center. What should you do?

  • A. Create log-based metrics and alerts in Cloud Logging and Cloud Monitoring for suspicious container activity within the production folder.
  • B. Configure Security Health Analytics within Security Command Center to monitor container runtime vulnerabilities in the production folder.
  • C. Ensure that the containers in the production folder are running on hosts that are using Container-Optimized OS.
  • D. Enable Container Threat Detection in Security Command Center Premium tier for the projects within the production folder.
Show Suggested Answer Hide Answer
Suggested Answer: D

Wyjaśnienie

✅ PRAWIDŁOWA ODPOWIEDŹ: D

Prawidłowa odpowiedź: D – Enable Container Threat Detection in Security Command Center Premium tier for the projects within the production folder.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
DLACZEGO D JEST PRAWIDŁOWE?
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
Container Threat Detection (CTD) to dedykowany moduł SCC Premium który:
- Wykrywa anomalie w runtime kontenerów: ładowanie dodatkowych bibliotek, wykonywanie binary, reverse shells.
- Monitoruje zmiany w systemie plików kontenerów.
- Działa w czasie rzeczywistym na poziomie kernela.
- Integruje się z GKE natively.
To właśnie rozwiązanie dla scenariusza "additional libraries loaded or malicious binary executed".

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
DLACZEGO INNE OPCJE SĄ BŁĘDNE?
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
A. ❌ Log-based metrics = logi aplikacji nie zawierają informacji o ładowaniu bibliotek na poziomie kernela. Brak visibility do runtime behavior.
B. ❌ Security Health Analytics = statyczna analiza konfiguracji (misconfigurations), nie runtime threat detection.
C. ❌ Container-Optimized OS = hardened OS, zmniejsza powierzchnię ataku, ale nie wykrywa runtime threats.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
WSKAZÓWKI EGZAMINACYJNE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
• "Runtime threat detection" + kontenery = Container Threat Detection (SCC Premium).
• SHA = konfiguracja (static), CTD = runtime (dynamic).
• CTD wymaga SCC Premium tier.
• "Additional libraries" + "malicious binary" = CTD keywords.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
REGUŁY
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
• Runtime container security = Container Threat Detection (SCC Premium).
• Static config security = Security Health Analytics.
