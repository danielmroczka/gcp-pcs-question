Question 347 / 361

Your company has recently enabled Security Command Center at the organization level. You need to implement runtime threat detection for applications running in containers within projects residing in the production folder. Specifically, you need to be notified if additional libraries are loaded or malicious scripts are executed within these running containers. You need to configure Security Command Center to meet this requirement while ensuring findings are visible within Security Command Center. What should you do?

  • A. Create log-based metrics and alerts in Cloud Logging and Cloud Monitoring for suspicious container activity within the production folder.
  • B. Configure Security Health Analytics within Security Command Center to monitor container runtime vulnerabilities in the production folder.
  • C. Ensure that the containers in the production folder are running on hosts that are using Container-Optimized OS.
  • D. Enable Container Threat Detection in Security Command Center Premium tier for the projects within the production folder.
Show Suggested Answer Hide Answer
Suggested Answer: D

Wyjaśnienie

Poprawna odpowiedź: D (Enable Container Threat Detection in Security Command Center Premium tier for the projects within the production folder.)

Dlaczego ta odpowiedź jest poprawna:
- Container Threat Detection: Jest to dedykowana usługa w SCC Premium, która wykrywa "runtime threats" (np. uruchomienie złośliwego skryptu, ładowanie nieoczekiwanych bibliotek w kontenerach).
- "Runtime threat detection": To bezpośrednie zadanie dla tej usługi.

Analiza niepoprawnych odpowiedzi:
- A. Cloud Logging/Monitoring: Można stworzyć alerty, ale wymaga to manualnego definiowania reguł, a nie jest gotową, zarządzaną usługą detekcji zagrożeń w czasie rzeczywistym.
- B. Security Health Analytics: Służy do skanowania *konfiguracji* (misconfigurations), a nie do detekcji zagrożeń w *runtime* (uruchomionym kontenerze).
- C. Container-Optimized OS: To system operacyjny (OS), który jest bezpieczniejszy, ale samo jego użycie nie daje detekcji zagrożeń w runtime.

Wskazówki i triki (Tips & Tricks):
- "Runtime threat detection" + "Container" = Container Threat Detection (SCC Premium).

Praktyczne informacje na egzamin:
- Zapamiętaj: Container Threat Detection jest częścią Security Command Center Premium.

Dokumentacja i linki:
- Container Threat Detection overview

Wskazówki egzaminacyjne (Tips & Tricks)

Reguła Egzaminacyjna (Exam Rule): 
W pytaniach typu 'Security in GCP', zawsze priorytetyzuj rozwiązania natywne (SCC, Cloud KMS, Secret Manager, VPC SC) nad rozwiązaniami typu 'third-party' lub 'self-managed', chyba że scenariusz wymaga specyficznej integracji hybrydowej.

Haczyki egzaminacyjne (Exam Traps):
- Pułapka 'Least Privilege': Egzamin często podpowiada role o szerokim zakresie (np. 'Editor' lub 'Owner') – zawsze odrzucaj je na rzecz ról predefiniowanych o najmniejszym zakresie uprawnień.
- Pułapka 'Logging vs Monitoring': Pamiętaj: Audit Logs służą do badania aktywności (Who/What/When), a Monitoring do zbierania metryk wydajnościowych.

Głębokie wyjaśnienie techniczne:
Każda architektura bezpieczeństwa w GCP powinna być projektowana w oparciu o 'Security by Default'. Oznacza to m.in. szyfrowanie w spoczynku (domyślne), tożsamość opartą na rolach (IAM) oraz pełną widoczność zapewnianą przez scentralizowane logowanie (Cloud Logging/SCC).

Kluczowe zagadnienia

Sugerowana odpowiedź: D

Analiza strategiczna: Pytanie sprawdzające umiejętność doboru odpowiedniego narzędzia detekcji zagrożeń w GCP. Kluczowe jest rozróżnienie skanowania konfiguracji (SHA) od detekcji zagrożeń w czasie rzeczywistym w kontenerach (Container Threat Detection).
