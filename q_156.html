Question 156 / 361

Your company plans to move most of its IT infrastructure to Google Cloud. They want to leverage their existing on-premises Active Directory as an identity provider for Google Cloud. Which two steps should you take to integrate the company's on-premises Active Directory with Google Cloud and configure access management? (Choose two.)

  • A. Use Identity Platform to provision users and groups to Google Cloud.
  • B. Use Cloud Identity SAML integration to provision users and groups to Google Cloud.
  • C. Install Google Cloud Directory Sync and connect it to Active Directory and Cloud Identity.
  • D. Create Identity and Access Management (IAM) roles with permissions corresponding to each Active Directory group.
  • E. Create Identity and Access Management (IAM) groups with permissions corresponding to each Active Directory group.
Show Suggested Answer Hide Answer
Suggested Answer: CE

Wyjaśnienie

1. Prawidłowa odpowiedź lub odpowiedzi:
C. Install Google Cloud Directory Sync and connect it to Active Directory and Cloud Identity.
E. Create Identity and Access Management (IAM) groups with permissions corresponding to each Active Directory group.

2. Kompleksowe wyjaśnienie dlaczego dana odpowiedź jest prawidłowa (Analiza):
Firma przenosi infrastrukturę do GCP i chce zintegrować lokalne Active Directory w celu zarządzania tożsamościami i dostępem:
- C (Synchronizacja tożsamości): GCDS (Google Cloud Directory Sync) to darmowe, oficjalne narzędzie instalowane lokalnie, które synchronizuje użytkowników, grupy i członkostwa z lokalnego Active Directory bezpośrednio do Google Cloud Identity w jedną stronę.
- E (Konfiguracja uprawnień IAM): Najlepszą praktyką bezpieczeństwa (szczególnie przy integracji z AD) jest tworzenie grup w Google Cloud/Cloud Identity odpowiadających grupom w AD, a następnie przypisywanie ról IAM tym grupom. Dzięki temu uprawnienia są automatycznie dziedziczone przez zsynchronizowanych użytkowników na podstawie ich członkostwa w grupach lokalnych.

3. Wyjaśnienie z osobna każdej niepoprawnej odpowiedzi:
- A. Użycie Identity Platform: Identity Platform służy do uwierzytelniania klientów zewnętrznych (np. użytkowników aplikacji mobilnej/webowej), a nie do synchronizacji tożsamości korporacyjnych pracowników z Active Directory.
- B. Użycie integracji SAML do provisioningu: SAML (Security Assertion Markup Language) służy do uwierzytelniania jednokrotnego (SSO - Single Sign-On), czyli weryfikacji haseł. Sam protokół SAML nie synchronizuje (nie provisionuje) struktury grup i kont użytkowników do Cloud Identity, co jest wymagane przed przypisaniem uprawnień IAM.
- D. Tworzenie ról IAM dla każdej grupy AD: Tworzenie niestandardowych ról IAM (Custom Roles) dla każdej grupy jest skomplikowane i nieefektywne. Należy korzystać z ról predefiniowanych (Predefined Roles) i przypisywać je grupom chmurowym (E).

4. Wskazówki, hinty, tips and tricks:
- Integracja Active Directory z GCP zawsze wymaga:
  1. Synchronizacji tożsamości za pomocą **GCDS** (Google Cloud Directory Sync).
  2. Uwierzytelniania SSO (SAML IdP, np. AD FS).
  3. Nadawania uprawnień IAM na poziomie **Grup Google** (Google Groups), a nie kont indywidualnych.

5. Reguły wyboru odpowiedzi (Słowa kluczowe):
- Integracja Active Directory + GCP Access Control -> GCDS (provisioning) + IAM roles assigned to Groups.
