Question 156 / 361

Your company plans to move most of its IT infrastructure to Google Cloud. They want to leverage their existing on-premises Active Directory as an identity provider for Google Cloud. Which two steps should you take to integrate the company's on-premises Active Directory with Google Cloud and configure access management? (Choose two.)

  • A. Use Identity Platform to provision users and groups to Google Cloud.
  • B. Use Cloud Identity SAML integration to provision users and groups to Google Cloud.
  • C. Install Google Cloud Directory Sync and connect it to Active Directory and Cloud Identity.
  • D. Create Identity and Access Management (IAM) roles with permissions corresponding to each Active Directory group.
  • E. Create Identity and Access Management (IAM) groups with permissions corresponding to each Active Directory group.
Show Suggested Answer Hide Answer
Suggested Answer: CE

Wyjaśnienie

Poprawna odpowiedź: CE (C: Install GCDS, E: Create IAM groups with permissions)

Dlaczego te odpowiedzi są poprawne:
- Google Cloud Directory Sync (GCDS): Jest to standardowe narzędzie (agent instalowany lokalnie), które synchronizuje użytkowników i grupy z lokalnego Active Directory do Cloud Identity / Google Workspace. Jest to proces tzw. "Provisioning", czyli zapewnienie, że tożsamości z AD istnieją w Google Cloud.
- Zarządzanie dostępem przez grupy: Najlepszą praktyką bezpieczeństwa (i standardem w GCP) jest nadawanie uprawnień (ról IAM) całym grupom, a nie pojedynczym użytkownikom. Dzięki synchronizacji grup przez GCDS, administrator może zarządzać dostępem do zasobów chmurowych poprzez zmianę członkostwa w grupach wewnątrz lokalnego Active Directory.

Analiza niepoprawnych odpowiedzi:
- A. Identity Platform: Jest to rozwiązanie przeznaczone do zarządzania tożsamościami klientów (B2C/B2B) w Twoich aplikacjach, a nie do integracji pracowniczej (workforce) Active Directory z konsolą Google Cloud.
- B. Cloud Identity SAML integration: SAML służy do autentykacji (Single Sign-On - SSO), czyli pozwala użytkownikom na logowanie się do Google Cloud za pomocą ich haseł z AD. SAML sam w sobie nie służy do masowego tworzenia (provisioningu) użytkowników i grup (choć istnieje mechanizm Just-in-Time provisioning, nie jest on tak kompletny jak GCDS dla grup).
- D. Create IAM roles: Role IAM to zestawy uprawnień (np. Storage Admin). Nie tworzysz ról "odpowiadających grupom", lecz przypisujesz istniejące (lub własne) role do zsynchronizowanych grup.

Wskazówki i triki (Tips & Tricks):
- GCDS = Provisioning (Synchronizacja tożsamości).
- SAML = Authentication (Logowanie/SSO).
- Zawsze zarządzaj dostępem przez GRUPY (Groups over Users).

Praktyczne informacje na egzamin:
- Zapamiętaj, że GCDS jest procesem jednokierunkowym (One-way sync). Zmiany dokonane w Google Cloud NIE zostaną przeniesione do Active Directory.
- Pamiętaj o kolejności: Najpierw synchronizujesz tożsamości (GCDS), a potem konfigurujesz logowanie (SAML/SSO).
