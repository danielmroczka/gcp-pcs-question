Question 100 / 361

You need to implement an encryption at-rest strategy that reduces key management complexity for non-sensitive data and protects sensitive data while providing the flexibility of controlling the key residency and rotation schedule. FIPS 140-2 L1 compliance is required for all data types. What should you do?

  • A. Encrypt non-sensitive data and sensitive data with Cloud External Key Manager.
  • B. Encrypt non-sensitive data and sensitive data with Cloud Key Management Service
  • C. Encrypt non-sensitive data with Google default encryption, and encrypt sensitive data with Cloud External Key Manager.
  • D. Encrypt non-sensitive data with Google default encryption, and encrypt sensitive data with Cloud Key Management Service.
Show Suggested Answer Hide Answer
Suggested Answer: D

Wyjaśnienie

1. Prawidłowa odpowiedź lub odpowiedzi:
D. Encrypt non-sensitive data with Google default encryption, and encrypt sensitive data with Cloud Key Management Service.

2. Kompleksowe wyjaśnienie dlaczego dana odpowiedź jest prawidłowa (Analiza):
Wymaganie polega na zbalansowaniu bezpieczeństwa i złożoności zarządzania kluczami dla dwóch rodzajów danych (zwykłych i wrażliwych), przy zachowaniu zgodności z FIPS 140-2 L1:
- Domyślne szyfrowanie GCP (Google default encryption at-rest) automatycznie szyfruje wszystkie dane w spoczynku bez jakichkolwiek działań administracyjnych ze strony użytkownika (zerowa złożoność). Jest ono w pełni zgodne z normą FIPS 140-2 L1.
- Dla danych wrażliwych użycie Customer-Managed Encryption Keys (CMEK) za pośrednictwem Cloud KMS pozwala użytkownikowi na pełną elastyczność i kontrolę nad rotacją kluczy (rotation schedule) oraz lokalizacją ich przechowywania (key residency). Cloud KMS również spełnia normę FIPS 140-2 L1.
Połączenie tych dwóch podejść minimalizuje narzut operacyjny przy jednoczesnym spełnieniu wymagań compliance i kontroli.

3. Wyjaśnienie z osobna każdej niepoprawnej odpowiedzi:
- A. Szyfrowanie wszystkich danych przy użyciu Cloud External Key Manager (EKM): EKM przechowuje klucze poza środowiskiem Google Cloud, co generuje olbrzymią złożoność operacyjną, opóźnienia sieciowe oraz koszty. Stosowanie tego dla danych niewrażliwych narusza wymóg minimalizacji złożoności.
- B. Szyfrowanie wszystkich danych za pomocą Cloud KMS: Wymagałoby to ręcznego tworzenia, rotowania i zarządzania kluczami dla danych nieistotnych, co niepotrzebnie zwiększa złożoność administracyjną (management complexity).
- C. Szyfrowanie danych wrażliwych za pomocą Cloud EKM: External Key Manager jest rozwiązaniem nadmiarowym w tym scenariuszu. Cloud KMS (CMEK) w zupełności wystarcza do kontroli rotacji i rezydencji kluczy bez wprowadzania dodatkowej złożoności integracji z zewnętrznym HSM.

4. Wskazówki, hinty, tips and tricks:
- GCP domyślnie szyfruje wszystkie dane w spoczynku. Jeśli dane nie są poufne i nie wymagają specyficznej rotacji/kontroli klienta, zawsze wybieraj domyślne szyfrowanie (default encryption), aby zminimalizować złożoność.
- Jeśli wymagana jest kontrola nad rezydencją (key residency) i rotacją (rotation schedule), właściwym wyborem jest Cloud KMS (CMEK).

5. Reguły wyboru odpowiedzi (Słowa kluczowe):
- Zwykłe dane (low complexity) + Wrażliwe dane (rotation/residency control) -> Default Encryption + Cloud KMS (CMEK).
- Zgodność FIPS 140-2 L1 -> Zarówno Default Encryption, jak i Cloud KMS spełniają ten wymóg (dla L3 wymagany jest Cloud HSM).

6. Dodatkowe źródła i dokumentacja:
- Google Cloud Encryption at Rest: https://cloud.google.com/security/encryption-at-rest
- Cloud KMS compliance (FIPS 140-2): https://cloud.google.com/kms/docs/fips-140-2

Głęboka analiza:

Analiza spornych kwestii (AI): Pytanie to testuje zrozumienie 'Risk-based security'. Nie wszystko musi być chronione najdroższą i najtrudniejszą metodą. Analiza odpowiedzi na forach pokazuje, że Google promuje model, w którym domyślne zabezpieczenia platformy są 'wystarczająco dobre' dla większości danych, a KMS jest rezerwowany dla danych wymagających ścisłego nadzoru klienta.
