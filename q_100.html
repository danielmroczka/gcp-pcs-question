Question 100 / 361

You need to implement an encryption at-rest strategy that reduces key management complexity for non-sensitive data and protects sensitive data while providing the flexibility of controlling the key residency and rotation schedule. FIPS 140-2 L1 compliance is required for all data types. What should you do?

  • A. Encrypt non-sensitive data and sensitive data with Cloud External Key Manager.
  • B. Encrypt non-sensitive data and sensitive data with Cloud Key Management Service
  • C. Encrypt non-sensitive data with Google default encryption, and encrypt sensitive data with Cloud External Key Manager.
  • D. Encrypt non-sensitive data with Google default encryption, and encrypt sensitive data with Cloud Key Management Service.
Show Suggested Answer Hide Answer
Suggested Answer: D

Wyjaśnienie

Potwierdzona odpowiedź: D (Default encryption + Cloud KMS)

Wyjaśnienie: 
Strategia zbalansowana: 1. Dane zwykłe szyfrujemy domyślnie (Google default), co nie wymaga zarządzania kluczami (zero complexity). 2. Dane wrażliwe szyfrujemy za pomocą Cloud KMS (CMEK), co daje kontrolę nad rotacją i rezydencją. Oba rozwiązania spełniają wymóg FIPS 140-2 L1.

Dlaczego pozostałe są błędne:
A, B. Używanie KMS/EKM dla wszystkich danych (nawet tych nieistotnych) zwiększa niepotrzebnie złożoność i koszty.
C. External Key Manager (EKM) jest najbardziej złożonym rozwiązaniem i zazwyczaj stosuje się go tylko dla najbardziej rygorystycznych wymogów compliance, gdzie klucz musi być poza Google.

Wskazówki egzaminacyjne (Tips & Tricks):
Mieszaj poziomy szyfrowania, aby zoptymalizować 'operational overhead' (złożoność).

Kluczowe zagadnienia do powtórzenia:
- Encryption at rest strategy
- Default vs CMEK vs CSEK vs EKM
- Compliance (FIPS 140-2)

Dokumentacja:
https://cloud.google.com/security/encryption-at-rest

Analiza i Podsumowanie Dyskusji (AI)

Analiza i Wyjaśnienie

Sugerowana odpowiedź: D

Głęboka analiza:

Analiza spornych kwestii (AI): Pytanie to testuje zrozumienie 'Risk-based security'. Nie wszystko musi być chronione najdroższą i najtrudniejszą metodą. Analiza odpowiedzi na forach pokazuje, że Google promuje model, w którym domyślne zabezpieczenia platformy są 'wystarczająco dobre' dla większości danych, a KMS jest rezerwowany dla danych wymagających ścisłego nadzoru klienta.
