Question 162 / 361

Which Identity-Aware Proxy role should you grant to an Identity and Access Management (IAM) user to access HTTPS resources?

  • A. Security Reviewer
  • B. IAP-Secured Tunnel User
  • C. IAP-Secured Web App User
  • D. Service Broker Operator
Show Suggested Answer Hide Answer
Suggested Answer: C

Wyjaśnienie

Poprawna odpowiedź: C (IAP-Secured Web App User)

Dlaczego ta odpowiedź jest poprawna:
- Identity-Aware Proxy (IAP): Pozwala na kontrolowanie dostępu do aplikacji HTTP(S) oraz zasobów TCP (jak SSH/RDP) w oparciu o tożsamość użytkownika, bez konieczności używania VPN.
- IAP-Secured Web App User: Jest to specyficzna rola IAM wymagana do uzyskania dostępu do zasobów HTTPS chronionych przez IAP (np. aplikacji App Engine, usług Cloud Run lub backendów Load Balancera). Bez tej roli, nawet jeśli użytkownik przejdzie pomyślnie autentykację Google, IAP odrzuci jego żądanie dostępu (autoryzacja).

Analiza niepoprawnych odpowiedzi:
- A. Security Reviewer: Jest to rola ogólna, która pozwala na przeglądanie konfiguracji zabezpieczeń w GCP, ale nie nadaje uprawnień do korzystania z konkretnych aplikacji chronionych przez IAP.
- B. IAP-Secured Tunnel User: Ta rola służy do korzystania z funkcji "TCP Forwarding" w IAP. Pozwala ona na tunelowanie ruchu (np. SSH lub RDP) do instancji VM, które nie mają publicznych adresów IP. Nie nadaje ona uprawnień do bezpośredniego dostępu do aplikacji webowych HTTPS.
- D. Service Broker Operator: Jest to rola związana z zarządzaniem Service Brokerami w środowiskach takich jak Anthos lub Kubernetes, nie ma bezpośredniego związku z dostępem użytkowników do aplikacji przez IAP.

Wskazówki i triki (Tips & Tricks):
- "HTTPS resources" + "IAP" = Web App User.
- "SSH/RDP" / "TCP Tunneling" + "IAP" = Tunnel User.
- Zapamiętaj: IAP sprawdza tożsamość (Kim jesteś?) i rolę (Czy masz uprawnienie Web App User?).

Praktyczne informacje na egzamin:
- IAP działa na warstwie 7 (HTTP/S) i warstwie 4 (TCP).
- Aby IAP działał dla aplikacji webowej, musi ona znajdować się za External HTTP(S) Load Balancerem lub być częścią App Engine.
- Rola 'IAP-Secured Web App User' może być nadana na poziomie projektu, ale dobrą praktyką jest nadawanie jej na poziomie konkretnego zasobu (backendu).
