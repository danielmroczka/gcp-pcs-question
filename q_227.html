Question 227 / 361

You are migrating your users to Google Cloud. There are cookie replay attacks with Google web and Google Cloud CLI SDK sessions on endpoint devices. You need to reduce the risk of these threats. What should you do? (Choose two.)

  • A. Configure Google session control to a shorter duration.
  • B. Set an organizational policy for OAuth 2.0 access token with a shorter duration.
  • C. Set a reauthentication policy for Google Cloud services to a shorter duration.
  • D. Configure a third-party identity provider with session management.
  • E. Enforce Security Key Authentication with 2SV.
Show Suggested Answer Hide Answer
Suggested Answer: AE

Wyjaśnienie

1. Prawidłowa odpowiedź lub odpowiedzi:
A. Configure Google session control to a shorter duration.
E. Enforce Security Key Authentication with 2SV.

2. Kompleksowe wyjaśnienie dlaczego dana odpowiedź jest prawidłowa (Analiza):
Odpowiedzi A i E są prawidłowe, ponieważ bezpośrednio utrudniają przechwycenie i ponowne użycie (replay) ciasteczek sesyjnych (session cookies) oraz poświadczeń użytkowników przez złośliwe oprogramowanie na stacjach klienckich.

Analiza techniczna:
a. **Krótszy czas trwania sesji (A):** Skrócenie czasu ważności sesji w konsoli administracyjnej ogranicza czas przydatności skradzionego ciasteczka sesyjnego. Nawet jeśli napastnik przechwyci ciastko (cookie), szybko straci ono ważność, zmuszając użytkownika do ponownej weryfikacji.
b. **Klucze bezpieczeństwa (Security Keys - FIDO2/WebAuthn) (E):** Wymuszenie fizycznych kluczy bezpieczeństwa jako drugiego składnika (2SV) chroni przed wieloma wektorami ataków. Standard FIDO2 opiera się na kryptografii asymetrycznej i jest odporny na phishing oraz przechwycenie sesji w locie. Tokeny autoryzacyjne FIDO2 są powiązane z konkretną domeną (origin-bound), co uniemożliwia ich ponowne użycie na fałszywych witrynach i utrudnia ataki typu man-in-the-middle / session replay.

3. Wyjaśnienie z osobna każdej niepoprawnej odpowiedzi:
B. Set an organizational policy for OAuth 2.0 access token with a shorter duration.
   * Dlaczego nieprawidłowa: Polityki organizacji w GCP nie posiadają natywnej funkcji bezpośredniej zmiany domyślnego czasu życia standardowych tokenów dostępu użytkowników OAuth 2.0. Zarządzanie sesjami odbywa się centralnie w konsoli administracyjnej Cloud Identity/Workspace.
C. Set a reauthentication policy for Google Cloud services to a shorter duration.
   * Dlaczego nieprawidłowa: Reauthentication policy (częstotliwość ponownego logowania) chroni przed pozostawieniem aktywnego CLI na odblokowanym laptopie, ale w przypadku zaawansowanego cookie replay (gdzie napastnik kopiuje ciasteczka sesyjne z przeglądarki) sama ta opcja bez wymuszenia sprzętowego klucza FIDO (opcja E) nie chroni w pełni przed ponownym użyciem skopiowanej tożsamości z innej maszyny.
D. Configure a third-party identity provider with session management.
   * Dlaczego nieprawidłowa: Przeniesienie zarządzania sesją do zewnętrznego dostawcy tożsamości (IdP) nie eliminuje podatności po stronie Google – po pomyślnym uwierzytelnieniu w zewnętrznym IdP, Google i tak wystawia własne ciasteczka sesyjne (GCP session cookies) na stacji użytkownika, które nadal byłyby podatne na ataki replay.

4. Wskazówki, hinty, tips and tricks:
* Najlepsza ochrona przed phishingiem i man-in-the-middle / session replay -> **FIDO2 Security Keys** (np. YubiKey).
* Zarządzanie czasem życia sesji w Google odbywa się przez **Google session control**.

5. Reguły wyboru odpowiedzi (Słowa kluczowe):
* Cookie replay attacks protection -> Google session control + Security Key (FIDO/2SV).

6. Dodatkowe źródła and dokumentacja:
Control Google session length
Enforce 2-Step Verification with security keys

Wskazówki egzaminacyjne (Tips & Tricks)

Reguła Egzaminacyjna (Exam Rule): 
Jeśli scenariusz dotyczy zabezpieczania zasobów chmurowych (GCP), zawsze wybieraj rozwiązanie typu Managed (SCC, Secret Manager, Cloud KMS), a unikaj rozwiązań self-managed, chyba że pytanie wyraźnie wymaga dostosowania niskopoziomowego.

Haczyki egzaminacyjne (Exam Traps):
- Pułapka IAM: Pytania o uprawnienia często sugerują 'Project Owner' – zawsze szukaj 'Least Privilege' (np. 'Role: Secret Manager Secret Accessor').
- Pułapka Sieciowa: Często mylone są VPC Peering (wydajność) oraz VPN (szyfrowanie/on-premise).

Głębokie wyjaśnienie techniczne:
Rozwiązanie bazuje na GCP Shared Responsibility Model. Google zarządza bezpieczeństwem infrastruktury (Physical, Network, Host), podczas gdy administrator zarządza tożsamością (IAM), danymi (Encryption, Cloud KMS) i regułami dostępu (VPC Firewall).

Analiza i Podsumowanie (AI)

Kluczowe zagadnienia

Sugerowana odpowiedź: AE

Analiza strategiczna: To pytanie uderza w fundamenty ochrony tożsamości. Kradzież ciasteczek sesyjnych to obecnie jeden z najpopularniejszych sposobów omijania nawet silnego MFA (typu SMS/Google Prompt). Tylko klucze sprzętowe (FIDO) eliminują ten wektor ataku, a Session Control ogranicza "okno czasowe" dla atakującego.
