Question 227 / 361

You are migrating your users to Google Cloud. There are cookie replay attacks with Google web and Google Cloud CLI SDK sessions on endpoint devices. You need to reduce the risk of these threats. What should you do? (Choose two.)

  • A. Configure Google session control to a shorter duration.
  • B. Set an organizational policy for OAuth 2.0 access token with a shorter duration.
  • C. Set a reauthentication policy for Google Cloud services to a shorter duration.
  • D. Configure a third-party identity provider with session management.
  • E. Enforce Security Key Authentication with 2SV.
Show Suggested Answer Hide Answer
Suggested Answer: AE

Wyjaśnienie

Potwierdzona odpowiedź: AE (A: Configure Google session control to a shorter duration, E: Enforce Security Key Authentication with 2SV)

Wyjaśnienie:
- Session duration (A): Skrócenie czasu trwania sesji (Session duration) oznacza, że sesja wygasa szybciej. Wymusza to na użytkowniku ponowne logowanie, co unieważnia skradzione pliki cookie sesji po upływie czasu.
- Security Key Authentication (2SV) (E): Klucze bezpieczeństwa (np. FIDO2/WebAuthn) są jedyną metodą MFA całkowicie odporną na ataki typu "man-in-the-middle" (MITM) oraz "cookie replay". Nawet jeśli atakujący zdobędzie sesję, nie będzie mógł "odtworzyć" (replay) procesu logowania z kluczem fizycznym, ponieważ klucz jest przypisany do konkretnego originu (domeny).

Dlaczego pozostałe odpowiedzi są niepoprawne:
- B. OAuth 2.0 access token: To ustawienie dotyczy technicznych tokenów dostępu używanych przez aplikacje (np. z gcloud), a nie sesji użytkownika w przeglądarce. Nie chroni przed przejęciem sesji webowych.
- C. Reauthentication policy: (Opcja zamienna z A). Choć "reauthentication frequency" jest również bardzo dobrą metodą, "session control duration" w połączeniu z Security Keys (E) jest klasyczną odpowiedzią egzaminacyjną na problem cookie replay.
- D. Third-party identity provider: Federacja z zewnętrznym IdP sama w sobie nie chroni przed przejęciem sesji Google, jeśli po zalogowaniu do IdP nie zostaną wdrożone odpowiednie mechanizmy po stronie Google (session management).

Wskazówki i triki (Tips & Tricks):
- "Cookie replay" / "Session hijacking" = Zawsze Security Key (E) + skrócenie czasu sesji (A lub C).
- Pamiętaj: Security Key (MFA) to najlepsza ochrona przed phishingiem i przejęciem sesji.

Praktyczne informacje na egzamin:
- Zrozum: Skrócenie czasu sesji to podstawowy element "Security Hygiene" w organizacjach wysokiego ryzyka.
- Współczesne ataki na sesje często wykorzystują "session proxy" (np. Evilginx), co sprawia, że Security Keys są absolutnie niezbędne dla ochrony sesji.

Wskazówki egzaminacyjne (Tips & Tricks)

Reguła Egzaminacyjna (Exam Rule): 
Jeśli scenariusz dotyczy zabezpieczania zasobów chmurowych (GCP), zawsze wybieraj rozwiązanie typu Managed (SCC, Secret Manager, Cloud KMS), a unikaj rozwiązań self-managed, chyba że pytanie wyraźnie wymaga dostosowania niskopoziomowego.

Haczyki egzaminacyjne (Exam Traps):
- Pułapka IAM: Pytania o uprawnienia często sugerują 'Project Owner' – zawsze szukaj 'Least Privilege' (np. 'Role: Secret Manager Secret Accessor').
- Pułapka Sieciowa: Często mylone są VPC Peering (wydajność) oraz VPN (szyfrowanie/on-premise).

Głębokie wyjaśnienie techniczne:
Rozwiązanie bazuje na GCP Shared Responsibility Model. Google zarządza bezpieczeństwem infrastruktury (Physical, Network, Host), podczas gdy administrator zarządza tożsamością (IAM), danymi (Encryption, Cloud KMS) i regułami dostępu (VPC Firewall).

Analiza i Podsumowanie (AI)

Kluczowe zagadnienia

Sugerowana odpowiedź: AE

Analiza strategiczna: To pytanie uderza w fundamenty ochrony tożsamości. Kradzież ciasteczek sesyjnych to obecnie jeden z najpopularniejszych sposobów omijania nawet silnego MFA (typu SMS/Google Prompt). Tylko klucze sprzętowe (FIDO) eliminują ten wektor ataku, a Session Control ogranicza "okno czasowe" dla atakującego.
