Question 183 / 361

Your company conducts clinical trials and needs to analyze the results of a recent study that are stored in BigQuery. The interval when the medicine was taken contains start and stop dates. The interval data is critical to the analysis, but specific dates may identify a particular batch and introduce bias. You need to obfuscate the start and end dates for each row and preserve the interval data.
What should you do?

  • A. Use date shifting with the context set to the unique ID of the test subject.
  • B. Extract the date using TimePartConfig from each date field and append a random month and year.
  • C. Use bucketing to shift values to a predetermined date based on the initial value.
  • D. Use the FFX mode of format preserving encryption (FPE) and maintain data consistency.
Show Suggested Answer Hide Answer
Suggested Answer: A

Wyjaśnienie

Potwierdzona odpowiedź: A (Use date shifting with the context set to the unique ID of the test subject).

Wyjaśnienie:
Date Shifting (przesunięcie daty) to technika pseudonimizacji w Cloud DLP, która dodaje lub odejmuje losową liczbę dni od daty. Kluczowym elementem jest użycie "kontekstu" (np. ID pacjenta) – dzięki temu dla danego pacjenta wszystkie daty (np. rozpoczęcia i zakończenia leczenia) zostaną przesunięte o TĘ SAMĄ liczbę dni. Pozwala to na zachowanie precyzyjnych interwałów czasowych (czasu trwania kuracji) przy jednoczesnym ukryciu prawdziwych dat kalendarzowych, co chroni przed identyfikacją konkretnych partii leku lub osób.

Dlaczego pozostałe są błędne:
- B. TimePartConfig: Wyciąganie części daty (np. tylko roku) całkowicie niszczy informację o precyzyjnym interwale czasowym. Nie będziesz wiedzieć, czy pacjent brał lek 2 dni czy 20 dni.
- C. Bucketing: Grupowanie dat w przedziały (np. "Styczeń 2023") powoduje utratę precyzji niezbędnej do analizy interwałów czasowych w badaniach klinicznych.
- D. Format Preserving Encryption (FPE): FFX/FPE służy do szyfrowania danych przy zachowaniu ich formatu (np. numeru karty kredytowej), ale nie jest to technika optymalna do manipulacji datami w celu zachowania relacji czasowych (interwałów).

Wskazówki egzaminacyjne (Tips & Tricks):
- "Preserve interval data" + "obfuscate dates" = zawsze szukaj "Date Shifting".
- Słowo "Context" w Date Shiftingu zapewnia spójność zmian dla danego obiektu (np. użytkownika, pacjenta).

Kluczowe zagadnienia do powtórzenia:
- Metody de-identyfikacji w Cloud DLP (redaction, masking, bucketing, date shifting).
- Różnica między de-identyfikacją a pseudonimizacją.
- Zastosowanie Cloud DLP w branżach regulowanych (Healthcare - HIPAA).

Analiza i Wyjaśnienie

Sugerowana odpowiedź: A

Głęboka analiza: W badaniach klinicznych daty są danymi wrażliwymi, ale różnica między nimi (interwał) jest krytyczna dla analizy skuteczności leku. Date Shifting w Google Cloud DLP jest unikalnym narzędziem, które pozwala na zachowanie tej użyteczności danych przy pełnym zachowaniu prywatności. Przesunięcie o losową liczbę dni (np. +14 dni dla wszystkich dat pacjenta X) sprawia, że interwał pozostaje ten sam.
