Question 316 / 361

You want to set up a secure, internal network within Google Cloud for database servers. The servers must not have any direct communication with the public internet. What should you do?

  • A. Assign a private IP address to each database server. Use a NAT gateway to provide internet connectivity to the database servers.
  • B. Assign a static public IP address to each database server. Use firewall rules to restrict external access.
  • C. Create a VPC with a private subnet. Assign a private IP address to each database server.
  • D. Assign both a private IP address and a public IP address to each database server.
Show Suggested Answer Hide Answer
Suggested Answer: C

Wyjaśnienie

✅ PRAWIDŁOWA ODPOWIEDŹ: C

Prawidłowa odpowiedź: C – Create a VPC with a private subnet. Assign a private IP address to each database server. Use Private Google Access to allow the servers to communicate with Google APIs and services.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
DLACZEGO C JEST PRAWIDŁOWE?
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
Wymaganie: serwery DB bez dostępu do publicznego Internetu, ale możliwość komunikacji z Google APIs. Odpowiedź C:
- Prywatny subnet = brak publicznych IP.
- Private Google Access = pozwala serwerom bez publicznych IP na dostęp do Google APIs (BigQuery, Cloud Storage) przez wewnętrzną sieć Google.
Bez Private Google Access, serwer bez zewnętrznego IP nie mógłby się połączyć z Google APIs.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
DLACZEGO INNE OPCJE SĄ BŁĘDNE?
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
A. ❌ NAT gateway umożliwia wychodzący ruch do Internetu – narusza wymóg braku komunikacji z "public Internet". NAT ≠ Private Google Access.
B. ❌ Statyczny publiczny IP = bezpośrednia ekspozycja na Internet. Przeciwieństwo wymagania.
D. ❌ Oba IP (prywatny + publiczny) = nadal ma publiczne IP = komunikacja z Internetem = naruszenie wymagania.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
WSKAZÓWKI EGZAMINACYJNE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
• "No public Internet" + "access Google APIs" = Private Google Access.
• NAT = routing przez Internet (nawet jeśli z prywatnego IP – wychodzi na publiczny Internet).
• Private Google Access = dostęp do Google APIs bez Internetu (przez backbone Google).

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
REGUŁY
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
• Brak Internet + Google APIs = Private Google Access.
• NAT = Internet access (nie "private").
• Cloud NAT vs Private Google Access: różne koncepcje!
