Question 10 / 361

Your team needs to obtain a unified log view of all development cloud projects in your SIEM. The development projects are under the NONPROD organization folder with the test and pre-production projects. The development projects share the ABC-BILLING billing account with the rest of the organization. Which logging export strategy should you use to meet the requirements?

  • A. 1. Export logs to a Cloud Pub/Sub topic with folders/NONPROD parent and includeChildren property set to True in a dedicated SIEM project. 2. Subscribe SIEM to the topic.
  • B. 1. Create a Cloud Storage sink with billingAccounts/ABC-BILLING parent and includeChildren property set to False in a dedicated SIEM project. 2. Process Cloud Storage objects in SIEM.
  • C. 1. Export logs in each dev project to a Cloud Pub/Sub topic in a dedicated SIEM project. 2. Subscribe SIEM to the topic.
  • D. 1. Create a Cloud Storage sink with a publicly shared Cloud Storage bucket in each project. 2. Process Cloud Storage objects in SIEM.
Show Suggested Answer Hide Answer
Suggested Answer: A

Wyjaśnienie

Potwierdzona odpowiedź: A (1. Export logs to a Cloud Pub/Sub topic with folders/NONPROD parent and includeChildren property set to True in a dedicated SIEM project. 2. Subscribe SIEM to the topic.)

**Reguła Egzaminacyjna (Exam Rule):**
Jeśli pytanie dotyczy zebrania logów z wielu projektów zgrupowanych w folderze lub organizacji w celu integracji z SIEM, zawsze wybieraj "Aggregated Sink" (Zsumowany zlew) stworzony na poziomie wyższym niż projekt (np. folder/organizacja) z flagą `includeChildren=True`.

**Haczyki egzaminacyjne (Exam Traps):**
- Pułapka: "Pojedyncze zlewy w każdym projekcie". Przy dużej liczbie projektów jest to nieefektywne zarządczo i podatne na pominięcia.
- Pułapka: "Billing Account sinks". Zlewy na poziomie bilingu służą do logów bilingowych, a nie logów operacyjnych/bezpieczeństwa aplikacji.
- Pułapka: "Publiczne buckety GCS". Nigdy nie wybieraj opcji sugerującej publiczne udostępnianie bucketów GCS – jest to krytyczny błąd bezpieczeństwa.

**Głębokie wyjaśnienie techniczne:**
1. **Aggregated Sink**: Logi w GCP są hierarchiczne. Zlew logów utworzony na poziomie folderu (np. `folders/NONPROD`) z ustawionym `includeChildren=True` automatycznie zbiera logi ze wszystkich projektów wewnątrz tego folderu (i jego podfolderów).
2. **Pub/Sub jako strumień**: Dla systemów klasy SIEM (np. Splunk, QRadar, Chronicle) Pub/Sub jest preferowanym wyborem, ponieważ umożliwia przesyłanie logów w czasie rzeczywistym (streaming), co jest kluczowe dla szybkiego wykrywania zagrożeń.

Analiza i Podsumowanie Dyskusji (AI)

Analiza i Wyjaśnienie

Sugerowana odpowiedź: A

Analiza spornych kwestii (AI): Kluczowym wyzwaniem w tym pytaniu jest ogromna liczba projektów ('hundreds of projects'). Ręczne ustawianie eksportu w każdym z nich (opcja C) jest technicznie poprawne, ale operacyjnie błędne. Egzaminatorzy szukają dowodu, że znasz funkcję 'Aggregated Sinks', która jest przeznaczona właśnie do takich scenariuszy korporacyjnych.
