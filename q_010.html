Question 10 / 361

Your team needs to obtain a unified log view of all development cloud projects in your SIEM. The development projects are under the NONPROD organization folder with the test and pre-production projects. The development projects share the ABC-BILLING billing account with the rest of the organization. Which logging export strategy should you use to meet the requirements?

  • A. 1. Export logs to a Cloud Pub/Sub topic with folders/NONPROD parent and includeChildren property set to True in a dedicated SIEM project. 2. Subscribe SIEM to the topic.
  • B. 1. Create a Cloud Storage sink with billingAccounts/ABC-BILLING parent and includeChildren property set to False in a dedicated SIEM project. 2. Process Cloud Storage objects in SIEM.
  • C. 1. Export logs in each dev project to a Cloud Pub/Sub topic in a dedicated SIEM project. 2. Subscribe SIEM to the topic.
  • D. 1. Create a Cloud Storage sink with a publicly shared Cloud Storage bucket in each project. 2. Process Cloud Storage objects in SIEM.
Show Suggested Answer Hide Answer
Suggested Answer: A

Wyjaśnienie

**Poprawna odpowiedź: A**

**1. Kompleksowe wyjaśnienie poprawnej odpowiedzi:**
Wymaganiem jest zebranie logów z wielu projektów rozwojowych (development) znajdujących się pod wspólnym folderem w organizacji (`folders/NONPROD`) i przesłanie ich do systemu SIEM za pośrednictwem Pub/Sub:
- **Eksport logów na poziomie folderu do tematu Cloud Pub/Sub w dedykowanym projekcie SIEM, z włączoną opcją includeChildren (A):** Log sink (odbiornik logów) utworzony na poziomie folderu z właściwością `includeChildren=True` automatycznie zbiera logi ze wszystkich projektów i podfolderów znajdujących się pod tym folderem. Przesłanie ich do jednego tematu Pub/Sub w dedykowanym projekcie pozwala systemowi SIEM na łatwą subskrypcję i pobieranie danych z jednego miejsca.

**2. Wyjaśnienie niepoprawnych odpowiedzi:**
- **B. Cloud Storage sink z poziomem billingAccounts:** Konto rozliczeniowe (billing account) nie grupuje zasobów w sposób logiczny dla celów bezpieczeństwa, a Cloud Storage (GCS) jest rozwiązaniem wsadowym (batch), nie nadającym się do przesyłania logów w czasie rzeczywistym do SIEM.
- **C. Eksport logów w każdym projekcie osobno:** Wymagałoby to ręcznej konfiguracji sinków w setkach projektów, co jest nieefektywne, trudne do zarządzania i audytu.
- **D. Publicznie współdzielony bucket Cloud Storage:** Udostępnianie publiczne logów bezpieczeństwa narusza podstawowe zasady poufności i stwarza ogromne zagrożenie wycieku danych wrażliwych.

**3. Wskazówki i pułapki egzaminacyjne (Tips & Tricks):**
- Zbiorczy eksport logów w GCP realizuje się na poziomie **Folderu** lub **Organizacji** z parametrem **`includeChildren=True`** (tzw. Aggregated Sinks).
- Integracja z systemami SIEM w czasie rzeczywistym prawie zawsze opiera się na **Cloud Pub/Sub**.

**4. Reguły wyboru odpowiedzi:**
- Wiele projektów w jednym folderze -> Aggregated Sink na poziomie Folderu.
- Integracja z SIEM -> Pub/Sub.

**5. Dodatkowe źródła:**
- Collate and routing organization logs: https://cloud.google.com/logging/docs/routing/monitored-resources

Analiza i Wyjaśnienie

Sugerowana odpowiedź: A

Analiza spornych kwestii (AI): Kluczowym wyzwaniem w tym pytaniu jest ogromna liczba projektów ('hundreds of projects'). Ręczne ustawianie eksportu w każdym z nich (opcja C) jest technicznie poprawne, ale operacyjnie błędne. Egzaminatorzy szukają dowodu, że znasz funkcję 'Aggregated Sinks', która jest przeznaczona właśnie do takich scenariuszy korporacyjnych.
