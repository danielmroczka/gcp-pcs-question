Question 193 / 361

Your organization's Customers must scan and upload the contract and their driver license into a web portal in Cloud Storage. You must remove all personally identifiable information (PII) from files that are older than 12 months. Also, you must archive the anonymized files for retention purposes. What should you do?

  • A. Set a time to live (TTL) of 12 months for the files in the Cloud Storage bucket that removes PII and moves the files to the archive storage class.
  • B. Create a Cloud Data loss Prevention (DLP) inspection job that de-identifies PII in files created more than 12 months ago and archives them to another Cloud Storage bucket. Delete the original files.
  • C. Configure the Autoclass feature of the Cloud Storage bucket to move files to the Archive storage class after 12 months. Use a Cloud Function to remove PII.
  • D. Implement a lifecycle policy to move objects to the Archive storage class after 12 months. Use the Cloud Data Loss Prevention (DLP) API to remove PII.
Show Suggested Answer Hide Answer
Suggested Answer: B

Wyjaśnienie

Potwierdzona odpowiedź: B (Create a Cloud Data loss Prevention (DLP) inspection job that de-identifies PII in files created more than 12 months ago and archives them to another Cloud Storage bucket. Delete the original files).

Wyjaśnienie:
- Cloud Data Loss Prevention (DLP): Jest to dedykowana usługa Google Cloud do odkrywania, klasyfikowania i ochrony danych wrażliwych (PII).
- Modyfikacja zawartości: Wymóg "remove all PII" oznacza konieczność edycji zawartości plików (np. zamazywanie danych na skanach dokumentów). DLP jest jedynym narzędziem w GCP, które potrafi "zajrzeć" do plików w Cloud Storage, rozpoznać PII i wykonać ich de-identyfikację (redakcję).
- Automatyzacja i Archiwizacja: Zadanie inspekcji DLP (Inspection Job) można skonfigurować tak, aby przetworzone pliki trafiały do innego bucketu (archiwum), co spełnia wymóg retencji danych zanonimizowanych.
- Usuwanie oryginałów: Po stworzeniu bezpiecznej kopii, usunięcie oryginałów zawierających pełne PII jest kluczowym krokiem dla zachowania zgodności (Compliance).

Dlaczego pozostałe odpowiedzi są niepoprawne:
- A. Lifecycle Policy (TTL): Polityki cyklu życia (Object Lifecycle Management) działają na metadanych obiektu. Potrafią automatycznie usunąć plik (Delete) lub zmienić jego klasę (np. na Archive) po określonym czasie, ale NIE potrafią modyfikować zawartości pliku (usuwać PII).
- C. Autoclass: Ta funkcja służy do automatycznego optymalizowania kosztów poprzez przenoszenie rzadziej używanych plików do tańszych klas storage. Nie ma ona nic wspólnego z bezpieczeństwem danych ani usuwaniem PII.
- D. Lifecycle Policy + DLP API: Choć teoretycznie można by spróbować połączyć te usługi, opcja B opisuje natywną funkcję DLP (Inspection Job), która jest zaprojektowana właśnie do tego celu – skanowania storage i wykonywania akcji na podstawie wyników. Lifecycle policy w tej opcji nie rozwiązuje problemu modyfikacji zawartości przed przeniesieniem.

Wskazówki egzaminacyjne (Tips & Tricks):
- "Remove PII from files" / "Anonymize files" + "Cloud Storage" = Cloud DLP.
- Lifecycle Policy = Tylko "Delete" lub "Change Storage Class". Nigdy nie modyfikuje zawartości.
- Pamiętaj: DLP obsługuje skanowanie obrazów (skany dowodów) za pomocą wbudowanego OCR.

Kluczowe zagadnienia do powtórzenia:
- Cloud Data Loss Prevention (DLP) - de-identyfikacja.
- Cloud Storage Object Lifecycle Management.
- Przetwarzanie danych wrażliwych (PII) w chmurze.

Wiele osób mylnie uważa, że Lifecycle Policy wystarczy do compliance, ale polityka ta jest "ślepa" na to, co jest w środku pliku. Cloud DLP to "inteligentne oko" bezpieczeństwa w GCP, niezbędne do realizacji wymogów takich jak RODO (right to be forgotten / minimization).
