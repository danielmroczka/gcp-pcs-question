Question 193 / 361

Your organization's Customers must scan and upload the contract and their driver license into a web portal in Cloud Storage. You must remove all personally identifiable information (PII) from files that are older than 12 months. Also, you must archive the anonymized files for retention purposes. What should you do?

  • A. Set a time to live (TTL) of 12 months for the files in the Cloud Storage bucket that removes PII and moves the files to the archive storage class.
  • B. Create a Cloud Data loss Prevention (DLP) inspection job that de-identifies PII in files created more than 12 months ago and archives them to another Cloud Storage bucket. Delete the original files.
  • C. Configure the Autoclass feature of the Cloud Storage bucket to move files to the Archive storage class after 12 months. Use a Cloud Function to remove PII.
  • D. Implement a lifecycle policy to move objects to the Archive storage class after 12 months. Use the Cloud Data Loss Prevention (DLP) API to remove PII.
Show Suggested Answer Hide Answer
Suggested Answer: B

Wyjaśnienie

1. Prawidłowa odpowiedź lub odpowiedzi:
B. Create a Cloud Data loss Prevention (DLP) inspection job that de-identifies PII in files created more than 12 months ago and archives them to another Cloud Storage bucket. Delete the original files.

2. Kompleksowe wyjaśnienie dlaczego dana odpowiedź jest prawidłowa (Analiza):
Wymaganiem jest automatyczne wykrycie i usunięcie danych osobowych (PII) z plików (np. skanów dowodów osobistych i umów) starszych niż 12 miesięcy, a następnie zarchiwizowanie zanonimizowanych plików w Cloud Storage oraz usunięcie oryginalnych, zawierających PII.
Do wyszukiwania i maskowania/usuwania danych wrażliwych (PII) w plikach tekstowych lub graficznych służy dedykowana usługa **Cloud Data Loss Prevention (Cloud DLP)**.
Prawidłowy scenariusz zakłada:
1. Uruchomienie zadania inspekcji DLP (Inspection Job), które skanuje pliki starsze niż 12 miesięcy.
2. Zastosowanie reguł de-identyfikacji (de-identification / redaction) w celu usunięcia/zamaskowania wrażliwych fragmentów (np. PESEL, numer dowodu osobistego).
3. Zapisanie przetworzonych, zanonimizowanych kopii plików w osobnym buckecie (pełniącym rolę archiwum).
4. Usunięcie oryginalnych plików z pierwotnego bucketu w celu zachowania zgodności z polityką ochrony danych.

3. Wyjaśnienie z osobna każdej niepoprawnej odpowiedzi:
- A. Set a time to live (TTL) of 12 months...: Polityka cyklu życia (Object Lifecycle Management / TTL) w Cloud Storage potrafi automatycznie usunąć obiekt lub przenieść go do innej klasy pamięci (np. Archive) po określonym czasie, ale nie ma możliwości modyfikacji zawartości plików i usunięcia z nich PII.
- C. Configure the Autoclass feature... Use a Cloud Function to remove PII: Funkcja Autoclass służy wyłącznie do automatycznego optymalizowania kosztów przechowywania danych (przenosi rzadko używane obiekty do tańszych klas). Użycie Cloud Function do samodzielnego wykrywania i usuwania PII z różnych typów plików (tekst, obrazy) byłoby niezwykle trudne w implementacji i nieefektywne w porównaniu do natywnego Cloud DLP.
- D. Implement a lifecycle policy to move objects to the Archive storage class... Use DLP API to remove PII: Ta kolejność działań jest niepoprawna. Przeniesienie plików za pomocą lifecycle policy do klasy Archive przed usunięciem PII spowodowałoby, że w archiwum wylądowałyby niezaszyfrowane, pełne dane PII. Ponadto operacja DLP musiałaby być uruchamiana na zarchiwizowanych obiektach, co generuje wysokie koszty operacyjne (opłaty za pobranie z Archive class).

4. Wskazówki, hinty, tips and tricks:
- Do modyfikacji i usuwania danych osobowych (PII / de-identification / redaction) w plikach przechowywanych w Cloud Storage zawsze służy **Cloud DLP**.
- Zapamiętaj, że polityki cyklu życia (Lifecycle Policies) działają tylko na poziomie metadanych (usunąć plik, zmienić klasę), a nie na zawartości pliku.

5. Reguły wyboru odpowiedzi (Słowa kluczowe):
- "remove all personally identifiable information (PII)" + "Cloud Storage" -> Cloud DLP inspection job -> de-identifies PII.

6. Dodatkowe źródła i dokumentacja:
- Inspecting Cloud Storage with Cloud DLP: https://cloud.google.com/dlp/docs/inspecting-storage

Sugerowana odpowiedź: B

Głęboka analiza: To pytanie testuje Twoją zdolność do odróżnienia zarządzania "kontenerem" (bucketem) od zarządzania "zawartością". Wiele osób mylnie uważa, że Lifecycle Policy wystarczy do compliance, ale polityka ta jest "ślepa" na to, co jest w środku pliku. Cloud DLP to "inteligentne oko" bezpieczeństwa w GCP, niezbędne do realizacji wymogów takich jak RODO (right to be forgotten / minimization).
