Question 33 / 361

A customer wants to move their sensitive workloads to a Compute Engine-based cluster using Managed Instance Groups (MIGs). The jobs are bursty and must be completed quickly. They have a requirement to be able to control the key lifecycle.
Which boot disk encryption solution should you use on the cluster to meet this customer's requirements?

  • A. Customer-supplied encryption keys (CSEK)
  • B. Customer-managed encryption keys (CMEK) using Cloud Key Management Service (KMS)
  • C. Encryption by default
  • D. Pre-encrypting files before transferring to Google Cloud Platform (GCP) for analysis
Show Suggested Answer Hide Answer
Suggested Answer: B

Wyjaśnienie

**Poprawna odpowiedź: B**

**1. Kompleksowe wyjaśnienie poprawnej odpowiedzi:**
Klient wdraża Managed Instance Groups (MIG) z dynamicznym skalowaniem i ma dwa wymagania dotyczące szyfrowania dysków startowych:
- Skalowanie musi przebiegać automatycznie i szybko (bursty).
- Klient musi zachować pełną kontrolę nad cyklem życia klucza szyfrującego (lifecycle control).
- **Customer-Managed Encryption Keys (CMEK) w Cloud KMS (B):** Klucze CMEK pozwalają klientowi na zarządzanie ich rotacją, włączaniem/wyłączaniem i niszczeniem bezpośrednio w Cloud KMS. Aby umożliwić automatyczne skalowanie MIG bez interwencji człowieka, nadaje się uprawnienia szyfrowania (role Encrypter/Decrypter) dla konta usługowego agenta Compute Engine. Google Cloud automatycznie odszyfrowuje i tworzy nowe dyski VM w locie za pomocą tego klucza.

**2. Wyjaśnienie niepoprawnych odpowiedzi:**
- **A. Customer-Supplied Encryption Keys (CSEK):** W przypadku CSEK klucz musi być podawany przy każdym tworzeniu maszyny w parametrach API (Google nie przechowuje go w KMS). Przy automatycznym skalowaniu MIG (Manged Instance Groups) Google Cloud nie miałby skąd pobrać klucza w locie, co uniemożliwia poprawne działanie automatycznego skalowania.
- **C. Encryption by default (Szyfrowanie domyślne):** Szyfrowanie domyślne (Google-managed keys) nie daje klientowi żadnej kontroli nad cyklem życia kluczy (Google w pełni nimi zarządza).
- **D. Pre-encrypting files:** Szyfrowanie plików przed wysłaniem nie chroni samego dysku startowego (boot disk) systemu operacyjnego maszyny wirtualnej.

**3. Wskazówki i pułapki egzaminacyjne (Tips & Tricks):**
- Zapamiętaj kluczową różnicę na egzaminie:
  - **CMEK (KMS):** Klucze są w chmurze. Obsługuje **MIG i autoscaling** (ponieważ GCP ma uprawnienia do pobierania klucza z KMS).
  - **CSEK:** Klucze są poza chmurą (podawane w locie przez użytkownika). **Nie obsługuje** MIG i autoscalingu.

**4. Reguły wyboru odpowiedzi:**
- Własny klucz + Autoscaling/MIG -> CMEK (Cloud KMS).
- Własny klucz + Statyczna pojedyncza maszyna bez chmury -> CSEK.

**5. Dodatkowe źródła:**
- Encrypt disks with CMEK: https://cloud.google.com/compute/docs/disks/customer-managed-encryption

Analiza i Podsumowanie Dyskusji (AI)

Analiza i Wyjaśnienie

Sugerowana odpowiedź: B

Analiza spornych kwestii (AI): W przypadku CMEK, nadajesz specjalnemu kontu serwisowemu Google (Compute Service Agent) rolę 'CryptoKey Encrypter/Decrypter'. Dzięki temu Google może w Twoim imieniu automatycznie tworzyć zaszyfrowane dyski podczas skalowania MIG, zachowując jednocześnie Twoją władzę nad kluczem w KMS (np. możesz go w każdej chwili zniszczyć, uniemożliwiając odczyt danych).

Wyjaśnienie Audytowe

Reguła Egzaminacyjna (Exam Rule):
Pamiętaj, że w egzaminie Professional Cloud Security Engineer kluczowe jest wybieranie rozwiązań najmniej uprzywilejowanych (Principle of Least Privilege), zoptymalizowanych kosztowo i spełniających wymogi compliancy (np. CMEK, Data Loss Prevention).

Haczyki egzaminacyjne (Exam Traps):
- Wybór rozwiązań, które wydają się wygodne, ale nie spełniają wymogów bezpieczeństwa (np. zbyt szerokie uprawnienia IAM).
- Mylenie usług: np. Cloud Armor (WAF) z Cloud IAP (Identity-Aware Proxy).

Głębokie wyjaśnienie techniczne (GCP Professional Cloud Security Engineer):
W każdym pytaniu analizuj warstwy: IAM (dostęp), Encryption (at rest/in transit), Logging/Monitoring (Audit Logs, Cloud Logging, Security Command Center) oraz Networking (VPC Service Controls, Firewall Rules). GCP kładzie duży nacisk na współdzieloną odpowiedzialność (Shared Responsibility Model) - klient odpowiada za konfigurację zabezpieczeń wewnątrz usług chmurowych.
