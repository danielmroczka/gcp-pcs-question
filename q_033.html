Question 33 / 361

Which boot disk encryption solution should you use on a MIG cluster to control the key lifecycle?

  • A. CSEK
  • B. CMEK using Cloud KMS
  • C. Encryption by default
  • D. Pre-encrypting files
Show Suggested Answer Hide Answer
Suggested Answer: B

Wyjaśnienie

Poprawna odpowiedź: B (CMEK using Cloud KMS)

Analiza poprawności:
CMEK (Customer-Managed Encryption Keys) to usługa w Google Cloud, która daje administratorowi pełną kontrolę nad cyklem życia klucza szyfrującego (rotacja, wyłączanie, niszczenie) poprzez Cloud KMS. Jest to rozwiązanie w pełni wspierane przez Managed Instance Groups (MIG). Podczas definiowania szablonu instancji (Instance Template), możesz wskazać klucz KMS, który zostanie użyty do zaszyfrowania dysków systemowych (boot disks) każdej nowo uruchomionej instancji w ramach grupy, co jest standardem bezpieczeństwa w architekturach Enterprise.

Dlaczego pozostałe są błędne:
A (CSEK - Customer-Supplied Encryption Keys): Wymaga podania klucza szyfrującego jako parametru przy każdym uruchomieniu/starcie VM. Ponieważ MIG-i muszą automatycznie skalować (samodzielnie startować nowe instancje w odpowiedzi na obciążenie), Google nie mogłoby zarządzać startem VM bez Twojej manualnej interwencji przy dostarczaniu klucza przy każdym nowym dysku.
C (Encryption by default): Google szyfruje dane "by default" (domyślnie), ale używa do tego kluczy zarządzanych przez Google (GMEK). Użytkownik nie ma kontroli nad ich cyklem życia (nie może ich ręcznie rotować ani usunąć).
D (Pre-encrypting files): Szyfrowanie plików na poziomie systemu operacyjnego nie chroni całego dysku systemowego (boot disk) i jest bardzo trudne w zarządzaniu na poziomie skalowalnych grup instancji.

Wskazówki egzaminacyjne:
- "MIG" + "Control key lifecycle": Zawsze wybieraj CMEK.
- "Automated scaling": Odrzuć CSEK, ponieważ wymaga ręcznej podaży klucza.
- "Control": GMEK (Encryption by default) = brak kontroli; CMEK = pełna kontrola.

Dokumentacja:

Analiza i Wyjaśnienie

Sugerowana odpowiedź: B

Analiza spornych kwestii (AI): Przy użyciu CMEK w MIG, nadajesz systemowemu kontu serwisowemu (Compute Service Agent) uprawnienia do używania Twojego klucza w KMS. To pozwala Google na automatyczne tworzenie dysków w Twoim imieniu, zapewniając bezpieczne zarządzanie cyklem życia klucza.
