Question 201 / 361

Your company's Google Cloud organization has about 200 projects and 1,500 virtual machines. There is no uniform strategy for logs and events management, which reduces visibility for your security operations team. You need to design a logs management solution that provides visibility and allows the security team to view the environment's configuration.

  • A. 1. Create a dedicated log sink for each project that is in scope. 2. Use a BigQuery dataset with time partitioning enabled as a destination of the log sinks. 3. Deploy alerts based on log metrics in every project. 4. Grant the role Monitoring Viewer to the security operations team in each project.
  • B. 1. Create one log sink at the organization level that includes all the child resources. 2. Use as destination a Pub/Sub topic to ingest the logs into the security information and event management (SIEM) on-premises, and ensure that the right team can access the SIEM. 3. Grant the Viewer role at organization level to the security operations team.
  • C. 1. Enable network logs and data access logs for all resources in the Production folder. 2. Do not create log sinks to avoid unnecessary costs and latency. 3. Grant the roles Logs Viewer and Browser at project level to the security operations team.
  • D. 1. Create one sink for the Production folder that includes child resources and one sink for the logs ingested at the organization level that excludes child resources. 2. As destination, use a log bucket with a minimum retention period of 90 days in a project that can be accessed by the security team. 3. Grant the security operations team the role of Security Reviewer at organization level.
Show Suggested Answer Hide Answer
Suggested Answer: B

Wyjaśnienie

1. Prawidłowa odpowiedź lub odpowiedzi:
B. 1. Create one log sink at the organization level that includes all the child resources. 2. Use as destination a Pub/Sub topic to ingest the logs into the security information and event management (SIEM) on-premises, and ensure that the right team can access the SIEM. 3. Grant the Viewer role at organization level to the security operations team.

2. Kompleksowe wyjaśnienie dlaczego dana odpowiedź jest prawidłowa (Analiza):
Odpowiedź B jest prawidłowa, ponieważ centralizacja logów z wielu projektów (tutaj 200 projektów) i integracja z lokalnym systemem klasy SIEM w czasie rzeczywistym wymaga zastosowania zagregowanego odbiornika logów (Aggregated Sink) na poziomie organizacji oraz kolejki Pub/Sub.

Kluczowe aspekty tego rozwiązania:
a. **Zagregowany log sink (Aggregated Log Sink):** Tworząc jeden sink na poziomie organizacji z flagą uwzględniania zasobów podrzędnych (`includeChildren=true`), automatycznie przechwytujemy logi ze wszystkich istniejących i nowo tworzonych projektów bez konieczności ręcznej konfiguracji sinków w każdym projekcie z osobna. Jest to wysoce skalowalne i odporne na błędy administracyjne.
b. **Pub/Sub jako miejsce docelowe:** Przesyłanie logów w czasie rzeczywistym do systemu SIEM on-premises najlepiej zrealizować poprzez Pub/Sub, który działa jako wysoce wydajny bufor wiadomości i pozwala na asynchroniczne pobieranie logów przez lokalne kolektory SIEM.
c. **Uprawnienia do widoczności konfiguracji:** Nadanie zespołowi bezpieczeństwa roli `Viewer` na poziomie organizacji daje im prawo do przeglądania konfiguracji i metadanych zasobów w konsoli, co jest niezbędne do analizowania środowiska, nie dając jednocześnie uprawnień do edycji lub dostępu do danych wrażliwych.

3. Wyjaśnienie z osobna każdej niepoprawnej odpowiedzi:
A. 1. Create a dedicated log sink for each project... 4. Grant the role Monitoring Viewer...
   * Dlaczego nieprawidłowa: Tworzenie dedykowanych sinków w każdym z 200 projektów oddzielnie jest operacyjnym koszmarem i nie gwarantuje, że nowe projekty będą automatycznie objęte monitoringiem. Dodatkowo rola `Monitoring Viewer` nie pozwala na pełny wgląd w konfigurację wszystkich zasobów w organizacji.
C. 1. Enable network logs and data access logs... 2. Do not create log sinks...
   * Dlaczego nieprawidłowa: Niezapisywanie logów do zewnętrznego odbiornika uniemożliwia ich analizę w systemie SIEM i powoduje utratę logów po standardowym okresie retencji GCP. Zespół bezpieczeństwa nie miałby centralnego miejsca analizy.
D. 1. Create one sink for the Production folder... 2. Use a log bucket...
   * Dlaczego nieprawidłowa: Logowanie do lokalnego Log Bucket w GCP utrudnia integrację z on-premises SIEM. Ponadto ta opcja nie obejmuje całej organizacji, a rola `Security Reviewer` na poziomie organizacji daje duże uprawnienia, ale samo rozwiązanie nie realizuje integracji SIEM on-premises w sposób natychmiastowy i efektywny za pomocą Pub/Sub.

4. Wskazówki, hinty, tips and tricks:
* Kiedy celem jest integracja z zewnętrznym/lokalnym (on-premises) systemem SIEM, domyślnym i zalecanym mechanizmem transportu w GCP jest **Pub/Sub**.
* Zagregowane odbiorniki logów (Aggregated Sinks) na poziomie Organizacji lub Folderu są jedyną poprawną metodą zbierania logów w środowiskach wieloprojektowych (multi-project).

5. Reguły wyboru odpowiedzi (Słowa kluczowe):
* Integracja z SIEM on-premises -> szukaj Pub/Sub.
* Centralizacja logów w skali organizacji -> szukaj "log sink at the organization level" lub "aggregated sink".
