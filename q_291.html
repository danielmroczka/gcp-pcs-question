Question 291 / 361

Your organization is using a third-party identity and authentication provider to centrally manage users. You want to use this identity provider to grant access to the Google Cloud console without syncing identities to Google Cloud. Users should receive permissions based on attributes. What should you do?

  • A. Configure the central identity provider as a workforce identity pool provider in Workforce Identity Federation. Create an attribute mapping by using the Common Expression Language (CEL).
  • B. Configure a periodic synchronization of relevant users and groups with attributes to Cloud Identity. Activate single sign-on by using the Security Assertion Markup Language (SAML).
  • C. Set up the Google Cloud Identity Platform. Configure an external authentication provider by using OpenID Connect and link user accounts based on attributes.
  • D. Activate external identities on the Identity-Aware Proxy. Use the Security Assertion Markup Language (SAML) to configure authentication based on attributes to the central authentication provider.
Show Suggested Answer Hide Answer
Suggested Answer: A

Wyjaśnienie

1. Prawidłowa odpowiedź lub odpowiedzi:
A. Configure the central identity provider as a workforce identity pool provider in Workforce Identity Federation. Create an attribute mapping by using the Common Expression Language (CEL).

2. Kompleksowe wyjaśnienie dlaczego dana odpowiedź jest prawidłowa (Analiza):
Odpowiedź A jest prawidłowa, ponieważ Workforce Identity Federation (Federacja Tożsamości Pracowników) jest oficjalną usługą GCP zaprojektowaną do uwierzytelniania pracowników i kontrahentów w konsoli Google Cloud przy użyciu zewnętrznego IdP bez konieczności synchronizowania ich kont do Google Cloud Identity.

Szczegóły techniczne i zalety:
a. **Brak synchronizacji (Keyless/Accountless):** Użytkownicy logują się przy użyciu swoich poświadczeń u zewnętrznego dostawcy (np. Okta, Azure AD). GCP nie tworzy dla nich kont w lokalnym katalogu Cloud Identity.
b. **Mapowanie atrybutów za pomocą CEL:** Podczas logowania zewnętrzny IdP przesyła token zawierający atrybuty użytkownika (np. rola w firmie, dział). Używając języka Common Expression Language (CEL), możemy zmapować te atrybuty na właściwości GCP (np. zmapować grupę "GCP-Admins" z IdP na grupę w puli tożsamości GCP), a następnie przypisać odpowiednie role IAM bezpośrednio tym grupom atrybutów.

3. Wyjaśnienie z osobna każdej niepoprawnej odpowiedzi:
B. Configure a periodic synchronization of relevant users and groups... Activate SSO by using SAML.
   * Dlaczego nieprawidłowa: Ta metoda wymaga aktywnego synchronizowania (kopiowania) wszystkich kont użytkowników i grup do Cloud Identity (np. za pomocą GCDS). Narusza to kluczowe wymaganie "without syncing identities to Google Cloud".
C. Set up the Google Cloud Identity Platform. Configure an external authentication provider...
   * Dlaczego nieprawidłowa: Identity Platform (CIAM) służy do uwierzytelniania zewnętrznych klientów (customers) aplikacji SaaS wdrożonych przez klienta. Nie służy do nadawania dostępu pracownikom do samej konsoli Google Cloud Console (administrative access) w celu zarządzania infrastrukturą chmurową.
D. Activate external identities on the Identity-Aware Proxy. Use SAML to configure...
   * Dlaczego nieprawidłowa: IAP (Identity-Aware Proxy) z zewnętrznymi tożsamościami służy do zabezpieczania dostępu do aplikacji webowych klienta. Nie służy do uwierzytelniania i autoryzacji dostępu administracyjnego do standardowej konsoli Google Cloud Console.

4. Wskazówki, hinty, tips and tricks:
* Dostęp dla pracowników/kontrahentów do konsoli GCP bez synchronizacji kont (no identity synchronization) -> Zawsze **Workforce Identity Federation**.
* Mapowanie atrybutów tożsamości z zewnętrznego IdP realizuje się za pomocą **Common Expression Language (CEL)**.

5. Reguły wyboru odpowiedzi (Słowa kluczowe):
* Grant access to GCP console without syncing identities -> Workforce Identity Federation (workforce identity pool).
