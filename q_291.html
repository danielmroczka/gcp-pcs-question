Question 291 / 361

Your organization is using a third-party identity and authentication provider to centrally manage users. You want to use this identity provider to grant access to the Google Cloud console without syncing identities to Google Cloud. Users should receive permissions based on attributes. What should you do?

  • A. Configure the central identity provider as a workforce identity pool provider in Workforce Identity Federation. Create an attribute mapping by using the Common Expression Language (CEL).
  • B. Configure a periodic synchronization of relevant users and groups with attributes to Cloud Identity. Activate single sign-on by using the Security Assertion Markup Language (SAML).
  • C. Set up the Google Cloud Identity Platform. Configure an external authentication provider by using OpenID Connect and link user accounts based on attributes.
  • D. Activate external identities on the Identity-Aware Proxy. Use the Security Assertion Markup Language (SAML) to configure authentication based on attributes to the central authentication provider.
Show Suggested Answer Hide Answer
Suggested Answer: A

Wskazówki egzaminacyjne (Tips & Tricks)

Reguła Egzaminacyjna (Exam Rule): 
W pytaniach typu 'Security in GCP', zawsze priorytetyzuj rozwiązania natywne (SCC, Cloud KMS, Secret Manager, VPC SC) nad rozwiązaniami typu 'third-party' lub 'self-managed', chyba że scenariusz wymaga specyficznej integracji hybrydowej.

Haczyki egzaminacyjne (Exam Traps):
- Pułapka 'Least Privilege': Egzamin często podpowiada role o szerokim zakresie (np. 'Editor' lub 'Owner') – zawsze odrzucaj je na rzecz ról predefiniowanych o najmniejszym zakresie uprawnień.
- Pułapka 'Logging vs Monitoring': Pamiętaj: Audit Logs służą do badania aktywności (Who/What/When), a Monitoring do zbierania metryk wydajnościowych.

Głębokie wyjaśnienie techniczne:
Każda architektura bezpieczeństwa w GCP powinna być projektowana w oparciu o 'Security by Default'. Oznacza to m.in. szyfrowanie w spoczynku (domyślne), tożsamość opartą na rolach (IAM) oraz pełną widoczność zapewnianą przez scentralizowane logowanie (Cloud Logging/SCC).

Wyjaśnienie

Potwierdzona odpowiedź: A (Configure the central identity provider as a workforce identity pool provider in Workforce Identity Federation. Create an attribute mapping by using the Common Expression Language (CEL).)

Wyjaśnienie:
- Workforce Identity Federation: To nowoczesne rozwiązanie Google Cloud, które pozwala na dostęp do zasobów GCP (Konsola, gcloud) bez konieczności synchronizacji kont do Cloud Identity. Tożsamość jest federowana "w locie".
- Attribute mapping (CEL): Pozwala na dynamiczne przypisywanie uprawnień na podstawie atrybutów przekazanych z zewnętrznego IdP (np. dział, rola), co realizuje wymóg sterowania dostępem przez atrybuty.

Dlaczego pozostałe odpowiedzi są niepoprawne:
- B. Cloud Identity sync: Wymaga synchronizacji kont, co jest wprost wykluczone w treści pytania ("without syncing identities").
- C. Identity Platform: To rozwiązanie CIAM dla użytkowników aplikacji końcowych, a nie dla pracowników (workforce) potrzebujących dostępu do Konsoli GCP.
- D. Identity-Aware Proxy: Służy do ochrony aplikacji webowych i SSH/RDP, a nie do zarządzania federacją tożsamości dla całej platformy Google Cloud bez synchronizacji kont.

Wskazówki i triki (Tips & Tricks):
- "Without syncing identities" + "Access to console" = Workforce Identity Federation.
- Pamiętaj: Atrybuty w federacji mapuje się za pomocą języka CEL (Common Expression Language).

Praktyczne informacje na egzamin:
- Zapamiętaj: Workforce Identity Federation eliminuje potrzebę posiadania "Google Accounts" (gmail/workspace) dla zewnętrznych inżynierów czy partnerów.

Analiza i Podsumowanie (AI)

Kluczowe zagadnienia

Sugerowana odpowiedź: A

Analiza strategiczna: To pytanie testuje znajomość najnowszych metod zarządzania tożsamością w dużych przedsiębiorstwach. Eliminacja konieczności synchronizacji kont (shadow accounts) drastycznie zmniejsza pole ataku i upraszcza zarządzanie cyklem życia użytkownika.
